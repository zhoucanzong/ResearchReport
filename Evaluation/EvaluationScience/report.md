# 评测科学：分数何时支持“模型更好”或“能力泛化”

**范围**：跨领域讨论 benchmark 分数的解释条件，重点看构念效度、数据污染与饱和、judge/人评信度，以及 agent 与机器人在交互环境中的外部效度。本文不是 benchmark 名录，也不提供当前模型排行榜。

**核心结论（跨来源综合）**：分数首先只支持“这个模型在这套任务、数据、指标和执行条件下得分更高”。要把它升级为“模型普遍更好”或“具备可迁移的某种能力”，必须逐段论证：抽样能代表目标分布、任务和评分确实操作化了目标构念、评测数据对模型/训练过程足够独立、评分者误差不会改写比较、并且评测环境包含了部署任务的关键反馈与约束。结论越抽象，所需证据越多。[S1 §2–3, Table 1]

## 1. 评测分数是一条推理链

Freiesleben 与 Zezulka 将预测 benchmark 视作测量工具：模型在固定数据和指标上得到的经验分数，可以在独立同分布、样本量足够等条件下估计该学习问题上的期望表现；这仍然只是对“这个学习问题”的一般化。要推到其他数据集、理论任务或部署用途，还需要外推、构念化及用途/决策条件。[S1 §2–3, Table 1]

### 比较分数时，先拆开三层协议

“同一 benchmark”不一定意味着测量过程相同。为检查两项结果能否直接比较，可以把评测拆成三层；这是本报告的分析框架，论文对三层的命名和打包方式并不统一。

| 层 | 固定的对象 | 原文例子及其说明 |
|---|---|---|
| **Benchmark：题目与样本** | 任务定义、题目版本与抽样、初态/参考答案，以及它想代表的场景 | HELM 先定义任务、领域和语言场景，再选择覆盖集合；LiveBench 每次更新平均替换六分之一题目。[S2 §3.1–3.3；S4 §2.7] |
| **Harness：执行脚手架** | 提示、控制循环、工具接口、上下文管理、环境、重试和时限；agent 评测还须钉住环境初态 | WildClawBench 固定同一批任务并比较四个 harness；同一 MiMo V2 Pro 在 Claude Code 与 Hermes Agent 的总分相差 18 个百分点。作者将差异联系到控制循环、工具 schema、上下文管理和输出恢复，而不是把它解释成模型本身变化。[S5 §3.4、§4.1、§4.3, Table 3] |
| **Metric：判分与聚合** | 什么算成功、由谁/什么判分、任务如何加权、是否跨随机重复汇总 | HELM 并列报告准确率、校准、稳健性等指标；τ-bench 以数据库终态和必要回复共同决定单次奖励，并区分“k 次全成功”的 `pass^k` 与“至少一次成功”的 `pass@k`。[S2 §2.3、§4；S12 §3] |

因此，跨论文分差不能自动归因于模型版本：题目样本、执行 harness 或 metric 任一改变，都可能改变分数代表的对象。模型 checkpoint/API 快照与调用参数也要单独说明；不能统一的层就把比较对象写成完整的“模型 + harness + benchmark + metric”配置。WildClawBench 的 18 点差异是这一风险的实测例子，不是所有 agent 基准的通用效应量。[S5 §4.1–4.3, Table 3]

| 目标主张 | 分数直接测到什么 | 还需补的证据 |
|---|---|---|
| “A 在测试集上高于 B” | 特定 split、指标和协议下的样本表现 | 明确模型版本、提示/解码、样本与不确定性；排除实现或评分差异 |
| “A 在同类新样本上更好” | 若测试样本可视为目标总体抽样，可估计同分布表现 | 数据独立、抽样覆盖、样本量/区间、训练与调参是否适配测试集 |
| “A 的某项能力更强” | 对所选任务操作化的成功率 | 任务对构念的代表性、指标是否遗漏重要属性、不同任务/指标的会聚证据与反例 |
| “A 能迁移到真实使用或长任务” | 受控基准中的执行证据 | 环境、用户目标、工具、反馈、预算、失败恢复与安全约束和目标场景的对应关系；目标场景实测 |

**小样本下的分差尤其需要区间。** 对小型、专门构造的评测集，正态近似或普通 bootstrap 的区间可能低于名义覆盖率；按总体题数计算区间也可能把同一材料下的问题簇误当作独立样本。Bowyer 等人的 ICML 2025 Spotlight position paper 在多种模拟设置中比较区间覆盖率：在一个 IID 二元准确率例子里，N=100 时名义 95% 的 CLT 区间实际覆盖率为 92.5%；聚类问题、成对模型比较和 F1 等非线性指标也需要显式建模其依赖或指标结构。作者在所考察的小样本条件下推荐 Wilson 区间或 Beta-Bernoulli 区间处理单模型二元准确率，并以聚类或成对贝叶斯模型处理更复杂设计；这些是该文模拟和模型假设下的建议，不是适用于所有任务的固定样本阈值。区间只量化既定抽样/模型假设下的不确定性，不能补上不具代表性的抽样或污染审计。[S9 §3.1–3.5, §4, Figures 2–6]

将“能力”从任务分数中读出来，风险在于 benchmark 可能同时漏掉目标构念的重要部分（构念代表不足），也可能奖励与目标无关的线索（构念无关变异）。因此，效度不是一张基准固有的“通过证书”，而是针对某个分数解释和用途建立、允许被反例削弱的论证。[S1 §3, §6.2；来源定位见 sources/MANIFEST.md]

### 构念效度与任务真实性

HELM 展示了一种更透明的设计：先说明任务、领域、语言组成的场景空间，再按覆盖、最小化和用户任务相关性选择场景；同时跨准确率、校准、不确定性、稳健性、公平性、毒性和效率等维度测量，而不是压成一个唯一分数。作者在该版本中评估 30 个模型，标准化覆盖 96% 的“模型 × 核心场景/指标”单元，并报告场景与指标之间的取舍。[S2 §1.1–1.2, §3.1, Figure 3]

这能让读者看到“评了什么、没评什么”，但不会自动证明这些场景覆盖了通用语言能力，也不会消除场景选择中的价值判断。HELM 自己明确保留未覆盖区域，且采用 few-shot prompting 等具体适配方案；换任务、提示或运行条件时，不应把其分数照搬为部署能力结论。[S2 §3.2, §7, §11；来源定位见 sources/MANIFEST.md]

### 用途决定最低有效证据

同一分数可以适合一个窄用途、却不足以支持更广泛用途。例如，一个可自动判定的数学测试可能适合比较特定题型中的答案正确性；它不能单独证明模型有稳健的数学推理能力，更不能证明它能在开放任务里规划和纠错。报告结论时，先写清“要推断什么”，再列出这一推断需要的子步骤和可推翻证据。2026 年的效度框架将常见子推断分为 generalization、extrapolation、conceptualization、predictability 与 decision；其中广泛能力/部署推断要求逐步增加条件，不存在由排名自动获得的通用效度。[S1 §3, Table 1, §6.4]

## 2. 污染、适应性复用与饱和：分数为何会失去区分力

污染的核心问题不是只有“训练集里有没有完全相同的测试字符串”。训练数据暴露可表现为精确重复、改写/变体、答案或近似题泄露；另一个相关但不同的问题，是团队在公开基准上反复挑提示、解码或模型选择，形成评测适应。不同形式的检测难度与分数影响并不相同。Palavalli 等人的分类及摘要/问答案例说明，不能把某个 n-gram 重合阈值当作通用清洁证明。[S3 摘要、§2–5；正式会议版本见 ACL Anthology]

污染结论应按“审计找到什么”来写，而不是把 benchmark 简单盖成“干净/不干净”。原文指出，常见重合检测往往需要访问训练语料、对较长序列或成簇样例才敏感；无训练语料的方法也依赖测试材料未被改写或分散等假设。因此，某个检测器没有命中，只能说明它没发现自己覆盖到的污染形式，不能证明训练数据中不存在改写、拆分或答案侧暴露。[S3 §2.1–2.2、§2.4]

| 观测或做法 | 能支持的判断 | 不能单独支持的判断 |
|---|---|---|
| 在可访问训练语料中发现测试项或其改写 | 该语料/检测范围内存在相应暴露；还需看模型、训练阶段和暴露形式，才能估计对分数的影响 | 所有高分都由污染造成，或污染幅度可由重合比例直接读出 |
| 对语料、模型或公开元数据运行检测但未命中 | 未发现该检测器能捕捉的形式 | “训练集无污染”；尤其不能排除改写、分布式暴露或检测假设不成立的情况 |
| 使用近期题目或滚动更新 | 降低旧题长期公开带来的直接复用机会 | 新题必然未泄露，或新旧版本分数处在同一难度量尺 |

还要把**训练数据污染**和**评测适应**分开：前者询问测试样例或答案是否进入训练过程；后者询问团队是否反复依据公开基准挑提示、解码设置或模型。HELM 将 prompt adaptation 作为需明确的评测条件，污染分类研究也把先验任务理解与样例污染分开讨论；没有精确文本重合，不等于评测选择过程没有适配该基准。[S2 §2.2、§7；S3 §2.1–2.2] 这属于证据类型区分，不应把后者未经审计地称为“训练污染”。

LiveBench 的设计回应是让问题依赖近期竞赛、论文和数据集，定期更新，并优先采用可验证的 ground truth 自动评分；论文规定按月替换约六分之一题目，使题集约每六个月完整更新一次，新题延迟一个月公开。论文分析了两次月度更新：相邻版本的模型排名相关均高于 0.997；但从最初版本到最新版本，在每轮榜单都出现的模型中，平均分和中位数平均分都下降约 1.2%。这些是有限版本与模型集上的作者报告值，不证明未来版本间必然可比或不可比。[S4 §2.7, §3.4, §5–6, Appendix A.6–A.7]

但“更新”不是构念效度或无污染的替代品：新题仍可能只覆盖可自动判分的能力；论文也承认 ground-truth 不能胜任旅行指南等开放生成任务，不含非英语任务，且不同模型家族仍可能偏好不同 prompt。作者还说明少数代码题来自 2023 年 11 月、部分 AMC 题只做了较低程度的改写，因此承认基准仍有一小部分可能被近期模型污染。更新分析显示排名相关很高、分数水平略降，提示读者区分排名稳定与原始分数跨版本可比；报告固定版本，或说明量尺如何链接，是本文据此提出的复核要求，不是论文已经验证的结论。[S4 §3.4, §5, Appendix A.6–A.7；跨版本报告建议为本文推断；来源定位见 MANIFEST](sources/MANIFEST.md)

**饱和也不等于能力耗尽。** 高分天花板会让基准难以区分模型，低分地板也会压扁差异；反过来，某套题分数尚低并不保证它代表真实能力瓶颈。WildClawBench 对最终 60 题的筛选包含先跑模型再保留有区分度的任务（最大模型间差距至少 0.2），这是减少 ceiling/floor 的有意设计；这也提示题集区分力应在新模型群或不同用户群上重检。[S5 §3.3, Figure 4；关于候选模型筛选的外推边界为本文推断]

## 3. 评分者协议与误差来源

MT-Bench/Chatbot Arena 的奠基研究给出了支持 LLM-as-judge 的正面证据，也测出了它的边界。MT-Bench 为 80 道多轮问题、8 类任务；受控人评涉及 58 名专家级标注者和约 3,000 张票。该论文在无平票设置 S2 下报告 GPT-4 与人类一致率 85%，人类彼此一致率 81%。Arena 侧则从 30,000 人类投票中抽取 3,000 票，由 2,114 个不同 IP 的众包用户贡献。它支持的是特定问答类型、judge 版本、prompt 和比较协议下的偏好近似，不是“LLM judge 等同于专家”的普遍结论。[S6 §2–4, Table 5; Appendix C]

可靠度至少分三问：同一 judge 重跑是否稳定（重复信度）；不同 judge 是否一致（评判者间信度）；判断是否对准任务目标且不偏袒某种位置、长度或表达风格（效度/偏差）。Shi 等人在 MTBench 和 DevBench 的 15 个 judge、22 类任务、约 40 个候选模型、超过 150,000 次评判中发现，一些强 judge 的重复稳定性 RS 超过 0.95，但位置一致性与偏好公平随 judge、任务、候选质量差距而变化；重复稳定只能说明“稳定地这样判”，不能说明“判得对”。[S7 v9 §1, §2.2–2.3, §3.2–4, Table 2, Figure 2]

位置交换是有用的诊断，但不是完整修复。Zheng 等人在相似答案的 MT-Bench 子集里，GPT-4 对调顺序后一致率只有 65.0%；few-shot 后升到 77.5%，但 GPT-3.5 的偏向由第一位转向第二位。更重要的是，位置偏差在接近的候选模型、开放式写作或知识题中更突出；大质量差距可掩盖偏差。这说明平均一致率会随问题难度和候选组成变化。比较前后版本时应报告 tie 处理、位置交换、重复次数、人工抽样复核和 judge 版本。[S6 §3.3–3.4, Appendix D.1, Tables 2, 11–13]

对 pairwise judge 还要区分“判得一致”与“恢复整体排序”。Brocai 与 Becker 在 Bradley–Terry 设定中指出，位置翻转、非传递性及逐对 agreement 等等权指标容易被接近的质量对主导；但对排序恢复影响较大的错误，往往出现在人类金标准差距较大的 pair。其模拟让不同 judge 的逐对人类一致率都为 60%，只改变错误落在近差距还是远差距 pair 上，恢复出的金标准排序却明显不同。两个教育文本语料上的六个 judge 对照也显示聚合不一致指标与人类排序相关性不稳定；far-pair consistency 与排序相关性在 12 个“judge × corpus”点上的相关为 0.897（Holm 校正 p=0.001），而总体一致性相关不显著。该研究的实测只含 Clear 与 ASAP 2.0 教育语料、12 个 judge-corpus 点，且作者承认对中等关联的检验力有限；它说明应按 pair 难度报告指标并直接检查排序恢复，不说明近 pair 的偏差无害。[S10 §3–5, Tables 1–2; Limitations；来源定位见 sources/MANIFEST.md]

**实践判据（据上述研究的建议）**：对开放回答，至少保留人类校准子集和 disagreement/置信度；对可判定事实、文件或环境副作用，优先用执行器、状态检查和可执行 rubric，judge 只处理无法规则化的语义部分；报告 judge 与人类的一致指标及抽样方式，并审计位置、长度、自偏好和 prompt 敏感性。人类标签也需说明任务专家性、标注指南、平票处理和标注者间差异；“人类金标准”本身不是免检前提。[S6 §4; S7 §2–4]

若最终用途是模型排序，除了总体 agreement，还应报告排序与人类金标准的对应，并在可估计质量差距时按近/远 pair 分层呈现位置翻转与分歧；小样本 judge 比较须把有效独立单位（题目、文本、任务或用户）和区间方法一并交代。S10 的仿真说明错误所在的差距区域会改变排序损失，不能据此忽略近 pair、把争议都当作 tie，或免做位置偏差校准。[S9 §3.3–3.4; S10 §4–5]

## 4. Agent 与机器人：外部效度取决于闭环中的什么被保留

静态问答通常把输入固定，模型只产生一次回答；agent 需要经过工具、状态、时间预算和失败反馈完成任务。最终答案对错可能漏掉“是否真的写入文件/改变环境”“是否越权”“轨迹是否可审计”这些部署属性。Agent 评测因此至少应描述任务目标、环境状态、工具权限、交互轮数、重试、时限、成本、评分器与终止条件，并区分模型能力与 harness/工具链的共同效果。

交互评测的**环境可重置**与**agent 可重复成功**是两种证据。τ-bench 固定数据库状态并让 GPT-4 用户模拟器以温度 1 产生多轮互动；其 `pass^k` 估计同一任务随机抽取 k 次都成功的概率，和只要求至少一次成功的 `pass@k` 不同。主结果表至少运行三次/任务；Figure 4 的曲线画到 k=32，但确切试次数及区间没有讲清，因此适合支持“重复成功会下降”的机制判断，精确曲线不宜过度解读。它的最终数据库状态与回答必需信息组成二元奖励，作者承认未被检查器编码的政策违规仍可能拿到满分。[S12 §3、§5.1 Table 2/Figure 4；[原文精读](papers/2406.12045-tau-bench.md)]

桌面和网页基准提供互补的环境/判分设计。OSWorld 通过 VM snapshot 与配置重建初态，再由逐任务 evaluator 检查最终文件或应用状态；WebArena 通过 Docker image 恢复站点状态，操作任务按数据库、API 或页面属性核验，信息任务则混用 exact、must-include 和 GPT-4 fuzzy match。两篇原论文的主模型结果都没有报告同一任务多随机运行的 `pass@k`、均值/方差或置信区间；OSWorld 的多轮任务审查、WebArena 的任务模板变体都不能替代这种重复试验。[S13 §2.2–§4.1 Table 5; S14 Appendix A.2, §3.2/Table 1, §5.2/Table 3；[OSWorld 精读](papers/2404.07972-osworld.md)；[WebArena 精读](papers/2307.13854-webarena.md)]

这些设计还暴露出终态 checker 的边界：状态正确不必然证明策略合规；有限样本的人工作业检查也不能证明所有 evaluator 无误。OSWorld-Verified 维护者在 2025 年公告中称处理了 300 多个社区问题，并集中重测、修订任务和评估函数；这说明任务与 checker 需要持续维护。该版本记录应和 2024 年原论文结果分开报告，维护者发布的重测也不等于独立第三方复现。[S12 §3; S13 §3.2; S14 Appendix A.8; S15；来源定位见 sources/MANIFEST.md]

WildClawBench 是 2026 年值得纳入的案例：arXiv v1（2026-05-11）报告 60 个双语、多模态、人工编写任务，6 类场景，平均约 8 分钟、20 余次工具调用；任务运行在容器化的 CLI agent runtime，涉及 bash、浏览器、文件、邮件和日历等工具。评分组合确定性规则、环境副作用审计和 GPT-5.4 语义评分；ground-truth 资源在 agent 退出后才挂载。作者在 OpenClaw harness 下评测 19 个模型，最高分为 Claude Opus 4.7 的 62.2%；另在四个代表模型上比较四种 harness，其中 MiMo V2 Pro 在 Claude Code 与 Hermes Agent 间相差 18 个百分点。这直接提醒读者：agent 结果的测量对象常是“模型 + harness + 工具 + 环境”的组合，而非孤立模型。[S5 摘要、§3.1–3.4、§4.1–4.3, Tables 2–3]

这仍不能推出生产部署泛化：论文承认任务都以单轮指令开始、没有用户中途澄清/纠正；60 题对真实部署覆盖仍有限，GUI 密集型控制及生物、金融、法律等专家工作流代表不足。GPT-5.4 judge 的人评一致性案例只抽取 5 个需要 LLM judge 的任务，由两名独立专家盲评并使用同一 rubric；这只是小样本案例，不是对整套语义评分的外部效度验证。[S5 Appendix B, H]

真实用户来源与真实交互评测也需分开。RealWebAssist 从 10 名美国大学校园参与者各 40 分钟的真实网页辅助会话中整理出 1,885 条连续指令、107 个任务和 66 个网站；任务保留用户改主意、跨页指代和反复交互等现象。作者在离线回放中用当前网页截图和历史记录评估动作是否落入人工标注点击区域；在其模型设置中，最高任务成功率为 14.0%、平均进度为 28.7%，同一数据集的人类操作员结果为 93.4%。因此它为静态单指令任务补上了真实用户指令来源和长序列历史，但仍测的是受控离线点击，而非 agent 与用户/网站的在线闭环：参与者规模和多样性有限，没有 assistant-user 对话，模型实验用 ground-truth captions 而不是语音交互；历史截图由 GPT-4o 摘要成文字，模型只收到当前页截图。这些条件是结果的测量边界，不构成生产使用能力的估计。[S11 Abstract, §§3–5, Table 1–2, Limitations]

机器人评测把外部效度问题推到物理执行层。VLA 现有专题的 SIMPLER 原文总结指出：仿真应作为成对 sim/real 策略排序或回归筛选证据，原作者的目标是排序相关，而非让仿真绝对成功率替代真机成功率。真机还需控制本体、相机、控制频率、初始摆位、trial 数、成功判据与人工判分；这些条件变动会改变测量对象。[S8 §I、§IV、主实验表；详见本库 [VLA 评测专题](../../WorldModel/EmbodiedVLA/topics/evaluation-and-datasets.md)]

**跨领域综合推断**：两类交互评测相通之处是，成功必须在状态变化后由环境验证，且部署依赖策略与环境的闭环；差别在于 agent 环境的工具、权限、接口、外部服务及用户纠正，机器人环境则有本体、传感、接触物理与安全边界。它们不宜用同一个“真实性分数”概括，但都要求复现环境版本和执行协议，并在目标环境中做外部验证。[S5 §3–4, Appendix B; S8 §I, §IV; 来源定位见 sources/MANIFEST.md]

AI for Science 还要求把**候选优化**与**科学解释验证**分开：代理模型上找到高分候选，不能替代新实验；用极端样本检验某个机制，也不能自动给出总体命中率。闭环择样、独立测试和机制干预的具体证据阶梯见[AI for Science 发现评测专题](../ScientificDiscovery/report.md)。

## 5. 主张检查建议

| 发表或引用的句式 | 最低限度需随句给出的证据 |
|---|---|
| “模型 A 在基准 B 高于模型 C” | benchmark 固定版本、checkpoint/API 日期、提示与解码、样本量及有效抽样单位、split、指标/平票规则和适配设计的统计区间；确认测试是否参与训练、调参或反复择优 |
| “A 在未见同类问题上更好” | 对应总体的抽样或时间切分、污染/适应性审计、样本和不确定性；说明为何这一总体就是目标人群 |
| “A 的能力 X 更强/可泛化” | 操作化 X 的构念定义；多个互补任务/指标的会聚与分歧、反事实/扰动测试、构念漏项清单；限制到证据覆盖的范围 |
| “A 可用于生产或真实环境” | 目标场景任务分布、真实用户/工具/状态的代表性、长时程和失败恢复、安全/权限审计、时延/成本约束、独立实测或前瞻性验证 |

若证据只覆盖第一行，就写“在 B 的 vX、协议 P 下 A 得分较高”。不要把统计显著性、榜单排序、题目新鲜度或 judge 与人类的高总体一致率单独升级成“能力更强”的证明。

## 6. 未解决问题

- 对多 benchmark 的结果如何聚合：单一平均分可能抹去维度冲突、不同误差成本和使用者价值选择。[S1 Table 1 注脚；S2 §1.1]
- 动态 benchmark 如何保持时间上的可比性，同时避免题集公开后污染；何时应按版本分开报，何时可以用校准集链接量尺。[S4 §5–6]
- judge 经过 prompt / rubric / model 更新后，怎样做跨版本校准和审计自偏好；同意率、重测信度、排序恢复、pair 难度分层和被审属性效度如何同时报告。[S6–S7, S10]
- agent benchmark 在什么任务与用户采样设计下能代表真实工作流；离线真实用户记录、模拟交互环境与在线运行数据如何共同支撑部署推断。[S5 Appendix B; S8; S11]
- 交互任务应采用何种重复次数与抽样单位；如何同时报告 `pass^k`/`pass@k`、任务态、政策约束和随机用户模拟器带来的变化；基准 checker 修订前后怎样保持可比。[S12–S15]
- 更广泛跨学科框架如何纳入基准策展者、受影响群体和决策后果；现有测量效度框架本身没有穷尽这些社会维度。[S1 §6.3]
