# 精读：独立实现 FunSearch——复现、基准污染与跨尺寸测试

## 亮点与差异

- **一句话亮点**：数学家给出更易配置的 FunSearch 实现，并以重复运行、多个模型和变体任务检验其是否可复现、是否会迁移。
- **新在哪**：相对原论文的发现案例，这篇将“模型能否重现已有数学记录”和“程序是否学到可迁移策略”分开测试，并明确指出已公开记录可能进入后来模型训练数据。
- **证据强度**：每项主要基线做 8 次独立运行并比较不同 LLM；相同相对 token 预算并不让模型具有相同实际延迟或训练语料。原 cap-set 512 记录在被测条件下未复现。
- **值不值得引用**：适合讨论数学评测的数据污染、重复次数、问题改写与同尺寸/跨尺寸泛化；不是对原 FunSearch 构造正确性的复现审查，也没有推出新的记录。

## 1. 解决什么问题

原始 FunSearch 的 8 维 cap set 512 是有效的新构造，但后续 LLM 再生成相似代码时，怎样区分独立搜索与从公开内容中复现/记住？第二个问题是：FunSearch 是否能在别的组合/数论任务和不同规模下稳定工作？本文做独立实现和基准诊断，而非声称重复做出一个新记录（v2 §§1、3–4）。

## 2. 核心方法

仍用 `priority`—`solve`—`evaluate` 设置：演化 LLM 编写的 priority 程序，固定人写的构造器和 evaluator；程序经执行和计分后进入按分数抽样的 island population，后续提示样本驱动新函数生成。新实现扩展为任意签名程序搜索、多供应方/混合模型、异步多核评估与可配置容器沙箱（§§1–2）。

在 cap set 示例中，`solve` 以优先级贪心添加点，并跳过会出现三点和为零的候选；evaluator 返回最终集合大小。论文也使用 priority 筛法找窄 admissible tuple，以及在 `n×n` 网格贪心生成无等腰三角形点集（§3.1–3.3）。它们仍由人类决定目标函数、固定算法骨架和评估口径；模型负责排序规则而不是自由提出数学命题。

## 3. 数据与规模

- **三个问题**：cap set（8 维，已知记录 512）；窄 admissible tuple（`n=5000`，已知分数 672）；无等腰三角形格点集（`n=64`，PatternBoost 已有 110 个点）（§3、Tables 1–3）。
- **重复/模型设置**：cap set、窄 tuple、no-isosceles 各列 7 个 LLM，每模型 8 次独立运行，每次 `2×10^6` relative tokens；每轮配置 16 samplers、16 evaluators、15 分钟 island reset（§4.1、Tables 1–3）。Relative-token normalization 使模型间预算单位可比于所采用价格比例，不保证实际训练数据、延迟或推理难度相等。
- **更长运行**：Gemini 2.0 Flash 在每题 `10^8` relative tokens 单次长跑，与 `8×2×10^6` 的多次短跑对比；Table 4 记录三个任务的一次长跑结果（§4.1、Table 4、Fig. 2）。
- **泛化测试**：no-isosceles 在单一 `n`、一段尺寸、随机尺寸训练后，测试 priority 在训练尺寸以外的集合大小；另设 random priority 作无训练贪心基线（§4.2、Figs. 3–4）。

## 4. 主要结果（带条件）

- **Cap set**：8 次运行的每模型最佳成绩约 316–448；已知 512 纪录未被这些设置达到（Table 1）。作者也明确担忧训练在原 FunSearch 发表之后的 LLM 可能已见过 512 生成程序（§3.1）。
- **Narrow admissible tuples**：`n=5000`、每次 2M relative tokens，模型最佳成绩 410–582，仍低于表中已知 672（Table 2）。
- **No-isosceles**：`n=64` 下各模型最佳成绩至多 96，PatternBoost 的参考分数为 110；作者说明 PatternBoost 从一个由非 LLM 方法生成、规模较大的种群起步，且该文给 FunSearch 分配的计算资源更少（§3.3、Table 3）。因此是资源条件不同的参照，不是等预算败北结论。
- **预算与运行数**：对 Gemini 2.0 Flash，三项任务各自的 8 次短跑中最好一次优于 Table 4 单次 `10^8` token 长跑；长跑不是随样本单调改善（§4.1、Table 4、Fig. 2）。作者猜测 prompt 反复携带既有候选导致路径依赖，但未把这一机制单独证明。
- **跨尺寸迁移**：训练出的 no-isosceles priority 在未见尺寸上超过 random-priority；混合多个训练尺寸在该试验中没有显示更好迁移（§4.2、Figs. 3–4）。不过模型通常未找到已知最优集，且对大型网格结果弱于 PatternBoost。

## 5. 消融 / 对照说明了什么

1. **同一预算改变 LLM 提议器**：不同模型在三个问题的最高分不同；论文报告模型成本与表现没有稳定相关性。该比较不控制各模型预训练数据或接口特性（§4.1、Tables 1–3）。
2. **重复运行**：每模型 8 seeds 展示最佳/最低/平均最好分及命中已知 best 的次数，证明最高分有明显方差；单一成功记录不等于稳定复现（Tables 1–3）。
3. **短跑多种子 vs 长跑单种子**：相同模型在 `8×2M` relative token 多次运行与 `100M` 一次长跑相比，若干任务短跑最好结果更高，支持探索路径/岛重置等因素可能比单次增加预算重要；两种安排不是完全等量的重复实验（Table 4、Fig. 2）。
4. **训练尺寸 / random priority 对照**：训练函数在未见尺寸上超过随机优先级，但多尺寸训练没有明显改善迁移；这说明出现了可迁移启发式，但不等于学到尺寸不变理论或找到最优集（§4.2、Figs. 3–4）。

这些是复现实验、基线或任务设置对照，并没有将所有 FunSearch 组件做正交、等算力的因果消融。

## 6. 失效条件与边界

- **未复现 512**：被测模型/参数下没有达到 cap-set 既有值；原文同时指出该程序公开后可能成为训练数据。这既不能声称已独立复现，也不能推翻原始构造的正确性（§3.1、Table 1）。
- **离最优仍有差距**：narrow tuple 未达到 672；no-isosceles 的最高 96 低于 110，而且在该任务上未达到 SAT 可求出的多个小尺寸最优值（§3.2–3.3、§4.2）。
- **单次长跑不一定改善**：Table 4 的三次任务结果不同方向，不支持“更多 token 必然更好”；作者提出路径依赖作为解释而非定论（§4.1、Fig. 2）。
- **评估可复现性**：Relative tokens 是本论文所定模型预算换算口径，供实验内比较；它不等于实际相同成本/墙钟时间，模型/provider、样本温度与此前训练语料仍会影响结果。

## 7. 与同类系统的可判定差异

这篇是数学家团队做的**FunSearch 实现与系统评测**，不是原始的 discovery 结果论文：它公开了配置更简单、可选 LLM 多的实现，展示不同问题、模型、seed 与问题尺寸下性能会怎样变。与原论文相比，它没有重现 8 维 512 记录；与只报告最好一次的论文不同，它系统列出重复运行分布、失败和污染风险。其主要贡献是阅读模型发现时的复现与基准方法，而非一项新构造定理。
