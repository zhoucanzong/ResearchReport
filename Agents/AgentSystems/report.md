# Agent 系统：让模型在环境中持续完成任务

Agent 不是一种单独的模型结构，而是模型围绕目标观察环境、选择行动、接收反馈并继续决策的系统。读 Agent 论文时，先问它改动了这个闭环的哪一处：控制流程、任务记忆、工具选择，还是动作后的评估？不同论文即使都使用多个模型或“记忆”一词，解决的也可能是不同问题。

本专题从基础控制循环读到 2026 年的记忆、工具与执行恢复研究；重点是机制、实验能说明什么，以及哪些环节仍未被测到。推荐顺序见文末。

## 先看一个最小闭环

```mermaid
flowchart LR
    G[目标与当前状态] --> M[模型决策]
    M --> A[工具或环境动作]
    A --> O[新观察与执行结果]
    O --> G
    O -. 跨步骤保留 .-> H[短期 / 长期记忆]
    H -. 相关上下文 .-> M
```

ReAct 的关键是把推理、动作和观察交替放进同一轨迹。它让模型能根据环境结果调整下一步，但每次观察仍可能错、工具也可能失败。原论文在 ALFWorld 报告的 71% 是最佳提示配置的结果；与 BUTLER 的 37% 相差 34 个百分点，但提示选择预算并不相同，这不是 ReAct 对任意 CoT 系统的通用增益。[ReAct, v3, §4, Table 3](https://arxiv.org/html/2210.03629v3)

Reflexion 将一次尝试得到的语言反馈写成 episodic memory，供后续尝试参考；它改变的是跨尝试的经验利用，不是模型权重。AutoGen 展示可定制的多 Agent 对话编排，也没有证明增加角色数量本身会提升可靠性。[Reflexion, v4, §3–5](https://arxiv.org/html/2303.11366v4) · [AutoGen, v2, §2–4](https://arxiv.org/html/2308.08155v2)

这给出一个基础区分：ReAct 改的是**决策与反馈的次序**；Reflexion 改的是**经验如何进入下一次尝试**；多 Agent 框架改的是**任务如何在角色间分工**。评估它们时应控制模型、任务、工具和总尝试预算。

## 长任务为何把“记忆”变成策略问题

短任务可以把所有状态留在当前上下文；长任务则会遇到事实被挤出、历史信息过期、用户偏好分散在多轮对话等问题。2026 年的几篇论文把记忆问题拆成了不同阶段：

| 研究对象 | 方法改变了什么 | 论文证据能说明什么 |
|---|---|---|
| **AgeMem：决定如何管理记忆** | 将添加、更新、删除长期记忆，以及检索、摘要、过滤当前上下文做成策略可选的动作；用三阶段强化学习逐步训练长短期记忆协调。[精读](papers/2026-acl-long-981-agemem.md) | 在 ALFWorld、SciWorld、PDDL、BabyAI、HotpotQA 等受控任务上，完整方法优于其报告的无记忆与消融配置。真实长期用户交互仍未被覆盖。[ACL 2026, §3–4, Table 2, Figure 4](https://aclanthology.org/2026.acl-long.981/) |
| **JAM：为当前请求构造记忆上下文** | 离线保留原始历史并建立轻量导航结构；请求到来后由 Researcher 搜索、查看证据并组合上下文，再交给下游 Agent。[精读](papers/2609.34385-jam.md) | 在多种记忆与长上下文任务上报告结果，并用三个随机种子检查推理波动。它研究上下文构造，不等于证明下游 Agent 能可靠完成真实工具操作。[arXiv v1, §2–4, Appendix B.5](https://arxiv.org/html/2609.34385v1) |
| **TEPA：撤销已经失效的经验** | 给记忆项显式标注候选、可检索、已撤销状态；按同一冲突键累积新证据，决定旧值何时退出活动记忆。[精读](papers/2608.07429-tepa.md) | 在隐藏规则反转与文件执行设置中，撤销机制显著优于保留旧值的基线；但依赖可识别的冲突键，多跳与超长上下文结果很弱，不能视作通用记忆纠错。[arXiv v2, §3–5, Table 2, Figure 4, Table 5](https://arxiv.org/html/2608.07429v2) |
| **Mem2ActBench：记忆能否驱动工具参数** | 从对话历史中分散的事实恢复约束，再将它们落到工具选择和参数上。[精读](papers/2026-acl-long-370-mem2actbench.md) | 被动检索与 oracle 证据的参数 F1 差距显示，在该离线基准上，找对记忆是主要瓶颈之一；基准并不执行工具，也不观察动作后的环境反馈。[ACL 2026, §3–5, Tables 1–6](https://aclanthology.org/2026.acl-long.370/) |

AgeMem 与 JAM 都研究 Agent 如何使用记忆，但干预点不同：AgeMem 让策略决定**何时写、删、取或压缩**；JAM 训练一个针对当前查询**逐步找证据并构造上下文**的子过程。Mem2ActBench 则提醒我们，检索到信息和把信息正确用进行动参数是两种能力。不能用一个记忆问答分数替代完整的行动能力。

TEPA 补上另一个状态问题：记忆可能仍与当前任务相关，却已被环境变化证伪。它显式撤销旧经验，说明“召回得准”不足以保证“当前仍有效”；不过它的主要机制依赖同键冲突与受控漂移，隐含矛盾和关系链变化仍未解决。[TEPA, §3–6](papers/2608.07429-tepa.md)

## 工具越多，选择本身也需要研究

工具调用通常包含任务规划、工具选择、参数生成和工具执行。ToolScope 研究执行前的工具目录：它先合并语义重叠的工具，再按当前请求检索和排序候选项，减少选择歧义与传入上下文的工具数量。[ToolScope 精读](papers/2026-acl-long-1573-toolscope.md)

作者在 BFCL、Seal-Tools、UltraTool 上报告工具选择指标改善；收益随基准的候选集规模与冗余程度而变。这支持“整理候选工具可能改善该评测中的选择”，不说明工具执行正确、授权安全或端到端任务成功。MCP 一类协议负责能力发现与消息交互，也不能替代模型选择、宿主授权和执行结果校验。[ToolScope, ACL 2026, §3–4, Tables 2–6](https://aclanthology.org/2026.acl-long.1573/) · [MCP Architecture, 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/architecture)

### 多 Agent 之间的信任边界

单个 Agent 保留了工具来源与权限信息，不代表编排器把结果交给另一个 Agent 时仍保留这些属性。Multi-CaMeL 把父子调用拆成可信指令 `message` 与带来源/能力信息的 `variables` 两条通道，由解释器阻止工具输出进入可信控制流。它把安全目标限定为**控制流完整性**：不可信观察可以影响既定计划的数据分支，但不能凭空新增计划外的工具调用。[精读](papers/2610.05640-multicamel.md) · [arXiv v1, §§II–IV](https://arxiv.org/html/2610.05640v1)

在 MultiAgentDojo 的 949 个注入实例配置中，五个后端模型的平均攻击成功率由无 CaMeL 的 12.9% 降至 Multi-CaMeL 的 0%；这是该基准上的观察，不是对自适应攻击的通用保证。实验使用空安全策略，因此没有实证验证“用户是否授权发送给该收件人”。该方法主要保护 Agent 间的数据/指令边界，不等于完成目的地授权、审批或外部副作用补偿。[Multi-CaMeL, §IV–VI, Table III](papers/2610.05640-multicamel.md)

单个 Agent 的间接注入威胁模型、运行时来源/capability 防御与上下文相关攻击见独立的[Agent 安全专题](../AgentSecurity/report.md)；本节只说明 Multi-CaMeL 的跨 Agent 边界。

## 工具出错后：诊断、恢复和学习恢复是三件事

失败不等于同一个事件。执行轨迹可以先出现一次无害的无效调用，之后 Agent 仍然恢复；真正阻断任务的往往是更早的错误状态或错误假设。因此，**找出错误、恢复环境状态、改变模型后续策略**需要分别研究。

| 方向 | 改变的环节 | 阅读时要保留的边界 |
|---|---|---|
| **AgentRx：定位不可恢复的关键失败** | 从轨迹、工具 schema 和策略约束生成逐步校验，再让 judge 结合证据判断最早导致任务无法完成的步骤与原因。[精读](papers/2602.02475-agentrx.md) | 诊断失败不等于修复失败；弱或下游的约束信号会把 judge 引向错误根因。[arXiv v2, §§2–4、§7](https://arxiv.org/html/2602.02475v2) |
| **AgentRewind：恢复到一致的上下文与工作区** | 在运行时保存上下文和受控文件工作区的配对检查点；选定检查点后恢复两者，并把失败经历的摘要带入新轨迹。[精读](papers/2608.14380-agentrewind.md) | 能回滚工作区文件，不能撤销网络请求、外部服务副作用或所有 Git 状态；是否 rewind 仍由 Agent 决定。[arXiv v1, §3、Appendix C.5](https://arxiv.org/html/2608.14380v1) |
| **Fission-GRPO：训练模型从工具错误中恢复** | 把当前策略产生的失败轨迹交给 Error Simulator 提供诊断反馈，再从“原对话 + 失败调用 + 反馈”重采样恢复轨迹，形成 on-policy 修正训练。[精读](papers/2026-acl-long-1880-fission-grpo.md) | 这是训练期恢复能力，不会回滚真实环境状态；实验限于交互式工具调用基准。[ACL 2026, §3–4、Tables 1–3、Limitations](https://aclanthology.org/2026.acl-long.1880/) |

这三类方法互补而不等价：AgentRx 试图回答“哪一步使这条轨迹走不通”，AgentRewind 回答“能否从仍可控制的状态重新开始”，Fission-GRPO 则回答“能否让策略下次更会处理错误反馈”。它们的机制、实验与边界见[长程执行恢复综合](topics/long-horizon-execution-recovery.md)。如果外部副作用不可回滚，系统还需要幂等操作、补偿机制或人工确认；这属于环境与工具契约，不能由模型学会重试替代。

## 评分器也可能改变“成功”标签

即使轨迹固定，奖励或终态检查器也可能通过重置环境、执行参考动作等过程改写它随后要评分的状态。Oracle Integrity 论文把评测 harness 当作待测软件，检查评分前后状态不变量、重复判分一致性和已知答案控制，并在发现缺陷后重放已记录的工具动作修正标签。[精读](papers/2610.16067-oracle-integrity.md) · [arXiv v2, §§3–5](https://arxiv.org/html/2610.16067v2)

在该论文审计的 4,320 条归档轨迹上，修正后的成功率从原标签 94.3% 降至 65.5%，足以改变模型比较的观测结果；范围只限 30 个 retail 任务、一个服务方及可重放的历史调用。重放不能自动迁移到不可重置或有不可逆外部副作用的环境。它补足 AgentRx 的轨迹根因诊断：先确认 oracle 正确读取了环境状态，再解释 Agent 为什么失败或恢复。

## 目前最值得继续追问的地方

- **记忆的纠错与时效**：TEPA 展示了显式冲突键下的撤销，但隐含矛盾、跨属性传播、证据来源可靠度和错误撤销后的再晋升仍缺少长期实证。
- **检索到使用之间的断层**：证据可能被漏取，也可能已经取到却没有进入参数或计划。记忆评测应分别观察证据命中、参数落地与执行后的状态，而不是只看最终回答。
- **从诊断走到可恢复闭环**：离线轨迹诊断、文件工作区回滚和训练期错误修正覆盖不同环节；仍缺跨越真实 API 部分成功、权限拒绝和外部副作用的统一实验。Multi-CaMeL 保护计划外动作不被注入新增，尚未覆盖真实用户授权与补偿流程。
- **测量与行为分开**：Agent 的随机轨迹、执行恢复、工具权限和 oracle 正确性是不同误差源；目前没有同一环境下同时测量这些因素的比较研究。
- **架构收益和额外计算**：反思、多 Agent、运行时检索都增加步骤。比较时应报告相同任务与预算下的收益，并解释多出来的调用到底解决了哪类失败。

因此，当前文献更支持一套分层观察方式：先检查模型是否选对行动，再检查记忆是否提供了足够证据，最后检查执行反馈能否促使系统纠正状态。它尚未给出通用 Agent 的最佳架构。

## 推荐阅读顺序

1. **ReAct → Reflexion**：理解交错行动循环与跨尝试记忆两个基础机制。
2. **AgeMem → JAM**：比较策略内的记忆操作和查询时的证据构造。
3. **TEPA → Mem2ActBench**：从记忆是否仍有效，读到证据如何转化成工具参数。
4. **ToolScope → Multi-CaMeL**：先看如何筛工具，再看多 Agent 间如何保留指令与数据边界。
5. **AgentRx → AgentRewind → Fission-GRPO**：先定位不可恢复失败，再对照运行时回滚和训练期恢复。
6. **Oracle Integrity**：检查评测器和环境重放是否可靠，再解释 Agent 的成功率。
7. 再读图书馆的[评测科学](../../Evaluation/EvaluationScience/report.md)与[具身 VLA](../../WorldModel/EmbodiedVLA/report.md)，分别理解 Agent 测量和动作策略的边界。
8. 若关注实际电脑操作，接着读[长程电脑使用 Agent](../ComputerUse/report.md)，看跨应用状态、GUI/CLI 协作和交付验证如何形成独立研究问题。
9. 若关注工具注入与授权边界，接着读[Agent 安全专题](../AgentSecurity/report.md)，比较动态攻击评测、单 Agent 运行时隔离与上下文证据审计。

本专题的 2026 进展现覆盖记忆更新、工具筛选、多 Agent 信任边界、失败诊断/恢复和评估器完整性；长程浏览器/桌面操作另见[电脑使用专题](../ComputerUse/report.md)。真实授权、不可逆外部副作用和跨环境重复成功仍未形成统一证据链。论文报告的基准成绩不等于真实部署结论；下一步最值得做的是固定一个可复现的工具环境，同时跟踪失败识别、状态恢复、权限执行和判分器完整性，而不是再加通用框架名录。
