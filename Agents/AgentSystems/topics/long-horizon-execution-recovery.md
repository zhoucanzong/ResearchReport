# 长程 Agent 的执行恢复：诊断、回滚与学习修正

多步 Agent 失败至少有三个不同问题：**哪一步让任务变得不可恢复**、**错误造成的环境状态能否撤销**、以及**策略能否从工具返回的错误中学会下一步修正**。把它们都叫“自我纠错”会掩盖关键设计差异。

| 工作 | 作用点 | 关键机制 | 直接边界 |
|---|---|---|---|
| [AgentRx](../papers/2602.02475-agentrx.md) | 轨迹诊断 | 从工具 schema、策略与轨迹合成逐步约束，让 judge 根据带证据的 violation log 定位首个不可恢复失败 | 是失败定位器，不负责把轨迹恢复；生成的约束可能误报或只标出下游症状 |
| [AgentRewind](../papers/2608.14380-agentrewind.md) | 运行时状态恢复 | 对齐 checkpoint 保存 Agent 上下文与可控工作区，回到指定点后带入 rewind memory 再执行 | 回滚只覆盖受跟踪工作区，不撤销网络、外部服务或进程副作用；Agent 还须决定何时 rewind |
| [Fission-GRPO](../papers/2026-acl-long-1880-fission-grpo.md) | 训练期策略修正 | 从当前策略的失败轨迹生成诊断反馈，再对纠正上下文重采样并训练 | 证明限于带错误反馈和重试的工具调用基准；训练策略修正不等于运行时回滚 |

这三种能力可以串成一条链，但彼此不能替代。先从轨迹定位问题，可以判断该回滚哪一段；状态恢复后，策略还需要用之前的失败信息选择不同动作；如果没有可控快照，模型的纠正只能面对当前状态继续补救。AgentRx 的“关键失败”定义为首个不可恢复点，不是轨迹里最早出现的错误，也不必是最后一个失败动作。AgentRewind 与 Fission-GRPO 则分别改变状态和学习过程。

最容易过度外推的是“rollback/recovery”一词。AgentRewind 的实验恢复文件工作区；外部副作用仍存在。Fission-GRPO 在模拟/基准提供的错误回执上训练；它不证明模型可以安全撤销真实 API 操作。真实服务若需重试，需要额外处理幂等键、事务状态、补偿动作和人工确认，这些是工具与环境契约。

实验比较也应把过程与结局分开：诊断器看关键失败步与根因分类；运行时回滚看同一失败端点恢复率和最终状态；训练法看触发错误后的条件恢复率，并同时报告错误前的 one-shot 成功。只报最终 pass@1 会混合“减少错误发生”和“出错后恢复”两种不同机制。

**阅读顺序**：先读 AgentRx，明确关键失败标签；再读 AgentRewind，观察如何恢复上下文/工作区及其副作用边界；最后读 Fission-GRPO，看如何把失败用于策略训练。需要追用户模拟或重复成功分母时，回到图书馆的 [评测科学](../../../Evaluation/EvaluationScience/report.md)，不要把这些论文的不同指标排成统一排行榜。
