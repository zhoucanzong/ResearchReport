# CivBench：把“主动看状态”与“兑现计划”变成可观察行为

原文：[CivBench: A Long-Horizon Benchmark for Tool-Mediated Agents in Civilization VI](https://arxiv.org/html/2609.02459v1)，固定版本 v1。建议读 §3.2–3.3、§4.1–4.4、§5.1–5.2、§6.1–6.2 与 Appendix A。

## 问题：结果分数看不到长程交互里的过程失误

几百回合的工具任务可能以输赢、得分或最终状态结束，但聚合结果压扁了中间过程：Agent 有没有查询关键的全局状态？它说过的计划有没有继续执行？CivBench 把 Civilization VI 包装为一个通过 MCP 工具交互的环境，一局超过 300 回合，提供 76 个工具和结构化叙述层。重要设计是：不少游戏状态**能够被查询，但不会自动进入 Agent 的观察**。这使基准可以把“信息不存在”和“信息存在但 Agent 没取回”区分开。

## 机制：叙述层控制可观测性，轨迹指标分开测两个环节

叙述层把游戏状态转成结构化文本；Agent 需要主动调用工具查询胜利进度、外交或城市信息。基准把全局监控行为量化为 **Proactive Monitoring Rate (PMR)**：战略状态查询占非基础设施工具调用的比例。PMR 是注意分配的代理指标，论文明确不把它定义为越高越好。

第二个指标是 **Reflection–Action Gap @10 (RAG@10)**：从 Agent 的 planning diary 提取具体目标承诺，判断其是否在未来 10 回合内执行，并对部分完成计半分。这里的 RAG 指反思—行动差距，和 Retrieval-Augmented Generation 的常用缩写重名。它只衡量明确的、短期自述承诺兑现度，不等于完整计划质量。

## 论文报告了什么

论文将 23 场可用游戏、四个模型家族作为 pilot，而非排行榜。作者在其共享 playbook 条件下报告 PMR 持续偏低；在可从状态工具发现胜利威胁的 20 场失败中，有 7 场未在给定预警窗口内查询胜利进度。三个具有足够承诺样本的模型家族，其 RAG@10 处于 48.2%–65.8%。这说明查询状态和兑现明确计划可从交互轨迹独立观察；数字只适用于该游戏、工具接口、playbook 和小样本。

RAG 标签由 LLM 从日记中抽取，并以 50 条人工标注样本做验证。论文报告的标签一致性支持该测量流程在此样本上的可用性，不是所有自然语言计划均可客观判定的证明。

## 取舍与边界

- 叙述层能把隐藏于界面中的信息组织成文本，但仍要求 Agent 判断何时查询；它让监控行为可测，不替 Agent 做监控。
- Playbook 让长程运行更稳定，也为监控/承诺提供共同约定；因此观察到的失败是给定指导下的行为偏离，不能直接断言模型缺少该能力。
- 总分不稳定地区分模型时，轨迹指标能暴露不同失败；反过来，PMR/RAG@10 也不是最终任务效用或通用 Agent 可靠性总分。
- CivBench 提供 benchmark 与行为可观测性，不实现持久项目状态、review gate 或回滚机制。它测量问题，不是一个修复这些问题的 Agent runtime。

与[Argus 精读](2608.05144-argus.md)合读：CivBench 把关注点放在单个长 episode 的环境状态查询和近端计划兑现；Argus 把运行切成多个 mission，并管理跨 mission 的持久状态、审查和证据门控。二者研究层次不同，结果不能横向比较。
