# AgentRewind：在受控工作区里回到错误发生前

> Zhuang et al., *AgentRewind: Recoverable Execution for Long-Horizon LLM Agents*, arXiv:2608.14380v1 (2026-08-14). [固定版本 HTML](https://arxiv.org/html/2608.14380v1)

## 问题：继续修补不一定能恢复已污染的状态

长任务里的错误会同时进入 Agent 上下文和环境：错误结论可能带偏后续计划，文件误改或删除也可能让后续操作继续建立在坏状态上。AgentRewind 将恢复做成运行时能力，而不是只靠更好的计划或安全拦截（§1–3）。

## 机制：对齐恢复点，而不是只重开对话

系统在每个 LLM 决策边界记录上下文和受控工作区状态的配对检查点。Agent 发现当前路径难以继续时，选择一个检查点并生成 rewind memory；执行器终止当前后缀、恢复上下文与工作区，再注入失败经验后重新执行。已保留前缀从执行日志恢复，不重新调用工具（§3）。

## 实验支持什么

MettleBench 将五类工程任务整理成 82 项长程作业，每项有 5–12 个有序验收条件，共 640 项。验收条件经过任务级审核和抽查，不是 640 项逐条都由人工标注；评估器是检查最终工作区状态的 Python 程序。针对 50 个因重复失败而终止的 Continue 端点，作者配对比较相同上下文和环境副本：Continue 恢复率为 8%，AgentRewind 为 30%；清单进度变化分别为 5.1 和 12.2 个百分点（Table 4）。

在 GPT-5.4 + mini-SWE-agent 的 82 任务组件消融中，完整 AgentRewind 的任务成功率/平均清单进度为 87.8%/94.3%；移除环境回滚后降至 43.9%/63.5%，是三项消融中降幅最大的一项（Table 5；Appendix B.5）。这支持“恢复环境状态对该设置很重要”，不等于对真实外部服务的回滚保证。

## 回滚边界决定它能恢复什么

快照覆盖受跟踪的工作区文件：修改可还原、删除文件可恢复、新建文件可移除。网络请求、外部服务状态和工作区外的进程状态没有撤销路径；`.git` 内容也被排除，仓库根的 Git 历史可能仍记录 Agent 在工作树回滚前做过的提交或 reset（Appendix C.4–C.5）。因此它是特定工作区内的状态回退机制，不是分布式事务，也不是 API 补偿机制。

作者固定策略运行三次，并检查评估器对相同最终状态给出相同判定；但端到端轨迹仍有波动。主比较中，656 个“任务×策略×模型”三次重复组里，490 组判定完全一致（74.7%）。作者将不一致归于轨迹、工具返回和文件系统时序等运行变化，不把它当作评估器噪声估计（Appendix A.5）。评估器确定性和 Agent 行为可重复性是两种证据。
