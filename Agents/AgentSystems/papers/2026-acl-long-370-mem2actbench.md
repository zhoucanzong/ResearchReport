# Mem2ActBench：从记得信息到用记忆完成动作

> Shen et al., *Mem2ActBench: A Benchmark for Evaluating Long-Term Memory Utilization in Task-Oriented Autonomous Agents*, ACL 2026, pp. 8173–8190。 [论文页](https://aclanthology.org/2026.acl-long.370/) · [PDF](https://aclanthology.org/2026.acl-long.370.pdf)

## 它补的测量缺口

不少记忆基准直接问“用户预算是多少”，Agent 只需检索并回答。真实工具任务往往只给一个不完整的新指令，Agent 必须自己意识到该翻历史，再把偏好和状态填进工具参数。Mem2ActBench 将这一点定义为：给定长期对话记忆与当前请求，生成一个选择正确工具、且参数由历史事实支持的调用（§1、§3.5）。

## 构造方式

作者把 ToolACE/BFCL 工具轨迹与 OASST1 对话噪声合并，建立事实演变链，再从完整工具调用反向生成信息不完整的请求，避免最终请求本身泄漏答案（§3.1–3.4）。最终包含 2,029 段会话、平均 12 个用户/助手/工具轮次及 400 项工具任务（Table 1）。五位专家参与检查，抽查集里事实提取准确率 96.5%、冲突解决质量 86.7%、记忆依赖有效性 91.3%（Table 2）；这些是各抽样环节的验证率，不应误读成 400 题全量人工标注准确率。

## 结果指向检索与参数落地

实验固定 Qwen2.5-7B/32B/72B 系列和 temperature=0（§4.1）。作者报告工具整体识别准确率处于约 87–97%，而参数 F1 平均从 7B 的 20.4 升至 72B 的 28.9，32B 到 72B 的增量变小（Table 3）。给定 oracle 检索到的目标记忆，F1 约 53.8；最好的被动检索约 30.7，差距超过 23 分（Table 4）。这提示该测试上证据命中是主要瓶颈之一，单纯加大模型无法替代更好的检索。

## 主要限制

基准只评估离线生成工具调用，不执行调用或观察环境反馈；主实验使用同一家族 backbone 控制变量，不能代表跨模型家族表现。数据经过自动合成，可能无法覆盖真实对话复杂度；人工验证在边界案例上也可能有偏差（Limitations）。作者指出中间位置的记忆较易漏取，且强记忆系统的失败会从“检索没找到”转向“取到却没使用”（§5.5）。

这篇论文的核心贡献是把 Agent 记忆评价拆成可观测步骤：找到证据、保持事实时序、将证据绑定到参数，再生成工具调用。离线调用分数仍不能代表真实环境中的完整行动可靠性。
