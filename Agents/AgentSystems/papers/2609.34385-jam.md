# JAM：把长期记忆检索变成一次运行时研究

> Yan et al., *Just-In-Time Agent Memory with Runtime Agentic Research*, arXiv:2609.34385v1，2026-09-28。 [固定版本 HTML](https://arxiv.org/html/2609.34385v1) · [PDF](https://arxiv.org/pdf/2609.34385v1)

## 问题：预先压缩不知道下次会问什么

常见 ahead-of-time（AOT）记忆系统在请求到来前压缩历史。它节省在线检索，却可能丢掉低频细节，或无法预先连接跨会话的证据。JAM 的目标是针对当前查询构造一份尽量小、同时不妨碍后续任务表现的上下文（§2.1）。

## 机制：保留原始记录，让轻量索引导航

离线 Memorizer 将完整历史写进层级 page-store，为每个会话产生 memo，并以目录层级和 README 摘要提供导航；原始记录保留为可追溯证据（§2.2）。在线 Researcher 根据用户请求查看导航页、搜索并打开相关原文，累积证据、判断是否充分，再构造传给下游 agent 的上下文（§2.3）。所以 JAM 不是普通向量检索的别名：它把多轮查找、检查和停止显式建模为策略。

训练先用经过核验的轨迹做 SFT，再在 SFT 模型上以 Hint-guided GRPO 训练多步探索。Memory-Gym 从历史构造 9 类任务、6 个来源领域，记录答案支持证据；28,276 个候选中 16,794 个通过验证（59.4%），200 个保留样本人工抽查时 95.0% 满足相应质量标准（§3.1、Appendix A.4）。这些数描述作者数据流水线的筛选结果，不是对所有训练样本的独立人工审计。

## 实验结果：比较的是论文指定的记忆任务

JAM 以 Qwen3.5-4B 为 backbone，默认检索结合 BM25 与 BGE-M3（§4.1）。Table 1 报告训练版在 LoCoMo 各类任务的 overall F1 52.09、LongMemEval accuracy 65.20、NarrativeQA F1 45.72；HotpotQA 在 56k / 112k / 224k 上分别为 64.56 / 59.28 / 58.69。对于其中两个基准，Memory-R1 数字来自其原论文，表格脚注明确标注了这一点；应避免把该行当作统一管线复跑后的严谨头对头结果。

论文还在未用于 Memory-Gym 训练的 LongCodeQA 上报告跨域表现：Researcher 从未训练的 54.08 overall 升至 SFT 的 65.67，再升至 SFT+RL 的 75.54（Table 3）。这支持训练的记忆使用行为可迁移到该代码理解任务，不能推出更广义的代码 Agent 执行能力。

消融中，完整系统优于去掉 Researcher 或 Memorizer 的配置（Table 4）；推理预算增加通常能提高表现，但收益逐渐变小。作者固定 checkpoint、工作区、提示、检索设置和预算，仅改变三个随机种子，在四组主基准报告标准差 0.31–1.34（Appendix B.5、Table 10）。这比单次运行更能说明随机性，却仍是每个基准三次重复，不能估计全部训练/数据波动。

## 解释边界

1. **它解决的是上下文构造，不是完整 Agent 的行动正确性。** JAM 把记忆提供给 downstream client；本文主表以记忆问答或长上下文 benchmark 评估，不等于能可靠操作真实 API 或软件环境。
2. **充分性判断是内部停止信号。** Appendix B.4 说明预算耗尽时仍会用已收集证据生成上下文，且 sufficiency 判断不保证证据已完整找到。
3. **数据与评估包含模型生成环节。** Memory-Gym 用自动流水线和 LLM 过滤轨迹；作者有人工抽检和质量控制，但仍存在合成数据、自动评价器与有限抽样边界。
4. **当前证据是预印本。** 本笔记固定 arXiv v1（2026-09-28）；不据此声称同行评审结论或实际部署可靠性。
