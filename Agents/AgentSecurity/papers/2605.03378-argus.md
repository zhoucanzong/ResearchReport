# ARGUS：审计动作背后的因果证据

> Shihao Weng et al., *ARGUS: Defending LLM Agents Against Context-Aware Prompt Injection*, arXiv:2605.03378v2（2026-07-08）。[固定版本完整 HTML 原文](https://arxiv.org/html/2605.03378v2)

## 为什么需要新的攻击设置

很多工具 Agent 的用户请求只给目标，具体对象和参数要从运行时材料中读取。例如，“支付我最新的电费账单”没有告诉 Agent 账单金额或收款方；这些信息来自工具返回的账单。攻击者可以在账单里插入与任务相关的说法，让多付一笔服务费看起来像正常账单处理。若防御只问“这个工具是否被用户请求授权”，合法的 `send_money` 调用可能掩护恶意收款人；若把外部文本一律视作无用指令，Agent 又无法从账单中得到完成任务所需的信息。ARGUS 把问题重新表述为：**每个会改变环境状态的动作，能否由用户任务和可信运行时证据共同解释？**（§1–2）

论文用 **AgentLure** 专门构造这类组合攻击：用户请求保留待解析的细节，恶意载荷则贴合它所在的上下文和当前任务，而非通用的“忽略先前指令”。基准包含 Banking、Travel、Workspace、Slack 四种环境，每种 10 个任务，每个任务配 8 种攻击，共 320 个攻击样例；攻击覆盖工具选择、参数、条件、推理、记忆、交接、技能和工作流，并落在六类来源面上（工具说明、工具返回、检索文档、记忆、技能、Agent 间消息）。四位每周使用 Agent 超过 20 小时的参与者构造样例，作者检查后要求重做 23 个未通过或有歧义的样例；两位作者初审一致性 κ=.78（§3）。

## 从“文本可信不可信”转向“它能否支持这个动作”

ARGUS 在 Agent 执行层维护 **Influence-Provenance Graph（IPG，影响来源图）**。图的节点记录提示、读操作、写操作和观察到的上下文；边记录一次模型调用里哪些上下文影响了哪个动作，以及动作产生了什么返回值。它不是一般意义上对全部模型内部推理的追踪，而是利用运行时可见的调用轨迹，保留证据进入上下文、再影响动作的外部链路（§4.1–4.2）。

新上下文进入图后，ContextSegmenter 按片段标记为 benign 或 anomalous。一个可疑片段不因此被删除，也不必然是恶意；它只是暂时不能作为改变状态的动作依据。这样保留上下文可供 Agent 理解和恢复，同时阻止它未经验证地获得执行权。对每个拟执行的写操作，ArgumentGrounder 沿 IPG 回溯参数的支持来源；若参数依赖异常片段，EntailChecker 再检查良性证据单独是否足以推出该参数。最后，InvChecker 将整个动作与从原始用户请求提取的任务不变量比较，防止运行时材料虽然支持某个局部参数，却把用户任务扩成另一类操作。两种检查分别回答“这个具体值从哪里来”和“即使这个值有依据，整体动作是否仍在授权范围内”。只有良性证据足以蕴含参数且动作满足不变量，运行时才放行（§4.2–4.3）。

这个设计介于两种常见防御之间。文本级防御用分隔符或额外指令提醒模型不要服从外部文本；它们允许 Agent 使用上下文，却不判断最终动作到底由哪段证据支持。只按用户提示生成工具白名单或计划的执行级防御，则在用户提示有意留下细节时可能拦掉正常任务，或允许攻击者借用已获准的工具。ARGUS 允许上下文补全用户没有指定的变量，但把这种权限限定为“只能支持任务本身容许的动作”，并在执行前检查证据到参数的因果链（§1、§5.2）。

## AgentDojo 提供的是互补对照，不是一个可被轻率归为“简单”的基准

AgentDojo 已是动态工具环境：原始工作包含 97 项现实任务与 629 个安全测试样例，评估工具返回的不可信数据怎样影响 Agent。ARGUS 没有只在 AgentLure 上测自己，也报告在 AgentDojo 上将攻击成功率从 38.1% 降到 5.0%，clean utility 从 65.0% 升到 69.0%（Table 3；[AgentDojo 原论文](https://proceedings.neurips.cc/paper_files/paper/2024/hash/97091a5177d8dc64b1da8bf3e1f6fb54-Abstract-Datasets_and_Benchmarks_Track.html)）。

因此，两者的区别应理解为**评测问题的侧重点不同**：AgentDojo 建立了通用动态环境和任务/攻击/防御扩展框架；AgentLure 有意把请求未定细节、任务相关上下文与上下文感知载荷绑定起来，集中测试“恶意证据伪装成完成任务所需证据”的难例。ARGUS 在 AgentDojo 上的结果说明其审计思路能迁移到已有环境，但不能说明 AgentDojo 覆盖了 AgentLure 的全部攻击构造，也不能只凭两张基准表作横向排名。论文把许多既有 benchmark 的缺口描述为请求和载荷较少依赖具体运行时语境；这适用于它所指出的任务设置差异，不应改写成 AgentDojo 没有动态环境或真实工具交互。

## 实验支持的结论与代价

AgentLure 主实验用 GPT-4o-mini 同时作为被测 Agent 和 ARGUS 的审计子 Agent。与无防御相比，ARGUS 将 ASR 从 28.8% 降到 3.8%，clean utility 为 87.5%，相对 token 成本为 1.24×；八类攻击中最高的单类 ASR 为 7.5%。表中的 clean utility 无防御值为 92.5%，所以防御保留了大部分正常任务能力，但不是零代价（§5.1–5.2，Table 2）。作为取舍参照，MELON 的 ASR 更低（1.6%），但 clean utility 只有 65.0%、拒绝率 35.0%、attacked utility 10.9%；ARGUS 的优势是整体安全与任务效用折中，而非每项指标都最佳。

消融比总分更能解释机制：移除片段级 ContextSegmenter 后，ASR 从 3.8% 升至 25.0%；移除 EntailChecker 后升至 11.2%；移除任务不变量检查后升至 8.1%；移除 ArgumentGrounder 后升至 7.5%（Table 4）。这支持作者的设计判断：可信证据必须既经过片段判断，又与具体动作参数相连；仅仅在历史里找到某段良性材料不够。白盒自适应攻击让攻击者得到完整防御说明、组件提示、信任配置和每个样例的标准运行轨迹，再由原样例构造者改写载荷。该设置下 ASR 从标准攻击的 3.8% 升至 5.9%，其中交接注入达到 15.0%（Table 5）。这表明攻击者针对防御反馈进行定向改写仍能找到薄弱处，且论文报告的是固定改写集上的一次评估，不是对任意持续自适应攻击的保证（§5.4）。

## 证据边界与开放问题

IPG 记录的是运行时观察到的来源与影响关系，**不证明来源真实**。论文的自适应攻击失败案例指出：若一张伪造发票成为唯一可见来源，Agent 可能沿一条内部一致的图推导出恶意转账；因果链完整仍可能建立在伪造载体上。作者因此把签名记录、发行方验证和跨记录一致性检查列为后续方向（§6.2）。实际部署还依赖动作是否被正确分类为只读或状态改变；算法对只读操作直接执行并记录返回值，所以把有副作用的操作误标为只读会绕过写操作前的审计（§4.3）。

此外，片段分类、参数 grounding、蕴含和任务不变量检查由提示驱动的子 Agent 完成；论文给出了消融和基准结果，却没有证明这些判定在任意领域可靠或可形式化验证。任务不变量抽取不完整、错误标记可信来源、真实授权本身含糊、或外部副作用发生在被审计接口之外，都可能破坏“动作有良性依据”的推理。当前结果主要来自四种模拟工具环境、320 个攻击样例及单一 mini 级模型配置；跨模型、长期运行、异步工具和真实不可逆交易仍待检验。后续关键问题是把来源真实性、显式授权、动作分类、因果审计与失败后的独立证据恢复组合起来，并分别评估误放行和误拦截。
