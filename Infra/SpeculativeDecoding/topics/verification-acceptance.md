# 横切专题②：验证、接受率与无损性的适用条件

> 范围：有限词表上单链拒绝采样的证明、确定性草稿、截断分布和树验证的条件。数学等式可独立检查；具体框架的行为仍须回到固定 commit。分布等价不等于逐次输出相同，更不等于任意硬件上的 bitwise 一致。

## 1. 先把符号钉死

| 符号 | 定义 | 易混淆点 |
|---|---|---|
| \(p\) | 目标基线在当前已接受历史上的实际采样分布 | 包括基线原本采用的温度、top-p/top-k、约束等处理 |
| \(q\) | 真正产生该位置候选的提议分布 | 不一定是 draft 模型未经处理的 softmax |
| \(\alpha\) | 单位置候选的平均接受概率 | 不是一次验证输出的 token 总数 |
| \(r\) | 拒绝条件下的修正分布 | 通常不等于无条件 \(p\) |
| \(K\) | 此处指词表截断大小 | 不与一次草稿长度混用 |

所谓“使用完整 p”是保持目标基线定义的全部概率质量，而不是取消用户原本要求的 top-p、温度或 grammar。更改基线的采样参数就已经更改了要保持的目标。

这里的 `p` 与 `q` 指**实际用于抽目标 token 和提议草稿 token 的归一化分布**，不是处理前的 logits，也不是根据配置名推测的概率。两者不必使用完全相同的过滤器；但候选实际从哪个 `q` 产生，接受与残差就必须使用同一个 `q`。

## 2. 单链无损性：修改的拒绝采样

### 2.1 一个位置的算法

候选 \(X\sim q\)，以 \(\min(1,p(X)/q(X))\) 接受。若拒绝，从

\[
r(y)=\frac{[p(y)-q(y)]_+}{Z},
\qquad Z=\sum_z[p(z)-q(z)]_+
\]

采样修正 token。若 \(p=q\)，拒绝概率为零，不需要计算零分母的残差。

这是 [Leviathan 等 Algorithm 1](https://arxiv.org/html/2211.17192v2) 与 [Chen 等 Algorithm 2](https://arxiv.org/html/2302.01318v1) 所用的单链采样思想；本页下式给出直接推导。

### 2.2 输出为什么等于 p

接受到 \(y\) 的概率为 \(\min(p(y),q(y))\)。总拒绝概率为

\[
1-\sum_z\min(p(z),q(z))
=\sum_z[p(z)-q(z)]_+=Z.
\]

因此最终输出 \(y\) 的概率为

\[
\min(p(y),q(y))+Zr(y)
=\min(p(y),q(y))+[p(y)-q(y)]_+
=p(y).
\]

证明要求候选真的来自所写的 \(q\)，并且残差针对同一个历史和同一个目标 \(p\) 计算。附近存在一个变量名不能替代这两个条件。

### 2.3 从一个位置推广到序列

对接受的草稿前缀，可继续验证后续候选。一旦某个位置拒绝，原草稿后缀的历史已改变，不能照旧继续接受；应丢弃失效后缀，输出修正 token，再在新历史上重新起草。全部草稿接受时，可从 target 额外输出一个 token。

逐位置条件分布一致，才可推出序列分布一致。相同随机种子下与普通解码逐 token 相同不是这一证明保证的性质。

## 3. top-K 到底改变什么

标准算法的平均接受率为

\[
\alpha=\sum_x\min(p(x),q(x))=1-\operatorname{TV}(p,q).
\]

将提议截断并重新归一化后，只要采样与验证都使用新的 \(q_K\)，残差仍补回目标分布缺失的质量，就能保持 \(p\)。

### 3.1 接受率不会因截断必然下降

以下为本页构造的有限分布反例，不是论文 benchmark：

| 情况 | \(p\) | 原始 \(q\) | top-2 后 | 接受率变化 |
|---|---|---|---|---|
| 截断更接近目标 | \((0.5,0.5,0)\) | \((0.45,0.45,0.10)\) | \((0.5,0.5,0)\) | 0.9 → 1 |
| 截断远离目标 | \((0.6,0.3,0.1)\) | 与 \(p\) 相同 | \((2/3,1/3,0)\) | 1 → 0.9 |

因此“截断必降接受率”不成立。要看新的总变差距离；在特定树构造上的经验趋势不能当成任意单链分布的定理。

draft-only 的 top-p 也可精确保留目标。若 `p=(1/2,1/3,1/6)`，原始 `q=(2/5,7/20,1/4)`，top-p=0.7 保留前两项并归一化为 `q'=(8/15,7/15,0)`；两者公共接受质量为 `(1/2,1/3,0)`，缺少的 `1/6` 由残差分配给 `C`，混合后仍是 `p`。若 top-p 同时施加在目标侧，则目标本身改为处理后的 `p`，不能继续把原始 `p` 当成基线。

### 3.2 grammar mask 与过滤顺序

grammar 把当前可选词限制在合法集合 `L` 时，目标分布通常是把非法 token 的概率置零，再在 `L` 内重新归一化。草稿端可以有不同处理；无损性仍取决于实际候选分布 `q` 是否被正确传给接受与残差计算。

一个有限例子可以看出次序为何重要。词表为 `(A,B,C)`，原始目标 `p=(1/2,1/3,1/6)`，原始草稿 `q=(1/6,1/3,1/2)`，grammar 只允许 `L={A,B}`。分别 mask 并归一化后，目标为 `p_L=(3/5,2/5,0)`，草稿为 `q_L=(1/3,2/3,0)`。若再把草稿 top-1 截为 `δ_B`，接受质量是 `(0,2/5,0)`，拒绝质量 `Z=3/5`，残差为 `δ_A`，混合输出仍是 `p_L`。

若先对原始 `q` 做 top-1，会选到非法的 `C`；随后再 mask 得到全零向量，不是可抽样的归一化 `q`。框架必须定义重采样或回退行为，不能把空向量直接代入拒绝采样公式。更一般地，只 mask 目标而让草稿仍可提议非法 token，数学上仍可精确保留 `p_L`，前提是非法候选按 `p_L(x)=0` 被拒绝，且残差使用真实 `q`；它会浪费草稿预算，但这与无损性是不同问题。

本例是有限分布的有理数检查，不是论文 benchmark 或框架运行。它说明操作次序会定义实际的 `p`、`q` 或使 `q` 无法归一化；它本身不证明任何框架采用了哪一种次序。

### 3.3 one-hot 草稿也是合法提议

若候选确定为 \(d\)，则 \(q=\delta_d\)，接受概率为 \(p(d)\)。拒绝后：

\[
r(d)=0,\qquad r(y\ne d)=p(y)/(1-p(d)).
\]

拒绝残差单独看不等于 \(p\)，但与接受分支混合后恢复 \(p\)。所以确定性草稿可以保持分布；它的接受率与效率可能不理想，但“有 draft 模型却没有完整 draft_probs”本身不能证明有偏。

相反，若候选原来按随机 \(q\) 采出，却在验证时假装为 \(\delta_d\)，便不能直接沿用上述证明。必须检查实际生成方式和条件分布。

## 4. 贪心与采样是两套接受规则

| 维度 | 目标为贪心 | 目标为概率采样 |
|---|---|---|
| 目标 | 在相同历史选 argmax | 从 \(p\) 抽样 |
| 典型接受 | 候选等于 target argmax | \(\min(1,p/q)\) |
| 拒绝后 | 用 target argmax 修正 | 从相应残差修正 |
| 确定性草稿 | 不需要完整词表概率 | 可用已知 \(\delta_d\)，仍不需要保存完整向量 |
| 必须核查 | tie-breaking、历史、约束 | 实际 \(q\)、残差、历史、采样处理 |

T>0 的 point-mass 接受概率 \(p(d)\) 不等于“候选是否是 target argmax”。两者只有在目标本身退化为确定性分布等特殊情况下相同。

框架入口见 [vLLM 分册](../papers/vllm-implementation.md) 与 [SGLang 分册](../papers/sglang-implementation.md)。开关名称和存储字段不是无损性的充分证明。

## 5. 树验证：静态拓扑不是充分条件

固定树形只说明拓扑不随候选变化，不自动证明每个节点的候选分布、兄弟分支的相关性、遍历规则和拒绝残差正确。一个静态树若采用 typical acceptance，也不能因此称为严格分布保持。

动态树还需要处理“候选是否存活依赖它的取值”带来的选择条件。若剪枝改变分布，验证时使用未经选择条件修正的旧 \(q\)，单链证明不再直接适用。这是需要单独分析的数学问题，而非所有动态树必然有偏。

[RheoSampling 分册](../papers/2609.21827-rheosampling.md) 讨论了其论文范围内的 proxy/真实概率分离；没有核对具体实现、条件和默认值时，不能宣称所有 EAGLE 配置都会采用或都需要同一个修复。

## 6. “无损”需要区分保证与经验

| 声明 | 需要的证据 |
|---|---|
| 保持目标分布 | 定义目标、给出采样与修正算法，并证明条件分布一致 |
| 贪心输出等价 | 固定模型、约束与 tie-breaking，核对接受和修正 |
| 分布偏移有界 | 指明距离、假设和上界；不能只给任务准确率 |
| 任务质量近似不变 | 固定评测协议、样本量与误差；属于经验结果 |

“逐 token 验证”和“序列级验证”是算法形式，不是两种天然不同的正确性等级。若都证明目标分布一致，其保证可以相同。

[Medusa 的 typical acceptance](../papers/2401.10774-medusa.md) 不等于经典拒绝采样；在没有额外定理时，也不能笼统把它升级成“分布偏移有界”。不同保证与不同基线的加速数字不能合成排行榜。

**安全评测是另一条任务指标轴。** `Secure Speculative Decoding`（arXiv `2610.08678v1`，§3–§7）研究的是**有损 verifier**：作者将标准验证与放宽验证比较，发现 jailbreak / prompt-injection 的 PRR 可早于 HumanEval / GSM8K 下降，并用早期位置校正来恢复部分安全性能。这不改变标准拒绝采样的分布等价证明，也不构成对任意攻击或所有模型的安全保证；见[论文精读](../papers/2610.08678-secure-sd.md)。

## 7. 指标口径：两个分母、一个修正 token

按 [vLLM 分册及锚点表](../sources/CODE-AUDIT.md) 的固定版本记录：

- draft acceptance rate：接受草稿 token 数 / 提议草稿 token 数。
- mean acceptance length：每次验证实际输出 token 数；该实现的聚合公式包含额外修正或 bonus token。
- per-position acceptance：还要说明相应位置有多少次有效提议。

增加草稿长度可能降低第一个指标而提高第二个，但不是必然。EOS、最大输出长度、grammar 作废候选及统计实现可能改变实际分母，跨版本要重新核对。

## 8. 核验一项无损声明

1. 基线的温度、截断和约束是什么？
2. 候选实际怎样产生，对应哪个 \(q\)？
3. 拒绝后补什么分布，失效后缀怎样处理？
4. 树剪枝与候选相关性是否进入证明？
5. 浮点、并行执行与 RNG 是否只保证分布意义而非相同样本？
6. benchmark 的模型、硬件、batch、输入输出长度与对照是否一致？

只有接受率或任务准确率，均不能单独证明严格分布保持。

## 9. 证据边界

本页的有限词表有理数检查覆盖 `p=q`、one-hot 草稿、目标概率为零的候选、draft top-K/top-p 及 grammar mask 与 top-1 的组合；每个有效案例都逐项得到输出 `p`。这验证的是数学恒等式与示例计算，不是框架实现。没有运行 GPU kernel、模型或统计分布测试。

固定 commit 的源码和测试各自能证明的范围见[代码审计表](../sources/CODE-AUDIT.md)。统计检验有助于发现实现偏差，但有限样本检验未拒绝零假设不等于数学上的精确等价；固定 seed 的轨迹回放也不等于自由随机生成的分布证明。具体论文性能结果仍以对应分册和固定原文版本为准。
