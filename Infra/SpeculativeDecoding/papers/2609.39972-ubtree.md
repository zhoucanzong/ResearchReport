# UBTree：用并行 bigram 边评分，把块草稿扩成多条可验证路径

来源：Liang et al., [*UBTree: Parallel Tree Drafting via Unigram and Bigram Models for Speculative Decoding*](https://arxiv.org/html/2609.39972v1)，固定版本 arXiv v1（2026-09-30，CC BY 4.0）。重点阅读 §3.1–§3.2、§4.1–§4.4、Appendix D；特别留意 Figure 2、Tables 1–4、Table 7 与 Limitations。

## 问题：并行草稿有速度，却通常只押一条路径

以 DFlash 为例，模型一次前向并行给出未来每个位置的 token 分布。这个结构省掉了逐 token 草拟的串行等待，但各位置没有看到同一 block 中已经选出的前驱 token。于是位置上各自最可能的 token，组合起来可能落在互相矛盾的续写分支上；当 target 的分布熵较高时，单条草稿路径很容易早早偏离，后面的草稿位置也随之失去提交机会。

UBTree 同时处理两个限制：**多路径树提供候选多样性**，而**轻量 bigram selector 给候选边加入相邻 token 依赖**。它把多样候选先组织成树，再由 target 按标准 tree speculative verification 选可提交路径。论文的正确性来自该 target verifier 与常规残差/bonus-token 规则；bigram selector 负责候选的覆盖和排序，不是新的分布保持证明。[§1–§3](https://arxiv.org/html/2609.39972v1)

## 从 unigram 候选到 bigram 边，再到有预算的树

UBTree 有三个阶段：

1. **Unigram proposer**：以 DFlash backbone 为基础，为 block 中每个位置并行给出 top-$K$ token 候选。这里的 unigram 指每个位置的初始提议不依赖 block 内其他位置的具体采样 token，并非语言数据集只统计词频。
2. **Bigram selector**：对相邻位置候选对 $(a,b)$ 打分，回答“当前前驱若为 $a$，后继候选 $b$ 是否是一条连贯边？”它用 successor position 的 proposer hidden state、target embedding 派生的 predecessor/successor codebooks 和 depth-specific scales 计算分数。所有边可以批量并行打分；之后树搜索只用缓存分数，不必再运行一个逐 token neural head。
3. **Tree builder + target verifier**：按边转移分数构造多个路径，并用 DARTree 的 depth-wise progressive construction/global pruning 保留预算内的树；target 一次前向验证整棵树，提交其规则允许的最长接受续段。[§3.1.1–§3.1.3、Figure 2、Appendix A](https://arxiv.org/html/2609.39972v1)

这解释了它相对相邻方法的增量：DDTree 从并行位置的边际概率乘积给整条路径排序，路径分数不会随已选前驱改变；DARTree 添加自回归 correction head 让分支分数条件化，但需要随树深逐层计算；UBTree 把依赖压缩到相邻边 bigram 分数，集中在一次并行评分，再复用这些分数构树。它比完全独立的 unigram path 更会表示邻接关系，却仍是 bigram 近似，并没有建模任意长前缀条件。[§2、§3、§5](https://arxiv.org/html/2609.39972v1)

## Tree-native training：让 selector 学会保留 target 的替代续写

普通单路径 drafter 通常重点学习 target 采样轨迹或 greedy token；但树验证希望多个分支都带有可接受概率质量。若训练时只强化一条轨迹，selector 可能把 target 的合理替代路径排在树预算之外。UBTree 保留 proposer 的 token CE 训练，同时用 **高温 target 轨迹 + 候选集合上重归一化的 forward KL**监督 bigram selector，使其学习 top-$K$ 支持中的概率相对关系。训练温度 $T_{train}$ 与推理温度 $T_{infer}$ 可以分开：论文训练 $T_{train}=1$ 的 checkpoint，再在 $T_{infer}=0$ 和 $1$ 下评测。[§3.2、Table 4](https://arxiv.org/html/2609.39972v1)

它解决的是**单路径训练和多路径验证之间的训练—推理失配**，而非单纯更大 top-$K$。代价是 target-specific rollout、selector 训练以及固定的树搜索预算；树节点增多仍会增加 target verification 计算。

## 结果如何阅读

学术规模实验在 Qwen3-4B/8B 指令模型与 Qwen3-4B reasoning 模型上进行，涵盖七个数学、代码、聊天基准；使用一张 H200、batch 1、transformers backend，推理温度 $T_{infer}=0/1$。树配置为 $B=64$ 个非根节点、search width $W=12$、每个位置 top-$K=64$；平均 accepted length $\tau$ 含 target 产生的 bonus token。作者报告对 AR 的平均 speedup 在 Qwen3-4B/8B、$T=0$ 时分别为 6.88× / 6.94×，$T=1$ 时为 6.00× / 5.84×。论文进一步报告其在 28 个模型–基准–温度 comparison 中都高于 DARTree；这不是“相对 DARTree 达到 6–7×”，这些倍数的分母是普通 autoregressive decoding。[§4.1、Table 1](https://arxiv.org/html/2609.39972v1#S4)

并发 serving 实验是另一组证据：SGLang、BF16、一张 H200、CUDA Graphs，在 Qwen3-4B/8B、$T=1$ 和 client concurrency 1/8/16/32 下测试；各方法分别从同一候选配置集和标准中调选 $B/W$。UBTree 在所测并发点报告比次优方法高 7.0%–16.3% aggregate throughput。这组结果包含按负载调整树预算，不能与学术规模、batch 1 transformers backend 的 speedup 混成一个 headline。[§4.1、Table 2](https://arxiv.org/html/2609.39972v1#S4)

论文还用 SGLang 在较大模型 Ling3-Flash-124B 与 Qwen3.8-27B 上测试，并用同一批 LongBench-v2 请求和固定的 SWE-bench agent replays 测长 prompt / 累积上下文下的 acceptance length。它支持所测 checkpoint 与请求轨迹上的树覆盖表现，不等于所有长上下文或 agent runtime 都得到同样收益。[§4.2–§4.3、Tables 3、8–9](https://arxiv.org/html/2609.39972v1#S4)

## 哪些部分不能外推

- Bigram selector 提供局部相邻依赖，不能替代完整自回归条件；树的可达 target mass仍受 proposer top-$K$ 候选和节点预算限制。
- 构树沿用 DARTree 的 depth-wise search 和 pruning；速度收益来自 proposer、selector、tree build 与 target verification 的组合，不能全归因于某一层。
- 生产服务中的 $B/W$ 对每种模型与并发分别通过配置搜索选定。论文明确指出它不是基于每轮转移分数和当前算力余量在线求最优；tree decoding 在极高并发、target 已变成 compute-bound 时仍可能失去加速。
- 上述结果都是论文报告，没有在本仓库重新训练或复现；报告的 speedup 只在相应 target、任务、硬件、温度和 baseline 下成立。

**带走的机制区别**：DSpine 在 backbone 各层沿相邻位置注入预测特征，主要让因果条件在一次并行前向的网络深度中逐步形成；UBTree 则保留多条 top-$K$ 路径，用并行 bigram edge scores 选择哪些替代续写进入 target 可验证树。两者都改善并行草稿里的依赖关系，前者强化单路径序列一致性，后者把相邻关系用于多路径覆盖。
