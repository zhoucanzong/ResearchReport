# DFlash：让块扩散只负责草稿

**原文**：[arXiv 2602.06036v2](https://arxiv.org/html/2602.06036)，CC BY 4.0。阅读 §3–§6、Table 1–9 与 Appendix A.2–A.5。本文只摘出与跨专题综合有关的设计和证据；没下载权重，也没运行模型。

## 它在解决什么问题

扩散语言模型能在一次前向中预测一整块 token，但独立扩散模型的语言能力往往不够强。若用它直接生成，扩散迭代次数、长度控制与输出质量都成了产品本身要承担的代价。DFlash 把角色收窄：扩散模型只提出草稿，AR target 负责决定哪些 token 真正进入输出。这样，草稿可以错；只要 target 验证和纠正规则正确，最终仍可服从 target 的输出分布。

## 机制：并行提议加上 target 的内部信息

AR draft 为生成长度 \(\gamma\) 需要串行执行多次小模型前向；块扩散 draft 用一次前向同时预测 \(\gamma\) 个位置，令草稿延迟不再随块长线性增加。并行使更深的 draft 网络在延迟预算内变得可行。

DFlash 的 target 先做 prefill，从多个深度提取隐藏状态并融合，再通过 **KV injection** 将这些表示送入 draft 的各层。其设计判断是：target 隐状态已包含 prompt 语义、长程关系和未来 token 线索，独立小模型从词面上下文“从头猜”会产生较差候选。与只在 draft 输入处融合不同，KV 注入让每个 draft 层都能访问 target 表征。训练目标在噪声块上预测原始 token；推理按块并行提出，再由 target 验证。

## 作者报告的证据与边界

论文报告 Qwen3 指令模型、推理模型和 LLaMA-3.1-8B 上的加速结果。主表中的平均值依赖特定任务、温度、模型和后端；不能跨表与不同硬件论文排成一个通用榜单。尤其 SGLang 的 serving 表里，Qwen3-4B/MATH500 的加速从并发 1 时 4.8× 降到并发 32 时 2.9×，说明 target 验证成本会随 batch 上升而显现。[§5.1–5.3、Table 1–5]

消融发现，相同 5 层 draft 与 block size 8 下，逐层 KV 注入比只做输入融合提高接受长度和加速；但训练成本、target 特征可用性、draft/target 配套和运行时树验证能力都是条件。作者没有证明任意预训练 diffusion LM 都能直接替换 EAGLE，也没有给出无限并发下持续加速的保证。[§5.5.3–5.5.5、Table 7–9]

这篇的核心价值是把 diffusion 的长处放在“便宜并行提议”这个子问题，而不要求它独自承担完整生成质量。它也留下一个新问题：当一次前向已产出多个位置上的候选时，怎样挑选值得花 target 验证预算的路径？DDTree、DARTree 和 PRESTO 分别研究这个选择问题。
