# Spiffy：让扩散语言模型为自己草拟后续去噪状态

**原文**：[arXiv 2509.18085v4](https://arxiv.org/html/2509.18085)，2026-06-11 版本，FoGen @ ICML 2026 workshop。阅读 §3–§6、Appendix A–D、Table 1–4。未运行作者代码或模型。

## 它与“diffusion draft + AR target”不同

Spiffy 加速的是 diffusion language model 自身的去噪。target 是原来的 dLLM；它用同一 dLLM 当前步的分布，对未来可能出现的 block state 做 auto-speculation，再并行验证。系统不引入独立 draft model，也不试图把扩散语言模型升级成 AR 目标。

AR speculative decoding 常见 draft tree 是单根树：一个节点只有一个父前缀。Spiffy 的节点表示某个 block 在后续去噪时刻可能达到的 token/state 子集。dLLM 的双向注意允许这些状态有多个有效父节点，因此用有向 draft graph 表示候选关系。作者先用少量校准样本统计常见解遮蔽模式，再离线定图；推理时按当前接受概率剪枝。

验证的关键是：dLLM 先按自己的原始 target 分布产生下一步状态；仅当一个预先起草的未来状态和真实下一状态完全吻合，才跳到已计算过的后续分布。论文在 Appendix A 证明这一接受规则保留目标 dLLM 的输出分布。因此该方法追求的是**同一个 dLLM 基线下严格的 distribution preservation**，不是扩散模型与另一个 AR 模型之间的质量匹配。

## 作者报告的证据与限制

作者评估 LLaDA-8B-Instruct、Dream-7B-Instruct、SDAR-8B-Chat-b32，并与 prefix KV caching、threshold-based dynamic unmasking 组合。论文报告最高 8.6× 的模型推理次数减少和最高 6.3× token-rate 加速；数字依赖模型、任务、图校准、并行解遮蔽和系统设置，不是单独图结构在所有任务的平均值。[§5、Tables 1–4]

校准在 MATH500 与 MBPP 各取 25 个样本，每个模型离线约 10 分钟；若生成的 token 解遮蔽模式与校准图覆盖不符，可用 draft 边就可能减少。该方法将成本转成目标模型的多分支并行前向和注意力 mask 管理；并非“无需独立 draft 所以零成本”。[§4.4.3、Appendix D]

Spiffy 补上独立 diffusion drafter 之外的路线：把“同一个扩散模型如何跳过部分迭代”当作投机问题，依赖的是去噪状态图与精确状态匹配；DFlash 家族依赖外部块草稿和 AR target verification。两条线共享“并行提出候选，再核实能否提交”的直觉，target 与正确性定义不同。
