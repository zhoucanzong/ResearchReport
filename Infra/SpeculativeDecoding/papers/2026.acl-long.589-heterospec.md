# HeteroSpec：把验证预算投向更可能延长接受前缀的上下文

来源：Liu et al., [*HeteroSpec: Leveraging Contextual Heterogeneity for Efficient Speculative Decoding*](https://aclanthology.org/2026.acl-long.589/)，ACL 2026 Long Papers，正式会议版。重点阅读 §3–§5、§7、Appendix A.2–A.8 与 A.10–A.12。

## 从“多生成几个 token”转向“哪些上下文值得多验证”

投机解码中的草稿候选并非同样有希望：某些上下文的分布很尖、候选容易沿着 target 的高概率路径延续；另一些上下文的不确定性高，增加深度或保留更多分支未必抵得过 target 的额外计算。HeteroSpec 把这种差异称为 **verification heterogeneity**，但其实现并不是逐候选直接按熵连续分配算力。它先用候选路径的 **cumulative meta-path Top-K entropy** 估计当前上下文复杂度，再据此选一组按数据划分的运行策略。[§3、§4.1](https://aclanthology.org/2026.acl-long.589.pdf)

具体流程分三步：

1. 选取最终 token 置信度最高的 draft path，累计路径各位置归一化 Top-K 概率的熵，作为复杂度信号。
2. 用 ShareGPT 路径样本训练浅层 CART 决策树；监督标签是 Terminal Confidence Rank，即 EAGLE-3 rerank 的候选中，最终被接受的最长前缀排名。树把连续复杂度分成离散区域。
3. 在低熵区域扩展 draft depth，并调节保留的 Top-N 候选；为这些动态配置 JIT 编译和缓存计算图，控制不同树结构带来的执行开销。[§4.1–§4.3](https://aclanthology.org/2026.acl-long.589.pdf)

这里的“免重训”应准确理解为**不重新训练 target 或 draft language model**：作者仍从运行轨迹训练决策树分类/分层器。因而实际问题不只是熵指标是否有效，还包括训练样本如何代表目标服务负载、分区是否迁移，以及动态深度和 Top-N 的额外计算能否在目标硬件摊薄。论文在 H20-3e 主设置报告决策树训练约 2.4 秒，并做跨任务/模型与硬件实验；这些证据支持其在所测 EAGLE-3 栈内的可行性，不自动证明对其它 drafter 通用。[§4.2、§5、Appendix A.3–A.7](https://aclanthology.org/2026.acl-long.589.pdf)

## 这与 HCSpec 的“异构”不是一条方法

[HCSpec](2026.acl-long.353-hcspec.md) 依据草稿位置的预期未来接受收益，设计前重后轻的两级 draft architecture；HeteroSpec 读取运行时路径的不确定性，再动态调整当前树的草拟深度、Top-N 与计算图。两者切入点不同：

| 问题 | HCSpec | HeteroSpec |
| :-- | :-- | :-- |
| 异质性来自哪里 | 同一 draft 序列中前后位置的边际接受价值 | 不同上下文 / draft path 的可预测性差异 |
| 改变的对象 | 位置对应的 drafter 模块容量与特征流 | 运行时 draft depth、候选保留量和计算图 |
| 需要更新什么 | 训练两级 draft（target 冻结） | 拟合轻量决策树，不重训语言模型 |
| 主要证据边界 | 经验切换策略；未证明全局最优 | ACL 正文实验主要运行在 EAGLE-3 框架内 |

所以它们共同支持“统一预算可能浪费”，却不应合并成一个 HCSpec/HeteroSpec 级联算法；两者可以被视为 draft 结构预算与在线验证预算的两条互补设计轴，实际能否组合仍须实测。

## 与候选估值和 verifier 理论的边界

- [ValuSpec](2610.31338-valuspec.md) 先给**已经生成的候选分支**估值，再筛掉 target greedy 轨迹上价值低的分支；HeteroSpec 用上下文复杂度分区来调整深度和 Top-N，并包括 JIT 计算图适配。它们都会影响送入 target 的工作量，但信号和所处阶段不同。
- [When Is a Draft Accepted?](2606.30265-when-is-draft-accepted.md) 证明给定 $KL(p\|q)$ 条件下的局部接受证书；HeteroSpec 不提出这种新证书。
- [HSD](2601.05724-hsd.md) 构造严格序列级分布平衡与回补证明；HeteroSpec 的 ACL 正文声称保留严格接受条件和精确分布，但没有另给 HSD 式定理。其主文实验默认 $T=0$，$T=1$ 结果在 Appendix A.8；阅读“精确分布”时应区分框架对正确性的声明、其继承的 verifier 条件和各温度下展示的实验，不能把摘要句本身当成新分布保持证明。[§4.3、§5、§7、Appendix A.8](https://aclanthology.org/2026.acl-long.589.pdf)

## 结果和限制

作者在五个基准（MT-Bench、HumanEval、GSM8K、Alpaca、CNN/DailyMail）及 Vicuna-13B、LLaMA-3.1-8B、LLaMA-3.3-70B、DeepSeek-R1-Distill-LLaMA-8B 上比较 EAGLE-3。论文报告 mean 4.24× speedup，**这是相对普通自回归解码的加速比**；与 EAGLE-3 的逐模型比较另列于 Table 1，不能把 4.24×说成相对 EAGLE-3 的倍率。主要结果使用 H20-3e，70B 用两卡；温度 1 的结果另列 Appendix A.8。作者还观察到 summarization 的可预测性和增益较弱，说明靠低熵上下文扩展候选的机会取决于任务。[§4.4、§5.1、Table 1、Appendix A.8](https://aclanthology.org/2026.acl-long.589.pdf)

论文局限段将泛化到其它 speculative decoding 方法列为待验证项；此外，决策树是在 EAGLE-3 轨迹上定义复杂度与 Terminal Confidence Rank，转移到不同候选排序机制时需要重新验证。论文的 4.24× 总体均值、严格接受声明和“低开销”都应连同模型、任务、硬件、树配置及温度阅读，而不是作为跨框架结论。[§7、Appendix A.2–A.8](https://aclanthology.org/2026.acl-long.589.pdf)

**阅读边界**：本精读按 ACL Anthology 正式会议版阅读，未独立复现作者实验，也未检查补充代码。论文没有提供一条独立定理来替代其继承的 EAGLE verifier 正确性条件；对其它 drafter 和 T>0 场景的分布保证需依具体实现与补充论证判断。
