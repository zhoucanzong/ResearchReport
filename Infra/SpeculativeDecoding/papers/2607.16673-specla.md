# SpecLA：当 target 的历史是递归状态，树验证怎样并行？

> Wang et al., [*SpecLA: Efficient Speculative Decoding for Linear-Attention Models*](https://arxiv.org/abs/2607.16673v1)，arXiv v1，2026-07-18，CC BY 4.0。重点阅读 §§2–8，特别是 §§4–6、Figures 3–11、Tables 1–3。结果均按论文报告；未运行代码或复现实验。

## 研究问题：递归状态没有可直接截断的“拒绝后缀”

Transformer speculative decoding 可以将草稿 KV 当作临时后缀：target 验证后，只留下接受 token 对应的 cache 位置，拒绝的后缀直接截掉。线性注意力模型则把历史压缩进递归状态；每个 token 都读写同一个稠密状态。多条草稿分支不能顺序改写同一份状态，否则兄弟分支会互相污染；若为每个候选复制完整状态，内存随树节点数增长；若验证后重跑已接受 token，又会把昂贵的 target 计算重复一遍。

SpecLA 研究的是：**如何让 stateful linear-attention target 并行验证链或树，同时只把被接受路径写入持久状态？** 论文以 Gated DeltaNet（GDN）作为具体对象。优化目标同时包括 target 验证的计算顺序、接受态恢复和可供 verifier 使用的草稿质量；它并未证明同一实现可直接覆盖所有线性注意力或状态空间模型。[§§1–3](https://arxiv.org/html/2607.16673v1#S1)

## 验证算子：链、全树与链分解混合路由

SpecLA 不假定一种 kernel 适用于所有候选树。它将树形验证中两个相反目标拆开：短链要尽量降低初始化和搬运开销；宽树要让不同分支并行，同时维持父子状态依赖、禁止兄弟分支相互影响。

### State-resident serial：沿链复用片上状态

普通逐 token decode kernel 每走一步都把递归状态写回 HBM，下一 token 再读入。SpecLA 将已知的草稿序列改成 **layer-major** 执行：按模型层处理候选 token，使相邻候选的状态 tile 尽可能留在片上，而不是在 token 间反复读写完整状态。

每个 GDN 状态太大，不能完整驻留在一个 SM 的 SRAM 中，因此 kernel 沿 value 维分块，保留完整 key 维，让每个 tile 局部更新并计算输出；若改沿 key 维切分，则输出会被分在多个 block，需要额外跨 block 归约。这个设计省的是短链验证中的状态往返，不会消除链内的父子串行依赖。[§4.1、Figures 3–4](https://arxiv.org/html/2607.16673v1#S4)

### Tree-masked parallel：把拓扑依赖嵌入递归更新

将树扁平化成多个根到叶序列会重复计算共享前缀；使用普通因果 mask 则可能使分支读到兄弟节点。SpecLA 按拓扑顺序为候选节点编号，用 **tree mask** 表示祖先关系：节点只聚合公共前缀和自己的祖先，不能看兄弟分支。

对于一般线性注意力，祖先 mask 可以约束并行状态计算；GDN 的 Delta-rule 还需将 mask 放进 UT factorization，因为更新依赖此前已校正的状态。论文将该递归关系改写成针对整棵树的因子化并行计算：从同一个 pre-tree state 得到多个候选输出，后续再选接受分支。[§4.2、Figure 5](https://arxiv.org/html/2607.16673v1#S4)

完全并行并非总是更快：树 mask、因子构造、矩阵求解和归约需要额外阶段与中间张量。对于只有少量候选的 speculative window，准备这些矩阵可能比顺序执行短链更贵。

### Chain-decomposed hybrid：把宽树拆成若干依赖链

混合路径使用 heavy-light decomposition 将候选树拆成覆盖全部节点的互不重叠链。每条链内部沿父子顺序使用低开销 serial kernel；只有当父链产生子链所需的边界状态后，多个子链才并行启动。模型层之间仍按原始层依赖顺序运行，增加的并行度来自同层的独立链。

该路线保留树拓扑，不重复计算共享前缀；又避免对很小的树总是构造完整并行矩阵。它引入的决策是**当前树更适合哪种执行形状**，而不仅是“树有多少节点”。[§4.3、Figure 6](https://arxiv.org/html/2607.16673v1#S4)

## 接受路径与持久状态的交接

候选尚未验证时，target 不知道哪一条会被接受；因此递归状态不能像 KV cache 一样简单保留节点后缀或回滚。论文比较了三种状态恢复方案：

| 恢复方案 | 暂存内容 | 接受后如何前进 | 主要代价 |
|---|---|---|---|
| 全状态快照 | 每个候选的完整递归 state endpoint | 拷贝被接受终点的 state | 内存随候选数线性增长；大状态要在 HBM 存取 |
| token replay | 候选 token 本身 | 把接受 token 重新过一遍 target | 省快照，但重算验证时已经得到的 projection 与 state factors |
| factor buffer | 每个候选的轻量状态更新因子 | 选出接受路径的因子，构造对应的 state delta | 需要保留 layer-specific 更新量；比完整 state 小，也避免 replay |

GDN 的更新可拆成较重的 `FactorGenerate` 和较轻的 `DeltaConstruct`。验证阶段保存生成的 key/value、衰减和 Delta-rule 因子；接受路径确定后，系统只收集该路径因子并构造增量。这个机制不保存完整分支状态，也不重跑 target 主体。[§5.1、Figure 7](https://arxiv.org/html/2607.16673v1#S5)

**Delayed state update** 进一步把接受态更新移到下一轮验证开始时，与下一轮 kernel 融合。若独立 commit kernel 先读写 state、下一次 verify 又重新加载 state，就会多一次 HBM 往返；把 pending accepted factors 留到下一轮，可以在加载一个 state tile 后先应用增量，再立即验证新候选。[§5.2、Figure 7](https://arxiv.org/html/2607.16673v1#S5)

这是一条与 Transformer KV cache **不能等同**的状态交接路径：KV 的拒绝通常是截尾，recurrent state 则必须恢复到被接受路径的数值状态。因子缓冲能否使用，取决于具体 state update 是否可分解并从所存中间量准确重建；论文对 GDN 给出构造，未证明所有 stateful model 共用相同因子结构。

## Draft 侧为何也必须 target-aware

即使 verifier 很快，低质量草稿仍会浪费它的递归计算。SpecLA 用目标 GDN 的 recurrent features 训练 EAGLE-style drafter，并在送入 verifier 前按累计 draft path log-probability 修剪低置信分支。筛选只减少验证节点；接受规则仍由 target 决定。

这让 draft 构造与 target kernel 的可用并行度相连：不是单独最大化 proposal tree 的宽度或 draft token 数，而是尽量提供 verifier 可以有效处理、且有望被接受的路径。[§6.1–6.2、Figure 8](https://arxiv.org/html/2607.16673v1#S6)

| 实验 | 作者报告及条件 | 能说明什么 / 不能说明什么 |
|---|---|---|
| 端到端生成 | NVIDIA H100，纯 GDN-1.3B target；EAGLE-style 混合提示集、GSM8K、HumanEval；greedy，最多生成 128 token。SpecLA 分别报告 1.42×、1.70×、1.06× 对 AR speedup。[§8.1–8.2、Fig. 9] | 小幅收益和接近 AR 的任务说明目标 kernel 变快仍要有足够可接受草稿；不是对所有 LLM 或服务负载的泛化结果。 |
| 树形验证微基准 | 对相同候选树比较 serial、tree-parallel、hybrid；在指定 runtime-like 树形中，hybrid 相对 serial 报告 1.39–1.92×，相对 root-to-leaf replay 的部分形状最高 7.11×。[§8.3、Fig. 10、Table 1] | 这是 GDN target 的 kernel/拓扑微基准，不是端到端 tokens/s，也不能与论文的整体 speedup 混算。 |
| 状态管理微基准 | GDN-1.3B 的指定维度、每层 state 约 2 MiB；8 个候选的 factor buffer 论文报告为 128.5 KiB/layer，full-state snapshot 约 16 MiB/layer。factor reuse 对 token replay 的 commit-boundary latency 报告为 2.74–4.28×。[§5.1、§8.4、Fig. 11] | 说明当前 GDN 设置中 snapshot 和 replay 的各自开销；不是所有线性层都得到相同比例收益。 |

所有速度数字均是作者在其 GDN 实现与 H100 配置下的报告，未独立运行。论文称实现使用 PyTorch 与 Triton 并嵌入 EAGLE-style runtime，但未提供 SpecLA 实现仓库/固定 commit；因此这里是论文机制精读，不是源码审读。论文还以结果 hash 对齐 AR 输出；“无损”在这里指相对 target greedy decoding 的输出一致性，不意味着 kernel 浮点计算在任意硬件上 bitwise 相同。[§7–8](https://arxiv.org/html/2607.16673v1#S7)

## 放回投机解码的算子/状态地图

| 执行对象 | Transformer full-attention target | SpecLA 的 GDN target |
|---|---|---|
| 验证拓扑 | 展平候选节点，树 mask 限定每个 query 可读的祖先；所有节点在一次 target forward 中并行打分 | tree mask 还要进入递归更新的 UT factorization；serial、全树 parallel、chain-decomposed hybrid 对应不同树形/开销 |
| 拒绝后的 KV/state | 接受前缀写入 KV，拒绝后缀释放或截断 | full-state snapshot / replay / factor buffering 之间选择，只有接受路径更新持久状态 |
| 下一轮接续 | 延续 committed KV prefix | 可以独立更新 state，或把 accepted factors 延迟到下一轮 fused commit-and-verify |

已有 [SpecInfer](2305.09781-specinfer.md) 与 [Sequoia](2402.12374-sequoia.md) 帮助理解 KV-cache target 上的树构造、mask 与硬件树预算；[vLLM](vllm-implementation.md) 和 [SGLang](sglang-implementation.md) 固定源码分册解释 proposer、拒绝采样和树节点选择，但没有审读 attention backend / CUDA graph 的全部低层实现。SpecLA 的新增重点是**target state 的并行验证和恢复**；它不是树 mask 的基础定义，也不能代替对常规 Transformer kernel 的研究。
