# RheoSampling：随机动态树的 one-hot 困境与双身份解耦（Hu et al., 2026）

> **一手来源**：arXiv:2609.21827 **v1**（2026-09-18），正文 HTML 逐节读取；license = **arXiv.org perpetual non-exclusive license**。｜ **主等级**：`[精读原文]`
> **一句话定位**：动态树（EAGLE-2/3）在 T>0 时把草稿分布塌缩成 one-hot；RheoSampling 给“采样出来的那个 token”两个概率身份——**建树用 proxy、验证用真实采样概率**——从而第一次同时做到「上下文感知 top-K 建树 + 随机采样 + 严格无损」。
> **亮点与差异四行**
> - **一句话亮点**：不改 EAGLE-3 的草稿模型、不重训，只改“建树/验证”的概率语义，就把 T=1.0 下的平均接受长度从 **5.04 提到 5.25**、端到端加速从 **2.84× 提到 2.93×**（Llama-3.1-8B）。
> - **新在哪**：① 指出“同一 draft 分布同时用于建树与验证”是 one-hot 塌缩的根因；② 用 **proxy 概率**（与采样 token 取值无关）保住“存活与取值独立”，这是无损性的关键；③ 用 **OT 验证**重分配残差质量，比无放回递归拒绝采样（RRSw）接受率更高；④ 给出等价类分析下的 Theorem 1。
> - **证据强度**：中上。6 benchmark × 3 target（Llama-3.1-8B / Vicuna-13B / DeepSeek-R1-Distill-8B），每个 80 题，3 seeds，单张 A6000；有 m/温度/验证策略消融；但**没有代码/权重**，所有数字为论文自报、未独立复现，也没有 batch>1 的数据。
> - **值不值得引用**：**值得作为“T>0 动态树无损修复”的首选引用**；引用时必须带 T=1.0、树宽 60/深度 8、单卡 A6000、EAGLE-3 官方 checkpoint 这些条件。

## 1. 问题：one-hot 困境的准确表述

### 1.1 两个互相冲突的概率角色（§1、§3）

同一个 draft 分布 `q` 被用于两件事：

| 角色 | 用途 | 需要的性质 |
| :-- | :-- | :-- |
| **建树** | 决定哪些 token 进树、树的拓扑、剪枝 | 排序稳定，能近似“哪条路径会被接受” |
| **验证** | 决定输出分布是否等于 target `p` | 必须用草稿**真实采样分布**的概率 |

- **T=0**：两者不冲突。draft 的 top-1 通常与 target 对齐，按 `q` 排序既是一棵好树，也基本等于接受顺序。
- **T>0**：冲突显式化。接受判据是 `η ≤ min(1, p(x)/q(x))`，**是否接受取决于比值，而不是 `q(x)` 的绝对大小**。按 `q` 排序建树 → 树收敛到少数高 `q` 分支 → 近似 one-hot → 丢掉了随机性，也不再预测接受。

### 1.2 为什么“直接改成采样”会破坏无损性

若把 top-K 换成“随机采样后仍按 `q` 排序”，则一个 token **能否在树中存活**取决于它自身的取值；对“存活”取条件，会让存活 token 的条件分布偏离原采样分布 `q̃`。验证阶段再用 `q̃` 判接受，基准就错了，输出分布不再等于 `p`。

> 论文把这叫“**建树/验证耦合**”：不是实现细节，而是概率语义层面的错误。

## 2. 方法：双身份 + 混合采样 + OT 验证

### 2.1 混合采样（§3.2）

每个扩展步分配 K 个槽位：

| 槽位 | 内容 | 目的 |
| :-- | :-- | :-- |
| 前 **m** 个 | 按 `q` 确定性取 top-m（lead tokens） | 保住高质量骨架 |
| 第 **m+1** 个 | 从**残差分布** `q̃`（top-m 之外的尾部）采样一个 token `x_s` | 注入随机性 |
| 其余 | 用剩余词表中排名最高者填充（fill tokens） | 填满预算 |

### 2.2 同一个 token，两个概率身份（§3.2）

| 阶段 | 用的概率 | 公式/性质 |
| :-- | :-- | :-- |
| 建树/排序/剪枝 | **proxy** | `q_proxy(x_s) = min{ q(x_m), z }`，其中 `z = 1 − Σ_{i≤m} q(x_i)` 是残差质量 |
| 验证 | **真实采样概率** | `q̃(x_s)` |

- 关键：`q_proxy` **与 `x_s` 的取值无关**。因此“这个槽位能否穿过全局剪枝”与“它采到了什么 token”独立——这是无损性的命门。
- 边界 `m=0`：取 `q_proxy = q(x_1) + ε (ε>0)`，把采样 token 锚在首位。
- **Lemma 1**：proxy 与 `q̃` 独立是**必要但非充分**；还必须满足排序下界 `q_proxy ≥ q(x_{m+1})`。论文给了反例：词表 `{A,B,C}`、`q={0.5,0.3,0.2}`、`K=3, m=1` 时，若取 `q_proxy=0.25`，存活 token 会被强制成 `B`（概率 1）而不是 `q̃(B)=0.6`。

### 2.3 无损性定理（§4）

**Theorem 1**：对任意剪枝预算 `R ≥ 1` 与任意 token 序列 `Seq`，

`E_{T_R}[ Pr(Rheo(T_R) = Seq) ] = p(Seq)`

证明难点：动态树本身是随机的——采样的 `x_s` 同时决定自身取值与后续 fill tokens 的身份，进而影响更深节点的路径分数与剪枝；两层随机性强耦合。论文用**等价类分析**把随机树空间压成可处理类别。

### 2.4 OT 验证（§3.3）

- 若 `x_s` 存活，先用真实采样概率独立验证 `min(1, p(x_s)/q̃(x_s))`；若被拒，用残差 `r = norm(max(0, p − q̃))` 在候选集上递归拒绝采样。
- 论文比较了 OT 与 **RRSw**（无放回递归拒绝采样）：OT 全局重分配质量、与 `p` 的重叠更大，采样 token 接受率更高。

### 2.5 两个实现前提

1. **稀疏分布**：softmax 前把 logits 截到 **top-128**，其余置 `−∞`。只要**验证阶段使用同一截断分布**，无损性不受影响；top-128 覆盖了 draft 的大部分概率质量。
2. **温度与建树解耦**：建树（扩展 + 重排）**不做温度缩放**，沿用原始 draft 概率排序；温度只作用于采样与验证。理由：低温会破坏 token 相对排序的序信息。

### 2.6 `m` 是连续旋钮

- `m` 小 → proxy 大 → 采样 token 更易存活、随机探索更能落地，但确定性骨架变弱。
- `m` 大 → 拓扑质量高，但采样 token 可能被剪掉。
- 论文默认 **m=1**：在多数设定最好或接近最好。

### 2.7 与 EAGLE-3 的兼容性：不改模型，只改概率语义

RheoSampling 不训练新 draft、不改 EAGLE-3 的 checkpoint，只改三处逻辑：

1. **扩展时**：前 m 个槽仍取 top-m，第 m+1 个槽从残差 `q̃` 采样；
2. **排序/剪枝时**：采样 token 用 proxy 分数参与，而不是它的真实 `q̃`；
3. **验证时**：用真实 `q̃` 判接受，拒绝后走 OT 残差重分配。

这意味着它可以作为 EAGLE-3 推理栈的**替换模块**（理论上），代价是每步多一次采样 + OT 验证开销。论文报告的净加速为正，说明这笔开销小于随机探索带来的接受长度增益。

### 2.8 为什么 top-128 截断不影响无损性

无损性要求“验证用的分布 = 采样用的分布”，而不是“分布必须是完整词表”。只要建树、采样、验证三处都用**同一个 top-128 截断分布**，Theorem 1 的证明对截断分布同样成立。反过来，如果建树用 top-128、验证用完整词表，接受判据的基准就变了——**这是一个容易被实现忽略的前提**。

## 4. 结果（带条件）

| target | 采样方式 | τ | 端到端加速 | τ 增益 |
| :-- | :-- | --: | --: | --: |
| Vicuna-13B | Top-K（基线） | 5.75 ±0.03 | 3.37× | — |
| Vicuna-13B | **RheoSampling** | **5.89 ±0.03** | **3.43×** | +0.14 |
| Llama-3.1-8B | Top-K | 5.04 ±0.02 | 2.84× | — |
| Llama-3.1-8B | **RheoSampling** | **5.25 ±0.03** | **2.93×** | +0.21（+4.2%） |
| DeepSeek-R1-Distill-8B | Top-K | 4.99 ±0.01 | 2.89× | — |
| DeepSeek-R1-Distill-8B | **RheoSampling** | **5.21 ±0.02** | **2.99×** | +0.22 |

- **加速增益小于 τ 增益**（Llama-3.1-8B：τ +4.2%，加速只 +3.2%），因为随机探针的采样与验证本身有额外开销；作者称净加速在所有模型上严格为正。
- 论文强调这是**相对自回归**的绝对加速，不是“相对 EAGLE-3 的提升”；与 ARC-Decode 的“相对 EAGLE-3 最高 1.6×”不是同一量纲。

## 5. 消融：m、温度、验证策略

| 变量 | 对照 | 结论 |
| :-- | :-- | :-- |
| 旋钮 `m` | 0 / 1 / 2 / ≥3 | **m=1 多数设定最好**；m=0、2 也可行且优于 Top-K；m≥3 时 proxy 被摊薄，采样 token 在重排阶段被剪掉，收益退化 |
| 温度 | T→0 / T=1.0 | T→0 时采样退化为确定性取 top token，Top-K / RRS / OT 三类验证趋同；**方法价值集中在“温度不是极低”的采样区间** |
| 验证策略 | OT vs RRSw | OT 全局重分配质量，采样 token 接受率更高 |
| 稀疏截断 | top-128 | 保留大部分概率质量；验证必须用同一截断分布 |
| 树参数 | 60/8（固定） | 未做树宽/深度扫描；换参数需重测 |

**T→0 的两种退化模式**（§5.4）：`m=0` 是“双重退化”（采样与拓扑都回到 Top-K）；`m=1` 是“单重退化”（采样坍缩，但拓扑因 proxy 不匹配 `q(x_2)` 仍与 Top-K 不同）——这正是 `m=1` 与基线在低温下仍有差距的原因。

## 6. 失效边界（独立段）

1. **没有公开代码/权重**：论文未放代码、HF 页面 404；所有数字为**论文自报**，未独立复现（`[⚠️受限核验]` 的复现层）。
2. **只测单张 A6000、batch=1**：没有高并发/大 batch 数据；与 CAST 的“batch 场景边际收益为负”、MagicDec 的“长上下文大 batch 反转”是否冲突**未知**。
3. **T→0 退化**：温度越低，随机探针越接近确定性；方法收益集中在 T 不太低的采样区间。
4. **top-128 截断是前提**：验证必须使用与建树相同的截断分布；换截断（top-64/256）会改变接受率与无损性前提。
5. **树参数未扫描**：固定 60/8；EAGLE-2 的 7B 设置是 60/6，换树参数后 τ 与加速比不可直接比。
6. **m 依赖任务**：m=1 是“多数设定”最优，不是所有任务最优；论文自己也说 m=0/2 可行。
7. **与结构化输出约束的耦合未测**：vLLM 的 `num_draft_tokens` 会扣除被约束作废的草稿，RheoSampling 未讨论这种场景。
8. **OT 的额外成本**：验证阶段的重分配不是免费；论文报告净加速为正，但没有给出 OT 自身的耗时拆解。

## 7. 与同类系统的可判定差异

| 维度 | RheoSampling | Top-K 动态树（EAGLE-2/3） | 静态树 + 采样 | Traversal Verification | ARC-Decode |
| :-- | :-- | :-- | :-- | :-- | :-- |
| T>0 支持 | ✅ 原生 | ⚠️ 塌缩为 one-hot | ✅ | ✅（不改采样语义） | ✅（专为采样设计） |
| 输出分布 | **严格等于 p**（Theorem 1） | 严格（greedy 主结果） | 严格 | 严格 | **有界风险**（JS 上界） |
| 建树/验证解耦 | ✅ proxy / 真概率双身份 | ❌ 同一分布两种用途 | 部分（拓扑与取值无关） | ❌ 改遍历，不改建树 | 放宽验证判据 |
| 改的是什么 | 建树期随机性 + 验证概率重分配 | 基线 | 拓扑固定 | 遍历顺序与判据粒度 | 接受判据 |
| 典型收益（条件） | τ +0.14~0.22；加速 +3~4% | 基线 | 低于动态树 | τ +2.2%~5.7% | 相对 EAGLE-3 最高 1.6× |
| 证据等级 | 精读原文（未复现） | 精读原文 | 由 Rheo 对比论述 | 精读原文 | 摘要级 |

**可判定差异一句话**：RheoSampling 与 Traversal Verification 都保严格无损，但前者改“**建树+验证的概率语义**”，后者改“**验证的遍历顺序**”；两者理论上可叠加。ARC-Decode 则主动放弃严格无损，换更高的接受率——三者不是同一保证等级，不能相减。

## 8. 对本条目结论的影响

- **“无损”要分等级**：严格分布等价 / 序列级等价 / 有界风险。RheoSampling 是严格一档；引用时不能与 ARC-Decode 混排（见 [topics/verification-acceptance.md](../topics/verification-acceptance.md)）。
- **T>0 是动态树的真实边界**：EAGLE-2/3 的“动态树更优”只在 greedy 下成立；RheoSampling 给出了机制级修复，但**默认 EAGLE 配置并未启用它**——这意味着线上 T>0 服务仍可能踩坑。
- **指标必须成对报告**：τ 与 acceptance rate 分母不同、会反向移动；只报一个会得出相反结论（见 [topics/verification-acceptance.md](../topics/verification-acceptance.md) §2）。

### 8.1 工程落地成本

| 成本项 | 说明 |
| :-- | :-- |
| 每步多一次采样 | 从残差 `q̃` 采一个 token，词表大时有开销；top-128 截断是为控制这项成本 |
| OT 验证 | 拒绝后要重分配残差质量，比标准 `min(1,p/q)` 多一步归一化 |
| 额外显存 | 需要保存 `q̃` 与 proxy 分数；树宽 60/深度 8 下规模可控，但比纯 Top-K 多 |
| 实现复杂度 | 建树/验证的概率语义必须成对修改；只改建树或只改验证都会破坏无损性 |

## 9. 引用注意（何时不该引它）

- 不要说“RheoSampling 让 EAGLE-3 加速 2.93×”——2.93× 是**相对自回归**、在 Llama-3.1-8B、T=1.0、单 A6000 上的绝对加速；EAGLE-3 自己的 6.5× 是另一套条件。
- 不要把它与 ARC-Decode 的 1.6× 比较——后者是**相对 EAGLE-3**、且是**有界风险**。
- 不要声称“已复现”——没有公开代码；所有数字应标“论文自报”。
- 不要外推到 batch>1 或长上下文——论文没有这些数据。
