# ValuSpec：在 target 验证前筛掉低价值候选分支

来源：He et al., [*ValuSpec: Plug-and-Play Candidate Valuation before Target Verification for Tree-Based Speculative Decoding*](https://arxiv.org/html/2610.31338v1)，固定版本 v1（2026-10-22）。重点阅读 §2–§5，尤其 §3、§5.1–§5.4 与 Appendix A–C。

## 它优化的不是“怎样生成树”，而是已有树里哪些分支值得送验

树形投机解码能在一个 target 前向中验证多个候选，但候选树由 draft 分数、检索历史或动态树算法构建；较大的树可能包含许多很快就会偏离 target greedy 轨迹的分支。ValuSpec 把优化位置放在两个阶段之间：先接收一个已构造好的候选树，再给分支估值、筛掉低分分支，最后仍由 target 执行原有 greedy verification。

这个定位使它与树构建/剪枝算法不同：DARTree、DDTree 或 CaDDTree 改变候选如何产生/选择；ValuSpec 不改变候选供应过程，只决定现成候选中哪些会进入昂贵的 target 验证。它也不是新的拒绝采样公式或分布校正器。

## 迁移监督如何设定筛选阈值

ValuSpec 使用一个轻量 valuation model `q_φ` 为候选分支计算序列平均 log-probability。它不是 target，目标是判断该分支与 target greedy 轨迹的吻合程度。作者从与 evaluation split 分开的 calibration split 采集 target greedy trajectories，用 `q_φ` 对这些轨迹打分，并取分数分布的低分位作为迁移阈值。推理时，低于阈值的分支被过滤；剩余树再交由 target 执行标准 greedy verification。[§3、§4](https://arxiv.org/html/2610.31338v1)

ValuSpec 声称对确定性 greedy decoding 保持输出与普通 target greedy 解码一致：过滤只减少 target 要检查的候选，最终接受仍要求候选 token 与 target argmax 一致；若过滤后树空或无 token 可接受，则退回一步 target greedy 解码。它**不提供 T>0 概率采样下的输出分布保证**，不能与 `p/q` 拒绝采样或 HSD/RheoSampling 的随机路径证明混为一谈。

## 候选估值、候选供应和接受规则是三个可组合层

| 层 | 问题 | 代表机制 |
| :-- | :-- | :-- |
| 候选供应 | 树中有哪些 tokens / branches？ | retrieval trees、EAGLE-3 dynamic tree、DARTree / DDTree |
| 候选估值 | 已有候选里哪些较可能沿 target 轨迹继续？ | ValuSpec 的 target-trajectory-calibrated scorer |
| target 验证 | 什么条件下可提交 token、拒绝后怎样回补？ | 本文使用 output-identical greedy verification；sampling 需另读验证机制 |

因此它可以与某些 generation-side tree method 叠加，但“可以插入”不是跨任何树/模型的通用保证：候选树结构、估值模型校准分布、tree mask/target verifier 和空树 fallback 都是实现条件。

## 论文报告的收益限于 recurring-workload greedy 设置

论文主实验以 retrieval-based candidate trees 为主：用 70% calibration split 得阈值，evaluation split 与建树上下文再分开；在 HumanEval、GSM8K、Dolly 的 Llama-2-7B/13B、A100、greedy `T=0` 设置下，作者报告相对 AR 的 2.18×–2.38× 端到端吞吐提升。它还把模块接到 EAGLE-3 dynamic tree 上测试。这里的条件有两点尤其重要：其一，阈值来自相似历史 workload，跨数据集迁移需另测；其二，greedy 输出相同不等于随机采样分布相同。[§4、§5.1–§5.3、Appendix C](https://arxiv.org/html/2610.31338v1)

作者也报告在 Qwen3.5-9B / Qwen3.5-0.8B 条件下的扩展实验；这仍是论文提供的模型与运行配置，不应从跨候选供应商的单次实验推导所有 tree builder 都能获得相同收益。ValuSpec 的核心贡献是候选估值成为一个独立可插拔阶段，而不是“tree decoding 一定更快”。

**带走的区别**：ValuSpec 的筛选发生在 target 验证前，目标是减少验证冗余；最终正确性仍来自后续 target greedy verification。不要把“候选过滤器”写成新 verifier，也不要把 output-identical greedy 保证扩写为概率分布无损。
