# DDTree：用扩散草稿的位置分布搭候选树

**原文**：[arXiv 2604.12989v1](https://arxiv.org/html/2604.12989)，CC BY 4.0。阅读 §3–§5、Algorithm 1、Table 1–2 与 Appendix A–B。未独立运行。

## 从单条草稿到多条有希望的前缀

一次 block-diffusion 前向会给未来多个位置分别产生 token 分布。最简单的 DFlash 取一条草稿路径交给 target；它忽略同一轮中其它位置候选所对应的替代前缀。DDTree 把这些边际位置分布转成树节点概率的乘积，为候选前缀打分，然后在固定节点预算下用 max-heap best-first 搜索，选出最可能延长接受前缀的树，最后由 target 一次前向做 tree attention 验证。

论文证明，按其 draft-induced surrogate 目标，best-first 能找到节点预算下的最优树。这里的“最优”是对**草稿定义的替代目标**而言；它不等于对 target 真正接受长度的无条件最优，也不消除 target verification 的计算成本。

## 与 DFlash 和 DARTree 的关系

DDTree 复用 DFlash 的块扩散 draft，把问题放在“怎样利用各位置已经算出的分布”。DARTree 后来指出，单纯相乘边际分数忽略每条路径的因果前缀；它加入 autoregressive correction head。再往后，DARTree 批量计算同一深度的分支校正，并把剪枝延后，减少逐节点 heap 调度造成的串行开销。于是三篇的机制关系是：**低延迟块草稿 → 候选树覆盖 → 路径校正与并行树构造**。

## 作者报告的结果与限制

作者在 8 张 H200 上对 Qwen3-4B、Qwen3-8B 和 Qwen3-Coder-30B-A3B，评估数学、代码和对话任务；温度为 0 与 1。每个模型、数据集、温度的 DDTree 结果从节点预算 16–1024 中选取最佳值。[§5.1–5.2、Table 1]

论文报告 Qwen3-4B、T=0 的 AIME24 加速从 DFlash 5.56× 到 DFlash+DDTree 7.27×；该条件下平均接受长度由 7.54 增至 10.37。这是该 GPU、target、任务和预算搜索下的作者报告结果，不等于所有负载都会获得相同增益。树预算不足会错过有用路径，预算过大则增加 target 验证成本；不同任务的最佳预算并不相同。[Table 1、§5.3–5.4]

这篇适合回答“一个 diffusion drafter 算出很多候选，怎样用 target 前向有效验证？”路径分数只是近似接受机会的排序信号；DARTree 与 PRESTO 会进一步处理位置分布不含前缀条件的信息缺口。
