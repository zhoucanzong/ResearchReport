# HSD：在可访问分支间分层平衡概率质量

> **固定版本**：arXiv `2601.05724v2`，2026-03-02；license = **CC BY 4.0**。固定来源：[HTML v2](https://arxiv.org/html/2601.05724v2)、[PDF v2](https://arxiv.org/pdf/2601.05724v2)。下载 PDF SHA-256：`910af2b7672c5a277cba1967688438525f3c334605301b1bdffa0441ee04cc17`。
>
> **一句话定位**：Hierarchical Speculative Decoding (HSD) 在完整可访问分支层级上重新分配 draft 与 target 的过剩/不足概率质量，使联合序列验证不必枚举词表上的所有可能路径，同时在期望意义下精确恢复 target 分布。
>
> **亮点与差异四行**
> - **方法**：按已接受前缀构造分层 resampling 分布；在分支局部无法填补的 target 欠额，由其它分支的过剩质量跨层补足。它是概率质量平衡算法，不是把候选 token 的概率近似成相等。
> - **Qwen 结果**：GPTQ int8 Qwen2.5-0.5B draft + 72B target、单张 H20、T=1；Table 1 的 HSD 速度为 GSM8K **32.52**、HumanEval **27.48**、CNN/DailyMail **12.33 tokens/s**。相对 tokenwise 分别 +3.3%、+4.4%、+3.6%。
> - **Table 4 的边界**：Table 4 是 LLaMA-3 与 EAGLE-3 结果，不是 Qwen。EAGLE-3 的 top-K draft 槽位在此设置下等概率，理论上各 verifier 退化为相同行为；Table 4b 的 80.49 vs 71.59 tokens/s 主要归因于 HSD 实现绕过 EAGLE tokenwise verifier 的显式循环，接受率差可能来自随机性和浮点精度。
> - **证据与限制**：论文给出理论证明及多模型、任务和消融；未在此独立运行论文代码或 benchmark。主实验集中在 Qwen2.5、单 H20 与温度/草稿长度扫描，不能据此推断任意推理栈的端到端收益。

## 1. 机制与保证

### 1.1 从 token 残差到分支层级的质量平衡（§3–§5）

Tokenwise speculative sampling 以 `min(1, p/q)` 接受 draft token，拒绝时按正残差 `max(p−q, 0)` 重采样。对单 token，target 的过剩与不足总质量相等；对序列前缀，局部分支里的过剩/不足不必相等。HSD 用 branch divergence 表示该不平衡，并利用定理 4 的父子分支关系，把一个层级的正、负不平衡总量连接起来。于是某个分支内不够恢复的 target 质量，可以由层级中其它可访问分支的 draft 过剩质量补偿。

操作上，HSD 沿候选序列从深到浅检查接受条件，确定最后接受位置，再使用相应层级的 resampling 分布一次回退采样；候选序列的联合概率不需要对词表中的所有可能续写显式求和。定理和附录证明其最终生成序列的分布等于 target 分布。

**不要混淆等概率 top-K 与 HSD。** HSD 的分层平衡是按 target/draft 概率及分支比例计算的随机校正，保证完整输出分布无损。论文 Table 4b 的 EAGLE-3 设置则让候选 top-K 槽位具有相同的 draft 概率；作者据此指出，各 verifier 理论上退化到同一行为。那是该集成实验的候选构造特性，不是 HSD 的概率近似，也不能解释为 HSD 在此处获得了接受率优势。

### 1.2 与 blockwise 和多 draft 的关系（§2、§5.3、§6）

论文将 HSD 设计为可替换 verifier 的方法，与 draft 构造相对正交。主 Qwen 结果将其与 tokenwise、blockwise 比较；多 draft 实验用 11 个候选 draft，采用 Recursive Reject Sampling (RRS) 作为 tokenwise 基线，因为它可扩展且不依赖复杂 tree attention。作者没有把 blockwise 纳入多 draft 比较，因此该表不能作为 HSD 对 blockwise 多 draft 的直接胜出证据（[arXiv v2 §5.3、§6.2](https://arxiv.org/html/2601.05724v2)）。

## 2. 实验条件与结果

| 维度 | 论文设置 |
| :-- | :-- |
| 主模型 | GPTQ 8-bit instruction-tuned Qwen2.5；draft 0.5B，target 14B/32B/72B |
| 数据 | GSM8K 数学、HumanEval 代码、CNN/DailyMail 摘要 |
| 默认参数 | 温度 1；Table 1 默认草稿长度 γ=10；单张 NVIDIA H20 96GB |
| 指标 | Block Efficiency（tokens/target step）与 Decoding Speed（tokens/s） |
| 扩展评估 | LLaMA-3.1-70B/8B 非量化 pair，8×H20；EAGLE-3-LLaMA-3.1-8B，γ=7 |
| 运行时消融 | Qwen2.5-72B/0.5B、单张 H200、100 个 GSM8K 问题，报告各解码组件耗时占比 |

### Table 1：Qwen2.5 主结果（§6.2）

| 数据集 | verifier | 72B target tokens/s | 相对 tokenwise |
| :-- | :-- | --: | --: |
| GSM8K | Tokenwise / Blockwise / HSD | 31.49 / 31.79 / **32.52** | HSD +3.3% |
| HumanEval | Tokenwise / Blockwise / HSD | 26.31 / 26.96 / **27.48** | HSD +4.4% |
| CNN/DailyMail | Tokenwise / Blockwise / HSD | 11.90 / 12.10 / **12.33** | HSD +3.6% |

这些是指定 0.5B draft、72B target、量化、GPU、温度与数据设置下的吞吐，不是普适速度倍率。Table 1 中 72B 的 BE 增益也依任务而变：GSM8K +3.3%、HumanEval +3.3%、CNN/DailyMail +4.3%。

### Table 4：不同实验，不应与 Qwen 数字串表（§6.2）

- **Table 4a**：LLaMA-3.1-70B/8B、8×H20；单 draft HSD 为 9.18 tokens/s（tokenwise 8.41），多 draft HSD 为 11.02 tokens/s（tokenwise 10.21）。
- **Table 4b**：EAGLE-3 集成。EAGLE-3 71.59 tokens/s；EAGLE-3H 80.49 tokens/s（+12.4%）。候选 top-K 槽位等概率，理论上各 verifier 的行为相同；作者认为 BE 的 +4.4% 可能来自采样随机性和浮点精度。论文将明显的吞吐改善归因于 HSD 实现避免了 EAGLE tokenwise verifier 的显式循环。该实现层面的速度对比不等价于接受行为的理论改进。

附录 H 的 runtime breakdown 另在单 H200 测 100 个 GSM8K 问题：verification 为 blockwise 0.160 ms/token（0.47%）和 HSD 0.127 ms/token（0.37%）；target forward 约占 72–73%，draft forward 约占 23–24%。这支持“此测试配置中 verifier 占比小”，不能证明其它框架或硬件上开销同样可忽略。
