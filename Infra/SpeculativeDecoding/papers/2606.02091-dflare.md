# DFlare：让每层 draft 学会看不同的 target 层

**原文**：[arXiv 2606.02091v2](https://arxiv.org/html/2606.02091)，CC BY 4.0。阅读 §3–§7、Table 1–2 与 Appendix A。未运行作者代码或模型。

## 问题和机制

DFlash 证明块扩散草稿可用较少的串行步骤提出更长候选；DFlare 追问扩散 draft 是否还能更大、更有表达力。作者认为 DFlash 的融合路径形成瓶颈：所有 draft 层共享从少数 target 层合成的单一表示，draft 加深后每层看到的 target 知识仍趋同。

DFlare 让每个 draft 层分别学习一组 target 层融合权重，再通过异构 KV 投影注入各层。每层因此可以选择对自己有用的 target 深度组合。训练上同时增加数据，并用 progressive position-weighted loss：训练早期先学靠前、较容易接受的位置，随后逐渐增加后续位置的权重。

这是“draft 并行之后，如何增加容量”的后续路线：DFlash 提供一次块前向与 target 特征注入，DFlare 改善各层的特征融合和训练课程。它仍保留 AR target 的验证职责，二者的正确性逻辑相同；主要变化在 draft 质量和训练成本。

## 作者报告的证据

实验用 Qwen3-4B、Qwen3-8B、GPT-OSS-20B，七层 draft、block size 16、六个数学/代码/对话基准；训练数据约 2.4M 条。[§5.1–5.2]

论文报告贪心设置下，相对 DFlash 的平均接受长度增益分别为 15.5%、14.7%、5.8%；端到端 wall-clock 加速增益为 10.6%、8.1%、5.4%。作者报告六项基准平均加速为 5.52×、5.46×、3.91×。这些是对应模型、数据、draft 深度、块长和作者运行配置下的结果；不能直接与其他论文标题数字比较。[Table 1]

作者也明确写出代价：较大的 draft 与训练集带来更高训练成本，且更大数据规模仍未探索。消融显示分层融合、异构 KV 投影和位置权重均对结果有贡献，不能把全部提升归因于单一模块。[§6、Table 2、§7]

## 阅读意义

DFlare 说明块扩散的并行性不会自动带来高接受率；它腾出了更大的 draft 预算，但要用 target 内部信息、网络结构和训练数据把预算转成更像 target 的候选。真正的取舍是“一次并行草稿能接受多少”与“提高接受率要花多少训练/模型容量”，而不是单看 diffusion 模型的 token 并行数。
