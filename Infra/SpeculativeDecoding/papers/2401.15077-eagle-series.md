# EAGLE / EAGLE-2 / EAGLE-3：特征级草稿、动态树与训练目标演进（2024–2025）

> **一手来源**：EAGLE = arXiv:2401.15077 **v3**（2025-03-04）；EAGLE-2 = arXiv:2406.16858 **v2**（2024-06-30）；EAGLE-3 = arXiv:2503.01840 **v3**（2025-04-23）。三篇均按正文 HTML 逐节读取。｜ **主等级**：`[精读原文]`
> **一句话定位**：EAGLE 把「草稿」从 token 级搬到 **target 倒数第二层特征**的级联，EAGLE-2 把静态草稿树改成 **上下文感知的动态树**，EAGLE-3 再去掉「必须拟合 target 特征」的约束、用 **Training-Time Test（TTT）+ 多层特征融合** 直接预测 token——三步把自投机推到“单卡可训、vLLM/SGLang 的特定实现路径”的工业位置。
> **亮点与差异四行**
> - **一句话亮点**：用 target 自己的隐藏特征做自回归草稿，比独立小模型更快、比 Medusa 多头更准，且**输出分布不变**（无损）。
> - **新在哪**：① EAGLE-1 首次系统论证「特征级自回归优于 token 级」并用 **shifted token** 消除特征不确定性；② EAGLE-2 用 draft 置信度的**路径连乘**做动态树扩张/重排；③ EAGLE-3 用 TTT 把「训练时模拟多步验证」写进训练目标，并放开对顶层特征的依赖，使**加数据继续涨点**。
> - **证据强度**：强。三篇合计覆盖 Vicuna / LLaMA2-Chat / LLaMA3-Instruct / Mixtral 8x7B，MT-bench / HumanEval / GSM8K / 对话 / 代码 / 数学 / 指令跟随；EAGLE-3 有 SGLang 生产框架的 batch 扫描（batch=1 与 64）；消融把「特征 vs token」「是否动态树」「是否 TTT」逐项拆开。
> - **值不值得引用**：**值得，且必须带条件**。引用 EAGLE 系数字时要同时给「模型 / 温度 / 树参数 / batch」；**greedy（T=0）下报告值不能外推到 T>0**（见 §9 与 [topics/verification-acceptance.md](../topics/verification-acceptance.md)）。

## 1. 问题：为什么“再训一个小模型”不是答案

经典投机解码（Leviathan / Chen，2023）要求 draft 与 target **同 tokenizer、同分布族**，且 draft 足够小才划算。EAGLE 论文把这条路径的困难拆成三条（§1）：

1. **7B 以下没有合适的 draft**：LLaMA2 系列里 7B 已是“最小可用”，再小就没有同族模型；用 7B 给 13B 做 draft，draft 自身开销把收益吃光（正文实测 13B **无加速**、33B **1.12×**、70B **1.88×**——这是“独立 draft”路线的天花板证据）。
2. **跨族 draft 的分布漂移**：TinyLLaMA 一类与 instruct 模板不一致，接受率崩。
3. **训练成本**：为每个 target 单独训一个 draft 太贵（论文引 SpecInfer 报告的 **275 A100 GPU-hours** 作为对照）。

EAGLE 的回答是：**不另起一个模型，而是在 target 的第二层顶层特征上做自回归**，再用 target 自己的 LM head 解码成 token。草稿头只加一个 FC + 一个 decoder layer。

## 2. EAGLE-1：特征级自回归与 shifted token

### 2.1 两个观察

- **观察一（特征比 token 平滑）**：在 target 倒数第二层特征（LM head 之前）上做自回归，比直接在 token 上做更“规整”。同一实验设置下，token 级加速 **1.5×**，特征级到 **1.9×**（MT-bench、Vicuna 7B、T=0，图 4）。
- **观察二（特征不确定性）**：给定当前特征 `f_t`，下一个特征并不唯一——它取决于 target 采样出哪个 token（“I am” vs “I always”）。直接把 `f_t` 喂给草稿头会引入歧义。
- **解法**：输入**超前一步的 token 序列**（shifted tokens）。即预测 `f_{t+1}` 时同时喂 `f_t` 与 `t_{t+1}`（上一轮已采到的 token）。加上这一步，加速从 1.9× 提到 **2.8×**（同图 4 条件）。

### 2.2 架构（§3.1，图 6）

| 组件 | 是否训练 | 作用 |
| :-- | :-- | :-- |
| Embedding | ❄️ 复用 target | 把 shifted token 变成向量 |
| Autoregression Head | ✅ 训练 | 一个 FC（2d→d）+ **一个 decoder layer**，输入是 `[feature; token_embed]` 拼接 |
| LM Head | ❄️ 复用 target | 把预测出的特征映射回词表分布 |

- 草稿头参数量约为主模型的 **~7%**（单层 decoder + FC），这是“单卡可训”的来源。
- **树注意**：草稿不是一条链，而是一棵树；target 一次前向并行验证整棵树。论文给的例子是 **3 次草稿前向生成 10 个 token 的树**（图 6）。
- **无损性**：树每个节点递归套用投机采样（附录 A.2），与 SpecInfer 的树验证同源，输出分布严格等于 target。

### 2.3 训练目标（§3.2）

- **特征回归**：Smooth L1（对预测特征与 target 特征）。
- **token 分类**：交叉熵（对 LM head 输出的 token 分布）。
- **数据增强**：给 target 特征加 `U(−0.1, 0.1)` 的均匀噪声，缓解特征误差沿链累积。
- 两个损失同时用；但不能由跨方法的接受率差值单独归因于特征监督；需要同 target、数据、温度、树预算的消融对照。

### 2.4 树结构与验证

- 树深度 `m`、每层扩张若干节点，`m` 次草稿前向即可得到「深度 m、节点数 > m」的树（附录 A.1 给实际树形）。
- 验证阶段用 tree attention 一次算完所有节点，再按投机采样规则逐节点接受/拒绝；被接受路径上的特征会被缓存给下一轮草稿。
- **树 vs 链的消融**（表 5、图 7，MT-bench、T=0）：树把平均接受长度抬高 **0.6–0.8**、加速比抬高 **0.3–0.5×**；不用树时 EAGLE 仍有 **2.3–2.7×**。

## 3. EAGLE-2：把静态树换成动态树

### 3.1 核心洞察

EAGLE-1 的树是静态的，隐含假设「第 k 个位置的接受率只取决于位置」。EAGLE-2 的经验发现是：**接受率还取决于上下文**；而 EAGLE 的 draft 是**良好校准**的（confidence ≈ 接受率，误差小），于是可以用 draft 概率构造动态树。

### 3.2 两阶段：扩张 + 重排（§4.1–4.2）

| 阶段 | 做什么 | 依据 |
| :-- | :-- | :-- |
| **Expansion** | 从当前层选 **top-k** 个节点送入 draft 继续长 | 节点的 **value = 从根到该节点 confidence 的连乘**（即“全局接受概率”） |
| **Rerank** | 从所有节点里再选 **top-m** 组成最终草稿 | 同样按 value；同 value 时优先浅层，保证选出的节点仍连通成树 |

- 为什么用 value 而不是单点 confidence：单点 confidence 是局部的，无法反映“前缀都被接受”的概率；value 是路径连乘，才是真正的接受概率上界。
- 两个阶段解决不同问题：expansion 负责“加深”，rerank 负责“把浅层但更可能被接受的分支捞回来”。

### 3.3 关键超参（附录）

| 项 | 7B / 8B | 13B | 70B |
| :-- | :-- | :-- | :-- |
| 草稿 token 总数 | **60** | **50** | **48** |
| 树深度 | **6** | 6 | 6 |
| 每层扩张节点数 | **10** | 10 | 10 |

> 注意：EAGLE-3 论文与 RheoSampling 复现时用的是「树宽 60、深度 8」，与 EAGLE-2 附录的 7B 设置（60/6）不同——**引用时要写清树参数**，否则 τ 不可比。

### 3.4 结果（T=0，MT-bench，表 2）

| target | 方法 | 加速比 | 平均接受长度 τ |
| :-- | :-- | --: | --: |
| LLaMA2-Chat 70B | EAGLE | 3.01× | 3.81 |
| LLaMA2-Chat 70B | **EAGLE-2** | **3.51×** | **4.48** |
| LLaMA3-Instruct 70B | EAGLE | 2.83× | 3.62 |
| LLaMA3-Instruct 70B | **EAGLE-2** | **3.29×** | **4.16** |
| LLaMA3-Instruct 8B | EAGLE | 2.72× | 3.65 |
| LLaMA3-Instruct 8B | **EAGLE-2** | **3.46×** | **4.53** |

摘要口径：三系列模型 × 六任务上 **3.05–4.26×**，比 EAGLE-1 快 **20–40%**。

## 4. EAGLE-3：去掉特征预测约束，让“加数据”继续有效

### 4.1 问题：EAGLE 的 scaling 瓶颈

EAGLE-1/2 的草稿头被要求**拟合 target 的顶层特征**。论文观察到：把训练数据加大，EAGLE 的收益**很快饱和**。原因不是数据不够，而是「必须拟合顶层特征」这个约束把草稿的表达能力锁死了——顶层特征只对应“下一个 token 的 logits”，用它预测“下下个 token”信息不足。

### 4.2 两个改动

| 改动 | 内容 | 解决什么 |
| :-- | :-- | :-- |
| **Training-Time Test（TTT）** | 训练时就模拟推理的多步草稿：把上一步的**预测 token 与预测特征**当作下一步输入，而不是只用 ground-truth | 训练/推理分布错位（exposure bias）；让加数据真的涨点 |
| **多层特征融合** | 取 target 的 **低 / 中 / 高** 三层特征，各 k 维拼接成 3k，再经 FC 压回 k 维 | 摆脱“只能用顶层特征”的信息瓶颈 |

- 去掉特征回归损失后，草稿的输入不再被约束为 target 顶层特征；EAGLE-3 直接预测 token。
- 论文与 HASS 的明确切割（§2）：HASS 仍保留特征预测损失、输入仍须顶层特征，只是在损失与上下文对齐上做修补；EAGLE-3 是**移除约束**，因此能吃到数据 scaling 的红利。
- 训练数据约为 EAGLE 的 **8×**。

### 4.3 结果（五任务，chat + reasoning 模型）

| 条件 | 结果 |
| :-- | :-- |
| 全任务 | **3.0–6.5×**，比 EAGLE-2 再快 **20–40%** |
| HumanEval（代码，模板多） | 最高 **6.5×**，τ 最高 **7.5** |
| batch=1、单 H100、LLaMA3.1-8B | 相对 EAGLE-2 延迟 **1.4×** |
| **SGLang、batch=64、H100、LLaMA3.1-8B、MT-Bench、链长 3、不用树** | 吞吐 **1.38×**（正文亦写“38% 提升”） |
| 同一 SGLang 设置、batch=24 | **EAGLE 已开始掉吞吐**，EAGLE-3 仍为正收益 |

> **口径提醒**：6.5× 是**摘要上限**（chat+reasoning 五任务里最好的那个点），3.0× 是同一批实验的下沿；4.79× 是另一篇材料里 LLaMA-3.3-70B 的特定设定值，**不是 EAGLE-3 的通用指标**。三者不可混用。

### 4.4 batch 曲线：同一算法在 2→64 上不是一条直线

SGLang 团队在 **1×H100、LLaMA-3.1-8B、MT-Bench、链长 3、不用树**下扫描 batch（表 3，基线 = 无投机 1.00×）：

| batch | 2 | 4 | 8 | 16 | **24** | 32 | 48 | 56 | **64** |
| :-- | --: | --: | --: | --: | --: | --: | --: | --: | --: |
| EAGLE | 1.40× | 1.38× | 1.23× | 1.02× | **0.93×** | 0.94× | 0.88× | 0.99× | 0.99× |
| **EAGLE-3** | 1.81× | 1.82× | 1.62× | 1.48× | **1.39×** | 1.32× | 1.38× | 1.34× | **1.38×** |

- **EAGLE 在 batch=24 就跌破 1.0×**（0.93×），此后一直在 0.88–0.99× 徘徊——这是“高并发下投机解码不划算”的直接生产证据。
- EAGLE-3 把曲线整体抬到 1.3–1.8×，但**形状仍是递减**：2→4 最高（1.81–1.82×），16 之后稳定在 1.3–1.4×。
- 同一设置下 batch=1 的吞吐（表 4）：SGLang 无投机 **158.34 tokens/s** → EAGLE-2 **244.10** → EAGLE-3 **373.25**（约 **2.36×** 于无投机）。注意这是**吞吐**，不是单请求延迟。

> 这张表是 [topics/systems-throughput-latency.md](../topics/systems-throughput-latency.md) 的核心证据：**“投机解码是否划算”由 batch 决定，且拐点随算法版本移动**（EAGLE 24、EAGLE-3 更高）。

## 5. 训练成本：为什么它能“单卡可训”

EAGLE-1 的工程数字（§4.3.3、附录）：

| 项 | 值 |
| :-- | :-- |
| 训练数据 | ShareGPT **68,000** 段对话（固定数据，不用 target 现场生成） |
| 超参 | lr **3e-5**、AdamW `(β1, β2) = (0.9, 0.95)`、梯度裁剪 **0.5** |
| 可训练参数（7B/13B/33B/70B target） | **0.24B / 0.37B / 0.56B / 0.99B** |
| Mixtral 8x7B 的可训练参数 | **0.28B** |
| 训练时长（70B） | **1–2 天 / 4×A100 40G**；7B–33B 可在单台 RTX 3090 节点 1–2 天完成 |
| 数据敏感性 | 用 target 现场生成答案只带来**边际提升**（表 6）——这是“固定数据集”策略的依据 |

> 这组数字解释了 EAGLE 与“独立 draft 模型”路线的成本差：后者要预训练一个完整小模型（SpecInfer 报告 **275 A100 GPU-hours**），EAGLE 只训一个 **<1B** 的草稿头。

## 6. 消融：每个设计值多少（逐篇拆）

| 论文 | 变量 | 对照 | 结论 |
| :-- | :-- | :-- | :-- |
| EAGLE-1 | 草稿粒度 | token 级 vs 特征级 | **1.5× → 1.9×**（MT-bench、Vicuna 7B、T=0） |
| EAGLE-1 | shifted token | 只用特征 vs 特征+超前 token | **1.9× → 2.8×**（同条件） |
| EAGLE-1 | 树验证 | 链 vs 树 | τ **+0.6–0.8**、加速 **+0.3–0.5×**；不用树仍有 **2.3–2.7×** |
| EAGLE-2 | value vs confidence | w/o value vs 完整 | **3.21× → 3.62×**（MT-bench、Vicuna 7B、T=0） |
| EAGLE-2 | rerank | w/o reranking vs 完整 | **3.48× → 3.62×**（同条件） |
| EAGLE-2 | 两者都不要 | w/o both | **2.81×**，τ 3.92（同条件） |
| EAGLE-3 | TTT | 无 TTT 的 EAGLE 式训练 | 接受率随草稿链变长**不塌**（图 7）；有 TTT 才能吃 8× 数据 |
| EAGLE-3 | 多层特征 | 仅顶层 vs 低/中/高融合 | 论文以消融支撑“信息更丰富→接受率更高”（§2） |

**消融读法**：EAGLE-2 的增益几乎全来自「按 value 选节点 + 全局重排」这两步；EAGLE-3 的增益来自「训练目标不再拟合特征」，因此**数据越多收益越大**——这是它区别于 EAGLE-2 的机制级差异，不是调参。

## 7. 与同类的可判定差异

| 维度 | EAGLE-1 | EAGLE-2 | EAGLE-3 | Medusa | Lookahead |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 草稿来源 | target 倒数第二层特征 | 同 EAGLE-1 | **多层特征 + 直接 token** | target 最后隐藏态 + K 个并行头 | 无草稿模型（Jacobi + n-gram 池） |
| 是否训练 | 需训练草稿头 | 同 | 需训练（数据 8×） | 需微调头（backbone 可冻结） | **免训练** |
| 树 | 静态树 | **动态树（value 选点）** | 沿用动态树 | 笛卡尔积/优化树 | 无树，验证 disjoint n-gram |
| 接受率（同条件参考） | ~0.8（论文自述） | 更高 | 最高 | ~0.6 | 更低 |
| 典型加速（带条件） | 70B 2.7–3.5× | 3.05–4.26×（T=0） | 3.0–6.5×（五任务） | 2.3–2.8×（Vicuna 7/13B，T=0） | 1.8×（MT-Bench） |
| 主要成本 | 训练 + 树验证 | 同 + 建树 | 训练数据 8× | 头训练 + 树验证 | 无训练，但命中率受限 |

**可判定差异一句话**：EAGLE 系与 Medusa 都是「自投机 + 树验证」，但 EAGLE 的草稿是**自回归特征**（有前缀依赖），Medusa 的头是**并行独立预测**（无前缀依赖）；这决定了 EAGLE 的树更深、接受率更高，而 Medusa 的训练与部署更简单。

## 8. 在本条目中的位置

- **谱系轴**：EAGLE 是「草稿训练（draft-training）」这一族的核心，且横跨「静态树 → 动态树 → 去约束」三代；它同时是「自投机」与「特征级」两个标签的交点。
- **对系统层的意义**：EAGLE-3 是 vLLM / SGLang 的默认 speculator 之一；SGLang 的 batch=64 吞吐实验（1.38×）是「投机解码在高并发下是否仍划算」的第一个生产级证据（见 [papers/vllm-implementation.md](vllm-implementation.md)、[papers/sglang-implementation.md](sglang-implementation.md)）。
- **对验证层的意义**：EAGLE-2/3 的动态树是 [topics/verification-acceptance.md](../topics/verification-acceptance.md) 里“T>0 塌缩”问题的**被限定对象**；RheoSampling（[papers/2609.21827-rheosampling.md](2609.21827-rheosampling.md)）正是以 EAGLE-3 为基线修这个问题。

---

## 9. 失效边界（独立段）

1. **T>0 下的动态树塌缩**：EAGLE-2/3 的树按 draft 概率 `q` 排序；T>0 时接受判据变成 `min(1, p/q)`，`q` 的大小不再是接受率的可靠指标，树会塌缩成近似 one-hot，接受率显著下降。**这是机制性的，不是实现 bug**；直接“改成采样”还会破坏无损性（详见 [papers/2609.21827-rheosampling.md](2609.21827-rheosampling.md)）。
2. **高 batch 下验证成本反超**：SGLang 实测 EAGLE 在 batch=24 就开始掉吞吐；EAGLE-3 到 batch=64 仍为 1.38×，但再往上没有公开证据。CAST 的二手数据甚至给出 EAGLE-2 在 batch=8、CNN/DM 上 **0.84×**（比自回归还慢）。
3. **换 target 必须重训**：草稿头绑定 target 的隐藏维、层结构与 tokenizer；EAGLE-3 虽放开特征约束，但仍需为每个 target 训一个 draft（SpecForge 只是把训练工程化，不是免训练）。
4. **训练成本与数据依赖**：EAGLE-3 用了约 8× 的数据；小团队复现时若数据不足，EAGLE-3 相对 EAGLE-2 的优势会缩小。
5. **树参数不可跨模型移植**：7B 的 60/6 与 70B 的 48/6 不同；RheoSampling 又用 60/8。用错参数，τ 与加速比都不可比。
6. **greedy 结论不可外推**：论文主表多为 T=0；T>0 的接受率、加速比需要重新标定（见 §4.3 与 topic 2）。
7. **特征级草稿的误差累积**：EAGLE-1/2 的链式特征预测会累积误差；论文用噪声增强缓解，EAGLE-3 用 TTT 从训练侧修，但没有根治“草稿链越深越不可靠”。

---

## 10. 引用注意（何时不该引它）

- 不要说「EAGLE 不需要训练」——它**需要**训练草稿头；免训练的是 Lookahead / REST / PLD 那一族。
- 不要把 EAGLE-2 的 3.05–4.26× 与 EAGLE-3 的 6.5× 放在同一张“加速比排行榜”里——前者是 T=0、MT-bench、三系列模型的区间，后者是五任务、chat+reasoning 的上限。
- 不要把 SGLang 的 **1.38× 吞吐**（batch=64）当成“延迟加速比”；两者量纲不同。
- 不要引用「EAGLE-3 在所有采样温度下都优于 EAGLE-2」——T>0 下动态树的塌缩问题对 EAGLE-3 同样存在。
