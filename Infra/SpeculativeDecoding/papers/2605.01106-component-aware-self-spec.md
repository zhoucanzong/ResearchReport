# Component-Aware Self-Speculation：混合架构能否把内部子网络当草稿器？

> 原文：Borobia, Seguí-Mas, and Tormo-Carbó, [*Component-Aware Self-Speculative Decoding in Hybrid Language Models*](https://arxiv.org/abs/2605.01106v1), arXiv v1, 2026-05-01。本文按 v1 阅读，重点看 §§2–5、Tables 2–8 与 §7。文章主要报告 acceptance 与 FLOP/理论速度估算；没有把结果写成完整的生产部署基准。

## 问题：内部 draft 不必总是“前几层”

传统 self-speculation 往往把 Transformer 看成一串同质层：提前退出、跳过部分层或加一个预测头，从 target 本身构造轻量 drafter。新一代 hybrid language models 则在一个 block 内混合 softmax attention 与状态空间/线性注意力。问题变成：**如果模型已经有一条不同的内部计算路径，它能否直接担当 draft，而不另训或存一个模型？**

论文称这种方法 component-aware self-speculation：从 hybrid target 中去掉 attention 分支，仅保留 SSM 或 linear-attention 子图生成 proposal，完整模型负责 verification。它利用模型本来已有的架构异质性，而不是增加一个完整 drafter checkpoint。[§1、§3](https://arxiv.org/html/2605.01106v1)

## 关键机制：提取子图作为 q，target 仍按标准拒绝采样

设完整 hybrid model 的输出分布为 \(p_H\)，移除 attention 组件后的子图为 \(q_S\)。子图对每步产生候选，并保留真实的草稿概率；target 用标准接受概率 \(\min(1,p_H/q_S)\)，在拒绝时从相应残差分布重采。只要这一步正确使用实际的 \(q_S\)，输出仍严格服从完整 target 的分布。论文给出的正确性来自标准拒绝采样，不是“内部模块天然与 target 等价”。[§3.2–3.3](https://arxiv.org/html/2605.01106v1#S3)

“zero-cost”要谨慎理解：它指**不增加独立模型权重**，不代表草稿计算为零。论文估算 Falcon-H1-0.5B 的 SSM-only 路径仍用完整模型约 **78.4% FLOPs**；Qwen3.5-0.8B 的 linear-only 路径约 **77.3%**。在前者，draft 路径保留了每层并行的完整 SSM 分支；在后者，移除 interleaved attention layers 会破坏模型原先的串行信息流。因而“混合模型有 SSM/linear attention”不足以保证内部草稿有效，**组件在 block 中如何组合**才是关键条件。[§3.4、§5.1、Table 2](https://arxiv.org/html/2605.01106v1)

## 为什么 parallel 与 sequential hybrid 结果差很大

论文比较三类小模型：Falcon-H1 的平行 Mamba-2 + attention block、Qwen3.5 的顺序交错 linear/attention layers、以及 Qwen2.5 纯 Transformer 控制。Table 3 报告 greedy decoding、不同 draft length 下的 all-token acceptance rate。以两 token draft 为例，Falcon-H1-0.5B 的序列全接受率为 **0.680**，Qwen3.5-0.8B 为 **0.038**；后者不是“少了几个百分点”，而是几乎无法利用仅有 linear 路径做候选。数字是论文在其模型/提示与采样条件下的作者报告，不等于端到端加速比。[§5.2、Table 3、Figure 1](https://arxiv.org/html/2605.01106v1#S5)

同一论文还显示，architecture pairing 会改变“哪一条自投机方法可用”：Qwen3.5-0.8B 上 component-aware linear-only draft 的 \(k=4\) 全接受率仅 0.019；通用 LayerSkip（跳过 33% 层）为 0.233；从前半模型提前退出则为 0。作者的解释是，Qwen3.5 的 linear layers 依赖其前后 attention layers 提供的全局上下文；按层跳过一部分仍保留交替结构，完全移除 attention 类则切断依赖。[§5.6、Table 8](https://arxiv.org/html/2605.01106v1#S5)

这组结果不是完整的系统实测 speedup 曲线。论文把接受率与各子图的 FLOP 估计结合，讨论 theoretical speedup；具体 runtime、内核、缓存和实际并发条件没有像 vLLM/SGLang benchmark 那样展开。长上下文时 SSM 的固定状态可能避免线性增长的 KV 访问，但这仍需以具体系统实测确认。[§3.4、§5.5](https://arxiv.org/html/2605.01106v1)

## 和 LayerSkip、VSD、Bole 的关系

| 方法 | Drafter 从哪来 / 改什么 | 这篇论文的相对位置 |
|---|---|---|
| LayerSkip | 通过训练时 layer dropout 和 early-exit loss，使 target 前段层成为草稿模型 | Component-Aware 不必按深度截断；直接抽取架构中的一种模块路径。论文在 Qwen3.5 上把两者作了对照 |
| VSD | 同一架构上改变 drafter 的训练目标，直接偏好 target 可接受的路径 | Component-Aware 改 drafter 的来源而非 loss。未来可以组合，但本论文没有测“组件草稿 + VSD 训练” |
| Bole | 在 hybrid 模型树验证端改线性注意力状态的树结构递推与 GPU kernel | Component-Aware 的重点是 draft 子图是否与完整 target 对齐；Bole 关注 target 如何并行验证多个树分支并延迟物化状态 |

两者组成一条有条件的路线：component-aware proposal 若能形成足够好的 \(q\)，仍需 tree-aware verification 在混合状态模型上高效而正确地处理分支；一个是候选生成侧，一个是验证侧，不可互相替代。

## 适用边界与开放问题

- 研究覆盖 Falcon-H1 与 Qwen3.5 两种 hybrid composition，再以 Qwen2.5 作为 Transformer 控制；不能据此推广到所有 Mamba、线性注意力或 MoE 模型。
- 大多数核心比较是 greedy/T=0；temperature sampling 下论文也给出结果，但同样应按具体 draft length、模型与测试条件阅读。高 all-token acceptance 不等于相同 wall-clock 加速。
- 额外权重为零不代表零额外计算；Falcon draft 子图仍承担相当比例的 full-model FLOPs。模型层间并行方式、状态传递与 GPU kernel 决定实际收益。
- 论文的 ablation→speculation viability 相关性值得用作候选筛查，但不等于 perplexity 单项可以普遍预测实际 acceptance。
- 真正的设计问题是：哪些 hybrid component 子图既足够便宜，又保留 target 最依赖的上下文？组件级 drafter 能否和 VSD/AAT 这类接受目标训练组合？在长上下文线上负载中，状态验证开销是否比草稿开销更主要？
