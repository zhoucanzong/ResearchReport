# HCSpec：草稿越往后，是否应该越轻？

来源：Zhang et al., [*HCSpec: Two-Tier Horizontal Cascade Speculative Decoding for High-Efficiency Large Language Model Inference*](https://aclanthology.org/2026.acl-long.353/)，ACL 2026 Long Papers，正式会议版。重点阅读 §3.1–§3.3、§4.1–§4.2 与 Limitations。

## 它改变的是草稿模型的“位置分工”

EAGLE 一类自蒸馏草稿器会连续提出多个位置的候选。直觉上，越靠后的 token 越难被接受；HCSpec 指出，仅看每个位置的接受概率下降还不够，因为一个位置的候选要继续通过后续所有位置，较早位置的失误会截断整条可提交前缀。论文因此分析 **expected future acceptance length**：从位置 $i$ 开始，未来连续通过的草稿长度期望。它比单点置信度更直接反映“再给这个位置多少计算，最终还可能换来多少已接受 token”。作者在 EAGLE-3、GSM8K 的 Qwen2.5-7B 与 Llama3.1-8B 设置中观察到，这个量会随草稿位置下降得比单步接受概率更快；这是设计动机和实验观察，不是对所有模型、负载都成立的理论定律。[§3.1、Figure 2](https://aclanthology.org/2026.acl-long.353.pdf)

HCSpec 将草稿过程分成两段：

1. **早期 tier（MH）**：双层 Transformer。一个输出通路预测当前 token logits，另一个传播供下一位置使用的辅助特征；把“当前预测”和“下游状态”分开，避免它们争用同一表示。
2. **后期 tier（ML）**：单层 Transformer，以更低计算量继续自回归草拟。它从 MH 交接的辅助状态起步，随后递归使用自己的输出。

所以“horizontal cascade”不是两个独立模型轮流接受目标模型验证，而是同一个草拟阶段中按位置切换能力等级：先把较贵的计算用在会影响长前缀的早期位置，后段再用轻量模块降低草拟开销。$L$ 较短（论文举例 $L<5$）时，MH 只跑首个草稿位置，之后交给 ML；默认半程切换只是配置策略，不是固定的数学最优点。[§3.2、Figure 3](https://aclanthology.org/2026.acl-long.353.pdf)

## 训练如何教会两个 tier 交接

论文采用三阶段蒸馏，冻结 target：先以 teacher forcing 训练特征提取器和 MH 的 logits；再让 MH 使用自己上一步生成的辅助特征，做多步训练时模拟测试；最后固定前两者，接在 MH 后训练 ML，使它学习实际交接后的状态分布。第三阶段冻结 MH 的理由很直接：早期位置的预测质量影响整段接受长度，不希望为了轻量尾段的局部收益而损伤前段模块。[§3.3](https://aclanthology.org/2026.acl-long.353.pdf)

这条路线与 [D-PACE](2605.18810-dpace.md) / [D-PAL](2610.28355-dpal.md) 关注的训练目标不同：后两者在固定块式 drafter 中重分配位置损失权重；HCSpec 直接改变不同位置运行的模块容量和状态传播方式。两类方法都从“位置边际价值不均匀”出发，但一个调整优化信号，一个调整推理时的计算结构。

## 论文结果应放回其配置中

作者报告了 Qwen2.5-7B、Llama3.1-8B、Qwen3-8B 和 Qwen3-14B 的实验。比较采用同一 drafting length，三种主要配置为 batch 1 / $T=0$、batch 32 / $T=0$、batch 1 / $T=1$；7B/8B 在 RTX 4090 上，14B 在 A100 上，推理框架是 SGLang v0.5.3.post1。HCSpec 在这些配置中相对 EAGLE-3 提高论文所报端到端 speedup；摘要给出的范围是 15–30%，相对普通自回归最高为 3.72×。[§4.1、Table 1、Figure 1](https://aclanthology.org/2026.acl-long.353.pdf)

读这个结果时，关键不是把百分比当成模型家族常数，而是看它随 batch、温度和候选长度变化：batch 32 时每请求可验证 token 数下降，较贵草稿位置的预算更紧；$T=1$ 时采样增加不确定性，draft 开销与候选对齐也会变化。论文自己的限制段承认，切换位置和后段模型缩减程度主要按经验设定，位置效用证据总体仍是定量观察形成的设计直觉，而非最优性证明或穷尽的硬件搜索。[§4.1、Limitations](https://aclanthology.org/2026.acl-long.353.pdf)

## 与验证类工作分开看

HCSpec 使用 EAGLE-2 的树验证策略，主要贡献是 **draft-side 的结构与位置分工**；它没有提出新的树概率回补证明。它与 [HSD](2601.05724-hsd.md) 的严格序列分布证明、[When Is a Draft Accepted?](2606.30265-when-is-draft-accepted.md) 的局部 KL 接受证书、[ValuSpec](2610.31338-valuspec.md) 的验证前候选筛选，分别处理架构、接受正确性/条件与候选估值，不是互相替代的 verifier。

**阅读边界**：本文的加速数字是作者在所列模型、硬件、SGLang 版本、draft 长度和温度下报告的结果；这里没有独立运行补充材料代码。HCSpec 的层级切换是否在其它 drafter、硬件、负载或与其他验证策略组合时保持收益，需另有对照证据。
