# Approximate Speculative Decoding：给 greedy 验证一个可累计的偏离预算

> 原文：Feng et al., [*Approximate Speculative Decoding*](https://arxiv.org/abs/2608.03447v3)，arXiv v3，2026-08-30。重点阅读 §§2–4，尤其 Algorithm 1、Tables 1–3、Figures 1–7。论文研究 **greedy 解码**的有损验证，不保持 target 输出分布；所有数字均为作者报告。

## 它想挽回 strict greedy verification 丢掉的什么？

Target 在一次 teacher-forced 前向中可以为整段草稿 $x_{1:K}$ 计算每个位置的 logits。标准 greedy verifier 从左到右比较草稿 token 与 target argmax；遇到第一个不同就截断后缀，并补上 target 在该 prefix 下的 greedy token。被截断的后续 token 并非都没有价值：有些 token 在把前面的一个 mismatch 当作已提交历史后，**恰好已经是该新历史下的 target argmax**，无需再计算一次 target 才能知道它可以继续使用。

ASD 问的是：**是否能让极少数“代价很小”的 mismatch 通过，同时把已经 target-scored、且在新历史下仍然 greedy 的连续后缀复用？** 它只改 verifier，不重训 drafter、不增加 target forward；交换条件是输出轨迹不再严格等于原始 target greedy 路径。[§2, Figs. 1–3]

## 一次 target 前向里如何记账

给定 target logits $z_i$，target greedy token $y_i^*=\arg\max_v z_i(v)$，draft token 为 $x_i$。若二者不同，论文定义局部 logit regret：

\[
r_i=z_i(y_i^*)-z_i(x_i)\ge 0.
\]

softmax 的归一化项会抵消，所以 $r_i$ 等于该位置 target 对 argmax 相对 draft token 的条件 log-probability gap。它是**token 级打分差**，不是该 token 导致下游答案错误的概率，也不是整条序列的 KL/TV 距离。

每次 draft block 使用三层控制：

1. **局部门槛 $g$**：只允许满足 $r_i/(K-i+1)\le g$ 的 mismatch。分母是当前剩余 proposal 长度，作为该位置可能解锁后续 target-greedy 后缀的机会 proxy；作者没有声称它是最优风险函数。
2. **块内异常数上限 $M$**：一个 draft block 中可接受的 mismatch 数不超过 $M$，防止预算全花在同一块。
3. **请求级 regret 预算 $B$**：跨多个 decoding rounds 维护已用额度 $s$。候选前缀累计 regret 不得超过 $B-s$，之后再更新 ledger。

最终只提交**最长可行连续前缀**。不能跳过一个违规位置再接受后面的 token，因为后续 target logits 是在包含全部先前 draft token 的 teacher-forced 历史上算出的；若提交路径中间有洞，缓存和 logits 对应的 history 就不一致。提交的 prefix 后若还有输出，使用已经计算的 target recovery row；草稿/target cache 只沿实际提交序列推进，其他分支状态丢弃。[§3, Algorithm 1, Eqs. 1–14]

有一个关键的实现直觉：如果 mismatch $x_i\ne y_i^*$ 被允许提交，而后续 $x_{i+1},x_{i+2},\dots$ 正好等于在包含 $x_i$ 的已实现 history 下各自的 target argmax，那么这段 suffix 已被当前 target forward 评分，可以随同 prefix 一起提交。ASD 的收益来源是复用这段 target-greedy suffix，而不是让 target forward 少算 draft block。

## 这是显式有损控制，不是另一种无损证明

- 当请求预算 (B=0) 时，ASD 退化回 strict greedy verification。
- 当预算为正时，它可能提交非 target-argmax token，输出会偏离 target 原始 greedy 轨迹；这正是近似机制的定义，不应叫“lossless”或“分布等价”。
- Request ledger 累加的是局部 logit gap；它**不是**全序列 log-likelihood-ratio、KL、TV 或语义风险的上界。满足额度不证明回答仍正确、安全，或人类偏好不变。
- 论文只研究 greedy decoding。不能直接将该规则套到 (T>0) 采样并声称保持采样分布。
- Hash divergence 可以显示路径变了；benchmark accuracy / 任务得分只能描述选定任务结果，不能证明单条轨迹语义等价。

这个定位与 [Traversal Verification](2505.12398-traversal-verification.md) 形成清楚对照：Traversal 改树上如何遍历和如何精确回补，目标仍是严格分布保持；ASD 放宽 greedy 接受判据，显式用可累计的 regret 与块预算控制行为偏离。[§2, §3.2]

## 作者报告的证据与适用条件

| 实验 | 作者报告 | 应保留的边界 |
|---|---|---|
| 主 fixed-work 结果 | Qwen3-14B + DSpark-14B，配置 (B=8, g=0.25, M=2)：七个任务相对匹配的 strict speculative decoding，吞吐平均增加 7.78%，每个任务均为正 | 论文在 NVIDIA L20、vLLM 0.11.0 下测；fixed-work 设置对齐 token 数。是作者报告的 workload-specific TPS，不代表任意线上流量。[§Experiments, Table 1] |
| 跨 drafter 结果 | DSpark、EAGLE-3、Medusa 的十个 target/task cell 报告 3.05%–15.26% 增益；cross-family 平均 7.52% | 同一 paper 的 matched fixed-work 与 natural-EOS protocol 分开读；模型、任务和 decode harness 仍受限于论文选取。[§Experiments, Table 2] |
| 自然停止的行为审计 | 任务准确率变化因数据集而异；GSM8K、MATH-500 上超过 95% 的输出 hash 不同，即使测得的任务准确率没有同步下降 | hash 表示 token 路径改变，不等同语义质量；任务分数相近也不证明逐例答案相同。作者据此强调需独立做自然 EOS 的质量审计。[§Experiments, Tables 1–2] |
| 大 target 的接受率 | DeepSeek-V4-Flash（284B）+ DSpark 的兼容性设置下，作者报告 GSM8K/MATH-500 上 verifier-side acceptance 提升约 10%–16% | H20 上以 FP4/FP8 混合兼容路径运行；这是接受指标，不应当作端到端吞吐或准确率提升。[§Experiments, Fig. 7] |

预算控制也会改变 throughput/accuracy 前沿。论文在 disjoint 数据上选参数，再以自然 EOS 评测；门槛更宽可接受更多低 regret mismatch，但若不同 target、drafter 或 workload 变更，需要重新冻结配置和做质量审计。作者的图 4 是初步 discovery frontier，而不是独立 holdout 结论。[§4, Figs. 4–6]

## 与其他 verifier 侧方法的分工

| verifier 改动 | 允许提交什么 | 保证类型 | 关键代价 |
|---|---|---|---|
| Strict greedy | 仅 target argmax 的最长连续前缀 | 轨迹与 target greedy 完全一致 | mismatch 后截断所有后续 draft token |
| Traversal Verification | 已评分树中的整条候选序列，按叶到根遍历 | 论文条件下严格保持 target 分布 | 多条树路径遍历与残差更新有额外开销；T=0 无收益 |
| ASD | 带预算的少量非 greedy mismatch + 后续 greedy suffix | **近似 greedy**；regret ledger 不是输出/语义等价证明 | 必须审计质量、选择预算，并维护跨轮请求状态 |

ASD 关注的是“某个 target 已经算出的后缀是否值得在小偏离下复用”；它不替代树拓扑优化，也不等同于按 uncertainty 分配 target verification budget 的方法。将其放进专题时应放在**有损 verifier**分支，与严格无损的树遍历分开讲。[§2.2–2.3, §3]
