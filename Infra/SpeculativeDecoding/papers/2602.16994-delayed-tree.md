# Dynamic Delayed Tree Expansion：把随机分支推迟到更有价值的深度

> **固定版本**：arXiv `2602.16994v1`，2026-02-19；license = **CC BY 4.0**。固定来源：[HTML v1](https://arxiv.org/html/2602.16994v1)、[PDF v1](https://arxiv.org/pdf/2602.16994v1)。下载 PDF SHA-256：`5922aa4589162969ab417f2ff86522de450aefafa3cc9305f869f7783aa60cf5`。
>
> **一句话定位**：与其让多个 i.i.d. draft rollout 从根部就分叉，Delayed Tree Expansion 先沿一条 draft 路径前进 `L₁` 步，再在选定节点分成 `K` 条、每条长 `L₂` 的 rollout；在线 selector 根据当前上下文和模型/硬件延迟选择何时、分多宽、分多深。
>
> **亮点与差异四行**
> - **观察**：在匹配的 i.i.d. 树设置下，Traversal Verification 是强基线；OT verifier 的 token 接受率随深度下降，而根部过早分支把树预算花在 draft/target 分布较接近的位置。
> - **方法**：先采样 trunk，再触发 i.i.d. branching；NDE selector 每次解码选择 `(K,L₁,L₂)`。这改变树拓扑，对兼容的 OT-based verifier 保持 target 分布。
> - **Table 6–7**：跨三模型、五数据集与八种采样设置平均，SpecInfer NDE 为 5.03 block efficiency、16.69 tokens/s，对 Traversal 的 5.31、15.89；吞吐平均约 +5.0%，但 Qwen/Gemma/Llama 单模型差异明显。
> - **训练与证据边界**：selector 用每数据集 350 prompts 的离线数据训练，并从每 16 tokens 的固定间隔取 root；需先生成树/target-draft 特征并测量延迟。论文称线上 MLP forward 开销可忽略，但未报告完整离线数据生成与训练墙钟成本；此处不作独立复现。

## 1. 从 verifier 对比到延迟分支

### 1.1 配平比较的发现（§3–§4）

论文将单路径方法（Naive speculative sampling、Block Verification）与多路径方法（NSS、NaiveTree、SpecTr、SpecInfer、Khisti、Traversal）放在匹配的 i.i.d. draft 条件下比较。在线评估覆盖五个数据集、每个数据集 50 prompts、八种采样设置；target/draft 分别为 Qwen2.5 32B/0.5B、Gemma-3 27B/270M、Llama-3 70B/8B。模型运行在 2×A100-80GB，Intel Xeon Gold 6342 CPU。

Table 2 的平均 block efficiency 中 Traversal 为 5.31，高于所有既有方法；Table 3 的平均吞吐为 15.89 tokens/s，也高于其它列出的基线。但模型分项并非一个固定排名：例如 Gemma 吞吐下 Traversal 11.56，Block Verification 10.57；Qwen 的 SpecInfer 19.58 接近 Traversal 21.35。作者进一步发现 OT-based 方法在树深处接受率下降，target-draft 分布差异随深度增大，因此认为把分支预算提前用在根部不够有效。

### 1.2 Delayed tree 与 selector（§5–§6）

给定上下文 `c`，先从 draft `q` 采样长度 `L₁` 的单一路径 `a₁:L₁`，再在该节点采样 `K` 条独立、各长 `L₂` 的后续路径。OTLP verifier 仍可在此树上使用，并保持 target 输出分布。`L₁=0` 是根部即分支；较大的 `L₁` 将分支延后。`K` 控制支路数、`L₂` 控制支路深度，三者共同影响接受长度、draft 前向次数和 target pass 成本。

Neural Delay-and-Branch (NDE) selector 用 root 可得信息（target/draft hidden states、熵和 KL 等不确定度、采样参数、上下文长度、draft/target forward 延迟）预测动作 `(K,L₁,L₂)`。每数据集以 350 prompts 产生离线训练数据，root 每 16 tokens 取样；对每个 root/action 估算 block efficiency，并以 microbenchmark latency 估算吞吐，训练小型 MLP 预测最优动作。训练动作集合为 `K∈{1,2,3,4}`、`L₁,L₂∈{0,…,8}`。论文报告 selector 每步 forward 开销相对模型 pass 可忽略；但完整训练数据生成、离线树样本数和总训练时间没有形成可复核的成本数字。

SpecInfer NDE 的平均吞吐比 Traversal 高 0.80 tokens/s（约 +5.0%），但平均 block efficiency 较低（5.03 vs 5.31）。三个模型的吞吐方向为 Qwen +5.6%、Gemma +14.7%、Llama −3.4%；因此论文摘要中的平均提升不是每模型稳定提升。Khisti NDE 的 Llama block efficiency 6.84 高于 Traversal 6.78，但吞吐低于 Traversal（13.24 vs 14.77），也说明接受长度不能替代实际吞吐。
