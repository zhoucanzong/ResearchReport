# Medusa：并行解码头与树注意验证（Cai et al., ICML 2024）

> **一手来源**：arXiv:2401.10774 **v3**（2024-06-14），正文 HTML 逐节读取；license = **CC BY 4.0**。｜ **主等级**：`[精读原文]`
> **一句话定位**：不训独立 draft 模型，而是在 target 最后隐藏态上挂 **K 个并行预测头**，用**树注意**一次验证多条候选续写——把「投机解码的草稿」变成 target 自己的轻量附件。
> **亮点与差异四行**
> - **一句话亮点**：给冻结的 backbone 加 5 个单层头，就能拿到 **2.2×** 以上加速；再联合微调 backbone（Medusa-2）到 **2.3–2.8×**。
> - **新在哪**：① 用**并行头**（每个头预测 t+k+1）替代串行 draft；② 用**笛卡尔积/搜索出的树**一次验证多分支；③ 提出 **typical acceptance**——用 target 概率阈值替代严格拒绝采样，在“不完全保分布”的前提下换更高接受率。
> - **证据强度**：中上。Vicuna-7B/13B/33B、Zephyr-7B 四种 target，batch=1、MT-bench 类对话与 AlpacaEval；有树配置、阈值、两阶段微调的消融；但**typical acceptance 不是无损**，论文自己承认“不坚持输出分布与 target 精确一致”。
> - **值不值得引用**：**值得作为“并行头/自投机”代表引用**；引用加速比时必须说明是 Medusa-1 还是 Medusa-2、是否用 typical acceptance、以及 batch=1 的前提。

## 1. 问题：draft 模型的三重门槛

论文把投机解码的落地障碍拆成三条（§1、§2.1.1）：

1. **获取成本**：要一个与 target 同 tokenizer、分布接近的小模型；SpecInfer 那条路线报告了 **275 NVIDIA A100 GPU-hours** 的预训练成本。
2. **分布漂移**：单独预训练的 draft 与 target 存在 capacity gap，接受率受限。
3. **服务复杂度**：多模型服务要处理显存、调度、分布式切分；对 7B 级本地部署尤其不友好。

Medusa 的取舍很直接：**不加第二个模型，只加 K 个轻量头**。头是 target 最后隐藏态上的单层 FFN，输出词表分布；K 个头分别预测 `t+1 … t+K+1`（原 LM head 负责 `t+1`）。

## 2. 方法：头、树、接受

### 2.1 Medusa 头（§2.1.1）

第 k 个头的定义：

`p_t^(k) = softmax( W2^(k) · ( SiLU(W1^(k) · h_t) + h_t ) )`

| 项 | 设计 | 原因 |
| :-- | :-- | :-- |
| 结构 | 单层 FFN + 残差 + SiLU | 与 Llama 的 LM head 同构，便宜 |
| 初始化 | `W2^(k)` 复制原 LM head，`W1^(k)` 置零 | 训练开始时头的输出 = 原模型输出，不破坏初始质量 |
| 头数 | **K = 5**（经验上足够） | 再多收益递减；树搜索可只保留 3–4 个头 |
| 额外参数 | 每个头 `d×d + d×V` | 对大词表模型是可观显存（见 §7） |

### 2.2 树注意与候选构造（§2.1.2）

- 把多个头的 top 预测组合成一棵树：例如第 1 个头取 **top-2**、第 2 个头取 **top-3**，得到 **2×3 = 6** 条候选路径。
- 用一棵**树形 attention mask**（每个 token 只能看见自己的祖先）在**一次 target 前向**里验证所有候选；位置编码按树深度重排。
- 候选不是随便拼：§2.3.3 给出“在给定头输出下搜索最优树形”的方法，用动态规划/搜索在候选集合里挑一棵期望接受长度最大的树。

### 2.3 两种接受规则（§2.3.1）——这是 Medusa 最重要的分岔

| 规则 | 做法 | 分布保证 |
| :-- | :-- | :-- |
| **拒绝采样** | 经典投机采样：`min(1, p/q)` 接受，拒绝后从残差分布重采样 | 严格等于 target 分布（无损） |
| **Typical acceptance** | 若 `p_target(x) > min(ϵ, δ·exp(−H(p_target)))` 则接受该候选前缀 | **不保证**严格分布等价，只保证“典型/不离谱” |

- `H(·)` 是 target 预测分布的熵；`ϵ` 是硬阈值，`δ` 是熵相关阈值。
- 机制解读：**高熵位置放宽**（多种续写都合理），**低熵位置收紧**（只接受高概率 token）。
- 第一个 token **无条件贪心接受**，保证每步至少产出一个 token；后续 token 用 typical acceptance。
- **T=0 时退化为贪心**（只有 argmax 有非零概率）；T 越高，接受前缀通常越长——这与“拒绝采样在高温下效率下降”正好相反。
- 论文的立场很明确：**不坚持输出分布与 target 精确一致**，用“质量相近”换接受率。这一点必须写进任何引用里。

### 2.4 解码一步的完整流程

把 Medusa 的一步拆开，可以看到它复用了多少 target 的计算：

1. **取隐藏态**：target 对当前序列做一次前向，拿到最后一个位置的 `h_t`（这一步本来就要做）。
2. **头预测**：K 个头 + 原 LM head 各出一次词表分布，取每个头的 top 候选。
3. **建树**：按笛卡尔积或 §2.3.3 的搜索树，把候选拼成树；给每个节点分配树内位置编码。
4. **树注意验证**：把整棵树拼成一个 batch 送进 target，**一次前向**得到每个节点的 target 概率；mask 保证每个 token 只能看见祖先。
5. **接受**：从根开始按拒绝采样或 typical acceptance 判前缀，取**最长被接受前缀**；被接受路径的 KV/隐藏态保留，进入下一轮。

关键点：第 4 步的 target 前向**同时**完成了“验证”和“下一轮的 `h_t` 计算”——候选 token 的隐藏态可以直接复用，不需要额外一次前向。这是 Medusa “不增加模型、只增加候选”的成本结构。

## 3. 训练：Medusa-1 / Medusa-2 / 自蒸馏

| 方案 | backbone | 头 | 适用 | 质量保证 |
| :-- | :-- | :-- | :-- | :-- |
| **Medusa-1** | ❄️ 冻结 | ✅ 只训头 | 资源有限、不想动原模型 | 冻结 backbone ⇒ 无损（若用拒绝采样） |
| **Medusa-2** | ✅ 联合微调 | ✅ 一起训 | 追求更高加速 | 需要特殊训练配方，防止 backbone 能力退化 |
| **自蒸馏** | — | — | 没有训练数据（如私有/RLHF 模型） | 用 target 自己生成训练数据 |

- Medusa-1 只训头，显存开销小，可配合量化（类似 QLoRA 的思路）。
- Medusa-2 的关键不是“联合训练”本身，而是**不让联合训练破坏 next-token 预测能力**；论文用两阶段/特殊配方实现（§2.2.2、§3.3.3）。
- 自蒸馏解决“拿不到 SFT 数据”的场景：让 target 生成问答对，再训头。

## 4. 数据与规模（带条件）

| 维度 | 设置 |
| :-- | :-- |
| target 模型 | Vicuna-7B、Vicuna-13B（公开数据）；Vicuna-33B（私有数据，作者注明实验性）；Zephyr-7B（SFT+alignment） |
| batch | **1**（论文明确聚焦“本地单用户”场景） |
| 评测 | MT-bench 类多轮对话、AlpacaEval；不同 prompt 类型分开报 |
| 训练数据 | Vicuna 用其 SFT 数据；33B / Zephyr 用自蒸馏 |
| 硬件 | 单 GPU 可训头（论文强调 Medusa-1 的低门槛） |

> 这是一个**刻意收窄**的实验设置：batch=1、对话为主。它让 Medusa 的数字很干净，但也意味着**不能直接外推到高并发服务**（见 §7）。

## 5. 结果（带条件）

| 条件 | 方法 | 加速比 | 备注 |
| :-- | :-- | --: | :-- |
| Vicuna-7B、batch=1、T=0 附近 | **Medusa-1** | **~2.2×** | 只训头、冻结 backbone；表 3 的阶段性结果 |
| 同设置 | **Medusa-2** | **~2.8×** | 头 + backbone 联合训练 |
| 多 prompt 类型平均 | Medusa | **2.3–2.8×** | 论文摘要口径；随 prompt 类型波动 |
| 接受率（与 EAGLE 对比的背景值） | Medusa 头 | **~0.6** | EAGLE 论文引用值；EAGLE 自述 ~0.8 |

> **版本差异**：v1 摘要曾写 Medusa-2 可达 **2.3–3.6×**，v3（2024-06-14）改为 **2.3–2.8×**。本条目以 **v3** 为准；引用旧数字时须注明版本。

### 5.1 加速从哪来：论文自带的 roofline 分析（附录 G）

Medusa 不只在“少解码步”上解释收益，还用 roofline 模型把收益拆成两类算子：

| 算子 | 解码阶段瓶颈 | Medusa 的作用 |
| :-- | :-- | :-- |
| attention 矩阵乘 | 内存带宽受限 | 增加候选 token 数 → 提高 operational intensity；论文在 **batch=16、seq=1024、64 候选**下报告 **44× FLOP/s、41× Operational Intensity** |
| 线性层（up/gate/down） | batch 小则内存带宽受限 | 候选 token 让线性层从 memory-bound 转向 compute-bound，提高利用率 |

论文进一步拟合出**接受率与候选数的对数关系**：`acc_rate ≈ 0.477 · log(num_candidate)`（Llama-7B、A100-80GB-PCIe、batch=1、seq=1024）。这条经验式说明：**候选数应按对数收益递增，而不是线性堆**。

## 6. 消融：树、阈值、两阶段

| 变量 | 对照 | 结论 |
| :-- | :-- | :-- |
| 头数 K | 3 / 4 / 5 / 更多 | **5 个足够**；优化树后 3–4 个也可用，多余头可关掉 |
| 树配置 | 笛卡尔积 vs 搜索优化树 | 优化树在同一头输出下接受更长；§2.3.3 给出搜索方法 |
| 接受规则 | 拒绝采样 vs typical acceptance | 高温下 typical acceptance 明显更快，但**不再无损** |
| 阈值 `ϵ / δ` | 多组 | 阈值越松接受越长、质量风险越大（§3.3.2） |
| 训练阶段 | 只训头 vs 两阶段（头→联合） | 两阶段是 Medusa-2 不伤质量的关键（§3.3.3） |
| 候选数 | 按 `0.477·log(num_candidate)` 拟合 | 候选越多接受率涨得越慢；候选数存在最优点（附录 G.3） |
| batch | 模拟 batch=1→64、seq=1024 | **batch>32 后线性层转 compute-bound，加速可能转负**（附录 G.3、图 22） |
| 序列长度 | seq 128→8192 | 长序列下 attention 矩阵乘开销上升，整体收益下降（同图 23） |

## 7. 失效边界（独立段）

1. **Typical acceptance 不是无损**：它只保证“接受的是 target 认为典型的 token”，不保证输出分布等于 target。需要严格分布等价的场景（审计、可复现采样）**不能用**；要用就只能退回拒绝采样，加速比会下降。
2. **高温度下拒绝采样效率差**：论文的动机之一就是“温度越高，独立采样越容易被拒”；typical acceptance 是对这个问题的工程绕行，不是理论修复。
3. **batch=1 的实验设定**：所有主结果都在 batch=1；batch 增大后 target 进入 compute-bound，树验证的额外 token 会与真实 token 争算力，收益下降（对照 EAGLE-3 的 SGLang batch 曲线与 MagicDec 的临界序列长度）。
4. **额外显存**：K 个头各含 `d×V` 的输出矩阵；对 70B/大词表模型，头参数与 KV cache 一起可能成为部署障碍。
5. **头是并行独立预测**：第 k 个头不建模前 k−1 个头的输出，链越长越不准；这正是 Hydra（顺序依赖头）要修的问题。
6. **树搜索/验证开销**：候选越多，树注意的 mask 与验证 token 数越大；高并发下这部分开销会吃掉收益。
7. **Medusa-2 的 backbone 漂移风险**：联合训练若配方不当会伤原模型能力；论文用特殊配方规避，但这是“工程约束”而非“理论保证”。
8. **batch 超过约 32 后可能负收益**：附录 G.3 的 roofline 模拟明确给出“batch>32 时加速下降、甚至为负”，原因是线性层从 memory-bound 转为 compute-bound；这是**模拟结论**，不是端到端实测，但方向与 EAGLE/SGLang 的 batch 曲线一致。
9. **长序列的 attention 开销**：序列从 128 拉到 8192 时，attention 矩阵乘的开销上升，而线性层计算不随序列长变化；因此 Medusa 的收益在长上下文会缩水。

## 8. 与同类系统的可判定差异

| 维度 | Medusa | EAGLE-1/2/3 | Lookahead | 独立 draft（Leviathan/Chen） |
| :-- | :-- | :-- | :-- | :-- |
| 草稿来源 | target 最后隐藏态 + **K 个并行头** | target 特征**自回归** | Jacobi 迭代 + n-gram 池 | 独立小模型 |
| 前缀依赖 | ❌ 头之间独立 | ✅ 有（自回归） | ✅ 轨迹依赖 | ✅ 自回归 |
| 是否训练 | 训头（Medusa-1）/ 联合（Medusa-2） | 训草稿头 | **免训练** | 预训练 draft |
| 树 | 笛卡尔积 / 搜索树 | 静态→动态树 | 无树（disjoint n-gram） | 链（可扩展树） |
| 接受率 | ~0.6 | ~0.8 | 更低（依赖命中） | 取决于 draft 质量 |
| 典型加速 | 2.3–2.8×（batch=1） | 3.0–6.5×（带条件） | 1.8×（MT-Bench） | 2–3×（同族 draft） |
| 无损性 | 拒绝采样时无损；typical acceptance **有损** | 声明无损（greedy 主结果） | 声明无损 | 无损 |

**可判定差异一句话**：Medusa 与 EAGLE 都是“自投机 + 树验证”，但 Medusa 的头**并行独立**、EAGLE 的草稿**自回归**——前者训练/部署简单，后者接受率高；这条差异直接决定了两者在工业界的定位（Medusa 更像“轻量插件”，EAGLE 更像“性能默认项”）。

## 9. 对本条目结论的影响

- **“草稿不必是独立模型”**：Medusa 与 EAGLE 一起证明了自投机路线可行，独立 draft 模型不再是必选项。
- **“无损”不是二值**：Medusa 的 typical acceptance 是本条目 [topics/verification-acceptance.md](../topics/verification-acceptance.md) 里“有界风险/近似”一档的早期代表；它比 ARC-Decode 早两年，但思路同源——用质量约束换接受率。
- **“树验证”成为共同基础设施**：Medusa 的树注意与 SpecInfer 的 token tree 验证同源，后续 EAGLE-2/3 的动态树、Sequoia 的硬件感知树都在这个框架里演化。

---

## 10. 引用注意（何时不该引它）

- 不要把 **Medusa-2 的 2.8×** 当成“无损加速”——它常与 typical acceptance 一起报告，后者不保分布。
- 不要把 Medusa 的 batch=1 数字外推到服务端高并发；论文没有给 batch 扫描。
- 不要说 Medusa “不需要训练”——头需要训练（或用自蒸馏生成数据），只是不需要独立 draft 模型。
- 引用头数时写 **K=5**，不要写成“固定 5 个头不可变”；论文明确说优化树后 3–4 个也可用。
