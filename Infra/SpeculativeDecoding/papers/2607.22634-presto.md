# PRESTO：把 diffusion 边际分数校准到 AR 前缀

**原文**：[arXiv 2607.22634v1](https://arxiv.org/html/2607.22634)，CC BY 4.0。阅读 §§2–6、Appendix A–F、Tables 1–4。未运行作者代码或模型。

## 核心错位

块扩散 draft 一次输出各位置的边际分布 \(q_i(x_i)\)。AR verifier 判断下一位置时却使用已选前缀条件 \(p(x_i\mid x_{<i})\)。若直接把 \(\prod_i q_i(x_i)\) 当成候选路径分数，前缀即使与早先选出的 token 不相容，也会保留相同分数。因而 DDTree 的边际质量树搜索能提高多路径覆盖，却可能把验证预算投向条件上不可信的路径。

PRESTO 给每个位置增加便宜的 prefix-conditioned signal \(\rho_i(x_i\mid x_{<i})\)，使用 \(\log q_i + \lambda_i\log\rho_i\) 对路径打分，再按累计分数做 beam 或 best-first 扩树。论文把 \(\rho\) 实例化为 3-gram 模型，作为校准信号而非替代目标；它的作用是更接近 target 验证真正使用的前缀条件。

同一构造既适用于独立 diffusion drafter + AR target，也扩展到 dLLM self-speculation：多个 block state 以树组织并交由 AR 验证，接受最长路径后，把仍有效的 mask slots 用于下一轮 draft。被拒绝分支依赖的预测会被丢弃。

## 作者报告的结果与使用边界

论文用 Qwen3 4B/8B/30B + DFlash drafter 和 Nemotron-Labs-Diffusion 8B self-speculation；NVIDIA B200、batch size 1，T=0/1，报告平均接受长度与 token/s 加速。DFlash 树预算从 128、256、512 中择优；自投机树预算固定为 32。报告中 4B/8B DFlash 的平均加速从约 4.8–4.9× 到约 7.3×；在不同任务、温度、模型与 backend 上增益不同。[§5、Table 2–4、Appendix D–E]

prefix signal 是启发式，来自 3-gram，而非 AR target 的精确完整条件概率；算法树评分也不应误读成改变 target 分布的验证准则。它改的是“把节点预算花在哪些候选路径”，target verification 才决定哪些 token 可以提交。树越大，接受机会可能增加，但验证会从并行收益转成计算开销；作者观察到很大的节点预算会使验证成本上升。[§4、§5.1–5.2]

PRESTO 的意义在于把“diffusion 产生并行候选”与“AR 按前缀验收”之间的结构错配写成可操作问题：候选多只是搜索空间，分数要对齐真正的验收条件，预算还要顾及硬件代价。
