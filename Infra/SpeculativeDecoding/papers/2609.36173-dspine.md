# DSpine：在并行草稿的每一层，把前驱预测传给后继位置

来源：Zhang et al., [*Draft in Parallel, Condition Through Depth: Adjacent Causal Injection for Speculative Decoding*](https://arxiv.org/html/2609.36173v1)，固定版本 arXiv v1（2026-09-28，CC BY 4.0）。重点阅读 §3–§5，尤其 §3.1–§3.2、§4.1–§4.5、Figure 2–6、Tables 1–3；拒绝采样与采样温度细节见 Appendix C.2–C.3。

## 问题：并行位置各自合理，接起来却可能不连贯

块式草稿器能一次预测多个未来位置，但通常在 target 验证前就为每个位置作预测。DFlash 这类方法让各位置并行读已确认的 target 上下文，草稿延迟很低；代价是第 2、3 个位置没有看到本轮真正采样出的前驱 token。举例说，某位置可能独立预测“纽约”，后继又独立预测“伦敦”，两者各自都常见，却不是同一条续写路径。Target 只接受连续前缀，前面的不一致会让后面的候选一起失去提交机会。[§2.2、§3](https://arxiv.org/html/2609.36173v1)

DSpine 追问：能不能让后继在并行计算期间，逐层看到前驱当前形成的预测？论文的两个实证观察是：早期 block 位置在浅层已形成较多可读出的预测信息；而相邻前驱的信息不能被更早历史完全替代，且越早注入，后继越能利用它。[§3.1–§3.2、Figure 2](https://arxiv.org/html/2609.36173v1)

## 机制：依赖沿网络深度展开，位置仍在同一层并行更新

DSpine 在每个 Transformer 层后为位置 $t$ 加一条只从相邻前驱 $t-1$ 传来的 gated message：receiver 和 predecessor 特征共同决定 gate，predecessor 特征经投影后写入 successor residual stream。所有位置在该层仍并行更新；block-causal attention 同时限制信息只能从前缀流向后继，不会让本轮后面的候选反向影响前面位置。[§4.2、Figure 3](https://arxiv.org/html/2609.36173v1)

消息需要一种能同时表示“前驱此刻预测什么”和“前驱最终选中了哪个 token”的共同空间。DSpine 从 frozen target LM head 的 output embedding 构造 transfer space：归一化词向量、PCA whitening、保留低维主成分并再归一化。前驱还未选定时，各层把其 hidden state 投影到此空间；前驱 token 被选定后，则直接以该 token 的 embedding 写入同一通路。[§4.1–§4.2](https://arxiv.org/html/2609.36173v1)

这让“预测中的前驱特征”与“已经选定的前驱 token”能走同一种信息通道。训练也在每层把投影后的预测特征向正确 token 的 transfer embedding 作方向性 cosine 对齐，帮助浅层更早形成有用的前驱提示；该损失只约束低维投影方向，没有把整层 hidden state 强制变成 token 分类器。[§4.4–§4.5、Eq. 6–8](https://arxiv.org/html/2609.36173v1)

## 选定前驱后，last-write refinement 与 transition cache 怎样工作

backbone 输出每个位置的 top-$K$ 候选后，DSpine 从左向右选 token。选定位置 $t-1$ 的 token 后，它在 successor $t$ 的缓存 pre-injection state 上重做最后一层写入：把前驱的预测特征替换成已选 token 的 transfer embedding，得到条件于真实前驱的 successor scores。这一步称为 **last-write refinement**。[§4.3、Figure 4](https://arxiv.org/html/2609.36173v1)

若每选好一个 token 才重新计算下一位置的所有候选分数，选择会串行。DSpine 因此预先对相邻候选集合的所有 predecessor–successor pair 计算分数并放入 transition cache；此后仍按前缀顺序选 token，但分数表已并行算好。它用每个边界约 $K^2$ 的打分工作，换较短的逐步依赖链；论文默认 $K=16$，并报告其 transition cache 与融合注入的开销低于所比较的 Domino / DSpark 后置顺序头配置。[§4.3、§5.4](https://arxiv.org/html/2609.36173v1)

## 与 DFlash、DFlash2、DSpark、HCSpec 的区别

| 方法 | 前驱信息在哪里进入后继 | 主要改变 | 要付出的代价 |
|---|---|---|---|
| DFlash | 只用已确认前缀的 target feature；本轮各位置独立预测 | 以块扩散一次并行提议 | 后继无法条件于本轮真实采样前驱，后缀更易失配 |
| DFlash2 | 加局部卷积与低秩 bigram selector | 在 DFlash backbone 中混合相邻位置，并在后面打分候选对 | 位置间条件信息仍主要在 backbone 之后使用 |
| DSpark / Domino | backbone 后追加 Markov / RNN / causal correction head | 先并行产候选，再对前驱条件作轻量修正 | 需要处理后置顺序校正的延迟 |
| **DSpine** | 每层向 successor 注入 predecessor 的预测特征；选定 token 后再做 last-write refinement | 让因果信息在网络深度中传播，同时给最终选择使用真实已选前驱 | 多层 injection 与 transition-cache $K^2$ 边打分；需训练 transfer-space 表征 |
| [HCSpec](2026.acl-long.353-hcspec.md) | 将草稿 block 前段与后段交给不同容量的模块 | 按草稿位置分配模型容量 | 解决位置预算，未直接替代 DSpine 的层内相邻信息流 |

这几条路线都在修补 parallel drafting 的条件依赖，但切入点不同：DSpine 把前驱预测特征送进 backbone 每一层；DSpark/Domino 在 backbone 后补局部依赖；DFlash2 用卷积和 bigram 候选评分；HCSpec 则改变前后位置所用的模型容量。[DSpine §2、§4；DSpark、HCSpec 对照见对应精读](2607.05147-dspark.md)

## 正确性：拒绝采样必须使用实际的条件 proposal

DSpine 的结构与中间监督本身不是“无损证明”。在每个位置，Target 依据该位置真实 proposal distribution $q_{\mathrm{draft},t}$ 作拒绝采样；首次拒绝时按标准残差分布 $[p_t-q_{\mathrm{draft},t}]_+$ 替换，全部通过时由 target 采样 bonus token。论文的 Appendix C.3 明确指出：$T=1$ 时 DSpine 从 transition-cache scores 在每个位置的 top-16 候选上的 softmax 采样，并将这个实际 proposal probability 传给 lossless rejection sampling；DFlash / Domino 的 proposal policy 则不同。正确性来自这套实际概率与 target correction 配对，而不是 DSpine 的 top-$K$ 本身，也不能拿训练时的 unigram logits 代替 last-write 之后的真实 proposal。[Appendix C.2–C.3、Eq. 11](https://arxiv.org/html/2609.36173v1)

## 论文支持到哪里

作者在 Qwen3-4B 与 Qwen3-8B、thinking disabled 条件下评测 GSM8K、MATH-500、HumanEval、MBPP、LiveCodeBench、MT-Bench 和 Arena-Hard；七项接受长度结果在 $T=0$ 与 $T=1$ 报告，serving throughput 则在 $T=0$、并发 2–32、固定验证预算下用 SGLang 测量。方法间训练数据和主要训练配置对齐。[§5.1–§5.3、Table 1、Figure 5](https://arxiv.org/html/2609.36173v1)

论文报告 Qwen3-8B 七基准平均接受长度从 DFlash 的 3.77 增至 4.82（$T=0$）；SGLang serving 下 DSpine 的平均吞吐比最强基线 DFlash2 高 11.1%（Qwen3-8B）、6.5%（Qwen3-4B），覆盖 GSM8K、MATH-500、HumanEval、MBPP 和并发 2–32。它们是作者报告的、固定 target、温度、引擎和候选预算下的结果，并不说明任意 target 或更高并发都会有相同收益。[§5.2–§5.4、Table 1、Figure 5、Table 8](https://arxiv.org/html/2609.36173v1)

消融显示，移除 last-write refinement 会降低接受长度，再移除层内注入会进一步下降；层级 embedding cosine supervision 也优于不监督或对每层直接施加全词表 CE 的变体。这支持组件有互补作用，但论文仍只评测 Qwen3-4B/8B 的特定目标和 serving 配置。[§5.5、Tables 2–3](https://arxiv.org/html/2609.36173v1)

**开放问题**：DSpine 每个相邻边界需对候选对打分，$K$ 增大时 transition-cache 的 $K^2$ 成本如何扩展？面对非相邻依赖、长 block、更高并发或不同 target backbone，层内注入的收益会否覆盖额外状态与打分？论文尚未用同一模型比较 DSpine 与 UBTree 的多路径 tree drafting，二者回答的“条件依赖”问题也不同：DSpine 提高一条并行链的因果一致性；UBTree 用 unigram 候选加 bigram 边评分保留多条可验证路径。
