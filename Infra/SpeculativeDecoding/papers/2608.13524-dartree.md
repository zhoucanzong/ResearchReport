## 1. 它补的是“并行 draft 有分支，但分支不懂自己的前缀”

块扩散 draft 可以一次并行提出整个 token block，降低草稿延迟；代价是每个位置的 proposal 分布是边际预测，不以同一条生成路径上已经选出的 token 为条件。已有做法可先沿单条链做自回归校正，再把边际候选铺成树，但替代分支没有沿各自父路径校正。[§1–§3]

DARTree 先做一次 block-parallel pass，再逐深度并行扩展多条候选路径：每条分支用前缀状态校正该深度候选；保留固定宽度形成较宽 supertree；末尾一次性按累计路径分数取 top-B 节点交给 target 验证。对照逐节点 best-first heap，它把逐个依赖的 correction/head 更新改为“深度间串行、同层批量”，并把 pruning 延后；论文证明在 `β≤0` 且 tie-break 偏向祖先时，全局 top-B 与逐步 best-first 选择等价。[§3，Algorithm 1，Lemma 1]

它是 training-free 的树构造方法，复用 Domino 的 correction head；因此新意集中于**路径校正 + 树构建调度**，不在训练一个新 draft 模型。[§4、§5]

## 2. 结果与条件

默认块长 16、每个位置 top-64 候选、target 验证预算 B=64、pruned 变体 supertree 宽 12、深度惩罚 `β=-0.2`。实验 batch=1，Qwen3-4B/8B，单张 RTX 6000 Ada Generation；温度覆盖 0 和 1，每个 prompt 最多生成 2048 token。表中对比 AR、DFlash、DDTree、Domino。[§5]

摘要给出的上限是每轮最多接受 12.97 tokens、相对同设置 DFlash 多 98.6%、相对本地 AR 最高 9.73×。这三个是不同指标/基准：不要把 9.73×说成平均值。以 Qwen3-4B/T=0、GSM8K 为例，pruned DARTree 为 `τ=12.97`、`9.73×`；7 个任务平均为 `τ=9.81`、`6.99×`。[摘要、Table 1]

在 GSM8K/HumanEval/MT-Bench 的树构造消融中，按分支逐路径校正优于“单链校正后构树”，`τ` 最多提高 16.4%；把 correction 与 heap 逐节点交错相比，DARTree 也降低了建树时间。并发结果则在 SGLang、单张 RTX 6000 Ada、BF16、Qwen3-4B 上运行，吞吐从并发 2 到 32 扫描；固定树预算下并发升高会降速，论文另报告 adaptive B/W 以缓解。[§5.2、Table 4]
