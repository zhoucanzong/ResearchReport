# SpecStream：长上下文下把 KV 等待变成可计算窗口

## 1. 研究问题：target 少跑几步，仍可能更吃显存

长上下文使每轮 target 验证都要读取历史 KV。投机解码减少串行 target 调用，却让验证树/草稿和临时状态占用额外显存。把 KV 放到 CPU 可以提升可并发请求数，但如果每一层 attention 都要等完整历史拷回 GPU，PCIe 等待会重新进入关键路径。[§1]

SpecStream 围绕两个事实设计系统：一轮验证中的多个 query 共享已提交历史；target 在等历史 KV 搬运时，GPU 部分计算单元可能空闲。它只把 target 已确认的历史迁到 CPU，未确认候选保留 GPU 本地，从状态边界上把“跨设备迁移”与“候选拒绝回滚”分开。[§4.1]

## 2. 三个互相配合的机制

1. **先到先算的 KV streaming**：按 token 切分 CPU 历史 KV；每块只传一次，供本轮所有验证 query 共用。每块 attention 用 online softmax 保存 `(m, l, a)` 中间状态，再与下一块按同一最大值重标定合并。实数运算下，这与全历史一次性 softmax 等价；浮点累加顺序改变会产生微小数值差异。[§4.2]
2. **按每个已提交 token 的代价调验证宽度**：控制器估算候选生成、target 验证、拒绝修正、历史传输与真正提交 token 数，选择估计 `T_round(q)/U(q)` 最小的 `q`。因此接受长度增加不必然带来吞吐增加。[§4.2、§5.3.2]
3. **Target 优先的同卡并行草稿**：在 KV H2D 传输造成计算空泡时，draft 在相同两张 GPU 上使用受限 TPC 并发前进；target 延迟预算超出时停止新 draft 工作。其目标是减少暴露在关键路径上的 draft 时间、节省专用 draft GPU。[§4.3]

## 3. 实验条件和结果

实现基于 SGLang 0.5.17；主实验用 2 张 A800 80GB PCIe Gen4、240GB host memory，Target/Draft 共卡，均 TP=2。对照包括 AR、SGLang SD、SGLang SD+Offload 和 TriForce；后者的开源实现面向 Llama，论文将其适配到 Qwen3/InternLM2.5。默认只让最近 512 token 的 target KV 留在 GPU，历史 KV 不额外占用 GPU cache；验证宽度在 `{2,4,6,8}` 中在线选择。[§5.1]

在 8 并发请求、三个数据集的汇总中，相对 TriForce，Qwen3 / InternLM2.5 平均吞吐分别是 `1.41× / 1.32×`；相对 SD+Offload 是 `1.44× / 1.62×`。不要把两个 baseline 混成一个“offload 基线”。和使用额外专用 draft GPU 的并行 speculative baseline 比，论文报告每 GPU 输出吞吐平均提升 55.4%。[摘要、§5.2.2]

结果也显示它优化的是“内存容量受限的服务”：长输入 LongBench v2 / MRCR 上，SpecStream 仍慢于 target KV 全驻 GPU 的 SGLang SD；每轮历史还要经 PCIe 传输。并发 32 时，Qwen3 转移 H2D 总量达每卡 7.79 TiB，InternLM2.5 为 3.29 TiB；作者观察到前者 throughput 恢复较弱。另一个设计代价是完整 draft KV 仍留在 GPU，随并发增长会限制可接纳请求数。[§5.2.2、§5.4]

质量对照中，6 组模型×任务的最大差为 0.1988 个百分点；作者将其归因于 chunked softmax 不同的浮点累加顺序。论文证明的是数学上保留全历史注意力定义，不是位级完全相同，也没有超出这些模型/任务的通用精度保证。[§4.2、Table 1]

## 4. 消融中最值得记住的点

在 16K 输入的消融里，固定 `q=4` 的 streaming access 相比“先完整恢复历史再验证”，Qwen3 平均吞吐提高 83.2%，InternLM2.5 提高 117.1%，是这组机制中最大的增益来源。之后跨层预取再提升 4.5–15.6% / 3.0–15.3%；cohort batching 在 4–16 并发下也带来收益，但单请求几乎无收益。动态 q 的效果不是单调：一个 InternLM2.5 设置接受长度从 3.64 升到 6.22，吞吐却降 1.2%。[§5.3.1–5.3.2]

这篇论文的研究价值在于把 speculative decoding 的系统边界从“草稿接受率”扩展到“已提交 KV 生命周期 × PCIe 流量 × 每轮有用输出 × GPU 并发调度”。它适合显存容量卡住并发的服务，不代表 offload 在长上下文上一定快过全驻 GPU。

## 5. 复现边界

- 文中比较跨三个模型/任务数据集的吞吐，但主要装置是单一 PCIe Gen4 + A800 拓扑，不能外推到 NVLink、NVMe 或其他 GPU。
- TriForce 的 Qwen3/InternLM2.5 结果由论文作者适配，非其原始公开 Llama 实现直接结果。
- arXiv 论文提到 SGLang 0.5.17，但没有链接代码仓库/commit；暂时只能引用论文固定版本，无法审计其内核实现与完整配置。
- 本批未运行 SGLang、未下载模型或独立复现吞吐。
