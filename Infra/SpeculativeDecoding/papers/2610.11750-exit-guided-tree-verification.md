# Exit-Guided Speculative Decoding：固定树的接受上限、直接验证与草稿反馈

来源：Hu et al., [*Where Draft Trees Lose Target Mass: Exit-Guided Speculative Decoding*](https://arxiv.org/html/2610.11750v1)，固定版本 v1（2026-10-08）。重点阅读 §2–§6，尤其 §3 的 canonical exit law / fixed-tree ceiling、§4 的 TEV、§5 的 ExitTrain、§6.2 verifier efficiency 与 Appendix A–C。

## 固定树先决定了 target 能走多远

给定一个已经构造好的 prefix-closed draft tree，target 模型从根开始按自身概率继续生成；当它走到某个节点后，下一 token 不在该节点的草稿子节点中，目标路径就“退出”当前树。论文定义：

- $P(v)$：target continuation 到达节点 $v$ 的概率；
- $\rho(v)$：到达 $v$ 后，target 下一 token 没有被该节点草稿子节点覆盖的概率；
- $w(v)=P(v)\rho(v)$：target 恰好在 $v$ 离开树的概率。

例如，target 有 0.4 的概率到达某前缀，但树的子节点只覆盖其中 0.25 的条件概率，则该节点贡献 $0.4\times(1-0.25)=0.3$ 的 exit mass。所有节点的 $w(v)$ 构成归一化分布，因为任何 target continuation 在有限树上恰好有一个最深的匹配节点。[§3.1](https://arxiv.org/html/2610.11750v1)

它把“树里哪些前缀有 target 质量”变成可计算的量：

\[
C_p(\mathcal{T})=\sum_{u\ne r}P(u)=\sum_v w(v)\,\mathrm{depth}(v).
\]

每个 target 到达的非根节点最多贡献一个被接受草稿 token；再加每轮的 bonus token，任何 exact path verifier 在固定树上的期望输出块长都不超过 $1+C_p(\mathcal{T})$。也就是说，如果高概率 target 路径根本不在候选树里，换一种 exact verifier 不能接受一个不存在的候选 token；更高接受长度必须来自更好的 draft-tree coverage。[§3.2–§3.3](https://arxiv.org/html/2610.11750v1)

## 相同的 exact 输出律，可以用不同计算实现

论文证明，达到固定树上限的 exact verifier 都必须实现同一个 exit law：以 $w(v)$ 选择退出节点，再从该节点未被草稿覆盖的 target residual distribution 抽一个 bonus token。作者指出 DDTree 的 predraw-and-follow 与 EAGLE-style sequential residual verifier 都已实现该饱和律；二者在同一 target 和同一树上没有更高的期望输出块长空间，差异在内部计算过程和系统成本。[§3.2、Appendix A.4](https://arxiv.org/html/2610.11750v1)

Tree Exit Verification（TEV）把这个概率律直接实现出来：先并行/逐层累积节点 exit mass，再抽一个 exit node，随后从该节点的 target residual 抽 bonus token。这样可避免 predraw 的每节点采样或 sequential residual 的数据依赖逐项检查，形成 sibling-order-invariant、level-parallel 的固定形状流程。它改变的是**如何执行同一个 exact verification law**，不是把 target 分布放宽，也不是提高固定树的统计接受上限。[§4、Appendix B](https://arxiv.org/html/2610.11750v1)

这里的“exact”有明确前提：论文的形式化对象是给定上下文、target (p)、已实现的有限 prefix tree 和 exact path verifier；树支持上的 target 概率与节点条件分布必须按原文定义精确计算。它不表示训练出的草稿器与 target 相同，也不自动保证任意近似 kernel、量化实现或不同树构造器都满足 bitwise 一致。

## ExitTrain 把验证中的“缺口”反馈给草稿训练

既然换 verifier 不能超过固定树 ceiling，论文再问如何改变下一次生成的树。exit law 的 $w(v)$ 标出 target 到达某前缀后，仍有多少概率从现有子节点漏出；ExitTrain 在训练当前 drafter 时，按实际 builder 构造 draft tree，再用冻结 target 在**真实树父前缀**上计算节点概率，并用 exit mass 给相应草稿 token 的似然加权。高 exit-mass 区域代表“target 经常到这里，但树漏掉了重要后继”，因此训练目标会推动有限节点预算转向这些区域。[§5](https://arxiv.org/html/2610.11750v1)

这与一般 token KL/CE、按 prefix reachability 加权或一个标量 tree reward 不同：它让训练信号定位到具体“哪里退出、缺了哪些 target 概率”。论文中 Qwen3-4B 固定 budget $B=64$ 的 matched ablation 报告，ExitTrain 在 $T=0$ 与 $T=1$ 相对 token-only finetuning 的平均输出块长分别再提高 5.9% 与 7.9%；该结果属于其模型、DFlash drafter、DDTree builder 和训练配置，不能外推为所有 draft 训练通用增益。[§6.2、Table 2](https://arxiv.org/html/2610.11750v1)

## 与 HSD、RheoSampling、ValuSpec 及 KL 证书的区别

| 工作 | 研究对象 | 主要改动 | 保证/边界 |
| :-- | :-- | :-- | :-- |
| [HSD](2601.05724-hsd.md) | 抽样 draft chain 的层级/序列接受 | 分层概率质量与 chain verification | 严格分布保持条件按论文的 sampled-chain 结构推导 |
| [RheoSampling](2609.21827-rheosampling.md) | (T>0) 的动态候选树 | target/draft 条件分离与概率回补 | 严格采样保证依赖其动态树和候选修正 |
| [When Is a Draft Accepted?](2606.30265-when-is-draft-accepted.md) | 给定 greedy/relaxed/top-m 局部接受规则 | 用 $KL(p\|q)$ 与 margin 给出局部接受证书 | 证书不是随机 sampling 的序列分布证明 |
| [ValuSpec](2610.31338-valuspec.md) | 已构造的候选树 | 用 target greedy 校准分数过滤候选，再做原有 greedy verify | 优化 T=0 候选冗余；不改变 sampling acceptance rule |
| 本文 TEV | 已构造的有限树与 exact path verifier | 按 exit law 直接采样 exit node / bonus token | 固定树 ceiling 的一种更直接执行实现；不提升树自身 coverage |
| 本文 ExitTrain | 草稿树的 target coverage | 用节点 exit mass 训练 draft 分支分配 | 改变未来树质量；收益依 builder、训练模型与预算条件 |

因此，树状 speculative decoding 至少有两种“验证侧改进”：**相同树如何更省延迟地做 exact verify**（TEV），以及**树外遗漏的 target mass 如何指导下一版 draft tree**（ExitTrain）。前者不提高固定树上限，后者不改变接受规则；两者可以组合，但各自的实验收益不能相加或混为一个 verifier 加速结论。

## 证据边界与阅读位置

- 作者在 Qwen3、Llama 3.1、Gemma 4 与 Qwen3-Coder 条件下评估不同树预算/温度；多任务的 accepted block length 和 speedup 是特定实验报告，不是通用树形保证。[§6、Appendix D](https://arxiv.org/html/2610.11750v1)
- TEV 的 verifier-stage latency 对照固定了 drafter、builder 和已实现的树，并单独排除共享 target tree forward；15% 的 verifier-stage 降幅不等于同幅度端到端收益。作者报告端到端收益更小，说明测量边界不可混用。[§6.2、Appendix D.1](https://arxiv.org/html/2610.11750v1)
- ExitTrain 的数据收益来自 target teacher 在实际树节点上的监督，以及相同 builder/budget 的对照；它不证明校准 target 或预训练 tree builder 可以零成本迁移。

**带走的机制区别**：先把树固定，exit law 给出任何 exact verifier 的上限；TEV减少到达这个上限的计算开销，ExitTrain则试图让下一棵树覆盖更多 target 概率。这里的“树验证”因而跨越概率正确性、候选支持与执行代价三层，不能归结为换一个遍历顺序。
