# Acceptance-Aware Training：让草稿损失看见“前面拒绝会作废后缀”

> 原文完整标题为 *Acceptance-Aware Draft Model Training for Speculative Decoding*（arXiv [v1](https://arxiv.org/abs/2609.24150v1), 2026-09-21）。正文 §§3–5、Tables 1–3，尤其是 §3.2 的 EAL 与 §3.3 的 WTV。正文中偶见 “LK Losses”作为近期 related work 的标签；本篇标题与官方 arXiv 元数据以 Acceptance-Aware Draft Model Training 为准。

## 问题：常见的 KL 目标把一个窗口里的 token 当得太平均

草稿模型通常用交叉熵或 KL 让每个位置的分布接近 target。对投机解码而言，窗口内的贡献却不相等：如果位置 2 拒绝，位置 3 到 γ 后面的候选即使“单 token 很像 target”，也无法被验证。草稿训练的真正收益取决于**连续前缀能被接受多长**，而这随 greedy 与 sampling 验证方式而变。[§1–2、§3.1](https://arxiv.org/html/2609.24150v1)

该工作在固定大小的 speculative window 内构造目标：若位置 \(t+j\) 的条件接受概率为 \(a_{t+j}\)，窗口从 \(t\) 开始，则前 \(k\) 个候选全部存活的概率为这些接受概率的乘积。因此预期接受长度可写为：

\[
\mathbb{E}[L_t]=\sum_{k=1}^{\gamma}\prod_{j=0}^{k-1}a_{t+j}.
\]

这个尾和公式让后续位置天然被前面每个接受事件门控。它不是把所有 draft token 的质量简单加总，而是按**连续路径存活概率**计分。[§3.1、Eq. (4)](https://arxiv.org/html/2609.24150v1#S3.SS1)

## Greedy 与 sampling 的“接受”不是同一信号

### Greedy：EAL 对齐 target 的 argmax 选择

若 target 用贪心解码，draft 在位置 \(t\) 被接受的概率就是 draft 分布给 target argmax token 的概率。由于训练前缀来自冻结 target 的 greedy 轨迹，该 token 与序列真值一致。将这个概率代入预期接受长度并取负，就得到 **Expected Accepted Length（EAL）loss**；论文允许把它作为 KL anchor 的辅助项，target 分布冻结、梯度只更新 draft。[§3.2、Eqs. (5)–(12)](https://arxiv.org/html/2609.24150v1#S3.SS2)

直觉上，EAL 不仅问“此位置 target 的首选 token 概率是多少”，还会把“前一位置高概率通过后，第二、第三位才有机会被接受”写进目标。它是**一个 window 内预期接受 token 数**的直接代理，而不是全序列实际耗时目标。

### Sampling：WTV 用分布重叠反映单步拒绝率

在拒绝采样下，单位置接受概率等于温度缩放后 target 与 draft 分布的重叠质量，即 \(1-\mathrm{TV}(\tilde p_t,\tilde q_t)\)。论文把这一量代入同一个窗口尾和，构成 **Window Total Variation（WTV）loss**：

\[
\mathcal L_{\mathrm{WTV}}^{(t)}=-\sum_{k=1}^{\gamma}\prod_{j=0}^{k-1}\left(1-\mathrm{TV}(\tilde p_{t+j},\tilde q_{t+j})\right).
\]

与“逐位置 TV 距离求平均”相比，乘积结构保留了前面位置的拒绝如何让后续候选失去价值。target 与 draft 必须按部署时的温度形成 \(\tilde p,\tilde q\)，因此 WTV 是对具体采样温度的目标，不是温度无关的固定损失。[§3.3、Eqs. (13)–(15)、Fig. 1](https://arxiv.org/html/2609.24150v1#S3.SS3)

EAL 与 WTV 针对不同接受规则：EAL 看 target 的贪心 token，WTV 看拒绝采样下的分布重叠。作者还尝试在 SFT 后加 GRPO，以模拟接受长度作为 reward。不能把它们合成一个“通用 acceptance loss”。[§3.4](https://arxiv.org/html/2609.24150v1#S3.SS4)

## 实验怎样区分“逐 token 匹配”和“窗口目标”

实验使用 Qwen3 家族的 target–draft 配对：Qwen3-8B/0.6B 的 DSpark，以及 Qwen3-8B/0.6B 的 DFly。两种 drafter 均采用固定窗口 \(\gamma=7\)；树设置最大深度 7，分层 branching factors 为 \((4,3,2,1,1,1,1)\)，运行时再剪到 128 个节点。评测 batch=1、在 H100 上运行，以接受长度作为主要指标。[§4.1](https://arxiv.org/html/2609.24150v1#S4.SS1)

训练数据是 60,000 条由冻结 target 从 ShareGPT prompt 生成的序列，最大长度 2,048；对照训练都以相同模型结构、数据、optimizer 设置与 update steps 比较。训练可采用 6 epoch SFT，或 3 epoch SFT 后接 3 epoch GRPO。[§4.1、Table 1](https://arxiv.org/html/2609.24150v1#S4.SS1)

作者的核心结果不是“所有 decoding mode 都由一个目标胜出”，而是目标与验证规则匹配：greedy 场景中在 KL anchor 上加入 EAL 有一致但较小的提升，GRPO 阶段可继续增加接受长度；sampling 场景中，WTV 在 \(T=0.5\) 与 \(T=1.0\) 上比单纯 KL 或 per-position TV 更有优势。Table 1–3 同时报告多个 target、task、温度和 chain/tree 配置；它们都是论文报告值，不能把不同温度或不同 drafter 的最高单项拼成一个排序。[§4.1–4.3、Tables 1–3](https://arxiv.org/html/2609.24150v1#S4)

## 放进草稿训练目标谱系中

| 目标 | 它直接改什么 | 与本文差异 |
|---|---|---|
| CE/KL | 让 draft 的逐位置 token 分布接近 target | 间接代理接受；不编码一个拒绝会使后续位置失效 |
| AdaSPEC | 只对更易拟合的训练 token 做选择性蒸馏 | 改**训练样本/位置选择**，不直接建模窗口存活概率 |
| VSD | 对 latent draft path 的接受有效性做变分优化 | 改**路径分布目标**，兼顾接受路径与 target 路径先验 |
| AAT / EAL、WTV | 在固定 window 内优化连续接受长度；按 greedy/sampling 分目标 | 直接表达窗口接受概率，但仍是局部窗口目标 |
| EDR | 用状态访问概率计算全序列期望验证轮数 | 跨 round/anchor 的全局目标；与本文 window-local objective 的优化范围不同 |

这条路线的核心转换是：从“训练时拟合 target 分布”转为“训练信号考虑草稿真正如何被验证”。但**接受目标也有不同粒度**：单位置、窗口内连续长度、整条候选路径、整条生成过程的 decoding rounds；它们不能只按同一个“acceptance-aware”标签合并。[AdaSPEC、Attention Drift、EDR 综合见 draft-side 横切专题](../topics/draft-side-and-training.md)

## 边界与问题

- 论文主要比较作者构造的训练条件和不同损失，训练使用冻结 target rollout；它没有证明 EAL/WTV 在任意 target、block size、tree budget 或线上 serving 模式下都更快。
- 主要评价指标是 accepted length，不是端到端 wall-clock。训练数据、draft forward、tree construction、verification kernel 与调度成本可能改变真实收益。
- EAL/WTV 都使用固定 window；当 draft block 位置依赖 round start、上一轮接受长度时，局部窗口目标是否足够，需要与 EDR 这类跨轮目标区分。
- WTV 通过全分布 TV 形成梯度，计算与存储开销、词表尺度和目标温度可能成为训练成本；论文实验条件不能自动推出生产训练预算。

开放问题是：窗口目标能否和路径级 VSD、全局 EDR 组合而不重复计分？当树的分支、block length 或 decoding temperature 在线变化时，训练目标该优化哪种接受状态？是否存在一套同时考虑接受长度与每轮硬件耗时的目标？
