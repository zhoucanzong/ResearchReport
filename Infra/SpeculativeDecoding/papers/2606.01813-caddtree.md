## 亮点与差异四行

- **问题**：DDTree 在固定节点预算下最大化期望接受长度，但该指标随预算增大不会下降，因此本身无法选择“树长到哪里才值得”；真实目标应计入 target 验证树的边际延迟。[§1、§3.4]
- **方法**：CaDDTree 用扩散草稿的一次并行输出生成位置边际概率，沿 DDTree 的 best-first 前缀概率次序扩展；将 draft 与验证延迟写入单位时间接受 token 数，在凸验证成本假设下证明预算目标单峰，以边际收益停止规则逐轮选树大小。[§4.1–§4.5、Algorithm 1、Lemma 1、Corollary 4]
- **Table 1**：Qwen3-4B、MATH-500、T=0 时，CaDDTree 的 `4.53 ms/token, τ=10.37` 与 DDTree 网格 oracle 的 `4.53 ms/token, τ=10.35` 接近，但平均树预算 221 而 oracle 固定选 256；八个任务中总体为匹配或多数胜过 oracle。不是普遍更低延迟：例如 Qwen3-4B/GSM8K 是 5.18 对 5.14 ms/token。[§5.1–§5.2、Table 1]
- **与 DARTree 的边界**：DARTree 已针对扩散草稿提出逐分支因果校正，并把并行建树与末尾 top-B 剪枝分开；CaDDTree 不应被写成首次扩散树或首次延后剪枝。它的具体新意是把树规模也纳入吞吐/延迟目标，结合测得的 target 验证成本逐轮选预算。它仍依赖一次性的硬件/模型延迟 profiling。[DARTree §3、Algorithm 1；CaDDTree §2、§4.6]

## 1. 从“越大越能接收”到边际吞吐停止

块扩散 draft 一次给出整段各位置的边际分布 `q_i`，不对块内已选 token 做自回归条件化。给定候选前缀树 `T`，target 仍在一个树注意力前向中选择最长可接受路径；验证节点越多，候选覆盖越广，但 target 的验证时间也增加。[§3.1–§3.3]

DDTree用各节点的前缀概率排序，在固定节点数 `B` 下取概率最高的前缀节点，最大化 drafter surrogate 下的期望接受长度。CaDDTree指出接受长度的单调性让这个目标无法判断新节点是否值得其代价。作者测量 draft 时间 `C_d` 和 target 验证时间 `C_v(n; ℓ)`，以 `(1 + 期望接受数)/(draft + verify 时间)` 作为每轮目标；利用相邻节点的期望接受增量和验证边际成本比较，构成按前缀分数扩展的停止准则。对单调凸的 `C_v`，作者证明该比值关于树大小单峰，于是停止处就是预算最优点。[§3.4、§4.1–§4.5、Appendix A]

此处的“自适应”不等于免测硬件：算法先离线以不同上下文长度、节点数实测验证耗时，再拟合成本曲线；在线每轮只需按当前边际分布与当前上下文成本扩树。作者称无需离线搜索任务/数据集预算，也不需新增训练。[§4.6]

## 2. 结果应连同目标模型和实现条件读

主测试配对 Qwen3-4B/8B target 与各自 DFlash checkpoint，八个任务覆盖数学推理、代码和指令跟随；使用 8×A800、BF16、块长16、最长生成2048新 token，温度0及1。[§5.1]

Table 1 的主比较是 AR、DFlash、DDTree-oracle 与 CaDDTree。DDTree-oracle 对每个数据集、模型、温度在 `{16,32,64,128,256,512,1024}` 网格中选最佳固定预算，因此是预算选择的强上界型参照；CaDDTree预算可逐轮变化，也可落在网格间。温度0下，Qwen3-4B八项中 CaDDTree基本贴近或优于 oracle；Qwen3-8B同样在大多数任务胜出。表中报告的是端到端每 token 毫秒及平均接受长度，不要只用 `τ` 代替延迟判断。例如 Qwen3-4B/Alpaca 为10.66 ms/token、τ=4.88，oracle为10.42 ms/token、τ=4.89：接受长度接近并不代表吞吐占优。[§5.1–§5.2、Table 1；T=1见Appendix C、Table 4]

验证成本消融尤其能说明机制：Table 2把 `C_v(n;ℓ)` 错设为常数后，收益代理随预算单调增加，算法打满1024节点，三个展示任务的延迟约翻倍；实测成本曲线在9个上下文长度（0–8k）上与单调凸拟合吻合（R²≥0.979，RMSE≤4.9 ms）。Figure 4–5显示同一个数据集内也会出现窄树已足够与需要宽分支的轮次。[§5.3–§5.4、Table 2、Figures 3–5]

## 3. 实验范围与相邻工作的定位

- CaDDTree论文的实现差异影响延迟解释：树验证用标准 PyTorch scaled-dot-product attention，因为 FlashAttention-2 不支持该自定义树 mask；AR 和 DFlash取两种 attention 实现中较快者，DFlash使用FlashAttention-2。因此表中是作者当前实现下的整体系统比较，不是所有方法都用同一 attention kernel 的受控内核对照。[§5.1]
- 单一 Qwen3 家族和 DFlash draft 无法证明该预算控制可直接迁移到其他 target、扩散 draft、树注意力实现或并发服务。验证成本需在目标硬件/模型上测量；作者的参数扰动消融只说明所测配置下中等误差影响较小。[§4.6、§5.5]
- 与专题已有 DARTree 的互补点是清楚的：DARTree每条分支以路径状态校正边际提议，并延后全局 top-B 裁剪；CaDDTree在成本曲线单峰前提下选择 B。两者可被视为分别处理“候选树质量/构造”与“树预算/时间”的研究问题，论文并未在 CaDDTree主表中直接比较 DARTree，不能据现有结果宣称谁更快或可直接组合。[CaDDTree §2；DARTree §3、§5]
- 本笔记未运行作者代码、重建 profiling 曲线或独立复现；所有性能数字都是原文作者报告值。
