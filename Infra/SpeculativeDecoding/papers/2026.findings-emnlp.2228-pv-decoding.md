# PV-Decoding：让扩散解码按置信度逐级验证

来源：Liu et al., [*PV-Decoding: Progressive Verification Decoding with Decode Gating for Diffusion Language Models*](https://aclanthology.org/2026.findings-emnlp.2228/)，Findings of EMNLP 2026 正式版。本文依据 ACL Anthology 会议版 PDF；重点阅读 §3–§6.2、Algorithm 1–2、Figure 1–3 和 Tables 1–3。题录由 paper-fetcher Crossref 检索得到，并与 ACL Anthology 元数据对照；paper-fetcher 的单篇抓取器不支持 Anthology URL。

## 它加速的是哪一种生成

PV-Decoding 的 target 是**扩散语言模型自身**。每轮仍由同一个 dLLM 对当前部分遮盖的 block 并行预测；没有另一个 AR target，也没有单独训练一个 draft。它是 dLLM 原生 block decoding 上的**自投机式推测与验证**：先让中等置信度位置暂时填入候选，再用下一轮同一模型的预测检查这些候选。

这使它和扩散草稿器为 AR target 服务的 DFlash、DARTree 不同，也和“用 LLaDA 本身替 AR 模型提议 token”不同。论文的三个实验模型是 LLaDA-8B-Instruct、Dream-7B-Instruct 和 openPangu-7B-Diffusion-Base；LLaDA 在这里是被加速的 dLLM，而不是 AR target。[§5.1、Table 1](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

## 机制：中等置信度先暂填，失败时卡住新的提交

Fast-dLLM 一类置信度解码按阈值 \(\tau_{dec}\) 直接提交高置信度 token。PV-Decoding 再增加较低的 \(\tau_{spec}\)，将仍被遮盖的位置分成三组：

- 置信度不低于 \(\tau_{dec}\)：直接解码并提交；
- 介于 \(\tau_{spec}\) 与 \(\tau_{dec}\)：暂时填入预测，留待下一轮验证；
- 低于 \(\tau_{spec}\)：继续保持 mask。

暂填很关键：扩散模型的同一 block 中各位置会双向互相影响。位置 A 的候选 token 可能帮助位置 B 更早确定，也可能让 B 在错误上下文上变得自信。因此，置信度不是独立于其它候选的局部正确率；候选的条件上下文需要通过下一轮检验。[§4.1–4.2、Figure 1](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

验证时，当前模型重新预测先前暂填的位置。候选须同时满足“当前 argmax 与暂填 token 一致”和“当前置信度达到 \(\tau_{dec}\)”才算通过。论文设计三种强度：

| 策略 | 怎样比较 | 失败时怎样处理 | 主要取舍 |
|---|---|---|---|
| **PV-1：单分支** | 在包含全部暂填 token 的同一分支上检查 | 未通过的候选重新 mask；若前一批候选未全部通过，本轮不再提交新的高置信度 token（decode gating） | 额外分支最少、前向轮数下降最大；候选互相影响时检验较弱 |
| **PV-2：双分支** | 并行跑“没有暂填候选”的 baseline 分支和“包含全部候选”的 speculative 分支 | speculative 分支全体通过才采用，否则回退到 baseline | 多一次分支计算，换更保守的整体判定 |
| **PV-multi：子集 DAG** | 以暂填位置的子集构造嵌套分支，用有限预算测试若干组合 | 从通过验证的分支中选包含候选最多者，其余位置重新 mask | 可保留部分有效候选；分支数和注意力计算可能超过节省的迭代成本 |

PV-multi 借用了 Spiffy 的 subset-DAG 作为一种候选验证结构，但它不要求固定某一张图：候选位置由本轮置信度阈值动态决定，DAG 只组织要比较的子集。正文 Algorithm 1–2 与 §4.3 给出门控、回退、重遮盖和分支选择的具体顺序。分支共享上下文，当前实现却把每个分支作为普通 batch 元素运行；因此论文指出，树形 attention layout 或融合 kernel 可能改变多分支策略的实际成本。[§4.3、Algorithms 1–2、§5.3](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

## 和 Spiffy 的关键差别：相同模型验证，不等于分布保持

Spiffy 也在 dLLM 内自投机，但问题和正确性标准不同。它从模型自身分布提出未来去噪状态，构造 draft graph；只有候选状态与模型真实的下一状态精确匹配时才跳步。其论文给出保持原 dLLM 输出分布的证明。PV-Decoding 则把中等置信度 token 暂填到当前 block，再根据下一轮的 argmax 一致性与阈值接受，并在不同分支间选择；方法本身是确定性的经验解码策略。

作者在 §4.1 明确说明，PV-Decoding **既不保持确定性解码轨迹，也不保持输出分布**。理由在机制中：暂填候选会改变同一 block 其它位置的条件输入；后续 argmax/置信度检查可以拒绝部分候选并重新 mask，但不会做拒绝采样的残差概率回补，也不证明最终的 token 承诺顺序与原 confidence decoder 完全相同。Decode gating 是降低错误传播的保护规则，不是分布等价证明。因此本文的“verification”应理解为筛查候选、降低经验错误率，不能读作严格的 target-preserving verifier。[§4.1、§4.3](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

它与 LLaDA / LLaDA 2.x 也处在不同层次：LLaDA 定义 masked diffusion 模型与迭代采样；LLaDA 2.1/2.2 把 token 替换、插入、删除等能力纳入模型训练和修订接口。PV-Decoding 不改训练目标，也不增加 Levenshtein 编辑动作，而是给现有块扩散解码器增加推理时置信度门控和验证分支。论文在 LLaDA-8B-Instruct 上报告结果，不能由此推断其与 LLaDA 2.x 的编辑策略兼容，或会继承那些模型的质量、长度控制和系统属性。

## 证据说明的是权衡，不是无损加速

作者在 GSM8K、MBPP、HumanEval 上评估三种 dLLM。Table 1 报告相对 Fast-dLLM 减少 8%–37% 的 sequential model forward passes；最明显的精度下降是 openPangu-7B-Diffusion-Base / HumanEval 上 PV-1 的 1.3 个百分点。这个例子说明单分支策略在代码任务上可能更脆弱，不能把平均 MFP 下降直接翻译成保持质量或分布不变。[§5.1–5.2、Table 1、Figure 2](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

在 Dream-7B-Instruct / GSM8K、单张 Ascend 910B3 的同硬件测试中，PV-1 和 PV-2 在并发 1、4、8 下分别报告 7.0%–13.6% 吞吐提升；PV-multi 则慢于 Fast-dLLM。作者将其归因于当前实现把分支作为独立 batch 元素执行，说明少做模型轮数并不自动转化为更低墙钟延迟。[§5.3、Table 2](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

Decode gating 的消融显示，在 GSM8K、HumanEval、MBPP 上，允许未完全验证时继续提交直接预测，会让 MFP 更少，但精度更低；这支持门控是一个抑制错误累积的经验设计，不说明该门控消除了所有错误传播。[§6.2、Table 3](https://aclanthology.org/2026.findings-emnlp.2228.pdf)

这些数字均为会议版论文报告结果。本文未运行模型或复现基准；阈值固定为 \((\tau_{dec},\tau_{spec})=(0.9,0.8)\)，模型、任务和单一 Ascend 硬件条件都限制可推广范围。尤其 PV-multi 的算法级少轮数结果与目前实现的吞吐方向相反，应把分支打包/内核优化看作尚未验证的后续系统问题，而非已兑现收益。[§5.1–5.3、§8](https://aclanthology.org/2026.findings-emnlp.2228.pdf)
