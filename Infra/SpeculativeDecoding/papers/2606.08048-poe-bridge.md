# PoE-Bridge：用中间分布缓和 diffusion 与 AR 的差异

**原文**：[arXiv 2606.08048v1](https://arxiv.org/html/2606.08048)，CC BY 4.0。阅读 §§3–6、Tables 1–3。未运行作者实现。

## 它问的是质量桥接，不是严格无损 draft 验证

作者把 DLM 作为并行 proposal，把 AR LLM 作为质量 target。两者序列分布差异较大时，直接重要性采样需要很多候选，计算代价高。PoE-Bridge 构造一个 product-of-experts 中间分布：混合 DLM 与 AR 的 token 条件概率，先通过拒绝采样把 DLM proposal 推向中间分布，再做 importance resampling 向 AR 目标校正。Mixed-temperature 提高有限候选数下的多样性，Elastic Rejection Window 限制一次验证跨度，避免验证大量最终会丢弃的 token。

这与标准 speculative decoding 的输出保证不同：它在有限候选预算下**不严格无损**。作者报告有限采样会有小幅 accuracy 降低，增加候选数可减小差距。因此应把它看作“向 AR 目标靠近的并行近似采样”，不能写成 target 分布精确不变。

## 作者报告的证据与边界

实验使用 Dream-7B-Instruct 作为 DLM proposal，Qwen2.5-Math-7B / Qwen2.5-Coder-7B 作对应 AR target；同 tokenizer，BF16，单张 A100 80GB，batch size 1。论文测 GSM8K、MATH、HumanEval、MBPP 的作者报告 accuracy 与 tokens/s；设置默认 PoE 权重 0.3、4 个候选、窗口 32。[§5.1、Table 1]

在其 MATH 结果中，PoE-Bridge 的 accuracy 与 Qwen2.5-7B AR 目标接近，吞吐约 94.94 token/s（有 IS 版本）或 99.49（w/o IS 版本），高于报告的 AR 46.50 token/s；但两个版本在四任务上的准确率并不与 AR 完全相同，论文明确承认有限重要性采样预算下非严格无损。[Table 1、§6]

局限包括 tokenizer 必须兼容、两个模型同时驻留带来显存压力、仅评估单 GPU batch=1，未研究多请求服务。窗口大小、候选数和 PoE 权重会改变吞吐—质量折衷。阅读它时要看质量与吞吐这对指标，不应只读最大加速值。[§5.3、§6]
