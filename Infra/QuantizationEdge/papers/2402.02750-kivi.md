# KIVI：Key 和 Value 为什么不沿同一维度量化

**原文**：[KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache](https://arxiv.org/abs/2402.02750v2)，arXiv v2（2024-07-25）。重点位置：§2–§4.2、附录 A。完整 HTML 原文：[arxiv.org/html/2402.02750v2](https://arxiv.org/html/2402.02750v2)。

## 从注意力计算看 KV 量化误差

解码时，当前 Query 与已缓存的 Key 先形成 (QK^T)，softmax 后再加权汇总 Value。Key 误差影响注意力分布，Value 误差影响被读出的向量。KIVI 观察到，在其研究的模型中，Key 有稳定的通道离群模式，而 Value 不呈现同样的模式；因此，Key 和 Value 的量化轴应分别选择。[§3.1–§3.2](https://arxiv.org/html/2402.02750v2#S3)

## 方法：K per-channel、V per-token，加上流式缓存缓冲

论文的 KIVI 使用 2-bit 均匀量化：Key 按通道聚组，使固定离群通道的误差局限在该通道；Value 按 token 聚组，以避免跨 token 的 Value 量化失真。Key 的 per-channel 分组需要把不同 token 放在一组，但生成时 cache 是逐 token 增长的，当前长度往往凑不齐分组。KIVI 因此把缓存分成已完成量化的 grouped cache 和暂存 residual cache；最后不足一组的部分保持高精度，等凑成一组后再量化。[§3.2–§3.3、Algorithm 1](https://arxiv.org/html/2402.02750v2#S3)

这不是纯粹的数值技巧：分组轴决定缓存更新方式、额外高精度尾部的大小以及 attention kernel 读取时的数据拼接。论文按不同缓存与量化器做 attention 输出误差分析，解释 Key 的按 token 量化会更明显地扰动注意力分数，而 Value 的分组选择影响输出误差。[§3.2](https://arxiv.org/html/2402.02750v2#S3)

## 论文证据支持什么

作者在 Llama、Mistral 和 Falcon 的生成、长上下文和吞吐设置中评估 KIVI；主要结论是该非对称方案可在论文条件下压缩 KV cache，并通过释放缓存空间提高可并行请求数。应把这些视为作者对具体模型、缓存配置、任务与 batch 的报告结果。[§4.1–§4.2](https://arxiv.org/html/2402.02750v2#S4) 这些结果不能外推为所有模型都适合相同 2-bit 分组，也不能直接预测某个 serving engine 的端到端加速。

## 后续路线

KIVI 用标量分组和不同量化轴解释 K/V 的结构差异。后续方法如 [VecInfer](2510.06175-vecinfer.md) 则用向量码本与平滑/旋转变换处理更低位宽下的离群值，并把反量化与 attention kernel 融合。前者的关键问题是“怎样对流式写入组织分组”，后者进一步问“怎样把 VQ 表示变成 GPU 上可执行的 attention”。
