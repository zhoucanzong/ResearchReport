# QATFactory：让训练期量化数值对齐部署格式

**原文**：[QATFactory: A Versatile, Deployment-Aligned Framework for Quantization-aware Training and Distillation of LLMs](https://arxiv.org/abs/2609.39223v2)，arXiv v2（2026-10-01）。重点位置：§3.1–§3.5、§4.2–§4.7。完整 HTML 原文：[arxiv.org/html/2609.39223v2](https://arxiv.org/html/2609.39223v2)。

## 研究问题：训练时模拟的量化，是否就是引擎实际执行的量化？

QAT 往往在训练中用 fake-quant 模拟低精度，再导出量化权重。但如果训练格式与推理引擎的 scale 粒度、舍入、块布局或激活规则不同，模型适应的噪声和上线后的误差可能不一致。另一道门槛是硬件：想训练 NVFP4 模型，未必有可用的 FP4 Tensor Core。QATFactory 把这两个问题合并成框架设计：以目标 engine 的格式实现前向量化，再用 BF16 完成矩阵乘与反向更新，训练后直接导出到目标引擎。[§3.1–§3.2](https://arxiv.org/html/2609.39223v2#S3)

## QAD 与 QARL

QATFactory 给出两条训练路径。

- **QAD（quantization-aware distillation）**：浮点教师保持冻结，学生从相同权重初始化，在目标低精度前向中训练，以 token 分布的 KL 目标贴近教师。论文的学生主要对 linear projections 做量化适配，其他模块按设置冻结；full-parameter 和 LoRA 两种版本有不同显存与质量取舍。[§3.3](https://arxiv.org/html/2609.39223v2#S3)
- **QARL（quantization-aware reinforcement learning）**：量化模型经低精度推理引擎采样 rollout，再由奖励或 verifier 评分并更新模型，随后同步更新权重。这把“部署时模型在低精度运行”带入 RL 训练/采样闭环，重点应检查 rollout 与训练权重之间的版本和数值一致性。[§3.4](https://arxiv.org/html/2609.39223v2#S3)

它不同于从头低精度预训练：QAD/QARL 从已有模型继续适配，并输出可部署 checkpoint。也不同于单纯“加了 fake quant”：QATFactory 的贡献重点之一是将目标格式的量化边界、尺度共享、量化/反量化和引擎导出纳入同一协议。

## 重要发现：越忠实模拟，并不总是越好

论文比较 NVFP4 与 MXFP4 的 W4A16、W4A4 训练设置。对于 NVFP4，训练时只量化权重在其模型实验中持平或优于同时量化激活；对于 MXFP4，Qwen3.5-9B 的 W4A4 配置较 W4A16有更好结果。作者将差异与块大小、scale 格式和训练梯度扰动联系起来，并把部分解释明确写成可能原因，而不是已证实的通用规律。[§4.3](https://arxiv.org/html/2609.39223v2#S4)

这打破了一个过度简单的 QAT 假设：训练前向越像推理，结果就一定越好。量化噪声提升部署匹配度，也可能污染学生要拟合的输出和反向梯度；格式会决定这个权衡。论文还报告 token 预算相同时，较少但更长的训练序列在其 Qwen3.5-9B 数学/代码域实验中更有利，跨域效果也不对称。相关结果只支持特定训练数据、格式和评测基准下的阅读判断，不应直接外推为“长序列 QAT 总更好”。[§4.5](https://arxiv.org/html/2609.39223v2#S4)

## 结果边界与阅读重点

论文展示 8B–230B 范围的模型和多种量化格式，核心质量比较以训练后的实际导出模型在推理引擎中的评测为目标，而不只看 fake-quant 仿真。[§4.1–§4.7](https://arxiv.org/html/2609.39223v2#S4) 这使它很适合研究“QAT 怎样变成 engine-native checkpoint”。但仍需把结论限制在论文已支持的格式、架构和训练条件：导出兼容不代表所有后端和模型配置均可直接套用；论文所示的 QAD/QARL 质量结果是作者报告，不是本库独立部署验证。

## 与其它低位宽路线的关系

- 对比 [LLM-QAT](https://arxiv.org/abs/2305.17888v1) 的“教师自生成文本、适应低位宽”，QATFactory 将重点往前推进到具体部署格式和推理引擎导出。
- 对比 [LC-QAT](2606.10531-lc-qat.md)，QATFactory 主要围绕部署格式、QAD/QARL 流程与 engine alignment；LC-QAT 则专注 2-bit 权重 VQ 的可微代码表示。
- 对比 [Quartet](https://arxiv.org/abs/2505.14669v4)，前者用高精度矩阵乘模拟目标量化并适配已有模型，后者研究原生 MXFP4 训练与 Blackwell kernel。两者分别解决训练可用性和训练数值/硬件效率问题。
