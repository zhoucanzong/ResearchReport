# LC-QAT：把 2-bit 向量码本改写成可微的线性结构

**原文**：[LC-QAT: Data-Efficient 2-Bit QAT for LLMs via Linear-Constrained Vector Quantization](https://arxiv.org/abs/2606.10531v3)，arXiv v3（2026-09-11）。重点位置：§2.1–§3.4、§4、§5.1–§5.3、附录 A.2–A.5。完整 HTML 原文：[arxiv.org/html/2606.10531v3](https://arxiv.org/html/2606.10531v3)。

## 问题：2-bit 标量 QAT表达力不足，VQ 的离散索引又难反传

2-bit 标量量化为每个权重提供很少的独立取值。向量量化可以将一组权重匹配到共享 codebook 中的一个向量，组合表达更丰富；但 nearest-neighbor 索引和 codebook lookup 是离散操作，梯度难以直接穿过。若用 beam search 或逐坐标搜索更新，参数的同步训练也可能变慢。LC-QAT 针对的是这个表示/优化接口：怎样保留向量码本的组合能力，同时让端到端训练有可微路径？[§2.1–§2.3](https://arxiv.org/html/2606.10531v3#S2)

## 方法：把码本向量表示为整数码的仿射映射

LC-QAT 将码本向量写成 `c = A z + B`：`z` 是每维 2-bit 的整数编码，`A` 与 `B` 是共享的浮点映射参数。前向中，proxy weight 先经舍入得到 integer code，再通过 `A`、`B` 解码成量化权重；反向用 differentiable gradient estimator 穿过离散化更新 proxy weight。初始化来自 PTQ 的低误差结果，避免从随机、表达能力弱的标量权重开始再用大量数据“救回来”。[§2.2–§3.4](https://arxiv.org/html/2606.10531v3#S3)

结构化解码还有系统意义：论文将映射重写成 activation 的小型线性变换加整数矩阵乘，因而可以复用为标量量化优化的整数 GEMM kernel；码本表达能力与部署执行路径被共同设计。这与 AQLM 用离散多码本索引、beam search 更新代码的路线不同：LC-QAT 刻意把码本限制在仿射结构中，换取更易优化和更容易与整数 kernel 对接的形式。[§3.2–§3.4](https://arxiv.org/html/2606.10531v3#S3)

## 证据及其条件

论文在 Qwen3-1.7B/8B、Llama-3-3B/8B 等基座模型上研究 2-bit 权重量化，并比较 PTQ、VQ-QAT 和标量 QAT。作者报告 LC-QAT 在同训练预算的若干评测中优于相关基线，并声称在其数据效率实验中，使用一部分 QAT 数据可达到或超过更大预算的对照。[§4–§5](https://arxiv.org/html/2606.10531v3#S4) 这些对照需要带着模型家族、2-bit weight-only 设置、训练语料和 benchmark 读；表格中部分 baseline 结果来自先前论文，不能把所有表内差异视为同一重跑的完全控制实验。

论文报告的 CUDA kernel throughput 对比也依赖具体量化布局、batch 与目标设备。[附录 A.2](https://arxiv.org/html/2606.10531v3#A2) 本文不把它换算成通用速度收益；核心学习点是“一个可微的 codebook 参数化如何把向量量化训练和常规整数 kernel 连起来”。

## 与 AQLM 和 QATFactory 的关系

- **AQLM** 通过多码本向量和离散索引提高 2-bit 左右的表示能力，依赖搜索与 block-level 优化。
- **LC-QAT** 将码本受限为仿射映射，以 PTQ 初始化建立离散码，再通过可微 proxy 参数优化；代价是表达集合受到线性结构约束。
- **QATFactory** 重点在训练数值与目标推理格式/引擎对齐，支持 NVFP4、MXFP4、Q4_K 的 QAD/QARL；它处理的是部署格式流程，而不是 2-bit VQ 的离散码本优化。

这几条工作共同展示了一个趋势：极低位宽不只要求“更强的量化算法”，也要求表示结构能够被优化器更新、被整数/GPU kernel 执行，并与最终推理格式保持一致。
