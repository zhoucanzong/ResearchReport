# VecInfer：把 KV 向量码本和 Attention kernel 放在一起设计

**原文**：[VecInfer: Efficient LLM Inference with Low-Bit KV Cache via Outlier-Suppressed Vector Quantization](https://arxiv.org/abs/2510.06175v1)，arXiv v1（2025-10-07）。重点位置：§3.1–§3.3、§4.1–§4.4、附录 B–D。完整 HTML 原文：[arxiv.org/html/2510.06175v1](https://arxiv.org/html/2510.06175v1)。

## 问题：矢量量化更灵活，为何极低位宽时仍掉点？

标量量化让每个元素独立落在整数格点；向量量化（VQ）则用 codebook 向量表示一段 cache，码本理论上能用更少索引比特表示更丰富的局部结构。但若 Key 向量中仍有离群值，码本中心难以覆盖长尾；而映射到 cache 的 token 维度又要兼顾在线 Attention 的读取方式。VecInfer 因此同时处理表示误差与 kernel 代价，而不是只换一个压缩格式。[§3.1](https://arxiv.org/html/2510.06175v1#S3)

## 双变换与 codebook

VecInfer 对 Key 使用平滑变换降低通道间幅值差异，再使用 Hadamard 旋转分散剩余离群值。为了不改变点积注意力分数，Query 和 Key 采用配对变换，使旋转与平滑可以在 (QK^T) 中抵消。变换后的 Key 与原始 Value 分别进入向量量化；码本通过预取样的 cache 表示和 K-means 预训练，而不是每个请求在线重新拟合。[§3.2](https://arxiv.org/html/2510.06175v1#S3)

这与 QuaRot 的共同点是利用等价变换缓解离群值；差别在于 VecInfer 的目标对象是流式 KV cache，并把变换后的表示交给 VQ，而 QuaRot 主线是对模型权重、激活与 KV 做 4-bit 标量量化。两者不能简单按“平均位宽”排名。

## 融合 kernel 解决什么

如果每次 attention 都先把整个压缩 cache 展开到 FP16，省下的内存读取可能被临时张量和反量化开销抵消。VecInfer 的 CUDA kernel 以小 tile 加载码本索引、查表得到向量，并将反量化与 attention 计算融合；因此它把 cache 压缩格式作为 kernel 的输入协议设计。论文还分析了 codebook 大小：更大的码本增加表示能力，也占用更多共享内存，可能降低计算效率。[§3.3、附录 B](https://arxiv.org/html/2510.06175v1#S3)

## 实验边界

作者在 Llama-3.1-8B、Qwen2.5-14B、Mistral 等模型上评估长上下文与推理任务。论文报告在 Llama-3.1-8B、196k 序列的特定设置下，2-bit KV 对大 batch attention 和单 batch 端到端延迟有收益；模型、序列长度、GPU 与 baseline 都是结论的一部分。[§4.1–§4.3](https://arxiv.org/html/2510.06175v1#S4) 本报告不把摘要中的最大加速数外推到常规短请求或其他引擎，也不把表中不同任务的分数合并成一个“质量保持率”。

## 与 KIVI 的关系

KIVI 用观测到的 K/V 统计模式选择不同的标量分组轴，并管理未满组的流式尾部；VecInfer 走向 VQ，依靠变换与 codebook 增强表达能力，并通过 kernel 融合控制运行成本。它们共同揭示：KV cache 量化的算法、缓存更新结构和 attention 内核是一个联合问题。具体哪条路线有价值，取决于模型的 K/V 分布、目标长度和服务 batch；2-bit 标签本身不能回答。
