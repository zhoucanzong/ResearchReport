# 图像生成：从表示与目标到控制和编辑

> 本报告是图像生成方向的学习入口，串联本库已有的扩散模型、DiT、可控生成、图像编辑和模型系列报告。它重点解释不同设计选择怎样影响生成与失败，不重复罗列厂商型号，也不把未公开的产品实现猜成某种架构。

## 1. 先把几个常被混为一谈的问题拆开

看到“扩散、DiT、自回归、多模态统一”这些词时，先问它们各自在描述什么。它们并不处于同一层：**自回归和扩散 / 流匹配主要描述生成目标或分解方式；DiT 描述实现去噪网络的骨干；离散 token、连续 latent 描述图像如何表示；ControlNet、参考图等描述条件从哪里进入。** 一个系统可以同时用语言模型处理文本、用扩散过程生成图像。

| 设计层 | 要问的问题 | 对学习的意义 |
|---|---|---|
| 图像表示 | 模型预测离散图像 token，还是连续像素 / latent？ | 决定生成序列长度、局部细节的表达方式及后续解码路径 |
| 生成目标 | 逐 token 预测，还是从噪声逐步去噪 / 预测向量场？ | 决定生成时的依赖结构、迭代过程和采样方式 |
| 网络骨干 | 去噪器使用 U-Net、Transformer，还是其他结构？ | 说明网络如何处理图像特征；骨干名称本身不说明训练目标 |
| 条件接口 | 文本、布局、边缘、深度、姿态或参考图如何影响生成？ | 解释“能不能照着做”以及控制精度与灵活性如何取舍 |
| 系统编排 | 是否有提示扩写、规划、工具调用或多轮交互？ | 区分模型内部生成机制与围绕模型搭建的产品流程 |

这个拆分能避免一个常见误读：DiT 不是与扩散并列的另一种生成目标。DiT 原论文把 Transformer 用作潜空间扩散模型的去噪骨干；它研究的是“扩散网络能否换成 Transformer，并随计算量扩展”，不是把扩散目标改成逐 token 自回归。[DiT 原文 §3、§5](https://arxiv.org/html/2212.09748)；本库的 [DiT 报告](../DiT/report.md) 详细讲其架构演进。

## 2. 三条路线说明了不同的表示与建模选择

### 离散表示上的自回归生成

早期 DALL-E 先用离散 VAE 把图像压成 token 网格，再把文本与图像 token 拼为序列，使用 Transformer 建模联合分布。模型因而可以沿用语言模型的下一个 token 预测，但必须把图像变成长序列；图像 tokenizer 的压缩与重建质量也会限制最终输出。[DALL-E 原文 §2.1–2.2](https://arxiv.org/html/2102.12092)

Janus 展示了另一种多模态自回归设计：理解和生成使用分开的视觉编码路径，但由同一 Transformer 处理。其图像生成分支仍然自回归地生成离散视觉 token。这个例子说明“共享主干”与“共享视觉表示”并不是同一个选择。[Janus 原文 §3.1–3.3](https://arxiv.org/html/2410.13848)；见 [DeepSeek 系列报告](../../Models/DeepSeek/report.md)。

### 连续表示上的扩散与流匹配

扩散模型学习从噪声恢复数据；潜空间扩散先压缩图像，再在 latent 中生成，以降低直接处理像素的负担。DDPM、DDIM、潜空间扩散和 CFG 建立了基础概念，Flow Matching 则以学习速度场的方式构造生成轨迹。[扩散模型报告](../DiffusionModels/report.md) 重点讲这些目标和采样的关系。

DiT 把常见 U-Net 去噪骨干换成处理 latent patch 的 Transformer。PixArt、MMDiT、FLUX、SANA 等工作又引入不同的训练、跨模态交互、流匹配或计算效率选择。比较它们时，应把“生成目标”“骨干结构”“文本条件注入”和“实验任务”分列；不能只因名称里有 Transformer，就把它们视为同一算法。[DiT 报告](../DiT/report.md)

### 混合式多模态生成

HunyuanImage 3.0 把统一多模态模型描述为自回归框架，但其技术报告进一步区分了文本与图像路径：文本 token 采用自回归预测，图像 latent 采用扩散式预测。这是离散与连续生成目标并存的混合系统，不等于“整张图像由语言模型逐 token 自回归生成”。[技术报告 v3 §3.1](https://arxiv.org/html/2509.23951v3)；见 [Hunyuan 报告](../../Models/Hunyuan/report.md)。

反过来，产品具备“原生图像生成”或多轮编辑能力，也不能据此断定其图像头采用自回归、扩散或混合机制。OpenAI 对 GPT-4o 图像生成公开了图文联合训练、后训练和若干能力 / 限制，但没有披露具体图像生成器结构；应把它留在“系统能力已展示、内部机制未知”这一类。[官方发布](https://openai.com/index/introducing-4o-image-generation/)；见 [OpenAI 生成模型报告 §6](../../Models/OpenAI-Gen/report.md#6-gpt-4o-image-generation-2025原生图像生成与未知实现)。

## 3. 提示遵循不是一个单一能力

“按提示生成”至少包含：提示中对象有没有出现；属性有没有绑定到正确对象；左右、前后等关系是否正确；数量是否符合要求；图中文字是否准确；风格与整体视觉质量是否合意。总体偏好分数、文字识别率或单个对象检测分数，都不能替代其余维度。

DALL-E 3 的研究值得从数据条件而非产品标签来读。它用更详细的合成 caption 训练，并在相同图像数据和同类模型设置下比较 caption 方案；这支持“训练图文配对质量会影响提示遵循”这一有限判断。产品版本还包含放大和其他训练改进，原文没有通过消融隔离所有收益，所以不能把跨代表现全部归因于 caption。论文也报告左右关系和文字渲染仍会失败。[DALL-E 3 原文 §3–5](https://cdn.openai.com/papers/dall-e-3.pdf)；见 [OpenAI 生成模型报告 §5](../../Models/OpenAI-Gen/report.md#5-dall-e-3-2023用详细-caption-改善提示遵循)。

这条证据链对阅读其他模型也有用：先确认作者评测的是对象、关系、计数、文字还是总体偏好，再看任务提示、评判方式和模型版本。某一类能力的演示不能推出“复杂指令已解决”；自动评判的优势是可规模化，不代表它对每种视觉关系都可靠。

## 4. 控制结构与编辑保真是相邻但不同的问题

文本条件提供语义，但对精确几何结构的约束较弱。ControlNet、T2I-Adapter 等方法把边缘、深度、姿态或布局变成额外条件；参考图适配器则试图传递外观或身份信息。这些机制帮助模型遵循特定输入，却带来条件冲突、控制强度和模型迁移等取舍。[可控生成报告](../ControllableGen/report.md)

图像编辑还多一个要求：除了完成指定修改，还要保留无需修改的内容。Prompt-to-Prompt 通过控制交叉注意力来复用原图布局；InstructPix2Pix 把原图和编辑指令作为两个条件，并展示图像相似度与编辑方向相似度之间的权衡。大幅移动或替换物体，本来就要求输出偏离输入；单独最大化整图相似度会惩罚正确编辑。[Prompt-to-Prompt 原文](https://arxiv.org/html/2208.01626) · [InstructPix2Pix 原文 §3–4](https://arxiv.org/html/2211.09800)；见 [图像编辑报告](../ImageEditing/report.md)。

因此评价编辑时至少要拆成两问：**要求的变化是否发生？不应改变的区域是否保留？** 全图 CLIP 相似度、结构相似度或文字偏好各自只覆盖一部分，不能单独证明区域保真。MagicBrush 将单轮、多轮、有 mask 和无 mask 的编辑都纳入数据集，适合用来理解任务为何比单句指令更复杂；其结果不等于所有图像编辑条件的统一排名。[MagicBrush 原文 §3–4](https://arxiv.org/html/2306.10012)；见 [图像编辑报告 §11](../ImageEditing/report.md#11-评测基准)。

## 5. 推荐阅读路线

| 顺序 | 阅读入口 | 带着什么问题读 |
|---|---|---|
| 1 | [扩散模型](../DiffusionModels/report.md)：DDPM、DDIM、潜空间扩散、CFG、Flow Matching | 模型究竟在预测什么？采样器如何改变生成过程？ |
| 2 | [DiT](../DiT/report.md)：U-Net 到 DiT、MMDiT 与流模型 | 改变网络骨干后，训练目标和条件注入哪些不变、哪些改变？ |
| 3 | [OpenAI 生成模型](../../Models/OpenAI-Gen/report.md)、[DeepSeek Janus](../../Models/DeepSeek/report.md)、[GLM CogView](../../Models/GLM/report.md)、[HunyuanImage](../../Models/Hunyuan/report.md) | 离散自回归、扩散与混合路线如何分配理解和生成？哪些实现公开，哪些未知？ |
| 4 | [可控生成](../ControllableGen/report.md)：ControlNet、Adapter、参考图 | 结构约束从哪里进入？控制精度与自然生成如何折衷？ |
| 5 | [图像编辑](../ImageEditing/report.md)：training-free、指令编辑、偏好与评测 | 如何区分目标编辑成功、原图保真和整体观感？ |

这条路线不要求读完每一份模型报告。先建立表示、目标、骨干和条件接口的区分，再挑两条架构路线比较，最后用控制与编辑中的失败案例检验自己的解释。

## 6. 仍值得追问的问题

- 更长、更细的文字描述何时真的改善对象—属性—关系绑定？它是否只是补充了训练 caption 缺失的信息？
- 多模态共享 Transformer 对生成有何帮助？理解与生成是否需要共用视觉表示，还是像 Janus 一样分路更合适？
- 精确计数、左右关系、文字渲染与主体一致性需要不同的表示和训练信号吗？哪些公开评测能把它们区分开？
- 编辑模型能否同时做到“改动足够大”和“未指定区域稳定”？目前的全图指标是否掩盖了局部区域的变化？
- 对内部架构未公开的系统，怎样将可观察到的能力、官方报告的结果与对内部方法的猜测分开？

这些问题比把模型按发布时间排成榜单更能说明路线差异。新论文只有在补充了一个明确机制、评测维度或失败边界时，才值得加入这条学习路线。
