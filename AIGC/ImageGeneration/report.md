# 图像生成：表示、生成目标、条件控制与评测

> 本报告把图像生成作为一条研究问题来读，而不是按厂商列模型。重点是：模型怎样把文字变成可计算的图像表示；生成目标和网络骨干分别决定什么；条件信息如何控制内容；论文如何证明提示被遵循，以及这些评测漏掉了什么。已有机制细读见 [扩散模型](../DiffusionModels/report.md)、[DiT](../DiT/report.md)、[可控生成](../ControllableGen/report.md) 与 [图像编辑](../ImageEditing/report.md) 报告；这里集中解释它们之间的关系。

## 1. 为什么“生成一张图”不是一个单一能力

读者给模型一句话，模型需要同时完成几件不同的事：识别对象和属性，把属性绑定到正确对象，决定对象之间的位置与关系，再生成形状、纹理、光照、风格等视觉细节。若图中还有标牌或海报文字，它还要生成可读字符；若输入包含参考图或编辑指令，则要保留某些特征、改变另一些特征。

所以，“好看”不等于“按要求画对”。一张图可能视觉逼真，但漏掉提示里的第二个对象；也可能对象都出现了，却把颜色绑定错了；也可能构图正确而图中文字拼错。评价“图像生成能力”时，必须先说清楚究竟在评价哪一项。

还有一个常见术语混淆：**图像表示、生成目标、网络骨干、条件接口、产品系统是五个不同层次。** 它们会组合成一个模型或服务，但不能互相替代。

| 层次 | 要问的问题 | 例子 |
|---|---|---|
| 图像表示 | 图像被编码成什么，生成器最终预测什么？ | 离散 VQ / dVAE token；连续像素或 VAE latent |
| 生成目标 | 模型如何定义输出分布？ | 自回归 next-token；扩散去噪；Flow Matching 速度场 |
| 网络骨干 | 用什么网络实现预测器？ | Transformer、U-Net、混合专家骨干 |
| 条件接口 | 什么信号影响生成？ | 文本、CFG、边缘图、深度图、姿态、参考图 |
| 产品系统 | 模型之外还有什么处理？ | 提示扩写、多轮对话、规划、搜索或图像编辑工作流 |

因此，**DiT 不是扩散的替代物**：它是在扩散目标下把常见 U-Net 去噪器换成 Transformer；**GPT‑4o 的原生图像功能也不说明它内部采用自回归或扩散生成头**。后一个例子目前应保留为内部实现未公开。OpenAI 的官方发布描述了训练和展示能力，但没有披露图像生成器的具体结构。[官方发布](https://openai.com/index/introducing-4o-image-generation/)；见 [OpenAI 生成模型报告 §6](../../Models/OpenAI-Gen/report.md#6-gpt-4o-image-generation-2025原生图像生成与未知实现)。

## 2. 图像表示与生成目标：三个基本机制

### 2.1 离散图像 token：把图像变成可预测的序列

**DALL‑E（2021）**的关键问题是：能否沿用语言模型的序列建模能力来做文生图？它分两阶段处理：先训练 dVAE，把图像压成离散视觉码；再把文本 token 与图像 token 拼在一起，让 Transformer 自回归地预测联合序列。[原论文 §2.1–2.2](https://arxiv.org/html/2102.12092)

这个设计把图像生成转化为条件序列预测。若图像 token 为 (z_1,ldots,z_N)，文本为 (y)，自回归模型学习的分解可写成：

\[
p(z_1,\ldots,z_N\mid y)=\prod_{i=1}^{N}p(z_i\mid y,z_{<i})
\]

优势是文本和图像可以处在同一离散序列建模框架中，序列模型也能学习多对象与高层语义组合。代价是图像被压成离散码后，tokenizer 的重建能力成为上限；图像 token 还要逐步生成，空间上的局部错误可能进入后续 token 的条件上下文。原论文将其结果视为大规模自回归图像建模的可行性证据，不能据此说所有图像都更适合被建模成文本式 token 序列。

Janus 又利用了“共享 Transformer、分开视觉编码”的思路：理解路径使用连续语义特征，生成路径使用离散视觉 token；生成仍是自回归。它研究的是理解和生成为什么可能需要不同粒度的视觉表示，而不是把两种任务强行塞进同一个视觉编码器。[Janus 原论文 §3.1–3.3](https://arxiv.org/html/2410.13848)；另见 [DeepSeek 系列报告 §7](../../Models/DeepSeek/report.md#7-多模态生成janus)。

### 2.2 扩散与潜空间扩散：从噪声逐步恢复图像

扩散路线不按图像像素或离散码逐个输出，而是构造一个加噪过程，并训练模型在不同噪声水平上恢复目标。采样时从噪声开始，多次调用去噪网络，逐步得到图像。DDPM 让这条训练—采样路径成为现代生成建模的重要方案；DDIM 改变采样轨迹以减少迭代；Classifier-Free Guidance（CFG）让同一个去噪器同时学习有条件和无条件预测，再在采样时组合两者。[扩散模型报告 §3–5](../DiffusionModels/report.md)

潜空间扩散先用 VAE 把图像压缩，再在较小的 latent 空间运行扩散。这减轻了计算负担，但压缩也可能损失细笔画、极小物体等细节。文生图系统于是把任务拆成两个相互影响的部件：latent 去噪器负责生成，VAE 解码器负责把 latent 还原成像素。

CFG 的简化表达是：

\[
\hat\epsilon=\epsilon_{\text{uncond}}+s(\epsilon_{\text{cond}}-\epsilon_{\text{uncond}})
\]

其中 (s) 放大条件预测相对无条件预测的方向。它是一种**采样时的条件强调**，不是模型获得了额外的空间推理能力。较强引导会改变提示条件与生成分布之间的权衡，不能把“CFG 越大”简单理解为“指令遵循越好”。

### 2.3 DiT 与 Flow Matching：骨干和轨迹不是一回事

DiT 原论文问的是：扩散模型的去噪器能否由 Transformer 实现，并呈现随计算规模增长的改进？论文将 VAE latent 切成 patches，送入 Transformer 去噪；实验主要是 class-conditional ImageNet，不是开放式文生图提示遵循。[DiT 原论文 §3、§4–5](https://arxiv.org/html/2212.09748)

这一区别很关键：论文在 ImageNet 类别条件下观察到的生成质量变化，支撑的是特定任务与训练设定下的架构和计算扩展结论；它本身没有验证复杂自然语言提示、精确计数、文字渲染或图像编辑。要讨论这些能力，需要看采用文本条件的其他论文及其评测。

Flow Matching 改的是连续生成轨迹的学习方式：模型学习数据空间中的速度场，再通过数值积分从起点走到样本。它可以搭配 Transformer，因此常见组合是 **Flow Matching 目标 + Transformer 骨干**。这与“DiT 就是 Flow Matching”或“Transformer 表示自回归”都不是一回事。[Flow Matching / Rectified Flow 机制见扩散模型报告 §3.6](../DiffusionModels/report.md#36-flow-matching-与-rectified-flow20222023)；[DiT 的架构路线见 DiT 报告](../DiT/report.md)。

可以用下面的流程图区分生成过程：

```text
离散自回归：文本 + 前序图像 token → 预测下一个 token → 解码图像
扩散：      初始噪声 → 多步去噪器（文本 / 其他条件）→ VAE 解码
流匹配：    初始状态 → 学习到的速度场 / 轨迹积分 → 图像 latent
DiT：       Transformer 作为扩散去噪器的骨干，可作用于 latent patches
```

### 2.4 混合多模态系统：宏观称谓不能替代模块结构

HunyuanImage 3.0 是一个有解释价值的案例。技术报告把整体描述为自回归的原生多模态模型，但 §3.1 又明确说明：文本 token 使用自回归 next-token prediction，图像 latent 使用 diffusion-based prediction。这是文本与图像采用不同预测机制的混合离散—连续系统，不是纯自回归图像生成。[HunyuanImage 3.0 技术报告 v3 §1、§3.1](https://arxiv.org/html/2509.23951v3)；见 [Hunyuan 报告 §3.3](../../Models/Hunyuan/report.md#33-hunyuanimage-30混合多模态生成架构)。

Janus 则用共享主干、视觉编码分路来协调理解与生成；HunyuanImage 把语言模型和扩散图像生成路径融合进一个多模态系统。两者回答的是不同设计问题，不能因都叫“统一多模态”就归为相同架构。

## 3. 逐篇精读：四种设计决策如何改变生成问题

### 3.1 DALL‑E：离散化让序列模型读懂图像，但也把表示误差带进生成

**研究问题。** 当时的文生图方法多依赖专用生成结构、辅助损失或额外标注。DALL‑E 询问：如果把图像先压成离散视觉码，能否用一个 Transformer 直接建模文本与图像的联合分布？

**方法机制。** 原论文 §2.1 训练 dVAE，把 RGB 图像映射为固定网格的离散码；§2.2 拼接文本与图像序列，训练 Transformer 的自回归 prior。图像编码器 / 解码器与 prior 分开，使“像素细节怎么表示”与“在给定文本时怎么选择图像码”成为两个可以分别研究的部件。

**这个拆分解决了什么。** 在离散码上做 next-token prediction 让生成模型能使用 Transformer 熟悉的序列化接口；dVAE 则把高维像素缩短为更可处理的 token 序列。论文报告该方法在大规模图文数据下具备 zero-shot 文生图能力，并展示模型能组合训练集中未直接出现的概念。[DALL‑E 原论文 §2、§3](https://arxiv.org/html/2102.12092)

**边界。** 结果不能说明 AR 是唯一的规模化路线；tokenizer 对细节的损失、序列长度和自回归生成顺序都是代价。更重要的是，样例里能组合某些概念，不等于它具备稳定的关系推理。GenEval 后来的 object count / position 评测和 T2I-CompBench 对属性绑定的拆分，说明“能组合新概念”和“系统性遵循关系、数量与属性”是不同命题。

**阅读时的关键问题。** 当模型失败时，是语言条件没有表示清楚，视觉 codebook 丢了细节，还是 prior 没学会组合？只看最终图像无法区分这些来源，这也是现代系统需要单独讨论表示、训练目标与评测的原因。

### 3.2 DiT：把去噪器换成 Transformer，不等于解决文本理解

**研究问题。** U-Net 是扩散模型长期使用的骨干。Peebles 与 Xie 探索用 Transformer 处理 VAE latent patches，检查扩散 Transformer 的计算量、深度、宽度和 patch 数量如何影响受控生成质量。[DiT 原论文](https://arxiv.org/html/2212.09748)

**方法机制。** 输入是带噪 latent；模型把 latent 切成 patch token，在 Transformer 中结合时间步与类别条件，输出用于扩散预测的量。patch 越小，token 序列越长，空间细节分辨率和注意力计算负担都会改变。关键是：网络输出仍参与扩散反向过程，Transformer 没有把模型改成逐 token 自回归图像生成。

**论文支持什么。** 原论文的规模实验围绕 ImageNet class-conditional 任务，使用 FID 等图像分布指标观察模型计算复杂度增加时的变化。它支撑“Transformer 可作为扩散骨干，并在该 class-conditional 设定下扩展”的结论；不能直接支撑开放词汇 prompt-following、编辑保真或文本正确率的结论。

**设计取舍。** Transformer 让统一的 token 处理与计算扩展研究更直接，但图像空间关系需要模型从 patch 序列中学习。分辨率、patch 尺寸、latent 压缩和注意力复杂度会一起改变计算压力。另一方面，U-Net 的局部卷积与多尺度结构提供了不同的空间归纳偏置。架构比较需要同时看任务和条件形式，不能把一张 class-conditional ImageNet 表格当作所有文生图质量的排名。

**与后续工作的关系。** PixArt 更重视分阶段训练和文本编码，MMDiT 让文本与图像 token 进行更直接交互，FLUX 将 Transformer 与 Flow Matching 组合，SANA 关注高效注意力与压缩。它们不是“一个新骨干解决一切”，而是在不同计算预算、条件接口和质量目标下调整系统设计。[DiT 报告](../DiT/report.md) 已收录这些路线，重点阅读各自改变的模块和评测设置。

### 3.3 DALL‑E 3：caption 改进的是条件数据，不应被误读为架构突破

**研究问题。** 许多提示无法准确落在训练 caption 上：提示写得很细，图文训练对可能只有很短的描述。DALL‑E 3 工作研究能否用更详细的合成 caption，增强模型学习对象、属性和关系的条件信号。

**机制。** 论文区分训练期的图像重标与推理期的 prompt upsampling。训练期先用专门的图像描述模型为图像生成详细 caption，再与原始 caption 混合训练；推理期则可把用户简短提示改写成更完整文本。二者都增加条件信息，但发生在不同阶段，也不能概括成“用 GPT‑4V 重写全部训练数据”。

**证据。** 论文 §3.2–3.4 的受控 caption 实验在相同图像数据与相同类别的 T5-conditioned 模型设置下比较 caption 类型和混合比例，因而较有针对性地支持“caption 质量能影响提示遵循”。产品版本在 §4 还包含放大和其他训练改动；原文说明多项变化没有单独消融，所以不能把 DALL‑E 3 相对 DALL‑E 2 的全部收益归因于 caption。[DALL‑E 3 原论文](https://cdn.openai.com/papers/dall-e-3.pdf)；已整理的条件和边界见 [OpenAI 生成模型报告 §5](../../Models/OpenAI-Gen/report.md#5-dall-e-3-2023用详细-caption-改善提示遵循)。

**反例与边界。** 原文指出复杂空间关系、漏字 / 多字等仍有问题；报告还记录自动 GPT-V 评判在计数任务上不可靠，因此另有人评复查。由此可见，caption 数据改善不能消除生成器对结构关系的困难，也不能用一个自动总分替代不同提示维度。

### 3.4 HunyuanImage 与 Janus：统一系统也可以有不同生成模块

Janus 的核心决策是理解和生成分开编码、共享 Transformer 处理；图像生成路径使用离散视觉 token 的自回归建模。HunyuanImage 3.0 则以语言模型为多模态骨干，文本 token 自回归，图像 latent 用扩散式预测。前者展示“共享主干、分路视觉编码”，后者展示“共享多模态框架、不同模态采用不同生成目标”。[Janus §3](https://arxiv.org/html/2410.13848) · [HunyuanImage §3.1](https://arxiv.org/html/2509.23951v3)

这两个案例能纠正“统一模型必须所有模态都用一种 tokenizer / 一种生成目标”的直觉。统一可能发生在交互接口、主干网络、训练流程或任务系统层；判断真正共用到哪一层，需要读架构图、训练目标和推理路径，而非从产品名称推测。

## 4. 提示遵循：从“像不像”转向“每项条件有没有实现”

### 4.1 组合性提示由多种可分离要求组成

例如“左边有一只蓝色猫，右边有两只黄色狗，墙上写着 OPEN”至少包含对象出现、颜色绑定、数量、空间关系和文字渲染五项要求。模型可以满足四项、漏掉一项；一个总体视觉偏好判断可能掩盖这个错误。

T2I-CompBench 从属性绑定、物体关系、数量和复杂组合评测提示组合性；GenEval 则把对象共现、位置、数量和颜色拆成对象级检查。它们的共同价值是把“prompt adherence”拆小，观察模型在哪里失败，而不是仅评一张图总体是否美观。[T2I-CompBench++ 原文](https://arxiv.org/html/2307.06350) · [GenEval 原文](https://arxiv.org/html/2310.11513)

GenEval 用检测器和属性分类组件评分，可检查物体数量、位置、颜色等；但作者也指出，检测器的类别集合与粒度会限制可验证的内容，不能检查任意细粒度属性。T2I-CompBench++ 用不同方法评测不同能力：属性绑定依赖 VQA 询问，空间关系 / 数量用检测器，复杂组合尝试 MLLM 评估。论文分析了 MLLM 在空间和数量判断上的局限，因此 MLLM-as-judge 不是天然可靠的总裁判。

### 4.2 文字渲染需要专门表示与监督

在图像里画文字，不只是“图像里有一块像文字的纹理”。字符序列必须正确，字形位置和行布局必须匹配视觉空间，文字与背景还要融合。TextDiffuser 将任务拆成两步：先由 Transformer 生成关键词布局，再用扩散模型根据提示和布局生成图像；其数据集 MARIO-10M 使用 OCR 与字符级标注，MARIO-Eval 面向文字渲染评测。[TextDiffuser 原文 §3–5](https://arxiv.org/html/2305.10855)

它的失败分析很有教学价值：VAE latent 压缩可能损伤小字符笔画；包含很多关键词的长文本可能让布局重叠。于是“扩散模型能不能渲染文字”不是单纯加大 backbone 的问题，还涉及训练数据是否有 OCR / 字符级监督、布局是否显式表达、VAE 是否保留足够细节，以及评测是否真的读字。

### 4.3 不同评测回答不同问题

| 评测方法 | 更适合回答 | 主要盲区 |
|---|---|---|
| FID 一类分布指标 | 一批生成图整体分布是否接近参考集 | 看不出单条提示里的对象和关系是否正确 |
| CLIPScore / 图文相似度 | 图像整体语义是否与文本相近 | 可能漏掉计数、空间关系或属性错绑 |
| 检测器 / 属性分类器 | 特定对象、位置、数量或颜色是否出现 | 受检测器类别和粒度限制，无法覆盖开放世界所有概念 |
| OCR 与文字基准 | 字符识别、布局或文字生成是否正确 | OCR 成绩不等于设计质量或全图语义遵循 |
| 人类偏好 | 人更偏好哪一张，整体可用性如何 | 偏好会混合审美、指令遵循、文字可读性等因素，不一定揭示失败机制 |
| MLLM 评判 | 开放式语义解释和复杂场景判断 | 自身在计数、左右关系和视觉细节上可能犯错 |

所以引用结果时要说明任务、提示集、模型版本、评判者和评分维度。GenEval 的优势是对象级分析，局限来自检测器；T2I-CompBench++ 细分组合关系，但依赖不同评估器；TextDiffuser 的 OCR 专项更适合文字问题。它们互补，不能折算成单一“图像理解分”。

## 5. 条件控制：文字、结构图和参考图提供不同信息

CFG 在已有条件方向上加大采样时的推动力，不会自动提供像素级布局。若用户明确要求人物姿态、深度或边缘结构，ControlNet 在冻结预训练主干之外增加可训练分支，并通过零初始化卷积接入，使结构条件能逐步影响既有去噪网络。[ControlNet 原文 §3–4](https://arxiv.org/html/2302.05543)

这个设计解决“空间条件怎样安全接到强大但已经训练好的扩散模型上”的问题。论文展示边缘、深度、姿态、分割等不同控制输入，也考察提示缺失或与控制图冲突的情形。它的学习点不是“ControlNet 让模型懂物理”，而是结构化控制图提供了比自然语言更明确的空间信息；条件图本身不保证语义、审美和文本约束都同时正确。

IP-Adapter 处理另一类问题：如何让参考图表达外观、风格或主体信息，同时保留文字提示。它将文本 cross-attention 与图像 cross-attention 分开，冻结原扩散模型，只训练增加的图像条件模块；原文指出，把图像与文本特征直接拼接到原注意力层可能遗漏图像特有的信息。[IP-Adapter 原文 §3.2–4.4](https://arxiv.org/html/2308.06721)

| 条件方式 | 强项 | 代价 / 需要继续确认的事 |
|---|---|---|
| 文本提示 | 灵活表达语义和风格 | 复杂几何、精确布局难以仅靠文字稳定指定 |
| CFG | 调整对已有文本条件的采样响应 | 改变条件强度，不新增显式结构信息 |
| ControlNet / T2I-Adapter | 边缘、深度、姿态等空间条件 | 条件预处理、训练数据与多条件冲突影响结果 |
| IP-Adapter / 参考图 | 外观、风格、主体参照 | 全局图像 embedding 可能忽略细粒度区域；相似度不等同于身份精确保持 |
| LoRA / 个性化微调 | 让模型吸收角色、风格或概念 | 这是改变模型参数的适配，与单次提示条件不是同一控制机制 |

更好的控制接口会减少用户反复试提示，但会把问题转移到条件设计、条件冲突和保真评价上。具体机制可继续读 [可控生成报告 §3–5](../ControllableGen/report.md)。

## 6. 编辑是带约束的生成：改动强度与输入保留相互牵制

生成任务从噪声出发，编辑任务从已有图像出发。编辑必须同时回答两件事：目标改动是否发生，其他内容是否保持。两者不是同一个指标，甚至可能相互冲突：把车从图左移到图右，输出就不应与输入完全相似。

Prompt-to-Prompt 通过替换 / 控制跨注意力中的 token 关系，尝试在改提示时复用原生成布局；它证明了在特定扩散模型与提示变换下，注意力图可以成为干预点，但不能推出所有编辑都可由注意力注入稳定完成。[Prompt-to-Prompt 原文](https://arxiv.org/html/2208.01626)

InstructPix2Pix 把原图与自然语言编辑指令作为两种条件，训练一个前向编辑模型，并在推理时分别调节原图一致性和文本编辑强度。论文直接讨论了两种相似度目标的竞争：编辑幅度更大时，输出往往会偏离输入图像；过分保留输入则会变成“几乎不编辑”。[InstructPix2Pix 原文 §3.2、§4.2](https://arxiv.org/html/2211.09800)

MagicBrush 提供人工标注的真实图编辑样例，覆盖单轮、多轮、有 mask 与无 mask 情形，并报告自动与人类评价。它把编辑研究从模型能否按合成指令改图，推向更接近真实用户的多轮与区域编辑需求。[MagicBrush 原文 §3–4](https://arxiv.org/html/2306.10012)

因此，编辑评价最好分三层：

1. **变化是否到位**：物体、属性或布局是否按要求变化？
2. **未编辑区域是否保留**：脸部身份、背景、文字和结构是否意外改变？
3. **边界是否自然**：编辑区域与周边是否出现拼接、光照或纹理断裂？

全图 CLIP 相似度、DINO 特征或像素 L1 / L2 只反映部分维度。除非能区分编辑区和保留区，否则不能单独作为“未修改部分保持不变”的证据。现有 [图像编辑报告](../ImageEditing/report.md) 汇总了训练式、免训练式、偏好对齐与编辑基准，读者可以把这里的三层问题用作阅读线索。

## 7. 跨论文串联：能力由多环节共同形成

把上述工作连起来，可以得到一条比“模型越大越好”更具体的因果链：

```text
训练图文对与视觉编码
        ↓
文本 / 布局 / 参考图提供哪些条件
        ↓
表示方式与生成目标如何承接条件
        ↓
骨干、采样器和控制模块怎样把条件写入图像
        ↓
评测是否能发现漏对象、错属性、文字错误与保真损失
```

DALL‑E 3 展示训练 caption 质量会影响文本条件；ControlNet 表明结构图可补充文字难以精确表达的空间条件；TextDiffuser 展示文字渲染可能需要布局建模和字符级数据；编辑论文表明保留原图与完成改动之间需要显式权衡。它们分别落在数据、条件、表示、评测和编辑约束，不是单一架构升级的不同名字。

这条链也给出诊断顺序：如果颜色属性绑错，先问提示和数据是否清楚分离对象—属性；如果空间布局错，再看提示是否有结构条件；若大字正确、小字失败，检查 VAE 压缩和字符监督；若编辑后主体外观变了，区分参考图编码的粒度、编辑强度与局部保留指标。每个症状都可能有多个来源，不能未经实验就归到某一个模块。

## 8. 推荐精读顺序

| 顺序 | 精读入口 | 阅读时抓住的研究问题 |
|---|---|---|
| 1 | [DALL‑E 原论文](https://arxiv.org/html/2102.12092)，§2.1–2.2、§3.3 | 离散图像 code 怎样变成文本条件序列？组合能力从哪些示例观察出来？ |
| 2 | [DDPM / 潜空间扩散 / Flow Matching](../DiffusionModels/report.md) | 从噪声恢复和在 latent 生成分别改变了什么？采样步骤承担什么工作？ |
| 3 | [DiT 原论文](https://arxiv.org/html/2212.09748)，§3–5；[本库 DiT 报告](../DiT/report.md) | Transformer 改的是去噪骨干还是生成目标？原论文任务能支持哪些结论？ |
| 4 | [DALL‑E 3 原论文](https://cdn.openai.com/papers/dall-e-3.pdf)，§3–5 | 训练 caption 与推理时提示扩写如何区分？受控实验和产品差异在哪里？ |
| 5 | [GenEval](https://arxiv.org/html/2310.11513)、[T2I-CompBench++](https://arxiv.org/html/2307.06350)、[TextDiffuser](https://arxiv.org/html/2305.10855) | 对象、关系、数量和文字渲染分别需要怎样的基准？自动评测依赖什么模型？ |
| 6 | [ControlNet](https://arxiv.org/html/2302.05543)、[IP-Adapter](https://arxiv.org/html/2308.06721) | 结构条件和参考图条件分别通过哪个模块进入生成过程？ |
| 7 | [Prompt-to-Prompt](https://arxiv.org/html/2208.01626)、[InstructPix2Pix](https://arxiv.org/html/2211.09800)、[MagicBrush](https://arxiv.org/html/2306.10012) | 编辑方法如何修改图像，同时衡量目标变化与未修改区域？ |

OpenAI、Google、Hunyuan、Janus 等模型系列材料放在上述机制之后阅读：先知道要核对的是表示、目标、条件还是系统编排，再判断官方披露能支持什么。模型页面给出的“原生图像生成”“多轮编辑”等能力描述，不会自动揭示内部网络结构。

## 9. 仍开放的研究问题

- **构图能否被更直接地监督？** 布局图、对象关系图或可执行场景结构，能否减少只靠文本的关系错绑？结构控制会不会牺牲自然变化与生成多样性？
- **小字和长文字应该如何建模？** 是提高 VAE 细节保真、把 OCR / 字形作为独立 token、先生成布局，还是由渲染器与生成器分工？这些方案解决的是不同环节。
- **组合性评测如何覆盖开放世界？** 检测器有有限类别，VQA / MLLM 评判会自身误判；如何把可自动复查的实例级任务和有代表性的人工评价结合？
- **编辑保真应该落在什么粒度？** 整图相似度、对象身份、区域外像素、几何结构和文字位置并不等价。新的编辑基准应明确允许改变什么、要求保留什么。
- **理解与生成共享哪些表示才有益？** Janus 与 HunyuanImage 的设计分别让我们看到视觉编码分路与混合生成目标；共享表征何时促进对齐，何时因任务目标不同而冲突？
- **闭源系统如何进入可比研究？** 对 GPT‑4o、Nano Banana 等实现未披露的模型，仍可研究可观察的提示和编辑行为，但需要公开提示、版本、条件、样本与评判协议，不能由结果倒推网络架构。

这些问题将图像生成从“哪家模型更强”转回研究本身：图像怎样表示，条件怎样传入，目标怎样优化，失败如何被测量，以及用户要求变化时哪些内容应该保持稳定。
