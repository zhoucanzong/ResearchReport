# 视频生成：从图像先验到时空建模

> 视频生成不是“逐帧生成几张图再拼起来”。模型需要同时决定画面内容、物体如何运动、镜头如何变化，以及这些因素在时间上怎样保持一致。研究主线是表示与架构如何处理空间/时间压缩、条件注入、长序列建模，以及不同评测能说明什么。闭源模型没有公开的架构细节统一标为未知；产品演示和版本功能不作为内部机制证据。

跨媒介学习顺序见 [AIGC 学习地图](../../docs/aigc-learning-path.md)；本篇聚焦视频的时空状态与长程一致性，音频生成和数字人中的音画同步是相关但不同的评价问题。

## 阅读路线

1. 先读 **表示与问题地图**，理解一段视频被模型表示成什么。
2. 读 **Make-A-Video、Imagen Video**，看如何借助图像扩散能力并以级联模型补时间与分辨率。
3. 读 **Stable Video Diffusion**，看潜空间、时序层和数据阶段如何一起影响视频模型。
4. 读 **Sora、CogVideoX、HunyuanVideo、Wan**，比较时空 patch、3D VAE、跨模态 Transformer、因果缓存和数据训练的不同取舍。
5. 接着读 **Context Forcing 与 Stream4D**，分别理解长上下文监督失配、几何一致性奖励抑制运动这两种长视频失效机制；再看 **A²RD** 作为由模型、记忆和自我修订组成的外层视频创作系统。
6. 最后看 **VBench 与长时程边界**，辨析帧质量、运动、语义、主体持续和物理规律不是同一个评测问题。

## 1. 视频生成到底需要同时解决什么

给定文本、首帧/参考图、已有片段或它们的组合，模型要生成随时间变化的图像序列。文本到视频（T2V）需要把语言中的主体、动作、场景和关系落到像素；图像到视频（I2V）还要让首帧身份/构图持续，同时补出运动；视频编辑与延长（V2V/continuation）既要遵循新条件，也要保留未修改内容。

相邻帧看起来相似不等于视频一致。一个人可能每一帧都清晰，但衣服、脸型或手里的物体持续变样；一个物体也可能逐帧真实，却在运动方向上违反惯性或穿过其他物体。视频生成至少有以下彼此相关但不等价的目标：

| 目标 | 要回答的问题 | 常见失败 |
|---|---|---|
| 空间画质 | 单帧细节、颜色、构图是否可信 | 模糊、纹理融化、文字不可读 |
| 短时运动 | 动作和镜头是否连续、自然 | 抖动、闪烁、运动突变 |
| 主体/物体一致 | 同一对象在时间中是否保持身份、形状和属性 | 人物/物体换脸、衣物变化、物体消失或复制 |
| 条件遵循 | 生成对象、动作、顺序、位置是否符合文字/图像条件 | 漏掉对象、动作执行错误、关系颠倒 |
| 长时程结构 | 多秒至更长视频是否持续发展而非循环/漂移 | 动作重复、场景跳变、身份累积漂移 |
| 物理/因果连贯 | 接触、遮挡、物体状态变化是否合理 | 穿模、抓取失败、物体状态无因改变 |

因此，“视频像真”不等于“视频理解了物理规律”。研究结论应说明它支持的是哪一类目标、在哪些提示、长度、分辨率和评价协议下得到。

## 2. 表示方式决定时空建模的成本与上限

### 2.1 从帧序列到压缩潜变量

一段视频的直接表示可写成时间、通道、高度、宽度四维张量。若在像素空间直接扩散，随着帧数和分辨率上升，计算与显存很快变得不可接受。大多数现代路线先用视频 VAE 把帧压到较低空间分辨率，通常也会在时间维度压缩，再在潜变量上执行生成。

视频 VAE 不是透明的前处理。若时间压缩过强，细小动作、唇动、快速接触和高频边界可能被丢掉；若压缩不足，生成器必须处理过长序列。VAE 解码质量也会形成清晰度上限。CogVideoX、HunyuanVideo 和 Wan 都把时空 VAE 作为主要设计部分，分别强调时空压缩/连续性、统一图像视频预训练和因果分块编码等问题。[CogVideoX §2.1；HunyuanVideo §4.1；Wan §4.1](https://arxiv.org/html/2408.06072v3)

### 2.2 空间 patch 与时空 token

Transformer 需要把连续 latent 转成 token 序列。只按每帧空间 patch 化，再把帧按时间串接，得到的是长序列；直接使用时空 3D patch，可把一个 token 对应到一小块时间—空间体素。二者都要回答：哪些 patch 彼此做注意力、如何编码时间/空间坐标、不同长宽比和时长如何共享位置编码。

全时空注意力可直接连接任意时间和位置，但 token 数增长时，计算大致按序列长度平方增加；空间—时间分解或局部窗口能降低成本，却会限制跨远距离帧的信息交换。模型使用 Transformer，不代表它必然对每一个时空 token 做全局注意力；注意力分块、掩码、窗口和潜空间分辨率才共同决定建模范围。

### 2.3 生成方式：整段去噪、因果续写或两者结合

整段扩散从噪声 latent 开始，多轮更新一段视频，可在去噪时同时利用前后时间上下文；代价是采样迭代多，长序列仍贵。因果/流式路线按时间块向前生成，可缓存过去上下文、边生成边输出，却不能像双向整段去噪那样自由使用未来帧信息。分块生成还会遇到边界处人物身份、动作和镜头如何延续的问题。

这些是设计空间，不应当被简化成“因果模型更适合长视频、双向模型质量一定更好”。具体权衡取决于训练方式、潜空间、可用上下文、采样策略和评测长度。Wan 的流式系统使用滑窗去噪与历史 token 缓存解决计算/连续性问题，同时作者仍报告大幅运动的细节保持和推理成本有局限。[Wan §5.6、§6；arXiv v2](https://arxiv.org/html/2503.20314v2)

## 3. 早期路线：图像生成能力与视频时间模块分工

### 3.1 Make-A-Video：从文本图像学“画什么”，从无标注视频学“怎么动”

视频—文本配对数据比图像—文本配对数据难获得。Make-A-Video 的核心拆分是：文本图像模型提供语言—画面语义先验，未配文字的视频提供运动学习信号，再以时空因子化模块把两者接起来。论文不是用一个从头训练的完整 3D 模型，而是在已有 T2I 扩散骨干中加入 pseudo-3D 时空卷积/注意力；空间和时间方向采用分解近似以控制成本。随后通过空间超分、帧插值和时空解码提升画面大小与帧率。[原文 §3.1–3.4；Make-A-Video arXiv v1](https://arxiv.org/html/2209.14792v1)

这项设计把数据缺口变成架构问题：文字和静态图像提供“物体长什么样、怎样描述”，视频数据提供“画面如何随时间变化”。实验报告在论文自建的 300 条文本提示上进行人工评估，也比较文本对齐和视觉质量。级联解码能渐进提升分辨率和时间采样，但每个阶段都可能累积误差，插帧也只补中间画面，并不自动修复不合理的物理运动或人物身份漂移。[原文 §3–4](https://arxiv.org/html/2209.14792v1)

### 3.2 Imagen Video：空间超分与时间超分分别解决什么

Imagen Video 将视频生成组织为一组交替的基础生成、空间超分辨率和时间超分辨率模型：低分辨率基础模型先生成内容，空间 SR 增加画面细节，时间 SR 提高帧率。论文研究了 v-prediction、条件增强、图像/视频联合训练和 classifier-free guidance 蒸馏。与 Make-A-Video 一样，它以级联阶段管理计算；不同点在于系统地研究了空间/时间分辨率递进和更快采样。[原文 §2.2–2.7；Imagen Video arXiv v1](https://arxiv.org/html/2210.02303v1)

论文展示的高分辨率示例来自指定的模型链与短时视频设置。级联的强项是把不同分辨率任务拆开训练；局限是生成路径长，基础运动、超分和插帧误差可能相互影响，且高帧率/高像素数本身并不证明时序关系正确。将这条路线概括为“各帧独立生成再插帧”会遗漏它明确的时空扩散模块和视频级训练设计。

## 4. 潜空间视频扩散：图像先验如何接入时间

### 4.1 Stable Video Diffusion：模型架构与数据阶段一起缩放

Stable Video Diffusion（SVD）将图像 latent diffusion 扩展到视频：在 U-Net 的空间层后插入时间卷积与时间注意力，再对整个模型用视频数据微调。与“冻结空间层、只训练时间层”的极简迁移方式不同，论文对比并采用完整模型微调。它的贡献不只是增加 temporal layer，而是提出三阶段数据与训练路径：图像预训练、视频预训练、高质量视频微调；并系统清理和标注训练视频。[原文 §1–4、附录 A–C；SVD arXiv v1](https://arxiv.org/html/2311.15127v1)

这个路线说明视频能力依赖时空模型和数据质量。图像预训练补空间语义和细节，视频预训练提供运动先验，高质量微调再改善生成观感；如果视频数据质量、镜头切分或文本标注不一致，单纯增加参数未必能补上。SVD 论文还展示了图像到视频、帧插值、相机运动适配与多视角微调等下游用途，因此它的主要证据面向图像条件视频生成及表示迁移，不应只按 T2V 排名来理解。[原文 §3–4](https://arxiv.org/html/2311.15127v1)

这三个训练阶段不是同一数据反复“加量”：Stage I 从文本图像模型初始化空间生成先验，Stage II 用大规模视频教时间变化，Stage III 在较小的高质量视频子集上高分辨率微调。论文通过相同微调步数、不同初始化进行对照，比较跳过视频预训练与分别用经过筛选/未筛选视频预训练的差别；由此作者认为视频数据阶段对最终人类偏好和运动表示有独立贡献。该消融支持的是论文所用数据和 50K-step 微调设置下的训练路径，不应外推为固定的通用训练配方。[原文 §3.2–3.4、§4.2](https://arxiv.org/html/2311.15127v1)

SVD 的视频生成能力来自给图像骨干加时间建模，但这仍不等于完整世界状态建模。它能提供有用运动先验，也可在相机运动 LoRA 等特定数据上适配；长时程身份保持、复杂交互和精确事件顺序仍需专门的训练目标与测试。

### 4.2 Sora：公开的是表示方向和能力边界，不是完整架构图

OpenAI 2024 年技术说明公开了一个关键事实：Sora 在图像/视频 latent code 的时空 patch 上使用 Transformer，并在不同持续时间、分辨率、长宽比的视频与图像上联合训练；官方还解释了如何将视觉数据转成统一表示。公开报告没有给出可复现的完整网络图、latent 压缩率、全部训练细节或足以断言具体注意力实现的数据。[官方技术报告“Approach”](https://openai.com/index/video-generation-models-as-world-simulators/)

因此，Sora 可以作为“时空 patch + Transformer + 多规格视觉数据联合训练”的路线证据，不能把外部推测的 VAE 结构、参数量、因果掩码、精确采样器或产品输出时长写成官方架构事实。OpenAI 的报告也明确列出模拟器局限：玻璃破碎等基础交互、进食后的物体状态变化可能不准确；长片段会不连贯，物体会凭空出现。该自我评估把“看起来可信”与“持续遵守物理/状态规律”分开，为世界模拟主张划定了边界。[官方技术报告“Discussion”](https://openai.com/index/video-generation-models-as-world-simulators/)

## 5. 时空 DiT 的具体分歧：潜变量、文本融合和训练流程

### 5.1 CogVideoX：3D 因果 VAE + 专家 Transformer + 渐进式训练

CogVideoX 将视频以 3D causal VAE 同时压缩空间和时间。作者指出，时空压缩减少后续序列长度并有助于避免帧闪烁；Transformer 将文本和视频 token 一起输入，但两种模态的数值尺度和表示空间不同，于是用视觉、文本各自的 expert adaptive LayerNorm 处理不同特征，再用 3D RoPE 表示时间、高度、宽度位置，并做时空全注意力。[原文 §2.1–2.2；CogVideoX arXiv v3](https://arxiv.org/html/2408.06072v3)

该 VAE 的取舍可以从论文消融看到：作者比较不同空间/时间下采样率、latent 通道数和重建/闪烁指标，最后用空间 8×、时间 4×压缩且 16 个 latent channel 的一种配置进行预训练。时空 full attention 让视频和文本 token 可直接交互，Expert AdaLN 为视觉与文本分别计算条件调制，避免简单地假定两种 token 的特征尺度相同。论文的主模型报告 5B 与 2B 两个规模，生成尺寸/长度上限来自相应模型和实验设置；这组设计并不等于它已拥有任意分辨率或无限长度能力。[原文 §2.1–2.2、表 1、§3–4](https://arxiv.org/html/2408.06072v3)

训练流程也服务于长时程：multi-resolution frame pack 让同一训练中包含不同长度/分辨率片段，渐进式从较低像素训练到更高分辨率，显式均匀时间采样避免只偏向视频开头或某些位置。论文摘要中的 10 秒、16 fps、768×1360 是特定模型和实验配置报告，不能直接与分辨率、帧率、采样步数或基准不同的论文做单指标排名。[原文 §3.1–3.4、§4.2；v3](https://arxiv.org/html/2408.06072v3)

### 5.2 HunyuanVideo：文本/视频先各自建模，再联合交互

HunyuanVideo 采用统一图像—视频生成框架与 3D VAE，并将 3D 时空位置编码用于视频 token。其 MMDiT 风格结构采取“dual-stream → single-stream”：先让文字和视觉 token 经过各自的 Transformer block，减少早期异构特征相互干扰；之后进入共同序列进行跨模态交互。模型采用统一 full-attention 处理时空视觉 token，而文本侧使用经过视觉指令微调的 decoder-only 多模态语言模型表示复杂描述，并结合 CLIP 全局文本信息。[原文 §4.1–4.5；HunyuanVideo arXiv v1](https://arxiv.org/html/2412.03603v1)

这与 CogVideoX 的专家归一化方案构成有教育价值的比较：前者在 Transformer 层级先分流再融合，后者在共用架构中保留不同模态的归一化专家。它们都试图处理文本 token 与视频 latent 的分布差异，却不是同一套“通用双流架构”。HunyuanVideo 报告的人工比较覆盖 1,500 多个文本提示，由 60 名评估者进行；模型约 13B 参数，训练还包含逐步提高分辨率的数据过滤与人工标注微调。该结果属于作者设定的模型、提示与受试者协议，不可与其他论文异构人评分数视为统一竞赛排名。[原文 §1、§3、§4、§6；HunyuanVideo arXiv v1](https://arxiv.org/html/2412.03603v1)

### 5.3 Wan：时空 VAE 缓存与流式生成把“长”拆成可处理的块

Wan 2025 报告提出时空 VAE、DiT 基础模型和较完整的训练/评测路线。VAE 使用因果时间卷积，逐块编码/解码时把前一块末端特征缓存给后续块，维持 chunk 边界处的局部连续；在 DiT 上则探索流式视频生成，采用滑窗去噪、有限时间窗口和历史 token 缓存，降低长序列注意力开销。论文把“长视频可扩展”拆为潜空间因果编码、窗口内去噪、缓存上下文和蒸馏/加速等具体工程问题。[原文 §4.1、§5.6；Wan arXiv v2](https://arxiv.org/html/2503.20314v2)

但滑窗可以减轻计算，不自动等于语义上无限连贯。窗口有限意味着模型对遥远历史的直接可见范围受限；缓存可传递局部特征，却不必然保留整个剧情、人物状态或物体位置。Wan 作者也把大运动下的细节维持和大模型推理成本列为限制。对“任意长度”的表述应限定为流式生成机制可以继续追加窗口，而不是保证持续时间越长仍不漂移。[原文 §5.6、§6](https://arxiv.org/html/2503.20314v2)

Wan 报告里的实时数字指的是建立在预训练模型上的额外 streaming pipeline，而不是基础 14B 扩散模型在任意硬件上自然达到实时。论文展示 15 分钟视频在 8 张 A100 上以 8 FPS 生成，也展示经过 INT8 与 TensorRT 优化后单张 RTX 4090 以 20 FPS 生成；这些速度依赖额外流式训练、量化、编译和硬件设置。作者同时指出大运动细节与整体推理成本仍是限制，说明系统吞吐、模型长时连贯性和物理状态持续应当分别验证。[原文 §5.6、§6](https://arxiv.org/html/2503.20314v2)

## 6. 长视频一致性：监督上下文、几何奖励与外层记忆

流式自回归视频把整段去噪拆成连续片段，降低了单次生成成本，却让前面生成的误差成为后续条件。只扩大 KV 窗口不能保证模型学会使用更长历史；只加“3D 一致性奖励”也可能奖励静止画面。2026 年几篇工作把这两个问题分别变成**训练监督、奖励目标和系统编排**问题，展示的是互补路线，不是同一模型架构的三个版本。

### 6.1 Context Forcing：让教师也看到学生要学的长历史

[Context Forcing](papers/2602.06028-context-forcing.md) 关注流式蒸馏中的监督失配：学生用自身生成的历史做长程 rollout，但传统教师只看短窗口，无法评价长距离主体状态和事件关系。作者先做短窗口分布匹配以稳定局部生成，再让一个长上下文 teacher 在学生生成的上下文上监督未来片段；同时用逐渐增长的 rollout horizon、带残差扰动的 teacher 微调和 slow/fast KV memory 处理误差累积与缓存冗余。

这解释了一个重要边界：**上下文容量是模型可见的历史长度，长程一致性还取决于训练时的监督是否覆盖这种历史。** 论文使用 Wan2.1-T2V-1.3B 做教师/学生，报告其上下文可扩到 20 秒以上，并评估 60 秒生成；这些结论来自该模型、VidProM / VBench 等数据与协议，不是对任意流式骨干或分钟级生成的保证。Slow memory 以相邻 key 相似度筛选历史 token，隐含“相似代表冗余”的假设；若长期状态变化幅度小但语义关键，或相似画面包含不可丢的事件状态，仍可能被压掉。

### 6.2 Stream4D：一致性奖励不能把“没有运动”误当作好几何

[Stream4D](papers/2608.19556-stream4d.md) 发现静态 3D Gaussian Splatting 重建器不表达场景动态：真实物体运动会被当作重建误差，优化器可能通过冻结物体来提高重建分数。作者把评分器改为带时间变化的 4D Gaussian 表示，再组合重建一致性、自然运动强度/平滑度/刚性质量和感知锚点，训练已经蒸馏的自回归视频骨干。

论文在 Self-Forcing、Causal-Forcing 和 LongLive 三种骨干上做了对照，采用 5 秒或 10.3 秒生成设置，并构造 500 条强调物体运动的提示。作者报告 4D 重建和运动保留指标有所改善；这支持“几何奖励必须允许真实动态”的机制判断，不证明 4D-GS reward 等于物理正确性。其结果依赖 MoVieS 重建器、motion prior、提示筛选和 judge 协议；补充实验显示在未筛选提示上，单一重建分数仍会被静态画面取巧，必须同时评价运动与一致性。[Stream4D v1 §2–4、Appendix G](https://arxiv.org/html/2608.19556v1)

### 6.3 A²RD：外层记忆编排与生成器内部长上下文不同

[A²RD](https://arxiv.org/html/2605.06924v1) 将故事拆成片段，以多模态视频记忆、片段生成模式选择和边界帧/视频段自我修订形成 Retrieve–Synthesize–Refine–Update 循环。它适合说明长视频创作还能在**生成器之外**做记忆与规划：场景需要推进时偏向外推，已知状态需要保持时可使用参考帧和插值。它与 Context Forcing 的长上下文 teacher/student 训练、Stream4D 的生成器奖励优化处在不同层。

这种分工与[智能体系统](../../Agents/AgentSystems/report.md)中的计划—执行—检查循环相邻，但此处任务对象是视频片段和媒体状态；不能因使用 MLLM 评审和工具调用，就把视频生成器的内部机制归结为通用 Agent。

这篇工作在实验中调用 Gemini 3 Flash、Nano Banana 2 与 Veo 3.1 等外部模型；因此它的结果应理解为模型编排与反复修订的系统案例，不是公开了新的端到端视频扩散骨干，也不宜与单次生成模型按质量分直接排位。论文报告的片段级 self-improvement 增加多次 MLLM、图像和视频生成调用；它的 consistency 与 narrative 指标属于作者构造的 1–10 分钟基准/评审流程。[A²RD v1 §3–6、Appendix B.5](https://arxiv.org/html/2605.06924v1)

| 失效问题 | 路线改变的位置 | 适合回答的问题 | 仍未解决的边界 |
|---|---|---|---|
| 学生长 rollout、教师只看短窗口 | **Context Forcing：训练监督 + 慢/快上下文记忆** | 长历史如何进入教师目标，self-generated context 如何变成训练数据？ | teacher context 质量、缓存选择假设、长时训练成本 |
| 静态几何奖励压制动态对象 | **Stream4D：动态重建 + motion reward + 感知锚点** | 一致性奖励怎样避免以冻结画面作弊？ | 重建器和运动先验的偏差，物理规律未被直接保证 |
| 片段独立生成导致叙事/实体遗忘 | **A²RD：外层多模态记忆、规划与再生成** | 能否用结构化世界状态和片段修订维持故事？ | 依赖论文所用的 MLLM、图像和视频生成组件；多轮调用带来的系统结果不能归因于单一生成器 |

三者对应三个不同杠杆：**让模型在训练时看到长上下文、让优化目标正确奖励动态一致、在模型外维护叙事状态。** 它们都不能单独证明视频生成模型已经具备可靠物理模拟能力。对于物理状态变化或互动环境，还需要任务级闭环验证；本报告不把时长、帧率或偏好分数外推为世界模型能力。

| 工作 | 视频表示 / 生成器 | 条件如何进入 | 主要应对的约束 | 论文所能支持的结论 |

## 8. 运动、长时程一致性与控制为什么仍难

### 8.1 单帧先验强，不代表状态转移正确

图像模型能生成清楚的物体和场景，但视频还要预测物体在下一时刻的位置、速度、遮挡关系和状态变化。无显式物理/因果状态的生成目标通常是拟合训练视频分布；模型可以生成视觉上合理的局部片段，却在“物体是否持续存在、碰撞后是否改变状态、动作是否遵守接触关系”上失败。Sora 的技术报告公开列出的碎玻璃、进食状态、物体凭空出现和长片段不连贯，正说明画面逼真不等于可用作可靠模拟器。[Sora 官方报告 Discussion](https://openai.com/index/video-generation-models-as-world-simulators/)

### 8.2 时间上下文长度和故事连贯是两个问题

模型能够输出更多帧，表示它的生成窗口/缓存可容纳较长序列；故事连贯还要求记住人物身份、道具位置、已发生事件和未来动作计划。滑窗、重叠条件帧、因果卷积和 token cache 解决的是有限上下文下如何继续生成与减少接缝；它们本身不提供显式场景图或剧情状态。要验证长视频，应跨窗口追踪对象、服饰、镜头、动作目标和事件顺序，而不只报告生成帧数。

### 8.3 条件遵循是组合问题

文本常同时描述主体、动作、属性、数量、空间关系、时间次序与镜头。只要漏掉其中一项，CLIP/Text-Video 相似度仍可能不错，因为主体或场景词已满足。图像条件关注身份/构图持续，姿态条件关注具体运动，视频条件适合延续/编辑；它们的评测协议不同。模型需要在多个条件冲突时决定优先级，这也是“多模态条件支持”与“细粒度可控”之间的落差。

## 9. 如何读视频评测：一个总分通常遮住重要失效

VBench 把“视频生成质量”拆成 16 个维度，并为不同维度设计提示、自动评估和人类偏好标注，包含主体身份一致、运动平滑、时间闪烁、空间关系等。它的价值是提供分项诊断，而不是创造一个跨任务永远有效的总分；作者报告自动指标与其人类偏好数据相关，但该相关性仍受提示集、评测模型、模型版本和被测内容分布影响。[VBench §3–5；arXiv v1](https://arxiv.org/html/2311.17982v1)

| 评测类别 | 例子 | 解读边界 |
|---|---|---|
| 帧级视觉质量 | 图像特征分布、清晰度指标 | 可能忽略闪烁和动作错误 |
| 视频级真实性/连续性 | FVD、时序一致性模型 | 依赖特征提取器和参考集，难以诊断具体原因 |
| 文本—视频遵循 | CLIP/视频文本模型、对象/属性识别 | 全局相似度不保证每条关系/时间指令都成立 |
| 主体持续性 | 人脸/对象身份相似度、跟踪器 | 跟踪失效或遮挡会影响测量，不能覆盖人物状态 |
| 运动质量 | 光流/动作识别/时序平滑性 | 平滑并不等于符合语义或物理 |
| 人类偏好 | 成对比较或维度打分 | 结论依赖评审者、问题措辞、样本长度和任务 |

跨论文数字只有在同任务、相同提示集、相近分辨率/时长、同评价器和同模型版本下才适合直接比较。CogVideoX、HunyuanVideo、Wan 等论文同时报告自动指标与人评；若论文各自使用不同提示、生成设置、评估者和基线，就应引用作者报告结论，而非拼成排行榜。大规模人评能支持相对偏好，不等于证明物理一致性或所有场景都可控。

## 10. 开放问题与学习结论

1. **更好的时空表示**：如何让视频 latent 既压得足够短，又保留小动作、遮挡、文本和主体细节？VAE 重建误差应当与下游运动/身份质量联合考察。
2. **长时程状态记忆**：滑窗缓存能传递近邻信息，怎样表示人物、物体和场景状态，避免数十个窗口后身份与位置漂移？
3. **可执行的条件控制**：文本、首帧、参考主体、动作骨架、相机路径之间如何明确优先级，并能指出究竟哪项条件未遵循？
4. **运动/物理评测**：需要从视觉相似、动作语义、对象持续、接触关系、状态改变和因果顺序分别设计任务，而不是用一个“世界模拟器分数”概括。
5. **质量、时长和效率的联合评价**：更多生成帧、更高分辨率和更快推理各自是不同资源维度；报告结果须保留模型、硬件、采样步数、窗口与输出条件。

研究路线可概括为：早期工作借助图像先验和时空级联快速获得视频能力；潜空间视频扩散将时序卷积/注意力接入图像模型，并强调训练数据治理；时空 Transformer 进一步把 latent patch 当成长序列处理，针对跨模态融合、token 成本和序列长度开发不同方案；最新开源体系开始把因果 VAE 缓存、流式窗口、个性化和多任务作为系统组件。真正的研究进步不是模型名单变长，而是能指出哪种表示与训练设计解决了哪个具体约束、证据到哪为止。
