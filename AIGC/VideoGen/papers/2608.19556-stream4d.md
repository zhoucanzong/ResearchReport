# Stream4D：一致性奖励如何避免把真实运动冻住

来源：[Stream4D: 4D-Consistency for Streaming Autoregressive Diffusion Video Models](https://arxiv.org/html/2608.19556v1)，固定阅读版本 v1。重点位置：§1–4、Appendix G 与 I。

## 研究问题：静态 3D 重建奖励会奖励“不要动”

流式自回归扩散模型能逐段延长视频，但长期 rollout 会累积几何漂移和主体不一致。一个直觉方案是用 3D Gaussian Splatting 将各帧重建到同一场景，再以重建质量作为一致性奖励。问题在于单一静态 3D 场景无法表示动态物体：真实运动在重建中变成误差，奖励就可能鼓励画面冻结来换取更高分。对自回归模型，这个捷径尤其危险，因为早期静止状态还会成为后续片段的条件。[§1–2](https://arxiv.org/html/2608.19556v1)

## 4D 重建、运动先验和感知锚点

Stream4D 将静态重建器替换为带时间变化的 4D Gaussian 表示：先估计每帧相机，再由 MoVieS 从视频中重建动态场景，并通过重渲染衡量几何与外观是否能由同一动态场景解释。它同时从场景流估计运动幅度、时间平滑和局部刚性，避免 4D 重建指标仍偏爱低运动结果；最后保留一个轻量感知奖励锚定基础视觉质量。三类奖励合并后，用 forward-process DiffusionNFT 更新已经蒸馏好的自回归视频模型。[§3.1–3.2](https://arxiv.org/html/2608.19556v1)

设计顺序很重要：4D 重建奖励要求“运动中的场景仍可被一个随时间演化的几何解释”；运动项排除画面几乎静止和过度抖动两类捷径；感知锚点则防止一致性优化损伤原始画面质量。若只用几何一致性，优化仍可能趋向静态；若只提高运动幅度，又可能得到不自然抖动或物体形变。

## 证据应如何读取

作者将方法用于 Self-Forcing、Causal-Forcing 和 LongLive 三种 distilled autoregressive backbone，生成时长分别为 5 秒、5 秒和 10.3 秒；主要实验使用 500 条筛选出的运动突出提示，并另做随机提示子集检查。论文报告三个 backbone 上的 4D 重建指标改善，并配合独立重建器、运动 judge 和视频偏好指标观察是否出现“以静止换一致性”的现象。[§4.1–4.2、Appendix G](https://arxiv.org/html/2608.19556v1)

这支持一个窄而重要的判断：**时空一致性奖励若把动态场景压成静态几何，就会与运动质量冲突；评价奖励时需要同时测一致和运动。** 这些不是分钟级叙事、任意文本遵循或物理规律的实证结论。指标依赖相机估计、MoVieS/4DGT 重建、提示筛选和 judge；不同重建器或运动分布可能改变优化方向。

附录中的随机提示结果尤其值得注意：静态奖励方法也能得到较高重建分数，却可能在 motion / consistency joint verdict 上败给基础模型。这说明只报重建误差会漏掉关键失败；奖励优化的测试集必须含有确实需要运动的样本。[Appendix G](https://arxiv.org/html/2608.19556v1)

## 与 Context Forcing、A²RD 的区别

- **Context Forcing** 在训练期修正短上下文 teacher 与长 rollout student 的监督失配；它主要回答模型如何学会使用更长历史。
- **Stream4D** 在推理后训练/奖励阶段定义什么样的长 rollout 算“几何一致且仍在运动”；它不通过上下文缓存解决历史容量，也不维护显式剧情记忆。
- **A²RD** 在生成器外维护角色、环境和事件记忆，以片段规划和多轮生成/自我修订维持长叙事。它是模型编排系统，不是单独的扩散骨干。

因此，长视频一致性不是一个单一 loss 或更大 context window 能解决的问题：训练监督、奖励定义、缓存/记忆和评测协议分属不同层。Stream4D 解决的是动态几何奖励中“运动被惩罚”的目标设计问题；它没有证明模型形成了稳定的世界状态表示。
