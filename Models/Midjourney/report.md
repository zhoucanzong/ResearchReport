# Midjourney 模型与产品演进研究报告

> 覆盖范围：图像 V1–V7 与视频 V1，并讨论 2026 年公开的后续版本信息；重点是从公开证据理解图像/视频能力变化，不推断闭源架构。

## 1. 执行摘要

Midjourney 的公开证据主要支持**产品版本、输入控制和工作流**分析。官方材料描述 V4 是新代码库和新架构、V7 引入默认个性化与 Draft Mode，却没有给出各代网络层数、参数、文本编码器、训练目标或模型权重。因此，不能把输出更精致、速度更快或支持参考图，逐项翻译成 U-Net 扩容、T5、DiT、RLHF 或 IP-Adapter 的内部实现。[S1–S4]

官方记录显示 V1 默认期始于 **2022 年 2 月**，Stable Diffusion 则于 **2022-08-22** 公开发布。这个先后顺序不支持“V1–V3 基于已公开 SD 权重微调”的说法；但也不能反向证明 Midjourney 从零训练或完全未受 LDM 研究影响。LDM 论文与后来公开的 SD 产品权重是不同对象。[S1,S2]

产品上可见的演进是从早期图像生成到更强的提示控制、参考和个性化，再到单独的视频 V1 图像动画流程。闭源的限制不靠补造参数表解决；本报告将能查到的行为、作者公告和真正未知的训练机制分开。

## 3. 官方能确认的功能变化

### 3.1 早期与 V4 / V5：输出行为不等于网络结构

Legacy Features 将 V1–V3 描述为抽象、绘画化程度较高的早期模型，且列出初始 1:1 网格图像为 256×256；V4 的初始网格是 512×512。它们是**输出/工作流尺寸**，不是训练分辨率，更不是 VAE 压缩率证据。[S1 “Legacy Versions” 与 Upscalers 表]

V4 官方说明可以处理更多角色/对象和较小细节；V5 更偏照片，V5.1 有更强的默认美学。这些定性产品描述没有受控消融：不能由此证明 V4 “参考 NovelAI”，也不能用 V5 真实感提升推出参数从 1B 增至 2B 或采用 T5-XXL。[S1]

### 3.2 V7：迭代速度、质量与模型路由的取舍

V7 Alpha 公告将 Draft Mode 描述为更快、更便宜、质量较低的草稿流程，喜欢结果后可以 Enhance / Vary 重绘。该公告还明确当时放大、编辑、Retexture 会回到 V6，而非全部由新模型完成。[S3]

因此，同一网页中的一次操作可能经过不同版本。比较 V6 与 V7 的质量和延迟，需要记录是否 Draft、是否后续重绘、是否调用旧版编辑器，不能只读界面上的默认 `--v` 就认为全链路同一权重。公开材料不足以将所有结果变化归因于“新 backbone 更快”。

### 3.3 Reference：功能、兼容性和身份保持的边界

V7 的 Omni Reference 用于把某个角色、对象、车辆或非人类主体带入新图像；网页中选择该输入，Discord 用 `--oref`，强度用 `--ow`。它与 V6 的 Character Reference 不是可以跨版本互换的同一个参数。[S4]

官方还说 stylize / exp 会与 reference 争夺影响，过高 reference 权重可能更差，多主体参考属于实验性行为。这给出可直接研究的失败条件：主体、风格和提示在争夺控制力，参考图不保证身份或衣着的每个细节不变。官方没有说明使用了 InsightFace、AdaIN、StyleGAN 或 IP-Adapter，因此本报告不再以这些通用机制充当 Midjourney 的实现证据。

## 4. 视频 V1：已发布功能与具体失败模式

2025-06-18 公告已发布视频 V1，初始流程是图像动画：可用生成图或外部上传图作为首帧，用自动或手写 motion prompt 控制。发布时每个 job 产出四个 5 秒片段，并提供每次约 4 秒、最多四次的延长操作。这些是**发布日配置**，不视为 2026 年所有套餐的永久上限。[S5]

公告明确 low motion 有时几乎不动，而 high motion 可能产生不自然错误。延长次数也不能证明跨片段长程一致性已经得到保障。视频 V1 与图像 V1 是不同产品线，不能混用名称或发布时间。

## 5. 训练与架构：保持真正未知的部分

| 未被公开材料支持的推断 | 为什么现有证据不能支持 | 后续可验证方式 |
|---|---|---|
| V1–V3 由 SD 权重微调 | 时序理由错误，未给官方权重来源 | 原始技术披露、训练记录或可验证的模型出处 |
| 1B→5B、CLIP→T5→DiT | 画质和服务延迟不能唯一识别规模、编码器或 backbone | 官方架构/技术报告；没有时保留未知 |
| 数亿偏好判断、奖励模型与 PPO/RLHF | 有用户打分与个性化产品，不等于披露训练数据规模或算法 | 训练方法、数据规模和受控评价公开记录 |
| 所有图像统一锐化/色彩校正/2×或4×超分 | 不同版本与编辑/放大路由不同 | 分步骤测试与具体工作流文档 |

“SD U-Net → 更大 U-Net → 混合 DiT”把未公开实现串成因果链，无法作为技术演进史。美学偏好与可控性是可评测的行为维度；现有材料也不足以证明厂商内部只有美学一个目标或全部技术决策都服务于该目标。

## 6. 比较与复现设计

缺少固定型号、提示集、种子、模式和评审协议的星级排名不支持有效比较。若比较 Midjourney、SD、DALL-E 或 FLUX，应使用同一提示集并分别记录对象计数、文字准确率、空间关系、参考身份保持、风格变化和失败样本；审美人评也要与可计算指标分开。

Midjourney 还需记录 `--v`、参考参数、个性化开关、Draft/标准模式、放大与编辑步骤。否则“默认输出更好”可能来自默认样式或后处理路径，不能直接归因于训练架构。云端服务延迟包含队列与调度，也不能用来估参数量。

## 7. 局限与待补证

本报告主要依据官方文档与历史公告；其中优势和速度是开发者在各自条件下的报告结果，尚无账户内生成、盲评、模型推理或训练复现作为独立验证。官方公告存在产品宣传和选例偏向，引用时应限定在公告范围。

仍待补充的研究材料包括 V6 / V6.1 原始发布记录，以及可公开重跑的参考一致性与文字测试。公司人数、收入、融资和训练样本量没有足以支持技术结论的来源，故不纳入。Version 页面列出的 V8.2 属后续版本，不能反向写入 2025 年事件。
