## 1. 概述

字节跳动（ByteDance）作为全球领先的互联网科技公司，在 AIGC（AI Generated Content，人工智能生成内容）领域的布局呈现出"底层模型 + 中层平台 + 上层应用"的三层架构体系。与 OpenAI、Google 等以底层大模型为核心的策略不同，字节跳动依托其强大的 C 端产品矩阵（抖音、TikTok、剪映/CapCut、即梦AI），形成了独特的"模型驱动产品、产品反哺模型"的闭环生态。

本报告聚焦于字节跳动生成模型系列中的核心组成部分：

- **Seedance**：专业级视频生成大模型，采用 DiT（Diffusion Transformer）架构，是字节跳动在视频生成领域的旗舰技术产品
- **即梦AI（Dreamina）**：面向 C 端用户的 AI 创作平台，集成 Seedance 视频生成能力，主打中文场景与本土审美
- **剪映/CapCut**：全球领先的视频编辑工具，深度集成 AI 生成能力，形成"编辑 + 生成"一体化工作流
- **豆包/Seed**：底层大语言模型与多模态模型体系，为上层应用提供基础能力支撑

字节跳动的 AIGC 战略具有鲜明的特点：**优先服务自身内容生态**，视频生成模型 Seedance 首先集成在即梦AI 和剪映中，而非以独立 API 服务形式对外提供。这一策略与 Sora（OpenAI）、Runway 等竞品形成显著差异。

### 3.2 即梦AI（Dreamina）：C 端 AI 创作平台

即梦AI 是字节跳动面向 C 端用户推出的 AI 创作平台，定位为"每个人的 AI 创意助手"。其核心特点包括：

- **中文场景优先**：针对中文提示词进行深度优化，理解中文文化语境、成语、网络用语
- **本土审美**：训练数据包含大量中文互联网内容，生成风格更符合中国用户审美偏好
- **低门槛创作**：提供丰富的模板和预设，降低普通用户使用 AI 创作的门槛
- **社区生态**：支持作品分享、风格收藏、创作灵感推荐，形成创作者社区

即梦AI 的产品演进路径清晰：从 2024 年的 AI 绘画工具，发展为 2025 年的 AI 视频创作平台，再到 2026 年的多模态 AI 创作工作流。

### 3.3 剪映/CapCut：集成 AI 生成能力

剪映（国内版）和 CapCut（国际版）是字节跳动旗下的视频编辑工具，全球月活用户超过数亿。其 AI 集成策略：

- **编辑 + 生成一体化**：用户在编辑视频时可直接调用 Seedance 生成素材，无需切换应用
- **智能剪辑辅助**：AI 自动识别视频高光时刻、生成字幕、推荐 BGM
- **模板化生成**：提供大量 AI 生成模板，用户只需替换素材即可快速产出
- **跨平台协同**：手机端、PC 端、Web 端数据互通，创作无缝衔接

剪映的 AI 集成体现了字节跳动"工具即入口"的产品哲学——不单独做一个 AI 视频生成工具，而是将生成能力嵌入用户已有的工作流中。

### 3.4 Seedance：专业视频生成模型

Seedance 是字节跳动自研的专业级视频生成大模型，是即梦AI 视频能力的核心技术底座。其定位与特点：

- **专业级质量**：面向高质量视频内容生成，而非简单的短视频特效
- **DiT 架构**：采用 Diffusion Transformer 架构，区别于早期的 U-Net 扩散模型
- **质量与速度平衡**：针对消费级 GPU 和云端推理进行优化，兼顾生成质量与推理效率
- **多平台部署**：支持即梦AI（C 端）、剪映（工具端）、火山引擎（B 端 API）多形态输出

### 3.5 豆包/Seed：底层大模型能力支撑

豆包（Doubao）是字节跳动的大语言模型品牌，Seed 是其内部研发代号。在 AIGC 体系中，豆包提供：

- **文本理解**：解析用户提示词（Prompt），提取生成意图、风格要求、场景描述
- **多模态理解**：理解图像内容，支持图生视频时的视觉特征提取
- **Agent 能力**：在即梦AI 中支持多步骤创作工作流，如"生成角色 → 保持角色一致性 → 生成多场景视频"
- **中文优化**：针对中文语料进行预训练，在中文理解和生成上具有优势

## 4. Seedance 架构详解与推测

> **重要声明**：以下关于 Seedance 架构的分析基于公开技术趋势、行业论文（如 DiT、Latte、Open-Sora 等）以及字节跳动已知技术路线的合理推测。字节跳动官方未完全公开 Seedance 的技术白皮书，具体实现细节可能与推测存在差异。

### 4.1 整体架构推测：DiT 视频生成模型

Seedance 极大概率采用 **DiT（Diffusion Transformer）** 架构，这是 2024-2025 年视频生成领域的主流技术路线，由 OpenAI Sora、Stable Video Diffusion 等模型验证有效。

#### 4.1.1 为什么选择 DiT？

传统的视频扩散模型多采用 U-Net 架构（如 Stable Video Diffusion），但 U-Net 存在以下局限：

- **感受野受限**：卷积操作的局部性限制了模型对长距离时空依赖的建模能力
- **扩展性瓶颈**：U-Net 的扩展主要依赖增加通道数和层数，难以有效利用大规模数据
- **多模态融合困难**：U-Net 的编码器-解码器结构不利于文本、图像、视频特征的统一融合

DiT 架构通过将扩散过程与 Transformer 结合，解决了上述问题：

- **全局注意力**：Self-Attention 机制天然支持全局时空依赖建模
- **规模可扩展性**：模型能力随参数量和训练数据规模增长而持续提升（Scaling Law）
- **统一模态处理**：Transformer 的序列化特性便于融合文本、图像、视频等多种模态

#### 4.1.2 Seedance 1.0 架构推测

基于 DiT 架构的通用设计模式，Seedance 1.0 的架构可能如下：

```
输入：文本提示词（Text Prompt）+ 参考图像（可选，Image Prompt）
         ↓
┌─────────────────────────────────────────────────────────────┐
│                    编码器模块（Encoder）                       │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  文本编码器  │  │  图像编码器  │  │   VAE 图像编码器     │  │
│  │  (T5/CLIP)  │  │  (ViT/CLIP)  │  │   (压缩视频帧)       │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────────┐
│              时空联合 Transformer 核心（DiT Backbone）        │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  时空联合注意力层（Spatio-Temporal Joint Attention）    │  │
│  │  - 空间注意力：建模单帧内的像素关系（Spatial Self-Attn）  │  │
│  │  - 时间注意力：建模跨帧的运动关系（Temporal Self-Attn）   │  │
│  │  - 交叉注意力：融合文本/图像条件（Cross-Attention）      │  │
│  └─────────────────────────────────────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  前馈网络（FFN）+ 层归一化（LayerNorm）                  │  │
│  │  + AdaLN-Zero 条件注入（基于扩散时间步和文本特征）        │  │
│  └─────────────────────────────────────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  重复 N 层（N 可能为 12-24，取决于模型规模）              │  │
│  └─────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────────────┐
│                    解码器模块（Decoder）                       │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  VAE 解码器：将潜在空间表示解码为像素级视频帧             │  │
│  │  输出：连续视频帧序列（720p/1080p，通常 2-5 秒）         │  │
│  └─────────────────────────────────────────────────────────┐  │
└─────────────────────────────────────────────────────────────┘
```

#### 4.1.3 关键技术组件推测

**（1）视频 VAE（Video Variational Autoencoder）**

Seedance  likely 使用专门训练的视频 VAE 将像素空间压缩到潜在空间（Latent Space），以降低计算复杂度：

- **时间压缩**：不仅压缩空间维度（H×W），还压缩时间维度（T），例如 4× 时间下采样
- **通道数**：潜在空间通道数可能为 16-32，平衡压缩率与重建质量
- **因果卷积**：确保时间因果性，避免未来帧信息泄露到当前帧

**（2）时空联合注意力（Spatio-Temporal Joint Attention）**

Seedance 1.0 的核心创新可能在于时空注意力的设计：

```python
# 伪代码示意：时空联合注意力机制
class SpatioTemporalAttention(nn.Module):
    def __init__(self, dim, num_heads):
        self.spatial_attn = MultiHeadAttention(dim, num_heads)  # 单帧内
        self.temporal_attn = MultiHeadAttention(dim, num_heads)  # 跨帧
        
    def forward(self, x, text_cond):
        # x: (B, T, H, W, C) - 批次、时间、高度、宽度、通道
        
        # 步骤1：空间注意力 - 每帧独立处理
        x = self.spatial_attn(x, x, x)  # 自注意力
        
        # 步骤2：时间注意力 - 跨帧建模运动
        x = rearrange(x, 'b t h w c -> b (h w) t c')
        x = self.temporal_attn(x, x, x)
        x = rearrange(x, 'b (h w) t c -> b t h w c')
        
        # 步骤3：交叉注意力 - 融合文本条件
        x = self.cross_attn(x, text_cond, text_cond)
        
        return x
```

**（3）AdaLN-Zero 条件注入**

基于 DiT 论文的设计，Seedance 可能采用 Adaptive Layer Norm（AdaLN）进行条件注入：

- 将扩散时间步（timestep）和文本特征拼接，通过 MLP 生成缩放和偏移参数
- 相比传统的交叉注意力，AdaLN 计算更高效，且能稳定训练

**（4）3D 位置编码（3D Positional Encoding）**

视频是 3D 数据（T×H×W），需要 3D 位置编码：

- 可能采用可学习的 3D 正弦/余弦位置编码
- 或采用 Rotary Position Embedding（RoPE）的 3D 扩展版本
- 时间维度和空间维度的位置编码可能使用不同频率，以区分运动速度和空间细节

### 4.2 Seedance 2.0 架构升级推测

Seedance 2.0（2026.02 发布）相比 1.0 的重大升级，暗示了架构层面的显著改进：

#### 4.2.1 更大规模的 DiT 骨干网络

| 维度 | Seedance 1.0 推测 | Seedance 2.0 推测 |
|------|-------------------|-------------------|
| 参数量 | ~1-3B | ~3-8B |
| Transformer 层数 | 12-16 层 | 20-32 层 |
| 注意力头数 | 16-24 | 24-48 |
| 隐藏维度 | 768-1024 | 1024-1536 |
| 训练数据量 | ~1000万 视频片段 | ~5000万+ 视频片段 |

#### 4.2.2 改进的时序建模

Seedance 2.0 在"复杂运动更自然"方面的提升，可能来自以下技术改进：

**（1）长程时间注意力（Long-Range Temporal Attention）**

- 1.0 可能仅支持局部时间窗口（如 8-16 帧）的注意力
- 2.0 可能引入全局时间注意力或滑动窗口注意力，支持更长视频序列的连贯运动
- 可能采用时间分层注意力：底层高时间分辨率（捕捉细节运动），顶层低时间分辨率（捕捉整体运动趋势）

**（2）运动先验建模（Motion Prior Modeling）**

- 引入显式的运动流（Optical Flow）预测分支
- 或采用运动向量（Motion Vector）作为中间监督信号
- 可能参考 VideoLDM、AnimateDiff 等工作的运动模块设计

**（3）物理一致性约束（Physical Consistency）**

- 2.0 的"精细物理模拟"暗示可能引入了物理引擎约束或物理先验损失函数
- 例如：重力约束、碰撞检测、流体动力学近似
- 可能通过多任务学习，联合优化视频生成和物理属性预测

#### 4.2.3 2K 分辨率的技术挑战

从 1080p 升级到 2K（2560×1440）并非简单的分辨率放大，涉及多项技术挑战：

| 挑战 | 解决方案推测 |
|------|-------------|
| 显存爆炸 | 采用分块生成（Tiled Generation）或级联扩散（Cascade Diffusion） |
| 细节保持 | 高分辨率 VAE 或超分辨率后处理模块 |
| 时间一致性 | 跨帧特征共享（Cross-Frame Feature Sharing）或噪声一致性初始化 |
| 推理速度 | 模型量化（INT8/FP8）、推理引擎优化（TensorRT/vLLM 适配） |

Seedance 2.0 可能采用 **级联扩散架构**：

```
低分辨率生成（256×256 或 512×512）
         ↓
超分辨率模块 1（→ 1024×1024）
         ↓
超分辨率模块 2（→ 2K 2560×1440）
         ↓
时间一致性后处理（去闪烁、运动平滑）
```

这种级联设计可以显著降低高分辨率生成的计算成本，同时保持质量。

### 4.3 多主体一致性技术

Seedance 在多主体一致性方面的能力是其重要卖点，可能采用以下技术：

**（1）角色嵌入（Character Embedding）**

- 为每个主体（人物/物体）学习独立的嵌入向量
- 在生成过程中保持该嵌入向量不变，确保外观一致性
- 类似 IP-Adapter、ReferenceNet 的设计思路

**（2）身份保持注意力（Identity-Preserving Attention）**

- 在交叉注意力中增加身份保持约束
- 通过掩码机制确保不同主体的特征不互相干扰
- 可能采用主体感知的注意力分离（Subject-Aware Attention Disentanglement）

**（3）参考图像引导（Reference Image Guidance）**

- 用户上传参考图像后，模型提取关键视觉特征
- 在扩散去噪过程中，通过特征注入保持与参考图像的一致性
- 可能结合 ControlNet 风格的条件控制

## 6. 技术特点深度分析

### 6.1 DiT 架构：时空联合注意力

Seedance 采用的 DiT 架构是其技术核心，以下是详细分析：

#### 6.1.1 时空联合注意力的三种设计模式

视频生成中的时空注意力有三种主流设计，Seedance 可能采用其中一种或混合：

| 模式 | 名称 | 原理 | 优点 | 缺点 |
|------|------|------|------|------|
| 模式 A | 分解式时空注意力（Factorized） | 先空间注意力，再时间注意力，交替进行 | 计算效率高，内存友好 | 时空交互建模较弱 |
| 模式 B | 联合式时空注意力（Joint） | 将时间维度展平，统一做 3D 注意力 | 时空交互强，建模能力好 | 计算复杂度高，内存开销大 |
| 模式 C | 分层式时空注意力（Hierarchical） | 底层高分辨率空间注意力 + 顶层低分辨率时空联合注意力 | 兼顾效率和质量 | 实现复杂，训练难度大 |

**推测**：Seedance 1.0 可能采用模式 A（分解式）以保证推理速度；Seedance 2.0 可能升级为模式 C（分层式）或改进的联合式以提升质量。

#### 6.1.2 与 U-Net 扩散模型的对比

| 特性 | U-Net 扩散模型（如 SVD） | DiT 模型（如 Seedance） |
|------|------------------------|------------------------|
| 核心操作 | 卷积 + 下采样/上采样 | Transformer Self-Attention |
| 感受野 | 局部（受卷积核限制） | 全局（注意力机制） |
| 扩展性 | 扩展性有限 | 符合 Scaling Law，规模越大能力越强 |
| 多模态融合 | 需额外设计融合模块 | 天然支持序列化多模态输入 |
| 训练稳定性 | 相对稳定 | 需要 careful tuning（学习率、初始化等） |
| 推理速度 | 通常较快 | 注意力计算量大，需优化 |
| 长视频生成 | 时序建模能力有限 | 更适合长程依赖建模 |

### 6.2 多模态：文本+图像+视频统一生成

字节跳动的 AIGC 体系追求多模态统一，可能的技术路线：

**（1）统一潜在空间（Unified Latent Space）**

- 文本、图像、视频映射到同一潜在空间
- 通过统一的 Transformer 进行处理
- 模态间转换变为潜在空间内的操作

**（2）统一 Tokenizer**

- 图像：使用 VAE 编码为视觉 Token
- 视频：使用视频 VAE 编码为时空 Token
- 文本：使用 LLM Tokenizer 编码为文本 Token
- 所有 Token 统一输入 Transformer

**（3）多模态训练策略**

| 训练阶段 | 数据 | 目标 |
|----------|------|------|
| 阶段 1 | 大规模图像-文本对 | 学习视觉-语言对齐 |
| 阶段 2 | 视频-文本对 | 学习时序建模 |
| 阶段 3 | 图像-视频-文本三元组 | 学习跨模态转换 |
| 阶段 4 | 高质量精调数据 | 提升生成质量和可控性 |

### 6.3 中文优化：中文提示词理解，本土风格

Seedance 和即梦AI 的中文优化体现在多个层面：

**（1）中文文本编码器**

- 可能采用专门针对中文优化的文本编码器（如基于豆包 LLM 的文本编码器）
- 而非直接使用 CLIP 等英文为主的编码器
- 支持中文的细粒度语义理解（如"水墨画风格"vs"油画风格"）

**（2）中文文化概念理解**

| 概念类型 | 示例 | 技术挑战 |
|----------|------|----------|
| 传统文化 | 京剧、汉服、书法、园林 | 需要特定文化知识 |
| 网络文化 | 梗图、表情包、短视频风格 | 需要实时更新语料 |
| 地域特色 | 各地建筑、美食、方言场景 | 需要地域多样性数据 |
| 审美偏好 | 美白、瘦脸、特定色调偏好 | 需要本土用户反馈数据 |

**（3）本土风格模板**

即梦AI 提供大量本土风格模板，这些模板可能通过以下方式构建：

- 收集中文互联网热门视觉风格
- 通过 LoRA（Low-Rank Adaptation）或类似技术训练风格适配器
- 用户反馈驱动的模板迭代优化

### 6.4 工程优化：推理速度优化，成本控制

视频生成模型的推理成本极高，Seedance 的工程优化至关重要：

#### 6.4.1 推理加速技术

| 技术 | 原理 | 效果 |
|------|------|------|
| 模型量化 | INT8/FP8 权重，降低显存占用和计算量 | 速度提升 1.5-2×，质量损失可控 |
| 蒸馏加速 | 训练轻量级学生模型模仿大模型输出 | 速度提升 2-5× |
| 并行解码 | 多个时间步或空间块并行去噪 | 减少迭代次数 |
| 缓存优化 | 重用已计算的注意力 KV Cache | 减少重复计算 |
| 算子优化 | 针对 Attention、LayerNorm 等定制 CUDA Kernel | 底层效率提升 |

#### 6.4.2 成本控制策略

- **分级服务**：免费用户（低分辨率、慢速队列）/ 付费用户（高分辨率、优先队列）
- **边缘计算**：利用字节跳动的全球 CDN 节点，就近部署推理服务
- **动态批处理**：将多个用户的请求动态拼接成批次，提高 GPU 利用率
- **模型分片**：大模型拆分到多卡并行，支持更大 batch size

### 9.3 战略建议（分析性观点）

1. **时长优先**：在可灵已支持 3 分钟时长的背景下，Seedance 应优先突破长视频生成技术，否则在短剧等场景将处于劣势
2. **开放生态**：适度开放模型能力（如通过火山引擎提供更多自定义选项），吸引开发者和专业创作者
3. **垂直深耕**：在电商广告、教育、游戏等垂直场景建立深度解决方案，形成差异化
4. **成本持续优化**：视频生成的规模化应用取决于成本下降速度，需持续投入工程优化
