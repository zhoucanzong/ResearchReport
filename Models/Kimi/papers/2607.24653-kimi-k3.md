# Kimi K3：KDA、Block AttnRes 与 Stable LatentMoE 的联合设计

> **一手来源**：**Kimi K3: Open Frontier Intelligence** = arXiv:2607.24653 **v2**（2026-08-07，本轮引用版本），正文 HTML 全文逐节读取。配套：HuggingFace 模型卡 [`moonshotai/Kimi-K3`](https://huggingface.co/moonshotai/Kimi-K3)（last modified 2026-09-02）与[官方发布说明](https://www.kimi.com/en/blog/kimi-k3)。模型卡 API 的 `createdAt` 是仓库元数据，不作为权重公开日期证据。｜ **主等级**：`[精读原文]`
> **一句话定位**：K3 把 KDA/MLA 混合注意力、Block AttnRes、Stable LatentMoE、NoPE、从零训练的视觉编码器与 MXFP4 QAT 等选择放进同一模型方案。原文报告架构、数据与训练改进合计带来约 2.5× scaling efficiency，但没有证明这些选择彼此为必要条件。
> **亮点与差异四行**
> - **一句话亮点**：用「下界衰减」这一处参数化改动，把 KDA 的对角 tile 从逐 position-pair 计算变成 Tensor Core 稠密矩阵乘——数学上改一个映射，工程上删掉一整类 kernel。
> - **新在哪**：① KDA 的 scaled-sigmoid 下界衰减（`g_min = −5`）使 `1/Γ < e^80` 落在 BF16 范围内；② **Block AttnRes** 把残差从「累加」改成「对 block 源做 softmax 注意力」，`O(Ld) → O(Nd)`；③ **Stable LatentMoE**（前置 RMSNorm + SiTU-GLU + Quantile Balancing）在不加辅助损失的前提下稳住 896 专家。
> - **证据强度**：组件级证据不一（下界衰减、MoE 稳定化和视觉初始化各有针对性支持）；约 2.5× scaling 效率是作者报告的联合结果，没有逐项贡献拆分。主表数字均为厂商自报。
> - **引用边界**：报告分数时同时注明 max effort、harness、硬件校准和上下文压缩条件；不要把联合 scaling 结果归因于单个组件。

## 1. 问题设定：两条缩放轴，开源只走了一条

引言（§1）给出的诊断非常直白，值得原样记住它的逻辑链：

1. 长期以来 scaling 指「部署前投入更多算力」；推理模型兴起后，**test-time compute 成为第二条轴**（o 系列、extended thinking、R1/K1.5、K2.5 的 Agent Swarm）。
2. 开源生态在**第二条轴上进展快**（各种 RL / agentic 后训练方法普及很快），但**第一条轴慢**——「many recent models remain within or slightly above the 1T-class parameter regime」。
3. 后果是收敛风险：当大家把日益复杂的 RL 套在同等规模的基座上，开源之间的差异会被抹平，而与最强闭源系统的差距会拉大。

所以 K3 的目标函数是**两轴同时推进**：基座推到 2.8T，同时把 RL、effort 档位与长程交互推到 **1M 上下文**上。这也解释了为什么这份报告有一半篇幅是基础设施——3T 与 1M 都不是「调参就能到」的量级。

## 2. 架构：四个方向的「信息流」重排

报告用一条主线串起所有改动：**沿序列长度、网络深度、模型宽度三个方向重排信息流**，再叠加原生视觉与优化器。

### 2.1 沿序列：KDA 主体 + 周期 Gated MLA（3:1），且全层 NoPE

- **配比**：每个 block 内 **3 层 KDA 后接 1 层 Gated MLA**，全模型 93 层中 **69 层 KDA + 24 层 Gated MLA**；backbone 末尾**额外加一层** Gated MLA，保证最后一层一定是全局注意力。
- **KDA 的单步形式**（式 1）：先做 channel-wise 衰减再走 delta 规则，
  `S_t = (I − β_t k_t k_tᵀ) Diag(α_t) S_{t−1} + β_t k_t v_tᵀ`，`õ_t = S_tᵀ q_t`。
  `α_t ∈ (0,1)^{d_k}` 是逐通道单步保留因子，`β_t ∈ (0,1)` 控制写入强度。
- **chunkwise 并行**（式 4）：chunk 间递推、chunk 内并行，输出 = 跨 chunk 项 + chunk 内项；`Γ` 是累积衰减，`U/W` 来自 UT 变换。

**本轮最值得抄的一个技巧：下界衰减**

Kimi Linear 用 `g = −e^A · Softplus(z) ∈ (−∞, 0)`，`1/Γ` 无界，会在有限精度下溢出，于是 16-token tile 里的**对角 tile 只能用逐 position-pair 的显式计算**——这是 chunk 内并行的主要瓶颈。

K3 换成 **scaled sigmoid**：

```
g_t^h = g_min · Sigmoid(e^{A_h} z_t^h) ∈ (g_min, 0),    α_t^h = exp(g_t^h)
g_min = −5,  A_h 初始化为 0（可学习 per-head log-scale）
```

带来的三条硬结论（都是可验算的）：

- 每个保留因子 `α > e^{−5} ≈ 6.7×10^{−3}`；
- 16-token tile 的累积 log-decay 落在 `(−80, 0)`；
- 倒数缩放因子 `< e^{80}`，**留在 BF16 动态范围内**。

因此**对角与非对角 tile 都能用稠密 Tensor Core 矩阵乘**，显式的 position-pair 对角路径被删掉（图 3）。这就是标题里说的「算法-系统协同」的真实含义：不是写了个更快的 kernel，而是**改参数化让 kernel 变简单**。

**另两处与 Kimi Linear 的差别**：① 输出门从低秩参数化换成**输入相关的 full-rank 投影**（式 6，head-wise RMSNorm 后做 data-dependent gating）；② MLA 层**全部用 NoPE**——位置/近因信息交给 KDA 的递推与衰减，MLA 只负责无限制的全局内容交互。

**NoPE 的实际收益**：扩上下文时**不需要**改 RoPE 基频、**不需要** YaRN 类插值。这是 K3 与 K2 长上下文路线的结构性差异（K2 依赖 YaRN），也直接解释了为什么 1M 扩展可以放在 cooldown 阶段做完。

> 一个易被忽略的工程细节：报告说 flash attention 输出舍入存在偏差（引 [98]），因此**训练时注意力输出保持 FP32**；这使输出 tile 的片上占用翻倍，于是他们重写训练 kernel，把这块开销与 **KV staging buffer** 重叠（而不是与 query tile 重叠），腾出 shared memory 做更深的 KV 流水。

### 2.2 沿深度：Attention Residuals（AttnRes）——把残差做成注意力

- **动机类比极干净**：标准残差把所有历史压缩到一个状态 `h_l`，这就是「沿深度的 RNN 瓶颈」；Transformer 当年是用 attention 取代了沿时间的递推，AttnRes 就用 attention 取代沿深度的均匀累加。
- **全量形式**（式 8–9）：每层一个可学习 pseudo-query `w_l` 当 query，keys/values 是「token embedding + 所有前序层输出」；打分用 `exp(qᵀ RMSNorm(k))`，**RMSNorm 防止大幅值层主导权重**；`h_l = Σ α_{i→l} v_i`。深度 `L < 100`，所以 `O(L²d)` 算力可接受，真正的代价是 `O(Ld)` 的显存与流水并行下的跨 stage 通信。
- **Block 形式**（式 10）：把 L 层切成 N 个 block，块内输出求和成 `b_n`，跨块只对 N 个块级表示做全注意力；显存/通信 `O(Ld) → O(Nd)`。**K3 取 N ≈ 8**，具体是 8 个 12 层 block（末块不满），加上 embedding 共 9 个源。
- 附带好处：块结构**界定推理期状态**，块间并行结果可借 online softmax 与块内串行部分和合并，降低推理时间。

AttnRes 本身有独立的技术报告（**arXiv:2603.15031**，2026-03-16）：先接进 Kimi Linear（48B 总 / 3B 激活，1.4T tokens）验证，观察到输出幅值与梯度沿深度更均匀，并改善下游。K3 是它在旗舰规模上的落地。

### 2.3 沿宽度：Stable LatentMoE（896 选 16，稀疏度 56）

- **LatentMoE 的作用**：把「全模型宽度 d」与「路由专家宽度 ℓ」解耦——共享专家保留全宽通路，路由专家在紧凑 latent 空间工作。于是可以把路由专家扩到 **896 个、每 token 激活 16 个（稀疏度 56）**，而通信/权重流量不随路由重数线性膨胀。K3 的 latent 维度是 **3584（0.5×）**，每专家 hidden 3072，共享专家固定 **2**。
- **极端稀疏放大的两个失效模式**（报告的诊断，很有价值）：
  1. 路由通路 `W↓ → 门控专家 FFN → W↑` 近似四次连续矩阵乘，条件数差；在 2.8T 规模下**路由分支内部激活爆炸**。
  2. 近 `10³` 个专家的负载均衡，**超出 aux-loss-free 固定步长 bias 更新的良性区间**。
- **三件套解法**：
  1. **前置 RMSNorm**（式 11，专家聚合与 up-projection 之间）——降尺度敏感性；报告称「除稳定训练外，该 RMSNorm **一致改善验证损失与下游基准**」。
  2. **SiTU-GLU**（式 12）：把 SwiGLU 的两支各自套软钳位 `β tanh(x/β)`，取 `β₁=4`（门支）、`β₂=25`（up 支），输出满足 `|f(x)| ≤ β₁β₂ = 100`；近原点近似线性（保留 SwiGLU 局部响应），大值有界。对照：SwiGLU 两支都无界。
  3. **Quantile Balancing（QB）**（式 14）：不再用 `b ← b + γ·sign(ℓ̄ − ℓ_j)` 的固定步长，而是**直接按 router-score 分位数设 bias**：对 `s_{i,j} − α_i` 取 `1 − k/n` 分位、再减去均值去掉公共偏移。实现上用 **margin 直方图**估计全 batch 分位数（一次 all-reduce 汇总各 rank 分箱计数，每专家几百个 bin），代价远低于精确分位。bias **推理期冻结**。

### 2.4 原生视觉：MoonViT-V2「从零训」的实证结论

- **设计**：文本 / 图像 / 视频**同一个 backbone、同一个上下文**，无后置模态对齐阶段；MoonViT-V2 → 轻量 MLP projector → LLM。27 层、约 **0.4B（模型卡 401M）**，用 RMSNorm、**去掉所有 bias**。
- **与 K2.5 的关键背离**：不再用 SigLIP 之类的对比学习编码器做初始化，而是**完全从零、用 next-token prediction 训练**。
- **给出的理由是可检验的**：接上 SigLIP 初始化的 MoonViT-3D 后联合优化不稳，**梯度范数持续更高且频繁尖峰**；MoonViT-V2 全程更稳（图 6）。此外 NTP 训练让表征直接由语言建模目标塑形，而不是被「偏向全局语义」的对比损失塑形。
- **结论的强度要看清**：报告称 MoonViT-V2 **在视觉评测上与 SigLIP 初始化基线持平**（"matches"）。所以这是一个**「更稳且不掉点、可省掉对比预训练依赖」**的论证，**不是**「从零更好」的论证。
- **工程配额**：图/视频完全共享参数；注意力分解为帧内空间 + 帧间时间两趟；时间维再池化；投影前做 **2×2 pixel shuffle 降 4×** 视觉 token，使至 **3584×3584** 像素的输入在 1M 上下文里可负担。

### 2.5 优化器：Per-Head Muon

沿用 Muon 作矩阵参数优化器，但把 Q/K/V 投影的动量矩阵**按 head 切块**分别做 Newton–Schulz 正交化。直觉：全矩阵正交化把所有 head 当一个耦合块，梯度/动量尺度大的 head 主导共享更新方向，小尺度 head 得到欠归一化的更新。官方称：head 间学习动态更均衡、大规模训练更稳，且**开销略降**（对 tall 的 per-head 块做 NS 迭代比全矩阵便宜）。

## 3. 预训练

### 3.1 数据

- 四域文本：Web Text / Code / Mathematics / Knowledge；视觉语料按 K2.5 的分类学（caption、图文交错、OCR、感知、视频、**视觉编程**），并**显著扩大程序化多模态数据**——把代码片段与它渲染出来的视觉配对，覆盖 **SVG / 3D 资产 / Webpage / Game / CAD**。坐标监督同时给**绝对与归一化（[0,1]）两种格式**，使定位既精确又分辨率鲁棒。
- 知识/数学沿用 K2 的 rephrasing 配方（风格与视角多样化 prompting + chunk-wise 自回归生成 + 对源文档的保真校验）。

### 3.2 缩放律（一条可直接引用的方法论结论）

因为架构/数据/训练都变了，最优训练区间也变了，所以报告**重做了缩放律研究**，重调 batch size、learning rate、**tokens-per-parameter（TPP）** 与 model shape，在 **held-out OOD** 验证集上拟合，得到相对 K2 的 **≈2.5× 整体 scaling 效率增益**。

**关于 cosine vs WSD 的结论值得单独记**：他们选择 cosine decay，并明确指出——已有工作报告 WSD 能打平甚至超过 cosine，但两者的最优超参差别很大；**用同一套超参比较会不公平地偏向某一方**。他们**对两种 schedule 各自独立搜一遍缩放律**，在各自最优下 cosine 的最终 loss 一致更低。这条对任何做训练配方选择的人都有直接价值：**schedule 比较必须先各自调到最优**。

### 3.3 训练配方与长上下文课程

- 优化：Per-Head Muon + K2 的 weight clipping；MoE 负载用 QB；cosine + **1% 线性 warmup**；weight decay 0.1。
- 原生多模态：语言与视觉**从训练一开始就联合优化**，视觉与文本 token 交错在同一个 NTP 目标里。
- **四阶段上下文课程**：预训练 8K → 64K；cooldown 阶段 256K → 1M。把昂贵的长序列计算压在总预算的小部分，同时让模型渐进适应长依赖。
- **长上下文数据不是「拼长」**：长文档/长视频先过专用清洗（精确 + 模糊去重、视频帧的感知哈希、启发式与分类器质量过滤、结构校验）；因为真长且连贯的文档稀有，**对长样本上采样**，防止长上下文分布被短序列淹没；并**合成置换拼接任务**，使任务**只有跨 1M 全窗口取信息才可解**——这是防止注意力退化成局部模式的关键手段。

## 4. 后训练：9 个专家 → 1 个模型

三段式：**SFT → RL（3 域 × 3 effort = 9 个专家）→ Multi-Teacher On-Policy Distillation（MOPD）合并**。

- **SFT**：沿用前代流水线但大幅扩展复杂 agentic 任务覆盖；用前代 Kimi 系列模型合成轨迹 + 多级验证 + human-in-the-loop 标注；全部数据用 **XTML（eXtensible Token Markup Language）** chat template 序列化；**QAT 从 SFT 起就开**。
- **RL 三域**：general（经验/视觉/推理/忠实性/搜索/知识工作）、general agents（长程助手/深度研究/段落级写作）、coding agents（SWE/编码体验/kernel/Web 开发）。
- **长尾延迟**：扩展现有同步 RL 框架的 **partial rollout**——不等全部轨迹终止，完成比例 `λ` 就进入策略优化，暂停轨迹入队下轮优先恢复（依赖 §5.3.2 的沙箱）。由此产生的数据陈旧问题用**逐 token 正则**在局部邻域内约束更新来容忍。
- **effort 档位怎么来的**：给每题一个 cold-start 模型估计的 token 预算 `b₀(x)`，轨迹总 token 超 `τ·b₀(x)` 就把奖励覆盖为 `−1`；先训大 `τ` 的 **max** 档（同时封顶抑制过度思考），再退火 `τ` 得 high / low。general 任务的 `T(y)` 只算 thinking token，agentic 任务算**累计输出**（推理 + 工具调用参数）。
- **不可验证任务**用 **Agentic GRM**：强制协议「读产物 → 生成 rubric → 按 rubric 打分 → 写入 scorepad」，并以「输出长度超 `σ·ℓ₀` 直接判负」抑制冗长型 reward hacking。
- **MOPD**（式 15）：给定 query 与已生成前缀，用**逐 token 的 OPD 奖励** `clip(sg(log π_teacher/π_θ), −R_max, R_max)`（`sg` 为 stop-gradient）作为稠密奖励，天然兼容 partial rollout。报告说也试过更细粒度的 top-k 蒸馏目标，**在收敛速度与最终性能上都没看到明显优势**——这是一个有用的负结果。
- **部署相关**：MoE 专家权重 **MXFP4**、激活 **MXFP8**，非专家部分（注意力投影、latent MoE 投影、共享专家、router）保持高精度；QAT 贯穿整个后训练，**rollout 与训练同量化**以消除训练-推理失配；把预训练就有的 **MTP 层**微调成 **EAGLE-3 draft**，直接用**接受率的负对数（LK loss，式 16）**优化而非 KL 代理，训练期 unroll 7 步，draft 输入融合第 1/4/末个 AttnRes block 的低/中/高层特征（初始化 `W_E3 = [0 0 I]`）。

**RL 环境侧的新东西**（比模型本身更可能被后来者复用）：

1. **统一白盒 RL 环境**：把 harness 拆成工具接口 / 系统提示 / 上下文管理 / skills / memory / subagent 等可配置模块，可配置出 **Kimi Code、Claude Code、Codex、OpenClaw、Hermes** 等——**防止对单一 harness 过拟合**。
2. **知识图谱驱动的任务合成**：DAG 形式递归扩张概念图（agent 逐节点检索、去重、细化到原子概念），按粒度采样节点组合检索真实材料再合成任务。
3. **Kernel 优化任务 + 反 reward hacking**：覆盖 CUDA / Triton / CuTe DSL / Gluon / ThunderKittens / TileLang，BF16/FP8/FP4；奖励同时看正确性（超数值误差阈值直接 0）与性能（对齐专家实现得 0.5，逼近 roofline 趋近 1）；**专门检测 CUDA graph replay、输入缓存、降精度等作弊并惩罚**。
4. **Mock 版个人助理长程任务**：Gmail / Notion / Slack / Canvas 的「语义保真 mock」实现，多模拟日、数十个相互依赖事件；**单条 rollout 可达数千次工具调用、数百万上下文 token**。
5. **AET（Autonomous Execution Tasks）**：奖励只认 **verifier 对最终环境状态**的判定，不认模型自述完成；反作弊靠「agent 与 verifier 隔离 + 公开 verifier 给诊断反馈 / 隐藏 verifier 评 held-out 场景 + 有限提交预算下的惩罚」。

## 5. 基础设施：三个不能被绕过的瓶颈

| 瓶颈 | 手段 | 关键设计点 |
| :-- | :-- | :-- |
| KDA 的递推形态 | 融合 kernel；**KDA Context Parallelism**；**state-aware prefix caching** | 常规 prefix cache 假设可重放的 KV 张量，KDA 是**递推状态**，缓存语义不同；已向 vLLM 社区提交实现，随模型发布 |
| 3T 级 MoE 预训练 | **MoonEP**（完全均衡 EP）+ 内存高效训练 + 视觉编码器优化 | 每 rank 必须恰好收到 `S×K` 个 token 才能计算量相同；证明**每 rank 至多 `E/R` 个冗余专家**的均衡方案总存在且该界本质紧；预留 `E/R` 个冗余专家位即可保证规划永远可行、训练不中断 |
| 1M agentic RL | partial rollout + 外部 KV-cache 保留 + 自适应限流 + **可恢复 microVM 沙箱** | 单条长轨迹跨多个训练迭代，模型与环境状态都要能续 |

- **MoonEP 与既有方案的差别**（报告明确对比）：ECHO / UltraEP 这类工作**预设**冗余专家数量或给每 rank 加 token 上限，一旦无可行规划就必须停训，且上限要手调；MoonEP 改成**在线规划 + 冗余专家迁移**——前向用当前 micro-batch 与本层的 router 输出规划并预取冗余专家，反向在本地 reduce buffer 暂存梯度、算完后归约回 home rank。§E 给了上界证明。
- **训练并行组合**：PP（含 virtual stages）+ EP + ZeRO-1 DP + Pipeline ZeRO-2 梯度分片 + CP；共享专家在 EP rank 间复制；all-to-all 与计算重叠。
- **推理侧**：专家特化 kernel、cache-aware 与 budget-aware 的机群调度；官方建议部署在 **64 卡以上 supernode** 以扩大高带宽通信域。

## 6. 评测：必须带条件读的数字

**统一条件（模型卡脚注）**：K3 全部结果取 **reasoning effort = max、temperature = 1.0**；单步任务（GPQA Diamond、HLE-Full、无工具的视觉基准）`top_p = 0.95`，agentic 任务 `top_p = 1.0`；harness 按基准在 **Kimi Code / Claude Code / Codex** 中指定。

### 6.1 K3 自身结果及其测量条件

| 基准 | Kimi K3 (max) | 测量条件 |
| :-- | --: | :-- |
| GPQA Diamond | 93.5 | 单步、无工具 |
| HLE-Full | 43.5 / 56.0 | 无工具 / 带通用工具 |
| DeepSWE (v1.1) | 67.5 | Kimi Code harness；mini-SWE-agent 下 67.3 |
| Terminal-Bench 2.1 | 88.3 | K3 使用 Kimi Code；原报告各模型的 harness 选择不同 |
| SWE-Marathon | 42.0 | H20 校准分支 |
| MLS-Bench-Lite | 48.3 | H20 上 3 次平均；该基准官方设定为 H100 |
| Kimi Code Bench 2.0 | 72.9 | 内部基准；换 Claude Code harness 时为 73.7 |
| BrowseComp | 91.2 / 90.4 | 300K 触发上下文压缩 / 满 1M 不压缩 |
| MCPMark-Verified | 94.5 | 公共 500 任务子集，100 轮限制 |
| Video-MME (w. sub) | 90.0 | 3 次平均 |
| ZeroBench (pass@5) | 23.0 / 41.0 | 官方设定，跑 5 次 |

### 6.2 五处必须带条件引用的数字（正文口径）

1. **DeepSWE 67.5**——条件：**Kimi Code harness + max effort**；换 mini-SWE-agent 是 **67.3**。这说明 harness 选择会改变测量结果，不应把单个分数当作模型固有属性。
2. **SWE-Marathon 42.0**——条件：**H20 校准分支**（Docker 镜像、性能门槛、GPU 任务的参考 oracle 都按 H20 重标，正确性与反作弊校验器不变）。
3. **MLS-Bench-Lite 48.3**——条件：**H20 而非官方设定的 H100**，3 次平均；硬件与重复次数都属于结果协议。
4. **BrowseComp 91.2 / 90.4**——条件：**91.2 是启用 300K 触发上下文压缩后的分数**；「满 1M 不压缩」是 **90.4**。两条不能混用。
5. **Kimi Code Bench 2.0 72.9**——条件：**内部自建基准**；换 Claude Code harness 时为 **73.7**，说明内部基准与 harness 细节应一并披露。

## 8. 失效边界（独立段）

1. **对 thinking history 高度敏感（官方明示）**：K3 在 **preserved thinking history** 模式下训练。harness 若不按要求回传**全部**历史思考内容，或把**别的模型正在进行的会话中途切到 K3**，生成质量会**高度不稳定**。官方建议只用已验证兼容的 harness（如 Kimi Code），并**避免中途切换**。这条是部署方的硬约束，不是「建议」。
2. **过度主动（excessive proactiveness，官方明示）**：长程任务训练导致模型遇到小问题/歧义意图时**替用户做决定**。需要严格边界的应用必须在 system prompt / `AGENTS.md` 里显式约束。
3. **effort 档位不完整**：模型卡结果按 max 档报告；不能据此推断其他 effort 档或产品默认设置的表现。
4. **2.78T 的可及性门槛**：权重虽已公开，完整参数规模与 MXFP4 部署仍要求较高的硬件资源；官方建议 ≥64 加速器 supernode。权重可获取与可独立复现并非同一条件。
5. **本分册的证据边界**：主表数字均为厂商自报；SWE-Marathon 用 H20 校准分支、MLS-Bench-Lite 在 H20 上跑 3 次，均非独立重测。论文没有逐项量化六个架构/训练选择对整体收益的贡献；约 2.5× scaling efficiency 是作者报告的架构、数据与训练联合结果。
6. **架构结论的可迁移性**：下界衰减与 QB 有各自的机制推导或消融支撑；但「2.5× scaling 效率」是**打包结论**（架构 + 数据 + 训练配方一起），报告**没有**给出逐项拆分的贡献量化——引用时不能把它归因到单一改动。

## 9. 引用注意（何时不该引它）

- **不要**把单个 benchmark 分数当作模型固有能力：harness、硬件校准、fallback 和采样设置会改变测量条件。
- **不要**单独引「K3 的 BrowseComp 91.2」而不说 300K 压缩条件；不压缩时是 90.4。
- **不要**把 max 档数字当默认档；发布时无 low/high。
- **不要**说「MoonViT 从零训练更好」——原话是在视觉评测上**持平** SigLIP 初始化，收益在**更稳 + 省掉对比预训练依赖**。
- **可以**大胆引的是方法论类结论：cosine vs WSD 需各自调优；长上下文需合成「只有全窗口可解」的任务；反 reward hacking 要设计在奖励函数里；harness 模块化可防止过拟合。
