# GPT：从生成式预训练到推理与多模态系统

> GPT 系列的研究脉络不只是模型规模增长。它经历了几次对“能力放在哪里”的重新定义：先让同一个生成模型适配多个 NLP 任务，再让提示承担任务接口；随后用人类反馈改变回答行为；近年又把更多计算放到推理时，并将图像、音频与视频纳入可交互系统。
>
> 本报告以公开原始论文、技术报告和 system card 为据。GPT-4 之后，OpenAI 通常不公开足以复刻架构、参数规模与训练配方的细节，因此把官方描述的能力与已知机制分开。GPT-5/5.5/6 的型号更新只在能说明系统接口或公开证据边界时提及，不据发布节奏推断内部架构。

## 阅读地图：GPT 研究不断改变“模型能力”的位置

| 研究问题 | 代表工作 | 变化在哪里 |
|---|---|---|
| 预训练能否替代任务专用模型？ | GPT-1 → GPT-2 → GPT-3 | 统一 next-token objective，增加规模与数据，逐步从微调转向提示和上下文示例 |
| 生成能力怎样变成可遵循的助手行为？ | InstructGPT → ChatGPT | 示范数据、偏好排序、奖励模型与 PPO 把“续写文本”转换为“按指令作答” |
| 难题能否通过更多推理时计算解决？ | o1 → o3/o4 → GPT-5 thinking | 将 RL 后训练和 test-time compute 作为新变量；后续系统再由 router 决定何时使用深推理 |
| 视觉、音频和视频怎样进入生成系统？ | GPT-4V、GPT-4o、Sora、后续系统卡 | 从可输入图像的文本模型，到官方称端到端处理多模态的模型；视频生成仍有独立 DiT 路线 |
| 闭源模型的能力如何评价？ | GPT-4 技术报告与各代 system card | 公开材料从架构论述转向基准、安全评估和系统行为，研究者必须把未知保留下来 |

这几条线互相交叉，但不可混为一谈。GPT-4o 的实时语音能力不是“推理模型”的同义词；Sora 的视频生成架构也不是已披露的 GPT 文本模型内部模块；GPT-5 的统一用户入口不能说明底层只有一个网络。

## 一、生成式预训练：从任务微调到提示学习

### 1.1 GPT-1：先预训练语言，再用少量任务标记微调

GPT-1 的核心贡献不是参数规模，而是把 Transformer decoder 的自回归语言建模用于大规模无标注文本，再用带标签的任务数据微调同一主干。预训练阶段预测下一个 token，给模型建立通用语言表示；下游阶段通过调整任务输入格式和微调参数完成分类、自然语言推断、问答等任务。[GPT-1, §§2–3]

这个两阶段过程相比每个任务从头训练不同架构更统一，但每个新任务通常需要一份专门微调后的模型。它把“模型能力”主要放在预训练权重和任务特定的后训练里，提示本身仍不是核心的学习接口。

### 1.2 GPT-2：任务描述开始成为输入格式

GPT-2 延续因果语言建模目标，并扩大模型与网页文本数据。关键变化是论文系统性测试：能否把翻译、摘要、问答等任务写在文本上下文中，让模型在不做任务微调时尝试完成任务。提示像“Translate to French:”或摘要前缀，为模型提供任务线索；模型仍只训练“预测下一个 token”，并没有显式的 task head。[GPT-2, §§1–3]

这带来一个重要变化：模型不只是把语料知识压进参数，还能在上下文中识别任务模式。GPT-2 的零样本能力不等于它已能稳定遵循任意自然语言指令。论文同时显示能力随规模变化、不同任务提升不均，也报告模型对长文本生成、事实可靠性和偏见的局限。[§3–4]

### 1.3 GPT-3：in-context learning 成为模型使用方式

GPT-3 把相同的自回归预训练范式扩展至 175B 参数，并将评测重点放在 zero-shot、one-shot 和 few-shot 提示上。模型不更新参数，而是在 prompt 中读取任务描述与若干例子，接着预测新例子的答案；上下文示例就像临时写入的任务说明。[GPT-3, §§1、2、3]

这让模型使用可以被看成一种“临时任务适配”：用户在输入中给出任务描述、示范输入输出和新问题，模型根据上下文预测后续文本。它减少了为每个任务维护一份微调 checkpoint 的需求，但也把负担转移到提示设计和上下文长度。示例的顺序、格式、任务是否与训练分布相近，都会影响结果；一旦任务需要大量新知识或超出上下文窗口，few-shot 不会自动补足能力。

GPT-3 的论文还把性能随模型规模、训练数据和计算量变化作为重要观察，呼应此前的 scaling law 研究。这里的研究结论是：在论文测试的多个 benchmark 上，扩大规模常能改善任务无关的少样本效果；它没有证明所有能力都连续、均匀地随参数增长，也没有把“突然涌现”与基准阈值效应完全区分开。不同规模模型训练 token 数、评测提示和基准污染都影响曲线解释。[§3、§4]

这与微调不同：微调把任务信息写入模型参数；in-context learning 把它保留在当前输入上下文中。GPT-3 论文报告，许多任务的少样本表现随模型规模改善，但收益高度依赖任务、提示和示例选择。它并未说明模型获得了稳定的任务算法，也没有消除事实性、算术推理和基准污染等问题。[§3–4]

GPT-1→2→3 因此不是“同一个模型越来越大”的完整解释。变化来自三处：预训练数据与容量扩大；任务接口从微调逐渐移到文本提示；评估也从单任务微调效果转向模型是否能从上下文归纳任务。后来的对话对齐仍需解决“模型会续写，但未必按用户意图回答”的行为问题。

## 二、对齐：把偏好反馈加入预训练模型

### 2.1 InstructGPT：示范、比较、强化学习各解决一类问题

InstructGPT 论文提出一个清楚的三阶段流程：[InstructGPT, §§3–4]

1. **SFT 示范微调**：标注者对 API 用户提示编写期望回答，训练模型模仿这些回答。
2. **偏好数据与奖励模型**：对同一提示的多个模型输出排序，让奖励模型学习哪些回答更受标注者偏好。
3. **PPO 优化**：以奖励模型分数为信号继续调整 SFT 模型，同时用 KL 约束限制策略偏离原模型过远。

按论文给出的数据量，SFT 有约 13K 训练提示，奖励模型阶段约 33K 提示，PPO 阶段约 31K 提示。三类数据并非都来自同一分布：示范数据包含 API 与标注员提示，偏好比较在更广的 API 提示上收集，PPO 再从这些提示中采样回答。理解数据来源很重要，因为最终模型更像在特定实际请求分布上学会用户偏好，而不是在抽象“全任务”上统一对齐。[§3.2–3.4]

奖励模型的任务是从两个候选回答中预测标注者更喜欢哪个，再把排序偏好转成策略梯度可以使用的分数。它学到的是相对排名，而不是绝对正确性；如果标注者偏好详细、流畅但错误的答案，RM 也可能把这种特征奖励给策略。PPO 中 KL 项约束新策略别离 SFT 基线太远，可减轻奖励黑客和输出分布崩坏；论文还发现混入少量预训练目标有助于缓解公开任务回退。这使 RLHF 成为一个有偏好收益、也有能力回退风险的优化问题。[§3.1、§4.2、附录E.6]

三阶段不是重复做同一件事。示范让模型掌握回答形式；排序反馈覆盖多种合理答案之间的相对偏好；PPO 则尝试把偏好推广到新的输出。论文强调其对齐对象是特定提示分布中、由标注者表达的偏好，并不等同于一个普适的“人类价值函数”。

InstructGPT 的经典结果是：在论文所抽取的用户提示分布上，标注者更偏好 1.3B 的 InstructGPT，而不是 175B 的基础 GPT-3。这个结果支持“后训练对助手行为的影响可能大于单纯扩大参数”的判断，但只针对论文人评任务和偏好定义；它不表示 1.3B 模型在通用知识、推理或所有任务上超过 175B GPT-3。[§4.1]

实验设计本身解释了这个结果的意义。论文从 API 提示和标注者撰写的提示构建分布，让标注者比较不同模型的答案，再用偏好判断训练奖励模型；评估也主要问哪种回答更适合作为助手，包括是否跟随明确约束、是否合适、是否真实和是否有害。它没有用一组纯学术 QA 分数代表所有助手质量，而是直接测模型对实际请求的回应偏好。[§3.2–3.6]

同一研究还显示偏好目标有边界：PPO 模型在人类偏好上提高，却可能在 SQuAD、DROP 等公开任务出现小幅退化；预训练数据混合可以缓解部分退化，但也会改变奖励优化结果。安全表现还取决于输入提示和 system prompt；论文发现，模型在被明确要求保持尊重时更少生成有毒内容，而去掉这类提示后优势会缩小。这提醒我们，偏好微调不是把一个“价值函数”写入模型，而是在特定数据与约束下塑造输出分布。[§4.2、§5.1、附录E]

论文也报告了取舍：对齐版本在若干公共 NLP benchmark 上有轻微退化，且某些安全和真实性行为会因提示方式变化。SFT/RLHF 提升可用性，但也会把数据标注者、任务分布、奖励模型盲点带入系统。

对齐结果还受“谁在偏好”影响。论文明确指出，训练反映的是标注者和研究团队设定的偏好，并非对所有人价值的完整代表；标注者也可以跳过模糊问题。它通过 held-out 标注者检查模型偏好是否只记住训练标注者，但仍不能覆盖语言、文化、专业角色和用户群体的所有差异。安全评估方面，RealToxicityPrompts 使用特定提示采样规则，论文提醒绝对毒性数值会因抽样方式而改变。这些限制让 InstructGPT 成为可复用的训练框架，不是一个一次性解决对齐问题的配方。[§3.4、§5.2、附录E.10]

### 2.2 从对话助手到更复杂的对齐方法

ChatGPT 将指令模型放入多轮对话界面；GPT-4 等后续报告通常把 SFT、偏好对齐、安全分类器和产品层缓解作为系统的一部分描述。随着模型能力增加，单纯用“有帮助/无帮助”的回答排序难以表达复杂安全规则，因此研究出现基于规则的奖励、AI反馈和 deliberative alignment 等方向。

Deliberative alignment 的研究重点是让模型在作答前把安全规则作为推理时可读的条件，并在推理中应用这些规则。它与纯粹在输出端加分类器不同，也不等于 system prompt 本身已经解决对齐：论文的实验结论应限定在给定的规则、模型和评测任务中。它提供的是一种训练和策略设计，而不是对所有部署中“安全”的证明。[Deliberative Alignment, §§2–4]

更广的教训是：对齐问题同时涉及模型目标、偏好数据、奖励模型和部署环境。相同的语言模型，在训练反馈、系统提示、工具权限和使用者输入不同的情况下，可能呈现不同的安全与有用性。

## 三、架构不透明时代：GPT-4 之后能确认什么

### 3.1 GPT-4：能力报告没有给出模型结构

GPT-4 技术报告将其描述为可接受文本和图像输入、输出文本的大规模多模态模型。报告集中展示考试、基准和安全评估，但明确不披露架构细节、模型规模、训练计算量和数据集构成。[GPT-4 Technical Report, §§1、2、5]

因此，GPT-4 之后围绕参数量、MoE 专家数或具体训练 token 数的数字，如果只来自第三方推测，不能写成官方技术事实。即使某种架构猜测能解释基准表现，也不应将“观察到的能力”直接等价为“确认了内部结构”。

GPT-4 技术报告有教学价值的地方，是公开了研究者能看到的边界：相同 benchmark 的能力提升可以观察，但数据和架构无法复核；模型对图像的输入能力可以在系统层面确认，但内部视觉编码与融合层仍未知。这与 GPT-1/2/3 有大量训练信息的阶段构成公开程度变化。

报告仍然提供了一些可讨论的实验结构：GPT-4 与上一代模型在传统学术 benchmark、专业考试、内部对抗测试和多模态输入上进行比较，且在多个考试条件下区分了 zero-shot、few-shot 或经专门 prompt 诱导的设置。结果能说明模型在所测项目中提升，但由于训练数据、训练计算和结构未公开，不能通过报告反推这些进步究竟来自更多参数、数据质量、训练目标、数据混合或工程系统。这个“能力可测、机制不可归因”的状态，是后来闭源旗舰报告的共同阅读边界。

### 3.2 GPT-4V 到 GPT-4o：从图像输入到端到端多模态

GPT-4V system card 对图像输入、能力和风险提供系统级评估，但没有披露足以确认视觉编码器、投影层或融合位置的架构细节。因此，“ViT + projector + LLM”只能作为同代常见设计的示意，不能归为 GPT-4V 已公开架构。[GPT-4V System Card](https://openai.com/index/gpt-4v-system-card/)

GPT-4o 的 system card 则明确称它是 autoregressive omni model：输入可以组合文本、音频、图像和视频，输出可以组合文本、音频和图像；训练端到端覆盖文本、视觉和音频，并由同一神经网络处理输入和输出。官方描述支持“多模态处理不再只是把外部 ASR/TTS 结果串到文本模型”的系统判断，但没有披露离散 token 方案、各模态编码器细节或模型参数量。[GPT-4o System Card, Introduction]

因此应将两代变化写成“官方披露程度与可见能力发生变化”，不要进一步编造“统一 token 流”的具体内部表示。system card 还强调语音响应延迟和安全评估，这些描述的是端到端交互体验与部署风险；它们并不能单独证明语音识别、生成和轮次管理完全由同一机制完成。

## 四、推理时计算：o1 把更多计算放在回答之前

### 4.1 研究问题从“训练更大”转向“推理时多想一会”

o1 系列的研究叙述是：通过大规模强化学习，模型学会在回答前使用更长的链式推理；OpenAI 报告其表现随训练时计算增加而提升，也随测试时“思考”时间增加而提升。[Learning to Reason with LLMs]

这扩展了传统 scaling 讨论：预训练计算决定模型学到的基础能力，推理时计算决定单次问题可以投入多少搜索/生成预算。用户能观察到的是输出前延迟、推理长度和指定任务准确率的变化；公开材料没有说明 o1 是否采用外显搜索树、多个候选链投票、某种 verifier 结构或何种内部奖励模型。把这些机制写成事实会超过证据。

这一点和早期 Chain-of-Thought prompting 有区别。CoT prompting 是让既有模型在 prompt 里示范“分步解题”；o1 的公开描述则把大规模 RL 训练和回答时延长思考共同作为模型能力提升的来源。测试时增加预算能让生成过程继续尝试、修正和展开推理，但并不等于传统程序搜索；外显 reasoning token 是否逐一对应内部计算步骤也没有可复核公开材料。因此，更准确的技术表述是“推理策略经过 RL 训练，并在推理时增加计算投入”，而不是“官方证明模型内部运行了某种搜索树”。

官方在 o1 文章中特别说明，除非另有说明，其 benchmark 使用最大测试时计算设定；部分图表还同时呈现 pass@1 与 64 样本多数投票。因而引用结果时要保留推理预算和聚合协议。高预算结果说明系统可以通过更多推理时间提升给定任务表现，不代表默认配置或普通对话也有同样增益。[Learning to Reason with LLMs, Evals]

训练时计算和测试时计算也不是可直接互换的两种 token 预算：前者改变模型参数与策略，后者在固定参数下增加单个请求可进行的推理。OpenAI 展示两者上的性能提升曲线，支持它们都能在其测试任务上增加得分；但响应延迟、推理成本、可用任务类型和边际收益不同。若一个论文只报告 max-compute 结果而未给普通预算下的曲线，读者就不能判断默认用户拿到多少提升，也不能仅凭最高分推断单位计算效率。

### 4.2 与 InstructGPT 的区别：偏好奖励和可验证结果

InstructGPT 的奖励来自人类对回答偏好的排序；o1 的官方材料则强调通过强化学习改进推理，并展示数学、编程和科学 benchmark 上随计算投入变化的表现。两者都使用后训练，但优化目标不同：一个更直接地使回答符合标注者意图，一个试图让答案在具有可验证标准的任务上更正确。

这也带来不同的失败边界。人类偏好难以定义数学题唯一正确答案之外的表达质量；可自动验证的任务便于规模化反馈，却容易把训练范围集中在能被程序判分的题目。推理时延增加也不保证对模糊开放问题、事实检索或工具调用等任务同样有效。

### 4.3 GPT-5 Router：统一的是系统入口，底层仍有多个模型

GPT-5 system card 描述一个 fast/main 模型、一个 thinking 模型，以及根据对话复杂度、工具需求和用户意图进行选择的实时 router；卡片还说明模型之间的承接关系。公开材料因此支持“统一系统通过路由调度不同能力”的判断，但它没有说所有模式已合并成单一参数网络。[GPT-5 System Card, §§1–2]

从研究角度看，router 是模型外部的控制策略：简单请求可用低延迟模型，复杂推理转交给更深的推理模式。它把选择问题也纳入质量与效率：路由错了，会出现不必要的长推理或难题预算不足。公开 system card 表明路由器利用用户切换、偏好和正确性等信号持续训练，但它没有披露完整路由器架构、损失函数或误路由率。

GPT-5.5、GPT-6 等后续 system card 继续公开安全和能力评估，但没有系统公开网络架构、参数规模和训练配方。对阅读者而言，这些型号可以说明官方如何定义模型能力、风险和工具边界；不应仅根据型号变更推断新的预训练架构或算法范式。

GPT-5 system card 的对应表将 GPT-4o、o3、o4-mini 等前代能力分别映射到 main、thinking 及其轻量版本。这是系统级继承关系，不足以证明它们共享同一权重或通过某种蒸馏方式合并。读者应把“统一入口”理解为交互和路由层的融合，除非技术报告进一步披露底层网络结构。

对后续代际的阅读可以采用两层证据法：第一层只记录 system card 直接披露的接口、评测项目、评测条件和安全判断；第二层才讨论可能的训练或架构解释。若第二层没有论文、技术报告或代码支持，就明确保持未知。这样可以保留对模型实际能力的学习，同时避免把安全卡、发布博文或型号名称误当成架构论文。

## 五、多模态旁支：GPT-4o 与 Sora 是两种不同的生成问题

### 5.1 GPT-4o：低延迟交互中的多模态输入输出

GPT-4o 的重点不止“多了图像或音频输入”，而是同一个 autoregressive omni model 接受和生成多种模态组合。系统卡重点分析 speech-to-speech、语音身份、无根据推断和语音内容安全等新风险。[GPT-4o System Card, §§1、3]

传统语音助手常把语音识别、文本语言模型、语音合成接成流水线。端到端 omni 模型的潜在优势，是在单个网络内利用声学信息、说话方式和对话上下文共同生成响应，从而降低串联环节带来的延迟与信息损失；但端到端也让错误来源更难定位——一次不当回答可能来自语音识别、语义判断、声调理解或生成策略。GPT-4o system card 因而专门评估未经授权的声音生成、说话人识别、敏感属性推断及语音安全，而不只沿用文字安全基准。

官方 system card 报告音频输入的最低响应延迟约 232ms、平均约 320ms。这个数字是官方描述的产品模型语音响应，不代表每个硬件、网络和轮次都达到相同延迟；它与实验室模型吞吐也不是同一个指标。将语音能力视作“实时对话系统”时，首响应延迟、轮次管理和安全策略都属于研究对象。[GPT-4o System Card, Introduction]

同一模型处理多模态的好处，是减少把识别、文本推理、语音合成串联起来时的信息损失和延迟；风险是不同模态的评测与安全边界也需要同时覆盖。OpenAI system card 的安全评估重点放在语音，但仍将多模态风险拆成不同类别；研究者不能只用文本 benchmark 代表整个 omni 系统。

### 5.2 Sora：视频生成使用时空 patch 的扩散路线

Sora 的技术文章把视频模型描述为 diffusion transformer：视频和图像被切成时空 patch token，在统一表示中处理不同分辨率、时长和宽高比；模型由噪声逐步生成视觉内容。其研究目标是生成可由文本、图像或视频条件控制的连续视觉序列。[Sora: Video generation models as world simulators]

与 GPT-4o 的多模态输入输出相比，Sora 将扩散过程用于时空内容生成：文本条件定义所需场景，DiT 在压缩的时空 patch 上预测去噪方向，再还原为视频。统一 patch 形式使图像和视频能共享一类视觉表示，并支持不同长宽与时长输入；但高分辨率、长时间和多物体连续性都会推高计算与数据需求。公开文章展示的是架构思路和生成样例，没有提供完整训练规模、全部训练数据或足以验证“世界模型”主张的物理预测实验。

因此，将 Sora 称为“world simulator”应作为研究愿景而非已证实能力。视频片段看起来自然，并不能单独证明模型能在给定初始状态下预测真实世界未来；需要任务明确、可重复的状态预测与反事实评测，才能区分视觉连贯与物理建模。

Sora 与 GPT 主线的关系是多模态研究并行，而非已经证明共享 GPT 主干。OpenAI 的文章把视频生成与“世界模拟器”联系起来，但这属于研究假设与观察，不等同于已经验证了物理世界模型。视频的像素连续性、物体身份、时间一致和动作因果都需具体评价；生成逼真的片段不自动意味着模型能预测真实世界状态。

GPT-4o 关注多模态理解与实时对话，Sora 关注条件视觉序列生成；将两者合并成“原生全模态 GPT”会掩盖不同的表示、训练目标和评测任务。

## 六、跨代综合：研究目标改变了什么

| 阶段 | 能力主要放在哪里 | 研究方法 | 结论边界 |
|---|---|---|---|
| GPT-1 | 预训练参数 + 下游微调 | causal LM 预训练、任务微调 | 通用底座迁移有效，但任务仍需单独训练 |
| GPT-2/3 | 模型规模 + 输入上下文 | zero/few-shot 提示 | 同一模型可执行更多任务，效果仍依赖任务与示例 |
| InstructGPT | 人类示范与偏好反馈 | SFT → reward model → PPO | 助手行为可被后训练显著改变，但只对特定标注偏好和提示分布成立 |
| GPT-4 | 公开可见的能力评估 | 技术报告 / system card | 能力和风险可观察，架构及训练规模未知 |
| o1 | 推理后训练与 test-time compute | RL + 更长思考预算 | 特定复杂任务随计算投入改善；内部搜索机制未公开 |
| GPT-5 | 模型选择与系统路由 | fast/thinking 模式 + router | 统一的是任务入口和调度体验，不足以证明一个模型取代全部专用模型 |
| GPT-4o / Sora | 多模态交互或连续视觉生成 | autoregressive omni model / diffusion transformer | 同属多模态研究，但任务目标、生成方向和证据材料不同 |

这些变化揭示了 GPT 研究的三个层次：

1. **模型能否从预训练中迁移任务**：从微调转到提示学习，研究焦点由学习新权重改成使用上下文。
2. **模型是否按人类意图回答**：对齐不只是扩充知识，而是改变模型选择什么回答以及如何处理约束。
3. **模型部署时如何分配计算**：推理时计算与路由将效率/能力分配纳入系统设计，但也增加了新的评测变量。

“规模定律”仍能解释预训练损失与计算的关系，但它不足以单独描述 instruction tuning、推理预算、模态接口或 router 带来的系统变化。

## 失效边界与开放问题

- **提示学习并非显式算法学习。** GPT-3 的 few-shot 结果表明上下文示例有效，但不能单凭准确率判断模型内部是否形成可泛化的任务程序。
- **偏好对齐改变的是行为分布。** 人类标注样本有限且来自特定群体、任务和规则；偏好更高不等于知识更准确，也不自动表示更安全。
- **test-time compute 要连同评测预算报告。** 最大推理时间、采样次数、工具权限和投票方案变化都能改变结果，分数不是脱离预算的模型常数。
- **系统路由需要整体评估。** GPT-5 的 benchmark 可能涉及 router 选择和具体子模型；只有模型组件固定、路由条件透明时，才能判断提升来自何处。
- **闭源架构使机制归因变弱。** GPT-4、o1、GPT-5 之后的 system card 能帮助分析能力和风险，不能恢复完整网络与训练过程。
- **“全模态”不是单一任务。** 图像理解、实时语音、长视频输入和视频生成分别要求不同的数据、表示和评价。

## 推荐阅读顺序

1. GPT-1 与 GPT-2：从预训练—微调过渡到以提示描述任务。
2. GPT-3：读 few-shot 设置与 scaling 结果，分清示例学习和参数更新。
3. InstructGPT：跟读示范、排序、reward model、PPO 的训练闭环及其数据边界。
4. GPT-4 Technical Report 与 GPT-4o System Card：比较模型能力的公开材料从技术报告转向 system-level 描述。
5. o1 发布材料与 GPT-5 System Card：分别理解 test-time compute 和 fast/thinking router。
6. 最后读 Sora 视频生成材料：与 GPT-4o 对照多模态理解和时空内容生成两类问题。
