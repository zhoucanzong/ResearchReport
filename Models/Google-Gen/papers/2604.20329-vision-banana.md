# Vision Banana：把「视觉任务输出」压成 RGB，让图像生成器当视觉骨干（arXiv:2604.20329）

> **一手来源**：**Image Generators are Generalist Vision Learners** = arXiv:2604.20329 **v3**（2026-06-03T18:02:24Z，本轮引用版本；v1 2026-04-22T08:23:48Z / v2 2026-05-13T22:46:31Z）；正文 HTML 全文逐节读取（8 表 + 12 图 + 附录 A–D），参考文献条目逐条核对。配套一手：项目页 [vision-banana.github.io](https://vision-banana.github.io/)（Overview / Capabilities / Results / Contributors / BibTeX）、Google 官方博客 [Introducing Nano Banana Pro](https://blog.google/innovation-and-ai/products/nano-banana-pro/)（2025-11-20，即论文参考文献里的 Google 2025a）。｜ **主等级**：`[精读原文]`
> **一句话定位**：它不是在「加一个分割头」，而是把**视觉任务的输出空间整体换成 RGB 图像**——分割是"给每类一个颜色"，度量深度是"用一条可逆假彩色路径表示米"，表面法向是"把单位向量写进 R/G/B 三个通道"；然后在 **Nano Banana Pro（NBP）** 的原训练混合里**极低比例**掺入视觉任务数据做 instruction-tuning，得到一个权重共享、只靠 prompt 切任务的单一模型 **Vision Banana**。
> **亮点与差异四行**
> - **一句话亮点**：用「**输出即图像**」这一条参数化，把 2D 语义/实例/指代分割与 3D 度量深度/表面法向五件事压进同一个生成器的同一个输出空间，并且**解码回可算指标**——这是它与「生成器特征可做理解」那类论文最本质的区别（那些工作无法产生可被标准 benchmark 打分的输出）。
> - **新在哪**：① 一条**可逆**的深度↔RGB 双射（power transform + 沿 RGB 立方体棱的分段线性路径，λ=−3、c=10/3），使"生成一张彩色图"严格等价于"预测米制深度"；② 实例分割用「只给目标类和背景色、让模型自己分配实例颜色」+ 一套**多阶段连通域算法**把生成图还原成离散 mask；③ 把 instruction-tuning 的"轻"定义为**在原训练混合里低比例掺数据**（而非丢掉生成数据做全量微调），并报告与基座接近的人评胜率；缺少样本量、置信区间和等效性检验，不能据此证明生成能力未退化。
> - **证据强度**：**中偏强，但有一处结构性缺口**——五类任务的绝对数字都在论文内自洽（我逐张表复算了平均值恒等式，全部吻合，见 §4.5/§4.6 与 §10），且明确写了"评测基准训练集未进训练混合"；**但全篇没有一个真正的消融实验**（没有数据比例消融、没有任务数消融、没有解码鲁棒性消融、也没有"未 instruction-tuning 的 NBP"这一关键对照），模型细节（训练步数、学习率、是否冻结参数、生成分辨率）**一律未披露**。
> - **值不值得引用**：值得，但只能引用**它自己的零样本口径下的绝对分数**，并同时带走三个条件——「平均值口径（不是逐数据集全胜）」「实例分割依赖 Gemini 3.1 Flash-Lite 做存在性判定」「指代推理依赖 Gemini 2.5 Pro 转写查询」；**不要引用"Vision Banana 全面超过 SAM 3"**（SA-Co/Gold 上它就是输的，且论文自己承认），**也不要把它当可复现的方法论**（NBP 权重与训练混合都不可得）。

## 1. 问题设定：缺的不是"证据"，是"可打的分数"

论文把已有工作分成三段，这个分法本身是有用的判据（v3 §1）：

1. **"特征里有理解"类**（StyleGAN knows normal/depth、diffusion 特征做对应、各类 probing）：证明表征含信息，但**不产生标准任务输出**，因此无法进 benchmark。
2. **"能画出理解的 RGB 可视化"类**（Zuo et al., 2025；Wiedemer et al., 2025）：开放式生成能画出"像分割图/深度图"的东西，但**不严格遵守 prompt 的格式约束**，输出没法反解成可打分的量——"not provide state-of-the-art results on modern benchmarks"。
3. **"改架构做全量微调"类**（He et al., 2024/2025；Ke et al., 2024；Ye et al., 2024；Yu et al., 2024；Zhao et al., 2025 等）：加专用模块、全量微调，单任务能到 SOTA，但**牺牲跨任务通用性与生成能力**。

于是它的目标函数写得很清楚：**保持"一个模型、一套权重、只换 prompt"，同时让输出落到"可被 standard benchmark 打分"的格式里**。这句话的落地方式就是"输出 = RGB 图像 + 一个任务相关的逆映射"。

> **判据上的一个细节值得记住**：论文对"zero-shot transfer"的定义不是自造的，而是显式声明"遵循 Segment Anything 与 CLIP 的用法"——即**未在该 benchmark 的训练划分上训练**。所有对照方法里，"Non Zero-Shot Transfer"一律置灰。这条定义是本章后面所有"超过"结论的成立前提，也是最容易被二次转述时丢掉的一句（v3 §3.1）。

## 2. 方法：三条设计约束，一套解码器

### 2.1 "输出即 RGB"要同时满足三件事

论文给的表述是：instruction-tuning 只教**格式**，因此 ① 单一模型可覆盖多任务（权重共享，只换 prompt）；② 需要的新数据少（因为只学"怎么把 CV 输出画成 RGB"）；③ 基座生成能力易保留（输出本来就是 RGB 图）。这三条同时成立，才使它区别于"改架构全量微调"那条路线（v3 §2）。

我把它翻成可检验的形式：如果这条论证成立，那么**解码器的逆映射必须是任务特定的、但很薄**——薄的证据就在附录 A：它确实只有一个多阶段聚类需要额外设计，其余三个任务都是"取最近颜色"或"查表反解"。

### 2.2 任务 → 可视化 → 解码器 → 可打分的指标

| 任务 | 让模型生成什么 | 解码/后处理 | 最终进 benchmark 的量 | 一手位置 |
| :-- | :-- | :-- | :-- | :-- |
| 语义分割 | 按"类→颜色"映射上色的整幅图（**包含图里不存在的类**，颜色可用命名色/十六进制/RGB 三元组；prompt 风格支持自然语言或 JSON） | 每个像素归到**RGB 空间最近的目标颜色** | mIoU | v3 §3.1；Fig. 2 |
| 实例分割 | 只给**目标类 + 背景色**，要求"每个实例一个不同颜色"（实例数未知，颜色由模型自由分配） | 附录 A 的**多阶段连通域算法**（背景阈值→颜色相似分组→噪声剪枝→边界腐蚀→跨连通合并） | cgF1 / IL_MCC / pmF1（SA-Co 官方口径） | v3 §3.1；附录 A；Tab. 8 |
| 指代分割 | 按指代描述上色（单色 mask + 指定背景色） | 最近颜色 / 阈值反解 | cIoU（RefCOCOg）、gIoU（ReasonSeg） | v3 §3.1；Fig. 4 |
| 度量深度 | 一张**假彩色深度图**（不是热力图语义上的"好看"，而是与米制严格对应的颜色） | 反解：RGB→最近的立方体棱线段→反线性插值→反 power transform | δ₁、AbsRel | v3 §3.2；式 1；Fig. 5 |
| 表面法向 | camera-space 单位向量直写 R/G/B | 逐通道反解：x=1−2R/255、y=2G/255−1、z=2B/255−1 | mean / median 角度误差 | v3 §3.2；Tab. 7 |

### 2.3 度量深度：这条双射是整个方法里唯一"必须对"的部件

深度必须在**训练期**就把 GT 米制深度编码成 RGB（当训练目标），在**推理期**把生成的 RGB 反解回米制深度（才能算指标）。因此编码必须是**严格双射**，而"严格双射"在 [0,∞) → [0,1]³ 上是非平凡的：有限色域无法无损表示无界数值，必须先把无界深度压到有界。论文的做法是两步（v3 §3.2，式 1）：

1. **曲线化**：借用 Barron 的 power transform（参考文献 arXiv:2502.10647），并把形状参数约束到 λ<−1 以保证映射到 [0,1)：

   `f(d, λ, c) = 1 − (1 − d/(λc))^(λ+1)`
2. **着色**：把曲线化后的归一化距离 `f` 作为参数，沿 **RGB 立方体的棱**做分段线性插值，路径是"黑 → 白"（论文原话：similar to the first iteration of a 3D Hilbert curve）。

**关键超参（一手明写）**：`λ = −3`、`c = 10/3`；颜色增广使用 Plasma / Inferno / Viridis / 灰度四种替代色图。

**为什么"曲线化"不是可选项**（这是论文里最有工程含量的一段，且表述很克制）：作者的理由是"近距离的米制精度比远处更重要"（可抓取的物体对机器人更要紧；立体/单目基准通常也按视差或 log-depth 衡量精度）。这句话解释了为什么不做线性映射——线性映射会把绝大部分色阶浪费在远处。

**为什么"沿立方体棱"而不是任意 3D 曲线**：因为反解只需要"投影到最近的线段 + 反插值"，闭式、无查找表、对生成噪声鲁棒。这是"生成即输出"能落地的关键——如果着色路径是任意空间填充曲线，反解就得做最近邻搜索，误差传播不可控。

> **一个必须说清的口径问题**：论文**没有定义** δ₁ 与 AbsRel。按该领域通行定义，δ₁ = `max(d/d*, d*/d) < 1.25` 的像素占比，AbsRel = `mean(|d − d*|/d*)`。我在本分册里按通行定义解读这些数字，属于**评注**而非原文断言。

> **可逆性检查（评注）**：这条链是"曲线化 → 沿棱插值 → 8 bit 量化 → 生成 → 反量化 → 投影到最近棱段 → 反插值 → 反曲线化"。理论上无限精度下无误差，但实际上**每个 8 bit 色阶对应的米制间距随深度非线性变化**：在 λ=−3 的变换下，近处一个色阶对应的深度差远小于远处。这说明**颜色量化对应的米制分辨率随深度变化**，但仅凭量化步长不能断言生成误差已经呈某种统计分布。按上面的指标定义，固定绝对误差下 AbsRel = |d−d*|/d* 在**近处**贡献更大；δ₁ 以相对误差阈值计数，其允许的绝对偏差随真实深度增加。同样的相对误差不会仅因距离不同而受到不同惩罚。原稿“AbsRel 对远处惩罚更重”的解释方向错误。颜色映射的距离分辨率取舍仍需误差随深度的实测分布检验，不能由指标名称推定——论文固定 λ=−3、未做该旋钮的消融。

### 2.4 表面法向：唯一"天然对齐"的任务

法向是单位向量，值域 [−1,1]³，与 [0,1]³ 只差一个仿射变换，所以不需要任何双射设计（v3 §3.2）：

- 约定：**camera-space、右手系**（+x 右、+y 上、+z 指出像平面）。
- 编码：`R = trunc((1 − x)/2, 0, 1)×255`、`G = trunc((1 + y)/2, 0, 1)×255`、`B = trunc((1 + z)/2, 0, 1)×255`；注意 G 通道是 `(1 + y)/2`（y 向上为正），与 R/B 的 `(1 − ·)/2` 方向相反——这不是笔误，而是为了让"朝上的面"落在亮绿上。
- 直观校验（论文给的）：朝左 (−1,0,0) → 粉红；朝上 (0,1,0) → 亮绿；朝相机 (0,0,1) → 亮蓝。

**这里有一个隐含代价**（评注，非原文）：8 bit/通道量化下，单位球面上的法向分辨率在通道边界处不均匀，且生成模型的"颜色漂移"会直接变成角度误差。论文没有讨论量化误差的量级，也没有给"生成噪声 vs GT 量化"的误差分解——这使它在 mean 15.5° 这一档上的细粒度归因不可做。

### 2.5 语义分割：颜色映射就是 prompt

- **开放词表**：类别不限于固定集合，可随 prompt 动态给出；**并且显式包含图中不存在的类**（Cityscapes 评测时给全部 19 类的完整映射）——这一点很重要，它让"漏检类别"也进入分母，是比"只给出现类"更严的设定（v3 §3.1）。
- **多 prompt 风格**：自然语言（"the macaron cakes are represented by yellow"）、JSON 映射、命名色/十六进制/RGB 三元组混用（Fig. 2 逐字给出 4 个 prompt 实例）。
- **解码**：最近颜色归类。因此**颜色选择本身是超参**：两类颜色在 RGB 里越近，解码越易混。论文没有给"颜色分配策略"的消融（评注：这是该方法最脆弱的一环，见 §8）。

### 2.6 实例分割：把"数量未知"变成"颜色自由分配 + 聚类还原"

这是全篇唯一需要真正设计算法的后处理（附录 A 表 A1 式 2–6 给出全部阈值）：

| 步骤 | 做什么 | 阈值/参数（一手明写） |
| :-- | :-- | :-- |
| 1 背景初始化 | 与预定义背景色 `C_bg` 距离小于 τ 的像素标为背景（label 0），不参与后续 | **τ = 14**（RGB 欧氏距离） |
| 2 颜色相似分组 | 对剩余像素做**种子 floodfill、16-连通**；相邻像素与**该连通域种子像素**的距离 ≤ τ 才合并 | τ = 14，16-连通 |
| 3 噪声剪枝 | 面积小于图像一定比例的分量丢弃并回填背景 | **θ_size = 2×10⁻⁴**（图像面积的 0.02%） |
| 4 边界伪影消除 | 用 **3×3 方形结构元**做二值腐蚀，腐蚀后保留面积比过低的分量剪掉（针对生成模型在物体间产生的彩色细边） | **θ_erosion = 0.1** |
| 5 空间受限合并 | 空间不连通但平均色相近的分量合并（遮挡导致同一物体断开），但**合并后包围盒不得膨胀过度** | 颜色距离 ≤ τ；**γ = 5.0**（包围盒面积 ≤ γ×(两分量面积和)） |

论文对"为什么需要这套东西"的交代很实在：生成图有**高频噪声、单个 mask 内部轻微颜色漂移、边界混色**，所以标准的连通域/阈值法直接失效（附录 A 首段）。

### 2.7 "lightweight" 到底轻在哪：被混进去的是原训练混合

原话是：**把视觉任务数据以极低比例（very low ratio）混进 Nano Banana Pro 自己的训练混合**（v3 §2）。这句话有两个必须拆开的含义：

- **它保留了基座的训练分布**——这解释了为什么生成能力能保住（生成侧的监督信号仍在，只是被极低比例的视觉任务数据"轻微扰动"）。
- **它要求作者能访问 NBP 的原训练混合**——这是外部复现的第一道硬门槛：不是"给你一个 NBP 检查点 + 我的视觉数据"就能重跑，因为"原混合"本身不可得。

论文用它来区分"前人做法"：Gan et al. 2023 / Ke et al. 2024 / Zhao et al. 2025 被点名为"在生成模型上做全量微调**但没有保留图像生成数据混合**"的路线（v3 §2）。这条对比是本文立论的核心，但它**是立场性的**——论文没有给出"保留 vs 不保留混合"的对照实验。

## 5. 消融：这篇论文的真正缺口在这里

**结论先行：全篇没有一组真正的消融实验**（`[精读原文]`，我逐节核对：v3 正文 4 节 + 附录 A–D，没有任何 "ablation" 小节或表格）。

它能提供的"准对照"只有三处，且都不是消融：

1. **与基座 NBP 的双向人评胜率**（53.5% / 47.8%）——证明生成侧未崩，但样本与协议未披露。
2. **与专门家的跨方法比较**——同一基准、不同训练数据与架构，属"外部对照"而非"内部消融"。
3. **口径对齐脚注**（DepthLM 4 集 0.855 vs 0.865；DA3 4 集 0.918 vs 0.929）——这是**统计口径修正**，不是实验。

**六项本该做而没做的消融（按重要性排序，评注）**：

| # | 缺的消融 | 为什么它决定论点的强弱 |
| --: | :-- | :-- |
| 1 | **未 instruction-tuning 的 NBP，在同一解码协议下**的理解表现 | 这是整个因果链的核心：论文主张"NBP 本就有理解表征，instruction-tuning 只是解锁格式"。没有这一项，就**无法区分"表征获得"与"格式对齐"的贡献比例**，也就无法排除"instruction-tuning 本身把任务学会了"。 |
| 2 | **视觉数据的掺入比例**（very low ratio 的扫参） | "轻量"的全部含义就在这个比例；不扫参，"低比例即可"是断言。同时它决定生成能力保持的边界。 |
| 3 | **任务数量/任务组合** | 论文主张"统一模型不互相伤害"。只有 5 个任务、无"逐个加入"的阶梯实验，无法证伪"多任务互相干扰"。 |
| 4 | **颜色映射策略**（语义分割的类→色分配、实例的调色盘） | 解码器是"最近色"，是方法链上最脆的一环；换色盘后的鲁棒性未测。 |
| 5 | **解码后处理的敏感性**（附录 A 的 τ/θ_size/θ_erosion/γ） | 五个阈值只给取值、不给敏感性；这决定该方法的"工程可复现性"。 |
| 6 | **生成分辨率对 dense 指标的影响** | 若分辨率固定，则高 IoU 阈值的上限被结构性地限制——这正好对应附录 C 承认的"mask 比 SAM 标注略小/更细"惩罚。 |

### 5.1 如果要复现，最小可行实验长什么样

把上面六项缺口反推成实验设计，最小集只有四条（评注，供后续研究参考）：

1. **基座对照**：同一个 NBP 检查点，① 零样本直接 prompt（不 instruction-tune），② instruction-tune 后，两者用**同一解码器**比较——直接量化"格式对齐"的贡献。
2. **比例扫参**：视觉数据占比取 `0 / 极低 / 低 / 中` 四档，每档同时测一个 dense 任务指标 + 一个生成指标（如 GenAI-Bench 胜率），画出**"理解-生成"权衡曲线**。这是本文最该有而完全没有的图。
3. **解码敏感性**：语义分割换 3 套色盘、实例分割换 τ 与 θ_erosion，报告 mIoU/cgF1 的方差——决定"这套方法有多依赖后处理调参"。
4. **分辨率消融**：生成分辨率减半再测 cgF1/pmF1，把"边界细化能力"与"结构正确性"解耦。

如果这四条里第 1、2 条成立，论文的核心命题（"基座本就有理解表征，指令微调只解锁格式"）才算被证明，而不是被展示。

## 6. 与同类可判定差异

| 对比对象 | 它的做法 | Vision Banana 的差异（可判定） | 判定依据 |
| :-- | :-- | :-- | :-- |
| LISA / X-Decoder / APE-D / HybridGL / LocalizationHeads | 给 MLLM 加分割头 + 专用损失 + 在指代数据上训练 | **无新结构、无新损失**，输出仍是 RGB 图；训练数据只是"格式"层面的少量视觉数据 | v3 §1、§2、§4（Discussion："without specialized architectures or custom training losses"） |
| SAM 3 / SAM 2 | promptable 分割专用模型，需专用架构与海量人工 mask；对歧义返回多个 mask，只对其中一个算损失 | 生成式**多头**输出天然处理歧义；且**不需要人工 mask 标注**（2D 标注来自自家模型） | v3 §3.1；§4（Discussion 对 "mode-averaging" 的批评） |
| Marigold / Lotus / Lotus-2 / StableNormal / DSINE | 把扩散/生成先验搬来做**单一** dense 任务（特征或初始化层面），通常需相机内参 | **整模型 instruction-tune**；五任务共享一套权重；**完全不用内参**；输出是可视化 RGB 而非回归头 | v3 §3.2 与 Tab. 6/7 |
| Depth Anything 3 / Depth Pro / UniK3D / MoGe-2 / DepthLM | 专门架构 + 专门的尺度/内参处理 + 真实或混合深度数据 | **零真实深度数据**（全合成）、零内参；靠基座的世界先验定绝对尺度 | v3 §3.2（"trained entirely on synthetic depth data"） |
| 前人"生成器能画理解可视化"（Zuo 2025 / Wiedemer 2025） | 开放式生成，格式不受控 | **instruction-tune 到格式可控 + 严格可逆解码**，因此能进 benchmark 打分 | v3 §1 的分段论证 |
| 前人"视觉输出参数化为 RGB"（Ke 2024 / Zhao 2025 / Gan 2023 / Wang 2023 / Lu 2022/2024 / Xie 2024 / Inclusion AI 2025） | 已有 RGB 参数化思路 | 论文明确承认**不是首创**，差异在"配上强基座 + instruction-tuning 后打过专门家" | v3 §4（"we are not the first to encode vision outputs as RGB"） |

**一句话可判定差异**：**它把"接口"当成了唯一的创新点，而这个接口之所以成立，靠的是基座（NBP）已经足够强**——这正是它同时最有力（结果好）与最不可复现（换基座就没了）的地方。

## 7. 在本仓库条目中的位置

- **对 `Models/Google-Gen` 条目**：本条目此前的谱系是 **Imagen 级联扩散 → VideoPoet/Phenaki 自回归 → Lumiere 时空 U-Net → Veo 的 DiT 路线**，全部围绕"怎么生成得更好"。Vision Banana 是**第一条把 Google 的图像生成器当"视觉骨干"而不是"生成器"来用的线**，且它证明的命题是反向的：**生成的训练目标本身就是一种表征学习目标**。因此它与既有条目的关系不是"下一代模型"，而是"**同一批模型的能力被重新解读**"。
- **对 `VisualGen/DiT`**：它给出"DiT 类图像生成器的输出空间可以直接当任务接口"的最强证据（详见交叉引用），但**注意它没有披露 NBP 的架构**，因此"这一定是 DiT"属于**推测**，本分册不作此断言。
- **对 `VisualGen/3DGen`**：3D 理解（单目度量深度 + 表面法向）被当作 RGB 生成任务处理，是"3D 任务的 2D 化"而非"3D 生成"——它没有输出点云/网格/NeRF，**只输出 2D 图**，再接外部内参做反投影（Fig. 6）。这一点必须在引用时区分清楚。
- **对 `WorldModel` 系列**：不构成世界模型（无状态、无时序、无动作条件），但它是"**视觉表征可以完全从生成目标里长出来**"这一假设在 2D/3D 静态任务上的最强检验，对"世界模型要不要单独的表示学习目标"这个问题有间接参考价值（评注）。

## 8. 失效边界（独立段）

1. **存在性判定不可自理（论文自承）**。"我们**没有**调过模型去生成空 mask"——SA-Co 上必须外接 Gemini 3.1 Flash-Lite 做正/负判定。因此"通用视觉模型"在这条主指标上其实是"**生成器 + MLLM 编排**"的系统能力，且模型自带的判别能力（IL_MCC 0.84）**主要来自 Gemini**（附录 B 原文承认）。任何"单一模型搞定检测+分割"的转述都是错的。
2. **拥挤/杂乱场景的合并与拆分之误（论文自承）**。附录 C 的 7 个失败例分两类：① **把不同实例合并**（"a wall" 6 段墙合并、28 个邮筒合并成 1 个、家具合并、上下柱子合并）；② **把群体拆成个体**（查询"the crowd"时给 24 个人各出一 mask）。定量对应：Crowded 子集 cgF1 **34.4**（SAM 3 61.1）、SA-1B 子集 **33.5**（SAM 3 53.7）。
3. **高 IoU 阈值上的 mask 边界惩罚（论文自承）**。作者明确写：模型产出的 mask "usually slightly smaller"、"finer" 于 SAM 标注，在 10 档 IoU 的高阈值端被系统性罚分——即**部分量化差距来自标注偏差而非分割错误**。这条对"分数能不能直接比"很关键。
4. **近距离/车载尺度的深度退化（数据自证）**。nuScenes δ₁ **0.643**（UniK3D 0.840、MoGe-2 0.820）、KITTI **0.915**（DA3 0.953）、NYU **0.948**（UniK3D 0.965）。论文没有解释这三格的落后原因，只用"6 集平均最好"覆盖过去。
5. **绝对尺度依赖语义先验，而非几何（论文立场 + 数据）。** 不用内参、不用真实深度数据，尺度只能从"物体大小/关系"推断。**推论（评注）**：对"训练分布外尺度"（显微、航拍、鱼眼、极长焦压缩透视）与"无熟悉参照物"的场景，这套先验没有保障；论文**没有**做任何跨域/跨光学实验。
6. **数据来源不可审计（评注）。** 2D 标注是"in-house model annotations"，即**用自家模型生成的真值**——这既是"无需人工标注"的卖点，也可能把自家模型的偏差（如 SAM 类模型的边界偏好）固化进 Vision Banana，而这恰恰是第 3 条失败模式的来源。论文**没有披露**标注模型是什么。
7. **与基准图像的重叠风险未被排除（评注）。** 论文只声明"基准**训练集**不进混合"，未声明"网页抓取图与基准**图像**无重叠"。RefCOCOg 的图来自 COCO，而 COCO 图广泛存在于网页——这条无法从论文文本上排除，只能靠作者的内部流程保证。
8. **成本与延迟未量化（论文自承 + 缺口）。** Discussion 明写"utilizing image generators like Nano Banana Pro currently incurs a significantly higher computational overhead than running lightweight specialist models"，但**全文没有一个延迟/FLOPs/显存/单图成本数字**。因此"能不能部署"无法评估；反过来，任何"生成器可以替代轻量专家"的成本论断言都不被本文支持。
9. **输出上限被"生成分辨率"锁死（评注）。** dense prediction 的空间精度不可能超过生成图的分辨率，而论文未报分辨率。这直接后果是：细结构（论文 Fig. 2 举的猫胡须）**视觉上**能画，"像素级 IoU"上却未必占优——附录 C 的"更细更小"正是这一机制的体现。
10. **"没有专用损失"不等于"没有专用后处理"。** 每类任务各有一套解码：深度要反双射、法向要逐通道反解、语义要最近色、实例要五步聚类（含 5 个阈值）。所以"统一接口"的准确表述是"**统一的输出空间 + 各自轻薄的解码器**"，不是"零配置"。
11. **不可复现性（结构性）。** 基座 NBP 权重与训练混合都不公开；训练超参、数据量、模型规模、分辨率全部未披露。因此它**不是一个可被第三方验证的方法**，只能作为"存在性证明"（existence proof）引用。
12. **benchmark 覆盖面窄。** 语义分割只有 **Cityscapes 一个**（19 类街景），没有 ADE20K / VOC / COCO-Stuff；实例分割只有 **SA-Co/Gold**；指代只有 RefCOCOg + ReasonSeg；法向只有 4 集。因此"generalist"的"general"是 **5 类任务、14 次评测覆盖 12 个不重复数据集**（深度 6 集；法向 4 集，其中 NYU/DIODE 与深度重叠；分割 4 集）范围内的 general，**不能说"通用视觉"**。

## 9. 引用注意（哪些结论不能外推）

**可以引（证据在论文内自洽、条件明确）**

- "把视觉任务输出参数化为 RGB、并用 instruction-tuning 对齐格式，可以让一般化图像生成器在多个标准 benchmark 上达到零样本 SOTA 级"——但要附"**其基座是 NBP**"。
- 具体的**零样本**数字：Cityscapes mIoU 69.9、RefCOCOg cIoU 73.8、ReasonSeg gIoU 79.3、SA-Co/Gold cgF1 47.5（须带 Gemini 3.1 Flash-Lite）、6 集平均深度 δ₁ 0.882、室内三集法向 mean 15.549°——**每个都要带数据集 + 设置 + 口径**。
- 方法论层面的**可迁移观察**：① 生成目标存在"多模态输出"的天然优势，可避免判别模型的 mode-averaging（论文的论证，我认为成立，因为它与附录 C 的定性观察一致）；② 保留原训练混合的低比例掺数据是"保住生成能力"的可行做法（但**幅度不可引**，因无人评协议）。
- **深度编码的具体做法**（λ=−3、c=10/3、沿立方体棱的分段线性 + 逆投影反解）——这是本文最可直接复用的工程贡献。

**不能引（会被外推错）**

1. **"Vision Banana 全面超过 SAM 3"** ——错的。它的**零样本**在 Cityscapes/RefCOCOg/ReasonSeg 上高于 SAM 3 的对应设置，但在 **SA-Co/Gold 上 47.5 < SAM 3 的 54.1**（且论文自己写"we still lag behind the SAM 3 specialist"）。
2. **"超过 Depth Anything 3"** ——只在"DA3 报过的 4 集平均"上成立（0.929 vs 0.918），**逐集看 NYU / KITTI 都输**。同理"超过 Lotus-2"只在**室内三集平均**成立，室外输 0.169°。
3. **"生成能力完全无损"** ——字面数字是 T2I +3.5 个点、**编辑 −2.2 个点**，且无人评协议、无置信区间。正确表述是"在作者的人评协议下与基座接近"。
4. **"一个模型端到端完成实例分割"** ——SA-Co 上必须外接 MLLM 做存在性判定，IL_MCC 主要由该 MLLM 贡献。
5. **"通用视觉模型（generalist vision model）"** ——只能限定为"5 类任务、12 个不重复数据集上的 generalist"；语义分割仅 1 个数据集，**没有开放词表分割的广覆盖证据**。
6. **"训练数据规模小所以便宜/高效"** ——论文只说"少量视觉数据 + 轻量 instruction-tuning"，**没有任何数据量或算力数字**；且 Discussion 明说推理成本高于轻量专家。把它当"低成本方案"引用是反向的。
7. **不作跨厂商排行榜**：本文所有对照都是"它 vs 专任务专家"，不涉及其它厂商的通用大模型排名；本分册也不构造此类排序。
8. **不能引用为"NBP 架构 = DiT"**：论文未披露 NBP 架构；"它是 DiT 类"在当前证据下是推测（本分册在 `VisualGen/DiT` 的交叉引用里按"图像生成器"表述，不写 DiT）。

## 11. 关于「是否属 Gemini 家族」的单独说明

任务设定里给了两条互斥指令：若一手正文确认它属 Gemini 家族则加一行指向，否则不加。**事实是：arXiv:2604.20329 正文（v3，含附录 A–D）从头到尾没有说过 NBP 属于 Gemini 家族**——它对基座的称呼只有 "Nano Banana Pro (NBP)"，唯一的外部指涉是参考文献 Google 2025a。

而 Google 2025a 指向的官方博客本身把话说尽了：页面标题即 **"Nano Banana Pro: Gemini 3 Pro Image model from Google DeepMind"**，正文写 **"a new image generation and editing model built on Gemini 3 Pro"**（2025-11-20，Product Manager 署名 Naina Raisinghani）。

因此本分册的处理是：**在 `Models/Gemini/report.md` 加一行指向**，但把"家族归属"的证据明确标为"Google 官方博客（论文 Google 2025a 引用）"，而不是标成"论文正文所述"。这样既不违反"不推测"，也不遗漏一条对读者有用的一手线索。
