## 1. 概述

Google / DeepMind 在生成式 AI 领域的布局横跨图像、视频、音频三大模态，其技术路线经历了从**级联扩散模型（Cascade Diffusion）**到**自回归 Transformer（Autoregressive Transformer）**，再到**时空统一扩散（Spatio-Temporal U-Net）**，最终收敛于**DiT（Diffusion Transformer）视频生成**的完整演进。这一演进不仅反映了生成模型领域整体范式的变迁，也体现了 Google 在多模态整合与产品化路径上的独特选择。

与 OpenAI 的 DALL·E → Sora 路线不同，Google 的生成模型研究呈现出更强的**学术探索性**和**技术多样性**：
- 图像生成方面，Imagen 系列坚持级联扩散路线，强调文本编码器规模对生成质量的决定性作用；
- 视频生成方面，Google 同时探索了自回归（Phenaki / VideoPoet）和扩散（Lumiere / Veo）两条路径；
- 最终，Veo 系列以 DiT 架构统一了视频生成 pipeline，标志着 Google 视频生成技术路线的收敛。

本报告将系统梳理 Google / DeepMind 生成模型系列的架构演进，重点分析从 Imagen 到 Veo 的技术变迁，并探讨其对未来多模态生成的影响。

## 3. 模型架构详解

### 3.1 Imagen (2022)

Imagen 是 Google Research 于 2022 年提出的文本到图像生成模型，其核心创新在于**级联扩散架构（Cascade Diffusion）**和**文本编码器规模优先策略**。

#### 3.1.1 级联扩散架构

Imagen 采用三级级联 pipeline，逐步从低分辨率向高分辨率提升：

```
文本输入 → T5-XXL 编码 → [64x64 基础扩散] → [256x256 超分] → [1024x1024 超分] → 最终图像
```

**第一级：64×64 基础扩散模型**
- 基于 U-Net 架构的条件扩散模型
- 输入：T5-XXL 输出的文本嵌入（text embeddings）
- 输出：64×64 的噪声图像，经去噪后得到低分辨率图像
- 这是整个 pipeline 的"语义核心"，负责理解文本并生成对应的视觉内容

**第二级：64×64 → 256×256 超分扩散模型**
- 同样基于 U-Net 的条件扩散模型
- 输入：64×64 图像 + 文本嵌入
- 输出：256×256 高分辨率图像
- 负责在保持语义一致性的同时增加空间细节

**第三级：256×256 → 1024×1024 超分扩散模型**
- 最后一级超分，专注于纹理和边缘细节的精细化
- 输出 1024×1024 的最终图像

#### 3.1.2 文本编码器：T5-XXL

Imagen 最引人注目的设计选择是**使用 T5-XXL（约 4.6B 参数）作为文本编码器，且不冻结其参数，参与端到端训练**。

这一选择与同期模型形成鲜明对比：
- DALL·E 2 使用冻结的 CLIP 文本编码器
- Stable Diffusion 使用冻结的 CLIP 或 OpenCLIP

Google 在论文中提出了一个关键发现：**更大的文本编码器比更大的图像扩散模型对生成质量的提升更显著**。具体而言：
- 将文本编码器从 T5-XXL 降级到 T5-Large，即使保持图像模型规模不变，生成质量也会显著下降
- 反之，增大图像模型而保持文本编码器较小，收益相对有限

这一发现深刻影响了后续生成模型的设计方向，促使社区重新审视文本理解在视觉生成中的核心地位。

#### 3.1.3 关键技术与限制

**关键技术**：
- 动态阈值化（Dynamic Thresholding）：解决高分辨率扩散中的饱和问题
- 无分类器引导（Classifier-Free Guidance, CFG）：提升文本-图像对齐度
- 级联训练策略：各级模型独立训练，通过噪声条件化实现稳定级联

**限制**：
- 无公开模型或 API（Google 内部使用）
- 级联 pipeline 推理成本高，需要多次前向传播
- 文本渲染能力有限（后续 Imagen 2/3 重点改进）

### 3.2 Imagen 2 (2023)

Imagen 2 是 Imagen 的迭代版本，于 2023 年随 Google Cloud Vertex AI 发布。虽然 Google 未公开完整技术细节，但从产品特性和技术博客中可以推断其改进方向。

#### 3.2.1 已知改进

**图像质量提升**：
- 更好的细节保留和纹理生成
- 改进的光照和阴影处理
- 更自然的肤色和材质表现

**文本渲染能力**：
- 显著改进的文本生成能力（Imagen 的已知短板）
- 支持图像中的可读文本生成

**编辑能力扩展**：
- **Inpainting**：对图像局部区域进行重绘，保持上下文一致性
- **Outpainting**：扩展图像边界，生成超出原始画面的内容
- **Mask-based editing**：基于掩码的精细编辑

#### 3.2.2 架构推测

基于 Google 的技术博客和行业分析，Imagen 2 可能采用了以下改进：
- 保留级联扩散的整体框架
- 可能引入更高分辨率的基础模型（如 128×128 而非 64×64）
- 改进的文本编码器或额外的文本理解模块
- 更强的条件注入机制（如 cross-attention 的改进）

---

### 3.3 Imagen 3 (2024)

Imagen 3 于 2024 年 5 月在 Google I/O 大会上发布，代表了 Google 图像生成技术的最新水平。

#### 3.3.1 核心改进

**视觉质量**：
- 显著改进的细节层次（fine-grained details）
- 更自然的光照模型和全局光照一致性
- 更合理的构图和透视关系
- 减少伪影和失真

**文本理解**：
- 更精确的复杂提示词理解
- 更好的属性绑定（attribute binding，如"一只红色的狗和蓝色的猫"）
- 支持更长的描述性文本

**产品集成**：
- 集成到 Gemini 多模态对话中
- Google Search 中的图像生成功能
- Google Workspace 中的创意工具

#### 3.3.2 架构演进方向

虽然 Google 未完全公开 Imagen 3 的架构，但从行业趋势和 Google 的技术积累可以推断：
- 可能从纯级联扩散向更统一的生成框架演进
- 可能引入 DiT 元素或改进的 U-Net 变体
- 文本编码器可能从 T5 向 Gemini 系列模型演进
- 训练数据规模和质量的大幅提升

### 3.4 Phenaki / VideoPoet (2022-2023)

在视频生成领域，Google 早期探索了**自回归（Autoregressive）**路线，与图像生成的扩散路线形成有趣的对照。Phenaki 和 VideoPoet 代表了这一方向的两个重要里程碑。

#### 3.4.1 Phenaki (2022)

Phenaki 是 Google Research 提出的**首个能够从文本生成可变长度视频**的模型。

**核心架构：C-ViViT (Causal ViViT)**

Phenaki 的视频生成 pipeline 包含以下关键组件：

```
文本输入 → 编码器 → 视频 Tokenizer (C-ViViT) → 自回归 Transformer → 视频解码
```

**C-ViViT 视频 Tokenizer**：
- 基于 ViViT（Video Vision Transformer）的因果变体
- 将输入视频编码为离散的时空 token 序列
- "因果"意味着 token 生成仅依赖于过去的 token，支持自回归生成
- 采用 3D CNN 或时空 patch embedding 提取视频特征

**自回归 Transformer**：
- 接收文本嵌入和已生成的视频 token
- 逐个预测下一个视频 token
- 支持双向条件：文本描述 + 关键帧图像

**关键特性**：
- **可变长度**：能够生成从几秒到数分钟的视频
- **双向引导**：支持文本 + 图像联合条件
- **计算效率**：自回归生成在推理时逐 token 进行，但训练相对高效

#### 3.4.2 VideoPoet (2023)

VideoPoet 是 Google Research 于 2023 年底提出的**多任务视频生成模型**，其最大特色是采用类似 LLM 的自回归框架统一多种视频任务。

**核心设计：LLM 风格的自回归视频生成**

VideoPoet 将视频生成重新框架为**语言建模问题**：
- 使用 tokenizer 将视频（和音频）转换为离散 token
- 使用自回归 Transformer（类似 LLM 的 decoder-only 架构）建模 token 序列
- 统一处理多种模态和任务

**多任务统一能力**：

| 任务类型 | 描述 |
|----------|------|
| 文本到视频 (T2V) | 从文本描述生成视频 |
| 图像到视频 (I2V) | 从静态图像生成动态视频 |
| 视频编辑 | 基于文本指令编辑已有视频 |
| 风格化 | 将视频转换为指定艺术风格 |
| 视频到音频 (V2A) | 为视频生成匹配的音频 |
| 视频修复/扩展 | 视频 inpainting 和 outpainting |

**架构特点**：
- **Decoder-only Transformer**：与 GPT 系列类似的纯解码器架构
- **多模态 token 统一**：视频、音频、文本统一表示为 token 序列
- **任务提示（Task Prompting）**：通过特殊 token 或前缀区分不同任务
- **自回归生成**：逐 token 生成视频和音频内容

**VideoPoet 的意义**：
- 证明了自回归框架在视频生成中的可行性
- 展示了多任务统一建模的潜力
- 为后续多模态 LLM（如 Gemini）的视频理解能力奠定了基础

### 3.5 Lumiere (2024)

Lumiere 是 Google Research 于 2024 年 1 月提出的文本到视频生成模型，其核心创新是**时空 U-Net（STUNet）**，实现了视频的**一次性完整生成**，而非传统的逐帧或分段生成。

#### 3.5.1 时空 U-Net (STUNet)

传统视频生成方法通常采用以下策略之一：
- **逐帧生成**：独立生成每一帧，然后通过时序模型（如插帧）增加流畅性
- **分段生成**：生成关键帧，然后插值填充中间帧

这些方法的问题在于：
- 帧间一致性难以保证
- 全局时序动态（如物体的持续运动）容易被破坏
- 需要额外的时序对齐步骤

**STUNet 的核心思想**：

```
文本输入 → 文本编码器 → STUNet (时空联合去噪) → 完整视频输出
```

STUNet 在标准 U-Net 的基础上引入了**时空联合卷积/注意力**：
- **3D 卷积层**：同时处理空间（H×W）和时间（T）维度
- **时空注意力（Spatio-Temporal Attention）**：在时空立方体（T×H×W）上执行自注意力
- **时间下采样/上采样**：在编码器路径中对时间维度进行下采样，在解码器路径中恢复

**架构优势**：
- **全局时序一致性**：模型在单次前向传播中"看到"整个视频，自然保持时序连贯
- **避免拼接伪影**：无需后期拼接或插帧
- **更自然的运动**：能够建模复杂的、非线性的物体运动

#### 3.5.2 技术细节

**多尺度时空处理**：
- STUNet 在不同分辨率层级处理视频
- 低分辨率层级处理大尺度运动
- 高分辨率层级处理细节和纹理

**文本条件注入**：
- 通过 cross-attention 将文本嵌入注入到时空特征中
- 支持细粒度的文本-视频对齐

**生成流程**：
1. 从纯噪声视频（T×H×W×C 的张量）开始
2. 通过 STUNet 逐步去噪
3. 输出完整的、时序连贯的视频

#### 3.5.3 局限与影响

**局限**：
- 内存需求极高：同时处理整个视频的时空体积需要巨大的 GPU 内存
- 视频长度受限：通常生成 5 秒左右的短视频
- 分辨率受限：受限于内存，通常为低分辨率输出

**影响**：
- Lumiere 的 STUNet 思想影响了后续视频扩散模型的设计
- 证明了时空联合处理在视频质量上的优势
- 为 Veo 的 DiT 时空注意力设计提供了经验基础

### 3.6 Veo 系列 (2024-2026)

Veo 是 Google 的视频生成产品系列，标志着 Google 视频生成技术从学术探索走向产品化，同时代表了架构上从 U-Net 向 **DiT（Diffusion Transformer）** 的关键转变。

#### 3.6.1 Veo 1 (2024.05)

Veo 1 是 Google 首个基于 DiT 架构的视频生成模型，在 2024 年 Google I/O 大会上发布。

**架构：DiT (Diffusion Transformer)**

Veo 1 的核心架构可以概括为：

```
文本/图像输入 → 编码器 → DiT (时空注意力) → 视频解码器 → 视频输出
```

**DiT 核心设计**：
- 将视频表示为时空 patch 序列（类似 ViT 的图像 patch）
- 使用 Transformer 替代 U-Net 作为去噪网络
- 在 patch token 上执行自注意力和交叉注意力

**关键特性**：
- 720p 分辨率视频生成
- 支持文本和图像作为条件输入
- 生成视频时长约 8 秒
- 较好的语义理解和运动一致性

#### 3.6.2 Veo 2 (2024.12)

Veo 2 于 2024 年底发布，重点改进了视频质量和物理一致性。

**改进方向**：
- **更高分辨率**：支持 1080p 视频生成
- **物理一致性**：改进的物理模拟，更真实的物体交互
- **更长的视频**：支持约 12-15 秒的视频生成
- **更好的时序连贯性**：减少闪烁和突变

**技术推测**：
- 更大的 DiT 模型规模
- 改进的训练数据筛选和标注
- 可能引入物理约束或 3D 先验
- 更高效的时空注意力机制

#### 3.6.3 Veo 3 (2025.05)

Veo 3 是 Google 视频生成的重要里程碑，首次实现了**原生音频生成**。

**核心突破：原生音频生成**

与"先视频后配音"的两阶段方法不同，Veo 3 实现了视频和音频的**联合生成**：
- 音频不是后期添加，而是与视频内容同步生成
- 支持环境音、音效、简单的音乐元素
- 音频与视觉内容在时序上精确对齐

**技术实现推测**：
- 扩展 DiT 以同时建模视频和音频 token
- 或采用多流 DiT，视频和音频分别由关联的 token 流表示
- 音频 tokenizer（如 SoundStream/EnCodec）与视频 tokenizer 联合训练

**其他改进**：
- 支持 60 秒视频生成
- 进一步改进的物理和时序一致性
- 更好的相机运动控制

#### 3.6.4 Veo 3.1 (2025.10)

Veo 3.1 将视频生成质量推向 4K 级别。

**关键升级**：
- **4K 分辨率输出**：支持 3840×2160 视频生成
- **更长时长**：支持数分钟级别的视频生成
- **改进的细节层次**：4K 下的纹理和边缘质量
- **更高效的推理**：针对高分辨率的优化

**技术挑战与解决方案**：
- 4K 视频的 token 数量巨大，对内存和计算提出极高要求
- 可能采用**分层生成**或**滑动窗口**策略处理长视频
- 时空注意力的稀疏化或局部化优化

#### 3.6.5 Veo 3.1 Fast / Lite (2026.03)

Veo 3.1 Fast 和 Lite 是 Veo 3.1 的低成本变体，面向实时或近实时应用场景。

**Fast 版本**：
- 优化推理速度，支持近实时生成
- 可能采用模型蒸馏、量化或稀疏注意力
- 针对低延迟场景（如直播、交互式应用）

**Lite 版本**：
- 更小的模型规模，更低的计算需求
- 适合移动端或边缘设备部署
- 在质量和速度之间取得平衡

**技术方向**：
- 模型蒸馏：从 Veo 3.1 教师模型蒸馏学生模型
- 推理优化：FlashAttention、KV-Cache 优化、 speculative decoding
- 渐进式生成：先生成低分辨率预览，再逐步细化


### 4.3 关键架构决策分析

**1. 从 U-Net 到 DiT 的转变**

| 方面 | U-Net (Imagen/Lumiere) | DiT (Veo) |
|------|------------------------|-----------|
| 归纳偏置 | 强（局部性、平移等变性） | 弱（依赖数据学习） |
| 全局建模 | 受感受野限制 | 天然全局（自注意力） |
| 可扩展性 | 扩展性有限 | 随数据/计算规模提升 |
| 训练稳定性 | 相对稳定 | 需要 careful tuning |
| 与 LLM 统一 | 架构差异大 | 可与 LLM 共享组件 |

Google 选择 DiT 的核心原因：
- **可扩展性**：DiT 的 scaling law 更明确，便于构建更大模型
- **多模态统一**：DiT 架构与 LLM 更接近，便于未来与语言模型整合
- **全局建模能力**：自注意力天然支持长程时空依赖

**2. 从级联到统一的演进**

| 阶段 | 代表模型 | 特点 |
|------|----------|------|
| 级联生成 | Imagen | 多模型串联，逐步超分 |
| 单次生成 | Lumiere | 单模型一次性生成完整视频 |
| 统一 DiT | Veo | 单模型端到端，支持多分辨率/时长 |

**3. 自回归 vs 扩散的选择**

Google 在视频生成上同时探索了两条路线，最终选择了扩散（DiT）：
- **自回归优势**：天然支持可变长度，与 LLM 架构统一，多任务灵活
- **自回归劣势**：推理速度慢（逐 token），长序列训练困难，视频质量上限受限于 tokenizer
- **扩散优势**：生成质量高，训练稳定，推理可并行（多步去噪）
- **扩散劣势**：固定长度输出，需要多步推理

Veo 选择 DiT 扩散路线，可能基于以下考量：
- 视频质量是产品化的首要目标
- DiT 的推理可以通过蒸馏和优化加速
- 与 Google 的扩散图像生成积累（Imagen 系列）形成技术协同

## 5. Veo 技术深度拆解

### 5.1 DiT 视频生成架构

Veo 的 DiT 架构是理解 Google 视频生成技术的关键。以下是对其架构的详细分析：

#### 5.1.1 视频 Tokenization

Veo 首先将输入视频转换为适合 Transformer 处理的 token 序列：

**时空 Patch Embedding**：
- 将视频（T 帧，每帧 H×W）划分为 3D patch（t×h×w）
- 每个 patch 通过线性投影转换为向量
- 添加时空位置编码（Spatio-Temporal Positional Encoding）
- 最终得到 token 序列：`(T/t) × (H/h) × (W/w)` 个 token

**与图像 DiT 的区别**：
- 图像 DiT（如 DiT 原论文）使用 2D patch（h×w）
- 视频 DiT 使用 3D patch（t×h×w），同时编码时间和空间信息
- 时间维度的 patch 大小 t 是关键超参数（如 t=2 或 t=4）

#### 5.1.2 DiT 去噪网络

Veo 的 DiT 去噪网络接收以下输入：
- 噪声视频 token（当前扩散时间步 t 的状态）
- 时间步嵌入（diffusion timestep embedding）
- 文本/图像条件嵌入（通过 cross-attention 注入）

**核心模块**：

```
输入: 噪声视频 token + 时间步 + 条件
    │
    ├──→ [多头自注意力] ──→ 建模视频 token 间的关系
    │       (时空注意力，可选因果掩码)
    │
    ├──→ [交叉注意力] ────→ 注入文本/图像条件
    │       (Q: 视频 token, K/V: 条件嵌入)
    │
    └──→ [FFN] ──────────→ 逐 token 特征变换
```

**时空注意力的实现方式**：

| 注意力类型 | 计算范围 | 复杂度 | 适用场景 |
|------------|----------|--------|----------|
| 全时空注意力 | 所有 token 两两交互 | O(N²), N=T×H×W | 短视频，高画质 |
| 分解注意力 | 空间注意力 + 时间注意力 | O(N_s²) + O(N_t²) | 平衡效率和质量 |
| 局部窗口注意力 | 时空邻域内交互 | O(N×k) | 长视频，快速推理 |
| 因果注意力 | 仅关注过去 token | O(N²) 但可缓存 | 流式生成 |

Veo 可能采用**分解注意力**或**分层注意力**策略：
- 底层使用全时空注意力建模局部精细运动
- 高层使用稀疏或分解注意力处理全局结构

#### 5.1.3 条件注入机制

Veo 支持多种条件输入：

**文本条件**：
- 使用 Gemini 或内部文本编码器提取文本嵌入
- 通过 cross-attention 注入到 DiT 的每一层
- 可能采用类似 Stable Diffusion 的文本条件化策略

**图像条件（Image-to-Video）**：
- 将首帧或关键帧编码为视觉 token
- 与噪声视频 token 拼接或融合
- 通过 attention 机制引导视频生成

**相机运动条件**：
- 将相机参数（平移、旋转、缩放）编码为嵌入
- 注入到 DiT 中控制相机运动

### 5.2 训练策略

#### 5.2.1 数据与标注

Veo 的训练数据可能包括：
- 大规模视频-文本对（内部数据集）
- 高质量视频片段（筛选后的 YouTube 内容）
- 合成数据（3D 渲染、物理模拟）

**数据筛选标准**：
- 美学质量评分
- 运动复杂度（避免静态或过度抖动视频）
- 文本-视频对齐度
- 分辨率和时长要求

#### 5.2.2 训练阶段

Veo 的训练可能分为多个阶段：

**阶段 1：文本到视频预训练**
- 在大规模视频-文本对上训练基础 DiT 模型
- 学习基本的视频生成和文本理解能力

**阶段 2：高质量微调**
- 在筛选的高质量数据上微调
- 提升视觉质量和细节层次

**阶段 3：物理一致性训练**
- 引入物理约束或 3D 先验
- 提升物体交互和物理合理性

**阶段 4：音频联合训练（Veo 3+）**
- 引入视频-音频对数据
- 训练视频-音频联合生成能力

#### 5.2.3 扩散调度与采样

Veo 可能采用先进的扩散调度策略：
- **EDM (Elucidating the Design Space of Diffusion Models)** 或类似改进调度
- **Flow Matching**：从扩散向流匹配的演进（如 Stable Diffusion 3）
- **少步采样**：通过蒸馏或一致性模型减少推理步数

### 5.3 推理优化

#### 5.3.1 渐进式生成

Veo 可能采用渐进式生成策略处理高分辨率长视频：

```
低分辨率短视频 (快速预览)
    ↓
高分辨率短视频 (空间超分)
    ↓
高分辨率长视频 (时间扩展)
    ↓
最终输出 (细化 + 音频)
```

#### 5.3.2 并行与缓存优化

- **FlashAttention**：优化时空注意力的内存访问
- **KV-Cache**：在自回归或因果生成中缓存历史 token
- **模型并行**：将大 DiT 模型分布到多 GPU
- **流水线并行**：重叠计算和数据传输

## 7. 挑战与未来方向

### 7.1 当前挑战

**1. 计算成本**
- DiT 视频生成的计算需求极高，4K 长视频的推理成本可能达到数百美元/分钟
- Veo 3.1 Fast/Lite 是应对这一挑战的尝试，但质量-成本权衡仍是核心难题

**2. 物理一致性**
- 尽管 Veo 2+ 显著改进，复杂物理交互（如流体、形变、破碎）仍难以精确模拟
- 长视频中的物理一致性衰减问题（后半段质量下降）

**3. 可控性**
- 相比 Runway 等工具的精细控制（相机运动、物体轨迹），Veo 的可控性仍较粗粒度
- 文本提示词对生成结果的控制精度有限

**4. 数据与版权**
- 训练数据的来源和版权问题持续受到关注
- Google 的 YouTube 数据优势同时也带来版权争议

**5. 安全与滥用**
- 深度伪造（Deepfake）风险
- 有害内容生成（暴力、色情、政治操纵）
- Google 需要在开放性和安全性之间取得平衡

### 7.2 未来方向

**1. 实时交互式视频生成**
- Veo Fast 系列的发展方向
- 应用场景：游戏、虚拟制作、实时特效
- 技术路径：模型蒸馏、神经渲染、混合生成-渲染 pipeline

**2. 世界模型（World Model）**
- 从"生成视频"到"模拟世界"的演进
- 可交互的 3D/4D 环境生成
- 与机器人、自动驾驶等领域的结合

**3. 多模态统一生成**
- 文本、图像、视频、音频、3D 的统一生成模型
- 与 Gemini 多模态 LLM 的深度融合
- 统一 token 空间下的任意模态转换

**4. 个性化与可控性**
- 基于少量示例的个性化风格学习
- 细粒度的时空控制（如指定物体的精确运动轨迹）

## 9. Vision Banana（2026-04）：把图像生成器当视觉骨干

> 本节为**增量新增**（2026-10-17），只写一手可核验内容；逐项数字、逐表条件、失效边界与未确证清单见专册 [`papers/2604.20329-vision-banana.md`](papers/2604.20329-vision-banana.md)。主等级 `[精读原文]`（arXiv:2604.20329 **v3**，2026-06-03）。

### 9.1 它是什么

**Vision Banana** 是 Google 把自家图像生成/编辑模型 **Nano Banana Pro（NBP）** 拿来做**视觉理解**的产物：在 NBP 的原训练混合里**以极低比例**掺入少量视觉任务数据做 instruction-tuning，得到**一套权重**的单一模型；任务只靠 prompt 切换。关键设计是把**视觉任务的输出空间参数化为 RGB 图像**，再对每种任务配一个"轻薄"的逆解码器：

| 任务 | 模型生成什么 | 怎么变回可打分的量 |
| :-- | :-- | :-- |
| 语义分割 | 按"类→颜色"映射上色的整幅图（含图中不存在的类） | 每像素取 RGB 最近的目标色 → mIoU |
| 实例分割 | 只给目标类 + 背景色，模型自己给每个实例分配不同颜色 | 多阶段连通域聚类（τ=14、16-连通、面积 2×10⁻⁴、3×3 腐蚀、γ=5.0） → cgF1 |
| 指代分割 | 按指代描述上色的 mask | 最近色/阈值 → cIoU / gIoU |
| 度量深度 | 一张与米制**严格双射**的假彩色深度图 | 投影到 RGB 立方体棱 + 反 power transform（λ=−3、c=10/3） → δ₁ / AbsRel |
| 表面法向 | camera-space 单位向量直写 R/G/B | 逐通道反解 → 平均角度误差 |

### 9.3 与本报告既有内容的关系（三点，均为"关系"而非"校正"）

1. **不是本生成谱系的"下一代"，而是同一批模型的"第二种用法"**。§3–§6 记录的是从 Imagen 级联扩散 → Lumiere 时空 U-Net → Veo DiT 的**生成质量演进**；Vision Banana **不引入新的生成架构**，它证明的是"**生成训练本身已经学到了可用于理解的表征**"。因此它不进 §4.1 的核心架构对比表，也不能被写成"Imagen/Veo 的后继"。
2. **它补上了本报告一个长期缺口：Nano Banana Pro 此前完全没有条目**。NBP 是产品级模型（2025-11-20 官方博客发布），Google 至今没有为它发布技术报告，论文正文也只以 "Nano Banana Pro" 指称它、**未披露参数量/架构/训练细节**。本报告据此**不推测**其架构；"它属 Gemini 3 Pro 图像侧"这一归属的证据来自官方博客而非论文正文（另见 `Models/Gemini/report.md` 的一行指向）。
3. **它把 §7.2 的"多模态统一生成"往前推了一步，但方向是"理解"而非"生成"**。§7.2 设想的统一是"文本/图像/视频/音频/3D 的统一**生成**"；Vision Banana 给出的是"**统一接口下的理解**"——图像生成当接口、语言 prompt 当任务说明。两者共享同一个假设（统一输出空间），但目标不同，不能混为一谈。

### 9.4 本条目视角下的引用注意

- **不要**把 Vision Banana 写进"Google 生成模型代际演进"叙事（它不是 Imagen/Veo 的后续版本，也不是新架构）。
- **不要**把"平均 δ₁ 0.882 最好"外推成"逐数据集超过 Depth Anything 3"——论文自己的表里 NYU 与 KITTI 两列是输的；**不要**把 SA-Co/Gold 的 47.5 说成"超过 SAM 3"（训练内 SAM 3 是 54.1，论文正文写明 "we still lag behind"）。
- **可以**引用的是方法论观察：① 生成目标对多模态输出歧义的处理优于判别式回归（与附录 C 的定性观察一致）；② 保留原训练混合的低比例掺数据，是"理解对齐但不遗忘生成"的可行做法（**幅度不可引**，人评协议未披露）。
- 成本侧只有一句定性（"显著高于跑轻量专门模型"），**没有任何延迟/算力数字**，因此"生成器可替代轻量专家"的成本论不被本文支持。

## 10. Nano Banana 2.1（2026-10）：生成与编辑型号更新

Google DeepMind 于 2026-10-06 发布 Nano Banana 2.1 模型卡。卡片将其描述为 **Gemini 3.6 Flash 的衍生型号**，支持文本和图像输入，图像及文本输出；模型卡列出最高 1M 输入上下文。该归属是目前可确认的公开模型依赖关系，但卡片没有给出图像生成模块的具体网络结构、参数量、扩散/自回归机制或独立训练数据配方，因此不能把它的实现细节写成 Imagen 4 或 Veo 系列的架构证据。

评测分 Thinking / No Thinking 两种设置，分别报告文本生成图像与图像编辑能力。模型卡使用成对人评 Elo 比较总体偏好、信息图设计和编辑能力，并以自动评分器评估信息图事实性；这些测试是 Google 公布的内部评测结果，模型卡没有提供独立复现。卡片指出的限制包括小字与长段落渲染、输入输出人物一致性、编辑指令遵循、姿态保留、左右定位以及高级世界知识、3D 推理和事实性。

对本报告架构主线的影响有限：Nano Banana 2.1 扩展了 Gemini 派生图像生成与编辑的产品支线，但公开资料尚不足以解释其图像生成器如何构造、与 Imagen 4 有何模块关系，或是否继承 Vision Banana 论文的训练设计。Vision Banana（§9）是另一项研究工作，不能由相似命名推断为 Nano Banana 2.1 的实现说明。
