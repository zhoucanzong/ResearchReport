# EmbeddingGemma 2：把多模态检索压进一个共享向量空间

## 研究问题：为什么还需要一个专门的 embedding 模型？

向量检索系统通常把文本、图片、音频和视频交给不同编码器；当查询混合多种模态时，还要先做 ASR、图像描述或片段对齐。这些前置步骤增加系统复杂度，也可能丢掉声音质感、画面细节或模态间关系。反过来，把大型多模态生成模型当 embedding 模型，又可能带来较高的推理和存储负担。

EmbeddingGemma 2 研究的问题是：**能否用小型模型把文本、代码、图像、视频、音频及其交错组合映射到可比较的共享向量空间，同时保留资源受限部署能力？** 它输出固定长度向量供检索、相似度、分类和聚类使用；它不是用于回答问题或生成文本的 Gemma 变体。[arXiv v1, §§1–2](https://arxiv.org/html/2610.37364v1)

## 架构：模态编码器接入共享 Transformer

论文报告的模型总量约 **744M 参数**：双向 Transformer backbone 与文本 embedder 合计约 271M，视觉编码器约 167M，音频编码器约 305M。官方模型卡把总参数四舍五入写作 740M；引用时要区分论文报告的组件相加值和产品卡的圆整值。[§2.1](https://arxiv.org/html/2610.37364v1) · [官方模型卡](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)

文本 token 由主 embedding table 映射；图像、音频等经可选编码器变成 soft token embeddings，再与文本 token 按输入顺序拼接。随后，所有 token 经过一个 **24 层、双向注意力**的 Transformer，模型对输出序列做 mean pooling，再线性投影并归一化，得到 768 维单位向量。这样设计的目标是让不同模态能在同一空间里互相检索，而不是让每种模态各自输出互不相容的分数。[§§2.1–2.2](https://arxiv.org/html/2610.37364v1)

### 一个参数设计选择：不要为每层再存一张 token 表

Gemma 3n / Gemma 4 使用 Per-Layer Embeddings（PLE）向中间层补充输入信息。EmbeddingGemma 2 保留每层投影，但去掉专用的 PLE lookup table，直接从共享输入 embedding 与模态编码器输出产生层级输入。作者的 MMEB-v2 中间 checkpoint 对照显示，projection-only 在 overall、image、video、visual-document 子项上均略高于带 lookup 的配置。这个消融说明“增加一张参数表”并非默认有益，且共享输入空间对多模态 token 有接口优势；实验仍限于该中间训练阶段和对应 benchmark。[§2.1、§3.1、Table 2](https://arxiv.org/html/2610.37364v1)

## 训练目标：让相似度可检索，而不只模仿教师

EmbeddingGemma 2 的训练把几类目标放在不同阶段组合：

| 目标 | 解决什么问题 | 机制与取舍 |
|---|---|---|
| 对比学习（NCE） | 让 query 与正目标接近、与负例分开 | 联合使用 in-batch、hard negative 与 same-tower negative；用重复样本 mask 避免把假负例推远 |
| Spread-out regularizer | 避免向量集中在表示空间的一小片区域 | 惩罚随机同塔向量的过高相似度；目标是改善空间利用、量化鲁棒性和 ANN 检索 |
| 教师蒸馏 | 从 Gemini Embedding 2 迁移跨模态知识 | 匹配 query、正目标和 hard-negative 向量；教师向量可截断以适配学生维度 |
| Matryoshka Representation Learning（MRL） | 让一个 checkpoint 支持多种向量长度 | 对重叠的 embedding 前缀维度分别训练，可输出 768、512、256 或 128 维向量 |

对比目标不仅让正例相似度上升，还要选负例、屏蔽重复项并处理跨任务梯度尺度。作者去掉早期版本的 hardness weighting，理由是弱关联正例会在训练早期放大噪声；同时加 same-tower negatives，避免 query 与 document 两侧坍缩到彼此分离的子空间。含排序标注的任务还用 Plackett–Luce listwise loss，而不是把所有监督都压成二元正负对。[§2.3](https://arxiv.org/html/2610.37364v1)

训练流程先进行 text-only pre-finetuning，再做 multimodal pre-finetuning，最后以对比学习和 spread-out regularizer 做 multimodal finetuning；之后再 merge checkpoint 并做量化感知训练。作者的 compute-equivalent 消融显示，继续蒸馏在相同步骤设置下基本停滞，最后的多模态 finetuning 对图像和视频检索提升明显，对视觉文档大致持平。这支持该训练阶段对所测任务有效，不证明蒸馏对所有模态无用。[§2.4、§3.2、Table 3](https://arxiv.org/html/2610.37364v1)

## 评测：总体跨模态覆盖，不等于每一类都胜过专用模型

论文在 MTEB（文本与代码）、MIEB（图像）、MMEB-v2（图像、视频、视觉文档）、MSEB 与 MAEB（音频）上评测。它们测的是 embedding retrieval、相似度或分类等任务，不能与生成模型的问答准确率并表。作者限制为 single-vector 模型，过滤训练数据与 benchmark 重叠率较高的模型；baseline 多来自公开 leaderboard，Jina Embeddings v5 Omni Nano 则以论文所述官方实现运行。[§4.1](https://arxiv.org/html/2610.37364v1)

| 结果 | 作者报告 | 该结果支持什么 / 不能支持什么 |
|---|---|---|
| 代码 embedding | MTEB Code Mean(Task) 从 EmbeddingGemma 1 的 68.76 升至 78.68 | 支持代码检索表示有所改善；不代表文本、视觉、音频所有任务同步提升。[Table 6] |
| 共享空间表现 | 论文在多组图像、视频、视觉文档及音频任务上与小于 1B 或专用模型对照 | 作者报告其跨模态整体表现形成 Pareto frontier；不同 benchmark、指标和训练污染过滤条件不同，不应压成“处处领先”。[Table 6、§§4.2–4.4] |
| native audio vs ASR | 同一模型族以 native audio 输入的 MSEB retrieval 高于先 ASR 再用文本向量的路径；full-dimensional MRR@10 为 69.54 vs 57.59 | 表明在该跨语言语音检索设置中，直接编码声学信息能保留 ASR 转写可能丢失的信号；并非所有音频任务都不需 ASR。[§4.4、Table 11] |
| 模态专用能力 | 音频 captioning 等个别子任务仍由 specialist 更强；gender clustering 低于 linear-probe 表现 | “共享空间”不等于每种语义标签都能零样本分开；表示可含某种信息，却不保证该信息在未经任务适配的距离几何中显现。[§4.4] |

### 消融揭示的资源—质量折中

视觉编码器若冻结，MMEB-v2 中间配置 overall 从 trainable 的 52.27 降至 48.18。这个结果挑战“多模态模型通常冻结视觉塔即可”的简单假设；两组模型都从相同 text pre-finetuning checkpoint 开始，证据只适用于该训练方案。[§3.3、Table 4]

视觉 token budget 也不是越多越好：视觉文档 retrieval 会从更细粒度 token 中获益；video 在推理预算从 280 增至 560 时反而下降，作者讨论了长序列稀释注意力与 mean-pooling 表示的问题。任务家族和帧率预算会改变最优点，部署前应在目标工作负载上验证。[§3.4、Table 5]

MRL 让输出可以截短，256 维在多项测试中接近 768 维；128 维则使某些多模态指标下降更明显。官方模型卡特别要求截断后重新做 L2 normalization，并让 query 和文档使用相同维度。精简向量减少存储，不意味着不改变相似度排序。[Appendix C] · [官方模型卡](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)

## 证据边界与开放问题

- 论文结果是作者报告；多数基线来自公开 leaderboard，不能当作独立复现或生产 RAG 的端到端成效。
- 单向量检索有存储和部署优势，但如何保留精细局部证据并非所有任务都一样；visual document 对 token budget 敏感，video 对过高预算可能退化。
- 数据覆盖、语言分布和训练—评测泄漏筛选影响结论。论文的 benchmark 覆盖广，但不等同真实多应用检索用户任务。
- 文本、图片、视频和音频的向量落在共享空间，不代表四类模态拥有相同的信息密度、可分性或校准质量。
- 该模型是 embedding encoder，不是回答问题的生成式 Gemma。它适合作为 RAG、搜索、分类或聚类管线的表示层，最终回答质量还取决于召回、重排、生成和验证。
