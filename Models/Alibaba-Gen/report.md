## 1. 概述

### 1.1 项目背景

通义万相（Wan）是阿里巴巴通义实验室推出的开源视频/图像生成大模型系列，于 2025 年初正式开源发布。该系列模型基于 **DiT（Diffusion Transformer）** 架构，采用 **3D 时空联合注意力机制**，旨在提供高质量、可控的视频生成能力，同时保持对中文语境和本土文化元素的深度优化。

Wan 系列的核心定位是**开源、可本地部署的视频生成模型**，直接对标 OpenAI 的闭源 Sora 模型。与 Sora 仅通过云端 API 提供服务不同，Wan 从发布之初就开放了完整的模型权重和推理代码，使得研究者和开发者能够在本地环境（包括消费级 GPU）上运行和定制视频生成流程。

### 1.2 核心优势

| 维度 | 说明 |
|------|------|
| **开源开放** | 模型权重、推理代码、训练细节全面开源，社区可自由使用和改进 |
| **中文优化** | 针对中文提示词理解、本土文化元素（如汉服、中式建筑）进行专门优化 |
| **消费级部署** | 1.3B 轻量模型可在 RTX 4060/4070 级别 GPU 上运行，降低使用门槛 |
| **生态集成** | 深度集成 HuggingFace、ComfyUI、Diffusers 等主流开源框架 |
| **持续迭代** | 从 Wan 2.1 到 Wan 2.6，快速迭代，功能持续增强 |

### 1.3 报告范围

本报告重点分析 Wan 系列从 2.1 到 2.6 的架构演进，涵盖模型结构、训练策略、开源生态、部署方案及与竞品的对比分析。同时纳入 2026 年 4 月发布的**天马（Tianma）**图像到视频模型作为补充参考。

## 3. 每代模型架构详解

### 3.1 Wan 2.1 (2025.01)

#### 3.1.1 发布背景

Wan 2.1 是阿里巴巴通义万相系列的首个开源版本，于 2025 年 1 月正式发布。该版本的发布标志着阿里巴巴正式加入开源视频生成大模型的竞争行列，与 OpenAI Sora、Runway Gen-3 等闭源模型形成差异化竞争策略。

#### 3.1.2 模型规格

Wan 2.1 提供两个主要规格：

| 规格 | 参数量 | 目标场景 | 显存需求 | 典型部署 GPU |
|------|--------|----------|----------|--------------|
| **Wan 2.1-14B** | 14 Billion | 全量高质量视频生成 | ~24GB+ | RTX 4090 / A100 / H100 |
| **Wan 2.1-1.3B** | 1.3 Billion | 轻量快速推理/消费级部署 | ~8-12GB | RTX 4060 Ti / RTX 4070 |

#### 3.1.3 架构设计

Wan 2.1 采用经典的 **3D DiT（Diffusion Transformer）** 架构，核心组件包括：

**1) 3D Causal VAE（变分自编码器）**

- **功能**：将原始视频数据压缩到低维潜空间（Latent Space），大幅降低后续 DiT 模型的计算负担
- **时空联合压缩**：同时在空间维度（H×W）和时间维度（T）上进行压缩，压缩比通常为 4×8×8（时间×高度×宽度）或类似配置
- **Causal 设计**：时间维度采用因果卷积，确保生成过程的时间一致性，避免未来帧信息泄露到当前帧
- **优势**：相比 2D VAE（如 Stable Diffusion 使用的），3D Causal VAE 能更好地保持视频时序连贯性

**2) 3D DiT（Diffusion Transformer）**

- **基础架构**：基于 Transformer 的扩散模型，替代传统的 U-Net 骨干网络
- **时空联合注意力（Spatio-Temporal Joint Attention）**：
  - **空间注意力**：处理单帧图像内的空间关系（类似标准 ViT 的自注意力）
  - **时间注意力**：处理跨帧的时间关系，确保运动连贯性
  - **联合机制**：通过统一的注意力计算同时建模空间和时间依赖，而非分离的模块设计
- **AdaLN（Adaptive Layer Normalization）**：注入时间步（timestep）和条件信息（文本提示）
- **文本编码器**：采用大规模预训练语言模型（如通义千问系列）提取文本特征，确保中文语义理解能力

**3) 条件注入机制**

- **文本条件**：通过交叉注意力（Cross-Attention）或 AdaLN 将文本嵌入注入 DiT
- **可选条件**：支持分辨率、时长、帧率等元信息作为额外条件

#### 3.1.4 训练策略

| 阶段 | 目标 | 数据规模 | 关键配置 |
|------|------|----------|----------|
| **Stage 1: VAE 预训练** | 训练 3D Causal VAE | 大规模视频+图像 | 重建损失 + 感知损失 + 对抗损失 |
| **Stage 2: DiT 预训练** | 训练基础 DiT 模型 | 千万级视频-文本对 | 文本到视频（T2V）任务 |
| **Stage 3: 微调优化** | 提升质量和可控性 | 高质量子集 | 高分辨率微调；人类偏好对齐 |

#### 3.1.5 性能表现

- **VBench 评测**：Wan 2.1-14B 在 VBench（视频生成基准测试）多个维度上取得领先成绩，包括语义一致性、运动平滑度、时序连贯性等
- **中文优势**：在中文提示词理解方面显著优于同期开源模型（如 CogVideo、Open-Sora 等）
- **生成质量**：支持 720p 分辨率视频生成，时长通常为 5-10 秒

#### 3.1.6 开源内容

- 模型权重（14B 和 1.3B 两个版本）
- 推理代码（PyTorch 实现）
- 技术报告（架构和训练细节）
- HuggingFace 模型卡和使用示例

### 3.2 Wan 2.2 (2025)

#### 3.2.1 改进概述

Wan 2.2 是在 2.1 基础上的重要迭代版本，重点解决视频生成中的**运动一致性**和**推理效率**问题，同时显著增强**图像到视频（I2V, Image-to-Video）**能力。

#### 3.2.2 核心改进

**1) 运动一致性提升**

- **问题**：Wan 2.1 在部分场景下存在运动不自然、物体变形、时序闪烁等问题
- **改进措施**：
  - 优化时间注意力机制，引入更精细的时序建模
  - 改进训练数据筛选，增加高质量运动样本权重
  - 引入运动一致性损失（Motion Consistency Loss），约束相邻帧间的光流一致性
- **效果**：物体运动轨迹更平滑，形变更少，长视频连贯性提升

**2) 推理速度优化**

- **优化方向**：
  - **注意力优化**：采用 FlashAttention-3 或等效的高效注意力实现，降低显存占用和计算延迟
  - **模型编译**：支持 torch.compile 等图编译优化
  - **采样步数减少**：通过改进的采样调度器（Scheduler），在保持质量的前提下减少去噪步数
- **效果**：相同硬件下推理速度提升 20-40%

**3) I2V（图像到视频）能力增强**

- **背景**：Wan 2.1 主要聚焦 T2V（文本到视频），I2V 能力相对基础
- **Wan 2.2 改进**：
  - 专门训练 I2V 分支，将首帧图像作为强条件注入
  - 支持多种 I2V 模式：静态图动画化、首帧引导续写、风格化视频生成
  - 图像条件通过专门的图像编码器（Image Encoder）提取特征，与文本条件融合后注入 DiT
- **应用场景**：照片动画化、艺术风格迁移、产品展示视频生成

#### 3.2.3 工程优化

**量化支持**

| 量化方案 | 精度 | 显存节省 | 质量损失 | 适用场景 |
|----------|------|----------|----------|----------|
| **FP16** | 16-bit | ~50% vs FP32 | 极小 | 标准推理 |
| **BF16** | 16-bit | ~50% vs FP32 | 极小 | 训练/推理 |
| **INT8** | 8-bit | ~75% vs FP32 | 轻微 | 快速推理 |
| **AWQ** | 4-bit | ~85% vs FP32 | 可控 | 消费级部署 |
| **GPTQ** | 4-bit | ~85% vs FP32 | 可控 | 消费级部署 |

- **AWQ/GPTQ 集成**：社区和官方共同推动量化方案，使得 14B 模型可在 16GB 显存 GPU 上运行，1.3B 模型可在 6-8GB 显存上运行
- **显存优化技术**：
  - 梯度检查点（Gradient Checkpointing）风格的推理优化
  - 分块注意力（Chunked Attention）处理长视频序列
  - CPU 卸载（CPU Offload）支持超大模型在有限显存下运行

#### 3.2.4 开源生态进展

- **Diffusers 集成**：HuggingFace Diffusers 库官方支持 Wan 2.2，提供标准化 Pipeline API
- **ComfyUI 节点**：社区开发的 ComfyUI 节点功能完善，支持工作流可视化搭建
- **LoRA 微调**：社区出现大量基于 Wan 2.2 的 LoRA 微调模型，覆盖特定风格、角色、场景

### 3.3 Wan 2.6 (2026)

#### 3.3.1 重大升级概述

Wan 2.6 是通义万相系列的重大版本升级，于 2026 年 1 月发布。该版本实现了从**纯视频生成**到**音视频联合生成**的跨越，同时在视频时长、生成质量和消费级部署友好性方面达到新高度。

#### 3.3.2 核心新特性

**1) 原生音频生成（Native Audio Generation）**

- **突破**：Wan 2.6 是首批支持**音视频联合生成**的开源模型之一
- **实现方式（推测）**：
  - 在 3D DiT 基础上增加音频生成分支，或采用统一的音视频联合 DiT 架构
  - 音频-视频联合注意力机制（Audio-Video Joint Attention），建模视听一致性
  - 时间对齐模块确保音频节奏与视频画面（如口型、动作）同步
- **应用场景**：
  - 带背景音乐的短视频生成
  - 人物说话视频（对口型）
  - 音效与画面匹配（如爆炸声、雨声）

**2) 更长视频生成**

- **时长提升**：从 Wan 2.1/2.2 的 5-10 秒扩展到 **15-25 秒**
- **技术支撑**：
  - 改进的时序建模机制，支持更长序列的注意力计算
  - 滑动窗口注意力（Sliding Window Attention）或线性注意力（Linear Attention）降低长序列复杂度
  - 分块生成 + 无缝拼接策略

**3) 消费级部署里程碑**

- **RTX 4070 Ti 可本地运行**：Wan 2.6 通过架构优化和量化支持，实现与 **LTX-2（Lightricks 开源视频模型）** 同级别的消费级部署能力
- **关键指标**：
  - 14B 模型 + 4-bit 量化：可在 RTX 4070 Ti（12GB）上运行
  - 1.3B 模型 + FP16：可在 RTX 4060（8GB）上流畅运行
  - 生成 5 秒 720p 视频：消费级 GPU 耗时约 2-5 分钟

**4) 完全开源与 ComfyUI 原生集成**

- **完全开源**：模型权重、推理代码、技术报告全面开放
- **ComfyUI 原生支持**：官方提供 ComfyUI 节点，无需第三方社区适配
- **工作流模板**：官方提供多种预设工作流（T2V、I2V、音视频联合生成）

#### 3.3.3 架构演进推测

基于 Wan 2.6 的功能特性，其架构可能在以下方面进行了演进：

| 组件 | Wan 2.1/2.2 | Wan 2.6（推测） |
|------|-------------|-----------------|
| **VAE** | 3D Causal VAE | 改进的 3D Causal VAE，更高压缩比或更好重建质量 |
| **DiT 骨干** | 3D DiT + 时空联合注意力 | 增强型 3D DiT，支持更长序列；可能引入线性注意力变体 |
| **音频模块** | 无 | 新增音频生成分支（Audio DiT 或 Audio Decoder） |
| **联合建模** | 无 | 音频-视频联合注意力 / 交叉模态对齐模块 |
| **条件注入** | 文本 + 图像 | 文本 + 图像 + 音频提示 + 时长/风格控制 |
| **文本编码器** | 通义千问系列 | 升级版本，更强的多语言/多模态理解 |

**可能的架构细节**：

- **音频编码器/解码器**：采用类似 AudioLDM、Stable Audio 的音频 VAE 将音频压缩到潜空间
- **联合 DiT**：在统一的 Transformer 框架下同时处理视频潜变量和音频潜变量，通过模态标识符（Modal Token）区分不同模态
- **时序对齐**：音频采样率（如 16kHz/24kHz）与视频帧率（如 24fps/30fps）的精确时间对齐机制

#### 3.3.4 性能与评测

- **VBench 2.0 / 同类基准**：在视频质量、运动一致性、时序连贯性等维度保持领先
- **音频质量**：在 FAD（Frechet Audio Distance）、CLAP 分数等音频指标上达到可用水平
- **中文场景**：在中文口型同步、中文语音生成方面具有独特优势

### 3.4 天马 Tianma (2026.04)

#### 3.4.1 发布背景

天马（Tianma）是阿里巴巴于 2026 年 4 月发布的图像到视频（I2V）专用模型，目前处于 **Beta 测试阶段**。该模型可视为 Wan 系列在 I2V 方向的专门化延伸。

#### 3.4.2 定位与特点

| 维度 | 说明 |
|------|------|
| **定位** | 专注图像到视频生成，与 Wan 系列的通用视频生成形成互补 |
| **阶段** | Beta 测试，部分功能/权重可能逐步开放 |
| **架构基础** | 推测基于 Wan 2.6 的 I2V 能力进一步扩展和优化 |
| **目标场景** | 照片动画化、电商产品视频、艺术创作、社交媒体内容 |

#### 3.4.3 架构推测

基于现有信息和 Wan 系列的技术路线，天马的架构可能包括：

- **图像编码器**：采用高性能视觉编码器（如 ViT-LLaMA 风格）提取图像特征
- **运动预测模块**：专门预测图像中的运动轨迹和时序变化
- **视频 DiT 解码器**：基于 Wan 的 3D DiT，以图像特征为初始条件生成后续帧
- **增强的 I2V 对齐**：更强的首帧保真度约束，确保生成视频与输入图像在内容、风格、构图上高度一致

#### 3.4.4 与 Wan 系列的关系

```
Wan 系列（通用视频生成）
├── T2V（文本到视频）
├── I2V（图像到视频）—— 基础能力
└── A2V（音频到视频）—— Wan 2.6 新增

Tianma（天马）
└── I2V（图像到视频）—— 专门优化，更深度的图像理解和运动生成
```

天马可能在以下方面超越 Wan 的 I2V 能力：
- 更精细的图像细节保持
- 更丰富的运动模式（相机运动 + 物体运动）
- 更长的视频时长（可能支持 30 秒以上）
- 更强的风格一致性

## 4. 核心技术特点

### 4.1 3D Causal VAE：时空联合压缩

**技术原理**：

3D Causal VAE 是 Wan 系列视频生成的基础组件，负责将高维原始视频数据压缩到低维潜空间表示。

```
输入视频: [T, H, W, 3] (帧数 × 高 × 宽 × RGB)
    ↓
3D Causal VAE Encoder
    ↓
潜空间表示: [t, h, w, c] (压缩后的时间 × 高度 × 宽度 × 通道)
    ↓
3D DiT 处理（扩散过程）
    ↓
3D Causal VAE Decoder
    ↓
输出视频: [T, H, W, 3]
```

**关键设计**：

| 设计 | 说明 | 优势 |
|------|------|------|
| **3D 卷积** | 同时在空间（H, W）和时间（T）维度进行卷积 | 统一建模时空信息 |
| **Causal 时间卷积** | 时间维度仅依赖过去和当前帧，不依赖未来帧 | 保证生成过程的因果性，支持自回归扩展 |
| **潜空间通道** | 通常为 16 或 32 通道 | 平衡压缩率和重建质量 |
| **压缩比** | 典型配置 4×8×8（时间×高度×宽度） | 将计算量降低约 256 倍 |

**与 2D VAE 的对比**：

| 特性 | 2D VAE（如 SD 1.5） | 3D Causal VAE（Wan） |
|------|---------------------|----------------------|
| 输入 | 单帧图像 | 视频片段 |
| 时间建模 | 无 | 原生支持 |
| 视频生成 | 需额外时序模块（如 AnimateDiff） | 端到端原生支持 |
| 时序一致性 | 依赖后处理 | 内建因果约束 |
| 计算效率 | 逐帧处理，冗余计算 | 时空联合，更高效 |

### 4.2 3D DiT：空间 + 时序注意力

**架构演进**：

DiT（Diffusion Transformer）由 Peebles & Xie 在 2023 年提出，用 Transformer 替代扩散模型中的 U-Net 骨干。Wan 系列将 DiT 扩展到 3D 时空域。

**标准 DiT（图像生成）**：
```
输入: 图像 Patch Embedding + 位置编码
    ↓
Transformer Blocks × N
    ├── 自注意力（空间）
    ├── 交叉注意力（文本条件）
    └── FFN + AdaLN
    ↓
输出: 预测噪声 / 预测 v-prediction
```

**Wan 3D DiT（视频生成）**：
```
输入: 视频 Patch Embedding (时空联合) + 时空位置编码
    ↓
3D Transformer Blocks × N
    ├── 时空联合自注意力
    │   ├── 空间注意力分支: 处理单帧内 H×W 关系
    │   ├── 时间注意力分支: 处理跨帧 T 关系
    │   └── 融合机制: 串联/并联/交替
    ├── 交叉注意力（文本/图像/音频条件）
    └── FFN + AdaLN (注入时间步和条件)
    ↓
输出: 预测视频潜空间噪声
```

**注意力机制变体**：

| 变体 | 计算方式 | 复杂度 | 适用场景 |
|------|----------|--------|----------|
| **Full Spatio-Temporal Attention** | 所有时空 token 两两计算 | O((T×H×W)²) | 短视频，高质量 |
| **Factorized Attention** | 空间注意力和时间注意力分离交替 | O((H×W)²) + O(T²) | 平衡效率和质量 |
| **Sliding Window Temporal** | 时间维度仅关注邻近帧 | O((H×W)²) + O(T×w) | 长视频，降低复杂度 |
| **Linear Attention** | 线性复杂度注意力近似 | O(T×H×W) | 超长视频，实时性要求 |

Wan 2.1/2.2 可能采用 **Factorized Attention**，Wan 2.6 可能引入 **Sliding Window** 或 **Linear Attention** 变体以支持更长视频。

### 5.3 快速部署指南

**环境要求**：
- Python 3.10+
- PyTorch 2.2+
- CUDA 12.1+（NVIDIA GPU）或 ROCm（AMD GPU）
- 推荐 16GB+ 显存（FP16 14B）或 8GB+（1.3B/量化 14B）

**安装步骤**：

```bash
# 1. 克隆仓库
git clone https://github.com/alibaba/Wan-2.1.git
cd Wan-2.1

# 2. 安装依赖
pip install -r requirements.txt

# 3. 下载模型权重（通过 HuggingFace CLI）
huggingface-cli download alibaba-pai/Wan2.1-T2V-14B --local-dir ./models/14B

# 4. 运行推理
python generate.py \
    --prompt "一只熊猫在竹林中吃竹子，高清，4K" \
    --model_dir ./models/14B \
    --resolution 720p \
    --duration 5s \
    --output ./output.mp4
```

**Diffusers 快速使用**：

```python
from diffusers import WanPipeline
from diffusers.utils import export_to_video
import torch

# 加载模型
pipe = WanPipeline.from_pretrained(
    "alibaba-pai/Wan2.1-T2V-14B",
    torch_dtype=torch.bfloat16
)

# 启用内存优化（可选）
pipe.enable_model_cpu_offload()
pipe.enable_vae_slicing()

# 生成视频
video = pipe(
    prompt="一位穿着汉服的女子在樱花树下翩翩起舞，水墨画风格",
    num_frames=81,
    height=720,
    width=1280,
    guidance_scale=7.5,
    num_inference_steps=50
).frames[0]

# 保存视频
export_to_video(video, "output.mp4", fps=16)
```

**量化部署（AWQ）**：

```python
from diffusers import WanPipeline
import torch

# 加载 AWQ 量化模型
pipe = WanPipeline.from_pretrained(
    "alibaba-pai/Wan2.1-T2V-14B-AWQ",
```

## 8. 挑战与未来方向

### 8.1 当前挑战
