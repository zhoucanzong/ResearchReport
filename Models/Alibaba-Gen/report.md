# 阿里巴巴通义万相（Wan）视频生成模型研究报告

> 原报告日期：2026-06-06；证据修订：2026-10-22。研究主体保留 Wan 2.1 / 2.2 / 2.6，不把本次复核扩展为最新型号大全。

## 1. 执行摘要

Wan 的两条发布线需要分开理解：Wan 2.1 / 2.2 有公开权重与推理仓库，可以检查配置；Wan 2.6 在本次核读材料中是阿里云提供的音视频生成服务。服务接口中的时长、音频和分辨率不能证明同名模型开放了权重，更不能推出消费级显卡部署条件。[S1–S4]

在可解释的机制上，Wan 2.1 的关键组合是时空压缩、完整时空注意力、文本交叉注意力与 flow matching；文本编码器是 **umT5**，Qwen 在官方示例中还可承担提示词扩写，两者不能混为一个组件。Wan 2.2 的 A14B 分支进一步按去噪阶段使用两个专家，而 TI2V-5B 是另一条高压缩的稠密模型路线。[S1 §4.2；S2 Prompt Extension；S3 Introduction]

已有结果支持在指定模型、提示集和推理配置下分析质量与效率取舍。它们没有证明 Wan 全系列在所有场景领先，也没有证明从参数存储大小就能估算完整推理显存。以下区分作者实验、官方运行示例与尚未核实的内容。

## 3. Wan 2.1：机制与为什么这样设计

### 3.1 表示和去噪主干

Wan-VAE 在时间和空间共同压缩，论文图 6 与 §4.1 给出时间×高度×宽度为 4×8×8 的压缩。§4.2.1 中 patchifying 再以 (1,2,2) 卷积组织潜变量；去噪 Transformer 在时空 token 上计算注意力，通过交叉注意力接入文本。**完整时空注意力**和“空间、时间两个分支交替”的因子化注意力是不同设计，不能在同一架构图里互换。[S1 图 6、图 9–10、§4.2.1]

时间步经 MLP 产生调制参数；该 MLP 跨 Transformer blocks 共享，各 block 保留独立偏置。这样把部分参数预算从条件调制转到主干深度，论文专门用对照实验检查该取舍。[S1 §4.2.1、§4.7.2]

文本条件来自 umT5，而非凭“阿里模型”推断为 Qwen。官方运行流程可以先让 Qwen 扩写用户提示，再把扩写文本交给生成模型。提示扩写改变输入分布，质量比较时应记录是否开启；它不能被当成视频主干使用 Qwen 编码器的证据。[S1 §4.2.1；S2 Prompt Extension]

### 3.2 目标函数与训练课程

论文 §4.2.2 定义噪声端点 x₀、数据端点 x₁，插值 xₜ = t x₁ + (1−t)x₀，训练网络回归速度 x₁−x₀。报告应据此称为 flow matching 训练，而非把任意扩散模型的噪声预测公式直接移植过来。[S1 式 1–3]

课程先做低分辨率图像预训练，再进行图像与视频联合训练，逐步增加分辨率；后训练保持模型架构和优化器配置，用更高质量数据优化。该流程说明高分辨率长序列会限制吞吐与 batch size，不能用“从一开始联合训练全部高分辨率视频”替代真实课程。[S1 §4.2.2–4.2.3]

## 5. Wan 2.2：按噪声阶段分工的专家

A14B 分支把去噪初段和末段交给不同专家，分别处理高噪声结构与低噪声细节；TI2V-5B 则采用稠密主干和更高压缩的 VAE。这些是两条不同的扩容/压缩路线，不能把 A14B 的机制套到全部 Wan 2.2 模型上。[S3 Introduction]

官方介绍比较了旧模型、替换高噪声专家、替换低噪声专家与完整新方案的验证损失曲线。它支持在所测训练设置下分工有益；该曲线本身没有分离更大训练数据带来的贡献，也没有证明原报告所写的“运动一致性损失”“固定 20–40% 加速”。这些缺少来源的机制与数字不再保留。[S3 Introduction → Mixture-of-Experts]

## 6. 部署条件与可复查示例

Wan 2.1 官方 README 报告 1.3B、480P、5 秒视频在 RTX 4090 上约 4 分钟；8.19 GB 为其报告的显存需求，完整配置还要看 Computational Efficiency 表与卸载选项。它不等于 8GB 显卡无条件可运行，更不能推广为 14B 或 Wan 2.6 的结果。[S2 Key Features、Computational Efficiency]

Wan 2.2 官方单卡示例分别给出 A14B 与 TI2V-5B 的条件；后者使用 CPU 卸载等选项时可按 24GB GPU 示例操作。复现时应固定模型分支、分辨率、帧数、步数和卸载配置，不能只列显卡型号。[S3 Run Generation]

以下是依据 **Wan 2.1 官方 README** 整理的示例，已核对参数名称，本次未下载模型或运行 GPU 推理：

```bash
git clone https://github.com/Wan-Video/Wan2.1.git
cd Wan2.1
git checkout 9737cba9c1c3c4d04b33fcad41c111989865d315
pip install -r requirements.txt
huggingface-cli download Wan-AI/Wan2.1-T2V-1.3B --local-dir ./Wan2.1-T2V-1.3B
python generate.py --task t2v-1.3B --size '832*480' \
  --ckpt_dir ./Wan2.1-T2V-1.3B --offload_model True --t5_cpu \
  --sample_shift 8 --sample_guide_scale 6 \
  --prompt 'A panda eating bamboo in a forest.'
```

原报告的 `alibaba/Wan-2.1` 仓库、`alibaba-pai/...-AWQ` 模型和 `--model_dir / --resolution / --duration` 命令没有形成可执行证据链，已由上面的官方路径替换。参数×位宽只估算权重存储；文本编码器、VAE、激活、注意力和运行时仍占显存，因此删除由此算出的整机显存与 2–3 倍加速表。

## 7. Wan 2.6：服务能力与未知实现

本次实读阿里云文档中，T2V / I2V 服务列出音画同步、多镜头、720P / 1080P 以及最长 15 秒的时长范围；R2V 是另一个接口分支，不能把其配置合并成全系列统一上限。[S4 “Wan 2.6” 表；文档最后更新 2026-10-11]

目前核读的资料不足以确定 Wan 2.6 的权重许可、参数量、音频分支形式、位置编码和本地推理配置。原报告的“完全开源”“4070 Ti 可运行”“15–25 秒”“原生 ComfyUI 权重”和对应架构推演均撤回。API 可调用只证明服务存在，不能证明开放权重；2.1 / 2.2 的实现也不能未经证据继承给 2.6。

## 8. 失效边界与后续研究

- **作者明确的限制**：大运动下细节保真、14B 推理成本，以及教育、医学等专业局部场景的知识不足。[S1 §6]
- **评价偏见**：主要实验取自作者技术报告，Wan-Bench 的权重与人评由作者组织；本次未做独立生成、盲评或跨推理引擎复现。VBench 与 Wan-Bench 衡量的维度也不同。
- **中文能力**：论文展示中英文视觉文字生成，不足以证明其在所有中文提示或文化题材上优于同代模型。要比较中文优势，应固定双语提示、采样数和失败分类。
- **下一批补证**：补 Wan 2.2 完整实验的训练条件和数据贡献对照；获取 Wan 2.6 发布时的官方公告与接口历史快照；确认 Tianma 名称归属。完成前不恢复相关硬件、模型身份或架构结论。
