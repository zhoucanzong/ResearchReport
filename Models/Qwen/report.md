# Qwen系列模型深度调研报告

> **覆盖范围**：以公开论文和技术报告可支持的 Qwen 架构、训练、推理与多模态研究为主。产品公告仅在能帮助理解研究路线时纳入；没有技术材料的发布状态不等同于能力或机制证据。

---

## 1. 概述与发展时间线

### 1.1 怎样读 Qwen 的研究路线

Qwen 不是单一文本模型的版本序列，而是共享部分基座技术、又分别发展的模型家族。读者可沿四条互相关联但不能混为一谈的路线进入：

1. **基座与架构**：从密集 Transformer 到 GQA、MoE 与混合注意力，关注参数共享、激活计算和上下文处理的取舍。
2. **后训练与推理**：从指令/偏好对齐到 Thinking、可验证奖励与长程工具使用，区分训练时策略更新和推理时增加计算。
3. **视觉语言与全模态**：关注视觉 token 的分辨率和时序表示，以及音视频输入输出如何接入语言模型；不同产品线不自动共用同一架构。
4. **专业模型与数据**：代码、数学、语音等方向展示任务数据、专用训练目标和通用基座之间的关系。

后续章节按这些研究问题展开。时间线用于定位代表工作，不意味着每个产品公告都带来架构创新；参数、数据量或榜单变化只有在能解释机制时才作为证据。

### 1.2 论文与机制时间线

本时间线按研究问题和可读技术材料组织，不追踪每个型号的上架状态、托管接口或榜单名次。

| 时期 | 代表工作 | 研究问题与机制变化 |
|---|---|---|
| 2023 | Qwen、Qwen-VL、Qwen-Audio | 建立文本基座，并分别探索视觉接入和多任务音频理解；多模态模型是并行分支，不等同于统一的文本基座扩展。 |
| 2024 | Qwen2、Qwen2.5、Qwen2-VL、Qwen2-Audio | GQA 与长上下文扩展改变文本模型的 KV 开销；视觉线发展动态分辨率和 M-RoPE；音频线从任务标签走向自然语言指令。 |
| 2025 | Qwen3、QwQ、Qwen2.5-Omni、Qwen3-VL、Qwen3-Next | 可验证奖励和 Thinking 模式进入后训练；Thinker-Talker 把多模态理解与语音生成分工；视频位置编码与混合注意力分别处理时序和长序列计算。 |
| 2026 | Qwen3.5 与 Qwen3.5-Omni 技术材料、Qwen-Image-2.0 | 混合注意力、稀疏专家、多模态流式生成和扩散式图像生成形成不同研究分支。相关模型结果应回到各自技术报告的实验条件，不拼成跨任务总榜。 |

对于只有产品公告、没有公开技术报告或论文的方法更新，本报告不把型号状态、厂商榜单和能力宣传插入研究时间线；图像生成机制见 [Qwen-Image-2.0](#9-qwen-image-20从语言模型家族延伸出的图像生成分支)，更广的跨方法比较见 [AIGC 图像生成综述](../../AIGC/ImageGeneration/report.md)。

### 1.3 阅读路线：三类约束，而非代际排名

| 研究线 | 核心约束 | 可对照的代表机制 |
|---|---|---|
| 计算与长上下文 | KV 缓存、激活参数和序列长度之间如何取舍？ | GQA、MoE、Gated DeltaNet 与 Gated Attention |
| 后训练与推理 | 怎样增加可验证推理，又控制错误奖励和生成成本？ | Thinking 模式、GRPO、强弱模型蒸馏 |
| 多模态表示与生成 | 如何保留分辨率、时序和跨模态对齐？ | 动态分辨率、M-RoPE/TMRoPE、Thinker-Talker、MMDiT |

这些路线在同一模型家族中交叉，但一条线的机制不能自动解释另一条线的能力变化。后续章节按约束组织证据，并在具体工作处说明它们之间的联系。

## 2. 纯文本基座：从 GQA 到混合注意力

纯文本基座是 Qwen 家族的一条重要主线，但视觉语言、语音和图像生成分支有各自的表示与训练设计，不宜都视为文本基座的简单派生。下面只沿公开资料较充分的纯文本基座路线比较代表代次；多模态和专业方向见后续章节。

### 2.1 代表基座的架构取舍

| 代表工作 | 注意力与专家结构 | 训练/推理侧关注点 | 读者要比较什么 |
|---|---|---|---|
| Qwen（2023） | 稠密 Transformer、MHA | 中英基座与词表设计 | 词表和数据组成如何影响多语言 token 效率？ |
| Qwen2（2024） | GQA；部分型号使用 MoE | 长上下文扩展与 KV 缓存 | KV 头数减少带来的缓存节省，是否伴随质量变化？ |
| Qwen2.5（2024） | 延续 Qwen2 主干 | 更大预训练与分阶段后训练 | 数据、模型规模与后训练同时变化时，哪些实验能隔离收益来源？ |
| Qwen3（2025） | QK-Norm；稀疏 MoE 变体 | Thinking/Non-Thinking、GRPO 与蒸馏 | 可验证奖励怎样改变推理轨迹？训练阶段各自承担什么作用？ |
| Qwen3-Next（2025） | Gated DeltaNet 与 Gated Attention 混合，结合稀疏 MoE | 长序列效率与多 token 预测 | 混合注意力如何分配局部记忆与全局交互？稀疏度如何影响表达和训练稳定性？ |
| Qwen3.5（2026） | 官方材料描述混合注意力与稀疏专家 | 多模态与更长上下文 | 这类结构如何在具体任务中复用？需要区分官方描述与论文实验。 |

表格只抽取有助于比较的机制，不是全部型号配置。上下文长度、参数量和基准分数因型号与测试协议而异，不能据此排成能力递增的单轴曲线。Qwen3.5 后续产品型号和服务形态不作为纯文本架构演进证据。

### 2.2 各代关键突破（演进叙事）

#### Qwen初代（2023.08）— 奠定基础架构

模型规模覆盖1.8B/7B/14B/72B四档，均使用 Decoder-only Transformer。论文描述的代表组件包括 MHA、RoPE、SwiGLU 和 Pre-RMSNorm；词表与 QKV Bias 在后续架构中仍可追踪，但不假设所有产品分支共用同一实现：

- **151,936词表BBPE分词器**：较大的子词词表改变中英文文本的切分粒度；词表大小本身不能单独解释多语言能力。
- **QKV Bias**：在Q/K/V投影中均引入bias项，作为系列架构标志延续四代直至Qwen3移除
- **上下文扩展三件套**：NTK-aware interpolation + LogN-Scaling + Window Attention，将基础8K扩展至32K（仅72B原生32K，其余通过推理扩展）

后训练采用SFT + RLHF（PPO）的标准范式。

#### Qwen1.5（2024.02）— MoE 与偏好优化的早期试验

Qwen1.5 主要通过官方发布材料记录，没有独立技术报告。阅读时可关注它如何尝试稀疏专家和偏好优化，不把运行框架兼容性当成模型机制：

- **首个MoE模型** Qwen1.5-MoE-A2.7B：14.3B总参/2.7B激活，引入**细粒度专家 + 共享专家**机制
- **偏好优化**：官方材料描述 SFT 与 DPO/PPO 的组合；不外推为后续所有版本都相同的训练配方。
- **110B 首试 GQA**：为 Qwen2 的 GQA 设计提供系列内的早期比较点。

#### Qwen2（2024.06）— GQA 与长上下文扩展

技术报告 [arXiv:2407.10671](https://arxiv.org/abs/2407.10671) 展示了 Qwen2 的注意力与上下文扩展设计。以下数字为论文报告的配置或结果，重点在于看设计选择：

- **GQA全面应用**：所有规模统一切换至GQA。例如Qwen2-7B采用Q头28/KV头4，Qwen2-72B采用Q头64/KV头8，KV Cache内存降低为1/4–1/8
- **RoPE基频提升**：从10,000→1,000,000，配合**DCA（Dual Chunk Attention）+ YARN**支持128K推理上下文
- **训练数据扩展**：报告区分不同尺寸使用的数据配置，并描述多语言覆盖扩展；不将总 token 数单独归因于能力变化
- **MoE成熟化**：Qwen2-57B-A14B采用64路由专家 + 8共享专家 + 8激活专家
- **Online DPO + Online Merging Optimizer**：作者在其训练设置中比较在线与离线偏好优化；收益限于论文所用对照与评测。

#### Qwen2.5（2024.09）— 数据与后训练扩展

技术报告 [arXiv:2412.15115](https://arxiv.org/abs/2412.15115) 描述其在 Qwen2 架构上扩大训练数据与后训练范围：

- **数据组成扩展**：增加常识、专家知识与推理相关数据；总量变化与数据筛选、后训练同时发生
- **长上下文支持**：报告区分不同模型尺寸与扩展配置；不要把托管产品上下文窗口等同于所有开放模型的原生上下文
- **监督微调与多阶段强化学习**：长文本生成、结构化分析和指令遵循分阶段优化；报告中的阶段收益要结合对应目标与评测阅读。
- **作为专业模型基座**：直接派生Qwen2.5-Coder/Math、QwQ等专业方向

#### Qwen3（2025.04）— Thinking 模式与可验证奖励

技术报告 [arXiv:2505.09388](https://arxiv.org/abs/2505.09388) 将 Thinking 模式、强化学习和蒸馏组织进同一训练路线。论文在 AIME'24 设置中报告 Qwen3-235B-A22B 经 170 步 RL 后分数由 70.1 升至 85.1；这是该论文模型与训练设置下的结果，不直接说明所有推理任务或后续版本都会获得相同收益。

- **Thinking/Non-Thinking双模式统一**：单一模型通过`/think`和`/no_think`切换深度推理与快速响应，支持精细的Thinking Budget预算控制
- **QK-Norm替代QKV Bias**：移除延续四代的Bias设计，以归一化方案提升大规模训练稳定性
- **GRPO强化学习**：基于 rule-based verifier 的 Group Relative Policy Optimization；论文配置与 AIME'24 结果见本节开头
- **数据与合成样本**：使用 Qwen2.5-VL 从 PDF 提取文本，并用 Math/Coder 模型生成合成数据；语料扩展与后训练共同变化
- **MoE架构简化**：移除共享专家，128路由专家/8激活 + Global-batch load balancing loss
- **后训练四阶段流水线**：Long-CoT Cold Start → Reasoning RL（GRPO）→ Thinking Mode Fusion → General RL
- **Strong-to-Weak蒸馏**：仅需四阶段方法1/10的GPU时间训练小模型，同时提升Pass@1与Pass@64

预训练分通用、推理和长上下文阶段。此处更值得关注阶段目标如何变化，而非仅比较各阶段 token 数。

#### Qwen3-Next-80B-A3B（2025.09）— 混合注意力与稀疏 MoE

Qwen3-Next 的[技术介绍](https://qwen.ai/blog?id=qwen3-next)提供了长序列与稀疏 MoE 结合的案例；它本身不能证明后续所有产品继承了相同结构：

- **Hybrid Attention**：用 **Gated DeltaNet（线性注意力变体）+ Gated Attention** 替代标准全注意力。Gated DeltaNet在长序列推理下开销大幅低于Full Attention，与Gated Attention混合后兼顾表达能力与效率
- **Native MTP（Multi-Token Prediction）**：在原生预训练中内置多token预测目标
- **更高稀疏度 MoE**：80B 总参数、3B 激活是该型号的配置；与 Qwen3 不同型号对照时，激活比例只是配置，不能代替质量或吞吐比较，也不据此推断同系列其它模型的路由设计。

Qwen3-Next 提供了 Gated DeltaNet 与 Gated Attention 混合的可读案例。后续型号是否复用这些模块、以及复用后对上下文或吞吐的贡献，需要分别看其技术材料，不能从型号先后关系推出。

#### Qwen3.5（2026）— 混合注意力与多模态扩展

Qwen3.5 的[官方技术介绍](https://qwen.ai/blog?id=qwen3.5)描述了混合注意力与稀疏专家设计。这里保留与机制理解有关的配置；产品矩阵、榜单名次和相对吞吐宣传不作为跨代结论：

- **397B总参/17B激活**：256路由专家 + 8激活 + **重新引入1个共享专家**（Qwen3移除后再次回归）
- **262K原生上下文**：相比Qwen3的128K再翻一倍
- **门控 Delta 网络与 Gated Attention**：前者提供线性递归式状态更新，后者保留全注意力交互；混合比例与具体模型的上下文条件决定实际取舍。
- **稀疏专家配置**：官方材料描述了不同总参数/激活参数的型号；总参数不能代替每 token 计算量或推理成本。
- **跨模态路线**：Qwen3.5-VL 与 Omni 分别处理视觉语言输入和流式多模态输入输出，不能仅因共享型号前缀而推断二者完全同构。

#### 后续产品线：从基座模型转向任务执行

Qwen3.6 与 Qwen3.7 的[官方产品说明一](https://qwen.ai/blog?id=qwen3.6)、[二](https://qwen.ai/blog?id=qwen3.7)强调代码、工具使用和长程任务。这些描述帮助定位产品所面向的工作流，但仅凭产品页或榜单无法判断模型是否沿用 Qwen3-Next 的混合注意力、采用何种策略后训练，或哪些组件导致了任务结果。本报告因此不把产品型号顺序写成连续技术升级；理解执行闭环可对照 [智能体系统综述](../../Agents/AgentSystems/report.md) 和 [电脑使用 Agent](../../Agents/ComputerUse/report.md)，语言模型侧的可读机制以 Qwen3 与 Qwen3-Next 技术材料为锚点。

### 2.3 训练数据和后训练的关系

Qwen2、Qwen2.5 与 Qwen3 的技术报告分别描述了更大规模的预训练、专业数据/合成数据使用，以及从偏好优化到可验证奖励的变化。它们往往同时调整语料、训练阶段和模型配置；仅比较 token 总数或 SFT 样本数，无法判断能力变化由哪一项造成。具体方法以各代报告为准，数字只在解释实验条件时引用。

### 2.4 MoE架构演进（一条独立的演进线）

MoE提供模型容量与每 token 激活计算之间的一种取舍：

| 代次 | 模型 | 总/激活 | 路由专家 | 激活 | 共享专家 | 均衡策略 |
|------|------|---------|---------|------|---------|----------|
| Qwen1.5 | MoE-A2.7B | 14.3B/2.7B | — | — | 有 | — |
| Qwen2 | 57B-A14B | 57B/14B | 64 | 8 | **8个共享** | 辅助loss |
| Qwen3 | 30B-A3B | 30B/3B | **128** | 8 | **移除** | Global-batch balance |
| Qwen3 | 235B-A22B | 235B/22B | **128** | 8 | **移除** | Global-batch balance |
| Qwen3-Next | 80B-A3B | 80B/3B | 高稀疏度 | — | (新设计) | — |
| Qwen3.5 | 397B-A17B | 397B/17B | **256** | 8 | **回归1个** | — |

表中列的是公开材料能具体描述的代表型号，不足以推出“专家数必然增加”或某种均衡策略成为全系列标准。比较稀疏模型时，总参数、激活参数、专家路由和负载均衡都要分开看。

## 3. 视觉语言模型演进（Qwen-VL → Qwen3-VL）

公开论文呈现的视觉语言路线，主要变化在视觉分辨率如何转成 token、视频时间怎样进入位置编码，以及视觉 token 如何与文本交错。后续产品公告提到屏幕和 Agent 用例，但不足以补成已公开的架构演进阶段。

### 3.1 跨代关键对比表

| 维度 | Qwen-VL (2023) | Qwen2-VL (2024) | Qwen2.5-VL (2025) | Qwen3-VL (2025) |
|------|----------------|-----------------|------------------|------------------|
| 视觉编码 | OpenCLIP ViT-bigG | 自定义 ViT | 论文描述的视觉编码器与混合注意力 | 视觉编码器与文本模型联合处理 |
| 分辨率与 token | 固定尺寸、压缩为查询 token | 动态分辨率，token 数随图像尺寸变化 | 动态图像与视频采样 | 长序列中的图文交错 |
| 位置与时间 | LLM 侧标准位置编码 | M-RoPE 统一时空位置 | 视频时间与帧率进入位置表示 | Interleaved-MRoPE 组织长序列 |
| 读者应追问 | 固定视觉 token 的信息瓶颈是什么？ | 分辨率变化如何改变计算预算？ | 时间戳和帧采样怎样影响事件定位？ | 交错序列如何在长上下文中保留模态边界？ |

### 3.2 这几篇论文呈现的设计变化

1. 固定图像尺寸转向动态分辨率，使模型能按图像内容分配视觉 token；代价是输入大小与计算预算相互耦合。
2. 视频建模需要把时间位置与帧采样纳入表示；M-RoPE 与 Interleaved-MRoPE 分别处理模态坐标和长序列交错问题，不是一个位置编码方案的简单升级排名。
3. 视觉编码器和语言模型的融合方式随论文变化，但现有材料不能概括为单向“从借用到自研”或证明后续每个产品复用了同一结构。

### 3.3 关键机制：分辨率和位置编码

#### Qwen2-VL：Naive Dynamic Resolution

传统VLM要么将图像缩放至固定分辨率（信息损失），要么切割为固定子图（伪影）。Qwen2-VL方案极为简洁：

- **移除ViT中的绝对位置嵌入**，改用2D-RoPE使ViT具备处理任意尺寸输入的能力
- 视觉token数与图像尺寸严格成正比：`(H/14)×(W/14)`
- MLP层将相邻2×2 token合并，最终token数为`(H/28)×(W/28)`
- 保留原始纵横比，无需padding或裁剪

#### Qwen2-VL：M-RoPE — 多模态位置编码

将RoPE的频率维度均分为三个独立子空间：

| 模态 | Temporal ID | Height ID | Width ID |
|------|------------|-----------|----------|
| 文本 | position | position | position |
| 图像 | 常量 | 行位置 | 列位置 |
| 视频 | 帧索引→绝对时间 | 帧内行位置 | 帧内列位置 |

#### Qwen2.5-VL进化：Window Attention + 绝对时间编码

- **Window Attention混合设计**：ViT大部分层使用窗口≤8×8的Window Attention，仅4层使用Full Attention，复杂度从O(n²)降至接近O(n)
- **绝对时间编码**：M-RoPE的temporal ID与真实秒数对齐（不再用帧索引），配合动态FPS训练，支持秒级事件定位（`mm:ss.ff`格式）
- **绝对坐标**：Bbox使用图像原始像素坐标（非归一化）
- **ViT架构与LLM统一**：LayerNorm→RMSNorm，GELU→SwiGLU
- 后训练新增**DPO阶段**

#### Qwen3-VL：图文交错长序列

技术报告 [arXiv:2511.21631](https://arxiv.org/abs/2511.21631) 将 Interleaved-MRoPE 用于文本与视觉 token 交错输入，并讨论长多模态上下文与视觉推理。理解这一设计时，重点是不同模态的空间/时间位置如何映射到同一序列，以及序列变长后计算和信息保留如何权衡；榜单名次不能替代这些机制问题。

产品公告后来将视觉理解扩展到屏幕、网页和工具操作等 Agent 用例；这些用例说明任务范围在扩大，但并不构成新的视觉编码器或控制机制证据。电脑界面操作的任务与方法见 [电脑使用 Agent](../../Agents/ComputerUse/report.md)，系统层的执行闭环见[智能体系统综述](../../Agents/AgentSystems/report.md)。

### 3.4 VL方向的机制综合

就以上论文而言，视觉语言路线逐步把空间和时间信息更直接地保留在模型输入中：
- Qwen-VL：使用固定数量的视觉查询 token 压缩图像特征，再交给语言模型处理。
- Qwen2-VL：按图像尺寸动态决定视觉 token 数，并将空间坐标纳入 M-RoPE。
- Qwen2.5-VL：把窗口注意力、视频时间位置与动态帧采样结合起来。
- Qwen3-VL：研究长序列中的图文交错和 Interleaved-MRoPE。
- 后续产品的 Agent 用例将视觉观测接入动作执行；其内部机制仍需专门技术材料说明

## 4. 多模态与 Omni：输入融合、任务提示与流式输出

Omni 研究面对的不只是“支持更多模态”，还要决定：音视频怎样压缩成可供语言模型处理的序列；任务由显式标签还是自然语言提示指定；输入如何流式到达；生成语音怎样与文本响应对齐。Qwen 的论文显示这些选择逐步出现，但不能把它们概括成所有型号共享的一条架构升级链。

### 4.1 代表工作按机制比较

| 工作 | 输入/任务组织 | 关键设计 | 适合比较的问题 |
|---|---|---|---|
| Qwen-Audio | 分层任务标签组织多种音频任务 | 音频编码器向 Qwen 语言模型提供前缀特征 | 标签层次如何减少任务混淆？冻结哪一侧如何影响跨任务迁移？ |
| Qwen2-Audio | 用自然语言指令指定音频理解任务 | Whisper 特征接入语言模型；训练加入偏好优化 | 自然语言任务描述是否更利于组合式指令，而不同评测能支持到何种程度？ |
| Qwen2.5-Omni | 文本、图像、音频与视频进入统一多模态流程 | Thinker 形成语义表示，Talker 基于表示生成语音；TMRoPE 组织模态时间位置 | 把理解和语音生成分工后，如何保持内容与声音的同步？ |
| Qwen3.5-Omni | 技术报告研究音视频输入及可控输出 | 具体设计和评测条件以技术报告为准 | 长音视频、流式响应和生成控制分别由什么机制支持？ |

论文结果按各自设置阅读，不用表中的跨任务概括作为统一能力排名。

在 LibriSpeech test-clean 设置中，Qwen2-Audio 论文报告 1.6% WER，Qwen-Audio 报告 2.0%。这是两篇论文各自报告的结果；由于编码器、任务提示与后训练等设计同时变化，不能把差异单独归因于自然语言提示。[Qwen-Audio](https://arxiv.org/abs/2311.07919)；[Qwen2-Audio](https://arxiv.org/abs/2407.10759)。

两者的输入组织差异值得单独看：Qwen-Audio 用任务类型、语言和时间戳等显式标签说明输出要求；Qwen2-Audio 改用自然语言提示来选择转写、感知或对话任务。前者把任务边界写进格式，后者让任务描述更可组合，但自然语言提示并不自动保证更强泛化；论文中编码器、数据和偏好训练也一同变化。

### 4.2 Thinker-Talker：为什么把理解与发声分开

Qwen2.5-Omni 技术报告提出 Thinker-Talker 架构：Thinker 接收多模态输入并形成语义表示，Talker 根据该表示生成语音。这个分工把“回答什么”和“如何发声”拆成有接口的两步，便于让语音生成跟随文本/语义响应，同时也引入接口对齐问题：Talker 是否保留了 Thinker 的语义、语气和时间信息？

TMRoPE 为文本、图像、音频和视频的时间/空间位置提供统一的位置表示；分块处理则让音视频输入可逐段进入模型，Talker 逐步输出语音。作者报告了在其任务和评测协议下的多模态理解与生成结果；这些是论文结果，不等于独立复现，也不能直接与使用不同输入条件、解码方式或基准的模型横比。来源：[Qwen2.5-Omni 技术报告](https://arxiv.org/abs/2503.20215)，架构、位置编码与流式推理章节。

分块输入和分步输出把两个实时问题分开：编码器怎样在新音视频片段到来时继续更新状态；Talker 怎样以较短语音块输出而不丢失 Thinker 提供的语义。模型报告的实时能力属于整套架构与解码流程，不能仅归因于 TMRoPE 或某个单独模块。

### 4.3 后训练问题：文本推理会不会损伤感知？

一项后续研究在固定的 Qwen2.5-Omni-7B 上比较文本优先和音视频后训练。作者报告，文本 SFT→GRPO 将九项音视频推理分数的宏平均从 39.80 提至 49.39；纯文本训练同时使七项感知指标宏平均从 77.37 降至 76.41。随后加入音视频 GRPO 做感知修复，作者报告保留了纯文本路线 93.5% 的推理几何均值增益。这里有学习价值的结论不是某个总分，而是两种目标可能竞争：提高语言化推理不保证提升感知，后训练分阶段设计需要同时观察两侧能力。条件限于作者在固定 Qwen2.5-Omni-7B 和指定任务上的实验，详见[论文精读](papers/2610.02819-text-centric-omni.md)。

### 4.4 研究边界与推荐阅读

阅读顺序建议为：先看 Qwen-Audio 的标签式多任务学习，再看 Qwen2-Audio 的自然语言任务提示；随后读 Qwen2.5-Omni，理解 Thinker-Talker、TMRoPE 与分块输入；最后对照 Qwen3.5-Omni 技术报告，分别追问长上下文和可控输出的实验条件。实时翻译等服务型产品展示的是具体工作流，不足以证明其延迟、声音保持或翻译质量来自某一个模型机制。

这一方向仍需把三件事分开测量：输入感知、跨模态推理、同步生成。聚合总分可能掩盖某个模态的退化；比较报告时应先确认任务协议和输入输出条件，再判断方法是否真的改善了目标能力。

## 6. 跨论文综合：四种约束，不能合成一条“变强曲线”

前文的纯文本、视觉语言、Omni 和专业模型研究分别处理不同瓶颈。把它们并列成型号越来越强的产品序列，会丢掉真正有助于学习的设计取舍。

### 6.1 推理计算：缓存、激活稀疏度与序列状态

GQA 减少每个查询头共享 KV 的数量，直接影响 KV 缓存；MoE 将模型容量与每 token 激活计算分开；Gated DeltaNet 等递归式状态更新探索降低长序列计算，而 Gated Attention 保留更直接的全局交互。三者分别改变缓存、激活容量和序列计算，并非一种注意力机制逐代替换另一种。阅读时要分别看任务质量、上下文长度、激活参数和推理预算，不能从“支持更长上下文”单独推出更强推理。

### 6.2 多模态位置：把内容、空间和时间放进同一序列

视觉语言路线中的动态分辨率让输入图像决定视觉 token 数；M-RoPE 将文本、图像和视频的空间/时间坐标映射到位置表示；TMRoPE 针对音视频时间对齐；Interleaved-MRoPE 处理图文交错序列。它们解决的问题逐步扩展，但并不是同一指标上的版本升级。关键问题是表示保留了什么信息、需要多少 token，以及长序列中模态边界和时间关系是否仍可辨认。

### 6.3 后训练：偏好信号与可验证奖励回答不同问题

DPO 使用偏好对，适合优化相对偏好；GRPO 配合可验证奖励，用于数学等结果可检查的任务。Qwen3 技术报告报告了特定 AIME'24 模型与 RL 设置下的提升（见 §2.2）；这个结果说明该训练设置在该题集上的变化，不证明规则奖励适用于所有任务，也不把 GRPO 变成 DPO 的通用替代。数学、代码和多模态推理需要各自检查奖励是否能代表目标能力，以及模型是否学会利用验证器。

### 6.4 数据规模：和数据组成、训练目标一起看

各代报告中预训练 token 数增长的同时，模型规模、语料构成、合成数据、后训练和评测条件也发生变化。现有时间线不足以将能力变化因果归结为数据量。引用数据规模时，应先说明它来自哪个模型/报告，再问是否有控制实验能区分规模、数据质量和训练方法的作用。

### 6.5 推荐阅读路径

- **理解注意力与推理成本**：Qwen2 的 GQA → Qwen3 的训练与 GRPO → Qwen3-Next 的混合注意力。
- **理解视觉和时间表示**：Qwen-VL → Qwen2-VL 的动态分辨率/M-RoPE → Qwen2.5-VL 的视频时间位置 → Qwen3-VL 的交错序列。
- **理解多模态生成**：Qwen-Audio 的任务组织 → Qwen2-Audio 的自然语言提示 → Qwen2.5-Omni 的 Thinker-Talker/TMRoPE → [Qwen3.5-Omni 技术报告](https://arxiv.org/abs/2604.15804)。
- **理解任务专用训练**：Qwen2.5-Coder/Math → QwQ → Qwen3 Thinking 与可验证奖励；跨领域 Agent 机制见[智能体系统综述](../../Agents/AgentSystems/report.md)。

这些路线复用部分基座和工具，但每条线的证据应回到各自论文的训练对象、实验条件与失败边界。


## 7. 开放问题：哪些机制能跨任务复用？

1. **长上下文究竟改善了什么？** GQA、混合注意力和扩展上下文分别影响缓存、每步计算与可读序列长度。需要把“可输入更长文本”与“能正确利用远距离信息”分开评测。
2. **多模态位置编码如何影响时间推理？** M-RoPE、TMRoPE 和 Interleaved-MRoPE 表示不同的空间/时间组织方式。比较时应控制帧采样、输入长度和问题类型，避免把分辨率或预算变化当成位置编码效果。
3. **可验证奖励何时能迁移？** 数学答案或代码测试可以提供自动反馈，但 verifier 覆盖范围有限。训练分数上升不能单独证明模型掌握了更一般的推理能力；应检查奖励漏洞和任务外迁移。
4. **专业训练和通用能力如何平衡？** 代码续训、数学合成数据、视觉编码和 Omni 语音输出改变了不同接口。跨分支比较时，要问新增模块或训练数据解决哪个约束，以及哪些通用能力被保持或牺牲。
5. **产品 Agent 行为由哪些可读机制支撑？** 任务成功可能同时依赖模型、工具接口、环境和验收脚手架。产品演示或榜单不能隔离这些因素；相关系统问题见[智能体系统综述](../../Agents/AgentSystems/report.md)与[电脑使用 Agent](../../Agents/ComputerUse/report.md)。

## 9. Qwen-Image-2.0：从语言模型家族延伸出的图像生成分支

Qwen-Image-2.0 Technical Report 为 Qwen 图像生成分支提供了可读的技术材料。它与本报告的语言模型/Agent 主线相关，但不应被当作文本基座的机制证据。固定版本为 [arXiv:2605.10730v1](https://arxiv.org/abs/2605.10730v1)（v1，2026-05-11）。技术路线是以 Qwen3-VL 编码多模态条件、16× 高压缩 VAE 表示图像 latent、MMDiT 在统一文本/图像流上做扩散生成；一个模型统一文本生图与指令式编辑。训练由预训练、持续预训练、SFT 与基于 GRPO 的 diffusion RLHF 组成，使用分辨率课程，并以审美、图文对齐、人像、指令遵循、视觉一致性等任务奖励优化。报告称支持最长 1K token 的生成指令；这是提示长度，不应与语言模型上下文窗口混为一谈。评测章节报告人工比较与图像生成/编辑基准，但页面宣称的对前代整体提升仍属于作者报告，本文不把它改写为独立复现或普遍 SOTA。

来源：Qwen 团队，[Qwen-Image-2.0 Technical Report](https://arxiv.org/abs/2605.10730v1)，v1 2026-05-11；[arXiv HTML 正文](https://arxiv.org/html/2605.10730)，§1 总览与摘要；§2 数据与训练；§3 架构（图 8、§3.1 VAE、统一文本/图像流）；§4 评测。技术主张依据固定版本正文。
