# World-in-Context：把视角、动作与相机路径放进同一个交互上下文

来源：[World-in-Context: Interactive Video World Modeling with In-Context Conditioning](https://arxiv.org/html/2610.33169v1)，固定版本 v1（2026-10-23）。重点阅读 §3–6、Table 1–2、Appendix A–B。

## 研究问题：多种控制为什么不能当作同一种条件

一个可交互视频模型既要回答“角色做什么”，也要回答“从哪里看”。第一人称（FPP）、第三人称（TPP）和自由相机（Free）下，相同的相机位移并不表示相同的角色运动；TPP 中角色动作与相机轨迹更是两个独立自由度。若把视角只写进文本，或把动作、相机分别送进不同条件分支，模型需要间接学会这些信号之间的依赖。

论文提出 World-in-Context，研究能否把 view mode、离散键盘动作和连续相机运动显式编码进同一视频生成上下文。它的目标是改进视频世界模型中的**控制接口与相互作用**，不是构造机器人动作策略，也不是证明生成画面具有真实物理动力学。

## 方法：控制信号成为视频 latent 旁边的 token

模型以 Wan2.2-TI2V-5B 为视频骨干。In-Context Conditioning（ICC）把不同控制信号投影到共享注意力空间中的 condition tokens，与带噪视频 latent 一起输入 conditional flow-matching 模型：

```text
世界描述 + view tokens + action tokens + camera tokens
                         ↓
        shared self-attention / flow-matching DiT
                         ↓
                未来视频 latent → 帧
```

具体地，view token 区分 Free、FPP、TPP；action token 把键盘动作拆成移动、转向及连续位移/旋转量；camera token 编码相对 6-DoF 位姿和 Plücker ray。这样做的要点是让模型在共同注意力空间内观察条件组合，而不是假定动作和相机只是可以互换的两种输入。论文的分析显示，动作更直接约束局部命令响应，相机轨迹更像全局位移锚点；这个分工来自其 WBench 控制对照，不应外推到任意动作空间。[§4.1–4.3、Figure 5](https://arxiv.org/html/2610.33169v1#S4)

共享注意力仍不足以显式表示“两个远距离帧之间发生了哪些控制变化”。Interaction-Transport RoPE（IT-RoPE）沿时间顺序累计动作与相机的变换，把区间控制路径加入 temporal attention。因为变换按顺序相乘，先左转再前进与先前进再左转不会被仅有的端点姿态视为等价；view-gated centered attention 则按当前视角筛选控制项的作用。[§4.4、Figure 4](https://arxiv.org/html/2610.33169v1#S4.SS4)

## 两种生成模式：双向交互片段与因果 rollout

基础 World-in-Context 采用双向视频生成设置，适合在整段生成中组合多种控制。作者另外构造 WiC-Causal：自回归预测未来 frame latent，把 view、action、camera 条件与 sink tokens（保留初始场景语义）及 recent tokens（近期视觉上下文）一同输入。它不是简单把基础 DiT 调用改成在线模式，而是增加 causal training 和历史 latent 上下文。[§4.5、§6.1、Appendix A.2](https://arxiv.org/html/2610.33169v1#S4.SS5)

这一区分关系到使用方式：**整段条件生成可响应一串已知控制，但不自动证明每个新画面都回流为下一次决策的真实观测；因果 rollout 才明确把最近生成历史作为后续条件。** 即使采用 causal 模式，也仍需进一步测试状态漂移、动作干预可信度和下游策略收益。

## 论文结果说明什么

作者在 WBench 的 navigation 与 FPP↔TPP perspective-switching split 上评估。WBench 收录 289 个案例、1,058 次交互回合；其导航分数拆为画质、场景遵循、交互响应、一致性和物理常识等维度，另以二元成功率评价视角切换。[§5.1、Appendix B.1](https://arxiv.org/html/2610.33169v1#S5.SS1)

在论文所用 WBench 设置中，5B World-in-Context 报告 navigation average 81.5，与 22B EchoWM 的 81.6 接近；FPP↔TPP 切换成功率为 93.8%，对照的最佳 5B baseline 为 18.8%。其 100K navigation clips 加 500 条 view-switching sequences 的数据规模，以及同数据量下与 additive/AdaLN 等控制注入方式的对照，支持“显式视角与统一条件接口在该基准上改善组合控制”的较窄结论；它不证明控制接口解决了现实机器人任务。[§5.2–5.5、Table 1、Appendix A.1](https://arxiv.org/html/2610.33169v1#S5)

WiC-Causal 在同一基准报告 navigation average 81.2、视角切换 90.6%，与基础双向模型 81.5 和 93.8% 相近。这说明论文提出的 causal adaptation 在这些测试项上保留了大部分基准表现；不能据此推出它已支持开放时长 rollout，或在未见物理环境中可靠运行。[§6.1、Table 2](https://arxiv.org/html/2610.33169v1#S6)

## 设计取舍与边界

- **显式控制接口**减少 view/action/camera 语义混淆，但需要对这些输入做结构化标注，数据分布和动作词表限制可迁移范围。
- **共享 attention**让信号可共同建模；它并不保证模型对任意新动作组合都有因果理解。
- **IT-RoPE**将已输入的控制顺序引入注意力，但机制设计本身不能保证长时程世界状态正确。
- **WBench 是交互视频基准**，包含导航和视角切换，不是实机机器人任务；“Physics”维度也不等于控制器经过物理安全或真实接触验证。
- 论文还展示游戏控制以及合成起始图像上的迁移，但没有提供真实机器人闭环结果。对人机创作或游戏交互的证据，不应写成具身策略的实机证据。

与纯视频生成相比，本文新增的是多轮动作/视角控制接口；与 VLA 相比，它输出未来观察而不是可执行机器人动作。它是一种交互式视觉环境模型实例，不是通用智能体或经过真机验证的机器人模拟器。
