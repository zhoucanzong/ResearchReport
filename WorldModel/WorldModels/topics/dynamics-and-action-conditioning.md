# 横切专题：环境动力学与动作条件化

> **定位**：把「世界模型的动力学到底学在哪、动作怎么进去」做成一张可判定的对照——这是本专题三条架构主线（动作条件化生成、潜空间预测模型、world foundation model 平台化）的机制分水岭。
> **主等级**：`[精读原文]`（结论均可在 `../papers/` 各篇找到正文级证据）。

---

## 0. 本章结论

1. **「动作条件化发生在哪一层」是第一条分水岭**：潜变量转移层（World Models / PlaNet / Dreamer 系）vs 像素/生成去噪层（GameNGen）vs 隐状态动力学但只出规划量（MuZero）vs 完全不条件化（V-JEPA）。`[精读原文]`
2. **「动力学该预测什么」是第二条分水岭**：重构观测（PlaNet，只作训练信号）→ 不重构只预测规划量（MuZero）→ 不重构只预测表征（V-JEPA）→ 像素即状态（GameNGen）。`[精读原文]`
3. **「治漂移/治误差」的手段因层而异**：潜空间用 latent overshooting（PlaNet）、free bits / 回报归一化（DreamerV3）、温度 τ（World Models）；像素扩散用**噪声增强**（GameNGen）。`[精读原文]`
4. **判据 (a)(b)(c) 管「算不算世界模型」，不管「怎么实现」**：同一判据下可有完全不同的机制——这正是「世界模型」一词歧义的根源。`[精读原文]`
5. **动作条件化的根本约束是"动作标签从哪来"**：原生环境给动作（World Models/PlaNet/Dreamer/MuZero/GameNGen 的游戏动作），多源数据只能给"伪动作"（UniSim 的文本/机器人动作混合），**无动作也能学表征但不能规划**（V-JEPA）。`[精读原文]`

## 2. 动作条件化的四种形式（写成式子看差别）

| 形式 | 概率对象 | 代表 | 动作进入的位置 |
| :-- | :-- | :-- | :-- |
| **潜变量转移** | `p(s_{t+1} \| s_t, a_t)` | World Models（MDN-RNN）、PlaNet / Dreamer（RSSM） | 转移函数的输入：RSSM 确定性路径 `f(h_{t-1}, s_{t-1}, a_{t-1})` |
| **像素去噪** | `p(x_{t+1} \| x_t, a_t)`（近似） | GameNGen | 动作流作为**条件**注入扩散去噪过程，逐帧生成像素 |
| **价值等价隐动力学** | `p(r_t, π_t, v_t \| h_t, a_t)` | MuZero | 动作进搜索树，模型只预测三个规划量，`h_t` 不对应任何观测 |
| **无条件预测** | `p(z_{t+1} \| z_t)` | V-JEPA | **没有动作这一项**——表征学习的目标与"如果我做 a 会怎样"无关 |

**这张表是选文的判据来源**：只有前三种满足判据 (b)「动力学被条件化」；(a)「可渲染/可交互环境动力学」只有 World Models/PlaNet/Dreamer/GameNGen/UniSim 满足；MuZero、V-JEPA 因此被收进来当**边界样本**而不是主线样本。

## 3. 两个端点：像素级 vs 潜变量级

**像素级动作条件化**（GameNGen）：动作流注入扩散去噪过程，逐帧生成像素。
- 优点：**可读、可交互**（人能玩）——单 TPU **20 FPS** 实时、下一帧预测 **PSNR 29.4** / LPIPS 0.249（多分钟连续游玩稳定）。
- 代价：误差以像素级累积（靠**噪声增强**压制）、依赖真实环境先采数据（需一个会玩 DOOM 的 agent）、单域。

**潜变量级动作条件化**（PlaNet / Dreamer）：
- PlaNet：动作进 RSSM 的确定性路径，**在线 CEM + MPC 规划**；比 model-free **少约 200× 环境交互**。
- Dreamer：同一 RSSM 上接 actor-critic，**在想象轨迹里用解析梯度**学策略——**5×10⁶ 环境步平均 823**，超过 D4PG 在 **10⁸ 步**的 786（1/20 交互量）。
- 优点：**紧凑、规划/训练快**；代价：rollout 不可读、表征瓶颈（DreamerV3 用 symlog/free bits 才跨域稳住）。

**判据归属**：两者都满足 (a)(b)(c) → 都入本专题；但**失效模式不同**（像素级怕自回归漂移、潜变量级怕表征瓶颈与想象误差），**评测也不能混用**（见 [incomparability-checklist.md](incomparability-checklist.md)）。

## 4. 「预测什么」的光谱

```
重构观测 ←————————————————————→ 不重构
PlaNet            V-JEPA          MuZero          GameNGen
(重构作训练信号)   (预测表征)     (预测规划量)      (像素即状态)
```

- **PlaNet**：重构观测，但观测模型**只作训练信号**、不用于规划——「重构是脚手架」；观测重建占用容量在无关细节上（MuZero 抓住这点做了激进简化）。
- **V-JEPA**：预测表征空间中被遮挡区域——**连重构都不做**；同一冻结主干在运动类（SSv2 **72.2**）与外观类（K400 **81.9**、IN1K **77.9**）上同时可用。
- **MuZero**：完全不重构，只预测规划直接需要的三个量；**隐状态不对应观测**，因此「没法从模型里看出未来长什么样」。
- **GameNGen**：像素即状态——模型本身就是"下一代画面"。

**这条光谱的结论**：预测目标越偏离观测，越不像「可交互环境」，越像「规划引擎」。**术语歧义就出在这里**：MuZero 自称 learned model，但语义上更像"价值等价的隐动力学"。

## 5. 动作从哪来：三条数据路线与它们的代价

| 路线 | 动作来源 | 代表 | 代价 / 限制 |
| :-- | :-- | :-- | :-- |
| **原生环境交互** | 环境自身的动作空间 | World Models（CarRacing 1 万条随机 rollout）、PlaNet/Dreamer（DM Control）、MuZero（Atari 棋盘） | 需要大量交互/算力（MuZero 训练成本极高）；环境规模有限 |
| **游戏 agent 采数据** | 先训一个会玩的 agent，再用它的轨迹 | GameNGen（第一阶段需 RL agent 在真环境跑） | **没有脱离真实环境**；单域（只演示 DOOM） |
| **多源数据编排（伪动作）** | 把文本/机器人指令/其它动作当"动作" | UniSim（文本-图像、视频字幕、人类活动、机器人、仿真渲染） | 不同社区为不同目的采集 → **信息鸿沟是物理上限**；域标识符提升域内质量但**伤泛化**；静态图文只能当"单帧 + 字幕动作" |

**副产品**：UniSim 的历史帧消融（Ego4D 验证集）显示 **4 帧 > 1 帧**，但**指数间隔拉太远的 4 帧反而更差**，且**超过 4 帧无进一步提升**——说明"动作条件化"依赖的是**近邻时序**，不是越长越好。

## 6. 治漂移 / 治误差工具箱（按层归位）

| 失效 | 机制 | 代表 | 层 |
| :-- | :-- | :-- | :-- |
| 模型被策略"钻空子"（梦高分、真失效） | 温度 τ（把模型做成随机的） | World Models | 潜变量 |
| 长程预测误差累积 | latent overshooting | PlaNet | 潜变量 |
| 动力学退化解 | free bits（保证每维 KL 下界） | DreamerV3 | 潜变量 |
| 跨域数值不稳 | 回报归一化 / twohot / symlog | DreamerV3 | 潜变量 |
| 自回归漂移发散 | 噪声增强 | GameNGen | 像素 |
| 规划太慢（每步一次 CEM） | 改为想象里学策略 | Dreamer（相对 PlaNet） | 潜变量 |

**对照阅读**：同一失效在两层里由完全不同的机制处理——这也是"评测必须分层"的机制性理由，详见 [incomparability-checklist.md](incomparability-checklist.md)。

## 7. 走一遍判据：(a)(b)(c) 的判定过程

| 系统 | (a) 可渲染/可交互环境动力学 | (b) 动力学被动作条件化 | (c) 用于决策/训练 | 判定 |
| :-- | :-- | :-- | :-- | :-- |
| World Models / PlaNet / Dreamer / DreamerV3 | ✅（潜空间动力学，可 rollout） | ✅ | ✅ 想象里训策略 | **入主线** |
| GameNGen | ✅（像素级、实时可玩） | ✅ | ⚠️ 由外部 agent 用 | **入主线（当训练环境）** |
| UniSim | ✅（动作进-视频出） | ✅（伪动作） | ✅ 零样本训练真机策略 | **入主线（当训练环境）** |
| MuZero | ❌（隐状态不可渲染） | ✅ | ✅ 搜索规划 | **边界样本**（"世界模型"≠"规划引擎"） |
| V-JEPA | ❌（不产生可读观测） | ❌（action-free） | ⚠️ 仅表征 | **边界样本**（表征线） |
| Physics-IQ / VBench-2.0 | —（评测工具） | — | ✅ 评测 | **评测类**（(c) 的一个特殊分支） |

## 8. 对条目结论的影响

- 主报告「架构谱系」的三条主线，其实是**「动作注入层 × 预测目标 × 行为派生」三根轴的组合**——本章给出可判定的坐标系；
- **判据与机制解耦**：同一判据下可有完全不同的实现；反过来，机制相似的系统（如 MuZero vs Dreamer）可能**分属不同判据层**；
- **失效模式随层而变**，因此「评测」也必须分层——见 [incomparability-checklist.md](incomparability-checklist.md)；
- **动作标签的可得性**是这条线最现实的瓶颈：原生交互最贵、游戏采数据最省但要真环境、多源编排最泛但受信息鸿沟限制。

## 9. 失效条件（本专题自身的边界）

1. 本章的"四根轴"是对 **10 篇入选论文**的归纳，**不是公认分类法**；新增机制可能落在轴外（例如"世界模型作为 RL 训练环境"的奖励建模，本专题只覆盖其动力学部分）。
2. 表格里 `p(s_{t+1}|s_t,a_t)` 等写法是**语义示意**，用于区分"条件化发生在哪一层"，**不是各论文的目标函数原文**（各论文的确切形式见对应分册 §1）。
3. 未逐篇核验的对照系统（如部分提过的生成式世界模型）**只作提及**，不作为本专题结论的证据；引用具体数字时请回到 `../papers/` 对应分册。

## 10. 条件化与「能不能规划」的关系

把"动作条件化"与"能不能用它做决策"连起来看，逻辑链只有一条：**要规划，就必须能回答"如果我做 a 会怎样"**。

| 系统 | 能否回答"做 a 会怎样" | 因此能否规划 | 说明 |
| :-- | :-- | :-- | :-- |
| World Models / PlaNet / Dreamer 系 | ✅（潜空间转移带动作） | ✅ | 区别只在"怎么用"：进化控制器 / CEM 规划 / actor-critic |
| GameNGen | ✅（像素级动作条件） | ⚠️ 由外部 agent 用 | 模型本身不出策略，只出"下一帧" |
| UniSim | ✅（伪动作：文本/机器人指令） | ⚠️ 间接 | 高层语言动作 + 逆动力学模型还原为机器人动作 |
| MuZero | ✅（隐状态 + 动作） | ✅ | 但**不可渲染**，只能搜索不能合成 |
| V-JEPA | ❌（action-free） | ❌ | 因此单独无法用于规划/控制（其后续版本才加动作条件） |

**这张表把"术语歧义"落到可判定的问题上**：MuZero 能规划但不能合成、GameNGen 能合成但不自己规划、V-JEPA 两者都不做（只出表征）——它们都被叫做"世界模型"，但**能回答的问题根本不同**。

## 11. 条件化的实现细节（三个可核对的检查点）

1. **动作进入哪里**：是进**转移/去噪**（World Models 的 MDN-RNN 输入、RSSM 的 `f(h_{t-1}, s_{t-1}, a_{t-1})`、GameNGen 的去噪条件），还是只进**搜索树**（MuZero）；
2. **动作空间是什么**：环境原生动作（CarRacing 的连续控制、Atari 的 18 个离散动作）vs 用户输入（DOOM 的键鼠流）vs **伪动作**（UniSim 把文本指令/机器人动作当动作）；
3. **动作标注从哪来**：环境自带（World Models/PlaNet/Dreamer/MuZero/GameNGen 的游戏环境）vs 先训 agent 采（GameNGen 第一阶段）vs 数据编排拼凑（UniSim）。

**为什么这是检查点而不是学术分类**：它决定**一个系统能不能被复用**——动作空间不匹配时，模型再好也不能直接接到你的控制回路上。
