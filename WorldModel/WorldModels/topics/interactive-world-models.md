# 交互式视频世界模型：控制接口、状态记忆与可用证据

> **定位**：本专题只讨论视频生成系统如何从“一次提示生成片段”走向“多轮动作改变后续观察”，并梳理这种交互离可靠环境模型和机器人闭环控制还有多远。它是 WorldModels 的跨论文横切分析，不替代世界模型总报告、AIGC 视频生成或 VLA 专题。

## 1. 先区分三种不同的交付物

普通文本到视频常表示为：

\[
p(x_{1:T}\mid c),
\]

其中条件 \(c\) 是文本、首帧或参考素材，模型一次生成整段 \(T\) 帧视频。即使模型支持视频续写、编辑或相机路径，也要看这些信号是一次性条件还是生成过程中可反复更新。

交互式视频模型更接近：

\[
p(o_{t+1}\mid o_{1:t},a_{1:t},c_{1:t}),
\]

每一轮根据历史观察、动作和当前条件生成后续观察，再允许用户或 Agent 根据新画面继续干预。[交互式视频世界模型综述 §II-A](https://arxiv.org/html/2606.01164v1#S2.SS1) 将“多轮、细粒度控制”“跨轮状态一致”“即时反馈”列为该类系统的关键属性。

但“多轮交互”仍有三个证据层次：

| 层次 | 系统实际交付什么 | 能证明什么 | 还不能证明什么 |
| :-- | :-- | :-- | :-- |
| 一次性条件视频 | 给定文本/图像后输出视频片段 | 条件生成或编辑能力 | 在线动作会改变后续生成状态 |
| 可交互视频 rollout | 多轮接收视角、动作或相机控制并生成新观察 | 在指定任务和基准中响应这些控制 | 控制策略有效、接触动力学准确或机器人安全 |
| 可用于具身闭环的学得环境 | 动作驱动状态转移，供策略训练/规划调用 | 在给定环境、策略和评测下检验下游行为 | 自动证明跨环境 sim-to-real 或任意真实物理规律 |

本库的操作性准入条件还要求系统可调用且动力学来自数据；某些综述使用的“interactive world model”更宽，可能涵盖用户直接 steer 视频或 3D 场景。因此读者应同时辨认**论文自己的术语**和**本库的交付物判据**，不能仅靠名称分类。[WorldModels 主报告 §1](../report.md#1-定义与判据)

## 2. 控制不是一个输入：观察视角、角色动作和相机运动

在第一人称视角中，前进键与相机前移往往看起来相同；在第三人称视角中，角色移动与镜头跟拍却可能分离。把三者合并为一个“动作条件”，会让模型无法判断某个控制是在改变世界中的角色，还是只在改变观察者的位置。

World-in-Context 把三类信号显式分开：

1. **view mode**：Free、first-person（FPP）、third-person（TPP），决定相同运动输入应怎样解释；
2. **character action**：键盘离散操作和连续运动增量，改变局部角色运动；
3. **camera trajectory**：相对 6-DoF 位姿和视线几何，改变观察视点。

它的 In-Context Conditioning（ICC）将这三类条件变成序列 token，和视频 latent 一同送进共享注意力；不是给每种输入增设独立条件支路。IT-RoPE 再把动作/相机变换沿时间有序累积，使两个端点相同但中间操作顺序不同的轨迹仍可区别。[World-in-Context v1 §4.1–4.4](../papers/2610.33169-world-in-context.md)

论文报告显示，动作与相机在其 WBench 对照中作用互补：动作对局部命令响应更直接，相机对全局轨迹更稳定。这个解释只对该模型、接口和 benchmark 负责；真实机器人上，控制输入还可能是关节目标、末端位姿、力/力矩或策略 chunk，不能把键盘 token 当作机器人动作空间。

## 3. 交互接口与环境状态不是一回事

当前路线大致有三种接口，不应把它们汇成“动作控制已经解决”：

| 接口 | 典型信号 | 主要设计问题 | 代表研究位置 |
| :-- | :-- | :-- | :-- |
| 文本/区域指令 | “向左走”“把物体拖到这里” | 自然语言是否足够精确；一条指令对应多少帧/区域 | 交互式视频综述 §IV；AIGC 视频条件控制 |
| 相机轨迹/视角切换 | pose、轨迹、Free/FPP/TPP | 观察者运动与角色运动怎样解耦 | World-in-Context ICC；多视角 3D world models |
| 环境动作 | 键盘、游戏动作、机器人动作 | 动作对学得状态转移的因果作用、输入输出对齐 | GameNGen、Genie 等游戏世界；机器人/Embodied 仿真接口 |

同时还要问模型**把什么状态记住了**。像素/latent history 适合短窗口连续生成；滑窗可以控制计算，但只能直接访问有限历史。更长交互可以加入压缩 memory、显式 3D 场景或状态变量，代价是状态构建、检索和跨时间更新的误差。交互式视频综述将长历史、memory、显式 3D 重建及 forcing-based 训练分为不同方向，说明“支持多轮输入”并不等同“拥有持久、可查询的世界状态”。[综述 §V](https://arxiv.org/html/2606.01164v1#S5)

这也解释了双向视频模型与因果 rollout 的区别。World-in-Context 的默认模型以 bidirectional flow matching 处理一组视频 latent 与控制序列；它另训 WiC-Causal，把历史 latent、sink tokens 和近期 latent 作为条件，自回归生成未来帧。二者可以在相似基准上表现接近，但实际使用要求不同：前者是整段/窗口的可控生成，后者更接近可持续滚动的下一帧/未来块预测。[World-in-Context §4.5、§6.1](../papers/2610.33169-world-in-context.md)

## 4. 交互感、世界状态与物理真实性要分别验证

一个视频 rollout 可以迅速跟随按键，仍然忘记远处发生过的事；场景外观可以保持，也可能没有稳定的物体状态；物理维度得分较高，也不证明机器人可以安全操作。因此评价至少分成：

1. **控制响应**：新动作输入后是否出现预期运动；延迟多少、是否与其他条件冲突？
2. **时间/空间一致性**：人物、物体、地点、相机和未观测区域跨轮是否保持？
3. **因果/物理合理性**：接触、遮挡、物体状态改变是否跟动作一致？
4. **下游闭环有效性**：一个策略依靠模型 rollout 选择动作，真实任务成功是否改善？真实观察回馈是否再次改变后续决策？

交互式视频综述把 benchmark 分到 open-world exploration、game engine、embodied AI 和 autonomous driving，且不同基准分别覆盖 camera control、3D consistency、memory、trajectory tracking 等指标。[综述 §VII](https://arxiv.org/html/2606.01164v1#S7) 这意味着视频 FVD 或单帧质量分数不能替代动作跟随；WBench 的命令响应/视角切换，也不能直接代表具身策略或实机操控成功率。

World-in-Context 在 WBench 的 289 cases、1,058 interaction turns 上测试 navigation 和 FPP↔TPP switching；论文报告 5B 模型的 navigation average 81.5，与 22B EchoWM 的 81.6 接近，视角切换成功率为 93.8%，其 5B 对照最佳为 18.8%。在因果版本中，作者报告同一 benchmark 下 navigation 81.2、switching 90.6%。这些数字是**论文报告结果**，限定在 WBench、其 view/action/camera 接口和相应生成设置；没有真机机器人任务或接触动力学验证。[World-in-Context §5–6、Table 1–2](../papers/2610.33169-world-in-context.md)

1. 先读 [AIGC 视频生成](../../../AIGC/VideoGen/report.md) §§1–3，理解表示、时空压缩和被动视频生成；再读 [WorldModels 主报告](../report.md) §§1–3，理解学得动力学与状态转移。

## 7. 仍未解决的问题

- **可控不等于可反事实预测**：若同一状态在不同动作下总生成近似画面，模型就不能可靠比较“如果改做 B 会怎样”。需要 action-conditioned counterfactual tests，而非仅看跟随指令的演示。
- **响应和长程连贯冲突**：为立即跟随新指令而频繁改动生成，可能破坏场景连续；过强历史条件又会让当前动作反应迟钝。
- **状态可见性不足**：只从画面记忆的模型难以保证画外物体持续演化；显式 3D 或 memory store 又引入估计、更新和检索误差。
- **基准指标不能代替下游闭环**：WBench 等交互基准衡量其规定的相机/键盘控制和生成质量，具身任务仍需单独评估策略是否用模型预测提升真实任务表现。
- **从模拟交互到机器人接口**：键盘/相机控制与关节/末端动作、力觉、低层控制器之间存在动作空间和时间尺度鸿沟，迁移必须单独证明。

这条线的学习重点不是把所有视频生成器重新命名为“世界模型”，而是检查动作怎样改变未来状态、记忆如何跨轮更新、生成观察是否能支持下一步决策，以及证据最终经过了哪类闭环测试。
