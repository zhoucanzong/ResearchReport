# 横切专题：不可比性清单（评测碎片化）

> **定位**：把「为什么不同世界模型的公开数字不能直接比」做成一张**可逐条执行的清单**——这是本专题「评测与基准」的机制级补充，也是引用任何跨系统数字前的检查表。
> **证据口径**：十篇分册内的数字标 `[精读原文]`；外部/未精读来源（如 Genie 3、Self Forcing、Hunyuan-GameCraft、WorldScore）标 `[摘要级]` 或 `[二手]`。

---

## 0. 本章结论

1. **「帧率」必须绑分辨率与硬件才可比**：GameNGen 的 20 FPS（320×240、单 TPU）与 Genie 3 的 24 FPS（720p、官方博客未给硬件）**不可直接比较**。`[精读原文]` / `[摘要级]`
2. **「画质指标」与「物理理解」是两回事**：Physics-IQ 证明视觉真实感 ≠ 物理理解；PSNR/SSIM/FVD/LPIPS 都不足以判定"懂不懂物理"。`[精读原文]`
3. **多套基准口径互不重叠**：VBench-2.0（内在真实性、自动评判）、Physics-IQ（物理理解、真实拍摄）、WorldScore（controllability/quality/dynamics，`[摘要级]`）——**没有统一的"世界模型总分"**。`[精读原文]`
4. **交互性（动作条件响应、长时程一致性）无第三方基准**：上述三套基准都不测它。`[精读原文]`
5. **不可比不是"数据脏"，而是六类口径的错位**（分辨率/硬件、指标、训练-推理、数据域、评测协议、物理 vs 感知）——**每类都能用正文级证据判定**。

## 1. 引用前的检查表（六问，逐条可判定）

引用"某系统达到 X"之前，逐条问：

| # | 检查项 | 若缺失 → 后果 | 例（本专题内可核） |
| --: | :-- | :-- | :-- |
| 1 | **分辨率 + 硬件 + batch/帧率**齐否？ | 裸 FPS 无意义 | GameNGen 20 FPS 绑 320×240 + 单 TPU `[精读原文]` |
| 2 | **指标口径**是什么（感知/物理/交互）？ | 跨口径相加 = 编造 | PSNR 29.4（感知）≠ Physics-IQ 的物理理解 `[精读原文]` |
| 3 | **训练/推理是否错配**，如何补？ | 一致性时长定义不同 | GameNGen：teacher forcing 训练 + 自回归推理（噪声增强补错配）`[精读原文]` |
| 4 | **数据域**是否相同？ | 域内结论被当跨域 | UniSim 零样本真机是**域内** `[精读原文]` |
| 5 | **评测协议**（人评 / VLM / 专家 / 自动）是否一致？ | 分数不可对齐 | VBench-2.0 用 VLM/LLM + 专家 + 人类对齐 `[精读原文]` |
| 6 | 结论说的是**感知真实感**还是**物理理解**？ | 把"像"当成"懂" | Physics-IQ 的核心反证 `[精读原文]` |

**用法**：六问全齐才允许写"可比"；缺一项就写"**在 X 条件下达到 Y，暂不可与 Z 比较**"。

## 2. 不可比性的来源（逐条展开）

### 2.1 分辨率 / 硬件 / 帧率口径

| 系统 | 帧率 | 分辨率 | 硬件 | 来源 |
| :-- | :-- | :-- | :-- | :-- |
| GameNGen | **20 FPS** | 320×240 | **单 TPU** | [papers/2408.14837](../papers/2408.14837-gamengen.md) `[精读原文]` |
| Genie 3 | 24 FPS | 720p | 官方博客未给硬件 | 官方博客 `[摘要级]` |
| Self Forcing | 17.0 FPS | — | — | `[摘要级]` |
| Hunyuan-GameCraft | 6.6 FPS | — | — | `[摘要级]` |

**结论**：帧率必须绑 (分辨率, 硬件, batch) 才可比；裸 FPS 无意义。

### 2.2 评测指标口径

| 基准 | 测什么 | 方法 | 数据 |
| :-- | :-- | :-- | :-- |
| GameNGen 自评 | 画质 + 可玩性 | PSNR 29.4 / LPIPS 0.249 + 人类判别 | DOOM `[精读原文]` |
| VBench-2.0 | **内在真实性** | VLM/LLM + 专家 + 人类对齐（5 维 18 子维） | 生成视频 `[精读原文]` |
| Physics-IQ | **物理理解** | 真实拍摄 + 受控物理方差（5 类物理、66 场景） | 真实视频 `[精读原文]` |
| WorldScore | controllability / quality / dynamics | 统一 world spec | 世界生成 `[摘要级]` |

**结论**：口径互不重叠，**无法加总成统一分**；把"VBench-2.0 物理维高分"当成"懂物理"就是跨口径外推。

### 2.3 训练 / 推理错配口径

- **GameNGen**：teacher forcing 训练、auto-regressive 推理 → 用**噪声增强**补错配。`[精读原文]`
- **潜空间系（Dreamer）**：想象训练、真环境部署 → 错配体现在"想象误差 → 策略误差"。`[精读原文]`

**结论**：两类的"一致性时长"定义不同：一个是**像素级自回归一致性**，一个是**潜空间 rollout 与真环境的一致性**，不能互相换算。

### 2.4 数据域口径

- **UniSim**：零样本真机是**域内**（真机域的仿真数据来自该域）；跨域时域标识符不可用。`[精读原文]`
- **DreamerV3**：固定超参跨 150+ 任务，但**仍是同一批域内**；RSSM 表征靠重构，视觉复杂度极高场景仍受容量约束。`[精读原文]`

### 2.5 评测协议口径（自动 vs 人评）

- **Physics-IQ**：明确讨论"为什么不用 PSNR/SSIM/FVD/LPIPS"——因为这些指标与人判物理理解不同构。`[精读原文]`
- **GameNGen**：人类判别者在**短片段（3 秒）**上判定能力；报告强调自回归 5–10 分钟后仍接近随机水平——**"人评的时长窗口"本身就是口径**。`[精读原文]`
- **VBench-2.0**：两条互补路线（自动 + 与人类对齐），说明单一自动指标不足。`[精读原文]`

### 2.6 感知真实感 vs 物理理解

Physics-IQ 的锋利之处：**视觉真实感 ≠ 物理理解**，两者**可以同时存在而不相关**——所以任何"画面更真 ⇒ 更懂物理"的推论都不成立。

---

## 3. 「视觉真实感 ≠ 物理理解」的证据链（可复核）

1. **构造**：Physics-IQ 用**真实拍摄** + **受控物理方差**（只靠真懂物理才能做对），覆盖 **5 类物理、66 个场景**；`[精读原文]`
2. **被测**：**8 个**视频生成模型（含 i2v 与多帧模型）；`[精读原文]`
3. **主结论**：当前模型**物理理解严重受限，且与视觉真实感无关**；个别用例已能被解出（说明并非不可能）；`[精读原文]`
4. **可推论**：一个模型能在 VBench-2.0 的 Physics 维得高分（VLM/LLM 评判），却在 Physics-IQ 的真实拍摄上崩——**两套"物理"不是一回事**。

---

## 4. 哪些比较其实是可行的（避免过度不可比）

不可比不等于"什么都不能比"。**同一条件下**的比较是站得住的：

| 可比的情形 | 为什么可比 | 例子 |
| :-- | :-- | :-- |
| 同一论文内的**消融** | 数据、硬件、协议、评测完全一致 | Dreamer：无价值模型 / PlaNet 在线规划 / Dreamer 三者对照 `[精读原文]` |
| 同一 benchmark、同一协议下的**同批模型** | 口径统一 | Physics-IQ 对 8 个模型的同基准比较 `[精读原文]` |
| 同域同硬件的**规模律** | 只变模型大小 | DreamerV3：模型变大 → 分数更高且交互更少 `[精读原文]` |
| 同任务的**交互量**对比 | 量纲一致（环境步数） | Dreamer 5×10⁶ 步 vs D4PG 10⁸ 步 `[精读原文]` |

**判据**：**比较双方在六问上至少 5 项一致**才写"可比"；否则写"条件不同，不作直接比较"。

---

## 5. 交互性评测的空白（本专题最大缺口）

三套基准（VBench-2.0 / Physics-IQ / WorldScore）都**不测** action-conditioned 的交互响应：

- VBench-2.0 测生成质量（含 Physics 维），**不测交互**；
- Physics-IQ 测物理理解（视频续接），**不测交互**；
- WorldScore 测世界生成的可控性/质量/动态，**不测实时交互**。

**结论**：可交互世界模型的评测——**动作条件响应、长时程一致性、action-following 延迟**——**目前无第三方基准**。这也是 [world-model-as-env.md](world-model-as-env.md) §5 所说"用学到的模型当评测环境几乎空白"的同一原因：**交互是这套系统最核心的能力，却最缺度量**。

---

## 6. 可比性修复建议（供后续工作）

1. **帧率必须绑参数**：报 FPS 时报 `(分辨率, 硬件, batch)`；
2. **区分"生成质量"与"物理理解"**：物理理解单独用真实拍摄基准（Physics-IQ 一类）；
3. **交互性需要专门基准**：动作条件响应延迟、长时程一致性、action-following 准确率；
4. **跨域统一口径**：视频 / 游戏 / 机器人各自为政，需要一个跨域的"世界模型"统一评测协议；
5. **最小报告清单**：任何宣称"实时/高分/可交互"的结果，至少报 六问中的 1–4 项，否则视为**不可比较的宣传口径**。

## 7. 失效条件（本清单自身的边界）

1. 本清单的"六问"来自本专题**十篇入选论文**的评测实践归纳，**不是评测社区公认标准**；
2. 表中 `[摘要级]`/`[二手]` 的数字（Genie 3、Self Forcing、Hunyuan-GameCraft、WorldScore）**本轮未精读**，仅用于说明"口径不同"，**不得作为性能结论引用**；
3. Physics-IQ 自身有边界：只覆盖 5 类物理、66 场景，静态相机、无相机运动，且 Luma/Veo2 未纳入（政策/可得性）——**它的结论同样带条件**。`[精读原文]`

## 9. 三个常见误用（示例与正确写法）

| 误用 | 为什么错 | 正确写法示例 |
| :-- | :-- | :-- |
| "GameNGen 20 FPS，比 Hunyuan-GameCraft 的 6.6 FPS 快 3 倍，所以更强" | 分辨率与硬件不同（320×240 单 TPU vs 未标注） | "在 320×240、单 TPU 条件下 GameNGen 达 20 FPS；与其它系统的帧率**因分辨率/硬件不同不可直接比较**" |
| "VBench-2.0 物理维得分高 ⇒ 该模型懂物理" | 口径错位：VLM/LLM 评判的"物理"≠ 真实拍摄的物理理解 | "其在 VBench-2.0（自动评判口径）表现较好；**物理理解**需另用真实拍摄基准（Physics-IQ 一类）验证" |
| "UniSim 实现零样本迁移到真机" | 丢掉**域内**限定 → 升格证据 | "UniSim 在**同一真机域**（Language Table）实现零样本部署；**未证明跨域零样本**" |

**共同点**：三种误用都是**把带条件的数字当成无条件结论**——这也是本条目"证据等级"纪律要拦的东西。
