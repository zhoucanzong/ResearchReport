## 七问

### 1. 解决什么问题？

移动操作同时需要找物体、导航、协调底盘与双臂，并在部分可观测环境中执行较长的技能序列。真机遥操作数据成本高，而且常覆盖有限的视角、接近路线和环境布局；只增加同一环境的示范，未必能覆盖物体位置变化或策略动作误差产生的状态。SimVLA 研究的问题是：能否从程序生成的厨房和物理仿真中得到足够多样的训练信号，支撑在真实 pantry 和家庭环境中的移动操作（§§1–2、§3.1–3.4、§4.7）。

### 2. 核心方法是什么？

**数据管线分三类，角色不同。**

- **SimAction**：约 200K 条轨迹、2,778 小时，覆盖 100 个程序生成厨房中的 35 个移动操作任务。每条包含多视角观察、语言指令、双臂末端执行器动作和底盘速度；任务由人工定义的原子 skill API 组合，再用 cuRobo 生成无碰轨迹。包括 navigation/search、抓放、开合、倾倒等（§3.2；Appendix D，Table 4）。
- **SimVQA**：约 1M 个从模拟器真值自动生成的问答样本，训练空间关系、3D 位置、跨相机对应、可达性/可抓取性、夹爪状态和当前/下一子任务等（§3.3；Appendix F，Table 6）。它是将仿真特权状态转成 VLM 可学的视觉语言监督，而非部署时直接读取真值。
- **SimDeploy**：用策略在 RoboCasa、MolmoSpaces、SceneSmith 等仿真环境零样本 rollout 收集约 22K 条轨迹、460 小时，纳入由模型动作误差形成的偏航、错误底盘位置、漏抓和重试等状态（§3.4）。

训练为两阶段：预训练同时使用 SimAction 连续动作 flow-matching、SimAction 的 FAST 离散动作预测和 SimVQA 自回归问答；随后在 SimAction + SimDeploy 上只做连续动作 flow-matching post-training，并允许动作损失更新 VLM backbone。基座为 PaliGemma 与 `π0.5` 风格 flow action expert；动作 chunk 为 50，训练预算作者报告约 1,272 GPU-hours（§3.5；Appendix G，Tables 7–9）。

**“零样本”边界。**没有用真机任务遥操作示范来训练 SimVLA；但作者在物理真机上执行校准序列，并比较实机与仿真的末端位置、末端旋转和关节信号来辨识模拟器的物理参数。混合系统辨识在 10 条跨 3 项操作任务的留出轨迹上测得，真机末端位置平均误差从 URDF 默认的 83.4 mm 降至 13.3 mm；最大误差从 120.7 mm 降至 40.6 mm（Appendix C，Algorithm 1、Table 3）。因此准确表述是：**策略任务训练数据来自仿真，物理校准仍使用真机轨迹信号**。作者还对视觉、物理、关节、家具与物体参数做域随机化（Appendix E，Table 5）。

### 3. 数据、硬件与实验规模是什么？

- **仿真数据覆盖**：程序生成 5 类厨房布局；SimAction 为 35 项任务、约 200K 轨迹；SimVQA 约 1M 问答对；SimDeploy 约 22K rollout。SimAction 的每条观测为前视和左右腕部三路 240×320 RGB、20 fps，动作空间为 23 维（双臂末端状态与夹爪 + 底盘速度），另含本体状态和初始位姿（§3.1–3.4；Appendix D）。
- **真机平台与任务**：Anubis 双臂移动操作机器人，每臂 6 DoF、平行夹爪、三轮全向底盘；前视 RealSense D455、腕部 D405。5 项任务为 mug/bowl/bottle 放入 sink、bowl 放入 drawer、bottle 倾倒至 mug（§4.2、Appendix H，Table 10、Fig. 2）。
- **真实环境与次数**：mock kitchen 包含 ID、物体/家具重排 OOD-pos、背景/光照变化 OOD-vis；另有 pantry 和 real home。mock kitchen 每个任务-策略-条件 20 次，pantry 的 3 个任务各 20 次，real home 的 2 个任务各 10 次；作者称总计 2,120 次 rollout（§4.2；Appendix H，Tables 13–17）。
- **对照基线**：`π0.5` 在 mock kitchen 每项任务用 50 或 200 条真机示范微调。它们是基线数据，不是 SimVLA 的训练集。作者比较的主要量是阶段进展，不只报告终局成功（§4.2–4.4）。
- **仿真外部比较**：RB-Y1 上在 5 个未见 SimVLA 厨房与 5 个 MolmoSpaces 环境测 3 项 pick、2 项 pick-and-place，每项 200 trials；部分可观测设置下，MolmoB0T 为 0% 成功，SimVLA 为 51.8%（MolmoSpaces）和 81.0%（SimVLA kitchens）。此外 Anubis 上 8 项长程任务、每项 50 rollouts（§4.1、§4.8；Table 2、Appendix H Table 12）。

### 4. 主要结果是什么（带条件）？

**先分清两个指标。**`task progress` 是预定义子目标完成比例，允许“完成了前几步但没做完”得到非零分；`binary success` 只在完整任务成功时记为成功。Appendix H 为每项任务定义不同的阶段标签，例如抽屉任务区分抓物、抓把手、打开、放入和关上；Tables 13–17 同时给 progress 均值/标准差与成功次数（§4.2；Appendix H，Task Progress Description、Tables 13–17）。因此 progress 领先不能改写成 success rate 领先。

- **Mock kitchen ID**：SimVLA 五项任务平均 progress 为 54.4%，作者报告高于 `π0.5` + 50 demos；但 `π0.5` + 200 demos 的 ID progress 更高（67.8%，Table 13 各任务均领先）。SimVLA 在五项任务的 binary success 为 9/20、6/20、6/20、9/20、8/20；50-demo baseline 为 8/20、5/20、6/20、7/20、7/20；200-demo baseline 为 15/20、11/20、10/20、11/20、11/20（Appendix H，Table 13）。
- **Mock kitchen OOD**：作者报告 OOD-pos 下 SimVLA 五项 progress 均领先，binary success 最优或相当（Table 14）；OOD-vis 下 SimVLA 在任务 1、3、4、5 最好，但任务 2 由 200-demo baseline 领先（Table 15）。这比“所有环境和任务全面胜过真机数据策略”更窄。
- **真实家庭环境**：pantry 三项任务各 20 次，SimVLA 成功分别 8/20、9/20、9/20；real home 两项各 10 次，成功分别 6/10 和 3/10。`π0.5` 50-demo 基线在 pantry 与 real home 对应各项为 0 成功，200-demo 基线在 home 两项也为 0/10（Appendix H，Table 17）。样本量较小，表明作者评测场景下的迁移结果，不是一般家庭成功率估计。
- **长程仿真**：Anubis 的 8 项任务每项 50 次，成功率从 put mug and bowl to sink 的 38%（19/50）到 put mug to sink / pour bottle to mug 的 76%（各 38/50）（Appendix H，Table 12）。

### 5. 消融说明什么？

- **需要预训练**：移除预训练、只在 SimAction–SimDeploy 混合数据上训练，mock kitchen-ID 五项任务的 progress 均降低；例如任务 1 从 SimVLA 的 0.60 降到 0.28，任务 2 从 0.50 降到 0.15（Appendix H，Table 13）。
- **SimVQA 与 tokenized SimAction 互补**：ID 消融中分别移除 SimVQA 或 TokSimAction 后，五项 progress 均低于完整模型（Appendix H，Table 16；§4.5 Fig. 5）。在 1,369 条留出 SimVQA 上，完整模型中位 3D 位置误差 0.06 m、cross-view IoU 0.61；不含 TokSimAction 版本分别为 0.50 m 和 0.04。去掉 SimVQA 的模型会输出 tokenized action，使这些问答指标无法定义；不能把无定义当作普通低分（Appendix H，Table 11）。作者也观察到 SimVQA 缺失时抓取精度变差（§4.5）。
- **SimDeploy 的收益取决于任务**：去掉 SimDeploy 后，sink / drawer 放置任务在 OOD 环境和 mock kitchen-ID 普遍变差；pour bottle to mug 的收益较小，作者将其解释为倾倒更依赖物体变化、而非场景布局覆盖（§4.6，Fig. 5；Appendix H，Tables 13–15）。
- **系统辨识本身重要，混合目标增益较小**：相对 URDF 默认参数，关节空间、末端空间及 hybrid 校准都大幅降低真机-仿真末端误差；hybrid 比关节空间均值仅改善 1.4 mm，且与末端空间结果差异很小。消融支持“先校准有效”，并没有强证据显示 joint + EEF 这个混合目标显著优于单一目标（Appendix C，Table 3）。
- **域随机化因子未被逐一消融**：表中的随机化范围说明覆盖广，但没有隔离每一个因素的贡献（§6）。

### 6. 什么条件下结论受限或方法失效？

作者明确列出四类限制：未分离各域随机化因素的贡献；当前任务集中于厨房环境中的刚体物体；评测的机器人 embodiment 与 VLA 架构有限；SimAction 依赖人工设计的 skill API，任务扩展还需要人工定义技能（§6）。此外，真机结果来自单一 Anubis 平台，家庭环境只含两项任务、每项 10 次；厨房/储物区域与更开放的家居任务仍有明显范围差异（§4.2、Appendix H Table 17）。

另一个边界来自训练信号的理想化：SimAction 由规划器和人工技能组合生成，SimVQA 使用模拟器真值；其迁移依赖真实系统辨识和大范围域随机化。当前结果证明这套组合在作者测过的环境与任务上可用，尚不能拆分视觉随机化、动力学校准、SimVQA 与 SimDeploy 对迁移的独立因果贡献。SimDeploy ablation 有任务差异，且真实 rollout 次数有限（§3、§4.5–4.7、§6）。

### 7. 与同类系统的可判定差异是什么？

SimVLA 的主要差异是**仿真数据监督的种类和训练闭环**：SimAction 给动作；SimVQA 将仿真特权状态转为视觉语言推理目标；SimDeploy 将策略自身造成的状态偏移回收为 post-training 数据。它没有提出跨 embodiment 迁移方法，也没有提出新 VLA 架构，而是在 `π0.5` 风格模型上验证数据和监督组合（§2、§3.5、§6）。

对比“只用 motion planning 扩增动作轨迹”的仿真管线，SimVLA 的贡献主张是加上视觉语言监督与部署 rollouts；对比需要真机 demonstrations 微调的 `π0.5`，SimVLA 的策略训练流程不使用这些任务示范，但保留校准实机动力学所需的真机序列。对比 MolmoB0T 的模拟评测，作者报告 SimVLA 在未见厨房、MolmoSpaces 和部分可观测任务上更好（§2 Table 1；§4.8 Table 2）。这些对照支持其“多源合成监督可用于移动操作零样本 sim-to-real”结论，不足以证明它对所有架构、机器人或非厨房任务普遍优越。
