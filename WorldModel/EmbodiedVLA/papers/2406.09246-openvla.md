## 亮点与差异

- **① 一句话亮点**：把 7B 开源 VLM（Prismatic-7B：SigLIP+DinoV2 双视觉编码器 + Llama 2 7B）在 Open X-Embodiment 的 **970k 条真机演示**上做动作 token 预测微调，得到**参数量少 7×却反超闭源 55B RT-2-X** 的开源通用操作策略。
- **② 新在哪**：相对 **RT-2**（闭源、动作=文本 token、co-fine-tune）——本文第一次把该配方落到**完全开源**的 7B 基座上，并把 RT-2 的 min–max 分箱改成 **1st–99th quantile 分箱**（抗离群）；相对 **RT-1-X / Octo**——同评测协议下平均成功率大幅领先（BridgeData V2 70.6% vs 18.5% / 20.0%）；相对 **RT-2-X（55B）**——跨 29 任务平均 **+16.5%**，但**语义泛化一类仍输**；相对 **Diffusion Policy**——窄而高灵巧任务上游更弱（窄任务 DP 100% vs 50.0%），多指令多物体任务上反超；此外本文自称是首个**系统研究 VLA 高效微调与量化部署**的工作（LoRA / 量化 / 推理吞吐）。
- **③ 证据强度**：**大规模真机 + 大规模仿真 + 完整消融**，且**权重 / 代码 / 微调 notebook / 推理 server 全开源**。真机 3 套协议、跨 2 个本体：BridgeData V2（WidowX）**170 rollouts = 17 任务 × 10 trials**、Google robot **60 rollouts = 12 任务 × 5 trials**、Franka 适配 **129 rollouts**（Tabletop 99 + DROID 30）；参数高效与量化各 **33 / 80 rollouts**；LIBERO 仿真 **4 套件 × 500 trials × 3 seeds = 1500 trials/套件**。训练：**970k 轨迹**（OpenX 筛选后，>70 子数据集 / >2M 轨迹全集）、**64×A100 × 14 天 = 21,500 A100h**、batch 2048、27 epochs。开源侧：HuggingFace 权重 + PyTorch 训练代码 + 微调 notebook + 远程推理 server（SigLIP / DinoV2 / Llama 2 三组件权重公开，但其训练数据与代码未公开——脚注 1）。**非小设置**。
- **④ 值不值得引用**：**值得引，且是本专题多个条目的奠基引文**。能支撑：①「动作=离散文本 token + 开源 VLM 主干」路线在 7B 规模上可行且强；②「跨本体数据多样性」是一阶泛化变量（OpenX 混合消融 −30pt，远超视觉编码器消融 −5pt）；③ 参数高效（LoRA r=32 68.2% ≈ 全参 69.7%，仅 1.4% 参数）与低显存部署（int4 7.0GB / RTX 4090 ~6Hz）的工程可行性。**不能**支撑：①「co-fine-tuning（机器人与互联网数据联合微调）必要/有效」——本文**没做**联合微调，且自承语义泛化因此弱于 RT-2-X；②「VLA 已高可靠」——作者自述 typically <90%；③「高频灵巧控制可用」——单图、无 action chunking，50Hz（ALOHA 级）场景不可用；④ int8 的掉点**不是**精度问题（是 1.2Hz 速度伪影，blocking 对照已证）。

## 1. 解决什么问题

- **一句话**：现有 VLA（RT-2 等）**闭源**、且没人系统研究过 VLA 的**高效微调与部署最佳实践**；本文要给出一个**开源、可微调、可低成本部署**的通用操作策略，并顺带回答"跨本体数据 + 开源 VLM 能到什么水平"（§1、§2）。
- **与 RT-2 的定位差异**（§2 末段四点差异的自述口径）：(i) 完全开源（权重 + 代码 + 数据管线）；(ii) 首次系统研究高效微调（LoRA）与量化推理；(iii) 更细的数据清洗；(iv) 融合式视觉编码器（SigLIP+DinoV2）。
- **判据落位**（对本专题 `WorldModel/EmbodiedVLA` 的 (a)(b)(c) 三判据）：视觉输入 ✓ + 自然语言指令条件化 ✓ + 直接输出机器人动作 ✓；且动作头挂在**网络规模预训练 VLM** 上 → **强 VLA、开源**。

## 2. 核心方法（关键设计 · 公式 · 关键超参）

### 2.1 架构（§3.1, Figure 2）

| 组件 | 规格 |
| :-- | :-- |
| 基座 VLM | **Prismatic-7B**（Karamcheti et al. 2024） |
| 视觉编码器（600M） | **SigLIP + DinoV2 双编码器**，图像 patch 分别编码后**通道维拼接**；DinoV2 供低层空间信息、SigLIP 供高层语义 |
| Projector | **2 层 MLP**，视觉特征 → 语言嵌入空间 |
| LLM 主干 | **Llama 2 7B** |
| 输入分辨率 | **224×224 px**（消融见 §5） |
| Prismatic 预训练数据 | LLaVA 1.5 数据混合，约 **1M 图文 / 纯文本样本** |
| 推理提示 | `"What should the robot do to {task}? A:"` |

### 2.2 动作 token 化（§3.2）

- 动作**每一维独立离散为 256 bins**（跟随 RT-2）；**7 维动作** = 相对位姿 [Δx, Δθ] + 夹爪 **ΔGrip**（Figure 2 标注）。
- **对 RT-2 的具体修正**：bin 在训练数据该维动作的 **1st–99th quantile** 区间内**均匀划分**，而非 RT-2 的 min–max —— 避免离群动作拉宽离散区间、降低有效粒度。
- **token 绑定**：Llama tokenizer 只预留 **100 个 special tokens**，不够；故**覆写词表最少使用的 256 个 token（即词表最后 256 个）**作为 action token。
- **目标函数**：标准 next-token prediction 交叉熵，**loss 只在预测的动作 token 上计算**（视觉/语言 token 不贡献 loss）。

### 2.3 关键超参（逐条落到数值）

| 超参 | 值 | 出处 |
| :-- | :-- | :-- |
| 预训练算力 | **64 × A100 × 14 天 = 21,500 A100 小时** | §3.5 |
| batch size | **2048** | §3.5 |
| 学习率 | **2e-5**，固定（与 VLM 预训练同），扫描多个数量级后选定 | §3.4 |
| LR warmup | **无收益**（消融结论） | §3.4 |
| 训练轮次 | **27 epochs**（VLA 远多于 LLM/VLM 惯用的 1–2 epoch） | §3.4 |
| 收敛判据 | 真机性能持续提升至**训练集 action token accuracy > 95%** | §3.4 |
| 视觉编码器 | 训练时**解冻并微调全部 7B 参数**（含 SigLIP-DinoV2） | Appendix D.3 |
| 下游 LoRA | 默认 **r = 32**（r=64 无显著增益） | §5.3 |
| 推理 | bfloat16 需 **15GB 显存**；单张 **RTX 4090 约 6 Hz**（无编译 / 投机解码加速） | §3.5 |
| 代码库 | PyTorch + AMP / FlashAttention / FSDP，集成 HuggingFace AutoModel，内置 LoRA 与量化推理 | §4 |

### 2.4 数据清洗（Appendix C，方法学上最易被忽略的一条）

- **BridgeData V2 首帧全零问题**：原始数据每条演示的**第一帧为全零（no-op）动作**；高容量 VLA 直接训练后会在评测时频繁输出全零动作而**"冻结"**。
- OpenVLA 的解法：**过滤每条演示的首个 transition**（即丢掉首帧），已足够缓解。
- 对照：**RT-2-X 无此预处理**，评测时须**始终查询第二大概率动作**作 workaround（与 Open X-Embodiment 原文评测 RT-2-X 的做法一致）；**动态查询**（先取最大概率、全零则取次大）实测**更差**——中途重查询引入延迟、扰动系统动力学。

## 3. 数据与规模

- **全集**：Open X-Embodiment **>70 个子数据集、>2M 轨迹**（§3.3）。
- **本文用量**：经筛选（仅保留**至少有 1 个第三人称相机 + 单臂末端执行器控制**的 manipulation 数据集）+ 沿用 **Octo 的数据混合权重**（启发式下调/去除低多样性数据集）→ **970k 条真机轨迹**（§1、Figure 1 caption）。
- **混合前列（Table 3，共 25 个子数据集）**：Bridge 13.3%、Fractal 12.7%、Kuka 12.7%、BC-Z 7.5%、FMB 7.1%、Language Table 4.4%、Stanford Hydra 4.4%、Taco Play 3.0%、Furniture Bench 2.4%、Roboturk 2.3% 等。
- **DROID 的特殊处理**：以保守权重 **10%** 加入；但训练全程 DROID 上 **action token accuracy 持续偏低**，为不损害最终模型质量，**训练最后 1/3 阶段移除 DROID**，权重重分配给其余数据集（§3.3 + Table 3 脚注 6）。
- **训练集 action token accuracy** 是本文唯一的"是否练够"的量化判据（>95%，§3.4）。

## 4. 主要结果（每条均带条件）

### 4.1 开箱即用多机器人评测（§5.1）

**条件**：两个实体本体——**WidowX**（BridgeData V2 水槽场景）与 **Google robot**（RT-1/RT-2 评测用移动操作臂）；四类泛化（visual / motion / physical / semantic）+ **language grounding**；全部 **A/B 评测**（同任务、同初始机器人与物体状态集）；部分任务允许 **0.5 部分分**（Appendix B.1.1）。**评测口径：BridgeData V2 每方法 170 rollouts（17 任务 × 10 trials）；Google robot 每方法 60 rollouts（12 任务 × 5 trials）**。

| 平均成功率 ± StdErr | RT-1-X（35M） | Octo（93M） | RT-2-X（55B，闭源，经 API） | **OpenVLA（7B）** |
| :-- | --: | --: | --: | --: |
| BridgeData V2（WidowX，170 rollouts） | 18.5±2.7% | 20.0±2.6% | 50.6±3.5% | **70.6±3.2%** |
| Google robot（60 rollouts） | 33.3±6.1% | 26.7±5.8% | 78.3±5.4% | **85.0±4.6%** |

（Table 4 / Table 6；Google robot 上 RT-2-X 与 OpenVLA 误差条重叠，正文称二者相当并共同加粗。）

- **跨 29 任务总结**：OpenVLA 以 **7× 更少参数**，绝对成功率**超过 RT-2-X（55B）16.5%**（29 tasks，WidowX + Google robot 两 embodiment，Abstract/§1）。
- **例外（不能只引均值）**：BridgeData V2 上 Take Purple Grapes out of Pot：RT-1-X **6** > OpenVLA **4**；Stack Blue Cup on Pink Cup：RT-2-X **5.5** > OpenVLA **4.5**。Google robot 上 Pick Pepsi Can：RT-2-X 5 > OpenVLA 4；Open Middle Drawer：Octo 4 > OpenVLA 3；Move Coke Can near Taylor Swift：RT-2-X 3 > OpenVLA 2。逐任务明细（10 trials / 5 trials 成功数）在 Table 4 / Table 6。
- **语义泛化例外**：RT-2-X 在 semantic generalization 类别上更高（Figure 3；**各类柱值在提取文本中与柱条错位，未能逐类核实 `[待核]`**）。正文归因：RT-2-X 用更大规模互联网预训练数据且 co-fine-tune 保留预训练知识，而 OpenVLA 仅用机器人数据微调（§5.1）。
- **定性行为**：RT-2-X 与 OpenVLA 均表现出更强鲁棒性——干扰物下仍接近正确目标、按目标朝向调整末端、抓握不稳后能恢复；RT-1-X 与 Octo 常操作错误物体，甚至出现"手臂无目的挥动"（§5.1）。
- **优势归因（§5.1 末段）**：(i) 更大训练集（970k vs RT-2-X 的 **350k** 轨迹）；(ii) 更仔细的数据清洗（Bridge 首帧过滤）；(iii) 融合视觉编码器（语义 + 空间特征）。

### 4.2 数据高效适配新机器人（§5.2, Table 7）

**条件**：两套 Franka Emika Panda 设置——**Franka-Tabletop**（桌面固定，**5Hz** 非阻塞控制器）与 **Franka-DROID**（DROID 设置移动台架，**15Hz**）；**7 个目标任务**、每任务 **10–150 条演示**（Put Carrot in Bowl 50 / Pour Corn into Pot 50 / Flip Pot Upright **仅 10** / Move &lt;object&gt; onto Plate 150 / Knock &lt;object&gt; Over 70 / Cover &lt;object&gt; with Towel 45 / Wipe Table 70，Appendix B.3.1）；评测：Tabletop 每方法 10–12 in-dist + 5–6 OOD trial/任务，DROID 每方法 18 in-dist + 12 OOD（Wipe Table 单 trial 满分 2 分，总分 60）；**合计每方法 129 rollouts**（Tabletop 99 + DROID 30）。

| 平均成功率（Table 7） | Diffusion Policy | DP (matched) | Octo | OpenVLA (scratch) | **OpenVLA** |
| :-- | --: | --: | --: | --: | --: |
| Franka-Tabletop | 48.5±4.9% | 43.4±4.7% | 43.4±4.4% | 43.4±4.6% | **67.2±4.0%** |
| Franka-DROID | 35.0±8.0% | 26.7±7.5% | 38.3±8.5% | 21.7±6.6% | **58.3±7.2%** |

- **OpenVLA (scratch)** = 从 Prismatic 基座直接微调、**无 OpenX 预训练**（消融项）：Tabletop 43.4% / DROID 21.7% → **OpenX 预训练对下游适配是关键贡献**，不是锦上添花。
- **分工现象**：Diffusion Policy 在**窄单指令**任务上最强（Put Carrot in Bowl in-dist **90.0%** vs OpenVLA 70.0%；Pour Corn into Pot in-dist **100%** vs 50.0%）；OpenVLA/Octo 在**多指令多物体**任务上反超（Move &lt;object&gt; onto Plate in-dist：OpenVLA **75.0%** vs DP 25.0%；Knock &lt;object&gt; Over OOD：**83.3%** vs 16.7%）。
- Abstract 称"微调 OpenVLA 超过 from-scratch Diffusion Policy **20.4%**"：与 Table 7 两组平均值的合成口径**不完全吻合**（Tabletop 差 67.2−48.5 = 18.7；按 99/30 rollout 加权约 **19.8**）→ **`[待核]`**（文中未明示合成公式）。
- §5.2 称"**OpenVLA 是唯一在所有任务上 ≥50% 成功率**的方法"：Table 7 中 Put Carrot in Bowl (OOD) 为 **40.0%**、Pour Corn into Pot (in-dist) 为 **50.0%** → 若按"任务×条件"粒度存在反例，若按"任务"合并粒度则可能成立，**判定口径 `[待核]`**。

### 4.3 参数高效微调（§5.3, Table 1）

**条件**：Franka-Tabletop 两个代表任务（Put Carrot in Bowl 50 演示 + Move &lt;object&gt; onto Plate 150 演示，含 in-dist 与 OOD 变体），**每方法 33 rollouts**；§5.3/§5.4 使用**较小变体**（Octo 同款小 OpenX 混合 + **仅 SigLIP 单视觉编码器**，脚注 4）。

| 配置 | 成功率 | 可训练参数 | 显存（batch 16） |
| :-- | --: | --: | --: |
| Full FT | **69.7±7.2%** | 7,188.1M | 163.3GB（FSDP 分片 2 卡） |
| Last layer only | 30.3±6.1% | 465.1M | 51.4GB |
| Frozen vision | 47.0±6.9% | 6,760.4M | 156.2GB |
| Sandwich（视觉编码器 + token embedding + 末层） | 62.1±7.9% | 914.2M | 64.0GB |
| **LoRA r=32** | **68.2±7.5%** | **97.6M（仅 1.4% 参数）** | 59.7GB |
| LoRA r=64 | 68.2±7.8% | 195.2M | 60.5GB |

- 结论：只调末层或冻结视觉编码器**明显掉点** → 视觉特征对目标场景的适配至关重要；**LoRA 匹配全参微调性能且只训 1.4% 参数**；r=32 与 r=64 差异可忽略 → 默认 **r=32**；**单张 A100 10–15 小时**完成单任务微调，相比全参微调（8×A100 × 5–15h/任务）**算力降 8×**。

### 4.4 量化推理（§5.4, Table 2 / Table 11）

**条件**：8 个代表 BridgeData V2 任务，**每方法 80 rollouts**；部署卡 **A5000**。

| 精度 | 成功率 | 显存 | A5000 实测频率 |
| :-- | --: | --: | --: |
| bfloat16 | **71.3±4.8%** | 16.8GB | — |
| int8 | 58.1±5.1% | 10.2GB | **1.2 Hz**（掉点） |
| int4 | **71.9±4.7%** | **7.0GB** | **3 Hz**（不掉点） |

- **机制**：int8 掉点源于**推理变慢**——量化算子开销使其在多数 GPU 上吞吐反而下降；1.2Hz 与 BridgeData V2 数据采集的 **5Hz 非阻塞控制**动力学失配。int4 因显存传输减少补偿了量化开销（3Hz），故性能不降。离线看三者 token accuracy 相当（脚注 5）。
- **因果确证（Table 11, Appendix D.4）**：强制每动作执行完再预测下一步（blocking control）消除速度差后 → bf16 **70.0±5.1%** / int8 **74.4±4.9%** / int4 **68.8±5.2%**，**误差条重叠** → 证明 int8 掉点是**速度伪影而非精度损失**。

### 4.5 LIBERO 仿真（Appendix E, Table 12）

**条件**：LIBERO 四个套件（Spatial / Object / Goal / Long），每套件 **10 任务 × 50 条遥操作演示**；**每套件 500 trials × 3 seeds = 1500 trials**；OpenVLA 用 **LoRA r=32** 微调；Diffusion Policy 用 DROID 论文实现（DistilBERT 语言嵌入，脚注 8）；**所有方法只用第三人称相机**（公平性，Appendix E.1）。数据清洗 5 步：(1) 重渲 **256×256px**（原 128×128 直接上采样质量差）；(2) 滤除 no-op；(3) 第三人称图**旋转 180°**（其硬件上 LIBERO 图像颠倒）；(4) 重放并滤除未成功轨迹（Spatial 去 **68/500**、Object 去 **46/500**、Goal 去 **72/500**、Long 去 **121/500**）；(5) 统一只用第三人称相机。

| 套件（1500 trials） | OpenVLA | Octo | Diffusion Policy |
| :-- | --: | --: | --: |
| LIBERO-Spatial | **84.7±0.9%**(1) | 78.9(2) | 78.3(3) |
| LIBERO-Object | 88.4(2) | 85.7(3) | **92.5±0.7%**(1) |
| LIBERO-Goal | 79.2(2) | **84.6±0.9%**(1) | 68.3(3) |
| LIBERO-Long | **53.7±1.3%**(1) | 51.1(2) | 50.5(3) |
| **平均** | **76.5±0.6%（rank 1.5）** | 75.1±0.6%（rank 2） | 72.4±0.7%（rank 2.5） |

- 正文注（Appendix E.2）：仿真上差距比真机小，归因于 OpenVLA 预训练**纯真机数据**、与仿真存在域差；预期预训练混入仿真数据后增益会增大。
- **同时是失分点**：LIBERO-Long 仅 53.7%、LIBERO-Object 被 DP 反超（92.5 > 88.4）。

## 5. 消融说明什么

| 变量 | 对照 | 结论（带数值） | 出处 |
| :-- | :-- | :-- | :-- |

## 6. 什么条件下失效

### 6.1 论文自承（§6 与各节明示）

1. **仅支持单图输入**（§6 第一条）：不支持多相机 / 本体感 / 观测历史；作者把"用交织图文预训练的 VLM 做柔性输入微调"列为未来方向。
2. **推理吞吐不足**（§6 第二条）：无法满足 **ALOHA 等 50Hz 高频控制**与更灵巧的双臂任务；建议 action chunking / speculative decoding。
3. **可靠性上限**（§6 第三条）："typically achieving **<90% ssuccess rate**"（原文如此），尚未达到高可靠。
4. **语义泛化弱于 RT-2-X**（§5.1）：Figure 3 semantic 类别 RT-2-X 更高；归因于未做 co-fine-tuning、无互联网知识保留。
5. **灵巧性弱于 Diffusion Policy**（§5.2）：窄而高灵巧任务上 DP 轨迹更平滑精确（OpenVLA 无 action chunking / temporal smoothing）；Table 7 实证 Pour Corn into Pot in-dist DP 100% vs OpenVLA 50.0%。
6. **int8 量化在慢 GPU 上掉点**（§5.4）：1.2Hz 失配系统动力学，58.1% vs bf16 71.3%（已被 Appendix D.4 证实为速度伪影）。
7. **DROID 数据学不会**（§3.3）：action token accuracy 始终偏低，后 1/3 阶段被移除；暗示需要更大混合权重或更大模型。
8. **LIBERO 上优势收窄**（Appendix E.2）：与 DP/Octo 差距比真机小；LIBERO-Long 仅 53.7%；LIBERO-Object 上 DP 92.5 反超。
9. **未探索的设计问题**（§6 末段）：基座 VLM 规模的影响、机器人 + 互联网数据 co-training 是否显著提升 VLA、最优视觉特征——**均因算力限制未做**。
10. **评测依赖数据清洗**（Appendix E.1）：作者自承 no-op 过滤等清洗对单步策略"至关重要" → 模型对演示数据中的**停顿模式敏感**。

### 6.2 本文推断（非论文自述，判断用）

- **A（推断）**：语义泛化差距很可能**不是模型规模**造成的（7B 输 55B 的恰恰是"世界知识"维度，而赢的是动作执行维度），而是**训练数据构成**造成的——本文的机器人数据微调会冲刷掉 VLM 的互联网语义先验。若要证伪，需做 co-training 消融，本文未做。
- **B（推断）**：`OpenVLA (scratch) 43.4%` 与 `OpenVLA 67.2%` 的巨大差距说明：**VLA 的性能下限由预训练数据多样性决定，上限才由微调数据量决定**——这解释了为什么 10 条演示的 Flip Pot Upright 也能到可用水平。
- **C（推断）**：int8 的"速度伪影"结论**只在非阻塞控制下成立**；一旦部署系统是阻塞式（同步等动作执行完），int8 反而是三个精度里最好的（74.4%），所以"int8 不可用"是**系统级而非精度级**结论，引用时必须带控制模式条件。
- **D（推断）**：单图 + 无历史的设计在**动态任务**（移动物体、需要记忆的任务）上应系统性弱于有历史帧的模型；本文未在该维度评测，但 Open X-Embodiment 的 Table II row 4 vs row 5（有历史 44.4% vs 无历史 14.5%）是同一结论的跨本体证据。

## 7. 与同类系统的可判定差异（对照表带条件列）

| 维度 | **OpenVLA**（本文） | RT-2 / RT-2-X | RT-1-X / Octo | Diffusion Policy |
| :-- | :-- | :-- | :-- | :-- |
| 规模 | **7B**（开源） | 55B（闭源，经 API 评测） | 35M / 93M | 未在本文列参数量 |
| 动作表征 | 离散 token，**每维 256 bin，1st–99th quantile 均匀分箱** | 文本 token，**256 bin（min–max）**，8 维（含终止维） | 离散 token（RT-1 系）/ 连续 chunk（Octo） | **连续**，action chunking（原版） |
| 是否联合微调 | **否**（仅机器人数据） | **是**（约 1:1 co-fine-tuning） | 否 | 否 |
| 视觉塔 | **SigLIP + DinoV2 双编码器融合，且解冻微调** | ViT + UL2（RT-2-PaLI-X，WebLI 预训练） | EfficientNet（RT-1）/ 自有 | 自有（单图，matched 版无本体感） |
| 观测输入 | **单图 + 指令** | 单图 / 历史（RT-2-X 评测用 none） | RT-1-X 用 **15 帧历史** | 原版 2 步历史 + 本体感；matched 版单图 |
| 训练数据 | OpenX 筛选后 **970k 轨迹**（25 子集） | **350k 轨迹**（本文引述） | — | DROID 实现（对比时） |
| 真机评测协议（条件） | Bridge **170 rollouts = 17×10**；Google robot **60 = 12×5** | 同协议（本文复现评测） | 同协议 | Franka 两设置 **129 rollouts** |
| 真机成绩（同条件） | Bridge **70.6±3.2%**；Google **85.0±4.6%** | 50.6±3.5% / 78.3±5.4% | 18.5±2.7 / 20.0±2.6；33.3±6.1 / 26.7±5.8 | Tabletop 48.5±4.9%；DROID 35.0±8.0% |
| 语义泛化 | **弱于 RT-2-X**（Figure 3 `[待核]`） | 更强（co-fine-tune + 更大互联网数据） | 更弱 | — |
| 窄任务灵巧度 | 弱于 DP（50.0% vs 100.0%，Pour Corn in-dist） | — | — | **更强** |
| 参数高效微调 | **LoRA r=32：68.2%，1.4% 参数，单 A100 10–15h** | 未报 | Octo 可微调 | — |
| 部署成本 | int4 **7.0GB**、bf16 15GB；4090 约 **6Hz** | 云端托管（题目称 55B） | 更小 | — |
| 开源程度 | **权重 + 代码 + notebook + 推理 server** | 闭源 | RT-1-X / Octo 开源 | 开源 |

**可判定差异的读法（三句话）**：

1. **同一条"动作=文本 token"路线**，OpenVLA 的增量是"**开源主干 + quantile 分箱 + 数据清洗**"，把 RT-2 的闭源 55B 结果**在 7B 上复现并小幅超越**（跨 29 任务 +16.5%）——因此它能支撑"路线成立"，不能支撑"RT-2 的配方必需 55B"。
2. **与 RT-2-X 的唯一系统性劣势是语义泛化**，而该劣势的**原因（无 co-fine-tuning）在本文中被作者自己承认**，所以引用"OpenVLA 全面超越 RT-2-X"是错的。
3. **与 Diffusion Policy 是分工而非替代**：窄任务/高灵巧归 DP，多指令多物体/语义条件化归 VLA（Table 7 的双向反超是最干净的判据）。
