# WoVR：把世界模型变成可控的 VLA 强化学习模拟器

> **来源版本**：[arXiv:2602.13977v2](https://arxiv.org/html/2602.13977v2)，2026-06-27，*WoVR: World Models as Reliable Simulators for Post-Training VLA Policies with RL*。
> **主等级**：`[精读原文]`（固定版本 arXiv HTML；重点阅读 §§3–4、§6 与附录 B–F）。
> **适用问题**：当策略在生成式世界模型里做闭环 RL 时，如何降低模型幻觉给策略的错误优化信号？

## 亮点与差异

- **一句话亮点**：WoVR 把“世界模型不是真实模拟器”当作训练协议问题处理：用稳定、可控的动作条件视频模型，靠关键帧初始化缩短想象前缀，再以演化策略采集的数据低频更新世界模型。
- **新在哪**：相对把视频模型当即插即用模拟器的 WMPO，WoVR 把可靠性拆为模型滚动稳定性、交互起点和策略—模型分布对齐三层；KIR 与 PACE 是作用于 RL 数据流的机制，不只是视频生成器的画质改进（§§2.2、3、Appendix D.2）。
- **证据强度**：LIBERO 四套仿真任务、模型视频指标与两种真机平台各三项任务；真机每任务 30 次。LIBERO 主比较明示每 suite 2,500 条“真实环境交互轨迹”（指 benchmark 环境轨迹，不是物理机器人试验）；WoVR 用 1,500 条基础策略轨迹和 1,000 条演化策略轨迹训练/精炼模型。作者报告真实机器人提升，但没有独立复现。
- **值不值得引用**：值得作为“通过约束想象交互来做 VLA-RL”的机制证据。引用时应保留真实数据预算、基准任务、真机试验规模，以及模型视频相似度不等于物理动力学正确这些条件。

## 七问

### 1. 解决什么问题？

VLA 的模仿学习表现受演示覆盖和质量限制，RL 有望继续改善行为；但真实机器人上的 on-policy RL 需要大量并行交互、重置和数据采集。生成式视频世界模型让策略可以在想象轨迹里更新，却可能生成视觉上合理、物理上错误的结果。作者把闭环想象中的系统性“想象—真实结果不匹配”称为 hallucination：自回归反馈会放大早期误差，策略更新又会把动作分布推离世界模型训练数据。若直接拿这些 rollouts 的奖励更新策略，策略可能学会利用模型漏洞，而非改善真实任务（§1；§3.2）。

### 2. 核心方法是什么？

**世界模型稳定化。** WoVR 将 Wan2.2-TI2V-5B 视频扩散骨干改为动作条件生成器，动作用两条路径注入：调制去噪特征的 timestep-conditioned normalization，以及替代文本嵌入、提供全局动作条件的 cross-attention（§3.1、Fig. 3）。每个自回归块把干净的初始帧 `o₀` 与最近生成记忆帧拼成 `[o₀, o_{t-c:t}]`。初始帧锚定场景布局和外观，近邻记忆帧保留局部运动；训练时只对非锚点上下文帧加轻噪声，缩小训练时真实上下文与推理时自生成上下文的差异（§3.1；Appendix B.1）。因此它降低漂移、结构坍塌和脆弱复制倾向，但不能保证模型每帧都符合物理。

**KIR（Keyframe-Initialized Rollouts）。** 常规 imagined rollout 从 `o₀` 开始，模型必须先想象长前缀才能到达关键接触或失败位置，之前的误差可能已累积。KIR 把一部分 rollout 初始化到任务关键时刻附近：保留 `o₀` 作为全局锚点，再将关键时刻之前最近四帧作为局部上下文，接着从该处生成后续动作条件帧（Appendix B.3，式 11–15）。关键帧索引按任务设定在基础策略通常进入关键失败区域的时刻，不逐条手工挑选；第一段之后照常按锚点和最近生成帧自回归。KIR 改的是输入上下文，不是世界模型结构。其目标是减少需要模型“凭空滚动”的有效误差深度，让 RL 的梯度更集中于决定成功/失败的局部动作；配套 GRPO 还按有效轨迹长度归一化（§3.2，式 1）。

**PACE（Policy–Aligned Co-Evolution）。** 策略在模型中优化后会改变动作分布，静态模型可能因分布外动作而失准。PACE 先用基础策略数据训练 `WM_Base`，在其中优化策略；随后用演化策略再采少量轨迹精炼为 `WM_Evo`，再继续优化。模型精炼频率低，不是经典 model-based RL 中高频更新 dynamics，也不要求训练期间持续人工监督或频繁重置真机；但这只是减少持续在线采集，不能解读为完全不需要真实轨迹（§3.3）。

策略在想象环境中用 GRPO 更新。模型同时给出奖励信号：主实验采用轻量 ResNet 二分类成功奖励；另试用 Qwen3-VL 2B 生成 0–10 级进度的稠密奖励，后者前期学习更快但 rollout 约慢 3 倍，最终性能接近，因此主实验选稀疏奖励（Appendix B.2、D.3）。

### 3. 数据与规模是什么？

- **LIBERO 策略实验（§4.2、Table 2）**：Spatial、Object、Goal、Long 四套，每套 10 项任务；从 OpenVLA-OFT 初始化，比较 one-trajectory SFT 与 full-trajectory SFT 两种基础策略。所有方法每个 suite 使用相同的 **2,500 条 LIBERO benchmark 环境轨迹预算**（仿真交互，不是真机 rollouts）。GRPO (Online) 直接用它们在线优化；WMPO 用它们训练世界模型，再在想象中 RL；WoVR 用 **1,500 条基础策略仿真轨迹训练初始模型 + 1,000 条演化策略仿真轨迹精炼模型**，策略更新则在想象中完成。真机实验是另一独立阶段。数据采集负担被重新分配，不能称 WoVR “real-data-free”或“无环境交互”。
- **世界模型视频质量评估（§4.1、Table 1）**：在 LIBERO 收集 3,000 条、每条 512 帧的 VLA rollout 训练世界模型，另用 200 条同长度轨迹作 held-out 评估；对照 EVAC、Cosmos-Predict2 和 WMPO 使用的 OpenSora。按相同 chunk-wise 自回归协议评估，报告 LPIPS、FID、FVD、FloLPIPS 和 FPS。
- **真实机器人（§4.3、Tables 3–4；Appendix F）**：Franka Emika Panda 上测 Pick Banana、Pick Bread、Open Drawer；AgileX Piper 上测 Fold Towel、Pick Cube、Pick Tomato。每个平台各训练一个覆盖三任务的多任务策略和对应世界模型；每个 task 做 30 次独立 trial，即 **2 平台 × 3 任务 × 30 次/任务**。Appendix F.1 报告 Piper 为 6-DoF、头视角 D435 RGB、10 Hz；Franka 为 7-DoF、固定第三人称 D435、30 Hz。两平台策略动作均为 delta end-effector，后经 IK 转成关节命令（Appendix F.3）。

### 4. 主要结果是什么（带条件）？

- **世界模型指标**（LIBERO、Table 1）：512 帧 rollout 时 WoVR 为 23 FPS、LPIPS 0.091、FID 34.252、FVD 68.011、FloLPIPS 0.154；OpenSora 对应 7 FPS、0.105、38.478、89.391、0.156。作者指出 WoVR 使用更大的 Wan 约 5B 骨干（OpenSora 约 1.3B），但仅 5 个 diffusion steps 且用 3D VAE，故速度也受采样和架构配置影响。感知/分布指标不能单独证明生成的接触动力学正确。
- **LIBERO 策略成功率**（Table 2）：one-trajectory SFT 下 OpenVLA-OFT 平均 40.5%，GRPO-online 44.6%，WMPO 50.9%，WoVR 69.5%；WoVR 对基础策略 +29.0 个百分点。Full-trajectory SFT 下分别为 88.1%、89.7%、92.4%、WoVR 表格报 96.0%（+7.9 个百分点）。正文 §4.2 将 WoVR 平均写成 95.9%，与 Table 2 的 96.0% 存在 0.1 个百分点的舍入/报告差异，引用宜注明依据表格。
- **作者报告的真机成功率**（Table 3，每 task n=30）：Franka 的 OpenVLA-OFT / WMPO / WoVR 平均为 51.1% / 64.5% / 80.0%，WoVR 相对基础策略 +28.9 个百分点；Piper 为 15.5% / 18.9% / 28.9%，WoVR +13.4 个百分点。逐项看 Franka 的 Pick Banana 为 36.7% / 56.7% / 86.7%，Pick Bread 为 70.0% / 76.7% / 90.0%，Open Drawer 为 46.7% / 60.0% / 63.3%；Piper Fold Towel 为 10.0% / 10.0% / 20.0%，Pick Cube 为 23.3% / 26.7% / 33.3%，Pick Tomato 为 13.3% / 20.0% / 33.3%。这是真机部署评估，不是仿真指标，但任务数和每项试次数有限。
- **另一 VLA 骨干**（Table 4）：AgileX Piper 上将 π₀.₅ 与 Flow-SDE 结合 WoVR，平均成功率从 34.4% 到 56.7%（+22.3 个百分点，30 次/task）；这支持在第二个策略骨干上的可迁移性，但仍是单平台、三任务的小规模实机证据。

### 5. 消融说明什么？

- **PACE 与数据量（Appendix D.2、Table 6）**：在 LIBERO Spatial / Object 的 one-trajectory 设置，1,500 条 base-policy 仿真轨迹且无 PACE 的两套平均为 75.8%；加到 2,500 条同分布 base-policy 仿真轨迹为 77.5%，+1.7 点；PACE 的 1,500 base + 1,000 aligned 仿真轨迹版本为 82.5%。这与“策略分布对齐比单纯增加同分布数据更有帮助”一致，但它是两 suite 的特定消融，不是所有环境下的数据效率定律。作者还报告 PACE 更新后 imagined training 曲线与 real evaluation 更一致（Fig. 8）。
- **KIR（Appendix D.2、Table 6）**：移除 KIR 后 Spatial 从 84.2% 降到 81.6%，Object 从 80.8% 降至 77.8%，两 suite 平均从 82.5% 降至 79.7%（-2.8 点），支持关键帧初始化在该设置下减少早期误差累积。
- **世界模型上下文机制（Appendix D.1、Table 5）**：在 LIBERO-Spatial、1,500 条训练轨迹、24 条 held-out 轨迹上，无固定 reference frame 或只用单帧上下文均使长 horizon 指标退化；例如 512 帧 LPIPS 从 0.091 升至 0.133 / 0.120，FID 从 36.687 升至 73.942 / 64.501。移除 noisy context 的退化幅度较小（LPIPS 0.099，FID 44.712）。这表明锚点与多帧记忆的证据强于噪声增强的单独贡献。
- **稀疏/稠密奖励（Appendix D.3、Fig. 9）**：稠密奖励有较快早期学习曲线，最终性能相近，但因 Qwen3-VL 2B 令 rollout 约慢 3 倍，主实验选稀疏 reward。文中未给出充分的显著性/跨种子统计来支撑普遍优越性结论。

### 6. 什么条件下失效或结论受限？

- 作者在 §6 明确承认，hallucination 如何传入策略优化仍以经验分析为主，没有形式化传播刻画，也没有相对真实环境最优策略的 regret bound。
- 评估集中于 LIBERO 和桌面操作；更长时程任务、移动操作、视角变化、更大状态空间与多样接触动力学尚未充分探索。此类场景可能放大误差；作者指出需要更多样的具身预训练数据和更强的误差抑制机制（§6）。
- KIR 依据任务设置固定关键帧索引，论文不是自动发现关键状态的通用方法；换任务时如何稳妥选取关键点、失败分布改变后是否仍合适，尚是部署问题（Appendix B.3）。
- PACE 用演化策略轨迹精炼模型，因此依赖额外真实环境采集。主实验预算与比较对齐在每 LIBERO suite 2,500 条，但实际部署中采集难度、标注成本及迭代成本没有被“无真实数据”消除。
- 真机证据为两种机械臂、六项桌面任务、每任务 30 次；Piper 与 Franka 的相机视角、采样频率和控制特性不同（Appendix F.1），跨平台平均不能替代严格同条件本体对照。平均成功率还掩盖任务差异，例如 Franka Open Drawer 的 WoVR 仅 63.3%，而 Pick Bread 为 90.0%（Table 3）。
- 表格全轨迹 SFT 的 WoVR 平均为 96.0%，正文写 95.9%（§4.2 / Table 2）；保留该 0.1 点出入，不推测哪一处更正。视频感知指标、RL imagined success 和物理机器人 success 是不同证据层次，不能互相代替。

### 7. 与同类系统如何判定差异？

最可判定的差异是它是否显式应对**策略更新导致的世界模型分布漂移**，以及是否改变想象 rollout 的起点。作者将 WMPO 描述为用 OpenSora 做想象 RL，但没有为策略变化设计专门的低频模型再对齐或 KIR 机制；在 LIBERO 表 2 的共同预算设置中，WoVR 优于 WMPO。与“只把世界模型当奖励/评价信号”的工作相比，WoVR 将模型放在动作执行—状态返回—策略优化循环中，直接提供 imagined environment transition（§2.2；Appendix A）。因此核心贡献是处理不完美模拟器与优化器之间的交互协议，而非宣称视频模型已经等价于真实物理环境。
