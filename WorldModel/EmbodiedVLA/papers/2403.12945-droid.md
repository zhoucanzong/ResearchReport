# DROID：A Large-Scale In-The-Wild Robot Manipulation Dataset（Khazatsky / Pertsch / Nair et al., 2024–2025）

## 亮点与差异

> **① 一句话亮点**：用**同一套 Franka Panda 硬件栈 + 统一采集协议**，把 **50 名采集员**在北美/亚洲/欧洲 **564 个真实场景（52 栋建筑）**里 **12 个月**采到的 **76k 条轨迹 / 350 小时**交互数据汇成一个 in-the-wild 数据集，并证明把它混进策略训练能提升性能与泛化（**6 任务 4 地点、平均 +20%**）。**引用时必须搬走的前提**：单一本体（Franka Panda 7DoF）、单一遥操作接口（Meta Quest 2）、15 Hz 控制、仅保留"成功"轨迹。
> **② 新在哪**：**相对此前大规模真机数据集**（BridgeData V2、RH20T、RT-1 数据），本文的差异是**场景与交互位置的多样性**而非单纯规模——论文专用一节（§IV）沿「任务 / 物体 / 场景 / 视角 / **交互位置**」多条轴做量化对比，结论是 DROID 在这些轴上**显著超过既有数据集**，且只有 Bridge V2 有量级相当的长尾技能分布（Fig. 3）。**相对 Open X-Embodiment**：OXE 是**跨本体的数据汇集与格式标准化**（22 本体 / 多机构），DROID 是**单本体、统一硬件与协议、分布式采集**——两者解决的是不同问题（格式统一 vs 采集一致性），**不可互相替代**。**相对仿真/合成数据**：本文提供的是真实物理下的接触与视觉分布，代价是无法像仿真那样按需生成与控制变量。**相对"先定任务清单再采集"的做法**：本文靠**共享采集协议 + 现场自选任务列表**（采集员每次从列表随机取任务）来摊平个体差异，并用**众包独立标注**（每条最多 3 条指令、来自不同标注员）提升语言多样性。
> **③ 证据强度**：规模数字全部为一手正文：**76k 轨迹 / 350 小时 / 564 场景 / 52 建筑 / 86 任务 / 50 名采集员 / 13 家机构 / 12 个月**（Fig. 1 图注、§I、§III-A）；硬件栈**复刻 18 套**（§III-A）；每场景约 **100 条轨迹或 ~20 分钟**交互（§III-A）；相机标定覆盖**约 36k 场景**（单相机对齐 base）与**约 24k 场景的"三种方法交集"超集**（附录 G）；策略侧评测 **6 任务 × 4 地点**（实验室 / 办公室 / 真实家庭），每任务 **50–150 条示范**，且**每个任务都设计了自己的分布外变体**（附录/§V-A）；训练用 **50/50** 混合（域内小数据 + 完整 DROID，剔除标记为不成功的轨迹），策略为 **U-Net 扩散头 + ResNet-50 视觉 + 冻结 DistilBERT 语言**、生成 16 步动作序列、rollout 时开环执行 8 步。**数据、训练代码、预训练权重与硬件复现指南全部开源，数据集许可 CC-BY 4.0**（Abstract、§I）。这是目前可核到的**采集一致性与场景多样性**方面最完整的一套真机数据证据。
> **④ 值不值得引用**：**值得引，应作为"真机数据从哪来、规模化采集的边界在哪"的一手出处**。**能支撑**：①大规模 in-the-wild 真机操作数据集的**规模与采集协议**事实；②"**场景/交互位置多样性**与单纯堆规模不是一回事"这一数据侧论点（§IV 的多轴分析）；③"混入大规模野外数据可提升策略性能与泛化"这一**在其 6 任务 4 地点设置内**的结论；④相机—基座自动标定的工程做法与其实测覆盖量。**不能支撑**：①**任何动作表征或策略架构结论**——DROID 不是 VLA 策略，它没有提出 token/flow matching/diffusion 的任何新设计，评测用的策略也是既有扩散策略实现（Robomimic 上的 diffusion policy）；②**跨本体结论**——全部数据来自 **Franka Panda + 同一遥操作栈**，把它当成"跨机器人通用数据"是误用（跨本体汇集是 OXE 的命题）；③**绝对性能数字的搬迁**——"+20%"是特定 6 任务、特定基线与特定混合比例下的值，不是常数；④**仿真的替代品**——它是真实数据，不能用来做受控变量实验。

## 1. 解决什么问题

- **痛点**（Abstract、§I）：造大规模、多样、高质量的真机操作数据**在后勤与安全上都很难**，需要大量硬件与人力投入。结果是：即便最先进的通用操作策略，**训练数据也主要来自少数环境、场景与任务多样性有限**。
- **本文的判断**：泛化能力的关键不是"数据总量"，而是**多样性沿哪些轴增长**——场景多样性 → 新场景泛化；任务 / 相机视角多样性 → 新指令与新视角泛化；**交互位置多样性**（交互发生在机器人基座坐标系下的哪些 3D 位置）→ 新布局、新台面高度、新工作空间区域的泛化。`[精读原文]`（§IV）
- **本文交付**：一个**分布式采集**的 in-the-wild 数据集 + 采集协议 + 硬件复现指南 + 策略训练代码与权重。**目标不是提出新策略架构**——策略侧实验用的是既有扩散策略实现。
- **定位差异（一句话）**：OXE 解决"**跨本体如何汇总**"，DROID 解决"**同一本体如何把野外多样性采到、并采得一致**"。两者是互补的数据命题。

## 2. 核心方法（关键设计 · 公式 · 关键超参）

> 本节按"数据集的构造方法"组织——DROID 的"方法"是**采集与标定管线**，不是模型。

### 2.1 硬件栈（统一是前提）`[精读原文]`（§III-A、Fig. 2）

| 组件 | 规格 |
| :-- | :-- |
| 机器人 | **Franka Panda 7DoF**，控制频率 **15 Hz** |
| 相机（第三视角） | **2 台可调 Zed 2 双目相机** |
| 相机（腕部） | **1 台 Zed Mini 腕部双目相机** |
| 遥操作 | **Meta Quest 2（Oculus Quest 2）手柄**，连续空间控制 6D 位姿与夹爪 |
| 计算 | Franka 控制箱 + 一台 NUC（托管 Polymetis server）+ 一台 Alienware 笔记本（跑采集 GUI） |
| 供电 | **单根电源线**——为的是频繁换场地 |

- **复刻度**：该套装配在整个项目里**复刻 18 次**，分布在北美/亚洲/欧洲多地点。`[精读原文]`
- **每 episode 内容**：三路同步 RGB + **深度** + **相机标定** + 自然语言指令。`[精读原文]`（Abstract、Fig. 1 图注）

### 2.2 采集协议（解决"50 人采得一致"的问题）`[精读原文]`（§III-B）

- **共享采集协议**：为**经验不足的采集员**降低方差——含"相机看不到机器人""遥操作员出现在画面里"等**已知错误检查**，以及**第三视角相机选址指引**（要在能看见机器人、同时姿势可控的位置）。
- **任务来源**：现场提供任务列表，**采集员每次随机抽取一个任务**来采——用随机化摊平个体偏好。
- **单场景用量**：**每场景最多约 100 条轨迹或约 20 分钟**交互数据，然后换场景。
- **语言标注**：**后处理阶段众包标注**（平台 tasq.ai），**每条 episode 最多 3 条独立标注指令**（来自不同标注员），以保证标注多样性。
- **过滤器**：发布数据中**不成功轨迹被标记**（策略训练时按 50/50 混合并**剔除"not successful"轨迹**）；另有部分轨迹因采集失误不计数入数据集规模。

### 2.3 相机—基座标定（数据可用性的关键工程）`[精读原文]`（§III-B 末、附录 G）

- **动机**：初始外参标定可能因棋盘格错位、光照不一致、OpenCV 标定方法固有误差而**不准**——作者把不准确度当作**必须显式处理**的问题。
- **做法**：**全自动**的三阶段事后标定（camera-to-base / camera-to-camera / 交集超集）。
- **交付三套标定矩阵**：
  1. **约 36k 场景**：左或右**一台**相机相对机器人基座标定；
  2. **全部场景**：camera-to-camera 相对变换；
  3. **约 24k 场景的超集**：两台相机均相对基座标定，且混合三种方法、各自带有质量保证（IOU 阈值 0.6、重投影误差 20、按匹配数取前 30% 分位）。
- **自承**：全自动流程**仍有假阳性**（附录 D 进入 Limitations）。

### 2.4 策略侧实验配置（用于验证数据价值，不是本文贡献主体）`[精读原文]`（§V-A、附录 F）

| 项 | 设置 |
| :-- | :-- |
| 策略 | U-Net **扩散头**（基于 Robomimic 的 diffusion policy 实现） |
| 视觉 | 两台**外部相机** RGB，下采样到 **128×128**，**ResNet-50**（ImageNet 预训练）编码 |
| 语言 | **冻结 DistilBERT** 嵌入 |
| 动作 | **绝对**末端执行器平移 + 旋转 + 夹爪 |
| 动作序列 | 训练生成 **16 步**；rollout 时**开环执行前 8 步**再重新推理 |
| DROID 用法 | 训练 batch **50/50** 混合（域内小数据 + 完整 DROID），**剔除标记为不成功的轨迹** |

> **注意**：以上是"用 DROID 训策略"的参照配置。**它是既有方法的组合，不是 DROID 提出的新方法**——引用时不可把该策略的能力算作 DROID 的方法贡献。

## 4. 主要结果（全部带条件）

> **条件前置**：以下结论只在「**Franka Panda + DROID 硬件栈 + 6 任务 + 4 地点**」的设置内成立；基线是"使用既有大规模数据集"的先进方法。

### 4.1 核心结论 `[精读原文]`（Abstract、§I）

- 在 **6 个任务、4 个地点**（实验室 → 办公室 → **真实家庭**）的实验中，「从实验室到办公室再到真实家庭」的场景跨度被显式覆盖。
- **结果**：DROID 使策略的**性能、鲁棒性与泛化性平均提升 20%**（相对使用既有大规模数据集的前沿方法）。
- 每个任务都配有**自己的分布外变体**，例如：加干扰物、换未见过的薯片袋、未见过的干扰物、要烤一个**新物体**等（Fig. 7 图注）。

### 4.2 任务与数据量（带条件列）`[精读原文]`（§V-A、Fig. 7）

| 任务 | 场景 | 时长档 | 示范数 | 分布外变体 |
| :-- | :-- | :-- | --: | :-- |
| Closing Waffle Maker | 实验室 | 短 | 70 | 桌面加干扰物 |
| Place Chips on Plate | 实验室 | 短 | 50 | 换薯片种类 / 加更多干扰物 |
| Put Apple in Pot | 实验室 | 中 | 60 | 未见过的干扰物 |
| Toasting | — | — | 50–150 区间 | 烤一个**新物体** |
| Clean up Desk | 办公室 | — | 50–150 区间 | 桌面与抽屉内干扰物 |
| Cook Lentils | 家庭 | 多阶段 | 50–150 区间 | 加干扰物 |

> 表中"50–150 区间"对应 Fig. 7 图注的全任务区间表述；前三行的逐任务数字来自正文与图注。

### 4.3 使用方式对结论的影响（必须一起引用）

- **50/50 混合**域内数据与完整 DROID，且**剔除不成功轨迹**是作者"实践中效果好"的选择（§V-A）——**换混合比例或不过滤，结论不保证**。
- 视觉只用了**两台外部相机**（腕部相机信息在策略侧未使用）——所以该结果**不等于**"DROID 的全部信息都被用上了"。`[精读原文]`

## 5. 消融说明什么

> DROID 是数据集论文，"消融"体现在**数据轴分析与使用方式**上，而不是模型组件。

| 变量 | 对照 | 结论 | 出处 |
| :-- | :-- | :-- | :-- |
| 有无 DROID 混合 | 只用域内小数据 vs 50/50 混合 | 混合后性能与泛化提升（平均 +20%） | §I、§V-A |
| 成功/失败轨迹 | 保留 vs 剔除标记为不成功的轨迹 | 作者报告**剔除**在实践中效果好 | §V-A |
| 多样性轴 | 任务 / 物体 / 场景 / 视角 / 交互位置逐轴对比既有数据集 | DROID 各轴均更高；仅 Bridge V2 有可比长尾 | §IV |
| 相机—基座标定质量 | 原始外参 vs 自动事后标定 | 事后标定修正棋盘格/光照/算法引入的偏差，并交付三套质量分级矩阵 | 附录 G |

**这组"消融"能说明什么**：①**数据多样性是可分析、可分轴的量**，不是形容词；②"混入野外数据"的有效性依赖**过滤与混合比例**这两个可报告的选择；③**标定质量是数据可用性的一部分**，不是附录里的细节。

## 6. 什么条件下失效

### 6.1 论文自承（附录 D Limitations and Future Work）`[精读原文]`

1. **标定仍有假阳性**：全自动三阶段流程虽然"每步都有保证"，但**仍存在错误**，作者明确希望后续改进。
2. **基座标定依赖的现成模型是在 Franka Panda 上训练的**：其**对其它机器人的零样本泛化能力"仍未可知"**（原文明说 remains to be seen）——也就是说这套自动标定管线**不能假定可直接迁移到别的本体**。
3. 作者提出的改进方向是用基础模型做机器人/夹爪分割与关键点估计以提升泛化性。

### 6.2 本文推断（非论文自述，判断用）`[推断]`

1. **单本体是硬边界**：全部数据来自 Franka Panda + 同一遥操作接口。把它当作"跨机器人数据集"使用缺乏依据；跨本体结论应回到 OXE 一类工作。
2. **"in-the-wild" 的边界是采集员可达的场景**：564 场景 / 52 建筑听起来广，但仍是**研究机构可进入的地点**（实验室、办公室、部分真实家庭），不等于任意部署环境。
3. **+"20%" 不是可搬迁的常数**：它绑定 6 个任务、特定基线、50/50 混合与过滤策略；换任务集或基线会变。
4. **成功轨迹过滤会引入分布偏移**：只保留成功轨迹意味着数据里**失败恢复的示范很少**——这与"部署需要失败恢复协议"之间存在结构性缺口（见 [失效边界专题](../topics/deployment-boundaries.md) §2.6）。
5. **数据不能替代仿真做受控实验**：真实数据无法随机化物理参数，因此 DROID 不适合回答"某个物理量变化会怎样"的因果问题。

## 7. 与同类系统 / 数据集的可判定差异（对照表带条件列）

> **不是排行榜**：每一行的可比性都受"本体是否相同、采集协议是否统一、任务是否重叠"约束。

| 维度 | **DROID**（本文） | Open X-Embodiment | BridgeData V2 | RH20T |
| :-- | :-- | :-- | :-- | :-- |
| 本体 | **Franka Panda 单一**（7DoF） | **22 本体**（跨机器人） | 单一（WidowX 类） | 多本体 |

| 场景规模 | **564 场景 / 52 建筑** | ——（跨机构汇集） | 多环境 | —— |
| 额外模态 | 三路 RGB + **深度** + **相机标定** + 语言 | 以统一格式汇总各数据集字段 | RGB 等 | —— |

**可判定差异（一句话）**：**DROID 优化的是"同一本体下的野外多样性 + 采集一致性"，OXE 优化的是"跨本体的格式统一与汇总"**；因此"用 DROID 做跨机器人实验"与"用 OXE 做单一硬件控制变量实验"都是误用。

### 7.1 与 VLA 动作表征议题的关系（重要）

DROID **与动作表征三路线（token / flow matching / diffusion head）无冲突也无贡献**：它是这些路线**共同的数据来源之一**（例如 OpenVLA 训练中曾以保守权重加入 DROID、FAST 用 DROID 做零样本高频评测、π0 预训练混合中含 DROID）。`[精读原文]`（见 [OpenVLA 分册](2406.09246-openvla.md)、[FAST 分册](2501.09747-fast.md)、[π0 分册](2410.24164-pi0.md)）

> **引用纪律**：用 DROID 支撑"数据规模 / 场景多样性 / 采集协议 / 标定管线"的结论；**不要**用它支撑策略能力或动作头优劣的结论。
