## 亮点与差异

- **① 一句话亮点**：把机器人动作**当成文本 token**、与网络规模视觉-语言数据**联合微调**同一个 VLM，从而把网页预训练的语义概念（符号、算术、多语言、人物识别）直接变成机器人策略的**涌现**能力，且不新增任何 action 专用层。
- **② 新在哪**：相对 **RT-1**（35M 专用 transformer、无 VLM 预训练）换成 3B–55B 的 PaLI-X / PaLM-E 主干并复用其权重；相对「用 VLM 做**视觉表征**（VC-1/R3M）或做**感知增强/高层规划/成功检测**（MOO、CLIPort 式两阶段）」改成 VLM **直接生成动作 token**、语言与动作共享全部权重同一损失；相对**朴素机器人数据微调**提出 **co-fine-tuning**（机器人数据 + 原始 web 规模 V-L 数据混合，机器人数据占比 50%/66%）；相对 RT-1 的**逐维 256-bin 均匀离散化**（沿用）在模型侧证明该方案可随主干规模扩展到 55B，并在 PaLM-E 上改用**覆写词表中最不常用的 256 个 token** 的方式绑定动作 token。
- **③ 证据强度**：真机评测约 **6,000 条评估轨迹**；**seen 200+ 任务（子类计数合计 208）/ unseen 280+ 任务**（Unseen Objects/Backgrounds/Environments 各分 Easy/Hard），每条指令 1–5 次；涌现能力评测用 **A/B testing 同条件对照**、每指令 5 次，三类（Symbol Understanding / Reasoning / Human Recognition）逐项打分；消融含 **5B vs 55B × {from scratch / fine-tuning / co-fine-tuning}** 与 Language-Table 仿真基准；**无开源**（基座为闭源 PaLI-X/PaLM-E，推理走 multi-TPU 云服务），单 embodiment 机器人数据（13 台同型机器人、17 个月、办公室厨房）。
- **④ 值不值得引用**：**值得，作为「动作即 token + 联合微调」路线的奠基引用与闭源上界参照**。能支撑：(a) 该路线在 5B–55B 上可行，且 co-fine-tuning 优于纯机器人数据微调（55B：63 vs 52）；(b) 涌现语义能力可被定量度量，且与纯机器人数据方法形成断崖（总平均 60/40 vs RT-1 17）；(c) 强 VLA 的判据不该是 seen 更高（91–93 ≈ RT-1 92），而是 **unseen 泛化倍数**（约 2× RT-1/MOO、约 6× 其余基线）。**不能**支撑：任何开源/可复现结论（无代码无权重、主干闭源）；新物理技能结论（作者明确模型不获得新运动能力）；跨 embodiment 结论（单本体、单环境数据）；高频控制场景（55B 仅 1–3 Hz）；行级复现（超参只在 Appendix E 给出，无训练硬件型号）。

## 1. 解决什么问题

- 机器人数据稀缺且语义覆盖面窄，而网页规模的视觉-语言预训练已具备大量语义概念与推理能力；问题是：**这些概念能否被迁移进端到端机器人控制** `[精读原文]`。
- 既有做法把 VLM 当**表征**（VC-1、R3M 式：冻结或微调视觉主干再挂策略头）或当**上层模块**（目标识别、高层规划、成功检测、单像素语义标注通道 MOO 式），动作空间与输出空间始终是另起的一套 `[精读原文]`。
- 本文提出的答案：把动作**表达为文本 token**，与语言 token 同词表、同损失、共享全部权重，"without introducing action-only model layer components"，使语言任务与动作任务在同一模型内互相增强；论文把这类模型命名为 **Vision-Language-Action (VLA)** `[精读原文]`。
- 由此提出四个研究问题（§4）`[精读原文]`：(1) seen 任务上能否保持 SOTA、并对对象/背景/环境泛化；(2) 涌现能力能否被观测与**度量**；(3) 泛化如何随参数量与训练设计变化；(4) 能否呈现 chain-of-thought 式推理。

## 2. 核心方法（关键设计 · 公式 · 关键超参）

### 2.1 动作 token 化与离散化（§3.2）

- **动作空间**：6-DoF 末端执行器位置/旋转位移 + 夹爪伸展量 + 1 个离散 episode 终止指令（terminate），共 **8 维**（原文："represented using ordinals of the discrete bins as 8 integer numbers"）`[精读原文]`。
- **离散化**：除 terminate 外所有连续维**均匀离散为 256 bins**（沿用 RT-1 / Brohan et al. 2022）`[精读原文]`。
- **字符串格式**：`"terminate Δpos𝑥 Δpos 𝑦 Δpos𝑧 Δrot𝑥 Δrot 𝑦 Δrot𝑧 gripper_extension"`，空格拼接；正文示例 `"1 128 91 241 5 101 127"` `[精读原文]`——注意该示例只列出 7 个数，与「8 integer numbers」的对应关系原文未明示 `[精读原文]`。
- **token 绑定（两个实例方案不同）** `[精读原文]`：
  - **PaLI-X**：1000 以内整数各有独立 token，直接把 action bin 映射到对应整数 token；
  - **PaLM-E**：无数字 token 表示，直接**覆写词表中最不常用的 256 个 token** 作为动作词表（作者注：这相当于一种 symbol tuning，引 Wei et al. 2023）。
- **输入格式**：相机图像 + 文本任务描述，标准 VQA 模板 `"Q: what action should the robot take to [task instruction]? A:"`（§3.2）`[精读原文]`。
- **输出约束（Output Constraint）**：机器人任务解码时只在合法 action token 上采样；标准视觉-语言任务仍输出完整自然语言词表（§3.2）`[精读原文]`。
- **目标函数**：next token prediction，作者明确其"corresponds to the behavior cloning loss in robot learning"（Appendix E）`[精读原文]`。

### 2.2 Co-Fine-Tuning：本文最关键的设计决策（§3.2、Appendix B）`[精读原文]`

- 把机器人轨迹数据与**原始 web 规模 V-L 数据**（VQA、captioning、图文交织样本）混合微调，而不是只用机器人数据朴素微调（naïve finetuning）。
- 混合配比通过**提高机器人数据的采样权重**实现：**RT-2-PaLI-X 机器人数据约占训练混合的 50%；RT-2-PaLM-E 约占 66%**（Appendix B）。
- Web 数据主体为 **WebLI：约 10B 图文对、覆盖 109 种语言**，按跨模态相似度过滤取 top 10% 得 **1B 训练样本**（Appendix B）；RT-2-PaLI-X co-fine-tune 时**不使用** Episodic WebLI。
- Language-Table 实验中 co-fine-tune 还混入 5 类预测任务：(1) 由两帧+指令预测动作；(2) 由图像帧预测指令；(3) 预测机械臂位置；(4) 预测两帧间隔 timestep 数；(5) 预测任务是否成功（Appendix B）。

### 2.3 主干、规模与超参（§3.1、§4、Appendix D/E）`[精读原文]`

| 实例 | 基座 | 规模 | lr | batch size | gradient steps |
|---|---|---|---|---|---|
| RT-2-PaLI-X | PaLI-X（ViT-22B 视觉 + 32B / 50 层 encoder-decoder，类 UL2） | 5B 与 55B 两档 | 1e-3 | 2048 | 80K（55B）/ 270K（5B） |
| RT-2-PaLM-E | PaLM-E（ViT-4B 视觉投影 + 12B decoder-only LLM） | 12B | 4e-4 | 512 | 1M |
| RT-2-PaLI-3B（仅 Language-Table 实验） | PaLI 3B（ViT-G/14 约 2B 视觉 + UL2-3B encoder-decoder） | 3B | 1e-3 | 128 | 300K |

- 其余超参（lr schedule、regularization）沿用 PaLI-X / PaLM-E 原论文（§4）；**训练硬件型号原文未给出** `[精读原文]`。
- **机器人训练数据**：沿用 RT-1 数据集——**13 台机器人、17 个月、办公室厨房环境**采集（§4）；每条轨迹带自然语言指令标注，覆盖 7 类技能（"Pick Object"、"Move Object Near Object"、"Place Object Upright"、"Knock Object Over"、"Open Drawer"、"Close Drawer"、"Place Object into Receptacle"，Appendix B）`[精读原文]`。
- **推理部署（§3.3）**`[精读原文]`：模型部署在 **multi-TPU 云服务**，机器人通过网络查询；**55B 模型 1–3 Hz，5B 模型约 5 Hz**；作者自称（发布时为）用于直接闭环机器人控制的最大模型（"largest ever, by over an order of magnitude"），同一云服务可同时服务多台机器人。

### 2.4 与 CLIPort/MOO 类路线的区分（§2 末段）`[精读原文]`

- RT-2 **不依赖受限的 2D 动作空间、不需要标定相机**；与「用 VLM 做视觉表征 / 目标识别 / 高层规划 / 成功检测」的用法不同，RT-2 让 VLM **直接生成**动作 token，统一输出空间使语言与动作任务共享全部权重。

### 2.5 Language-Table 的动作编码差异（§4.1）`[精读原文]`

- Language-Table 实验中动作编码为 `"X Y"` 文本格式，X、Y ∈ **{−10, −9, …, +9, +10}**（21 个离散值/维），表示 2D 笛卡尔 setpoint 增量——与主实验的 256-bin/8 维方案不同，说明该 token 化路线对动作空间粒度有弹性。

## 3. 数据与规模

- **真机评测总量**：约 **6,000 条评估轨迹**（§4）；默认实体机器人为 **7DoF mobile manipulator**（§4）`[精读原文]`。
- **机器人数据**：RT-1 数据集，**13 台同型机器人 / 17 个月 / 办公室厨房**，单 embodiment（§4）`[精读原文]`。
- **seen 评测集**：**200+ 任务**（picking 36、knocking 35、placing upright 35、moving 48、开关抽屉 18、抽屉取放 36，合计 **208**），沿用 RT-1 原套评测；仍变化物体摆放、一天中时间与机器人位置（§4.1）`[精读原文]`。
- **unseen 评测集**：**280+ 任务**（§4.1），以 pick-and-place 技能为主，分 Unseen Objects / Backgrounds / Environments 三类、各分 Easy/Hard（hard 环境为带显示器的办公桌，easy 为厨房水槽）；每条指令运行 **1–5 次**（Appendix F.2）`[精读原文]`。
- **涌现能力评测集**：三类指令清单（Table 3，Appendix F.2）`[精读原文]`——Symbol 1（move coke can near X/3/Y）、Symbol 2（move apple to tree/duck/apple/matching card）、Symbol 3（put coke can close to dog 等 3 条）、Math（4 条）、Logos（5 条：google/android/youtube/a search engine/a phone）、Nutrition（5 条）、Color/Multilingual（含西/德/法语共 8 条）、Celebrities（Taylor Swift / Tom Cruise / Snoop Dogg）、CelebA（person with glasses / man with white hair / brunette lady）；每指令 **5 次**（Appendix F.2）。
- **基线（均用完全相同的机器人数据，§4 Baselines / Appendix C）**`[精读原文]`：
  - **RT-1**：**35M 参数** transformer，无 VLM 预训练；
  - **VC-1**：ViT-L 视觉基础模型 + Universal Sentence Encoder 语言嵌入 + token learner + RT-1 decoder，端到端训练并解冻 VC-1（优于冻结）；
  - **R3M**：ResNet50，Ego4D 人类活动视频预训练，同样接 RT-1 decoder 并解冻；
  - **MOO**：VLM 生成单像素语义标注图通道 + RT-1 backbone（VLM 仅作感知增强模块）。

| 模型 | Seen | Unseen Obj Easy/Hard | Unseen Bg Easy/Hard | Unseen Env Easy/Hard | Unseen Avg |
|---|---|---|---|---|---|
| R3M | 45 | 32/14 | 13/9 | 0/2 | 12 |

| MOO | 75 | 58/48 | 38/41 | 19/3 | 35 |

| RT-2-PaLM-E-12B | 93 | 84/76 | 75/71 | 36/33 | **62** |

- 正文结论（§4.1）`[精读原文]`：seen 任务上 RT-2 与 RT-1 相当，其余基线更低；**unseen 泛化上 RT-2 两种实例平均相当，约 2× 优于 RT-1 与 MOO、约 6× 优于其余基线**（原文 "∼2x improvement … ∼6x better"）；PaLM-E 版在更难泛化场景更好、更易场景更差，平均打平。

### 4.2 Language-Table 仿真基准（§4.1、Table 1；开源仿真环境，5 Hz 推理）`[精读原文]`

- 条件：RT-2-PaLI-3B 用 PaLI 3B co-fine-tune（混合 5 类预测任务，§1.3 所述）；动作 "X Y" 格式；因模型小可 **5 Hz** 推理，与其余基线同频（§4.1）。
- 成功率为：BC-Zero **72±3**；RT-1 **74±13**；LAVA **77±4**；RT-2-PaLI-3B **90±10**（Table 1，成功率 ± 误差）。
- 定性：同一 checkpoint 在真机 Language Table 环境展示未见过的推动任务与新目标物体（Figure 5）`[精读原文]`。

### 4.3 Emergent 能力定量评测（§4.2、Table 5；A/B testing 同条件，每指令 5 次）`[精读原文]`

- 条件：取前两名基线 RT-1、VC-1 与 RT-2 两实例做 **A/B testing**（Fisher, 1936）在完全相同条件下依次评测以降低方差。
- 三类平均成功率（%）：
  - **Symbol Understanding**：VC-1 11 / RT-1 16 / RT-2-PaLI-X-55B **82** / RT-2-PaLM-E-12B 36（子项 Symbol 1/2/3：PaLI-X 93/60/93）；
  - **Reasoning**：VC-1 10 / RT-1 16 / PaLI-X **46** / PaLM-E 43（子项 Math/Logos/Nutrition/Color-Multilingual：PaLI-X 25/52/48/58，PaLM-E 35/56/44/35）；
  - **Person Recognition**：VC-1 13 / RT-1 20 / PaLI-X **53** / PaLM-E 43；
  - **总平均**：VC-1 **11** / RT-1 **17** / RT-2-PaLI-X-55B **60** / RT-2-PaLM-E-12B **40**。
- 正文表述（§4.2）：最佳模型超过次优基线（RT-1）**3 倍以上**（"more than 3x average success rate"）；Appendix H.2 表述为 "2x to 3x better than RT-1"——两处口径措辞不同，引用时择一并注明出处 `[精读原文]`。PaLM-E 版在 math 上反而更好，归因其预训练混合比偏视觉预训练的 PaLI-X 更擅长数学计算（§4.2）。
- **公平性脚注**（Appendix H 脚注 1）`[精读原文]`：PaLM-E-12B 原始预训练混合中含机器人图像的**高层 VQA 规划**样本，与泛化场景图像可能相似，但**不含任何低层动作**，故作者认为不影响本评测有效性。

### 4.4 Chain-of-Thought（§4.4、Figure 7、Appendix I）`[精读原文]`

- 对 RT-2-PaLM-E 变体仅**追加数百个 gradient steps** 微调（"just a few hundred gradient steps"）以增强语言与动作的联合利用。
- 数据增广：加入 "Plan" 步骤——先用自然语言描述动作目的，再接动作 token；示例 `"Instruction: I'm hungry. Plan: pick rxbar chocolate. Action: 1 128 124 136 121 158 111 255."`（§4.4）。该增广充当 VQA 数据（视觉推理）与操作数据（动作生成）之间的桥梁。
- 定性结果（Figure 7/10）：即兴工具使用（"I need to hammer a nail" → Plan: Rocks）、按状态选物（"I am sleepy" → Plan: Pick redbull can）、按颜色归拢物体等；**无量化成功率数字**。

## 5. 消融说明什么

### 5.1 规模 × 训练方案消融（§4.3、Table 6）`[精读原文]`

- 设置：只用 RT-2-PaLI-X（因 PaLM-E 结构限制，RT-2-PaLM-E 只能取特定 PaLM/ViT 尺寸组合）；比较 **5B vs 55B** × 三种训练方案 {from scratch / fine-tuning（仅机器人数据）/ co-fine-tuning}；本组去掉 seen 评测、只看泛化。

| 规模 | 方案 | Unseen Obj E/H | Unseen Bg E/H | Unseen Env E/H | Average |
|---|---|---|---|---|---|
| 5B | from scratch | 0/10 | 46/0 | 0/0 | **9** |
| 5B | fine-tuning | 24/38 | 79/50 | 36/23 | 42 |
| 5B | co-fine-tuning | 60/38 | 67/29 | 44/24 | 44 |
| 55B | fine-tuning | 60/62 | 75/38 | 57/19 | 52 |
| 55B | co-fine-tuning | 70/62 | 96/48 | 63/35 | **63** |

- 三条结论（§4.3）：(1) 大模型 from scratch 表现极差（5B from scratch 仅 9），故 55B from scratch 直接跳过未评；(2) **co-fine-tuning 优于仅机器人数据 fine-tuning**——归因于保留原始 web 数据使模型不遗忘 VLM 预训练概念；(3) **规模越大泛化越好**。
- **说明什么**：VLM 预训练权重是必要前提（from scratch 崩），但预训练权重单独不够（5B fine-tune 42 < 44 且远低于 55B），**规模与联合微调存在交互作用**——co-fine-tune 的收益随规模放大（5B 档 +2 个点，55B 档 +11 个点）`[推断]`。

### 5.2 未见直接消融、只能从对照读出的变量 `[推断]`

- **`[推断]` 动作 token 绑定方式（PaLI-X 数字 token vs PaLM-E 覆写最不常用 token）无独立消融**：两实例同时更换了基座、规模（55B vs 12B）与机器人数据混合比（50% vs 66%），因此 60 vs 40 的总平均差异不能归因于 token 绑定策略。
- **`[推断]` 动作离散精度的敏感性无消融**：主实验固定 256 bins（§3.2），Language-Table 换用 21 值/维（§4.1）同时改变了任务与模型规模，无法据此得出 bin 数结论。
- **`[推断]` 推理频率与成功率的关系无消融**：55B 1–3 Hz 与 5B ~5 Hz 的频率差异与模型规模、能力同时变化，无法分离。
- **`[推断]` 每指令 1–5 次（unseen）/ 5 次（emergent）是小样本口径**：单条指令上 ±1 次成功即使成功率波动 ±20%，故 Table 4/5 的组内平均只能看趋势，不宜当作精确点估计引用。

## 6. 什么条件下失效

### 6.1 论文自承的失效条件 `[精读原文]`

1. **不产生新动作技能**（§5 第一条 + Appendix G）：web 预训练只带来语义/视觉概念泛化，模型**不会由此获得新运动能力**；物理技能仍限于机器人数据分布内的技能（"The model's physical skills are still limited to the distribution of skills seen in the robot data"），只是以新方式组合部署。作者归因于数据在技能轴上的多样性不足，提出人类视频等新数据收集范式作为未来方向。
2. **推理成本与频率瓶颈**（§5 第二条）：55B 只能 1–3 Hz；面向高频控制时实时推理会成为主要瓶颈；建议量化与蒸馏。另一相关限制：当时可用作 VLA 基座的通用 VLM 太少（多为闭源且无微调 API），作者呼吁更多开源模型（提及 llava-vl.github.io）。
3. **Appendix G 具体失败模式**（Figure 9，Language Table 真机设置）：
   - 对**未见过的物体动力学**不泛化：笔直接滚下桌、香蕉质心远离接触点导致推动失败；作者引 Yu et al. 2016 指出推动动力学难以预测与控制，并假设需要更多样的推动动力学数据；
   - 当前数据组成与训练方法下表现差的四类情形（逐字）：**抓握物体特定部位（如把手）**；**超出机器人数据的新动作（如用毛巾擦拭、工具使用）**；**灵巧或精细动作（如叠毛巾）**；**需要多层间接推理的扩展推理**。
4. **Table 4 中的掉点**：Unseen Environments Hard 上 RT-2-PaLI-X-55B 仅 35%、PaLM-E-12B 33%（对比 Easy 63/36）；Unseen Backgrounds Hard 上 PaLI-X-55B 掉到 48（Easy 96）；R3M/VC-1 在 Unseen Environments 上几乎为 0。
5. **Table 5 中的掉点**：PaLM-E-12B 在 Symbol 2 / Symbol 3 仅 20/20（远低于 PaLI-X-55B 的 60/93）；两个 RT-2 在 Math 子类都弱（25 / 35）；VC-1 在 Symbol 3 与 Math 上为 0。

### 6.2 我们的推断（原文未直接陈述）`[推断]`

- **`[推断]` 「2×/6× 泛化」是倍数口径，不能当作绝对成功率引用**：62 vs 32（RT-1）与 62 vs 10–12（VC-1/R3M）的比值建立在各自 Easy/Hard 混合的评测集上，评测集不同则倍数会变；引用应带 unseen 平均绝对值与任务集描述。
- **`[推断]` 单 embodiment 数据限制了「VLA 通用性」的可外推范围**：机器人数据来自 13 台**同型**机器人、单一办公室厨房环境（§4），因此「跨本体泛化」不是本文证明的结论；后续开源路线改用 OpenX 跨 embodiment 数据时，数据构成差异必须标注。
- **`[推断]` 云推理是该方法形态的一部分而非实现细节**：multi-TPU 云服务 + 网络查询（§3.3）意味着该方法在离线/低网络质量场景下不可用；「1–3 Hz」同时包含网络往返与 55B 前向。
- **`[推断]` 涌现能力的度量口径对符号类任务最友好**：Symbol Understanding 上 PaLI-X 82、Reasoning 46、Person 53，跨类别落差明显；把 60 的总平均当作统一的「语义迁移强度」会掩盖类别间差异。
- **`[推断]` 与 RT-1 在 seen 上打平（91–93 vs 92）反过来说明 seen 评测已饱和**，RT-1 原套评测无法区分大 VLM 主干带来的收益；新增收益几乎全部体现在 unseen 与涌现两类评测上。

### 7.2 (a)「动作作为文本 token + 联合微调」路线成立性——**强支持** `[精读原文]`

- 动作即 token：256 bin 均匀离散、8 维动作编码为整数 token 串、与语言 token 同损失同词表训练（§3.2），无需任何 action 专用层。
- 联合微调有**正向消融证据**：Table 6 显示 55B 上 co-fine-tune 63 vs fine-tune 52、5B 上 44 vs 42；正文归因于保留 web 预训练概念、避免遗忘（§4.3）。
- 涌现能力是该路线的独有收益：Table 5 总平均 60/40 vs RT-1 17（Symbol / Reasoning / Person 三类均大幅领先），且这些概念从未出现在机器人数据中（§4.2）。
- 路线迁移性：换仿真环境 + 换机器人（Language-Table）后 3B 模型仍 90±10 超过全部基线（Table 1）。
- CoT 兼容性：加 Plan 步骤的数百步微调即可引出多阶段语义推理（§4.4），说明该路线与 LLM 推理范式兼容。

### 7.3 (b) 强弱 VLA 判据素材 `[精读原文]`

- **seen 与 unseen 的落差**：弱模型 seen/unseen 同步差（R3M 45/12），强 VLA seen 持平 SOTA（91–93 vs RT-1 92）而 unseen 翻倍（62 vs 32）——「强 VLA」的关键不是 seen 更高，而是 **unseen 泛化倍数**（约 2×/6×，§4.1）。
- **涌现语义能力**：Symbol Understanding / Reasoning / Human Recognition 三类定量评测（Table 5）是纯机器人数据方法（RT-1/VC-1 ≤20）与 VLA（40–60）之间的断崖，可作为「语义迁移强度」判据。
- **规模敏感性**：5B→55B co-fine-tune 44→63（Table 6），容量是强弱变量之一；但 5B 上 co-fine-tune 收益微弱（+2），提示「规模 × 联合微调」存在交互作用。
- **推理频率可行性**：55B@1–3 Hz、5B@~5 Hz（§3.3）——部署频率可作为「可用性强弱」的约束条件。
- **失效边界判据**：Appendix G 四类失败（特定部位抓握 / 新动作 / 灵巧动作 / 多层间接推理）可作为强弱 VLA 共同的边界测试清单。
- **评测规模口径**：约 6,000 条真机评估轨迹（§4）本身是「VLA 可信结论所需评测规模」的参考锚点；emergent 评测用 A/B 同条件框架降方差（§4.2）是可复用的评测方法论。

### 7.4 (c) 开放权重 / 256-bin 离散化路线的对照锚点 `[精读原文]`

- RT-2 证明 256 bin 均匀离散化在 5B–55B 闭源 VLM 上可行；开放权重路线（OpenVLA 等，属其他条目范围）把同一 256-bin 方案搬到开源 7B 主干，并常把 bin 边界从 min-max 改为分位数——**该对照关系本册不展开、也不引用未在本册核验的数字** `[精读原文]`。
- 成本-性能参照系：RT-2-PaLI-X-55B 需 multi-TPU 云服务、1–3 Hz（§3.3）；训练 batch 2048 / lr 1e-3 / 80K 步（Appendix E）；5B 档为 270K 步。
- RT-2 的 seen 成功率 91–93（Table 4）与 Language-Table 90±10（Table 1）是后续模型对比时可引的基线数字，但**必须同时给出本体、频率与评测集规模**。
- 数据构成差异：RT-2 为单 embodiment（13 台同型机器人、单厨房环境，§4）；跨 embodiment 数据路线与之不可直接横向比较，须显式标注。

### 7.5 对 EmbodiedVLA 条目结论的影响（小结）

- (a) 成立性：**支持**，且有消融（Table 6）与涌现能力（Table 5）双重证据；注意 co-fine-tune 在 5B 上增益微弱（+2 个点），规模是前提条件之一。
- (b) 判据：建议以「unseen 平均成功率相对机器人-only 基线的倍数 + 涌现三类成功率 + 部署频率」三元组刻画强弱 VLA。
- (c)：RT-2 提供闭源大规模端的上界参照（55B、1–3 Hz、TPU 云、80K 步 × bs2048）；开放权重 7B 路线若能在相近任务上达到可比较成功率且可本地部署，即构成对 (c) 的支持证据。
