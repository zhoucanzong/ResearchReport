# 横切专题：失效边界与部署条件

> **定位**：`report.md` 第 8 章（失效边界综述）的机制级展开。回答一个工程问题：**"什么条件下这个系统会坏"**——按类归纳，而不是逐篇复述。
> **口径**：本册把「论文自承」与「我们的推断」**严格分开**。推断一律标 `[推断]`，并用分册里的证据指出推理链。
> **本册不做选型推荐**：每条的"部署条件"是**必要条件清单**，不是充分条件。

---

## 0. 本册结论

1. **失效不是随机噪声，而是六类可命名的机制**：数据分布缺口、仿真—真机错位、延迟与频率不匹配、动作离散化误差、表征/容量瓶颈、评测与安全缺位。每类都能用分册级证据判定。
2. **"能跑"（demo 级）与"能上"（部署级）之间隔的是延迟、失败恢复与可观测性**，不是成功率——8 篇中**没有一篇**给出统一的失败恢复 / 接管协议。`[精读原文]`
3. **高频 + 高动作维是最容易同时命中多类失效的场景**：它同时压 token 序列长度（离散化）、推理延迟（采样步数）、以及数据频率混合的一致性。`[精读原文]`（FAST 的动机章）
4. **"仿真表现好"不能作为部署判据**：见 [评测与数据集册](evaluation-and-datasets.md) §2。
5. **部署条件里最常被漏掉的一项是"动作频率与推理间隔的绑定关系"**：它不是常量，而是随本体变化的（π0 的 0.8 s / 16 步 vs 0.5 s / 25 步）。`[精读原文]`

## 1. 失效的六类机制（总览）

| # | 类别 | 触发条件 | 表现 | 本专题证据 |
| --: | :-- | :-- | :-- | :-- |
| 1 | **数据分布缺口** | 目标场景/本体/任务不在训练分布内 | 语义失败：指令理解对、动作不对 | OXE 的跨本体分域结论 `[精读原文]` |
| 2 | **仿真—真机错位** | 用仿真分数替代真机结论 | 仿真过关、真机失效 | SIMPLER 的自承 + π0.5 的开放世界反证 `[精读原文]`/`[摘要级]` |
| 3 | **延迟 / 频率不匹配** | 控制频率高于推理吞吐 | 策略"看到的是过去"、动作滞后 | π0 的推理间隔与耗时 `[精读原文]` + FAST 的延迟对比 |
| 4 | **动作离散化误差** | 高频灵巧 + 逐维分箱 | 抖动、量化误差、动作不连贯 | FAST 的动机与对比 `[精读原文]`；OpenVLA 的 DROID 案例 |
| 5 | **表征 / 容量瓶颈** | 数据异构度过高，或模型过小 | 某数据域"学不会"（可观测为 token accuracy 不升） | OpenVLA 训练中移除 DROID `[精读原文]` |
| 6 | **评测 / 安全缺位** | 无统一失败恢复、越界抑制、人在环路协议 | 事故不可预期；结论不可比 | **本轮未见专用一手文献**（列入待跟踪） |

## 2. 逐类展开

### 2.1 数据分布缺口

- **可判定信号**：同一策略在 in-distribution 与 out-of-distribution 上的成功率差值。OXE 的贡献之一就是把这件事**分域量化**（小数据域 / 大数据域 / 泛化与 emergent 能力分开汇报）。`[精读原文]`（[OXE 分册](../papers/2310.08864-open-x-embodiment.md)）
- **部署条件**：必须能回答"目标本体 / 场景是否在训练分布内"；跨本体迁移需要**目标本体的适配数据**，而不是仅靠零样本。`[精读原文]` + `[推断]`
- **易被掩盖**：把"零样本可用"与"零样本达到可用水平"混为一谈——前者是能力存在，后者是性能阈值。`[推断]`

### 2.2 仿真—真机错位

- SIMPLER 自承：仿真永远是真机的不完美代理；其目标是**相对排序相关**。`[精读原文]`
- π0.5 的立场（`[摘要级]`，arXiv:2504.16054 摘要）：开放世界泛化仍需真机验证。
- **部署条件**：任何"仿真达标即可上线"的推理都不成立；仿真输出只能用于**回归检测与候选排序**。`[推断]`

### 2.3 延迟 / 频率不匹配

| 系统 | 频率相关设置 | 含义 |
| :-- | :-- | :-- |
| π0 | 20 Hz 本体：每 0.8 s 推理（执行 16 步）；50 Hz 本体：每 0.5 s 推理（执行 25 步）；on-board 73 ms（RTX 4090） | 推理代价与硬件、本体绑定 |
| FAST | 对比 FAST 与逐维分箱、以及 stream 式 vs 动作分块解码的延迟差异 | 吞吐决定可用频率 |
| Diffusion Policy / RDT-1B | 多步去噪采样 → 延迟随步数增长 | 高频场景需要调度器加速 |

> **部署条件**：必须给出"控制频率 + 推理间隔 + 推理耗时 + 硬件"四元组；只给"实时"这类形容词的结论不可用。`[精读原文]` + `[推断]`

### 2.4 动作离散化误差

- 逐维分箱在高频灵巧数据上表现差（FAST 的核心动机）。`[精读原文]`
- OpenVLA 训练中 DROID 子集的 action token accuracy 持续偏低，最终**在训练最后 1/3 阶段移除 DROID**——这是"数据学不会"的**可观测证据**，而不是修辞。`[精读原文]`（[OpenVLA 分册](../papers/2406.09246-openvla.md) §3.3 + Table 3 脚注）
- **部署条件**：动作维 × 频率 × 分箱数的组合必须与 tokenizer 的压缩能力匹配；否则 token 序列成为瓶颈。`[推断]`

### 2.5 表征 / 容量瓶颈

- **可观测代理指标**：训练过程里某数据域的 token accuracy 是否收敛。`[精读原文]`（OpenVLA）
- **部署条件**：异构数据混合需要**数据域级的训练监控**，否则"某个域没学会"在上线前不可见。`[推断]`

### 2.6 评测 / 安全缺位（本轮最薄弱的一环）

| 缺什么 | 后果 |
| :-- | :-- |
| 失败恢复协议（失败后如何重试 / 回退） | 长时程任务中断即失败 |
| 越界 / 危险动作抑制 | 无统一判据，靠人工围栏 |
| 人在环路接管与交接语义 | 无标准接口，责任不可界定 |
| 安全评测报告项 | 无法横向比较"安全性" |

**状态**：本轮**未检索到**针对 VLA 安全与失败恢复的专用一手文献——**不写结论，列入待跟踪**。`[受限核验]`

## 3. 部署条件清单（可逐条勾选）

> 每条都是**必要条件**。缺任一条，该系统的成功率数字就不构成可部署性证据。

| # | 条件 | 为什么必须 | 验证方式 |
| --: | :-- | :-- | :-- |
| 1 | 目标本体的**适配数据**存在（或明确接受零样本） | 跨本体迁移的边界 | 分域评测，而非合并汇报 |
| 2 | **控制频率 + 推理间隔 + 推理耗时 + 硬件**四元组已测 | 延迟不匹配是首要工程失效 | 实测，不看论文叙述 |
| 3 | **动作 tokenizer / chunk 长度**与频率匹配 | 离散化与 chunk 是频率的函数 | 复现 tokenizer 的压缩率 |
| 4 | 训练中**逐数据域的收敛监控** | 掩盖"某域没学会" | token/action accuracy 分域曲线 |
| 5 | 评测**六要素齐备**（见评测册 §1） | 否则数字不可比、不可继承 | 逐条核对 |
| 6 | **失败恢复 / 接管**协议已定义 | 长时程任务必然遇到失败 | 显式接口 + 演练 |
| 7 | **许可合规**：数据/权重可再分发 | 否则无法交付第三方 | 见 [MANIFEST.md](../sources/MANIFEST.md) |

## 4. 长时程任务的特有失效（与短任务的差别）

短任务（单次抓放）的失效是**局部**的：失败了重试一次即可。长时程任务把失败**复合**起来：

| 机制 | 为什么长时程更糟 | 本专题证据 |
| :-- | :-- | :-- |
| **时序漂移** | action chunk 开环执行期间环境已变；chunk 越长，漂移越大 | π0 每 0.8 s / 0.5 s 重新推理并在 chunk 内开环执行固定步数 `[精读原文]` |
| **误差复合** | 阶段 k 的偏差成为阶段 k+1 的输入分布外样本 | π0 / DROID 的多阶段任务（如 Cook Lentils、Put Apple in Pot）`[精读原文]` |
| **无恢复示范** | 数据多为成功轨迹 → 模型没见过"从失败中恢复" | DROID 训练**剔除标记为不成功的轨迹** `[精读原文]`（[DROID 分册](../papers/2403.12945-droid.md) §2.2） |
| **无中间成功判据** | 只有最终成功/失败，无法定位是哪一阶段退化 | 各论文均报任务级成功率，不报阶段级分布 `[推断]` |

**推论 `[推断]`**：长时程部署的必要条件不只是"任务成功率够高"，还包括**阶段级可观测性**（能判断当前进行到哪一步）与**恢复策略**（失败后回到哪一个已知状态）。本轮 8 篇**均未给出**这两项的统一方案。

## 5. 失效模式的可观测信号（用于上线前自检）

> 这些信号的作用是在**上线前**发现失效，而不是在上线后解释失效。

| 信号 | 观察窗口 | 若异常意味着 |
| :-- | :-- | :-- |
| **逐数据域的动作 token / action accuracy 曲线** | 训练期 | 某个数据域"没学会"（OpenVLA 移除 DROID 的可观测依据）`[精读原文]` |
| **推理耗时 P50 / P95 vs 控制周期** | 部署期 | 延迟挤占控制余量 → 类型 3 失效 |
| **action chunk 内位置漂移（开环段首尾误差）** | 部署期 | 时序漂移超出 chunk 承受范围 |
| **指令跟随的对照测试**（换指令是否改变行为） | 上线前 | 语言条件化实际未生效（退化为任务 ID 策略） |
| **分布外变体通过率**（加干扰物 / 换物体 / 换视角） | 上线前 | 泛化能力不足，属类型 1 失效 |
| **失败后的重试成功率** | 部署期 | 无恢复能力；长时程任务会复合失败 |

**用法**：任一信号缺失，就意味着该系统的"成功率"数字**不足以预测其部署表现**。

## 6. 物理与接触层面的失效（视觉观测覆盖不到的部分）

- 本轮 8 篇的观测都以 **RGB（部分含深度）** 为主；**力/触觉信息基本不在条件里**（DROID 采集含深度，但策略侧评测只用两台外部相机 RGB）。`[精读原文]`
- **推论 `[推断]`**：因此以下失效在数据与判据层面**不可见**：接触力过大导致物体损坏、柔性物体形变失败、滑移、卡死。论文的成功率**不区分**这些物理成因——它们都被计入"失败"。
- **对上线的含义**：若任务涉及易碎物、柔性物或高精度插装，必须**额外**补力/触觉通道与对应的安全判据；仅靠本轮 8 篇的协议无法覆盖。
