# 横切专题：评测与数据集（真机 vs 仿真、协议、规模与许可）

> **定位**：把「为什么 VLA 的成功率数字不能直接横比」和「数据到底从哪来、能不能用」做成**可逐条执行的清单**。这是 `report.md` 第 5、6 章（评测、数据）的机制级展开，也是引用任何跨系统数字前的检查表。
> **本册不做排行榜**：所有对照表**带条件列**（本体 / 频率 / 任务数 / trial 数 / 协议 / 评测方），任何一行都不得脱离条件被单独引用。
> **证据口径**：8 篇精读分册内的数字标 `[精读原文]` 并给出分册链接；未精读的外部对象标 `[摘要级]`（官方摘要 / 官方页）或 `[受限核验]`。**未确证的进第 7 节，不写进结论。**

## 0. 本册结论

1. **真机与仿真不是替代关系，而是两类不同的证据**：真机成功率是**直接部署证据但复现成本较高**（需报告初始条件、物体、本体和人工评分的一致性）；仿真可复现、可并行，但**保真度受限**。`[精读原文]`（[SIMPLER 分册](../papers/2405.05941-simpler.md)）
2. **SIMPLER 的主张被精确限定为「相对排序相关」，不是「绝对分数可替代」**：其正文明确"a simulator will always be an imperfect proxy for the real world"，目标是让策略 A 优于 B 的**排序**在仿真中保持，而不是复现真机的成功率数值。`[精读原文]`
3. **反方证据同为一手**：π0.5 以真机开放世界泛化为目标，说明"仿真里表现好"与"真机能泛化"之间仍有实质落差。`[摘要级]`（arXiv:2504.16054 摘要 + 官方博客）——与上条**不是矛盾**，而是各自限定在不同问题上（排序 vs 绝对泛化）。
4. **评测协议本身是最大的不可比来源**，而不仅是模型差异：同一模型在**不同本体、不同控制频率、不同每任务 trial 数、是否含腕部相机、是否算部分分**下的成功率是不同量纲。`[精读原文]`（[OpenVLA](../papers/2406.09246-openvla.md)、[FAST](../papers/2501.09747-fast.md) 分册）
5. **数据侧的三个真问题**：①规模从哪来（真机遥操作 vs 跨机构汇集 vs 仿真合成）；②**动作空间与控制频率是否统一**（同一个数仓里 3 Hz 与 50 Hz 混存）；③**许可与可再分发性**（arXiv 默认许可不授予再分发权）。`[精读原文]` + 许可核验（见 [MANIFEST.md](../sources/MANIFEST.md)）
6. **本册的判定口径**：一个 VLA 数字只有在**六要素齐备**时才允许写入"可比"；缺一项就写"**在 X 条件下达到 Y，暂不可与 Z 比较**"。

## 2. 真机 vs 仿真：能力边界对照（带条件）

| 维度 | 真机评测 | 仿真评测 | 本专题证据 |
| :-- | :-- | :-- | :-- |
| 可复现性 | **低**：场景/摆放/光照/硬件漂移不可控 | **高**：同 seed 可重放、可并行 | `[精读原文]`（SIMPLER 的动机章） |
| 证据强度（对"能否部署"） | **高**：是唯一能回答"真机行不行"的证据 | **中低**：只能回答"排序是否一致" | `[精读原文]`（SIMPLER §I 自承 + π0.5 的开放世界结论） |
| 成本 | 高（人力、场地、机器人机时） | 低（但环境构建本身有一次性成本） | `[精读原文]`（SIMPLER 的轻量环境构造主张） |
| 保真度要求 | — | **不需要**精确数字孪生，只需缓解**控制差异**与**视觉差异** | `[精读原文]`（SIMPLER：控制侧离线系统辨识 + 视觉侧 matching / variant aggregation） |
| 典型失败模式 | 环境与评分条件未控制时，结论难以复验 | 仿真里过关、真机失效（视觉/接触/摩擦差异） | `[精读原文]` + `[摘要级]`（π0.5） |
| 可否做大规模消融 | 通常不可（样本少） | 可以 | `[精读原文]`（OpenVLA 的 LIBERO 500 trials × 3 seeds / 套件） |

### 2.1 一条被反复误读的结论

SIMPLER 的"强相关"**不是**"仿真成功率 ≈ 真机成功率"。原文口径是：

> 目标不是 1:1 复现真机成功率绝对值，而是**相对性能**强相关——若策略 A 在真机上优于 B，仿真中应保持同一排序。`[精读原文]`

**推论（本文推断 `[推断]`）**：因此 SIMPLER 类环境正确的用法是**用它做相对筛选与回归检测**（候选策略排序、改动是否退步），**不能**把仿真分数当作真机成功率的上界或代理值写进结论。

### 2.2 仿真作为训练环境 ≠ 仿真作为评测环境

| 用途 | 代表 | 关键差异 |
| :-- | :-- | :-- |
| 仿真**训练/合成数据** | 仿真平台 + 规则物理引擎（本条目 R6，仅作环境引用） | 关注**数据量与多样性**，容许保真度换规模 |
| 仿真**评测**（real→sim） | SIMPLER | 关注**排序相关性**，必须与真机成对采集 |
| 世界模型当**训练/评测环境** | 见 `WorldModels` 条目章 5/6 | 交付物不同，归 `WorldModels`（本条目只登记接口） |

> **归属提醒**：评测环境与数据集**本身**既非 VLA 也非 WorldModels（本条目 `report.md` 规则 R6），只作"数据与评测环境"引用。

### 3.1 动作空间与频率**不统一**是数据侧的第一大坑

- 同一个"数仓"里，不同子集的控制频率与动作空间**本就不同**：OXE 汇集了不同本体的数据，频率从个位数 Hz 到 50 Hz；FAST 的动机正是"逐维逐时刻分箱在**高频**灵巧数据上表现差"。`[精读原文]`
- π0 的推理间隔按频率分档：20 Hz 的 UR5e/Franka 每 0.8 s 推理一次（执行 16 步），50 Hz 的机器人每 0.5 s 一次（执行 25 步）。`[精读原文]`
- **推论 `[推断]`**：把不同频率的数据直接混合训练时，"一个动作 token 代表多少秒"这件事在子集之间是**不一致**的；这就是为什么动作 tokenizer / action chunk 频率本身是一个需要单独报告的超参。

### 4.1 成功判据是否需要人工

- 本轮 8 篇中，**真机成功率均依赖人工判定或人工布置初始条件**——这增加了复验成本，需要标准化布置与评分；不能据此断言真机实验不可复现。`[精读原文]`
- 仿真侧（LIBERO 一类）可自动判定成功，但**自动判据的语义与真机语义不同**（仿真里"任务完成"由状态检查器定义）。`[精读原文]`（OpenVLA 的 LIBERO 复现章）
- **推论 `[推断]`**：报告任何成功率时，**"成功由谁判定、判据是什么"**应与数字同列；只给百分比的引用是不可核的。

### 4.2 跨系统可比性的三条硬规则（本条目约定）

1. 不同基准的分数**不得横向比较**，除非明确说明**本体、观测、动作空间、控制频率、评测协议**一致；
2. 引用任一 VLA 成功率**必须同时给出**基准 / 本体 / 评测协议三要素（建议再加频率与 trial 数）；
3. 仿真结果只能作**相对排序**参考，**不能**作真机绝对性能的代理。
