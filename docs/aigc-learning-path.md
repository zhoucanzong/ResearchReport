# AIGC 学习地图：从表示到可控生成

这份地图帮助读者在图像、视频、音频、3D 与数字人专题之间建立共同问题框架。它不是把所有媒介归成一种模型：各媒介的表示、时间结构、控制目标和有效性判据不同，下面的路线只说明哪些问题可以互相启发，具体机制以各专题的论文精读为准。

## 先用五个问题读生成系统

```mermaid
flowchart LR
    A[表示：模型接收和生成什么] --> B[目标：如何定义生成分布]
    B --> C[条件：文本/参考/结构信号如何进入]
    C --> D[媒介约束：空间/时间/身份/几何]
    D --> E[评测：哪些失败被测到]
```

1. **表示是什么？** 图像可能是离散视觉 token 或 VAE latent；视频还要压缩时间；音频可用波形、频谱或神经 codec token；3D 则可能输出点云、隐式场、Gaussian 或 mesh。表示决定生成器要预测多长的序列，以及解码器能恢复哪些细节。
2. **模型的生成目标是什么？** 自回归、扩散去噪、Flow Matching 和混合式预测有不同的生成顺序与计算路径。Transformer 是骨干选择，不能单独说明目标；“DiT”指 Transformer 去噪器，不是与扩散并列的生成目标。
3. **条件如何进入模型？** 文本、参考图、掩码、姿态、旋律、音频片段、时间戳和 3D 约束传递的信息不同。条件“可输入”不等于模型能稳定满足条件，也不说明多个条件冲突时谁优先。
4. **媒介带来什么额外约束？** 图像要求对象/属性/空间关系正确；视频要持续身份、动作和事件状态；音频要兼顾声学细节与时间/歌词结构；3D 要在未见视角保持几何一致并产出可用资产；数字人还要协调身份、口型、表情和身体动作。
5. **评测实际测了什么？** 单帧画质、文字/对象计数、跨帧一致、歌词可懂、音画同步、几何精度和资产可编辑性不是同一指标。论文分数只能支持它实际覆盖的任务、样本和评价协议。

## 推荐学习路线

以下路线按概念依赖安排阅读顺序，不表示研究历史从图像单向演进到音频、视频或 3D；这些媒介有并行发展的技术路线。

### 路线一：先建立生成机制，再学习控制与编辑

推荐顺序：[图像生成综述](../AIGC/ImageGeneration/report.md) → [扩散模型](../AIGC/DiffusionModels/report.md) → [DiT 架构](../AIGC/DiT/report.md) → 按需求进入[可控生成](../AIGC/ControllableGen/report.md)或[图像编辑](../AIGC/ImageEditing/report.md)。

这条路线依次回答：图像如何表示和生成、扩散轨迹/采样解决什么、Transformer 如何实现去噪、条件控制如何改变生成过程，以及编辑时如何同时满足“改目标”和“保留输入”。读到这里应能区分模型架构改进、条件接口改进和评测变化。

### 路线二：从静态图像走向时间连续的生成

推荐顺序：[视频生成](../AIGC/VideoGen/report.md) → [音频与音乐生成](../AIGC/AudioGen/report.md) → [数字人与 Avatar](../AIGC/AvatarGen/report.md)。这是为了先理解时间序列，再理解声学条件和音画/动作耦合，不表示音频生成历史从视频生成派生。若关心动作如何控制未来画面、视角和相机，继续读[交互式世界模型综合](../WorldModel/WorldModels/topics/interactive-world-models.md)，并区分可控视频 rollout 与真实机器人闭环。

视频把生成对象扩展到时空 latent 和长序列；音频增加 codec、韵律、事件顺序与长程音乐结构；数字人把视觉身份、动作变量和音频条件放进同一输出过程。视频与音频可以共同生成，但“音视频同步”不等于语义和动作都正确；Avatar 的口型同步也不能代表整段动作自然或身份稳定。

### 路线三：从 2D 先验走向三维几何与可用资产

先读[图像生成](../AIGC/ImageGeneration/report.md)理解 2D 视觉先验，再读[3D 生成](../AIGC/3DGen/report.md)比较 2D score 蒸馏、直接生成 3D 表示、多视图生成后重建和 shape latent。关键转折是：多视角看起来都合理，并不自动保证几何正确；可渲染也不等于拓扑、材质和编辑性都适合作为下游资产。

## 跨媒介比较时不要混为一谈

| 比较问题 | 可以共用的思考方式 | 媒介特有的判据 |
| :-- | :-- | :-- |
| 压缩表示 | 比较压缩率、信息损失和解码成本 | 图像细节/文字；视频快速动作；音频瞬态/歌词；3D 几何和拓扑 |
| 条件遵循 | 判断提示或参考信号是否逐项落实 | 对象空间关系；镜头/动作；歌词与声学时间；身份/姿态；几何约束 |
| 长程一致性 | 追踪生成历史中状态是否漂移 | 视频主体/场景；音乐段落；数字人身份/动作；持续重建的 3D 结构 |
| 评价有效性 | 检查指标与任务目标、评价器偏差 | 人类偏好、感知指标、同步、3D 几何精度、可编辑性 |

共享 Transformer、DiT、codec 或 latent 这些术语，不能证明两个系统使用相同生成目标或训练配方。跨媒介借鉴时，应先找到相同的瓶颈，再说明迁移了哪个机制、原论文的证据是否覆盖新媒介。

## 学习时的证据边界

- 模型卡和产品演示能说明公开输入/输出和使用条件；它们不能补全未公开的骨干、训练数据或推理机制。
- 对闭源系统，把“已披露”“论文提出”“外部推测”分开写；不能把研究积累或产品迭代顺序写成已证实的架构继承关系。
- 生成速度、分辨率、时长、参数量只在能解释具体设计取舍时保留，并注明论文版本、模型、任务、硬件或评价条件。
- 实验数字默认引用作者报告结果；这份图书馆不要求逐项复算或复现。把时间用于理解方法、论文关系和失败条件。
