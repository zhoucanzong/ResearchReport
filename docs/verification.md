# 证据与发布核验

本页说明如何判断研究结论是否有足够依据，以及如何检查图书馆改动。它不要求为每篇论文建立一份核验日志。项目规范见 [`team.md`](team.md)；旧迁移和构建记录保留在[历史档案](archive/verification-history-2026-10.md)，其中规则不再适用。

## 研究结论

1. **理解原文**：阅读支撑主要判断的官方原文或固定版本源码，解释研究问题、机制、设计取舍及论文关系。
2. **解释证据与边界**：将核心判断与相关实验、对照或消融相连，说明其适用条件、失效边界和开放问题；证据有限时收窄结论。
3. **区分证据类型**：标明这是论文作者报告、原文/源码直接支持，还是本次确实运行所得。静态源码阅读和存在的测试不能写成运行时证明。

数字默认引用论文报告的结果。来源位置、必要条件及进一步核查的触发条件统一遵循 [`team.md` 的“证据与引用”](team.md#证据与引用)，本页不另设逐项数字检查或复现实验要求。验证服务于阅读理解和主要判断的可追溯性；例行搜索、下载、缓存管理不写入正文。

## 文档与站点检查

按改动范围运行相应检查：

- 新增或移动专题后，运行 `python3 scripts/library_index.py --repo-root . --out-root . --write-stats --check-links`，检查条目唯一归类和生成链接。
- 修改 Markdown、导航或门户后，运行 `.venv-mkdocs/bin/mkdocs build --strict`；关注本次改动引入的断链或渲染错误。
- 只在相关行为或生成逻辑改变时运行针对性测试。低影响的说明文字修改不要求为覆盖率额外编写测试。

本页只记录方法。每次改动的临时输出留在本地工作记录；只有能帮助后续读者理解内容边界、且不宜放进条目的实质证据才长期保留。避免复制整份命令输出、重复数字表或本机缓存校验清单。
