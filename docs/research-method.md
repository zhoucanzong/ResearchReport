# 阅读与证据说明

ResearchReport 汇集模型综述、论文分册和开源代码分析。阅读时，应把“作者报告的结果”“对原文或源码的核验”和“独立运行复现”分开看待；一个链接、一个分册或一张表都不能单独证明结论成立。

## 从哪里开始

- 先读条目的范围和结论，确认它回答的问题与自己的需求一致。
- 对具体机制、实验和反例，沿链接进入论文分册或代码专题。
- 引用数字前，回到对应的论文版本、表格或源码行；检查正文是否保留了原来的条件。
- 遇到待核或受限核验标记，应连同限制一起引用，避免把它改写成确定结论。

## 证据标签代表什么

| 标签或措辞 | 可以说明 | 不能据此推出 |
|---|---|---|
| 精读原文 | 报告记录了对一手正文或源码的阅读与定位 | 所有句子已复核、作者结果已独立复现 |
| 摘要级 | 核对了题录、摘要或官方页面的有限信息 | 完整训练配方、消融和隐藏实现已经公开 |
| 二手 | 可作为检索线索或背景材料 | 原始数字和因果解释已经成立 |
| 受限核验 / 待核 | 存在明确的来源、版本或条件缺口 | 可以用常识填上尚未获得的证据 |
| 研究推断 | 基于已列证据作出的解释或假设 | 作者原文或代码已经直接证明 |

标签应约束具体主张。主报告读过，不代表所有引用论文都读过；函数名存在，不代表所有调用路径都正确；没有报错，也不等于性能与质量相同。

## 怎样读一个性能数字

至少同时核对模型或 checkpoint、数据集与 split、指标定义、输入输出预算、硬件、软件版本及对照方法。Agent 还需说明工具权限、环境、重试次数和评分方式；服务系统还需说明并发、排队及延迟约束。

例如准确率从 80% 变为 78%，是下降 2 个百分点、相对下降 2.5%。这是不同的描述，不能统一简称为“下降 2%”。论文中的最高加速也不能直接换成目标业务的平均收益。

跨任务、跨硬件或跨模型的配置差异不是受控消融。若要解释某个机制的贡献，应检查是否只改变该因素，以及误差、重复次数和反例是否被保留。

## 怎样读代码分析

一条完整运行路径应解释入口、核心交接、状态归属和输出或副作用。固定 commit 的文件与行号让读者能够复查；版本号、移动分支和未保留的临时目录不一定能唯一标识原来读过的代码。

静态源码阅读可以支持某个分支的行为解释，但不能替代设备实测、完整故障注入、数值分布检验或跨平台验证。存在测试文件，只能说明测试契约存在；只有实际运行并记录环境与结果后，才能说本次测试通过。

## 怎样理解当前覆盖

各条目经历不同批次的写作与复核，证据密度并不相同。专题目录齐全、篇幅较长或机械审计零告警，均不作为整篇通过的依据。

优先补齐的是错误的比较、无条件数字、缺失的来源版本、方法解释和失效边界。可以为讲清问题而拆分文档，也可以删除无法支持的推演；增加长度本身不代表增加了证据。
