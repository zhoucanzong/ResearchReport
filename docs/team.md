## 规则
1. **触发**：仅被点名或被指派者响应；没任务不唤醒。
2. **流水线**：写 → `research/<topic>-<作者>` 分支 → 图图 merge 到 `main`（无冲突 fast-forward；有冲突图图解，仅内容语义不明时回问作者）。
3. **单写者**：一个目录同一时间只有一个写者；入库 / 索引 / 统计更新由图图独占。
4. **门禁**：合入 `main` 前全仓链接回测 0 失效（相对 + 指向 GitHub 的绝对链接）；统计数字与实测一致（或注明由脚本刷新）。
5. **派单格式**：目标 / 产出物 / 验收标准 / 交付方式 / 状态（由泡泡(Bot) 维护）。
6. **条目定义**：**条目 = 主文档**。当前实现口径为「条目 = `report.md`」——每个 `<topic>-research/` 目录一份；同目录的其它 `.md`（分册、`plan.md`、`notes/`、`raw-extracts/`、`sources-index.md`、`knowledge-graph.md`）是它的**子文档**。`README.md`（根 / 子库 / `scripts/`）、`docs/*.md` **不算条目**。front-matter 契约（`type` / `domain` / `subject` / `upstream`（代码类带 `@commit`）/ `date` / `evidence` / `status`）已定但**当前填充 0 份**，索引必须在无元数据时优雅退化。索引由脚本生成，人不手改。
7. **统计口径**：**脚本落地前**，内容写者随改动同步自己那部分并注明"人工维护"；**脚本落地后**（`scripts/library_index.py --write-stats` 已可用），统计数字一律由脚本产出、图图解，写者不再手改。`docs/statistics.md` 与根 `README.md` 的统计数字以 `index/stats.json` 为唯一真值。
8. **写权限**：Grant 的 `orchestratorWrite` 不是开关；会话直写被拒（`Operation not permitted`）时，走 `create_assignment` + 该目录 grant（Assignment 侧权限 `workspace-write`、cwd = 仓库目录，实测可 commit / push）。

## 原文与引用规约（Sources & Citations）

**入库（版权安全的部分）**：
- ✅ `sources/MANIFEST.md`——每条目的**馆藏地图**：`arXiv ID` + 版本 + 日期 + `license` + 去哪找原文（可选：缓存路径、行号锚点）。
- ✅ `papers/*.md`——**我们自己的精读分册**（提炼的方法 / 数字 / 条件 / 失效边界），是"我们的综述"，可检索、可 diff、可被索引。
- ❌ **论文全文（PDF 或 markdown）一律不入库**——版权不因格式豁免；且公式/图表在转换中会丢。

**缓存（可选、不入库、不强制）**：只在需回看原公式/原图时用；优先 arXiv HTML → LaTeX 源码 → PDF 兜底。**缓存是工具，分册才是资产**。

**引用格式**：默认「章节 / 标题 + 引用块」；若有缓存版原文可加 `行号`（便于机器核验"引了却未落地"）。

**未核实不入库**：仅摘要支撑的内容标 `[摘要级]` / `[⚠️受限核验]`，不许升格。

## 深挖批次标准（Deep-dive Spec）

**先筛选，后精读（宁少勿滥）**：
- 入选门槛（至少满足其一）：提出新机制 / 新范式 ｜ 首次在某能力上成立并给规模证据 ｜ 结论被广泛引用或成基线 ｜ 证伪 / 纠正已有共识；
- 淘汰标准（命中其一即不写分册）：① 增量调参无新机制 ② 只在玩具设置验证或无消融 ③ 已被后续取代 / 结论被推翻 ④ 与本条目主题仅擦边 ⑤ 拿不到正文（只能摘要）；
- 被淘汰的**留痕**：`report.md`「选文说明」或 `sources/CANDIDATES.md` 记 **候选池 N 篇 / 入选 M 篇 / 排除清单 + 一句话理由**（以后不重复筛）。

**每篇分册开头固定「亮点与差异」四行**：① 一句话亮点（最核心贡献）② 新在哪（相对已有工作的具体差异）③ 证据强度（实验规模 / 可复现性 / 是否小设置）④ 值不值得引用。读者 30 秒知道值不值得看，其余章节展开七问。

**体量（下限红线，上限不设——写长就拆文件）**：
- `report.md`（入口 / 结论 / 谱系 / 判据 / 失效边界综述）：**≥600 行**
- `papers/*.md`（逐篇精读）：**入选 5–8 篇**（下限 5、上限 8，按价值筛、不硬凑；行数分档：短文 100–150 / 常规 200–300 / 大系统 300–500，必要时拆多文件）
- `topics/*.md`（横切专题）：**≥3 篇 × 150–300 行**
- 条目总量 **≈≥2,400 行**（`report ≥600` + 入选分册 + topics；**以"讲清楚"为准，不靠行数凑**）

**七问判据（真验收标准，不是行数）**——读完每篇能答上：1. 解决什么问题？2. 核心方法（关键设计 / 公式 / 关键超参）？3. 数据与规模？4. 主要结果（带条件）？5. 消融说明什么？6. 什么条件下失效？7. 与同类系统的可判定差异？**七问答全 = 讲明白了**（哪怕 150 行）；**答不全 = 200 行也是空的**。

**密度红线（防堆行数）**：每 200 行 ≥ 5 处带条件的具体数字（数据集 / 设置 / 硬件 / 版本）+ ≥ 1 张带条件列对照表；每篇有独立失效边界段；分册与主报告不得大段重复；精读占比 ≥60%；仅摘要支撑的标 `[摘要级]` / `[⚠️受限核验]`，不许升格。

**验收（机器可查）**：文件 / 行数分布、数字密度、表格数、精读占比、重复段落指纹、**引用与正文对账**（引了却未落地）、**候选 / 排除清单齐备**。
