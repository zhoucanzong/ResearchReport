## 1. 概述

视频生成（Video Generation）是生成式 AI 领域最具挑战性的任务之一。与静态图像生成不同，视频不仅需要保证每一帧的空间质量，还必须维持时间维度上的连贯性、运动合理性和长期一致性。从 2022 年的级联扩散模型到 2026 年的统一多模态视频 DiT，视频生成技术在短短四年间经历了从"能生成"到"生成得好"再到"生成得高效"的跨越式发展。

本报告系统梳理视频生成技术的架构演进路径，核心线索是：**如何将原本为 2D 图像设计的扩散模型（Diffusion Model）扩展到 3D 时空域，并最终演化为专门化的 3D DiT（Diffusion Transformer）架构**。这一演进不仅涉及模型结构的重新设计，还包括 VAE 压缩、位置编码、时序注意力机制、训练策略等一系列关键技术的突破。

报告涵盖以下核心内容：
- 从 Make-A-Video 到 Sora 的架构范式转变
- 3D DiT 的核心设计思想与实现细节
- 2025-2026 年主流视频生成模型的技术特点
- 关键架构技术（3D VAE、RoPE、长视频生成等）
- 评测基准与未来挑战

## 3. 从图像到视频的架构演进

### 3.1 早期视频生成 (2022-2023)：级联扩散模型

#### 3.1.1 Make-A-Video (Meta, 2022)

Make-A-Video 是早期视频生成的代表性工作，核心思想是**将文本到图像（T2I）的能力扩展到文本到视频（T2V）**。由于视频数据远少于图像数据，Make-A-Video 采用"先训练图像模型，再扩展到视频"的策略。

**架构设计**：
- **基础模型**：文本到图像扩散模型，生成低分辨率（64×64）视频帧
- **超分模型**：将 64×64 提升到 256×256
- **插帧模型**：在关键帧之间插入中间帧，提升帧率
- **时序超分**：进一步提升时间分辨率

**局限**：
- **计算昂贵**：需依次运行多个扩散模型，推理成本高
- **时序一致性差**：各帧独立生成后再插帧，运动不连贯、闪烁明显
- **质量瓶颈**：误差在级联过程中累积

#### 3.1.2 Imagen Video (Google, 2022)

Imagen Video 采用类似的级联扩散思路，但规模更大：
- 共使用 **7 个扩散模型** 级联
- 基础模型生成 24×40 分辨率视频
- 通过空间超分和时间超分逐步提升到 1280×768
- 引入 **v-prediction** 参数化方式，提升生成稳定性

**关键局限**：级联架构的时序建模能力弱，无法捕捉复杂的长期运动模式。

### 3.2 Latent Video Diffusion (2023)：潜空间扩展

#### 3.2.1 核心思想

Latent Video Diffusion 的核心突破是：**不再在像素空间直接做视频扩散，而是先在潜空间（Latent Space）进行压缩表示，再在潜空间执行扩散过程**。这一思想继承自 Latent Diffusion Model (LDM)，将 2D 图像的潜空间扩展到 3D 时空潜空间。

#### 3.2.2 Stable Video Diffusion (SVD, 2023)

SVD 是 Latent Video Diffusion 的开源代表，其架构设计如下：

**VAE 扩展**：
- 将图像 VAE 的 2D 卷积扩展为 **3D 卷积**（空间 2D + 时间 1D）
- 时序维度压缩：将 T 帧压缩为潜空间中的 T' 帧（通常 T' = T/4）
- 空间维度压缩：保持 8×8 的空间压缩率

**U-Net 时序化**：
- 在预训练的图像 U-Net 中**插入时序层（Temporal Layers）**
- 时序层包括：1D 时序卷积（Temporal Conv）和时序注意力（Temporal Attention）
- 空间层保持预训练权重不变，仅训练时序层
- 这种"冻结空间、训练时序"的策略有效利用了大规模图像预训练知识

**时序建模方式**：
- 在 U-Net 的每个分辨率层级插入时序注意力
- 时序注意力沿时间轴计算，捕捉帧间依赖
- 使用 **3D 全注意力（3D Full Attention）**：同时关注空间和时间维度

**局限**：
- U-Net 的归纳偏置（Inductive Bias）较强，对长视频的扩展性有限
- 时序注意力计算复杂度为 O(T²)，长视频时内存爆炸
- 生成质量受限于 U-Net 的表达能力

### 3.3 DiT 视频化 (2024)：Transformer 取代 U-Net

#### 3.3.1 核心问题：视频 = 超长 Token 序列

DiT（Diffusion Transformer）在 2023 年由 Peebles & Xie 提出，将图像扩散中的 U-Net 替换为 Transformer。将 DiT 扩展到视频时，面临的核心挑战是：

**Token 数量爆炸**：
- 一张 256×256 的图像，Patch Size=16，Token 数 = (256/16)² = 256
- 一段 5 秒、24fps、512×512 的视频，Token 数 = (512/16)² × 120 = 122,880
- 视频 Token 数量是图像的 **480 倍**

这一挑战直接决定了 3D DiT 的核心设计：如何高效处理超长时空 Token 序列。

#### 3.3.2 3D DiT 架构设计

**空间 Patchify + 时序注意力**：
- **空间维度**：将每帧图像切分为空间 Patch（如 16×16），每个 Patch 是一个 Token
- **时序维度**：将所有帧的空间 Patch 按时间顺序排列，形成时空 Token 序列
- **注意力机制**：在 Transformer Block 中同时计算空间注意力和时序注意力

**两种时序注意力策略**：

| 策略 | 名称 | 特点 | 代表模型 |
|------|------|------|----------|
| 因果注意力 | Causal Attention | 自回归式，第 t 帧只能看到前 t-1 帧 | Sora 早期、CogVideoX |
| 双向注意力 | Bidirectional Attention | 并行生成，所有帧同时去噪 | 可灵、Veo、HunyuanVideo |

**因果注意力**的优势是天然支持自回归生成（先生成前 N 帧，再生成后续帧），适合长视频；**双向注意力**的优势是生成质量更高、并行度更好，适合短视频生成。

#### 3.3.3 Sora (OpenAI, 2024)

Sora 是 3D DiT 视频化的里程碑，虽然技术细节未完全公开，但从已知信息可以推断其架构：

**时空联合潜空间 Patch**：
- 使用 **3D VAE** 将视频压缩为时空潜空间表示
- 压缩率推测为 **4×8×8**（时间压缩 4 倍，空间每维压缩 8 倍）
- 将潜空间表示切分为 3D Patch（空间 2D Patch + 时间 1D Patch）

**DiT 去噪**：
- 使用 Transformer（推测为 LLaMA 风格的 Decoder-only 架构）进行去噪
- 在潜空间执行扩散去噪过程
- 支持可变分辨率、可变时长、可变长宽比

**关键创新**：
- **统一表示**：将图像视为单帧视频，统一处理图像和视频
- **世界模拟器**：通过大规模训练涌现物理规律模拟能力
- **涌现能力**：模型规模达到一定程度后，视频质量非线性提升

#### 3.3.4 CogVideoX (智谱, 2024)

CogVideoX 是开源 3D DiT 视频生成的代表：

**3D Causal VAE**：
- 自研 3D VAE，时空联合压缩
- 采用 **Causal Convolution**，保证时序因果性
- 压缩率：时间 4 倍，空间 8 倍

**DiT 架构**：
- 基于 Transformer 的扩散模型
- 使用 **因果注意力**，支持自回归长视频生成
- 开源了 2B 和 5B 两个版本

#### 3.3.5 HunyuanVideo (腾讯, 2024)

HunyuanVideo 采用了创新的**双流 DiT** 架构：

**双流设计**：
- **图像流**：处理单帧图像的空间信息
- **视频流**：处理多帧视频的时空信息
- 两流共享部分参数，同时保留各自的专用参数

**联合训练**：
- 图像和视频数据联合训练
- 图像数据提升空间质量，视频数据提升时序连贯性
- 通过双流设计避免图像知识被视频训练"遗忘"

**开源贡献**：
- 开源了完整的模型权重和训练代码
- 支持 720p 分辨率、最长 5 秒视频生成

## 4. 3D DiT 架构详解

### 4.1 整体架构流程

3D DiT 的视频生成流程可分为以下阶段：

```
输入（文本/图像/视频）
    ↓
[条件编码器] → 条件特征（文本 Embedding / 图像特征）
    ↓
[3D VAE 编码器] → 潜空间表示 z ∈ R^(C×T'×H'×W')
    ↓
[加噪] → z_t（第 t 步的噪声潜变量）
    ↓
[3D DiT] → 预测噪声 ε_θ(z_t, t, condition)
    ↓
[去噪迭代] × N 步
    ↓
[3D VAE 解码器] → 输出视频
```

### 4.2 3D VAE：时空联合压缩

3D VAE 是 3D DiT 的基础组件，负责将高维视频数据压缩到低维潜空间。

#### 4.2.1 压缩策略

| 维度 | 原始尺寸 | 压缩后 | 压缩率 | 实现方式 |
|------|----------|--------|--------|----------|
| 空间 (H) | 512 | 64 | 8× | 2D 卷积下采样 |
| 空间 (W) | 512 | 64 | 8× | 2D 卷积下采样 |
| 时间 (T) | 120 (5s@24fps) | 30 | 4× | 1D 时序卷积 / 因果卷积 |

总压缩率：**4×8×8 = 256 倍**

#### 4.2.2 3D 卷积设计

3D VAE 的卷积核为 **(k_t, k_h, k_w)**，其中：
- k_t：时序卷积核大小（通常为 3）
- k_h, k_w：空间卷积核大小（通常为 3 或 4）

**因果卷积（Causal Convolution）**：
- 保证第 t 帧的输出只依赖前 t 帧的输入
- 实现方式：在时序维度上填充（Padding）只在前方
- 适合自回归生成，保证时序因果性

**非因果卷积**：
- 第 t 帧的输出可以依赖前后帧
- 适合并行去噪，生成质量通常更好

#### 4.2.3 训练策略

3D VAE 的训练通常分为两个阶段：
1. **图像预训练**：先用图像数据训练 2D VAE，学习空间压缩
2. **视频微调**：在 2D VAE 基础上插入时序层，用视频数据微调

这种策略有效利用了大规模图像数据，缓解视频数据不足的问题。

### 4.3 时空 Patchify

Patchify 是将连续数据离散化为 Token 的过程。

#### 4.3.1 3D Patchify

将潜空间表示 z ∈ R^(C×T'×H'×W') 切分为 3D Patch：

- **Patch Size**：(p_t, p_h, p_w)，如 (1, 2, 2)
- **Token 数量**：N = (T'/p_t) × (H'/p_h) × (W'/p_w)
- **Token 维度**：D = C × p_t × p_h × p_w

**示例**：
- 潜空间尺寸：C=16, T'=30, H'=64, W'=64
- Patch Size：(1, 2, 2)
- Token 数量：30 × 32 × 32 = 30,720
- Token 维度：16 × 1 × 2 × 2 = 64

#### 4.3.2 可变分辨率处理

为了支持可变分辨率（如 16:9、9:16、1:1 等），3D DiT 通常采用：
- **动态 Patchify**：根据输入分辨率动态计算 Token 数量
- **无绝对位置编码**：使用相对位置编码（如 RoPE），避免固定分辨率限制
- **填充（Padding）**：对不同分辨率填充到同一批次大小

### 4.4 时序注意力机制

时序注意力是 3D DiT 的核心，决定了模型的时序建模能力。

#### 4.4.1 全时空注意力（Full Spatiotemporal Attention）

最简单的设计：所有 Token 之间两两计算注意力。

- **计算复杂度**：O(N²) = O((T'×H'×W')²)
- **优点**：建模能力最强，能捕捉任意时空依赖
- **缺点**：计算量巨大，长视频时不可行

#### 4.4.2 分解注意力（Factorized Attention）

将时空注意力分解为空间注意力和时序注意力：

**顺序分解**：
1. 先计算空间注意力（每帧内部 Token 之间的注意力）
2. 再计算时序注意力（同一空间位置不同帧之间的注意力）

**并行分解**：
- 同时计算空间注意力和时序注意力
- 将两个注意力结果融合

**计算复杂度**：
- 空间注意力：O(T' × (H'×W')²)
- 时序注意力：O(H'×W' × T'²)
- 总复杂度远低于全时空注意力

#### 4.4.3 因果时序注意力（Causal Temporal Attention）

因果注意力限制第 t 帧只能关注前 t-1 帧：

```python
# 因果掩码示例
mask = torch.tril(torch.ones(T, T))  # 下三角矩阵
# attention_score[i, j] = 0 if j > i else score[i, j]
```

**优势**：
- 天然支持自回归生成
- 适合长视频：可以分段生成，每段依赖前一段
- 训练时可以使用"下一帧预测"任务

**劣势**：
- 生成质量通常低于双向注意力
- 无法利用未来信息优化当前帧

#### 4.4.4 稀疏注意力（Sparse Attention）

为了处理超长视频，采用稀疏注意力模式：

| 稀疏模式 | 描述 | 适用场景 |
|----------|------|----------|
| 局部窗口 | 每帧只关注邻近帧 | 短视频，局部运动 |
| 膨胀（Dilated） | 关注每隔 k 帧的帧 | 周期性运动 |
| 分层 | 低分辨率关注全部，高分辨率关注局部 | 长视频 |
| 线性注意力 | 将 O(N²) 降为 O(N) | 超长视频 |

### 4.5 位置编码

位置编码为模型提供时空位置信息。

#### 4.5.1 3D RoPE（Rotary Position Embedding）

RoPE 将位置信息编码为旋转矩阵，应用于 Query 和 Key：

```python
# 3D RoPE 示意
# 为每个 Token 分配 (t, h, w) 坐标
# 分别计算时序、高度、宽度的旋转角度
freq_t = theta ** (-2*i / d)  # 时序频率
freq_h = theta ** (-2*i / d)  # 高度频率
freq_w = theta ** (-2*i / d)  # 宽度频率
```

**优势**：
- 相对位置编码，天然支持外推（Extrapolation）
- 可以处理训练时未见过的分辨率/时长
- 在 LLM 中验证有效，迁移到视频生成

#### 4.5.2 时空联合位置编码

将时间和空间位置编码联合：

```
PE(t, h, w) = PE_time(t) + PE_space(h, w)
```

或更复杂的非线性组合：

```
PE(t, h, w) = MLP([PE_time(t); PE_space(h, w)])
```

### 4.6 条件注入

3D DiT 支持多种条件输入：文本、图像、视频、音频等。

#### 4.6.1 文本条件

- 使用预训练文本编码器（如 T5、CLIP）提取文本特征
- 通过 Cross-Attention 将文本特征注入 DiT
- 或使用 AdaLN（Adaptive Layer Norm）注入

#### 4.6.2 图像条件

- **首帧引导**：将首帧作为条件，生成后续帧
- **风格引导**：将风格图像通过 Reference Attention 注入
- **主体锁定**：将主体图像特征注入，保持主体一致性

#### 4.6.3 视频条件

- **视频编辑**：将源视频作为条件，生成编辑后的视频
- **视频延长**：将前段视频作为条件，生成后续帧
- **视频重绘**：对视频的部分区域进行重绘

#### 可灵 3.0 (快手)

## 6. 关键架构技术拆解

### 6.1 3D VAE 技术细节

#### 6.1.1 编码器-解码器结构

```
输入视频: (B, 3, T, H, W)
    ↓
[3D Encoder]
    - Conv3D(3→128, k=(3,3,3), s=(1,2,2))
    - ResBlock3D × 2
    - Conv3D(128→256, k=(3,3,3), s=(2,2,2))
    - ResBlock3D × 2
    - Conv3D(256→16, k=(3,3,3), s=(1,1,1))
    ↓
潜空间: (B, 16, T/4, H/8, W/8)
    ↓
[3D Decoder] (对称结构)
    ↓
输出视频: (B, 3, T, H, W)
```

#### 6.1.2 训练目标

3D VAE 的训练目标包括：
- **重建损失**：L1/L2 重建误差
- **感知损失（Perceptual Loss）**：使用预训练 VGG 提取特征，比较特征差异
- **对抗损失（GAN Loss）**：使用 PatchGAN 判别器提升细节质量
- **KL 散度**（如果是 VAE 而非 AE）：约束潜空间分布

### 6.2 位置编码技术

#### 6.2.1 3D RoPE 实现

RoPE 将位置信息编码为旋转矩阵，应用于 Query 和 Key。3D RoPE 为每个 Token 分配 (t, h, w) 坐标，分别计算时序、高度、宽度的旋转频率：

```python
# 3D RoPE 示意
freq_t = theta ** (-2*i / d)  # 时序频率
freq_h = theta ** (-2*i / d)  # 高度频率
freq_w = theta ** (-2*i / d)  # 宽度频率
# 分别应用旋转后融合
```

**优势**：
- 相对位置编码，天然支持外推（Extrapolation）
- 可以处理训练时未见过的分辨率/时长
- 在 LLM 中验证有效，迁移到视频生成

#### 6.2.2 可扩展位置编码

为了支持训练时未见过的分辨率/时长，采用：
- **NTK-aware 扩展**：调整 RoPE 的 base 频率，支持更长序列
- **动态插值**：将位置编码插值到新的尺度
- **无位置编码**：部分工作尝试完全去掉位置编码，依赖数据本身的顺序

### 6.3 并行 vs 自回归生成

#### 6.3.1 帧级自回归生成

```
生成第 1 帧 → 生成第 2 帧（条件：第 1 帧）→ ... → 生成第 T 帧
```

**优势**：
- 天然支持任意长度视频
- 每帧可以利用已生成帧的信息
- 训练时可以采用"下一帧预测"，数据利用率高

**劣势**：
- 生成速度慢：必须逐帧生成
- 误差累积：前面帧的误差会传递到后面帧
- 全局一致性差：难以保证整段视频的风格一致

#### 6.3.2 整段并行去噪

```
同时去噪所有帧：z_t → z_{t-1} → ... → z_0（所有帧同时更新）
```

**优势**：
- 生成速度快：所有帧并行去噪
- 全局一致性好：所有帧同时优化
- 质量通常更高

**劣势**：
- 内存需求大：需要同时存储所有帧
- 时长受限：受限于 GPU 显存
- 不支持无限长视频

#### 6.3.3 混合策略

当前主流采用**混合策略**：
- **短视频（<10s）**：整段并行去噪
- **长视频（>10s）**：分段生成 + 条件重叠

### 6.4 长视频生成技术

#### 6.4.1 分段生成 + 条件重叠

```
[段 1: 帧 1-30] → [段 2: 帧 21-50] → [段 3: 帧 41-70] → ...
              ↑ 重叠 10 帧
```

**实现方式**：
- 每段生成时，将前一段的后 N 帧作为条件
- 重叠区域用于平滑过渡
- 使用滑动窗口生成无限长视频

**挑战**：
- 重叠区域的一致性
- 长期依赖的保持（如一个物体从视频开头运动到结尾）
- 计算效率：重叠区域重复计算

#### 6.4.2 无限时序注意力（Infinite Temporal Attention）

为了解决分段生成的长期依赖问题，提出无限时序注意力：

- **压缩记忆**：将已生成帧压缩为记忆向量
- **稀疏访问**：当前帧只访问压缩记忆，而非所有历史帧
- **循环机制**：使用 RNN/GRU/LSTM 风格的循环状态传递长期信息

### 6.5 音频同步技术

#### 6.5.1 联合音频-视频生成架构

```
文本/音频提示
    ↓
[文本编码器] → 文本特征
    ↓
[音频 VAE] → 音频潜空间
    ↓
[联合 DiT] → 同时去噪视频潜变量 + 音频潜变量
    ↓
[视频 VAE 解码器] → 视频
[音频 VAE 解码器] → 音频
```

#### 6.5.2 音视频同步机制

- **时间对齐**：视频 Token 和音频 Token 按时间对齐
- **交叉注意力**：视频和音频 Token 之间计算交叉注意力
- **同步损失**：训练时增加音视频同步损失（如唇形同步损失）

## 7. 评测基准

### 7.1 VBench

VBench 是视频生成领域最全面的评测基准，涵盖多个维度：

| 评测维度 | 描述 | 指标 |
|----------|------|------|
| 视频质量 | 整体视觉质量 | FVD (Fréchet Video Distance) |
| 时序一致性 | 帧间连贯性 | 光流一致性、PSNR 变化 |
| 运动质量 | 运动自然度 | 运动幅度、运动合理性 |
| 文本对齐 | 与提示词的一致性 | CLIP 相似度 |
| 美学质量 | 视觉美学 | 美学评分模型 |
| 语义一致性 | 主体/场景一致性 | 特征相似度 |

**VBench 特点**：
- 自动评测，无需人工标注
- 多维度综合评估
- 被学术界和工业界广泛采用

### 7.2 AnimationBench (2026)

AnimationBench 是专门针对动画质量的评测基准：

| 评测维度 | 描述 |
|----------|------|
| 角色一致性 | 同一角色在多帧中的外观一致性 |
| 动作流畅度 | 动作过渡的自然度 |
| 表情一致性 | 面部表情与情绪的匹配度 |
| 物理合理性 | 运动是否符合物理规律 |
| 风格一致性 | 艺术风格在多帧中的保持 |

**AnimationBench 特点**：
- 针对动画场景优化
- 包含角色、动作、表情等细粒度评测
- 支持 2D 动画和 3D 动画

### 7.3 人工评测

自动评测指标无法完全捕捉人类感知，因此人工评测仍然重要：

- **ELO 评分**：两两对比，计算 ELO 分数
- **MOS（Mean Opinion Score）**：1-5 分主观评分
- **特定维度评分**：对质量、一致性、运动等分别评分

## 8. 挑战与未来方向

### 8.1 当前挑战

#### 8.1.1 计算成本

视频生成的计算成本仍然极高：
- **训练成本**：训练一个 14B 参数的 3D DiT 需要数千 GPU 月
- **推理成本**：生成一段 5 秒 720p 视频需要数分钟（消费级 GPU）
- **显存需求**：14B 模型需要 24GB+ 显存

#### 8.1.2 长视频生成

当前模型在短视频（<10s）上表现良好，但长视频（>1min）仍面临挑战：
- **长期一致性**：角色、场景、风格在长时间内保持一致
- **叙事能力**：生成有逻辑、有情节的视频
- **计算效率**：长视频的生成时间和显存需求

#### 8.1.3 可控性

用户对视频生成的可控性要求越来越高：
- **精细运动控制**：指定物体的精确运动轨迹
- **多主体交互**：多个主体之间的复杂交互
- **时间精确控制**：在特定时间点发生特定事件

#### 8.1.4 物理规律

虽然 Sora 展示了一定的物理模拟能力，但：
- **物理准确性**：碰撞、重力、流体等物理现象仍不准确
- **因果逻辑**：事件的因果关系常常不合理
- **长期物理一致性**：物理状态在长时间内保持一致

### 8.2 未来方向

#### 8.2.1 高效架构

- **线性注意力**：将注意力复杂度从 O(N²) 降到 O(N)
- **状态空间模型（SSM）**：如 Mamba，用于长序列建模
- **混合架构**：Transformer + CNN/RNN 的混合设计
- **模型压缩**：量化、剪枝、蒸馏，降低推理成本

#### 8.2.2 世界模型

- **交互式世界模型**：用户可以与生成环境交互
- **物理引擎融合**：将物理引擎与神经网络结合
- **3D 一致性**：保证视频中的 3D 几何一致性
- **因果推理**：理解并生成符合因果关系的事件

#### 8.2.3 多模态统一

- **音视频联合生成**：原生生成带音频的视频
- **文本-图像-视频统一**：统一的多模态生成模型
- **感知-生成统一**：模型既能理解视频，又能生成视频
- **任意到任意（Any-to-Any）**：任意模态输入，任意模态输出

#### 8.2.4 实时生成

- **流式生成**：视频生成与播放同步
- **实时编辑**：实时响应用户的编辑指令
- **低延迟推理**：将生成延迟降到秒级
- **边缘部署**：在手机、VR 设备上本地运行

#### 8.2.5 个性化与可控性

- **少样本个性化**：用少量参考图定制生成风格
- **精确运动控制**：通过轨迹、关键帧等精确控制运动
- **分层控制**：分别控制场景、角色、动作、风格
- **交互式生成**：用户实时参与生成过程
