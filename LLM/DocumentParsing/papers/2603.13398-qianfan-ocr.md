# Qianfan-OCR：把版面分析塞进“思维”里，一个 4B 端到端模型

> Baidu Qianfan Team, *Qianfan-OCR: A Unified End-to-End Model for Document Intelligence*, arXiv:2603.13398v1（2026-03-11，cs.CV；CC BY 4.0）。依据[官方完整 HTML 原文 v1](https://arxiv.org/html/2603.13398v1)精读，重点参照 §3.1–3.2、§4.1–4.2、§6.1、§6.5、§7，尤其是 Table 1–3、Table 8 与 Figure 5。代码与用法见 <https://github.com/baidubce/Qianfan-VL>。

## 端到端省掉了什么，这正是它的卖点也是它的缺口

多阶段流水线（版面检测 → 按区域识别 → 排序 → 组装）的每一步都能单独诊断，但阶段之间的接口是硬边界：上游漏检区域，下游没有机会补。端到端直接把页面图像映射成 Markdown，省掉接口，也带走了**显式的版面分析产物**——框、元素类别、阅读顺序。而生产用户恰恰常拿这些产物做定位、切分和类型过滤（§1）。

Qianfan-OCR 的起点就是补这个缺口，而不是再刷一遍识别精度：**Layout-as-Thought（LatT）**，一个由特殊 `⟨think⟩` token 触发的**可选**思维阶段，模型先输出结构化的版面表示（bounding box、元素类型、阅读顺序），再输出最终 Markdown（§1、§3.1）。论文称其有两个作用：恢复端到端范式下丢失的版面能力，以及用一个显式中间表示改善复杂版面的最终精度。

**用或不用，取决于页面异质性。** 论文报告：结构化程度高的页面（试卷、技术报告、报纸）开思维阶段精度更好；同质页面（单栏文字、简单表单）关掉它结果更好、延迟更低（§6 讨论、Figure 5）。这是一个需要按页型路由的开关，不是无脑开。

## 4B 是怎么练出来的

**架构**（§3.1）：视觉编码器 24 层 Transformer、隐维 1024、16 头、14×14 patch，每 tile 256 个视觉 token，最多 16 tile → 单页最多 **4,096 视觉 token**；语言主干用 **Qwen3-4B**（4.0B 总参数、3.6B 非嵌入、36 层）。所以“4B”是语言主干规模，不是整机算力。

**数据**（§3.2）：六条合成管线分别覆盖文档解析、关键信息抽取、复杂表格、图表理解、公式识别和多语 OCR。文档解析这条的关键选择是——**用 PaddleOCR-VL 做版面检测与内容识别**来造 Markdown 标签，bbox 归一化到 [0, 999] 保证分辨率无关，表格经 OTSL 中间格式转 HTML，公式包进 `$$`。作者还比较了 PaddleOCR-VL 与 MinerU 2.5 的标签粒度：前者正文标签更细（`vertical_text`、`paragraph_title`、`abstract`、`reference_content` 等），后者只有 `text`/`title`/`list`/`aside_text`，并认为细粒度直接利于下游结构化抽取。**这条依赖值得记住：它既是“端到端”的模型，又是用两阶段系统造的标签。**

**训练**（§4.1）四阶段：Stage 1 只训 adapter（50B token，lr 1e-3 快速对齐）；Stage 2 全参 2T token（lr 2e-5）；Stage 3 全参 800B（lr 1e-5）；Stage 4 指令微调。最大序列 32,768。

**消融的诚实处**（§4.2，Table 2）：4B 模型训练前先用同族的 Qianfan-VL-8B 做低成本消融。Stage 1 基线 71.37 → Stage 2 仅 OCR 数据 75.97 → 2+3 用 OCR+General 混合 80.07；而 Stage 3 只用 General 是 83.47，用 **OCR+General 1:1 混合**才到 84.39。也就是说，到第三阶段时**通用数据比 OCR 专属数据贡献更大**，作者没有把这个结论藏起来。

## 数字与口径

- **OlmOCR Bench**：总分 **79.8**，端到端模型里最高；其中 Old scans 42.0 为端到端最佳，Base 99.6、Headers & footers 92.2（Table 3）。同表里两阶段系统 PaddleOCR-VL 为 80.0，**只差 0.2，且对方是流水线**——所以“端到端第一”不等于“总体第一”。
- **OmniDocBench v1.5**：**93.12**，作者表述为“端到端模型第一”（摘要）。
- **KIE**：公开基准平均分最高，超过 Gemini-3.1-Pro、Seed-2.0、Qwen3-VL-235B-A22B（摘要、§6.4）。
- **吞吐**（§6.5、Table 8）：单卡 A100、vLLM 0.10.2、OmniDocBench v1.5、batch 512，以 **PPS（每秒整页）** 计。Qianfan-OCR **W8A8 = 1.024**、W16A16 = 0.503；对照 PaddleOCR-VL 1.224、MinerU 2.5 1.057、MonkeyOCR-pro-1.2B 0.673、Dots OCR 0.352。作者自己注明对手数字取自 PaddleOCR-VL 技术报告。
  → **代价在这里：不量化时吞吐只有两阶段系统的 0.41 倍**（0.503 / 1.224），靠 W8A8 才接近持平；“端到端更省”是量化之后才成立的结论，不能默认。

## 代价清单（论文自述 + 我们的解读）

1. **思维阶段不是免费的**：额外生成框、类别与顺序，token 与延迟都增加；同质页面反而变差，论文因此把它做成可选（§1、§6）。**我们的判断**：这意味着部署侧需要一个页型分类器来决定开关，理论收益要先扣掉这个路由成本。
2. **格式刚硬**：LatT 的版面输出是 SFT 教出来的固定格式，论文自述“相对僵硬”，未来想用 RL 按下游任务奖励来学“什么时候该做空间推理”（§7）。**论文报告**，即当前版本的 LatT 是“模板式思维”，不是自发推理。
3. **验证面窄**：LatT 只在 OmniDocBench v1.5 的文档解析上验证过，KIE、DocQA、图表理解上未评估（§7）。所以“思维阶段提升复杂版面精度”这句话的作用域只有文档解析。
4. **数据依赖两阶段系统**：训练标签来自 PaddleOCR-VL，其中包含对方的版面错误；论文的比较显示细粒度标签有用，但没有隔离“标签质量”与“标签粒度”两个因素。
5. **端到端上限未知**：论文自己把“纯端到端架构的性能天花板”列为开放问题（§7）。

## 与库里其它分册怎样放在一起看

- **和 PaddleOCR-VL（两阶段）**：不是替代关系。PaddleOCR-VL 用检测器 + 阅读顺序预测 + 小 VLM 识别裁剪区域，错在哪一步可查；Qianfan-OCR 用一次生成，错了只能在长输出里猜。两者在 OlmOCR Bench 上 80.0 对 79.8、吞吐 1.224 对 0.503（W16A16），**差距不在分数而在可诊断性与吞吐**。两者数据口径不同（同一张表里 Liu 等自测 vs 本文引用），不许把两边的 OmniDocBench 分数并成一张表。
- **和 MinerU 2.5 / MinerU2.5-Pro**：Qianfan-OCR 明确拿 MinerU 2.5 的**标签粒度**做对照组，认为粗粒度标签会限制下游结构化抽取。这是“数据工程决定能力上限”的又一条证据，与 MinerU2.5-Pro 那篇的数据侧主张方向一致，但两者模型与训练规模不同，不能互相印证分数。
- **和 Unlimited OCR（R-SWA）**：解的不是同一个约束。Unlimited OCR 改解码注意力，把**输出侧** KV cache 钉成常数以支持长时程；Qianfan-OCR 改的是“要不要先输出结构”，管的是**布局信息的可获得性**。一个管长度，一个管结构，结论不可互换。
- **和 HunyuanOCR-1.5 / MiniCPM-OCR 1.0 这类加速线**：它们压的是同一条端到端路径上的解码成本（并行草稿、DSpark 之类），Qianfan-OCR 的答案是“量化 + 少开思维”；三种手段作用在不同环节，比较必须固定量化与是否开思维。

## 我们的判断

Qianfan-OCR 的价值不在刷新纪录，而在于**把“版面分析”重新定义为一种可选的中间推理**，从而让端到端模型同时提供“只要文本”和“要框+顺序”两种档位。它的三个约束同样清楚：LatT 只是研究阶段的固定格式、只在一个基准上验证；吞吐要靠 W8A8 才追平两阶段；训练标签依赖对手系统。若要用它，先回答三个问题——页型是否异质、是否接受 W8A8、下游是否需要框与顺序；三问有一是否，收益就会打折。
