# GLM-OCR：0.9B 的两阶段解析器，用一次预测 10 个 token 换吞吐

> Zhipu AI + 清华大学，*GLM-OCR Technical Report*，arXiv:2603.10910v2（v1 2026-03-11，v2 2026-03-16）。依据[官方完整 HTML 原文](https://arxiv.org/html/2603.10910)精读，重点参照 §1、§2.1–2.2、§3、§6，尤其是 Figure 2 与 Tables 1–4。数字均标注基准版本；本文未独立运行模型、未重算指标。

## 一句话：把"小模型 + 外置版面 + 多 token 预测"三件事拼成一个系统

GLM-OCR 是 0.9B 的紧凑多模态模型，由 **0.4B CogViT 视觉编码器 + 0.5B GLM 语言解码器** 加一个轻量跨模态连接器组成（§1、§2.1）。它不做端到端整页生成，而是**两阶段**：先用 **PP-DocLayout-V3** 做版面分析与切区域，再对区域并行识别，最后由 Merge & Post Process 还原读序、输出 Markdown / JSON（§2.1 Task 1）。KIE 走另一条路——整页图 + 字段 prompt 直接生成 JSON，不切版面（Task 2）。

真正让它在 0.9B 上站住的是**解码方式**：MTP（Multi-Token Prediction）。主头之外挂 **k 个共享参数的辅助头**，训练时**一次预测 10 个 token**，推理时**平均每步产出 5.2 个**，论文报告吞吐约 **+50%**（§1）。注意它和"外挂草稿模型做推测解码"不是一回事——参数共享在同一模型内部，不引入独立 draft 权重。

## 四个部件怎么组合（这是本条目最需要说清的部分）

| 部件 | 规模/来源 | 作用与代价 |
|---|---|---|
| 视觉编码器 CogViT | 0.4B | 大规模图文 + grounding 训练，MIM 与 CLIP 双目标，并对齐一个更大的内部 ViT 做蒸馏（§2.2 Stage 1） |
| 连接器 | 轻量 | 视觉特征投到语言嵌入空间，作为前缀 token（§2.1） |
| 语言解码器 GLM | 0.5B | 自回归生成 Markdown / JSON；MTP 头挂在它上面（§2.1） |
| 版面分析 PP-DocLayout-V3 | 外置 | 把复杂页拆成区域，既降幻觉又能并行；代价是**错误传播**（§6.1） |

**MTP 的设计细节**（§2.1 Architecture）：辅助头与主头**共享参数**，但分别学不同的未来偏移量；训练目标从 Stage 2.2 起就带 MTP，Stage 3 SFT 保持开启以对齐训练/推理。作者给的理由是 OCR 的结构化 token（表格标签、Markdown 语法）**局部依赖极强**，一次预测多个 token 顺带让模型"往前规划"，产出更少断裂标签——所以 MTP 在这里不只是加速，也被当作结构稳定性的手段。

**训练配方四阶段**（Table 1）：① 视觉编码器训练（海量图文 + grounding/检索，MIM+CLIP+蒸馏）→ ② 视觉-语言预训练（先 2.1 拼接对齐，再 2.2 引入 MTP 目标）→ ③ SFT（文本/公式/表格识别 + KIE，数据配比平衡防单任务过拟合）→ ④ GRPO 强化学习。RL 的奖励是**任务感知**的：文本用归一化编辑距离、公式用 CDM、表格用 TEDS、KIE 用字段级 F1，另加结构校验（标签闭合、JSON 可解析、重复率惩罚）（Table 2）。这一层"奖励里带结构合法性"是它与纯 SFT 方案的重要差别。

## 两阶段 / 端到端的谱系里它站在哪

| 模型 | 版面 | 识别主干 | 加速手段 | 读序由谁决定 |
|---|---|---|---|---|
| **GLM-OCR**（本篇） | 外置 PP-DocLayout-V3 | CogViT 0.4B + GLM 0.5B | **MTP**（同模型共享参数多头） | 版面模块 + Merge 后处理 |
| PaddleOCR-VL（`2510.14528`） | 外置版面模型 | NaViT 原生分辨率 + 0.3B 语言模型 | 三线程异步流水线 | 版面 + 合批 |
| MiniCPM-OCR（`20261027-minicpm-ocr`） | 外置 PP-DocLayoutV3 | SigLIP + Qwen3.5 1.3B | **DSpark**（独立 draft 模型） | 版面模块 + SDK 组装 |
| MinerU2.5-Pro（`2604.04771`） | **模型内**（解耦粗到细，但同一 1.2B） | NaViT-675M + Qwen2-0.5B | 无（靠数据） | 模型自出结构 |
| HunyuanOCR（`2511.19575`） | 无（端到端） | 原生分辨率 + 0.5B 语言模型 | DFlash（草稿模型） | 端到端生成 |

两点值得记住：

1. **GLM-OCR 与 MiniCPM-OCR 的流水线几乎同构**——都用 PP-DocLayout-V3 系版面模型 + 区域级识别 + 后处理。差别在加速路线：MTP 在模型内部（共享参数、无需第二份权重），DSpark 是外挂草稿模型（需同批发布的 draft 权重）。**这不是"两阶段 vs 端到端"的差别，而是同一骨架上的两种加速选择**。
2. **只有 MinerU 和 Hunyuan 让模型自己产生版面结构**。要不要外置版面，是"降幻觉 + 可并行"与"避免错误传播 + 一步到位"的权重取舍，GLM 自己在 §6.1 承认了外置方案的代价。

## 口径：三个 94.x 不是同一个数

| 数字 | 基准与层 | 出处 | 备注 |
|---|---|---|---|
| **94.60 / 94.62** | OmniDocBench **v1.5** Overall | 论文 Table 3 / Table 4 与 §3.1（94.62），作者自测 | 同一结果两种写法（表 3 取一位、表 4 两位）；对照：PaddleOCR-VL-1.5 **94.50**、MinerU2.5 **90.67**、Qwen3-VL-235B 89.15、Gemini-3 Pro 90.33 |
| **95.15** | OmniDocBench **v1.6 Full（1,651 页）** | MinerU2.5-Pro 论文统一重跑（`2604.04771` §6.1、Table 2） | **不是本论文的数字**，是新协议下的第三方重评 |
| 分项 | v1.5 上 Table TEDS **93.96**、TEDS-S **96.39**；Text Edit 0.040；CDM 93.90 | 论文 §3.1、Table 4 | 分项口径：表格最强，文本与公式略逊 PaddleOCR-VL-1.5（0.035 / 94.21） |

**94.62 → 95.15 这 +0.55 值得单独理解**：v1.6 同时做了两件方向相反的事——MGAM 放宽了粒度匹配（对语义正确但切分不同的输出加分）、又新增 296 页 Hard 子集（减分）。同一模型净涨 0.55，说明**放宽匹配的收益盖过了加入难样本的损失**。推论（我们的判断）：v1.5 时代的分数系统性压低了那些"输出粒度与 GT 不同"的系统，跨协议比较不能只用"新集更难"来解释。

其他基准各说各的，不可并表：OCRBench (Text) **94.0**、UniMERNet **96.5**、PubTabNet **85.2**、TEDS_TEST **86.0**；自建六类场景里真实表格 **91.5**、印章 **90.5**、票据 KIE **94.5**，多语言覆盖 8 种（中英法西俄德日韩）。KIE 另有 Nanonets-KIE 93.7、Handwritten-KIE 86.1（§3.1）——**KIE 的 F1 与解析的编辑距离/TEDS 完全不可比**，这是它表 3 里最容易误用的一栏。

## 边界（§6 作者自述，四条）

1. **两阶段的错误传播**：版面检测错了，下游识别跟着降级；**跨页依赖**与**不规则多栏**的读序重建不完美（§6.1）。这是架构级边界，不是调参能解决的。
2. **数据覆盖**：极低分辨率或重度畸变、高度复杂的数学表达式、密集或不规则表格、训练语料里欠代表的语言，都可能退化（§6.2）。
3. **结构化输出的随机性**：生成模型在换行与空白处理上会有格式抖动，RL 与结构监督只能缓解，"严格格式保证"做不到（§6.3）——**下游若做精确 diff，需要容忍空白差异**。
4. **KIE 依赖 prompt 与 schema 清晰度**：字段边界含混时可能漏字段或重复（§6.4）。

补充两点我们的判断：**外置版面意味着"版面模型换了，分数就变"**，跨论文引用它的 v1.5 分数时要说清版面模块版本；**MTP 的"平均 5.2 token/步"是特定输出分布下的实测**，输出短、结构化程度低时收益会下降（与 HunyuanOCR 的 DFlash 同理会随输出长度变化）。

## 读法

先读 §2.1 的三个 Motivation——它解释了为什么 0.9B 还要外置版面、为什么把解析与 KIE 统一成结构化生成、为什么要 MTP；再读 Figure 2 的两条任务流；然后读 §2.2 的 Table 1 与 Table 2（训练四阶段 + 奖励设计），这是"小模型怎么被喂出来"的证据；最后读 §6 四条限制，比看 §3 的排名更能判断能不能用在你的场景。跨论文比较时，先确认对方说的是 v1.5 的 94.62 还是 v1.6 Full 的 95.15。
