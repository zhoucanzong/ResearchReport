# OmniDocBench：文档解析分数分别在测什么

> Linke Ouyang et al., *OmniDocBench: Benchmarking Diverse PDF Document Parsing with Comprehensive Annotations*, arXiv:2412.07626v2（2025-03-25，CVPR 2025）。依据[固定版本完整 arXiv HTML 原文](https://arxiv.org/html/2412.07626v2)阅读，重点参照 §1、§3–5、附录 II–V，特别是 Figure 2–4、Table 1–9、Table S3–S6 与 Figures S3–S34。arXiv 页面列出的最新版本为 v2；paper-fetcher 核对了题录信息。

## 它把“读懂一页 PDF”拆成了哪些不同问题

把一页双栏论文转成 Markdown，至少涉及四种容易混为一谈的能力：看清文字、找出页面区域、判断内容顺序、还原表格和公式结构。一个系统可以 OCR 字符很准，却把左右栏串在一起；也可以找到表格位置，但把合并单元格读错。OmniDocBench 的贡献不只是扩大样本，而是给同一批页面增加这些不同层次的标注和评测，让端到端输出与单项模块能够相互诊断（§1、§2.3、§3.2，Figure 2–4，Table 1）。

基准包含 981 个单页 PDF 样本，来自书籍、幻灯片转 PDF、研究报告、彩色教材、试卷、杂志、学术论文、手写笔记和报纸九类；语言以简体中文为主（612 页），另有英文 290 页、中英混合 79 页。页面布局包括单栏、多栏和复杂版式；特殊情况包括模糊扫描、水印和彩色背景（§3.1、§3.3，Table S3）。这比仅用英文论文页测 OCR 更能暴露领域迁移和长尾版式问题，但它仍是从文档中抽出的页面样本，不是多页文档理解或跨页检索测试。

样本先从 Common Crawl、Google、百度和内部来源收集的 20 多万份 PDF 中提取，再用 ResNet-50 特征和 Faiss 聚类挑出 6,000 个视觉多样页面，最后经人工属性标注和平衡筛选为 981 页（§3.1，Figure 3）。这个流程有意追求版式覆盖，不是按真实文档流量抽样；九类页面也不等于各类在部署环境中的自然占比。因此平均分是这套样本构成下的结果，不能直接解释为现实业务的预期准确率。

标注把页面位置、文字内容和关系拆开：区域框覆盖标题、段落、表格、图片等 19 类核心标注对象；另有阅读顺序、图表标题/说明与跨页段落关联，以及文本和表格属性。文字区域附 Unicode 文本，公式给 LaTeX，表格给 HTML 和 LaTeX。附录把标注统计分为 15 类块级、4 类跨度级，并另列 3 类用于屏蔽干扰的区域（§3.2.1、附录 II，Table S4–S6）。标注流程先用 LayoutLMv3、PaddleOCR、UniMERNet 和 GPT-4o 预标，再由标注者修框、补阅读顺序和关系，并逐字符校正；复杂公式/表格还由研究者检查可渲染性（§3.2.2）。因此“人工校正”提高了预标注质量，但论文没有报告整套数据的标注者一致性；机器预标注也可能影响标注者的注意方向。

## 四种分数不能互相代替

| 能力 | 评测对象与指标 | 读分时应注意 |
|---|---|---|
| 文本识别（OCR） | 页面解析输出中的纯文本，与标注段落对齐后计算归一化编辑距离；按语言、背景、旋转等属性还能切片（§4.1、§4.3，Table 2–4、8） | 越低越好。它主要反映字符序列差异，不说明区域定位是否正确，也不单独说明段落次序是否合理。匹配算法会合并/拆分预测段落，尽量减轻段落切分差异。 |
| 版面结构 | 在版面检测子集上比较预测区域框和类别，以 mAP 评估（§4、§5.2，Table 6） | 越高越好。它测区域检测，不等价于完整阅读顺序、跨区域语义关系或端到端可读性。 |
| 阅读顺序 | 将预测 Markdown 中抽取出的文本段落按出现次序，与标注序列计算归一化编辑距离（§4.1–4.3，Table 5） | 越低越好。但最终只计文本组件；表格、图片和若干被忽略组件不进入顺序分数。识别漏字、段落合并也会影响该分数，所以它并非纯粹隔离出来的排序能力。 |
| 表格与公式 | 表格先统一转成 HTML，再报告 TEDS（树编辑相似度）和归一化编辑距离；公式报告 CDM、归一化编辑距离和 BLEU，另有严格表达式正确率（§4.1、§4.3，Table 7、9） | TEDS/CDM 越高通常越好，编辑距离越低越好。表格指标关注 HTML 树结构与字符串；公式字符/结构指标关注符号识别。各指标惩罚的错误不同，不能把其中一个分数称为通用“文档理解准确率”。 |

全文评测的输入输出也有明确边界：系统对页面进行解析并输出结构化 Markdown；评测器从 Markdown 中按固定次序提取 LaTeX 表格、HTML 表格、独立公式、Markdown 表格和代码块，剩余内容再按空行切分段落（§4.1、Figure 4）。行内公式转成 Unicode 并并入段落文本，不作为独立公式项评分。标题、页眉页脚、页码、页脚注，以及图表说明在部分指标中被忽略，以减少不同系统输出规范造成的噪声（§4.2、附录 V，Figures S3–S4）。这些规则提高了异构输出间的可比性，同时意味着分数不覆盖所有读者实际关心的信息：例如图注和图片的阅读顺序、行内数学的独立正确性就没有被单独评价。

## 结果说明了什么，又没有说明什么

Table 2 的端到端对照显示，流水线工具在常见文档上的文字、公式和表格任务有竞争力；一般 VLM 在幻灯片、手写笔记等少见页面类型上展现了更好的泛化。作者把这种差异联系到机制：流水线先切分页面、再针对局部内容调用专用识别器，因而能绕开整页输入的视觉密度限制；VLM 则能利用更广泛的训练分布处理不常见格式。原文 Table 3、Table 4 及附录 Figures S11–S22 展示了不同页面类型和模糊、水印、彩色背景下的差异。它支持“能力随任务与文档条件改变”，不支持脱离具体配置的全局优劣判断（§5.1、附录 III）。

阅读顺序尤其能揭示端到端分数的耦合。作者观察到多栏和复杂布局普遍更难；VLM 会漏掉密集页内容或在难辨区域产生幻觉，部分模型会合并多栏文字。流水线也会因错误切栏或识别噪声而失分：例如 MinerU 在手写笔记上的区域处理问题会拖低单栏顺序成绩。因此低顺序分不能自动归因为“排序算法差”，它可能先由 OCR 漏检或布局切分错误触发（§5.1，Table 5，附录 III Figures S23–S30）。

表格和公式子集进一步说明“看起来读对”不代表结构复原一致。表格单项测试按语言、边框类型、合并单元格、背景、公式和旋转切片；RapidTable 总体较强，而不同系统在无框、三线和旋转表格上表现不同（§5.2，Table 7，Figures S31–S34）。公式子集对照 CDM、BLEU、编辑距离和严格正确率；论文指出字符级接近与整个表达式严格正确并非同一目标（Table 9）。这些是有解释价值的诊断分数，但子集大小和属性分布不同，不能直接与 981 页端到端总分横向比较。

## 跨系统比较的预算边界

附录 IV 给出的条件并不构成统一输入预算。MinerU 0.9.3、Marker 1.2.3、Mathpix 使用默认设置；Nougat 用 0.1.0-base（350M）；GOT-OCR 用格式 OCR 模式。GPT-4o、Qwen2-VL-72B 和 InternVL2-Llama3-76B 设为确定性解码；Qwen2-VL 的 `max_token` 为 32,000，InternVL 为 4,096，GPT-4o 用默认设置（附录 IV）。论文没有报告统一的页面栅格 DPI/分辨率、统一视觉 token 预算、跨模型计算量或同一分辨率下的受控消融。作者也明确把 VLM 在报纸等高密度页面上的困难联系到输入分辨率和 token 长度限制（§5.1）。所以 Table 2–5 更适合回答“这些版本按论文采用的配置处理该页集，分别出现了哪些长短板”，不能解释为模型架构在相同像素和计算预算下的纯能力排名。

另一个比较边界是版本和任务实现：论文固定了部分工具版本，但 SaaS/API 的 GPT-4o 使用默认设置，服务端模型版本和图像预处理在文中未细化；流水线内部的分块、缩放和 OCR 处理也采用默认配置而非统一策略。跨系统成绩同时混合模型、分辨率路径、专用组件和输出规范的差异。若研究问题是输入分辨率或视觉 token 的因果影响，需要固定模型与页集，控制页面像素尺寸/裁切及输出 token 上限，再比较；原论文不是这样的控制变量实验。

## 怎么读这篇基准

先看 §3.1–3.3 和 Figure 2–3，掌握 981 页如何从大规模来源中筛选以及它覆盖什么；再看 §3.2、Figure 4，理解页面框、内容、关系和评测管线；随后对照 §4.1–4.3、Table 2–9，分别读 OCR、版面、顺序、表格和公式指标；最后看附录 IV–V 与 Figures S3–S34，检查模型输入配置、忽略规则和典型错误。关键成绩均为论文报告；本精读没有独立运行 OmniDocBench 或重算表中指标。
