# Multimodal OCR：把图表和示意图也变成文档结构

> Handong Zheng et al.（含小红书 HiLab 团队）, *Multimodal OCR: Parse Anything from Documents*, arXiv:2603.13032v2（2026-03-19）。依据[该版本完整 HTML 原文](https://arxiv.org/html/2603.13032v2)精读，主要参照 §1、§3–4、Figure 1–3、Tables 2–5 与 Appendix A.1、A.3。题录由 `paper-fetcher` 获取。下文数字均为论文报告的结果，注明评测方式和来源位置；本文不独立重算或复现实验。

## 传统 OCR 把图表保留下来，却常把其中的结构丢掉

普通文档解析会识别正文、表格、公式并安排阅读顺序；遇到图表、流程图、示意图或图标时，往往只把它们作为一张裁切图片保留。这样虽然没有删除图像，却丢失了坐标轴、图例、箭头、部件关系等可编辑结构，也很难把这些结构直接转成多模态训练监督（§1，Figure 3）。

这篇论文提出 Multimodal OCR（MOCR）：按阅读顺序生成页面元素序列，每个元素带位置、类别和内容。正文输出文本，表格输出结构标记，公式输出 LaTeX；适合程序化表示的图形输出可渲染的 SVG。照片等没有紧凑程序描述的自然图像仍作为栅格内容保留（§3.1）。这把“看出图上有什么”推进到“恢复一个可渲染、可编辑的结构”。

有个容易误读的细节：虽然论文把目标称为统一解析，当前公开版本并不是一次生成同时输出整页文字和全部 SVG。它以任务条件分别运行页面级文字解析与区域级图像到 SVG，组合后才得到完整的多模态解析（§3.1）。这是一个统一模型覆盖多种目标格式的范式，当前推理流程仍有分开的解析阶段。

## 核心难题从识字转向“程序如何算对”

模型使用从头训练的高分辨率视觉编码器（约 1.2B 参数），最高处理约 1,100 万像素；生成端使用 Qwen2.5-1.5B 解码器。高分辨率让小字、细线和图表标记保留更多像素；解码器则必须能输出长篇结构化序列，例如包含形状、文字和样式的 SVG 程序（§3.2）。论文将整体模型称为 3B 级。

训练采用逐步加难的多阶段课程：先训练通用视觉输入接口，再混合通用视觉数据与文档文字解析，最后提高 MOCR 和图形解析任务的权重，并逐步增加图像分辨率。随后用经过规则筛查、渲染比较和强监督修订的 SFT 数据提高目标一致性（§3.3）。目标格式并非只有文字，因此训练既要保持 OCR 能力，也要让输出代码可渲染且结构贴近输入。

图形监督来自自然存在的结构数据。论文从 PDF 构造页面解析样本，以 dots.ocr 自动标注页面结构；网页通过渲染图像并利用 HTML/DOM 对齐取得监督；原生 SVG 则清洗元数据、规范数字精度、去重，并按来源领域和程序复杂度采样（§3.4）。渲染核验能发现代码无法正确画回原图的问题，但同一图像可能对应多份视觉等价 SVG，因此代码字符串完全相同不是合适的学习目标。规范化和图像渲染比较正是为这个非唯一性服务。

## 结果要按文档转写与图形重建两种任务来读

在 olmOCR-Bench 上，论文报告 dots.mocr 总分为 83.9±0.9（§4.1，Table 3）；表中分项显示它在旧扫描件、页眉页脚和长小字等类别并非都领先。对同一批基准图片，作者还用 Gemini 3 Flash 作裁判，将模型输出两两比较并计算 Elo；dots.mocr 在表列开源模型中得分最高 1124.7，低于 Gemini 3 Pro 的 1210.7（§3.5、§4.1，Table 2）。Elo 衡量裁判偏好，不与严格字符串匹配分数处于同一数值尺度。作者报告把候选顺序互换后再判断，并把两种顺序不一致的比较记作平局；这降低位置偏差，但依然依赖专有裁判模型的判断标准。

图形重建使用另一版本 **dots.mocr-svg**：它在基座 dots.mocr 上增加图形解析专项训练，不能与基础模型结果混为一谈。作者将预测代码渲染成图像，再用 ISVGEN 衡量与输入图像的相似度。在 UniSVG 总分上，论文报告 dots.mocr-svg 为 0.902、Gemini 3 Pro 为 0.735；在 ChartMimic 上分别为 0.905 与 0.788（§4.2，Table 4）。但基础 dots.mocr 的 ChartMimic 分数是 0.772，低于 Gemini 的 0.788。也就是说，较强图形重建结果来自专项增强版，而非所有文档解析任务都由基础模型全面领先。

ISVGEN 的渲染比较回答代码画出来是否接近原始图像，适合捕捉几何与视觉重建差异；它不能单独证明图表中的数值、化学键关系或科学含义都正确。论文同时提供 ChartMimic、Design2Code、GenExam、SciGen 和 ChemDraw 等不同类型数据集，让读者观察跨图形类别的效果，但它们的任务语义并不相同，不能只合并成一个总分理解。

## 可见性与证据边界

文档转写评测使用 olmOCR-Bench、OmniDocBench v1.5 和 XDocParse 提供的图片。论文报告了细分结果，并说明 Appendix A.1 中 OmniDocBench 指标是引用各模型论文报告值；而 pdf-parse-bench 分数由 Qwen3-VL-235B-A22B-Instruct 在统一设置下重测。作者还指出，公式与表格指标对检测和标注匹配规则敏感，因而没有在 Appendix A.1 作跨系统汇总（Appendix A.1，Table 6）。读者应区分这些既有论文数字与作者统一复测的数据。

训练数据工厂整合 PDF、渲染网页和原生 SVG，但论文没有提供可逐来源重建的完整语料清单及每类来源配比；所以数据规模背后的版权、覆盖偏差和重复情况不能仅凭本文评估。OCR Arena 的评测图片来自公开基准，判分则由 Gemini 3 Flash 完成；论文给出协议、汇总分及部分判分示例（Appendix A.3），但这仍是模型裁判证据，不是人工逐页审查的独立金标准。代码和模型在论文中标为公开，原文及项目入口见 [arXiv](https://arxiv.org/html/2603.13032v2) 与 [dots.mocr 官方仓库](https://github.com/rednote-hilab/dots.mocr)。

## 与 FireRed-OCR 的互补关系

FireRed-OCR 集中解决“整页识别结果结构是否可靠”：几何与语义数据分层、统一 Markdown 监督，再用格式约束 GRPO 提高表格、公式和层级输出的合法性。dots.mocr 扩大解析对象本身：不止文本和结构标记，还把可程序化描述的图形变成 SVG。前者把监督和奖励聚焦在文档文本结构，后者把图形像素转为第二种长序列程序输出。

两条路线都面对自动标注会继承教师偏差、结构目标并不唯一、评测分数难覆盖真实使用质量等问题；但失效面不同。FireRed 的格式奖励可能鼓励“合法但错字”的 Markdown；MOCR 的 SVG 可能视觉相似但语义数据错误，或无法用简短代码表达复杂照片与纹理。对于文档学习和检索，保留清楚文本结构可能优先；若目标是编辑图表、UI 或科学示意图，SVG 重建才带来额外价值。

建议按 §1、Figure 3 理解从 OCR 到图文联合解析的动机，再读 §3.1–3.4 追任务定义、模型与数据来源，最后比较 §4.1 的 Tables 2–3 和 §4.2 的 Table 4。性能数值均按 v2 原文引用：olmOCR-Bench 的标准评分与 OCR Arena Elo 是不同评测，图形专项结果则来自 dots.mocr-svg；本文不据此声称独立复现或全面排名。
