# ABot-OCR：先学会看内容，再用奖励修文档结构

> Kaitao Jiang et al., *ABot-OCR Technical Report*, arXiv:2605.27978v1（2026-05-27，署名 AMAP CV Lab）。依据[官方完整 HTML 原文](https://arxiv.org/html/2605.27978v1)精读，重点参照 §2–4.3.5，尤其 Figures 2–3、Tables 1–5。以下均为论文报告结果；多语言数据集为作者构造，未独立重算或复现。

## 它把文档解析分成“看全”和“排对”

从页面图像生成 Markdown，要同时做到两件事：完整读出文字、公式、表格等内容；再把这些内容放进正确的标题层级、表格结构和阅读顺序。字符没错但表格行列错位，或标题和段落关系混乱，仍然会让输出无法作为机器可用文档。

ABot-OCR 围绕此差异提出两个目标：**perception** 指看全内容并读对文字；**structure** 指把识别到的内容放回正确结构。它以 Qwen3-VL-2B-Instruct 为底座，先做模块化子任务训练，再做整页图像到 Markdown 的端到端训练，最后以结构约束强化学习（DHDO）提升表格、公式和格式闭合。（§3）

## 三阶段训练如何把子任务重新合起来

Stage 1 分开训练 text spotting、公式识别、表格识别和布局分析，让模型分别学习文字及位置、LaTeX、HTML 表格和区域类别。Stage 2 输入整页，目标直接生成 Markdown；训练标注统一了公式定界符、表格 HTML、标题层级和多栏阅读顺序。（§3.1–3.2）

Stage 3 的 DHDO 认为结构奖励应该服从感知准确度：当输出文本相似度低于 0.7 时，不启用结构奖励。文本使用去除标记后的编辑相似度；公式奖励兼顾能否通过 KaTeX 解析与图形结构相似度；表格奖励检查 HTML 嵌套、行列形状及 TEDS；另一项奖励约束 Markdown/HTML 标记闭合和标题层级。（§3.3.1）

这给出了一个有用的因果约束：先确认“读到的内容基本正确”，再奖励“排版结构正确”，避免模型为了一张形式合法的表格而牺牲文本。作者还将不同奖励分开归一化后再合并，减少在标准 GRPO 处理中不同尺度奖励信号被压扁的风险。（§3.3）

## 数据引擎既扩覆盖，也引入教师依赖

现有数据先经过由低成本到高成本的质量检查：先查 HTML/LaTeX 语法、边界框合法性等不需看图的规则；然后用版面分析与专业识别器核对内容位置、顺序和结构；最后让 VLM 对图像与标注作语义/视觉一致性判断。没有标注的网页文档则先布局拆分、再由文本/表格/公式专用工具生成伪标签；低置信样本会被过滤或送回修订。（§2）

这套分层流程比一次性让通用 VLM 扫描全部数据更可控，但规则检查只证明输出格式合法，专业模型与 VLM 验证也不是独立真值。多个生成/检查模型可能共享同类偏差，因此“层层校验”不能直接解释为有已知上界的标注错误率。论文说明了人工检查和伪标签流程，没有提供完整数据来源分布、分阶段误差率或标注者一致性统计。（§2）

## 作者报告的结果支持什么

在 OmniDocBench v1.5 上，作者报告 ABot-OCR 的整页总体分为 92.81；同表 PaddleOCR-VL-1.5 为 94.50。ABot-OCR 在端到端模型组中报告最高总体分，但对照中的流水线系统仍更高；其文字编辑距离 0.034 略低于 PaddleOCR-VL-1.5 的 0.035，而公式、表格等结构子项仍有差距。（§4.3.1–4.3.2，Table 2）

在 OmniDocBench v1.6 上，论文报告 ABot-OCR 总体分 93.30、文字编辑距离 0.037；表列 MinerU2.5-Pro 总体分为 95.69，Ovis2.6-30B-A3B 为 93.62，FireRed-OCR 为 93.20。（§4.3.3，Table 3）因此，这些结果支持“小型专门化端到端模型在该版本上具有竞争力”，不能概括成所有模型组中总体最高。

DHDO 消融也呈现目标间的取舍。相对于仅监督微调，混合文本、表格、公式三类 DHDO 的作者报告总体分由 91.71 升至 93.30、表格 TEDS 从 85.04 升至 88.83；单独强化 LaTeX 结构时，表格子结构改善，但 TextEdit 从 0.049 变为 0.047，恶化。混合奖励的收益说明分项目标需共同平衡，而不是只强化一个结构信号。（§4.3.5，Table 5）

论文还报告一个十语言内部评测集上的平均编辑距离 0.0624，但该数据集由作者构造，本文并未在报告中公开足以独立判断语言来源、样本分配和标注误差的详细信息。因此它是作者关于多语言能力的内部证据，不等同于独立公开基准上的普遍泛化证明。（§4.3.4，Table 4）

## 适用边界

- 单次生成 Markdown 简化了多组件部署，但仍受自回归长输出、遗漏和长距离结构错误影响；数据与奖励需要专门处理这些问题。
- DHDO 的阈值把结构奖励建立在文本相似度之上；文本评分本身若受标注噪声或归一化影响，奖励开关也会受影响。
- 作者的表格/公式结构检查贴合 HTML 与 LaTeX 输出规范，不能替代对表格语义、公式含义或图表数据正确性的完整验证。
- 两个公开基准结果不是统一硬件、同一解码预算的延迟比较；论文自己把提升推理效率列为未来方向。模型规模或总体分数不能直接代表真实服务吞吐。

ABot-OCR 与阿里 Logics-Parsing 都采用“监督训练打底、结构奖励补强”，但侧重点不同：Logics-Parsing 把框定位和段落读序作为奖励分项；ABot-OCR 把文本感知设成结构奖励的准入门槛，再分别检查公式、表格和标记闭合。它们的基准版本不同，适合比较设计思路，不适合拿总体分直接排高低。
