# MIPLIB-NL：把大规模 MIP 转成可对照的文本建模任务

**原文**：[Constructing Industrial-Scale Optimization Modeling Benchmark, arXiv 2602.10450v1](https://arxiv.org/html/2602.10450v1)。阅读 §§3.1–3.5、§4.1–4.4、Appendix B、E。

## 从已验证模型反向构造

MIPLIB-NL 从 MIPLIB 2017 选择一批 MILP，抽取紧凑循环结构，再配上自然语言说明、独立数据文件、数学模型和 solver code。它要保留原模型的数学内容，同时让问题能测模型是否恢复了索引、约束族和数据绑定；因此规模和结构比把数字写在一段短文字里更接近真实建模难点。[§3.1–3.3、Appendix B]

作者发布 223 个一一对应的实例，来自 MIPLIB 2017 一千多个模型中的代表性子集；选择受结构恢复与语义验证所需人工工作量限制。[§3.5] 这是一套从求解器模型反向生成自然语言的 benchmark，不是从业务人员日常需求中抽样的文本集。

## 两阶段验证与范围

论文先用最多 8 次独立 reconstruction 尝试检查一份描述：模型需重建数学 formulation 和 solver-executable code，solver outcome 在同配置下与发布实例匹配即通过。若所有尝试都失败，不直接判定 benchmark 错；转由专家和 LLM 检查 NL、外部数据与结构，并在发现生成错误时修订或剔除实例。[§3.4]

作者报告 245 个候选进入完整流程：163 个通过自动重建，另 82 个进入专家复核，其中 60 个修订后保留，22 个舍弃。8 个 infeasible 与 15 个 open 实例经专家验证后保留，但因没有 certified optimum，不纳入需要参考目标值的量化实验。[§3.4]

规模测试能揭示 toy benchmark 隐藏的结构困难；但其 NL 经 reverse generation 构造，并尽量显式涵盖模型结构。Pass@8 的存在性标准衡量“多次尝试至少有一次可重建”，不能读成单次模型可靠率或自然业务描述理解成功率。[§4.1–4.4]
