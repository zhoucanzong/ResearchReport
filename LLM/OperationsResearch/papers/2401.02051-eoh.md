# EoH：让算法思想和代码一起进化

**原文**：[Evolution of Heuristics, arXiv 2401.02051v3](https://arxiv.org/html/2401.02051v3)，ICML 2024。阅读 §§3–4、§4.3、Tables 6–7 与 Discussion。

## thought-code 双表示

EoH 的每个候选启发式由自然语言 thought 和 executable code 组成。LLM 可以先改写、组合算法思想，再生成对应代码；也有只改代码的算子。评价器在 online bin packing、TSP、flow-shop scheduling 实例上评估候选，进化选择让表现较好的 thought 与 code 继续参与搜索。[§3]

显式 thought 带来的价值，是把“算法如何决定下一步”的概念保留为搜索状态；研究者可以阅读，也可以在变异或交叉时组合两个算法思路。它不自动解释算法为何有效，仍需查看代码、实验条件和跨分布测试。

## 查询效率怎样解释才谨慎

EoH 在自己的 benchmark 设置里报告少量 LLM queries 可生成有效启发式，并引用 FunSearch 已报告的百万级样本规模作背景。论文针对在线装箱、TSP 和 flow shop 做实验；例如在线装箱使用 Weibull 生成的 5k-item 实例，并运行多次。[§4、§4.3]

这两个查询量来自不同系统的任务与配置，不能当作控制变量完全一致的 500 倍效率提升。在 EoH 自己的消融中，thought/code 联合进化优于只进化其中一种的设置；这支持二者在所测问题中的互补性，不证明所有搜索任务都必须采用双表示。[§4.3、Tables 6–7]

FunSearch 已把高分程序重新放入提示；EoH 的变化是让算法思想以显式自然语言形式保留并参与进化。两者都使用外部评价器与群体选择，不能把区别写成“独立生成 vs 第一次具备跨代学习”。
