# DataComp-LM：用固定训练预算比较数据策展

## 训练预算是比较设计的一部分

DataComp-LM 用固定 OpenLM decoder-only 配方训练策展后的语料，并按模型规模/训练 token budget 组织竞赛：1B-1x 为 1.4B 参数与 28.8B tokens；7B-1x 为 6.9B 参数与 138B tokens；7B-2x 为 6.9B 参数与 276B tokens（§3.2–3.5, Table 1）。下游比较使用 Core（22 个低方差任务）、Extended（53 项）及 MMLU 等。这个设计让研究者能问“固定模型与 token 预算后，数据策展策略带来什么差异”，而不是把更多训练 tokens 当成更优数据。

## 数据标签来源与阈值有可测量影响

在 1B-1x、约 28.8B tokens 下，FastText 过滤器以 OH-2.5 + ELI5 构造正例来源，Core/Extended 得分为 30.2/15.4；同表 RefinedWeb 重现 27.5/14.6，AskLLM 28.6/14.3，perplexity 29.0/15.0，top-k logits 29.2/14.7（§4.4, Table 4）。这是作者内部固定预算比较，不是独立团队复现。

在 7B-1x、138B-token 消融中，同为 10% 保留阈值，OH-2.5+ELI5 来源得到 Core/MMLU/Extended 41.0/29.2/21.4；Wikipedia 来源为 35.7/27.0/19.1。将 OH-2.5+ELI5 策略的保留阈值从 10% 放宽至 15% 和 20%，三项分数均下降（§4.4, Table 5）。这些结果支持“固定训练 token 预算时，标签定义与样本分布会改变评测结果”，不能直接证明这些来源在人类意义上具有普适更高的质量。

论文的人工标签小样本包含约 500 篇英文文档、16 位 AI 研究者/教授、平均标注一致率约 71%。AskLLM 在人工多数标签上的 ROC-AUC（约 .82）高于 FastText（约 .73），但用这些标签训练出的模型没有取得相应更好的下游分数（Appendix N）。这一结果只表明单篇文档的人类质量判断与所测训练效用不等价；不应概括成“人评无用”。

## 重要限制

- Datasheet 没有推荐 corpus-level train/dev/test split；策展策略会根据同一批下游基准反复筛选。因此这些结果是受控比较，但评测基准不是独立盲测集。
- 针对 MMLU 与 HellaSwag 的字符串污染移除是局部核查，不是 53 项任务全面无污染的证明。
- 论文没有充分估计 run-to-run variability；实验主要是英文和小模型规模。不要外推为中文、代码、多模态语料或更大模型上的过滤最优策略。版本、表格定位和具体局限见[来源清单](../sources/MANIFEST.md)。
- 7B 表格的早期低学习率配方与最终训练配方不同；表中大型预训练结果还引入额外数据来源和长上下文阶段，不能把最终分数全归因于筛选器。

**Reading takeaway:** DataComp-LM 的核心贡献是把数据策展变成能在固定模型和 token budget 下比较的实验问题。数据标签、正例来源、保留阈值与评测协议共同决定训练后的“质量”定义。详细版本与证据定位见[来源清单](../sources/MANIFEST.md)。
