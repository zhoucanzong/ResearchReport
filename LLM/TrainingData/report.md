# 训练数据策展：过滤、去重与预算如何改变模型测量

**范围**：用三篇受控研究说明训练数据处理怎样影响模型结果，重点比较网页文本抽取与过滤、去重粒度、重复数据与记忆，以及固定训练预算下的数据质量评估。本文不评选“最佳数据集”，也不把小模型英文网页实验外推为现代大模型的通用配方。

**核心结论**：数据质量不是只看单篇文档“像不像好文本”就能判定的内在标签。更可靠的问题是：固定模型、token预算与训练配方后，某种处理怎样改变下游训练效用、记忆行为和评测污染风险。现有证据同时给出三种边界：同预算下筛选策略会改变分数；跨快照全局去重可能丢弃对训练有用的文档；去重能大幅降低特定记忆测量，但不等于证明模型推理能力普遍提升。[S1–S3；证据定位见 sources/MANIFEST.md]

## 1. 数据处理不是单一的“质量过滤”

网页语料从抓取归档进入训练集，至少经历 HTML/文本抽取、语言与质量过滤、精确或近似去重、跨来源配比几个不同决策。每一步会改变样本数量、时间分布、语言/主题覆盖或文档结构。把最后的分数变化统一称为“高质量数据带来的提升”，会把处理路径与训练资源混在一起。

这三篇论文测量的问题不同：FineWeb 主要研究抽取/过滤/去重选择；DataComp-LM 把数据策展转化为固定模型与训练 token 预算下的比较；Deduplicating Training Data 主要测重复文本对生成记忆与验证困惑度的影响。它们可以互相补充，却不能合并成一个跨论文“数据质量分数”。详见 [FineWeb](papers/2406.17557-fineweb.md)、[DataComp-LM](papers/2406.11794-datacomp-lm.md) 与[去重和记忆](papers/2107.06499-deduplicating-training-data.md)。

## 2. 固定预算下，筛选信号能否预测训练效用

DataComp-LM 使用同一 OpenLM decoder-only 训练配方与分档模型/token预算比较候选数据策展策略。其尺度包括 1B-1x（1.4B 参数、28.8B 训练 tokens）、7B-1x（6.9B、138B tokens）和 7B-2x（6.9B、276B tokens）。论文以 Core 22 项低方差任务、Extended 53 项任务及 MMLU 等指标估计训练后的效用，而不是把人工文档标签直接当作答案。[S2 §3.2–3.5, Table 1]

在 1B-1x 条件下，fastText 过滤器使用 OH-2.5 与 ELI5 构造正例来源时，Core/Extended 为 30.2/15.4；同表中的 RefinedWeb 重现为 27.5/14.6，AskLLM 为 28.6/14.3，perplexity 阈值为 29.0/15.0，top-k logits 为 29.2/14.7（§4.4, Table 4）。这支持一个有限判断：在该数据池、模型和预算下，筛选信号与正负样本定义会改变训练效用。它不是对其他规模、领域或语言的普遍过滤器排名。

7B-1x、138B-token 消融继续改变 fastText 分类器的正例来源与保留阈值（§4.4, Table 5）。例如相同 10% 阈值下，OH-2.5+ELI5 来源得到 Core/MMLU/Extended 41.0/29.2/21.4；Wikipedia 来源为 35.7/27.0/19.1。将前一种策略阈值从 10% 放宽至 15%/20%，三个指标也随之下降。结果显示，在固定模型训练预算时，数据筛选改变的是被保留样本的分布，而不仅是训练 token 数。

**人类“可读质量”与训练效用并不等同。** DataComp-LM 的人工标注约含 500 篇英文文档、16 位 AI 研究者、每篇约 3 次标注，平均 IAA 约 71%。AskLLM 对多数标签的 ROC-AUC 高于 fastText，但相同训练流程下，基于这些人类标签的筛选模型没有相应超过基于 fastText 的下游效用。样本规模、英文范围和标签定义都有限；这说明单篇可读性判断不是训练效用的替代指标，不说明人评普遍无用。[S2 Appendix N]

## 3. 去重粒度会改变数据时间分布

FineWeb 在其固定的 1.71B Llama、GPT-2 tokenizer、2048 序列长度和约 2M global-batch-token 训练设置下，对相同训练 token 预算比较语料版本；多个主要消融使用两个数据/初始化种子，任务覆盖八项以英语为主的基准。论文的图中端点没有完整表格和误差区间，下面的图上差值只作近似阅读。[S1 §3.1–3.6, Figures 1–5, Appendix D]

FineWeb 的关键反例不是“不要去重”，而是**别把跨快照全局去重当作默认最优**。对约 96 个 Common Crawl 快照作跨快照 MinHash 去重，作者报告可把约 36T GPT-2 tokens 缩到约 4T，并大量删除较早快照；但在他们的 350B-token 数据比较中，全局去重只有 modest uplift，且部分设置落后 RefinedWeb。按单个快照分别去重可保留约 20T tokens，在相同实验设置下达到与 RefinedWeb 相近的分数。[S1 §3.4, Figure 3, Figure 5；[精读](papers/2406.17557-fineweb.md)]

同一旧快照的例子显示为什么：全局保留下来的约 31B tokens，表现低于从约 460B 已被全局去重剔除的材料中采出的 171B tokens（Figure 4）。作者检查样本后观察到保留集含更多广告、无关关键词列表和格式不良文本。跨快照保留优先较新内容，可能让某个较旧快照留下低质量尾部；因此重复率更低，不必然意味着训练样本更有用。上述效应只在作者的英文网页语料、模型和训练规模下成立。[S1 Figure 4; 精读见 papers/2406.17557-fineweb.md]

## 4. 去重的强证据是记忆减少，不是普遍能力增长

Deduplicating Training Data 对 C4 比较文档级近重复去重与 50-token 子串精确去重。两种干预不同：NearDup 移除整条近重复文档；ExactSubstr 从保留文档中删除重复片段。约 3.9% 的 NearDup 样例被移除；ExactSubstr 保持样例数但使 token 数从 177.3B 降到 165.4B（§4–5, Table 13）。

最清晰的效果是生成记忆：在 1.5B T5 XL 对 C4 的测量中，作者把无提示生成里落入训练集精确 50-token 子串的 token 视作记忆。原始训练集的比例为 epoch 1/2 的 1.926%/1.571%；NearDup 为 0.189%/0.264%；ExactSubstr 为 0.138%/0.168%（§6.2, Table 4）。论文也报告验证困惑度没有因此普遍变差，部分重复验证集上的拟合优势随去重消失。[S3 §6.1–6.2, Tables 4–5]

这篇研究明确没有测试下游 benchmark 能力是否因去重而提升。提示下的重复训练样例仍可被去重模型较好复现；去重也不能替代敏感数据过滤。因而可支持“减少某种定义下的可记忆训练片段”，不可扩写为“提升推理”“消除隐私风险”或“越多去重越强”。[S3 §2, §6.2, §7；定位见 sources/MANIFEST.md]

## 5. 读数据策展论文时的协议卡

| 必须固定的条件 | 为什么影响结论 |
| :-- | :-- |
| 抓取快照、文本抽取器、语言/质量规则 | 抽取和过滤会改变内容完整性与来源分布，FineWeb 的 WARC/WET 比较显示抽取方式可影响训练分数。 |
| MinHash shingles、阈值、去重范围、保留规则 | 全局/单快照、文档/子串去重删的是不同对象；时间顺序和源质量会影响被保留部分。 |
| 模型架构/初始化、tokenizer、训练 tokens/step、batch、学习率、seed | 需要判断收益来自语料，还是模型/算力/配方变化。 |
| 训练后指标、有效独立单位、任务样本和重复运行 | 训练集困惑度、下游分数、生成记忆和训练成本是不同结果，不能互换。 |
| train/validation/test 切分、benchmark 筛选历史、污染核查范围 | 评测被用来筛选策展方案后就不是独立盲测；只核查两个基准也不代表所有任务无污染。 |

这也改变了如何读库内厂商描述：[MiMo 报告](../../Models/MiMo/report.md)记录 URL + MinHash 全语料去重的流程和作者报告的一天处理时间；[DeepSeek 文本模型分册](../../Models/DeepSeek/deepseek-text-models.md)记录语料混合与中文占比。这些信息能说明流水线怎么搭建，但若没有同模型、同 token 预算和固定评测下的消融，不能单独证明该处理提升了模型能力。

## 6. 结论与证据边界

三篇论文支持一个方法论结论：**训练数据处理的价值要在明确预算、固定训练配方和目标任务下测量；去重还要明确粒度与时间范围。** DataComp-LM 显示固定 tokens 下筛选分布可改变任务结果，但论文也用评测集选择方案，且没有推荐 corpus-level train/dev/test split；FineWeb 展示全局去重的时间分布副作用；Deduplicating Training Data 更直接地支持减少特定生成记忆，却没有验证下游能力提升。

主要外推限制包括：FineWeb/DataComp-LM 以英文网页为主；小模型训练消融不能自动预测 70B 以上训练；不同基准之间的绝对分数不能跨论文横比；FineWeb 多为两 seed 且不少数值需从图读取，DataComp-LM 未充分研究 run-to-run 变异，记忆研究未覆盖所有类型数据或敏感信息。各论文完整章节、表图范围和未决问题见 [来源清单](sources/MANIFEST.md)；筛选与排除理由见 [候选清单](sources/CANDIDATES.md)。
