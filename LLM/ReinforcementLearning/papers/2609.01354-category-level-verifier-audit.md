# Where the Verifier Fails：RLVR 奖励信号的类别级审计

> **固定原文**：arXiv:2609.01354v1，2026-09-01，Esther Xin（Independent Researcher）。arXiv 页面标示 perpetual non-exclusive distribution license。原文：[HTML](https://arxiv.org/html/2609.01354v1)、[v1 PDF](https://arxiv.org/pdf/2609.01354v1)。缓存 PDF：`/Users/zhoucanzong/Documents/paper-cache/llm-rl-2026-10-23/2609.01354v1.pdf`，SHA-256 `bec99c27b3efd0f88a4ee57ada0492370984cf6efe2afc27fd87910178657ce7`。精读协议、四种 verifier 及结果、limitations；**未独立复现**。

## 亮点与差异

- **一句话亮点**：用可证明保持数学语义的 metamorphic answer 变换直接审计判分器，按答案类别拆解 false negative、执行失败与 false positive，显示 verifier 配置、字符串格式和数值尺度都会改变奖励信号。
- **方法贡献**：构造 43 种变换、14 个答案类别，使用 contract matrix 规定每种实现承诺处理的输入；把“返回错误 verdict”与“没有返回 verdict”分开计量，并以变换本身而非人工/模型裁决建立等价答案真值。
- **证据强度**：四种开源数学答案 verifier、4,990 个唯一 gold 答案（其中 2,000 个为合成答案）上共 307,420 次判定；报告 Wilson 置信区间，语料-only 分析仍成立。它是 verifier 级审计，不运行模型训练，不估计对 benchmark 分数或 RLVR 最终能力的因果影响；contract 划分含作者判断。
- **相对既有覆盖与引用边界**：与 [LLMs Gaming Verifiers](https://arxiv.org/html/2604.15149v1) 的归纳规则外延/同构验证对照互补：后者测模型能否利用任务评分规则；本篇测数学答案判分器对等价字符串、执行失败和数值误差的脆弱处。它也比主报告现有“有限单测留下未测行为无保证”的一般性提醒更具体，但不能据此声称这些格式错误已导致 RLVR 模型 reward hacking 或 benchmark 分数下降。

## 七问

1. **解决什么问题？** 已有 benchmark harness 报告自身对 gold answer 的 self-validation 约 94%，但总数没有说明哪些输出形式被拒绝，也掩盖 verifier 崩溃与错误拒答的区别。作者要分解这笔误差预算，并寻找误接受错误答案的具体机制。
2. **怎么建立可信的测试答案？** 给标准 gold (g) 应用语义保持变换 (T(g))，例如等价的 LaTeX/空格/标点形式；如果 verifier 拒绝，即为构造性可证的 false negative。对改变意义的 adversarial transform，若 verifier 接受则为 false positive。43 个变换归入 14 个 strata，并分成 certified-equivalent、contract-dependent、adversarial；contract-dependent 与超出实现承诺的输入只记录，不计为 bug。[§2.1–2.2]
3. **测试了什么？** 四个实现是 `math-verify` 默认 LaTeX 抽取、同库 plain-expression 配置、DeepSeek-Math 系 string normalizer、以及精确字符串→相对容差 (10^{-4}) 数值比较→SymPy 符号比较的参考 cascade。gold 来自 GSM8K、MATH 七科、Big-Math 和 2,000 个标准 MATH 答案形式的合成样本；ANTLR4 固定 4.13.2，五个 CPU 节点并行运行，单次子进程 5 秒预算。[§2.4–2.6]
4. **主要 false-negative 结果？** 在相同输入上的 self-validation 为 53.8%（mv-expr）、79.9%（mv-latex）、87.3%（sympy-cascade 全输入 coverage；只看有 verdict 的输入为 100%）和 95.2%（strip-string），跨度 41.3 个百分点。默认 LaTeX 配置的 in-contract false-negative 中 93.0% 来自空白/标点；plain-expression 配置为 74.1%。sympy-cascade 的残余主要是没有返回 verdict 的解析/执行失败，而另两个 math-verify 配置都返回 verdict、但错误拒答。须区分 self-val、coverage 和 judged 指标。[§3.1–3.2、Tables 1–3、Figures 1–2]
5. **发现什么 false-positive？** 参考 cascade 的 off-by-one 错答案接受率在金标准绝对值 (10^4) 处呈阶跃：低于阈值为 0%，达到或超过为 100%。相对容差 (10^{-4}) 导致 10,001 与 10,000 的相对差仅 0.01%，遂被接受。其汇总 false-positive 是 16.0%（95% CI 14.1–18.1，n=1,287），但均值遮住了阈值机制；另外三种 verifier 在该对抗变换上均拒绝。[§3.3、Table 4、Figure 3]
6. **结论适用范围与限制？** 结果说明实现、版本、抽取配置、runtime 和输入类别会改变 verifier 的 verdict；同一 math-verify library 两种配置对 49.9% 的测试对有分歧。作者明确不测任何模型的 benchmark 分数，也不运行 RLVR，真实模型输出并非以相同频率出现这些合成变体；仅测试开源实现，2,000/4,990 gold 为合成数据，contract assignment 可争论。作者报告语料-only 分析保持主要发现，但该研究本身不证明这些 verifier 缺陷会如何改变策略训练。[§3.4–3.5、§5]
7. **与已有工作的可判定区别？** *LLMs Gaming Verifiers* 展示任务设计中的外延 verifier 会鼓励模型枚举已给例子，而同构验证能在其归纳实验里抑制该捷径；本篇提供另一层：即便目标正确性是答案等价性，具体 parser、normalizer、执行覆盖和数值容差仍可能把正确字符串拒绝或把错误值接受。它是 verifier harness 的结构化审计，不是策略优化实验，也不是对前者结果的复现。
