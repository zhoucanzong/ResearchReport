# TOFU：用可控的虚构作者数据定义遗忘任务

来源：[TOFU: A Task of Fictitious Unlearning for LLMs](https://arxiv.org/html/2401.06121v1)，固定版本 v1。重点阅读 §1–§5，尤其 §2 的数据与指标、§4 的基线结果及 §5.1 的限制。

## 它先解决“要忘掉什么”不清楚的问题

机器遗忘希望把已训练模型改成一个在指定数据上“像从未训练过”的模型，而不重训完整模型。TOFU 指出，若直接用真实作者资料，模型可能早在预训练中见过这些知识，遗忘前后的差异就难归因；因此它构造 200 位虚构作者，每人 20 组问答，再把部分作者指定为 forget set。作者在基座上微调注入这些信息后，才执行遗忘。这样，待忘知识来源可控，比较目标也明确：unlearned model 应接近只在 retain data 上训练的 retrained model。[§1、§2.1](https://arxiv.org/html/2401.06121v1)

这个设计把“忘记”具体化为实体级删除：选定某位作者后，模型应不再回答与该人相关的信息，同时仍保留相邻作者、真实作者和一般世界知识。论文使用三个 forget-set 严重度（2、10、20 位作者）观察数据请求规模变化；基座包括 Llama-2-7B 和 Phi-1.5。[§2.1、§3–§4](https://arxiv.org/html/2401.06121v1)

## 为什么不能只看拒答或一个答案分数

TOFU 在 forget、retain、real-author 和 world-fact 四类集合上测模型效用；在遗忘集合上组合 ROUGE、答案概率与 truth ratio。Truth ratio 将正确答案改写为 paraphrase，并与若干模板相似但事实错误的答案比较概率，试图判断模型是否还偏向正确知识。多指标的原因是：ROUGE 低可能只说明模型输出变得含混；模型也可能拒绝回答，但仍在概率分布中保留正确答案信息。[§2.2.1–§2.2.3](https://arxiv.org/html/2401.06121v1)

该任务的主要教学点是**遗忘质量与保留效用必须一起看**。简单地对 forget set 做梯度上升可能连 retain set 一起破坏；加入 retain loss 或 KL 约束能在目标之间折中，但论文的基线整体仍未达到“像未见过 forget data”这一 retraining 参照。遗忘曲线还可能非单调：某种方法继续训练时，遗忘指标改善、保留能力又回升，或反向变化。[§3.2、§4](https://arxiv.org/html/2401.06121v1)

## 它作为基准的边界

- 虚构作者避免预训练语料污染，得到可控任务；但它不代表真实预训练集中的数据来源、重复和语义纠缠。
- TOFU 以实体级遗忘为主，不涵盖只删除某一条问答事实的 instance-level editing，也不把忘掉有害行为的 behavior-level alignment 纳入同一任务。[§5.1](https://arxiv.org/html/2401.06121v1)
- 它主要评估黑盒生成/答案行为，不能单独证明目标信息已从参数中不可恢复，也不是隐私保证。

**带走的区别**：TOFU 的贡献是一个可控的“forget vs retain”测量框架，不是某种普遍有效的遗忘算法。后续工作扩展它的评测目标时，应继续检查 retraining 参照、遗忘粒度、语义关联知识和潜在泄漏通道。
