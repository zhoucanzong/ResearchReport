# MEMIT：把多条事实更新分配到一组 MLP 层

来源：Meng et al., [*Mass-Editing Memory in a Transformer*](https://arxiv.org/html/2210.07229v1)，arXiv v1（2022-10-13）。建议读 §3–§5，特别是 §4.1–§4.3、§5.2–§5.4 与 Appendix B–D。

## 研究问题：单事实写入如何扩展成批量更新？

ROME 展示如何用一次局部权重更新改变一个事实。若要同时添加大量知识，逐条重复更新会造成编辑冲突、旧事实漂移以及不均匀权重变化。MEMIT 把任务改写成：对一批事实同时确定目标残差，再把这批残差有计划地分摊到若干关键 MLP 层。

## 方法：先求每条事实的目标表示，再分层注入残差

对每条编辑，MEMIT 优化最终关键层上的隐藏向量 (z_i)，使它能表达新目标宾语；随后把差值 (delta_i=z_i-h_i^L) 近似均匀分给关键 MLP 层。因为上游更新会改变下游激活，算法在逐层写入时重新计算后续表示。对一个线性层，多条更新被合并为批量线性系统；经验 key 协方差用于调节新事实拟合与已存关联保持之间的权重。[§4.1–§4.3、Figure 4](https://arxiv.org/html/2210.07229v1)

相比 ROME，MEMIT 不是简单重复 rank-one patch：批量目标共享一个矩阵求解，且编辑增量沿层深分摊。它提高更新容量，也引入新问题：同一层同时写入许多事实时残差相互作用；协方差样本、正则强度和目标层范围都会影响编辑的泛化与局部性。

## 如何读论文的“10,000 edits”结果

论文分别在 zsRE 和 CounterFact 设定下测试大批编辑。zsRE 表格偏向预测式 QA 指标；CounterFact 表格则把目标 efficacy、改写泛化、邻近事实 specificity 及生成质量分开报告。对 GPT-J 的 CounterFact 10,000-edit 设置，MEMIT 报告目标编辑与改写指标仍高，但邻近事实保持分数明显低于未编辑基线；在 GPT-NeoX 上结果不同。[§5.2、Tables 1–2](https://arxiv.org/html/2210.07229v1)

所以“支持一万条编辑”不等于“十万个事实都被无损更新”，而是作者在特定模型、编辑集、评价指标和协方差近似下测得该规模仍有可用编辑效能。zsRE 与 CounterFact 的结果不可混成同一 benchmark 的单一胜负。

## 失效边界：事实回忆与知识传播不是同一目标

编辑基准若只问原始事实，会漏掉被编辑事实对其它关系的推理后果。MQuAKE 用多跳问题检查相关 belief 是否随编辑事实发生应有变化，发现很多模型编辑方法可以回忆新事实，却无法在多跳链中正确使用它；这指出 MEMIT 的主要证据范围是局部事实编辑，不是对整个知识图谱的一致重写。[MQuAKE §1、§3–§5](https://arxiv.org/html/2305.14795v1)

持续追加编辑的可靠性还需要记录编辑顺序、冲突处理、reset/rollback 和旧模型输出的局部保持。MEMIT 的批量矩阵更新不是隐私删除协议，也不能由“记忆”隐喻推断它修改了模型里所有相关知识。

## 与 ROME、MEND 的关系

| 方法 | 更新单位 | 更新形态 | 主要要解决的问题 |
| :-- | :-- | :-- | :-- |
| [ROME](edit-rome-local-weight.md) | 单条事实 | 单层 rank-one 更新 | 能否对一个关联作局部写入 |
| [MEND](edit-mend-hypernetwork.md) | 单编辑样本 | editor 网络从梯度生成更新 | 如何让单次编辑快速且跨样本可学习 |
| MEMIT | 一批事实 | 批量求解并分层注入残差 | 如何让许多更新共同写入而不只逐条累积 |

它们都尝试“改变模型输出”；持续可撤销的 side memory 是另一种存储路线，见 [WISE](edit-wise-side-memory.md)。
