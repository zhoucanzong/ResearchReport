# 合成数据与自训练：模型生成的数据怎样变成训练信号？

> “合成数据”不是一种数据质量标签。它指数据由模型、规则或模拟器生成；它可能扩展任务覆盖、提供过程监督或降低人工标注成本，也可能复制教师偏差、放大评判器漏洞或压缩训练分布的长尾。本专题关心一条完整链：**数据从哪里来 → 怎样生成和筛选 → 用什么目标训练 → 如何独立判断收益和损失**。

## 1. 先把合成数据放回训练流程

把一个模型想成老师，合成数据就是它给学生准备的教材。但“老师写了很多题”只说明样本数量增加，并不能说明学生学到新能力。至少要区分：题目本身是否新；答案/推理是否可靠；标签或偏好从何而来；训练后是否在独立任务上变好；以及新增数据是否让原本少见的能力更难学。

```mermaid
flowchart LR
    A[种子任务/真实语料/模拟器] --> B[生成器提出样本或轨迹]
    B --> C[过滤器/评审器/验证器]
    C --> D[下游目标：SFT、偏好、RM、RL、预训练]
    D --> E[独立评测：能力、覆盖、保留与失效]
    E -->|发现缺口| B
```

每个方框都可能是另一模型或人工流程。若生成器、评审器和学生共享同一偏差，闭环可能让样本看起来越来越符合评分器，而不是越来越符合真实任务。因此解释论文时，要把“生成了什么数据”和“下游训练用了什么信号”拆开。

## 2. 四种任务：不要把所有合成样本叫作同一方法

| 合成数据任务 | 要解决的瓶颈 | 代表路线 | 主要验证问题 |
| :-- | :-- | :-- | :-- |
| 新建指令任务 | 人工指令覆盖有限 | [Self-Instruct](papers/instruction-self-instruct.md)、[Evol-Instruct](papers/instruction-evol-instruct.md) | 新样本是否增加任务/约束覆盖，而不只是改写或变难？ |
| 生成偏好与反馈 | 排序和批评标注成本高 | [UltraFeedback](papers/instruction-ultrafeedback.md) | 评审模型是否给出有效偏好，标签能否迁移到人类/任务目标？ |
| 生成推理轨迹 | 正确推理过程昂贵或稀疏 | [STaR](papers/reasoning-star.md)、[ReST](papers/reasoning-rest.md)、[Orca](papers/reasoning-orca.md) | 最终答案正确是否代表中间推理可靠？筛选会不会只留下容易题？ |
| 生成预训练/迭代语料 | 领域数据不足或模型需持续自举 | [真实/合成预训练配比](papers/feedback-pretraining-mixtures.md)、[递归训练与分布尾部](papers/feedback-recursive-model-collapse.md)、[迭代指令调优](papers/feedback-iterative-instruction.md) | 真实数据保留、迭代轮数和样本多样性如何影响遗忘/覆盖？ |

这些任务的训练目标也不同：SFT 学习目标答案或轨迹；偏好数据学习比较/奖励；RL rollout 把当前策略与环境反馈连起来；预训练语料改变语言分布本身。样本都由模型写出来，不代表它们可以交换使用。

## 3. 从任务池自举到难度演化

### Self-Instruct：模型如何提出“新任务”

Self-Instruct 从少量人工种子任务开始，让模型生成新的 instruction，再生成实例、去重和过滤，最后把保留项加回任务池继续迭代。它生成的是候选任务和任务实例，不只是为一条固定问题换个说法。分类任务可先枚举输出类别再生成输入，减少样本偏向多数标签；非分类任务则先生成输入再完成目标。[精读](papers/instruction-self-instruct.md)

这里生成顺序会改变数据分布。去重能移除明显词面重复，却不能保证语义上覆盖新任务；把视觉、代码等当前模型无法执行的题目排除，也会将生成集限定在教师能力范围内。作者的结果支持特定 GPT-3 初始化和过滤流程能够自举指令数据，不表示模型能靠自生成样本突破教师能力边界。

### Evol-Instruct：难度与覆盖是两条不同轴

Evol-Instruct 把已有任务作为搜索起点，分别做两类变换：in-depth 加限制、细化对象或增加推理步骤；in-breadth 扩展主题和任务类型。过滤器移除无实质变化、拒答或无效输出。[精读](papers/instruction-evol-instruct.md)

这说明“难度提升”和“能力覆盖变宽”应分别测量。若只不断加约束，数据集会向模型难以处理的长尾偏移；若只扩宽主题，任务深度可能没有增长。过滤器也有盲点：模型不能回答不必然说明题目无价值，模型能回答也不保证答案正确。

## 4. 合成偏好：评价管线也是训练数据来源

UltraFeedback 将多个指令集合与多模型回答组合，再用 GPT-4 按 instruction-following、helpfulness、truthfulness、honesty 等维度打分并生成 critique。一个提示下的多回答组内评分可减少不同提示之间的标准漂移；逐回答 critique 则提供额外文本监督。[精读](papers/instruction-ultrafeedback.md)

这条路线把标注成本转成评审模型和原则设计成本。偏好标签不等于客观真值：指令池决定覆盖，回答模型池决定候选风格，评分原则定义“好”的含义，judge 的错误再传到 reward model 或 PPO。要判断合成反馈有用，必须分别查看数据构造、judge 质量、奖励模型行为和下游策略结果；不能把下游模型分数提升全部归因于样本数量。

## 5. 推理轨迹：答案过滤、改进循环与教师解释

### STaR：用正确答案筛出可学习的理由

STaR 让模型先对问题生成 rationale 和答案；若答案正确，就把该轨迹作为监督样本；若错，则把正确答案作为条件，让模型尝试生成能支持目标答案的 rationale。过滤与再训练形成循环。[精读](papers/reasoning-star.md)

重要区别是：正确终答可验证时，理由仍可能是事后合理化或含有逻辑错误。轨迹质量取决于答案校验与 rationale 检查是否分开；如果只看答案对错，训练集会奖励“偶然答对但解释不成立”的样本。

### ReST：grow / improve 把采样和筛选分开

ReST 的 Grow 阶段从当前策略采样多条轨迹，再由奖励函数筛选；Improve 阶段在保留集合上做监督微调，并可重复下一轮。它把在线策略搜索转化成可缓存的离线数据循环，但保留集合会受到采样策略、奖励阈值和去重方式共同影响。[精读](papers/reasoning-rest.md)

这是与 RL rollout 的区别点：ReST 将成功/高分轨迹整理成监督数据后更新；在线 RL 则把策略更新与新 rollout 反馈继续闭环。两者可以组合，但数据来源和策略分布滞后不同。

### Orca：教师解释可以扩展监督，也会带入教师偏差

Orca 使用更强模型生成解释轨迹，并训练学生模仿教师的推理过程，而不只是复制最终答案。逐步解释能让监督包含“为什么”及中间决策；但轨迹依赖教师提示、教师能力和数据选择。解释写得连贯不等于它忠实展示了教师真实推理，也不自动证明学生学会了可泛化的算法。[精读](papers/reasoning-orca.md)

## 6. 递归使用合成数据：为什么混合比例和尾部覆盖重要

### 递归训练的风险是条件性的，不是“合成数据必然坍塌”

Model Collapse 研究显示，在某些生成分布被反复用于下一代训练的设定中，稀有模式可能逐渐流失，模型输出趋向高概率区域；从头训练的递归生成实验与将合成样本用于 LLM 微调不是同一协议。[递归数据精读](papers/feedback-recursive-model-collapse.md)

关键变量包括真实数据是否持续保留、每轮合成数据占比、生成器是否截断低概率尾部、过滤器会不会偏好模式化样本，以及迭代多少轮。因此不能从一次合成数据 SFT 的分数变化推出“模型已经发生 collapse”，也不能从单轮预训练有效推出无限递归仍可靠。

### 真实/合成混合与能力极化

单轮预训练比较、递归代际训练、迭代指令调优要分开读。合成教科书或改写网页在一个训练预算下可能改善某些能力；多轮迭代时，若选择器只保留模型已擅长的题型，训练分布可能逐步变窄。KITE 等迭代指令方法试图按能力弱项提出并筛选样本，但它的效果依赖错误诊断、外部验证器和具体循环协议。[配比研究](papers/feedback-pretraining-mixtures.md) · [迭代指令调优](papers/feedback-iterative-instruction.md)

模型生成的“难题”若由同一模型打分，也可能只是在优化自身偏好的题型；而能力极化不是一个总分下降就能识别的问题。应同时观察任务分布、长尾能力、保留集、模型族差异，以及变化能否在独立评测中复现。

## 7. 一条训练回路至少要保存哪些证据

| 环节 | 要记录/验证的对象 | 常见误读 |
| :-- | :-- | :-- |
| 数据来源 | 人工种子、真实语料、teacher/评审模型、模拟器、版本与许可 | 把“合成”当作来源已知或无版权风险 |
| 生成与筛选 | prompt、候选数、拒绝/过滤理由、去重和分布变化 | 只报告最终保留样本数量 |
| 训练使用 | SFT/偏好/RM/RL/预训练目标、token 预算、与真实数据比例 | 把不同目标下的样本统称“训练数据” |
| 评测 | 与训练生成器/judge 隔离的任务和答案验证、保留能力、跨域测试 | 用同一个 judge 生成数据又证明数据有效 |
| 迭代回路 | 是否复用模型生成、更新策略、累积版本和 rollback | 假设单轮收益可以线性延续多代 |

最有说服力的证据不是“生成了多少条数据”，而是固定或明确训练预算下，有没有比较数据构造/筛选消融，评测是否独立于生成器与 judge，以及新增能力是否以旧能力或多样性下降为代价。

## 8. 与相邻研究线的关系

- [训练数据策展](../TrainingData/report.md)研究真实语料抽取、过滤、去重和配比；本专题进一步看模型/模拟器主动生成样本后，生成器和筛选器如何改变分布。
- [模型对齐与后训练](../Alignment/report.md)研究偏好/规则/反馈如何成为训练目标；合成偏好只是这些目标的一种数据来源。
- [LLM 强化学习](../ReinforcementLearning/report.md)研究在线 rollout 与策略更新；ReST/合成轨迹 SFT 可离线更新，不能与在线 RL 混为一谈。
- [测试时学习与适应](../TestTimeAdaptation/report.md)更新测试期间的模型/fast weights；本专题主要研究预训练或后训练前生成的数据。
- [大模型辅助运筹](../OperationsResearch/report.md)与 [AI for Science](../../AI4Science/README.md) 展示合成任务/候选如何被求解器、模拟器或实验验证；生成答案不是外部真实性证明。

## 9. 推荐阅读顺序与开放问题

1. 从 [Self-Instruct](papers/instruction-self-instruct.md) 看任务池自举，再读 [Evol-Instruct](papers/instruction-evol-instruct.md)区分难度演化和覆盖扩展。
2. 读 [UltraFeedback](papers/instruction-ultrafeedback.md)理解合成偏好数据，再回到 Alignment 看反馈如何变成训练目标。
3. 读 [STaR](papers/reasoning-star.md)、[ReST](papers/reasoning-rest.md)、[Orca](papers/reasoning-orca.md)，比较答案筛选、离线改进和教师解释轨迹。
4. 最后对照递归训练、真实/合成预训练配比和迭代指令更新三篇反馈研究，检查多轮生成会不会改变长尾和能力分布。

仍开放的问题包括：合成标签能否在未知领域被独立验证；模型生成的多样性和难度怎样量化；judge 对生成器的偏好如何隔离；哪些领域/任务应持续混合真实数据；何时该停止递归；以及训练分布变化是否导致某些长尾能力或来源信息难以审计。
