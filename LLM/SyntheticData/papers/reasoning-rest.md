# ReST：把模型生成候选变成可重复利用的离线提升集

来源：[Reinforced Self-Training for Language Modeling](https://arxiv.org/html/2308.08998v1)，固定版本 v1。重点阅读 §3、§4 的 Grow/Improve 对照、§6 与 Appendix A。

## 它解决什么问题：在线采样昂贵，静态离线集又不会追随当前策略

RLHF 的在线训练会反复从最新策略采样并评分，计算成本随模型和训练步数增加；固定 preference dataset 则可能不含当前策略的新行为。ReST 把二者拆成两个循环：先从当前模型一次性生成一批候选，再在这批固定候选上做多次提升；策略改变后重新 Grow，形成外循环。

## Grow–Improve：先扩展行为，再筛选并训练

**Grow** 从当前策略对每个条件采样多个输出，把回答与输入组成增广数据集 (D_g)，再用 reward function 打分。**Improve** 通过阈值 (	au) 过滤较高奖励的样本，在固定 (D_g) 上用行为克隆或离线 RL 损失更新策略；阈值可逐步提高，数据变少但平均 reward 更高。之后再用改善过的策略生成新一轮数据。[§3、Algorithm 1](https://arxiv.org/html/2308.08998v1)

这使一份生成数据能承担多个 Improve 步，减少每个更新阶段都重新采样的成本；数据集也能被单独检查，观察 reward hacking。与此同时，过滤器会改变训练分布：高阈值可丢掉长尾条件或低分但有用的回答；稀疏/噪声 reward 下，阈值选择可能放大偶然的高分轨迹。

## 数据生成与在线 RL 的界线

ReST 是“在线生成、离线改进”的交替过程：每个 Grow 阶段从当前策略采样，后续 Improve 阶段复用固定样本。它并非只在静态合成数据上训练，也不是每个梯度步骤都重新 rollout 的标准 online RL。该算法在论文中用于机器翻译，奖励模型来自人工偏好，不是数学/代码等可验证答案奖励；它适合说明循环和数据复用机制，不应直接被当作推理数据生成的实验结论。

作者比较多种 Improve 损失后报告，在其实验任务和协议中行为克隆的 filtered-data 更新并不逊于复杂离线 RL；额外 Grow 可以继续提高 reward-model 分数，但人类评价不一定随 Grow 次数单调提升，重复迭代还会加剧对 reward model 过拟合风险。[§4、§6](https://arxiv.org/html/2308.08998v1) 这提醒读者：reward 上升、人工偏好与下游质量是不同观察量。

## 与 STaR 和推理合成数据的关系

[STaR](reasoning-star.md) 用答案正确性筛选 rationale，并用答案提示补齐初始模型解不出的题；ReST 用 reward model 对候选排序，标签不是“正确答案”，而是人工偏好的代理分数。两者都将模型生成文本写成训练数据，但过滤信号与优化对象不同。

在数学/代码推理中，ReST 式 Grow–Improve 的关键未决点是：怎样构造不被策略自身短板限制的候选；验证器是否真正检查推理步骤还是只看最终答案；固定候选池会不会让策略过拟合当前采样轨迹。它们需要通过独立任务、保留集和审计轨迹回答，不能由生成数据总量替代。

**带走的判断**：合成数据生成与 RL 并非互斥——模型可在线提出轨迹、离线筛选重用；但这条路径是否可靠，主要取决于 reward、候选覆盖和更新周期，而不取决于数据是否由模型生成这一标签。
