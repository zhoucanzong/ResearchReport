# GCG：对齐模型的离散后缀优化攻击

来源：Zou et al., [*Universal and Transferable Adversarial Attacks on Aligned Language Models*](https://arxiv.org/html/2307.15043v1)，固定版本 v1（2023-07-27）。重点阅读 §2.1–§2.3、§3.1–§3.3、§5–§6。

## 研究问题：白盒代理能否找到可迁移的攻击输入？

GCG 将攻击写成一个优化问题：在用户查询后追加一段可学习离散 token，使目标模型更可能输出预先指定的目标响应。它假定攻击者至少能对一个代理模型取得梯度；随后测试同一后缀能否迁移到不暴露梯度的其他模型。这里攻击的对象是拒答/安全行为的输入边界，不是模型新增了原本没有的知识或能力。[§2.1](https://arxiv.org/html/2307.15043v1)

## 机制：梯度选候选，离散前向做坐标替换

连续 embedding 上的梯度不能直接成为自然语言 token。GCG 对后缀中的一个位置计算目标响应 loss 对 token embedding 的梯度，用它挑出一小组可能有利的离散候选，再逐一做真实模型前向比较，替换该位置并循环搜索。这个 **greedy coordinate gradient-based search** 让梯度负责缩小候选，离散前向负责确认更新；它不是把反向传播直接穿过 tokenizer，也不是普通 prompt engineering。[§2.2](https://arxiv.org/html/2307.15043v1)

为了得到更通用的后缀，作者不是只对单个提示/单个模型搜索，而是把多种目标提示和多个可访问的开源代理放进同一目标，寻找跨条件较稳定的离散后缀。因而 transfer 不是攻击者没有白盒访问：攻击者在代理上优化，目标商业模型端才是黑盒。[§2.3、§3.2](https://arxiv.org/html/2307.15043v1)

## 论文结果能说明什么

作者在 AdvBench 的指定行为集合、模型版本、优化预算和成功判据下，报告 GCG 能诱导代理模型产生目标行为，并把搜到的后缀迁移到一些黑盒服务；结果依赖目标响应前缀、后缀搜索位置、代理模型和 judge 定义。[§3.1–§3.3](https://arxiv.org/html/2307.15043v1)

这支持“后训练对齐并不自动消除离散输入中的对抗脆弱性”，不支持所有产品、提示模板或防御下都能成功。不同论文若使用不同 harmful-behavior 集、judge、系统提示和成功标准，其 success rate 不可直接横排。

## 边界与带走的机制

- GCG 的后缀通常缺少自然可读性；后续工作将把可读性作为另一个目标，这说明攻击是否成功和输入是否像正常语言是两件事。
- 对代理模型有梯度是主要假设；黑盒迁移取决于代理与目标的训练/模板相似性。
- 目标响应字符串或自动判定器只是攻击成功代理，不是对真实危害、用户意图或全部模型安全性的证明。
- 该工作测的是“给定输入如何改变模型安全输出”，不等于模型本身因攻击获得了新知识。

**带走的区别**：GCG 的核心贡献是梯度指导离散搜索并尝试跨模型迁移；阅读时要同时看优化 access、目标响应、transfer 条件和成功判据。
