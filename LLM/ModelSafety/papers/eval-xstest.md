# XSTest：把过度拒答作为一类独立测量

来源：Röttger et al., [*XSTest: A Test Suite for Identifying Exaggerated Safety Behaviours in Large Language Models*](https://arxiv.org/html/2308.01263v3)，arXiv v3（2024-04-01），NAACL 2024。重点阅读 §3–§4、§5–§6，尤其 prompts、response taxonomy 与 limitations。

## 它补的是“安全”评测的另一侧

许多红队测试把目标设为让模型对有害请求合规；但若只记录 harmful compliance，就看不到模型是否把安全相关词语过度泛化，以致连明显无害请求也拒绝。XSTest 将此称为 exaggerated safety：例如在安全的体育、历史或日常语境中出现看似危险的词，不应自动触发拒答。[§1、§3.1](https://arxiv.org/html/2308.01263v3)

v3 包含 250 条安全提示，分成十类，并有 200 条不安全对照提示。每条安全提示都刻意与不安全语言在词面上相似；作者以人工方式创建 prompt，目标是诊断模型的拒答边界，而不是穷尽真实有害行为。评估把安全提示上的完全回答、部分拒答和完全拒答分开，因此“开头说不能帮助、后面仍给出回答”不会与干净合规混为一类。[§3.1–§3.3、Table 1](https://arxiv.org/html/2308.01263v3)

## 指标回答的是拒答校准，不是回答质量

XSTest 的主问题是安全提示是否被不必要地拒绝；它不规定每条安全提示唯一正确的答案，也不完整评价回答是否准确、充分或切题。作者在其 Llama 2、Mistral 7B 和 GPT-4 设置下用人工标注响应，报告不同系统提示会改变安全/有用性平衡，但这种改变并不一致。[§4.1–§4.3](https://arxiv.org/html/2308.01263v3)

安全提示通过只能说明模型未在这些特定词面/语境组合上过度拒绝，不能证明模型一般安全；unsafe contrast 中拒答也不等于能抵御自适应攻击。作者明确称该套件具有 **negative predictive power**：测试失败揭示一个特定弱点，测试通过则不证明广泛的能力或安全性。[§6](https://arxiv.org/html/2308.01263v3)

## 构念边界

- 250 条安全题和 200 条对照题均为单句英文、单轮交互；不测跨语言、长对话、工具使用或多模态攻击。
- 这些 prompt 是诊断性人工测试，并不提供对开放世界 harmlessness 的覆盖率保证。
- 论文报告模型/API、system prompt、温度与人工分类协议；跨版本复测要维持同样的提示和响应判定方法。
- v3 还承认模型响应会因很小的提示变化而翻转，专有 API 的重复结果也可能不稳定；因此应关注系统性失败模式，不从一个 prompt 个例推出总体安全结论。[§6](https://arxiv.org/html/2308.01263v3)

**带走的区别**：拒答过少与拒答过多是不同错误。安全评测若只优化攻击成功率，可能把“凡含敏感词都拒绝”的模型看成安全，却损害无害任务效用；反过来，XSTest 也不能替代 harmful-compliance 和自适应红队测试。
