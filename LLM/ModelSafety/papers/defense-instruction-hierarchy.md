# Instruction Hierarchy：训练模型分辨谁有权下达指令

来源：Wallace et al., [*The Instruction Hierarchy: Training LLMs to Prioritize Privileged Instructions*](https://arxiv.org/html/2404.13208v1)，arXiv v1（2024-04-19）。重点阅读 §1、§3.1–§3.2、§4 与 Appendix B.5。

## 研究问题：不同来源的指令冲突时，模型应服从哪一个？

聊天模型会同时看到开发者 system message、用户请求和第三方工具输出。应用设计者认为这些来源有不同权限；但若模型把它们都当作普通文本，网页或文件中的一段“忽略前文”可能覆盖开发者规则。Instruction Hierarchy 将这种问题定义为**消息来源与优先级冲突**：高权限指令应覆盖低权限但冲突的指令，而不冲突的低权限请求仍应执行。

这和“有害请求是否应拒绝”相关，却不是同一个判断。比如用户要求把安全的格式规则改成西班牙语，虽然低于 system 指令，若二者相容就应照做；只有冲突时才忽略低权限内容。防御目标不是“凡是看起来像攻击的文字都拒答”，而是让模型区分指令权限和语义冲突。[§1、§3.1](https://arxiv.org/html/2404.13208v1)

## 方法：合成不同优先级下的相容与冲突样本

作者通过自动化生成任务，先把复合请求拆成较小要求，再把它们放到不同来源/权限层级中，构造应服从或应忽略的例子；还利用 red-teamer LLM 生成直接/间接 prompt injection、系统提示抽取和 jailbreak 数据。模型随后用这些样本做 SFT 与 RLHF。它让“谁说了什么、是否和更高优先级冲突”成为训练监督，而不是只针对某个固定攻击字符串补丁。[§3.2、§4](https://arxiv.org/html/2404.13208v1)

论文在 GPT-3.5 Turbo 设置中报告，训练后在若干未参与构造的攻击评测上也有泛化；同时单独使用 benign / borderline prompts 检查 over-refusal。作者指出少数刻意构造的安全边界任务出现退化。结果支持“训练权限层级行为可提高特定攻击集鲁棒性”，不证明模型对所有越狱攻击都安全，也不证明经过层级训练的系统可替代应用层工具权限控制。[§4、Figure 2–4、Appendix B](https://arxiv.org/html/2404.13208v1)

## 与 Agent 工具安全的边界

论文把部分间接 prompt injection 放在模型输入层处理：模型要把工具输出视作低权限数据，而非可覆盖 system 规则的指令。但真实 Agent 的信息流、工具权限、代码执行沙箱和副作用控制仍由应用层决定。即使模型能正确识别冲突，若工具层授权过宽或执行层缺少确认/回滚，仍不能据此推出系统安全；这部分见 [工具 Agent 安全专题](../../../Agents/AgentSecurity/report.md)。

**带走的区别**：Instruction Hierarchy 训练的是模型的冲突处理行为；它不自动证明模型能可靠判断所有语义冲突，也不等同于对每类危险请求做统一拒绝。
