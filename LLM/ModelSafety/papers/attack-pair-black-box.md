# PAIR：用攻击模型与目标模型对话式改进提示

来源：Chao et al., [*Jailbreaking Black Box Large Language Models in Twenty Queries*](https://arxiv.org/html/2310.08419v1)，固定版本 v1（2023-10-12）。重点阅读 §2.1、§3.1–§3.4、§4.1–§4.3、Appendix A–B。

## 从白盒 token 搜索转向黑盒语义改写

PAIR 假设攻击者不能访问目标模型权重或梯度，但可以向目标查询，并得到其响应。一个 attacker LLM 根据当前目标和历史尝试提出候选提示；目标模型返回响应后，judge 判断这次是否满足给定的攻击目标；失败时，攻击模型将“提示—响应—评分”作为下一轮上下文继续改写。[§2.1、Figure 1](https://arxiv.org/html/2310.08419v1)

这是一种自动化的黑盒搜索环：

```text
attacker 提候选 → target 回答 → judge 按目标打分 → attacker 根据失败原因更新下一版
```

与 GCG/AutoDAN 不同，PAIR 不在目标 token logits 上做离散梯度优化，而把可读自然语言提示作为搜索对象；代价是每次改写都要消耗目标查询，结果还会依赖 attacker LLM 和 judge 的能力。它的“二十次查询”是论文在某些模型/目标设置中的观察，不是所有攻击都能用固定 query budget 成功。[§3、§4](https://arxiv.org/html/2310.08419v1)

## 成功标准由 judge 定义

论文把越狱写成一个提示—响应判定问题：judge 查看候选提示和目标响应，判断响应是否达成攻击者指定的不良目标。这个设计让黑盒攻击能够自动迭代，但也把一部分风险转移给 judge：judge 可能误判拒答、部分回应、引用讨论或边界内容；不同目标集合也会改变“成功”的含义。[§2.1、Appendix B](https://arxiv.org/html/2310.08419v1)

因此，PAIR 的数据结果不能只报“成功次数”。应同时说明目标任务、提示池、目标模型/系统提示、attacker 模型、judge 判据、query 预算和人工审查方式。论文的 transfer 结果也受模型版本和被测策略影响；它支持自动对话搜索可找到某些语义攻击，不证明对任何部署模型均有效。

## 三类攻击机制的比较

| 方法 | 目标端 access | 搜索对象 | 主要信号 | 主要代价/边界 |
| :-- | :-- | :-- | :-- | :-- |
| [GCG](attack-gcg-suffix.md) | 代理模型白盒优化，再测试黑盒迁移 | 离散 token 后缀 | 对目标响应 likelihood 的梯度/坐标替换 | 后缀可读性弱；transfer 依赖代理相似性 |
| [AutoDAN](attack-autodan-readable.md) | 优化阶段依赖代理信号，测试可迁移到目标 | 从左到右生成的可读 token 串 | 攻击目标 + 语言可读性 | 搜索复杂，judge/filter 和模型模板影响结果 |
| PAIR | 目标黑盒 query-only | 自然语言提示及其迭代版本 | 目标响应与自动 judge 反馈 | 查询预算、attacker/judge 可靠性决定效率 |

三者不是“攻击从弱到强”的单一演进轴：GCG 主攻离散 token 搜索与迁移，AutoDAN 加入可读性约束，PAIR 将目标响应反馈放入黑盒迭代。模型拒答是否被绕过，是输入与策略在特定接口下的结果，不表示攻击者获得模型权重，也不表示模型掌握了全新的能力。

## 证据边界

- 论文定义的 judge / target response 是评测代理；它不等于人工判断、真实用户风险或对所有未测危险类别的覆盖。
- 攻击者 access 需精确说明：可读梯度、代理白盒、目标黑盒查询、是否知道 system prompt 是不同威胁模型。
- 迁移率受模型架构、tokenizer、对齐训练、system prompt 和服务端过滤改变；不能把特定年份 API 的结果当作永久漏洞。
- 这类工作用于压力测试安全对齐和评估防御；精读应关注实验设计与防御含义，不复制论文中的攻击提示或有害目标内容。

**带走的区别**：PAIR 将目标模型反馈本身变成搜索信号；黑盒并不意味着无成本，也不意味着judge可以可靠定义安全成功。
