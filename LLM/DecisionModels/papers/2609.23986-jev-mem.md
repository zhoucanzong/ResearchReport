## 1 方法

**出发点**：现有 agentic memory 系统把**昂贵的自回归生成放在记忆操作的关键路径上**——用 LLM 决定"存什么、如何组织、如何检索、何时停止"。但作者的关键观察是：

> `many memory-control operations are semantic but not generative`——这些决策通常产出**有界输出**（标签、概率、分数），而非自由文本。

**三平面架构**：

| 平面 | 职责 |
|---|---|
| **System-One 控制平面** | 承担**写路径**（memory typing、冗余过滤、语义/时序/因果/实体**多关系构建**）与**读路径**（query routing、**检索预算分配**、图遍历、候选打分、证据充分性评估、**自适应停止**） |
| **结构化多关系记忆平面** | 共享的记忆数据面；保留"规范观察"以免过早信息损失，并**选择性构建关系**以抑制无谓的图连通性 |
| **System-Two 推理平面** | **仅在复杂推理与答案合成**时调用 |

**关键架构主张**：**同一控制平面统辖读写两条路径**（`This shared control plane is a key architectural property`）——记忆不由一套启发式构建、另一套启发式检索。

**Jev 的角色**：`Jev provides one concrete realization of the System-One controller through typed probabilistic decisions`——即 **Jev 只是 System-One 控制器的一种具体实现**，本文的**新意是架构层面的分工**，不是某个模型。

## 2 实验设置与条件

| 维度 | 具体设置 |
|---|---|
| **对照模型（baselines）** | 多种记忆系统 baseline，含 **A-MEM**、**MemoryOS**，以及**最快的竞争记忆系统**（build 时间 **1,044 s**、查询延迟 **1.47 s**）；另有**直接处理全上下文**（**1.74 s/query**）作为非记忆对照 |
| **缓存** | **未述跨请求缓存**；效率主张基于"把控制决策移出自回归循环 + 批量类型化决策 + 显式检索预算" |
| **工作负载** | **LoCoMo**（超长多会话对话）benchmark 上的长程问答 |
| **任务** | 需**时序、因果、跨会话推理**的信息找回；按 6 类问题分别报告 |
| **评价口径** | **LLM-as-a-Judge** 分数（judge 模型 = **gpt-4o-mini**）；效率指标 = **总记忆构建时间** 与 **平均每查询延迟** |

## 4 失效边界

1. **单一 benchmark**：全部量化结论来自 **LoCoMo**；**未**跨多个记忆 benchmark 验证。
2. **对照命名不完整**："最快的竞争记忆系统"（1,044 s / 1.47 s）在正文**未逐一点名**——主报告把它写成"最快的竞争记忆系统"是**忠实转述**，但**引用时不应自行补名**。
3. **效率口径无缓存假设**：**未述**跨请求缓存；% 降幅是在该配置下的端到端量测。
4. **judge 依赖**：效果用 **gpt-4o-mini** 作 LLM-as-a-Judge，**不是**人工标注；judge 更换可能改变排序。
5. **架构主张 vs 效果主张要分开**：作者自己声明**新意在架构分工**；"Jev 是唯一或最佳实现"**不是**本文结论（`Jev provides one concrete realization`）。
6. **代码可得性未证**：论文称代码公开，但正文**未给 URL**，故本文件**不主张**"可复现"（见 §7）。
7. **未报告**：跨请求缓存、token 成本、最慢案例、失败案例分布、judge 一致性。
