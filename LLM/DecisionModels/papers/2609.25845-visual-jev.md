## 1 方法

**问题**：许多视觉应用会对**同一张图**提出**若干互相独立的强制选择题**。逐一串行执行会**重复计算共享前缀**。

**Visual Jev 的执行模型**：
1. **图像 + 公共上下文编码一次**（vision encoder + shared prefix **KV cache**）；
2. 把**各问句后缀作为 batch** 执行；
3. **从 backbone 现有的 LM head 读候选 token 的概率**，并**在合法选项上归一化**。

> 预印本正文：`reads candidate-token probabilities from the existing LM head`；`LM head is the default; typed heads are matched controls`。

**readout 判定（重要）**：**默认走 backbone 自身的 LM head**；专用的 **typed/decision head 仅作匹配对照**，且本文结论是**不采用**它。

**可选控制头**：`optional controls: Choice / Claim / sufficiency heads`——**计算一次**。

## 4 失效边界

1. **"专用头更好"未被证实**：作者结论是**在给定数据、seed 与预算下无一致优势**，属**设计偏好**（选更简单的 LM-head 系统），**不是**证明两种训练严格等价（原文：`not evidence that the two training procedures are strictly equivalent`）。
2. **效率收益有硬条件**：
   - 需要**同时**知道同一张图的多个问题（共享 prefix 才有意义）；
   - 需要**可接受更高峰值内存**（8.40 → 10.10 GiB）；
   - **N=1 时反而更慢**（82.9 vs 48.1 ms）。
3. **"8.9×"是 warm amortized 口径**：报告的是总组时间 ÷ N，**不是**单题响应时间（单题在组内仍需等整组完成，约 182 ms）。
4. **质量增益不跨任务族泛化**：held-out 的 TextVQA / TallyQA 变化很小（`supports adaptation to the trained decision families, not a general claim of cross-task improvement`）。
5. **固定 slot 头有覆盖度陷阱**：训练时选项数覆盖不足会使后续 slot 无梯度（0.639 vs 0.973）。
6. **批处理不是数值恒等**：混合精度下 batched 与 prefix-fork 路径都会改变少量预测（0–20/7,532）；float32 才消除 argmax 翻转。
7. **可复现性缺口**：本文**未**提供公开权重、许可证或代码仓库（详见 [open-implementations.md §5](../open-implementations.md)）。

## 5 机制深读：共享视觉上下文到底省了什么

### 5.1 三类计算，只有一类能被摊销

把"一张图 + N 个强制选择题"拆成三段计算：

| 段 | 计算内容 | 与 N 的关系 | 能否摊销 |
|---|---|---|---|
| **A. 视觉编码** | 图像 → 视觉 token 特征 | 与 N **无关**（一次）| **可摊销**（N 越大越省）|
| **B. 公共前缀** | 视觉 token + 公共上下文进 KV cache | 与 N **无关** | **可摊销** |
| **C. 问题后缀 + 读出** | 各问句后缀分别前向、读候选 token 概率 | **正比于 N** | **不可摊销**（但可批量并行）|

**这就是论文效率结论的全部来源**：把 A+B 从"N 次"变成"1 次"，把 C 从"串行"变成"批处理"。**它不需要任何模型改动**——这是本文最实用的一点。

### 5.2 为什么 N=1 反而更慢

论文给的反例：N=1 时 prefix 共享 **82.9 ms vs 48.1 ms**。原因：

- A+B 的成本**只能摊到 1 个问题上**；
- 额外还要付出**缓存构建/扩展**的开销（复制、内存分配、调度）。

**推论**：consistency 要求的不是"永远共享"，而是"**在 N 足够大时才共享**"。N 的临界点取决于模型大小与图像分辨率——本文给的 N=32 是**测试点**，不是普适阈值（见 §10）。

### 5.3 "per-question 5.7 ms" 与 "group 182 ms" 不矛盾

论文同时给了两个数，容易被误读：

| 表述 | 含义 | 用法 |
|---|---|---|
| **5.7 ms/题**（N=32）| **摊销值** = 组总时间 ÷ 32 | 算吞吐、算单位成本 |
| **约 182 ms** | **组完成时间** = 从提交到 32 个答案全部返回 | 算**用户等待**。182 ÷ 32 ≈ 5.7，两者一致 |

**面试级问题**："32 题 5.7 ms 是不是说每题 5.7 ms 就返回？"——**不是**。单题不会 5.7 ms 返回；它是在批量里分摊后的平均。**引用时必须说明是摊销值。**

| 复用 prefix 相对批量 | 19.3 ÷ 5.7 | **3.4×**（与论文一致）✅ | — |

## 7 逐样本不等价：最值得写的"诚实披露"

论文报告了一个容易被忽略的结果：**6 条决策路径里 5 条得 0.9104、vision-cache 批处理路径得 0.9100**，且 **7,532 题中有 0–20 题的 argmax 预测与独立执行不同**。

| 事实 | 数值 | 含义 |
|---|---|---|
| 聚合准确率差 | 0.9104 vs 0.9100（**0.0004**）| 聚合上几乎不可见 |
| 逐样本 argmax 翻转 | **0–20 / 7,532**（≈0–0.27%）| 逐样本上**确实不同** |
| 数值来源 | 混合精度；float32 下最大概率差从 **1.8×10⁻¹** 降到 **1.4×10⁻⁵**，**翻转消失** | 差异来自数值路径 |
| 差异集中于 | top-2 边际很小的样例 | 可预测：边际小则易翻转 |

**这条为什么重要**：它说明"**聚合指标接近 ≠ 行为等价**"。若你的下游对**单条判定**敏感（如合规、拒赔），**不能**假设"换执行路径结果一样"——必须做**逐样本回归**。这是本文最该被引用的工程结论之一。

## 8 关键失效：slot-indexed 头的"无梯度槽位"

论文报告：held-out 的 **8 选项 TextVQA** 上，Choice head 只得 **0.639**，而它在"选项数 2–8 变化训练后"可达 **0.973**。

**机制**（按论文描述还原）：

| 环节 | 发生了什么 |
|---|---|
| 训练构造 | 早期 Choice 样例**最多 4 个选项** |
| 头结构 | **16-slot** 的 slot-indexed head |
| 梯度 | 第 5–16 个 slot **从未被监督** → 权重停留在初始化附近 |
| 推理 | 8 选项题用到第 5–8 个 slot → 输出**未训练过的分数** |
| 后果 | **0.639**（而非 0.973）|

**为什么 LM-head 读法不受影响**：它读的是**预训练候选 token 的概率**，token 的表示在预训练里已经见过；**不存在"槽位从未被监督"的问题**。

> **可迁移的教训**：任何"按槽位索引"的专用头，都要**确保每个槽位在训练里出现过**；否则失效是**静默的**（聚合上可能看不出来，直到遇到长选项的题）。这条也解释了论文为什么选 LM head 做默认。

## 9 与"专用头更优"这一常见预期的对照

| 维度 | answer SFT（LM head 读）| decision CE（专用 typed head）| 可判定性 |
|---|---|---|---|
| 等权 macro | **0.761** | **0.761**（四舍五入后同）| 论文口径 |
| 三 seed 区间 | 0.758–0.764 | 0.760–0.763 | **重叠** → 无一致优势 |

| 与同类的可判定差异 | §9（LM head vs typed head）+ §7（路径差异）|

## 14 与同族（this-that-model）的定位差异

| 维度 | Visual Jev（本篇）| this-that-model |
|---|---|---|
| 解决的问题 | **同图多问**的重复前缀计算 | **单问决策**的延迟与输出合法性 |
| 关键机制 | 视觉编码 + 公共前缀**只算一次**、后缀批处理 | 隐状态直读、**闭集 softmax**、零生成 |
| 是否改模型 | **不改**（复用 backbone 的 LM head）| 训练专用读出头 |
| 主要收益 | **吞吐**（8.9×，N=32）| **延迟**（30.9 ms）与**合法性** |
| 主要代价 | **峰值内存**（+1.70 GiB）| 输出空间**限于短标签** |
| 共同点 | 都强调"**不生成文本**、直接从已有表示读概率" | 同左 |
| 组合可能 | 可叠加：用共享前缀 + 闭集读出 → 多问、低延迟、合法输出 | 同左（但论文各自未测）|

> **重要**：这张表是**我们的定位整理**，不是任一论文的主张；两篇论文都没有互相比较。

## 15 术语表（本篇最小词汇集）

| 术语 | 含义 | 为什么重要 |
|---|---|---|
| **shared prefix KV cache** | 图像 + 公共上下文的 KV 只算一次并缓存 | 摊销的前提 |
| **warm amortized time** | 缓存已建好后的摊销耗时 | 与"冷启动"区别，引用时必须说明 |
| **group latency** | 一批 N 题从提交到全部返回的时间 | 用户实际等待 |
| **per-question cost** | 组时间 ÷ N | 只能用于吞吐/成本，不能当响应时间 |
| **slot-indexed head** | 每个选项槽位有独立参数的决策头 | 槽位未被训练即静默失效 |
| **matched control** | 同 backbone、同样例、同 prompt、同预算的对照组 | 论文用它证明"专用头无优势" |
| **argmax flip** | 因数值路径不同导致预测类别改变 | 聚合指标看不出的行为差异 |

## 16 审稿式问答（三个最容易被问到的）

**Q1：8.9× 到底是怎么来的？能直接引用吗？**
A：**不能直接引用而不说对照**。8.9× = 独立串行（50.7 ms/题）vs 批量+共享（5.7 ms/题）；其中"批量"贡献 2.6×、"共享"贡献 3.4×。**若你的系统本来就已经批处理**，那你只能拿到 3.4×。

**Q2：既然专用头没优势，为什么论文还做？**
A：**作为匹配对照**。没有它，"LM head 够用"就只是断言；有了它，才能说"在同等条件（同 backbone/样例/prompt/读出位置/预算）下，专用头没有一致优势"。**这是消融设计的价值，不是产品建议。**

**Q3：0–20/7,532 的翻转要紧吗？**
A：**取决于下游**。聚合准确率差 0.0004，几乎不可见；但若你的业务是"单条判定即执行"（合规、拒赔、自动退款），**翻转就是事故**。**建议**：上线前做逐样本回归，不要只看聚合指标。float32 下翻转消失，说明根因是数值精度而非算法。

## 17 内存与规模的边界（容易被忽略）

论文只给了 N=32 一个内存点（8.40 → 10.10 GiB，+20.2%）。**为什么这点重要**：

| 观察 | 推论 |
|---|---|
| 内存随 N 增长（共享批持有 N 份后缀 KV）| **N 不能无限增大**；吞吐提升会被显存上限截断 |
| N=1 时共享反而更慢（82.9 vs 48.1 ms）| 存在**盈亏平衡点**，只在 N 足够大时共享划算 |
| 论文未给 N 扫描曲线 | **不可外推到 N=64/128**；换硬件、换分辨率都要重测 |

**工程建议**：把 N 当**可调参数**，而不是固定 32；在目标硬件上扫 N ∈ {1,2,4,8,16,32,64} 找拐点。

## 19 三句话结论

1. **它省的是"共享部分"，不是"生成"**：视觉编码与公共前缀只算一次、后缀批处理；论文用"N=32 时生成 1 token 每题仍要 58.8 ms"证明主要收益不来自 decode。
2. **效率数字必须带对照**：8.9× 是"独立串行 vs 批量+共享"；共享本身 3.4×，批量 2.6×，单题等待约 182 ms（5.7 ms 是摊销值）。
3. **它最有价值的不是加速，而是两条诚实披露**：逐样本 argmax 有 0–20/7,532 翻转（聚合看不出）、专用 typed head 在长选项上**静默失效**（0.639 vs 0.973）——这两条都应进入任何"用决策头替代生成"的设计评审清单。
