## 1 方法

### 1.1 被评对象与契约（JEV 侧）

- TypeSafe JEV 是托管服务，接收结构化 state + 自然语言 instructions + 允许的输出类型；`Choice` 返回指定标签上的概率分布，`Noul` 返回是-概率，`Score` 返回有序档位概率。主实验每次请求只发一个 Choice 问题。
  find: `native Choice`（§4 / 表 5 单元）
- 接口同时返回原生 `confidence`（其分布的一个统计量）；原生 confidence 与最大标签概率的 Spearman 相关为 0.971 / 0.999 / 0.948（RewardBench / JudgeBench / HaluEval），因此全文统一用 `q = max_k p_k` 做置信度图、错误检测与上抛门控。
  find: `0.971, 0.999, and 0.948`（§4）
- 采集时 JEV 1.13.0 计费：输入 \$0.042 / 百万 token，输出不收。
  find: `0.042 per million input tokens`（§4）；表体 find: `0.042 / 0`（表 5，JEV 行）

### 1.2 对照侧契约

- 生成式评判者收到与 JEV **完全相同**的 instructions 与 state，被要求给出「决策 + 标签概率」且不给理由；其概率是言语化估计。
  find: `without a rationale`（§1、§4）
- 推理型模型用 low effort，唯 Qwen3.6 用默认 + JSON object 模式；其余 hosted 用 JSON schema 约束；两个 GPT-4.1 用 temperature 0（§4）。Skywork 只输出标量分数，其原始分数不进概率校准指标；每个回答单独打分、标量相等时给半分。
  find: `give half-credit to exact ties`（§4）
- PairRM（llm-blender/PairRM-hf）用上游 2,048-token 双序列 tokenizer、FP32，截断影响 7 个 RewardBench 与 59 个 JudgeBench 对，未截断者上分别得 67.7% 与 53.3%。
  find: `seven RewardBench and 59 JudgeBench`；find: `67.7% and 53.3%`（§4）

### 1.3 度量与统计口径（§4「Validity and metrics」）

- 输出校验：schema 字段、标签合法、概率有限、归一化（和容差 0.025）、verdict–argmax 一致；无效输出计入准确率分母。
  find: `sum tolerance 0.025`；find: `Invalid outcomes count as errors`（表 1 标题）
- 指标：accuracy、既有标签上的 macro-F1、多类 Brier、裁剪 NLL（下限 1e-6）、十桶 ECE；错误检测 AUROC 以 `1-q` 为分数。
  find: `clipped NLL (floor`；find: `10^{-6}`（§4）
- 配对差用 2,000 次 source-question cluster bootstrap；不做 repair/rerun，传输失败最多重试 3 次且全部保留。
  find: `2,000 source-question cluster bootstrap`；find: `at most three attempts`（§4）

### 1.4 级联机制与阈值冻结（本论文最易被误读处）

规则：JEV 输出置信度 `q`，`q ≥ τ` 时接受其裁决，否则上抛到更强评判者、由其给最终裁决。
find: `q\geq\tau`（图 5 MathML alttext）；find: `when confident, escalate when unsure`（图 4 标题）

对成对偏好，**两序各判一次、把概率对齐到语义响应后平均**：

$$\bar p(A)=\tfrac12\left[p_1(A,B)+1-p_1(B,A)\right]$$

find: `\bar{p}(A)=\tfrac{1}{2}`（式 (1) 的 LaTeX annotation）。精确并列给半分。
