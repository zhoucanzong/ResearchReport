## 1 方法

### 1.1 研究对象：三条 read-out 家族

论文审一个"类型化决策头"（typed decision head）：输入一个 typed question `q` + state `s` + 已声明选项集 `O=(o₁,…,o_k)`，渲染成**一个** encoder 输入；head 对每个选项出一个分数 `z_i`，经 `p = softmax(z/τ)` 返回分布；**非法候选在归一化前被 mask 掉**（实现是 `masked_fill` 把非法 logits 置一个极大的负值再 `softmax`；作者给出该常数，但含 `^{}` 上标、不便作逐字 find 串，故此处只保留操作名）——find: `masked_fill`。作者先证一条引理：

> **Lemma 1**：返回的决策对任意输入、任意权重、任意输入扰动都必是 `O` 的元素（§2；证明即"argmax 在 `O` 上取，`O` 外无概率质量"）。

由此推出对评测的三条后果，其中两条对本专题直接有用：**(i) 测出来的 0% type-error rate 不含关于模型的任何信息，它是 read-out 的属性**（find: `it is a property of the read-out`）；**(ii) 该保证与下文所有干预无关——"在 head 四个答案里错三个的条件下，它一样成立到底"**（find: `wrong on three answers in four`）。

| 家族 | 形态 | 原文依据（find） |
|---|---|---|
| **Marker read-out** | ModernBERT-large + 两层 transformer head；每个选项贡献一个 `[MASK]` marker token，对其上下文嵌入打分；带 question-type embedding 与 per-(type, k) 温度 | `ModernBERT-large encoder with a two-layer transformer head` |
| **Span-mean read-out** | DeBERTa-v3-large；一个选项的分数 = 其**整个渲染 span**（name **与** rubric）上 token 的均值；单一标量温度 | `DeBERTa-v3-large encoder` |
| **Hosted read-out** | 厂商自家产品，HTTP 调用，权重不可见；同为"renormalized-softmax 接口"，故 Lemma 1 对其同样成立 | `we cannot see its read-out and` |

三个家族的定位：`We study Jev and two Jev-like`（摘要，find 串即此）——即 Jev 系（含 vendor hosted 产品）与两个同族开源权重 checkpoint。作者**未在正文点名 checkpoint 的仓库名/revision**（§2 脚注 2 明说放在 released harness 里），因此本提取不对"哪个开源模型"作断言。

### 1.2 干预量：label–rubric swap（name↔definition 重映射）

**渲染**（§3 "Rendering"）：一个选项渲染为**名字后接定义**，即 `"no: <rubric>"` / `"yes: <rubric>"`；rubric 是任务自带的、定义该谓词的文本，name 只是标识符，**两者都对 encoder 可见**。

**工具**（§3 "The instrument"）：固定一个 item 与一对 option name `(ℓ₀, ℓ₁)`：

- **aligned 臂**：每个 name 绑自己的 rubric（as shipped）；
- **swapped 臂**：在两个 name 之间**交换 rubric**；
- **gold 全程挂在 rubric 上**——find: `model is unaffected by the swap`（原文：读 rubric 的模型不受 swap 影响，读 name 的模型反转）；
- **其余全部逐字节不变**：同样的 question、state、rubric 字符串、选项集、选项数。

**这一设计的关键性质**（回答任务书"只改名称↔定义绑定"一点）：干预是**声明式的、写在同一个输入里的、完全的**（§5：`declarative and complete`，不像 in-context demonstration 那样需要模型去猜映射），模型没有任何"没被告知映射"的借口。

**控制臂**（§3 "Control arm"）：对**同一个结构操作**换用**无极性名字** `0`/`1` 与 `A`/`B`。其作用是把"**词**"从"**通道**"里隔离出来——中性名上出现的任何位移，就是"当名字不含意义时，重新绑定本身要付的代价"。**正文所有效应都以它们为差（differences against them）**。

### 1.3 "decision flips 按被选定义而非返回名称计量"的精确含义

原文对 flip rate 的字面定义是（§3 "Metrics"，两行连续）：

- find: `flip rate, the fraction of items`
- find: `returned option changes between arms`

即"两臂之间**返回的 option 发生变化**的条目占比，不需要 label"。**但同一节的 aligned/swapped 定义立刻把口径锁死了**（§3 "The instrument"）：`model is unaffected by the swap` —— 这句话只有一种自洽读法：

- 若按**返回的 name 字符串**两臂对比：读 rubric 的模型在两臂会返回**不同的 name**（因为 name↔rubric 被交换了），它会被记成 **100% 翻转**，直接与"unaffected"矛盾；而纯 name 跟随者在两臂返回**同一个 name**，会被记成 **0% 翻转**，直接与主结果 76.92% 矛盾。
- 因此"returned option"在两臂对比时必须按**该选项当前绑定的定义/rubric 的身份**计（等价于：比较前先把 name 按其 rubric 重映射回去）。这样"读 rubric ⇒ 0% 翻转"与"读 name ⇒ 高翻转"才能同时成立。

**注意**：原文**没有显式写出**"按定义计量"这一步措辞（它只说 `returned option changes`），上述是从"gold 挂 rubric + unaffected/inverts 二元判据 + 76.92% 的方向"三者**反推的唯一自洽读法**，属本提取的推断而非原文定义，引用时请标为推断。两点旁证：① 交换被描述为 pure permutation——find: `the swap is a permutation of that`；② 作者明确把"翻转率高"与"排序失效"分开计量（§4.2：`negative`/`positive` 翻转 48.25% 但 AUROC 只从 .8258 到 .7579，"翻转率高估了损害"），说明"翻转"是定义层、排序是另一层。

### 1.4 指标

- **Balanced accuracy**（阈值 `p ≥ .5`）；
- **AUROC**（threshold-free ⇒ 把"排序信息丢失"与"操作点移动"分开）；
- **flip rate**（无需 label）；
- **difference-in-differences**（对中性控制的差），95% 区间用 **2000 次 bootstrap、按 record 聚类**——find: `bootstrap of 2000`；
- **test-retest floor**（仅 hosted：aligned 臂逐字节重复问两次，用与 flip rate 完全相同的口径打分，作为其下界）；
- **type-error rate**：find: `type-error rate, which is 0% everywhere`（正文口径，全条件 0%）。

## 4 失效边界

**（A）三类子设置不成立 / 被作者降级**

1. **失效形状只在 marker head 上成立。** marker **反转**、span-mean **稀释**、hosted **向机会水平塌陷**（.8146 → .5806，未穿过 0.5）。原文：类别**排序**在三族一致，**幅度不一致**，**失效形状也不一致**。find: `The ordering holds in all three`；`.8146`；`.5806`。任何"M 族反转"式表述都必须带 read-out 条件。
2. **`no`/`yes` 以外的极性对不普遍成立。** 4.3 明说其余极性对异质，只报区间 **12.3%–92.0%**，headline 只挂在**最小值 56.7%** 上；`negative`/`positive` 甚至只移动操作点（AUROC 保住 .7579 ⇒ "翻转率高估损害"）。find: `12.3–92.0%`；`56.7%`；`.7579`。
3. **"两个中性 pair 留在个位数"只对 marker head 成立。** Table 5 里 span-mean 的 `A`/`B` 是 **26.00%**（`0`/`1` 才 3.61%）——find: `26.00%`；`3.61%`；Table 7 的 span-mean 中性档是 **14.83%**（find: `14.83%`）。控制臂的"低位移"本身也是几何相关的。
4. **多元臂被作者降级为"方向性支持"**：该池 shipped accuracy 只有 **.5637**（k=6 时 **.167**，find: `.167 at`），作者明说读作对二元结果的方向性支持、不当第二个 headline（`we treat it as directional`）——find: `.5637`；`we treat it as directional`。
5. **opaque 名的"低翻转率"有上界**：span-mean 上 15 次抽签跨度 **2.00–31.61%**（s.d. 8.66），最宽的一签**比 `no`/`yes` 本身动得还多**（19.50%）⇒ 任何"换成随机串即可缓解"的命名规则都被这一条限住。find: `2.00–31.61%`；`s.d. 8.66`；`19.50%`。
6. **hosted 只有 5 组 opaque pair** 跑过（本地 read-out 是 15 组），且其"低翻转"落在自身非确定性地板附近（1.88% vs 地板量级 1.33% / 2.08%）。find: `first 5 through the hosted model`；`1.88%`；`at most 1.33%`；`2.08%`。

**（B）作者自陈的局限（§7 Limitations，逐条）**

1. 只审**两个 encoder checkpoint**（每种几何一个），**只做英文**；稀释机制能否定量迁移到其他架构**未测**（find: `in English; whether the dilution`）。
2. hosted 是**网络黑盒、单时点**：只能观察返回分布，**非确定性**（故有测得的地板），且"**该名字下服务的模型可能变**"；作者"看不到它的 read-out，也不给机制"（find: `we cannot see its read-out and`）。
3. **relabeling 的"保义程度"不齐**（"positive"合于发票对账，却不描述任何 agent-trace 属性），这正是 §4.3 用**逐谓词最小值**而非均值的原因；跨 relabeling 的**人工保义标注**是自然的下一步、本文没做。
4. **极性与训练词汇熟悉度未被本组臂分离**（`The two effects cannot be cleanly separated with these arms`），作者明确**不主张**分离；但方向令人不安：失效的**正是发货名**，而幸存的中性名**没工程师会选**。
5. **多臂池 shipped accuracy = .5637** ⇒ 只作方向性——find: `.5637`。
6. **只报告脆弱性与两条缓解，两条缓解都未评测**（用中性标识符 + 训练时随机化选项名把决策绑到 rubric；另有 curriculum rubric-following / option-ID debiasing / word-bias correction 三条"可用但本文不评"）。
7. **口径披露**（§3 "One disclosure"）：harness 把 question type 标为 `choice` 而非发货的 `noul`（`false`/`true` 两个 tag 渲染逐字节相同；`choice` 本是任意标签选项的接口本意类型）。这是唯一的分布外风险披露。
8. **600 条被排除**（通用 rubric 模板首词即相反极性标签 ⇒ name/definition 混杂），只作上界。
9. **摘要末句在源 HTML 中渲染损坏**：`Across all conditions, the type-error rate remains 0substantially.`（原文疑为 `0% … substantially`；find: `remains 0substantially`）。**不得据摘要这一句引述"0%"的口径**，应引正文 `type-error rate, which is 0% everywhere`。

**（C）本提取额外标注的读法风险**

- §1.3 的"按被选定义计量"是**推断**（原文只写 `returned option changes between arms`），引用时须标注。
- 三个家族**没有**一个通用的 frontier 生成式 LLM 对照；本文是"同契约内部"的对照研究，**不可**用于任何跨论文排行榜。
- checkpoint 的**仓库名与 revision 未在正文给出**（§2 脚注 2 说放在 released harness 中），故"这是哪个 Jev 系开源模型"在本源中**不可确证**。
