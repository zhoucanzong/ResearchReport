## 1 方法

**产物**：`this-that-model-1.0`，一个 **1.88B 参数的类型化决策模型**，自述"**答案直接从指定位置的隐藏状态读出**，并被限制在调用者声明的选项集内，因此不生成任何文本"。

**readout 机制（本文的实现要点）**：

> `one forward pass produces the hidden state at each answer position, and the distribution is a softmax over the option labels and nothing else.`

- **零采样**（`Nothing is sampled`）；**支撑集 = 声明选项集**：`a malformed answer is not unlikely, it is unrepresentable`。
- **标签设计**：**每个选项恰好占一个 token**。`n_k ≤ 10` 时用熟悉的 `(A) … (J)` 渲染；**超过则用 255 个大写字符串表**，tokenizer 将其映射到**单个 id**，从而"无论调用者声明多少选项都保持单次 gather"。
- **训练目标**：对**严格 proper scoring rule** 训练（§3.3），故"模型除如实报告其信念外无改进损失之途"——这是**阈值可路由**的前提。
- **N 问共享一次前向**：因答案不回写 prompt，各决策在给定输入下**条件独立**；N 问的成本是**一次**过 state（`one pass over |S| + Σ|q_k| + N`），而非 N 次。

**明确不主张**：`It is not a claim to be more accurate than a frontier model`——作者自陈在"较难的一半测试集"上不如 frontier 模型。

**开源与许可**（论文正文）：`the same interface under the MIT licence; it contributes the environment simulator and the recorded hosted-service cohort`——项目以 **MIT** 发布，并包含环境模拟器与真实托管服务队列记录。上游致谢：环境模拟器与 68 题队列来自 **NanoJev**（[模型卡](https://huggingface.co/flock-io/this-that-model-1.0)）。

## 4 失效边界

1. **不是"比 frontier 更准"**：作者**明说不是**（`It is not a claim to be more accurate than a frontier model`），且在自建 suite 的**较难一半**上确实不如。
2. **基准是自建的**：主要能力证据来自**本组构建并发布**的 benchmark（`a benchmark we built and released for this`），**非第三方独立评测**。
3. **30.9 ms 的条件是"一张笔记本 GPU"**：型号、batch、上下文长度、是否含预处理均**未在句中给出**；与模型卡主张的 31 ms 是**不同材料的两个数**。
4. **0.750 vs 0.746 的口径特殊**：这是"真实答案是**计算出的概率**"的**唯一一族**测量，且上限 0.746 被作者表述为"任何预测器都无法超过"——**不能**读作通用准确率。
5. **成本 `$10.636/千问` 是 API 对照价**，不是该模型自身的边际成本（作者称自身边际成本为"电费量级"，**未给数字**）。
6. **"百万分之一美分"是标题修辞**：正文**未**给出可复算到该量级的成本推导。
7. **模型卡自陈的分布外例子存在张力**：模型卡称某离训练分布的问题返回 `no (71%)` 为 `unconfident`，但 71% 按常规阈值并不低（详见 [open-implementations.md §1.5](../open-implementations.md)）。

## 8 机制深读（把"读出"拆成三步）

### 8.1 readout 数学：为什么它能"不生成文本"

模型卡给的读出头：`p_k(j | x) = softmax_j( ⟨w_{ℓ(k,j)}, h_k⟩ / τ )`。把它逐项拆开：

| 符号 | 含义 | 可判定性 |
|---|---|---|
| `h_k` | 第 k 个答案位置上的隐藏状态 | 论文说"one forward pass produces the hidden state at each answer position"，**位置由 prompt 结构确定** |
| `w_{ℓ(k,j)}` | 第 j 个选项对应标签 token 的 embedding（行向量） | 即"用标签 token 当一个线性分类器的权重" |
| `τ` | 温度 | **论文正文未给取值**；模型卡给出公式但**未给 τ 数值** → 标未确证 |
| `softmax_j` | **只在声明选项集内**归一化 | 这正是"支撑集=选项集"的数学表达：集合外选项概率恒为 0 |

**关键推论**：因为分母只对声明选项求和，**任何不在选项集内的答案在数学上不可表达**（`a malformed answer is not unlikely, it is unrepresentable`）。这不是"约束采样"（生成后过滤），而是**从输出空间就把非法答案删掉**——两者在工程上差别很大：前者要重采样、后者不需要。

### 8.2 为什么必须是"单 token 标签"

若一个选项要多个 token 表达（如 `"yes, but only after review"`），readout 就无法用"一次 gather"完成——需要逐 token 解码，退化成生成模型。论文的解法是：

- 选项 ≤ 10：用 `(A) … (J)` 这类**人类熟悉的单 token**；
- 选项 > 10：用**255 个大写字符串表**，并让 tokenizer 把它们**各自映射到唯一 id**。

**工程含义**：这套设计把"选项数"从"模型能力"问题降级为"tokenizer 工程"问题。**代价**是选项必须是**短原子标签**，无法承载带语义的长选项（这属于本文未测试的边界，见 §9）。

### 8.3 为什么必须用 strict proper scoring rule 训练

论文说"模型除如实报告其信念外无改进损失之途"。这句话的实际作用是**支撑下游的路由决策**：

- 若损失不是 proper，模型会倾向于**过度自信**（在某些损失下，虚报置信度能降损失）；
- 若损失是 strict proper，**最优策略就是报告真实后验** → 下游用"概率阈值"做路由（如 >0.9 才自动执行，否则转人工）才有意义。

**这是本论文最值得引用的一条方法论结论**：**"可路由的置信度"不是训练完自然出现的，而是由损失函数保证的**。它也可以反向用于评估其它"带置信度"的决策模型：先问它的训练目标是不是 proper。

## 9 成本与吞吐复算（我们的算式，非原文）

原文给出：30.9 ms/次、32 decisions/second、\$10.636/千问（API 对照价）。三者关系复算：

| 复算项 | 算式 | 结果 | 与原文一致性 |
|---|---|---|---|
| 由 30.9 ms 推吞吐 | 1000 ms ÷ 30.9 ms | **32.4 次/秒** | 与"32 decisions/second"**一致**（取整）|
| 由吞吐推单次时延 | 1000 ÷ 32 | 31.25 ms | 与 30.9 ms 一致（舍入）|
| API 对照价 / 次 | \$10.636 ÷ 1000 | **\$0.010636 / 次** | 原文只给千问价，此为单位换算 |
| 若 100 万次/月 | 1,000×\$10.636 | **\$10,636 / 月** | 换算，非原文 |
| 自建成本的**可算部分** | 电费 ≈ 笔记本 GPU 功耗(W) × 时长(h) × 电价 | **无法算**（原文未给功耗/电价）| **"百万分之一美分"不可复算**（§4 第 6 条）|

> **纪律**：上表最后一行是**拒绝给数字**，因为补齐它需要的两个量（功耗、电价）原文都没有。**"不可复算"要明说，不能靠乘法硬凑**。

## 10 与"前沿模型 + 结构化输出"的对照（不排名，只列可判定差异）

| 维度 | this-that-model-1.0 | 前沿 LLM + JSON schema 约束 | 可判定性 |
|---|---|---|---|
| 输出空间 | **声明选项集的子集**（数学上排除非法值）| 语义上约束、实现上靠解析/重试 | **可判定**（前者是闭集）|
| 延迟 | 30.9 ms（笔记本 GPU，单问）| 取决于模型规模与解码长度 | 条件不同，**不可直接比** |
| 成本 | API 对照 \$10.636/千问；自建未给 | 按 token 计费 | **不可直接比**（口径不同）|
| 准确率 | 作者**自陈不如** frontier（自建 suite 难的一半）| — | **作者承认**，属已知边界 |
| 置信度可用性 | 由 proper 训练保证 | 通常未校准，需额外校准 | **可判定**（前者有理论基础）|
| 多问并行 | N 问共享一次前向、条件独立 | N 次调用（或共享前缀缓存）| **可判定** |

**结论**：它不是"更准的模型"，而是"**在已知会答对的子集上，把延迟/成本/合法性压到可路由的水平**"。**用它的正确姿势是"分层路由"**：路由层先把简单分支交给它，难的交回 frontier——这也正是报告 §7.1 的论点。

## 17 三个典型场景的判断

| 场景 | 是否适用 | 理由（带条件）|
|---|---|---|
| 客服工单的"该退/该换/该升级"三分支 | **适用** | 选项短、原子、闭集；延迟 30 ms 可每请求求值 |
| 需要长文本结论（如"给出整改方案"）| **不适用** | 输出空间被限制为单 token 标签，无法生成文本 |
| 高风险动作前的"要不要人工复核" | **适用（作为路由层）** | 前提是阈值经本地校准；作者未给校准方法，需自测 |
| 多问题同源（一份输入问 N 个判断）| **适用** | N 问共享一次前向、条件独立；但每问都要有独立选项集 |

## 18 术语表（读这一类论文的最小词汇集）

| 术语 | 本文里的意思 | 为什么重要 |
|---|---|---|
| **typed decision model** | 输出被限制在"调用者声明的类型/选项集"内的决策模型 | 与"生成后解析"区分：前者从输出空间排除非法值 |
| **readout head** | 从指定位置的隐状态直接线性打分到标签的读出头 | 不经过解码器，所以没有 token-by-token 延迟 |
| **closed-set softmax** | 只在声明选项集上做 softmax（分母不含全集）| 数学上保证非法答案概率为 0 |
| **proper scoring rule** | 期望损失在"报告真实概率"时最小的评分规则；strict 版本唯一最优 | 保证置信度可被下游阈值路由使用 |
| **routing threshold** | 下游按置信度决定"自动处理 or 转人工"的分界 | 需要校准；本文未给校准方法 |
| **single-token label** | 每个选项恰好映射一个 token id | 保证一次 gather 完成所有选项打分 |
| **state sharing** | N 个问题共享同一次前向的隐状态 | 多问成本 ≈ 单问，而非 N 倍 |

## 19 审稿式问答（挑三个最容易被问到的）

**Q1：既然不如 frontier，为什么值得写？**
A：因为它不是"准确率竞赛"的参赛者，而是**分层路由的下层**。在"有知识的人一秒能判断"的分支上，它把延迟压到 30 ms、成本压到 API 的千问 \$10.636 之下，同时**保证输出合法**（闭集）。**收益在系统工程层，不在榜单层**。这个定位是作者自己在 §1 说清的，不是我们的推论。

**Q2：自建 benchmark 的结果能信吗？**
A：**只能当"作者声称的上界"**。本文的处理是：把"能力证据来自自建 suite"写进失效边界第 2 条，并把"较难一半不如 frontier"（作者自陈）并列。**没有第三方复现前，不升级为"已评测能力"**。这也是我们全库的统一做法。

**Q3：30.9 ms 能复现吗？**
A：**目前不能**。缺少：GPU 型号、batch、上下文长度、是否含预处理、测量方式（p50/p99）。**能复现的只有"它在一个笔记本级 GPU 上做到了几十毫秒"这一量级判断**。若你要在自己的场景引用，必须先自测。
