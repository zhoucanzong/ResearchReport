## 1 方法

**问题**：双过程 Agent——快策略 + 慢深思。真实场景中慢模型常**连续运行**；而在**回合制**与**机器人规划**中，它由**事件**触发（不确定或检测到失败）。

**本文设定**：一个**快速 learned actor 承担每一个决策**，仅在**门（gate）打开**时把控制权交给**推理型 vision-language model**，且**游戏实时继续**。

**环境与接口**：
- **闭环 Doom**（实时）；
- 新开源的 **"System One" 类型化决策模型**（**0.15B–9B**），全部经**同一 llama.cpp 接口**服务——这是"同一接口横向比较多个决策模型"的少见设计；
- **900 个 held-out 问题**。

**四条研究线**：① 零样本 actor 的行为偏差与准确率；② 准确率/校准/**敏感度**（置信度区分对错的 AUROC）三者**不是同一件事**；③ **离线**"把最不确定的一批交给推理模型"相对随机延迟的增益；④ **闭环**（33 局、3 个 seed）实机后果与失败链分析。

## 4 失效边界

1. **本文的最强结论是负面的**：闭环下**没有任何变体到达出口**；因此**不能**把离线门控增益读成"实时可用"。
2. **离线增益与闭环成功是两回事**：`rank correlation 0.87` 与 `+0.13` 是**离线延迟实验**的结果；闭环里**固定规则覆盖同样多的地**（`a fixed rule behind the same gate covers the same ground`）。引用时**必须**分开。
3. **"最好的 actor 不是该用的那个"**：作者明确 `the most accurate zero-shot actors are not the ones to use`——选型应看**敏感度（AUROC）**而非准确率。
4. **延迟率 15% 与 30% 是不同实验的量**：**30%** 出现在"增益正比于 AUROC"的离线扫描；**约 15%** 出现在"匹配大模型"的另一处表述。**两者不可混用**。
5. **状态可观测性限制**：推理模型把普通门误判为锁门，因为**状态本身无法区分**——这是**环境/表示**的限制，而非单纯模型能力问题。
6. **单一环境与规模**：结论来自**闭环 Doom**、**33 局 / 3 seed**、**900 个 held-out 问题**；游戏化环境与生产 agent 的差异**未**被论证。
7. **选项顺序是一个活跃混淆项**：正确答案在首位占 **41%**（已每局打乱），且**顺序确实改变部分模型准确率**——横比模型时必须固定或报告顺序方案。
8. **作者披露了 AI 辅助写作与编码**（见 §3 末行）；所有数字取自发布数据。
