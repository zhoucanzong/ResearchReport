# Interpretability in the Wild：IOI 电路如何暴露解释的冗余与不完整

来源：[arXiv v1](https://arxiv.org/html/2211.00593v1)，2022-11-01；ICLR 2023。阅读重点：§1–3、§5–6。

## 任务为何适合电路研究

Indirect Object Identification（IOI）任务要求模型在模板化自然语言句式中识别间接宾语，例如完成 “When Mary and John went to the store, John gave a drink to …” 时选择 Mary。行为目标清楚，可以提出可读算法：追踪重复出现的人名和句法角色，再把间接宾语信息送到输出位置。

作者用 path patching 从输出 logit 反向追踪候选路径，并结合 embedding-space projection、attention pattern 分析、activation patching 和 head knockout，提出 26 个 attention heads、7 类功能组成的候选子图。[§1–3](https://arxiv.org/html/2211.00593v1)

## 路径分解与验证标准

IOI 电路中，有些 heads 搬运姓名，有些抑制重复姓名或影响 Name Mover 的查询，也有写入错误方向的 negative name mover。不同干预问的是不同问题：

- **Path patching**：某个上游 head 是否通过特定边影响下游 head 或输出？
- **Activation patching / knockout**：替换或移除一个节点后，目标输出改变多少？
- **完整子图运行**：保留候选组件、破坏补集后，目标行为是否仍在？

论文用 faithfulness、completeness、minimality 讨论解释质量：faithfulness 检查只运行候选电路是否保留模型的目标表现；completeness 比较对候选电路的同一子集作 knockout 后，子图和全模型是否仍有相近变化；minimality 则检查每个节点是否在合适上下文下确有边际作用。Completeness 需要考虑电路子集的组合，论文用随机、head class 和贪心寻找不完整的反例，而非穷举全部集合。三个量都针对指定 IOI 模板、logit-difference 指标和选定干预方式，不是对模型机制的通用认证。[§4–6](https://arxiv.org/html/2211.00593v1)

## 一个反直觉的结果：模型会有备用路径

论文发现若干 “Backup Name-Mover Heads”：常规 Name Mover 被消融后，它们才接管输出。这带来重要后果：

1. 观察常规运行的激活不能保证发现所有潜在路径；
2. 干预会改变其他部件的作用，因而“消融后行为变化”需要连同替代路径读；
3. 一个任务电路的组成可能依赖模型状态和干预方式。

已识别电路能完成任务，支持其在该设定下足够执行；但若补集或备用机制仍贡献行为，完整性仍有限。反过来，过度剔除节点也可能让模型进入训练分布外的激活状态。

## 阅读所得与边界

IOI 工作把机制分析从合成模式推到一个自然语言任务，并把解释评估变成明确问题；但它仍分析固定的 GPT-2 Small、特定模板和狭窄行为。26 个 heads 不是“GPT-2 的一般推理电路”，也不代表更大模型可直接复用同一图。
