# 视觉语言模型：视觉表示如何进入语言模型

视觉语言模型（Vision-Language Model, VLM）的核心问题不是给 LLM 前面“接一个视觉编码器”这么简单，而是如何把图像/视频像素转成语言模型能读取的表示、如何选择视觉信息压缩到多少 token、哪些视觉细节在连接器中被保留或丢失，以及训练目标是否让模型学会把视觉证据用于回答。

不同 VLM 论文常被排成单一代际路线，但它们解决的并非完全相同的问题：CLIP 主要学习图文共同嵌入，Flamingo 和 BLIP-2 探索怎样复用冻结的视觉/语言模型，LLaVA 以视觉指令数据教会语言模型进行图像对话；高分辨率与视频模型则面对视觉 token 预算、时空位置和输入采样。理解这些方案要同时看**表示、连接器、训练目标、证据接口和评测协议**。

## 1. 先区分目标与接口

同一模型家族可以同时包含对比学习、图文生成、指令跟随、定位和视频理解等训练目标；“视觉语言模型”不是一个单一目标函数。用图文对比损失训练的双塔模型能判断图文是否匹配，但它并不因此变成开放式视觉问答模型；一个能生成流畅图片描述的视觉对话模型，也不因此证明自己可以精确数小物体或引用页面区域。

典型生成式管线可以抽象成三部分：

```text
图像/视频 → Vision Encoder → Connector / Merger → LLM → 文本或结构化输出
```

- **Vision Encoder** 把像素或视频帧转为 patch/区域特征。它决定空间分辨率、局部视觉信息和预训练视觉知识。
- **Connector / Merger** 将视觉特征投影到 LLM 隐藏维度，或以 query/resampler 压缩、以 cross-attention 供语言模型读取。它控制视觉 token 带宽，也是信息可能丢失的瓶颈。
- **LLM Backbone** 按文本自回归目标生成答案或行动描述；视觉信息怎样影响回答，取决于视觉 token 注入位置、训练数据和解码接口。

多模态对齐不能只理解为“维度相同”。把图像表示投影到词向量空间解决的是接口兼容，图文对比训练、视觉问答监督或区域 grounding 训练则分别塑造匹配、生成和空间定位行为。任务目标、表示和组件连接是不同层次，应分开分析。

## 2. 四种图像—语言连接路线

### 2.1 CLIP：图文对比学习得到共享检索空间

CLIP 使用图像编码器和文本编码器，在 batch 中把真实图文配对作为正例、其他配对作为负例，用对称对比损失训练共享嵌入。原论文用从互联网收集的 4 亿图文对训练，并在超过 30 个已有视觉基准测试零样本迁移；推理时可把类别写成文本描述，通过相似度分类或做图文检索。它的学习信号是“这幅图和哪段文字配对”，不是“针对图像生成任意回答”。

这种目标能从大规模弱配对数据中学习开放词汇对应关系，却主要优化全图—整句相似度；它不直接监督对象位置、实体间关系、多个相似物体的计数或长篇视觉推理。CLIP 论文确实在 OCR、视频动作识别等任务观察到零样本迁移，但不同任务表现取决于预训练数据覆盖和评测构造。即使视觉/文本嵌入相似，也不能保证模型能指出一条回答依据图像的哪个区域。[CLIP §2–3](https://arxiv.org/html/2103.00020)

### 2.2 Flamingo：用固定视觉 token 向冻结 LLM 注入上下文

Flamingo 目标是少样本多模态学习，可让文本、图像和视频在输入中交错出现。视觉编码器先得到时空特征，Perceiver Resampler 用可学习 latent query 将变长特征压成固定数量的视觉 token；原论文配置用 64 个 resampler 输出 token。语言模型大部分参数冻结，在其层间插入新初始化的 gated cross-attention，让语言模型按生成位置读取此前图像/视频表示。

设计取舍是通过冻结预训练 LLM 保留语言能力，只训练跨模态连接层和少量新增参数；固定 token 瓶颈控制了计算和上下文长度，却也意味着输入分辨率和视频帧数增加时，细节仍要挤进有限表示。原论文 resampler 将可变规模视觉特征压成 64 个 token；视频输入按 1 FPS 采样并添加时间嵌入，这些是 Flamingo 的架构/实验设置，不是所有视频模型的通用采样策略。它的 few-shot 能力也与图文交错训练有关，不能只将提升归因于 cross-attention 层。[Flamingo §2–3](https://arxiv.org/html/2204.14198)

### 2.3 BLIP-2：以 Q-Former 桥接两个冻结的编码器

BLIP-2 冻结预训练视觉编码器与 LLM，在中间训练 Querying Transformer（Q-Former）。一组可学习 query 通过 cross-attention 读取图像特征，并输出固定数量表示；原论文使用 32 个 query，输出规模为 $32×768$，远小于 ViT-L/14 的 $257×1024$ 图像特征。第一阶段在冻结视觉 encoder 上联合训练图文对比（ITC）、图文匹配（ITM）和图像条件文本生成（ITG）目标，使用不同 attention masks 控制 query 与文本交互；第二阶段把 Q-Former 输出投影到冻结 LLM 的嵌入维度，训练视觉到语言的生成对齐。

与 Flamingo 的主要差异是连接方式和训练目标：Flamingo 将 cross-attention 模块插进冻结 LLM 的层间；BLIP-2 用一个独立、可训练的 Q-Former 摘取固定视觉表示，再前置到 LLM 输入。查询瓶颈省计算，也强迫模型筛选语言相关视觉信息；若任务依赖小字、细微空间关系或 query 未能抽取的信息，后续语言模型无法从已经压掉的视觉特征中恢复。BLIP-2 还报告，在只有单图文对的预训练数据中未观察到显著 few-shot in-context 学习，说明界面能交错文本/图像与训练数据是否包含多图文序列也是不同条件。[BLIP-2 §3–5](https://arxiv.org/html/2301.12597)

### 2.4 LLaVA：简单投影加视觉指令微调

LLaVA 以 CLIP ViT-L/14 提取图像 patch 特征，用线性投影把视觉特征变成语言模型词嵌入维度的视觉 token，再输入 Vicuna。它把训练拆成视觉—语言特征对齐和端到端视觉指令微调：第一阶段主要训练连接层，第二阶段用图像对话、详细描述和复杂推理示例让语言模型学会回应视觉指令。

其关键不是复杂 connector，而是验证了**简单投影与指令数据**可以有效形成多模态助手。论文先由人工设计少量 seed examples，再让 GPT-4 基于 COCO 图像生成视觉对话、详细描述和复杂推理问题/答案，共收集 158K 样本（58K 对话、23K 详细描述、77K 复杂推理）。两阶段是先冻结视觉 encoder/LLM 训练投影层做 feature alignment，再端到端微调视觉指令数据。这个配方使回答风格与任务覆盖扩展，但也把教师模型的描述错误、问题选择和数据过滤带进训练；原论文的 GPT-4 judge 评估也不是人工真值。LLaVA 证明了视觉指令微调路线可行，不证明简单线性投影足以处理所有细粒度视觉任务。[LLaVA §3–5、Appendix E](https://arxiv.org/html/2304.08485)

这几条路线形成设计空间，而不是单向排名：CLIP 学图文匹配；Flamingo 插入跨注意力读取压缩视觉 token；BLIP-2 用 Q-Former 作为固定带宽桥接器；LLaVA 把视觉 token 线性映射到语言序列后，用指令数据训练交互。比较它们时应问：哪个模块可训练？视觉表征压缩多少？跨模态关系在哪些层建立？任务监督是配对、生成还是指令跟随？

| 路线 | 视觉接口与注入位置 | 主要训练信号 | 适合检验的问题 | 瓶颈 |
|---|---|---|---|---|
| CLIP | 双塔分别编码，再比较全局向量 | batch 内图文对比 | 图文是否匹配、零样本类别迁移 | 不生成解释、无区域级证据 |
| Flamingo | resampler 固定视觉 token；cross-attention 插入 LLM 层间 | 冻结 LLM 上的条件 next-token | 交错图文/视频的少样本任务 | token 压缩率和帧采样限制细节 |
| BLIP-2 | Q-Former 从冻结 ViT 查询特征，再作为 soft prompt 接入 LLM | ITC/ITM/ITG 两阶段对齐 | 可否用小 trainable bridge 复用两端模型 | 固定 query 数压缩视觉带宽 |
| LLaVA | 线性投影的视觉 token 前置到 LLM 序列 | 特征对齐后视觉指令 SFT | 对话式视觉指令是否可由简单接口学会 | 细粒度能力依赖 encoder 与指令数据 |

## 3. 高分辨率与空间 grounding

### 3.1 分辨率决定视觉证据预算

固定短边 resize 能控制视觉 token 数，却可能损失小字号、图表刻度、密集物体和远处细节。多裁切、patch 细分或原生动态分辨率可保留局部信息；代价是视觉 token 数增长，增加 encoder 计算、LLM prefill 和上下文占用。Merger 把相邻 patch 合并可以减少 token，但也可能损失局部文字/位置细节。

Qwen2.5-VL 的技术报告描述了原生动态分辨率、window-attention Vision Transformer、视频动态 FPS，以及与绝对时间对齐的 Multimodal RoPE。图像被处理为变长视觉 token，视频帧也可以按不同帧率采样；其 ViT 采用窗口注意力控制视觉 encoder 的计算，Merger 会合并空间邻近特征以减少送入 LLM 的 token。这把空间分辨率和视频时间采样变成输入预算决策：图像分辨率提高可以保留更细的信息，也会增大视觉序列；帧率提高改善时间覆盖，也会带来更多视觉 token。实际看到多少证据，仍要结合具体 checkpoint、输入 resize/patch 设置、窗口和帧抽取流程判断。[Qwen2.5-VL §2.1](https://arxiv.org/html/2502.13923)

### 3.2 坐标、物体关系和文档结构是独立构念

视觉 QA 的语言回答正确，不代表模型找对对象区域；检测到 bounding box，也不代表自然语言推理正确。对于 grounding，输出接口需要包含框、点、坐标或区域引用，并按对应标注评价；计数要区分目标类别、遮挡与重复实例；空间关系还涉及左右、前后和坐标系。单一全图 embedding 或普通 caption loss 不会自动提供这些监督。

文档页面进一步叠加 OCR、版面、阅读顺序、表格、公式和图文关系。OCR 识别准确不等于阅读顺序正确，版面框准确不等于表格结构或跨栏语义正确，端到端答案正确也不能反推每个中间结构都正确。文档解析的任务拆分、输入分辨率和 benchmark 边界见[OCR 与文档解析专题](../DocumentParsing/report.md)；评测工具的页面预算和输入归因见[VLM 评测输入预算专题](topics/evaluation-input-budget.md)。

## 4. 视频理解：采样、时间与多模态证据

把视频转成帧序列可以复用图像编码器，但会将连续运动压成有限采样点。低采样率可能漏掉短动作和事件边界；提高帧数增加 token 与推理成本，也不保证模型理解因果、顺序或跨段关系。视频 VLM 至少需要处理：时间戳如何编码、帧与帧间的对象如何对应、音频/字幕是否输入、以及长视频中关键证据如何定位。

Qwen2.5-VL 使用 absolute-time-aligned MRoPE，使视频帧位置对应绝对时间并支持动态 FPS。Qwen3-VL 在此路线中提出 Interleaved MRoPE、DeepStack 和文本时间戳：Interleaved MRoPE 将时空维度的频率成分交错分布；DeepStack 从 ViT 中间层取视觉特征并注入多个 LLM 层；时间戳文本为视频片段提供显式时序标记。其 DeepStack ablation 在内部 15B-A2B LLM、200B 预训练 token 且未做 post-training 的配置下比较基线与 DeepStack，报告平均分 74.7→76.0、DocVQA 89.5→91.1；这是该内部模型消融的作者报告结果，不证明多层注入在所有 VLM 上都同幅提升或普遍更好。[Qwen3-VL §2、§5.12](https://arxiv.org/html/2511.21631)

Video-MME 用 900 段视频、2,700 道多项选择题，覆盖短/中/长视频，另考察字幕和音频输入。论文中模型的视频帧预算并不一致：有的依视频时长抽帧，有的用固定帧数；音频与字幕是否输入也改变题目可利用的信息。它的结果应解释为“模型 + 预处理/采样 + 可用模态 + 选择题协议”的组合，而不是纯粹的连续视频推理。该 benchmark 的输入协议和一个 VLMEvalKit 实际代码路径见[Video-MME 精读](papers/2405.21075-videomme.md)与[评测输入预算专题](topics/evaluation-input-budget.md)。

## 5. 评测构念与闭源架构边界

VLM 的评估覆盖图文匹配、图像描述、视觉问答、OCR/页面解析、图表/数学、空间定位、视频时序和 GUI 操作。它们不共享同一个“多模态理解”指标：MMMU 由 11.5K 道大学考试、测验和教材题构成，覆盖六大学科、30 个科目和 183 个子领域，包含图表、地图、谱表、化学结构等 30 类异质图像，测的是领域知识与图像/文字联合推理；DocVQA/OmniDocBench 会拆 OCR、版面、表格和公式；Video-MME 包含 900 段 11 秒至 1 小时的视频与 2,700 道多项选择题，并允许字幕/音频作为输入；GUI benchmark 则还包括动作空间、工具调用、环境状态和成功判定。它们分别测试不同构念，不能合并成一个“VLM理解力”。[MMMU](https://arxiv.org/html/2311.16502)、[Video-MME](https://arxiv.org/html/2405.21075)

跨模型比较需要记录实际输入：图像分辨率与裁切、视觉 token、帧数和时间戳、音频/字幕、页面数、上下文预算、提示模板和评分器。指标也应匹配构念：文本答案准确率不检验框选质量，OCR 编辑距离不检验表格结构，视频多项选择准确率不检验定位跨度或因果解释，GUI 的任务成功率不能直接说明视觉 encoder 架构。

闭源产品的外显能力不唯一决定内部架构。若 GPT-4o 等模型没有公开足够技术材料，不能由“实时语音/视频”推断早期/晚期融合、共享 token 空间或具体 transformer 结构；应只写官方披露的接口和评测，并将内部实现标成未知。开源技术报告也应对应明确版本、输入预处理、权重和评测设置，模型家族名称不保证所有 checkpoint 使用同一视觉路径。

## 6. 综合判断、开放问题与推荐阅读

视觉语言模型的关键取舍可以归纳为：

| 设计层 | 代表路线 | 换来的能力 | 主要代价/边界 |
|---|---|---|---|
| 图文目标 | CLIP 对比学习 | 开放词汇匹配、零样本分类 | 不等于生成式对话或空间 grounding |
| 冻结模型桥接 | Flamingo cross-attention、BLIP-2 Q-Former | 复用已有视觉/语言模型、控制可训练参数 | 视觉带宽受 resampler/query 瓶颈限制 |
| 指令对齐 | LLaVA projector + visual instruction tuning | 对话、描述、指令跟随 | 依赖合成/人工指令质量与裁判评测 |
| 空间/细节 | 动态分辨率、多层视觉注入、坐标输出 | 小字、区域和细粒度视觉证据 | token、计算与坐标监督成本上升 |
| 视频时序 | 帧采样、时间位置、文本时间戳 | 多帧事件定位和跨段信息输入 | 采样遗漏、音视频协议不一致、长上下文退化 |

仍未解决的问题包括：如何压缩视觉 token 而保留小字和空间关系；如何让开放式回答指向可验证的图像区域或时间跨度；视觉指令合成何时改善交互、何时放大教师模型错误；视频帧预算、分辨率和模型预算怎样共同控制；以及如何把感知、grounding、推理、动作执行的错误分开评估。

### 推荐阅读顺序

1. [CLIP](https://arxiv.org/html/2103.00020) §2–3：图文对比目标及其检索/零样本接口。
2. [Flamingo](https://arxiv.org/html/2204.14198) §2 与 [BLIP-2](https://arxiv.org/html/2301.12597) §3：冻结模型上的两种连接器设计。
3. [LLaVA](https://arxiv.org/html/2304.08485) §3–5：视觉指令数据和分阶段训练。
4. [Qwen2.5-VL](https://arxiv.org/html/2502.13923) §2.1 与 [Qwen3-VL](https://arxiv.org/html/2511.21631) §2：动态分辨率、时间编码、多层视觉注入。
5. [Video-MME](papers/2405.21075-videomme.md) 与[输入预算专题](topics/evaluation-input-budget.md)：对照基准协议如何改变能力结论。
6. [OmniDocBench](../DocumentParsing/papers/2412.07626-omnidocbench.md)：查看文档解析的多任务/多层评估边界。

### 主要原文

- [CLIP](https://arxiv.org/html/2103.00020)：双塔图文对比学习和零样本迁移。
- [Flamingo](https://arxiv.org/html/2204.14198)：Perceiver Resampler、gated cross-attention 与少样本多模态输入。
- [BLIP-2](https://arxiv.org/html/2301.12597)：冻结视觉/语言模型之间的 Q-Former 瓶颈。
- [LLaVA](https://arxiv.org/html/2304.08485)：简单线性 projector、两阶段视觉指令微调和数据来源。
- [Qwen2.5-VL](https://arxiv.org/html/2502.13923)、[Qwen3-VL](https://arxiv.org/html/2511.21631)：动态分辨率、视频时序及多层视觉融合。
- [Video-MME](https://arxiv.org/html/2405.21075)：帧/字幕/音频协议与视频问答评测。
- [OmniDocBench](https://arxiv.org/html/2412.07626)：文档页面解析基准的子任务和属性标注。
