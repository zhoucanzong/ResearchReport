# VLM 评测的输入预算与 grounding：模型究竟看到了什么？

一个基准分数不只取决于模型。视频评测还取决于抽了哪些帧、字幕是否可见、音频是否输入；文档评测则受页面分辨率、裁切、OCR/版面流水线和页数影响。即使基准名称相同，实际输入也可能不同。读 VLM 成绩时，先重建“模型看到了什么”，再解释它答得如何。

本专题按一个视频基准、一套文档解析基准和一条评测工具代码路径展开。它补充输入协议与指标构念，不重新排模型榜单；通用评分效度与 judge 偏差见[评测科学总论](../../../Evaluation/EvaluationScience/report.md)。

## 视频：帧预算和可用模态改变了任务

[Video-MME 精读](../papers/2405.21075-videomme.md)分析了 900 段视频、2,700 道四选一题，覆盖短、中、长视频和多个领域。题目要求跨片段定位、事件关联或时序推断；但各模型没有共享一套统一视频预算：论文里 Gemini 1.5 Pro 按视频时长以 1 fps 或 0.5 fps 抽帧，其他模型则配置固定帧数，范围从 4 到 384。帧数相同也不保证看见相同时间点；对长视频，同样 8 帧意味着更稀疏的时间覆盖。

字幕与音频会进一步改变输入。Video-MME 的字幕取与抽帧时刻对齐的片段；有些模型还获得音频输入。Gemini 1.5 Pro 上，frames-only 整体准确率 75.0%，加字幕为 81.3%，加音频为 79.4%；这些是同一模型的输入消融，支持文本/音频线索对该选择题集有帮助。它们不能单独说明纯视觉时序推理提高了多少，因为字幕可能直接包含答案线索，音频也改变了信息来源。[Video-MME v3, §4.3, Table 5](https://arxiv.org/html/2405.21075v3)

基准的四选一准确率也有明确范围：模型只需输出 A–D，解析失败时还可能通过 judge 回退。它测的是该输入和提示协议下的选项正确率，不是开放式证据定位、长视频叙述、在线交互或时序因果解释。不同模型的输入/解码配置不一致时，跨模型总分是“模型 + 预处理 + 可用模态 + 任务协议”的联合结果。[Video-MME 精读](../papers/2405.21075-videomme.md)

## 文档：识字、找版面、读顺序、还原结构是不同能力

[OmniDocBench 精读](../../DocumentParsing/papers/2412.07626-omnidocbench.md)将文档解析拆为 OCR 文本、版面区域检测、阅读顺序、表格结构和公式表达等不同指标。OCR 的编辑距离不能代表多栏阅读顺序；区域框 mAP 也不能代表端到端表格/公式重建。阅读顺序指标会受 OCR 漏字和段落合并影响，因此某一子分数低，并不总是相应模块单独出了错。

该基准含 981 个单页 PDF 样本，覆盖九类页面；页面先由专用模型预标，再经人工标注和校正。它适合比较**页面解析**，但不是多页文档检索或跨页推理测试。跨系统配置也没有统一页面栅格分辨率、视觉 token 或计算量；不同工具版本、模型输入和解析流水线会共同影响分数。论文按 OCR、布局、顺序、表格和公式分别给出指标，读者不应把它们合并成一个含义不明的“文档理解分”。[OmniDocBench v2, §§3–5, Tables 1–9, Appendix IV](https://arxiv.org/html/2412.07626v2)

因此，grounding（输入内容落到可验证位置或结构的能力）也要说清单位：是文本字符、页面区域、阅读次序、表格树，还是视频时间戳与事件跨度？即使模型答案正确，也不能自动推断其证据定位正确；若评测器只看最终答案，过程中的错页、漏框或无来源猜测可能被掩盖。

## 代码路径怎样改变分数

在 VLMEvalKit 固定版本 `4d0dc8096b2ee365491c469088cc462ae1fb6041` 的 Video-MME 追踪中，`Video-MME_8frame + Qwen2.5-VL-7B-Instruct` 从数据配置、prompt、视频预处理一路到答案解析和分组平均。这个名字中的“8frame”在 Qwen 路径上是交给外部视频处理器的目标帧数；源码没有固定处理器最终选中的时间戳。其他非原生视频模型可能走数据集端等间隔抽帧路径，故同一个配置标签不保证实际视觉输入完全一致。[源码路径精读](vlmevalkit-video-mme-path.md)

该路径的预测文本先用正则提取 A–D；提取不到才调用 judge，judge 失败的样本记 `-1`，而均值聚合排除负分。于是至少有三类误差：视频/字幕准备或解码失败；输出格式异常或判分解析失败；输入正确但模型答错。VLMEvalKit 有助于把前两类暴露出来，却不会单凭静态代码证明实际图像张量、视频帧或网络侧模型输入与配置完全一致；本次也没有运行数据、模型或 benchmark。

## 读分时先写一张协议卡

| 维度 | 视频任务 | 文档任务 |
|---|---|---|
| 输入单位 | 视频时长、帧抽样数/时刻、帧分辨率、音频片段、字幕时间对齐 | 页数、栅格 DPI/分辨率、裁切/patch、OCR 与 layout 前处理 |
| 模型预算 | 视觉 token、文本/音频 token、上下文上限、解码预算 | 页面视觉 token、文本 token、最大页数、输出长度 |
| 目标构念 | 单帧识别、跨帧定位、事件顺序、跨段关联、音视频整合 | 字符识别、区域/阅读顺序、表格结构、公式识别、跨页检索 |
| 评分 | 选择题准确率、时间定位、证据跨度、开放回答评分 | 编辑距离、mAP、TEDS/CDM、页面/文档级聚合方式 |
| 失败分母 | 输入处理失败、无法作答、解析/judge 回退、有效样本数 | 页面读取失败、识别空输出、结构解析失败、被忽略元素与页数分母 |

若缺少这些字段，跨模型分差同时混合能力、数据构造与输入预算。最有解释力的下一步不是堆更多排行榜，而是在同一模型上控制帧/分辨率/token预算做消融，再把算法错误与预处理/解析错误分开；本文未执行此类实验。
