# DeepSeek-OCR 2：让视觉 token 按阅读逻辑进入语言模型

> Haoran Wei、Yaofeng Sun、Yukun Li，*DeepSeek-OCR 2: Visual Causal Flow*，arXiv:2601.20552v1（2026-01-28）。arXiv 提交历史截至本次阅读仅列 v1。依据[官方完整 HTML 原文](https://arxiv.org/html/2601.20552v1)精读，重点参照 §1、§3.1–3.3、§4.1–4.2、§5–6，特别是 Figure 1、3–5、Tables 1–4。数字均为论文报告结果，保留基准、指标和条件；未独立重算或复现实验。

## 这次升级解决的是视觉序列的“读序”，不是再压一次 token

DeepSeek-OCR 已经用视觉编码器把文档页压成较短的视觉序列，但常见视觉编码器把二维图像按从左上到右下的固定栅格顺序摊平。对单栏页面这通常够用；面对跨栏文章、表格、公式或非线性版面，空间先后不一定等于读者的理解顺序。DeepSeek-OCR 2 的问题是：能否在送入语言解码器之前，先把视觉信息组织成更适合因果语言模型逐步处理的序列？

因此它保留前代的 16 倍视觉压缩与 MoE 解码器，主要改造 DeepEncoder 的全局建模部分。DeepEncoder V2 不是把图像 patch 做一个可解释的离散排序，而是用一串有因果依赖的可学习 query 从全图表示中逐步提炼内容。更准确地说，它学习了带语义次序的视觉表示；论文把这一过程称作 visual causal flow（视觉因果流）。

## DeepEncoder V2 如何把双向看图与因果组织接起来

第一段仍是 SAM-base 视觉 tokenizer 加两层卷积压缩：输入 patch 经局部窗口注意力处理，token 数减少 16 倍。第二段把前代 CLIP 全局编码器换成 Qwen2-0.5B 风格的语言模型编码器。序列前缀是压缩后的视觉 token，后缀是与视觉 token 数量相同的 learnable causal flow queries。定制注意力掩码让视觉前缀彼此双向可见；每个 query 可以查看全部视觉 token 和它之前的 query，却看不到后续 query（§3.2.1–3.2.4，Figure 3、5）。

这套结构保留全局视觉上下文，同时迫使 query 按因果顺序逐步形成表示。只有 query 输出送进后续语言解码器，因此 query 序列承担视觉信息的语义组织与压缩。query 数量与视觉 token 数量相同，意味着它不是在前代视觉压缩之后又把序列长度继续减半；它改变的是交给解码器的表示形成方式和顺序偏置。这里的“因果”描述注意力方向，不代表模型已获得人类式因果推理能力。

多裁剪模式控制最终视觉 token 预算：全局视图为 1024×1024、256 个 query；局部视图为 768×768，每个裁剪 144 个 query，最多 6 个裁剪。因此送入 decoder 的 token 数为 256 到 1120（§3.2.3，Figure 4）。预算与前代相近；提升重点是重新组织表示，而不是用更长序列换精度。

## 训练既学习 query 顺序，也让解码器适应新表示

DeepSeek-OCR 2 复用前代 OCR 1.0、OCR 2.0 和一般视觉数据来源，论文称 OCR 数据约占混合数据的 80%。它还按文本、公式、表格以 3:1:1 调整 OCR 页面采样，并合并语义相近的版面标签（例如图注与图题）。这两个变化是重要比较条件：DeepSeek-OCR 2 相对基线的差异不只包含 DeepEncoder V2 架构（§4.1）。

训练分三阶段。第一阶段用 next-token prediction 训练图像编码器与轻量解码器，视觉 tokenizer 从 DeepEncoder 初始化，LLM 风格编码器从 Qwen2-0.5B-base 初始化；论文报告使用约 1 亿图文样本和 160 张 A100 训练 40k iterations。第二阶段接上 DeepSeek-3B-A500M，冻结 SAM 与卷积 tokenizer，联合更新 LLM 编码器和解码器，增强 query 表示。第三阶段冻结 DeepEncoder V2，只继续训练语言解码器，让它适应新的视觉序列并提高训练数据吞吐（§4.2.1–4.2.3）。

这种分阶段选择体现了模块之间的相互适配：query 学出来的次序如果直接交给只见过 raster 顺序的 decoder，收益可能受限；而全程联合训练又会更昂贵。作者让 query 表示先形成、再联合对齐、最后冻结编码器扩大解码器训练数据。因而论文比较的是一套训练与架构共同构成的新系统，不能把性能变化只归给注意力掩码。

## OmniDocBench 结果支持读序改善，但不是所有结构都同等受益

主要评测使用 OmniDocBench v1.5：论文描述该基准包含中英文 1,355 页、9 类文档。其 Table 1 报告 DeepSeek-OCR 2 的 overall 为 91.09，最高视觉 token 上限为 1120；DeepSeek-OCR 基线（9-crop）overall 为 87.36、上限 1156。相同表中的文本编辑距离从 0.073 降至 0.048，公式 CDM 从 84.14 升至 90.31，表格 TEDS 从 85.25 升至 87.75，表格 TEDS-S 从 89.01 升至 92.06，阅读顺序编辑距离从 0.085 降至 0.057（Table 1）。overall、CDM、TEDS 类是越高越好；编辑距离是越低越好。这里可见读序和若干结构指标同步改善，但指标定义不同，不能把一个总分当作所有能力的等价量尺。

作者报告 3.73 的 overall 提升时，比较是在相近训练数据来源与 token 上限下进行，但 OCR 2 更改了数据采样和版面标签；基线也采用 9-crop 配置。因而这组结果与视觉因果流设计的解释相符，却不是完全控制数据、预算、训练步骤后单独改变编码器的因果消融。原文 Table 2 的直接模型对照中，DeepSeek-OCR 2 overall 编辑距离由 0.129 降为 0.100，阅读顺序距离由 0.085 降为 0.057（越低越好；Table 2）。这更聚焦于错误序列，但仍是端到端评测，不是只评 query 排序模块。

文档类型切片揭示上限。作者称 OCR 2 在多数类别的文字编辑距离更低、阅读顺序距离在九类中均下降；报纸文字编辑距离却从 0.131 变为 0.139（越低越好）。论文把报纸弱项联系到两点：视觉 token 上限较低，以及训练中相关报纸样本约 25 万，难以覆盖密集文本页面（§5.2，Table 3）。因此读序机制可以改进版面逻辑，却不能补回分辨率不足或数据覆盖不足造成的字符识别损失。

## 生产重复率是可观察代理，不是准确率

生产环境没有逐页 ground truth，作者因此报告输出重复率作为可观察质量指标。Table 4 中，线上用户图像的重复率从 DeepSeek-OCR 的 6.25% 降至 OCR 2 的 4.17%；预训练 PDF 数据的重复率从 3.69% 降至 2.88%（§5.3）。重复率主要捕捉生成卡住或重复片段，不等同于字符准确率、结构完整性或业务任务成功率。把它与 OmniDocBench 的编辑距离或结构分数混为“生产准确率”会超出证据。

## 研究贡献与未解决问题

DeepSeek-OCR 把 OCR 作为视觉 token 压缩文本上下文的实验平台；OCR 2 则针对压缩后视觉 token 的顺序表示，尝试让 encoder 的输出更贴合 decoder-only LLM 的因果读取方式。两者处理的是相邻瓶颈：前者问“多少视觉 token 才读得回来”，后者问“同样数量的 token 怎样排布更适合读”。OCR 2 保留了前代压缩器和解码器，研究变化集中在编码器的全局语义整理方式。

论文把两段因果序列称为迈向 genuine 2D reasoning 的探索，同时明确承认要实现多次回看和多跳重排，可能需要比原始视觉序列更长的 causal flow tokens（§6.1）。这指出当前设计的一个张力：等量 query 控制预算，但可能限制反复核查与多步关系组织。更长 query 能否改善表格跨单元关系、跨栏依赖或图文对应，代价是多少，仍是开放问题。其他重要边界包括：评测主要是中英文文档页；指标受解析格式和基准规则影响；视觉排序本身难以独立标注，因此端到端得分未必能说明每个 query 实际形成了怎样的阅读路径。
