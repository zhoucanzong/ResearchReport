# 用粗到细视觉处理降低文档解析成本：PaddleOCR-VL

> **论文**：Cheng Cui et al., *Boosting Document Parsing Efficiency and Performance with Coarse-to-Fine Visual Processing*
> **固定版本**：arXiv:2603.24326v2，2026-04-03
> **原文**：[arXiv HTML v2](https://arxiv.org/html/2603.24326v2)（本文依据在线完整原文；下文用章节、表格定位）

## 先抓住问题：文档里不是每个像素都同样重要

文档解析不只是把字读出来。它还要辨认表格、公式、图表等元素，并恢复它们在页面中的结构和阅读顺序。高分辨率能保住小字、密集表格和公式细节，但把整页送进视觉语言模型（VLM）会让视觉 token 数随分辨率迅速增加；自注意力处理长序列的成本又近似随 token 数平方增长。论文的观察是，文档图像的有效内容分布并不均匀：文字、表格等信息区之间往往夹着大片背景或装饰区域。于是关键不只是“怎样压缩图像”，而是“能否先找出哪些区域值得高分辨率识别，并保留它们之间的结构关系”。（§1，Figure 2）

## 核心机制：先定位和排序，再逐块识别

PaddleOCR-VL 把整页解析拆成两个相接的阶段。

1. **粗阶段 VRFM**（Valid Region Focus Module，有效区域聚焦模块）以 RT-DETR 为基础，在整页上检测并分类文本、表格、公式、图表等区域。它再用 pointer network 对检测出的区域关系建模，预测成对的阅读顺序。这样输出的不只是裁剪框，也包括后续重建页面所需的顺序信息。（§3.1.1，Figure 4）
2. **细阶段 PaddleOCR-VL-0.9B** 将各有效区域裁出后送入小型 VLM 单独识别，再按 VRFM 的顺序合并结果。识别器使用 NaViT 风格的动态分辨率视觉编码器、MLP projector 和 ERNIE-4.5-0.3B 语言模型；不同区域可按内容保留所需分辨率，而不是把整张页面都扩成同等密度的视觉序列。（§3.1.2，Figure 3）

直观地说，这像先用一张低成本的页面地图标出段落、表格和公式，再放大阅读这些局部，并按地图上的顺序拼回文档。粗阶段决定“看哪里、先后如何”，细阶段负责“那里具体写了什么”。显式预测阅读顺序是这个设计的重要部分：只裁掉背景但不建模文档结构，可能连带丢掉跨区域的版面关系。

## 为什么选择两阶段，而不是统一压缩所有视觉 token

高分辨率对细粒度识别有价值，但若把所有区域均匀压缩，稠密文字、小公式和表格线也会一起损失。论文提出的替代方案是让一个轻量布局模块承担全页定位和结构预测，把昂贵的精细识别集中到内容区域。作者还强调，布局与元素识别可以分别优化：VRFM 面向区域检测和阅读顺序，VLM 面向局部内容理解。（§1，§3.1）

附录的 VRFM 对照提供了与“只减 token”相比的机制证据。论文报告，在 Qwen3-VL-8B 上直接使用 DocKylin 区域裁剪，token 数从 5818 降到 4316，但准确率从 89.60% 降到 87.75%；加入 VRFM 后，Qwen3-VL-8B 的 token 数为 4262、准确率为 90.37%。在 PaddleOCR-VL-0.9B 上，PP-DocLayout 加识别器报告 2347 tokens / 89.96%，VRFM 加识别器为 2561 tokens / 92.62%。这组对照支持作者的解释：保留结构和阅读顺序可能比单纯压缩区域更重要；它并不证明所有文档、裁剪器或识别器组合都会有相同收益。（Appendix III.1, Table S2；论文报告的 Acc. 与视觉 token 数）

## 数据和训练：系统效果不只来自架构

作者把数据建设视为性能的重要组成部分。训练数据来源包括公开数据、合成样本、网络收集的真实文档和内部数据；标注流程先用 PP-StructureV3 产生伪标签，再由 ERNIE-4.5-VL、Qwen2.5-VL 辅助修订，并通过幻觉过滤剔除可疑标注。针对模型的弱项，团队还用人工标注的困难样例评测集定位短板，再生成对应的长尾训练数据。（§3.2.1–3.2.3）

VRFM 的检测核心从 PP-DocLayout_Plus-L 权重初始化，在 2 万多个样本上训练 100 个 epoch；之后冻结检测核心，只训练 pointer network 200 个 epoch，以学习区域间的阅读顺序。（§3.3.1）

识别器分两阶段训练：先用 2900 万图文样本做模态对齐预训练，再用 270 万样本指令微调；微调阶段把最大视觉 token 数提高到 2048，并覆盖 OCR、表格结构、公式转写和图表数据提取。（§3.3.2，Table 1）这意味着论文呈现的系统收益来自“分阶段架构 + 大规模混合数据 + 针对弱项补数据”的共同作用，不能仅归因于 VRFM 一个模块。

## 原文报告了什么结果

### 整页解析

在 OmniDocBench v1.5 上，论文报告 PaddleOCR-VL-L 的 overall 为 92.62、使用 2561 个视觉 token；同表 MinerU2.5 为 90.67、3256 个 token。该版本基准包含 1,355 页中英文文档，overall 是文本、公式和表格指标的加权组合。论文还报告文本编辑距离 0.035、公式 CDM 90.90、表格 TEDS 90.48，以及阅读顺序编辑距离 0.043。（§4.1，Table 2；这些是论文报告值，不是本次独立评测）

这里最能说明方法取舍的是：该系统没有靠增加视觉 token 换取表格中的高分，而是在作者采用的基准和评测协议下，以较少视觉 token 报告了更高的 overall。不同方法的 token 预算、模型规模和推理管线并不完全相同，因此表格适合说明论文报告的系统级比较，不宜把它读成只改变一个变量的严格因果实验。

### 速度与显存

论文报告在 OmniDocBench 上将 PDF 以 512 页批次、单张 NVIDIA A100 运行，并统一使用 vLLM 0.10.2 后端。PaddleOCR-VL-L 的报告吞吐为 1.6192 页/秒；MinerU2.5 为 1.0574 页/秒。作者据此报告页吞吐提高 53.1%。同一表中 PaddleOCR-VL-L 平均显存为 42.1 GB；dots.ocr 为 78.5 GB。结果反映论文所列硬件、批量、后端和各系统实现条件，不等同于任意部署中的延迟或吞吐保证。（§4.3，Table 7）

### 元素级结果和数据边界

除整页指标外，论文分别测文本、表格、公式和图表。在 1050 个从 OmniDocBench v1.5 公式框裁出的子图上，作者报告公式 CDM 0.9404；裁切公式减少了版面检测对公式识别分数的影响。（§4.2.3，Table 5）图表评测使用作者内部的 1801 个人工核验样本，覆盖 11 类中英文图表；PaddleOCR-VL-L 报告 RMS-F1 0.8440。（§4.2.4，Table 6）内部测试集由作者构造，不能与公开基准结果视为同等独立验证。

## 适用条件、失效边界与开放问题

- **它依赖粗阶段先找对区域。** VRFM 漏检的小字、边注、跨栏内容或低对比公式，后续识别器就没有机会补救；错误的区域分类也可能把识别请求交给不合适的处理路径。论文展示了整体性能和消融，但这些数字不能替代对特定文档分布的漏检分析。
- **阅读顺序是被显式预测的，也会成为错误来源。** pointer network 能把顺序作为模型目标，而非固定规则；但面对跨页脚注、复杂多栏、浮动图注和非线性阅读路径，区域两两排序怎样稳定组合成整页次序，仍值得单独研究。
- **收益依赖“有效内容占比”和识别器开销。** 背景多、结构明显、局部内容稠密的页面更适合先筛选再识别。若页面大部分区域都含信息，或者裁剪与多次识别调度成为主要成本，粗到细带来的 token 节省可能缩小。论文给出的背景占比分析来自 OmniDocBench v1.5 的文档类型统计（§1，Figure 2），不能当成所有真实文档的固定比例。
- **架构与数据贡献尚未完全拆开。** 论文用 VRFM 消融说明结构化定位比朴素裁剪更有解释力，但其大规模合成、内部数据、伪标签修订和困难样例挖掘也共同训练了识别器。跨团队复现时，数据质量和训练配方可能是重要变量。
- **指标还没有覆盖全部使用需求。** 页面分数和元素分数能衡量识别与结构恢复的一部分，但下游检索是否找得到正确段落、表格是否保留单元格语义、公式是否可执行等任务效果，需要应用侧评测补充。图表结果尤其依赖内部测试集，开放可复核的数据与统一评测仍有价值。

因此，这项工作的核心启发不是“所有文档都应先检测再裁剪”，而是把文档解析当作一种有空间结构的稀疏视觉计算：先估计信息在哪里、如何排序，再把高分辨率算力分配给这些位置。实际是否合适，要看前级定位的召回、阅读顺序复杂度、有效区域比例，以及端到端系统中裁剪和调度成本。
