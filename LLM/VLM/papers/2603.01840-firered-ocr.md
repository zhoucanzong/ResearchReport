# FireRed-OCR：把通用 VLM 专门化为结构文档解析器

> Xiaohongshu Super Intelligence Team, *FireRed-OCR Technical Report*, arXiv:2603.01840v1（2026-03-02）。依据[该版本完整 HTML 原文](https://arxiv.org/html/2603.01840v1)精读，主要参照 §1–4.5、Figure 2–4、Tables 1–4。题录由 `paper-fetcher` 获取。论文报告的数字均保留对应基准和表格位置；本文不独立重算或复现实验。

## 它要修的不是“看不懂”，而是“看懂了却排错了”

通用视觉语言模型（VLM）能说出页面大意，却可能把表格行列串错、漏掉公式符号、打乱多栏阅读顺序，或生成无法解析的 Markdown。FireRed-OCR 把这类错误称为 **结构幻觉**：生成内容看起来合理，但空间对应关系或结构语法不符合原文（§1）。对于下游检索、训练或自动化处理，这种错误常比一句自然语言解释不够完整更难接受。

因此论文关注的目标不是再扩大通用模型，而是把 Qwen3-VL 系列专门化为能够输出完整页面 Markdown 的 OCR 模型。与先检测版面、再调用多个识别器的传统流水线相比，它希望把定位和结构生成能力内化进一个端到端模型；与直接提示通用 VLM 相比，它用专门的数据分布和训练目标约束输出。

## 数据工厂试图同时解决长尾版式与标注不一致

数据流程先把两个问题分开处理。几何索引根据页面图像特征聚类，目的是找到常见版式的重复样本并保留稀有布局；语义标签再标注语言、版面类型、文档来源和文档体裁。二者配合后，采样可以提高复杂表格、多栏论文、扫描件等长尾样本的比重，而不只按自然网页分布抽样（§2.1、§2.2.1）。

其次，作者把异构来源的标注重新整理为统一 Markdown：用 PaddleOCR-VL 批量生成规范化初稿，再做质量筛选；HTML/CSS 程序合成补充罕见表格和公式结构；规则检查语法闭合、表格列数和乱码，轻量模型区分不可用噪声与仍值得保留的困难样本。保留下来的 HardCase 再由更强的专有模型协助修订（§2.2–2.5）。这条链路的关键取舍是先扩大结构覆盖面，再把标注格式压到较窄的目标空间；统一格式有利于学习，却也会把初始 OCR、自动筛选器和教师模型的偏差带入训练集。

论文在 §4.1–4.2 报告了公开数据源与处理方法，包括公式、表格、手写和文档理解数据；§4.2 的阶段规模约为预对齐 130 万样本、专门 SFT 40 万对、GRPO 5 万样本。§2 另称标准化语料为一千万以上样本。数字是不同数据工序的口径，不能简单相加成互斥训练集合。原文没有给出全部语料的逐来源数量、自动标注误差分布和人工复核覆盖率；尤其内部 FireRedBench 被称为 internal benchmark，论文没有在该文中给出可检查的完整样本与标注清单。因此它适合说明作者针对什么难例设计流程，不能单凭规模主张数据质量已得到外部验证。

## 三阶段训练把像素定位、结构格式和内容准确分开教

第一阶段同时训练检测加 OCR、区域 OCR 和整页 Markdown。坐标框与文字一同生成，促使模型把视觉位置和识别内容联系起来；区域任务补充局部字形辨识，整页任务则开始建立版面到逻辑结构的映射（§3.1）。第二阶段用高质量文档到 Markdown 的监督数据，集中训练层级、闭合和公式等输出规范（§3.2）。

第三阶段使用格式约束 GRPO：对同一输入采样多个输出，按 LaTeX 可解析性、结构闭合、表格列数完整性和文本相似度给奖励（§3.3）。它瞄准的是离散格式规则，能补上 token 级交叉熵不直接表达“整个表格是否闭合”的缺口。作者还交替进行 SFT 与 GRPO，理由是 SFT 保持内容贴合标注，GRPO 强化可解析结构；再次引入 SFT 可以缓和模型只迎合规则奖励、生成空洞但格式正确输出的奖励投机风险（§3.3）。

这里有一个重要边界：格式奖励可以检查结构是否合法，却无法保证识别内容真实。论文的文本准确奖励用伪标注或人工标签与输出计算编辑距离；若伪标签本身漏字或错读，奖励依然可能巩固错误。作者报告的迭代训练和消融支持其训练配方在自设条件下有效，但不能把“格式约束”理解为已经消除结构幻觉。

## 结果支持专门化有用，不能推出无条件领先

在 OmniDocBench v1.5 上，论文报告 FireRed-OCR-2B 综合分为 92.94，DeepSeek-OCR 2 为 91.09、dots.ocr 为 88.41（§4.4，Table 2）。同一张表的 PaddleOCR-VL-1.5 为 94.50；因此更准确的结论是它在该表所列端到端 OCR 模型中表现较强，而不是总体最高。表格也显示它不同能力并非齐头并进，例如作者承认流水线模型在复杂公式指标上仍有优势。

在作者自建的 FireRedBench 上，模型报告总分 74.62；同表的 PaddleOCR-VL-1.5 为 76.47，Gemini 3 Pro 为 79.68（§4.4，Table 3）。这个集合主打畸变扫描、密集多栏和嵌入逻辑图等复杂页面，能作为压力测试的例子；但由于原文将它标为内部基准且未给出足以外部复查的完整样本及标签，分数主要是作者报告的内部证据。它不能直接当作独立公开基准上的泛化证明。

GRPO 消融提供另一个有用但范围有限的证据：在 Table 4 的 OmniDocBench v1.5 配方比较中，单域优化未必迁移到其他模态；文本与表格联合训练的总分为 88.72，低于纯文本基线 88.91。作者报告 1:1:1 混合的总分为 89.60，优于这些消融对照。这说明多任务信号有竞争关系，平衡采样比简单叠加数据更重要；它并不能独立证明某个奖励项是最终模型性能提升的原因，因为表 4 是特定基线和训练配置下的消融（§4.5，Table 4）。

## 这篇论文在 OCR 路线图中的位置

FireRed-OCR 是“通用 VLM 专业化”路线的例子：模型仍把一页内容序列化为文本标记，但用布局长尾数据、格式统一和结构奖励增强空间精度及输出合法性。它与 PaddleOCR-VL 的模块化版面定位加元素识别路线不同，也不同于 dots.mocr 把图表与示意图转成 SVG 代码的文图联合解析路线。FireRed 想让整页 Markdown 本身更可靠；它没有把每张信息图都恢复成可编辑矢量程序作为主要任务。

阅读原文时建议先看 §1 和 Figure 2 理解结构幻觉，再看 §2、Figure 3 追数据工厂，之后读 §3、Figure 4 了解课程训练，最后对照 §4.4–4.5 的 Tables 1–4。评测数字均指 v1 的论文报告结果；OmniDocBench v1.5 是可公开检视的基准，FireRedBench 则应按作者内部数据集看待。
