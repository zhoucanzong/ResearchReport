# Logics-Parsing：让强化学习直接惩罚错误的阅读顺序

> Xiangyang Chen et al., *Logics-Parsing Technical Report*, arXiv:2509.19760v1（2025-09-24，论文署名为 Alibaba Group / Logics Team）。依据[官方完整 HTML 原文](https://arxiv.org/html/2509.19760v1)精读，重点参照 §1–3.3，尤其 Tables 1–2。文中数字均为论文报告值及其自建基准结果；未独立重算或复现实验。

## 为什么普通 next-token 训练不够

整页文档解析需要把字符内容、二维位置和阅读顺序一起还原。标准监督微调（SFT）逐 token 学习参考 Markdown/HTML 序列，但作者指出，这种损失对结构错误的反馈是间接的：两个输出只差少数 token，可能对应完全不同的表格结构；段落文本都正确，先后顺序仍可能让整页含义改变。（§1、§2.1）

Logics-Parsing 选择端到端图像到 HTML 的方式，但在 SFT 之后增加布局中心强化学习（LC-RL），直接评价文本是否相符、区域框是否定位准确、段落读序是否正确。它以 Qwen2.5-VL-7B-Instruct 为底座，不从头训练新的视觉语言模型。（§2.3）

## 训练分两步：先学格式，再学结构

第一步 SFT 使用多来源页面数据，让模型学会识别文字、表格、公式、化学结构和手写中文，并生成规范化 HTML。论文报告训练集超过 300K 页面图像；它把公共数据和内部页面混合，使用 Mathpix 预标注、Gemini 2.5 Pro 辅助复杂样本修订，并对约 10,000 页困难样本进行人工校正，特别补充阅读顺序标签。（§2.2）

第二步 LC-RL 只用约 8,000 个困难页面：约 4,000 页由人工挑选，另外约 4,000 页按 SFT 模型的归一化编辑距离挖出。这一选择让强化学习集中修补模型“部分看懂但没解析对”的区域，而不是把计算均匀花在简单页面。（§2.2）

每个候选输出被转为文本/公式、边界框和段落序列，得到三个奖励：字符级负 NED、框定位准确度、以及参考顺序与预测顺序之间的段落逆序惩罚，再线性组合用 GRPO 更新。它的关键不是笼统地“加 RL”，而是让奖励直接对应页面结构中的错误类型。（§2.4）

## 为什么专门建一个复杂版面基准

LogicsParsingBench 包含论文报告的 1,078 页中英文文档、九类和二十余子类，偏重科学文档、嵌套公式、化学结构、多栏排版、音乐谱和古籍等困难内容。（§3.1）与 OmniDocBench 相比，作者更强调复杂读序和科学符号，并把同页文字拼接后再算文本编辑距离，减少段落切分粒度差异造成的惩罚；表格和公式另按结构指标计算。（§3.1、§3.2）

这些设计能把结构能力放到一个更具挑战性的测试里，但它也是作者提出的新基准。论文表示将发布基准，报告没有给出可独立核对的完整公开测试样本与标注。因此，基准内优势首先是作者自建评测上的证据，不应直接当成跨基准的普遍领先结论。

## 哪些结果支持布局奖励

在 LogicsParsingBench 上，论文报告 Logics-Parsing 的英语和中文总体编辑距离分别为 0.124 和 0.145（Table 1）。在同一表的分项中，它的阅读顺序误差并非所有系统里最低：作者承认商业 TextIn 更好；表格和公式也仍落后于部分专门工具。更合适的阅读方式是看它在页面总体文本及特定内容类型上的报告表现，再查各任务子分，而不是把“SOTA”当作全项最优。（§3.3.1，Table 1）

SFT→RL 消融更直接回答核心问题：在同一模型系列中，SFT 模型的英语/中文读序误差为 0.149/0.155；加入 LC-RL 后为 0.136/0.113。英语整体编辑距离从 0.133 到 0.124，中文从 0.159 到 0.145。变化与奖励中显式加入读序逆序惩罚的设计相符；它支持此训练阶段在作者自建测试集上的增益，但训练数据、奖励设计和模型采样并未被逐一完整拆因。（§3.3.2，Table 2）

## 设计边界与开放问题

- **布局奖励依赖可解析输出。** 如果模型的 HTML 结构已经坏到无法抽取区域、文本或段落，奖励分解也会受输出解析器影响。奖励正确性依赖序列化格式与预处理管线。
- **框奖励和读序奖励仍是代理目标。** 正确边界框不必然意味着表格语义正确；段落逆序也无法覆盖跨页脚注、图表引用或公式与正文的全部关系。
- **偏重困难页有取舍。** 把 LC-RL 预算投到模型的“学习区”可能更高效，但不同 SFT 底座的错误分布变化后，阈值区间和 hard-example 挖掘策略未必仍合适。
- **结果主要来自作者自建基准。** 训练集含内部数据，评测集强调特定中英文复杂页面，语言范围和来源代表性有限；论文结果不能直接外推到其他脚本、拍照文档或在线业务流。

Logics-Parsing 与 Dolphin 都显式处理布局和读序，但位置不同：Dolphin 先生成版面元素序列，再逐块裁剪、并行识别；Logics-Parsing 让整页模型直接输出结构化 HTML，再以结构奖励修正序列目标。两者的结果不能仅凭总体分数比较，因为测试集、模型规模和解码方式不同；它们更适合作为“把结构做成显式中间状态”与“把结构写进训练奖励”两种研究选择的对照。
