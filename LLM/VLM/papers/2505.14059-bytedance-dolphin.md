# Dolphin：先读版面，再并行解析文档元素

> Hao Feng et al., *Dolphin: Document Image Parsing via Heterogeneous Anchor Prompting*, arXiv:2505.14059v1（2025-05-20）。依据[官方完整 HTML 原文](https://arxiv.org/html/2505.14059v1)精读，重点参照 §1、§3–5，尤其 Figure 2、Tables 1–4。文中数字是论文报告值，保留对应数据集和指标；未独立重算或复现实验。

## 它要在两种文档解析方式之间取舍

传统系统把版面检测、文字识别、公式识别和表格结构恢复交给不同模型，再把输出拼起来。这样的系统可以给不同元素配专门工具，却可能把前一阶段的漏检和错切传给后续模型；多个接口也需要协调。另一种方式是让 VLM 直接从整页生成 Markdown，避免组件间交接，却要求模型在一条很长的自回归序列里同时安排阅读顺序和生成细节，复杂页面容易丢失结构且生成慢。（§1）

Dolphin 的问题是：能否保留全页布局推理，同时让内容识别以局部、并行的方式进行？它把两种工作拆成“先分析、后解析”，让第一阶段产生的版面元素成为第二阶段识别的锚点。

## 同一个模型分两次读页面

Dolphin 使用约 322M 参数的 encoder-decoder VLM，视觉端为 Swin Transformer，生成端为 mBART。第一阶段输入整页图像和布局提示，输出按阅读顺序排列的元素序列；每个元素包含类别和边界框，并可表达标题—段落、图表—说明文字等关系。第二阶段从原始图像裁出这些区域，按元素类型给出不同提示，再并行生成文本、HTML 表格或公式内容。（§3.1–3.3，Figure 2）

这里的“异构锚点”不是额外标记的一组通用位置编码，而是带类别与框坐标的布局结果。它把“这是什么、在页面哪里、接下来按什么顺序读”先写成显式中间结构，随后才让识别器回答“区域里具体是什么”。与纯整页生成相比，这减少了内容识别阶段必须同时处理的版面范围；与多模型流水线相比，两阶段仍共享一套 VLM 参数。

设计也把新的依赖集中到第一阶段：漏掉区域，或把阅读顺序排错，局部识别就无法自行补回完整页面。裁剪还会削弱跨区域关系。因此它并没有消除误差传播，而是把模块交接改成模型自身的布局预测。

## 训练规模为何支持这种拆分

论文报告训练集共 30.27M 样本，包括 0.12M 带边界和顺序的混合页面、4.37M 由 HTML 渲染的页面、0.5M LaTeX 文档、0.71M Markdown 页面、1.57M 表格样本和 23M 公式样本（§4.1，Table 2）。数据同时覆盖整页布局与独立元素，配合阶段一和阶段二的不同粒度目标：模型先学整页元素序列，再学区域内的专门内容解析。

这个配方减少了收集大量完整复杂页面标注的压力，因为单独的表格、公式或段落更容易获得成对图像与标记文本；代价是页面级训练数据与元素级训练数据存在分布差异，测试时必须靠第一阶段把它们重新接起来。30M 是样本总数，不表示 30M 张彼此独立的真实页面；其中含大量渲染或单元素数据。

## 结果要拆成页面结构和局部识别看

在论文自建的 Dolphin-Page 复杂页面设置中，作者报告页面级编辑距离为 0.1028、吞吐为 0.1729 页/秒；其英文和中文 Fox-Page 纯文字集合报告的编辑距离分别为 0.0114 和 0.0131（§5.2，Table 1）。这些是论文在指定测试集和设置下的结果。Table 1 中部分竞品数字带星号，脚注说明它们来自 GOT 论文报告，不能视为作者把所有系统在完全相同条件下重测。

消融更能解释设计选择：在 Dolphin-Page 上，串行处理取代并行处理后吞吐从 0.1729 降至 0.0971 页/秒；把元素专用提示换成统一提示后，编辑距离从 0.1028 升至 0.1613；用边界框查询代替实际裁剪后则升至 0.1849。（§5.3，Table 4）这支持“类型先验”和“局部视觉输入”对论文设置有帮助，但并不证明任意模型都应使用并行裁剪。

并行效果也受工程条件限制。作者指出元素裁剪预处理有开销，且每批最多处理 16 个元素；元素更多的页面需要多次前向计算，所以论文报告的 FPS 不能直接理解为 PDF 端到端服务吞吐。（§5.3）

## 适用边界

- 布局阶段的召回和顺序预测是下游上限；若页面密集到首阶段漏掉小字、脚注或跨栏关系，裁剪识别器看不到这些信息。
- 局部裁剪适合元素边界较清楚的页面；标题、图注、公式和正文的关系若超出单一裁剪框，第二阶段可能失去上下文。
- 训练语料混合了合成页面、真实页面和孤立元素；论文提供了来源与规模，但无法由总样本量推出各类真实文档的覆盖代表性。
- 主要结果集中于单页文档解析；它没有单独验证多页引用、跨页表格或基于整册 PDF 的检索问答。

Dolphin 的学习价值在于把文档解析拆成一个显式结构预测问题和一组局部识别问题。它与 PaddleOCR-VL 同属“布局先行、元素识别随后”的路线，但由单一 VLM 在两种粒度间切换；与 Logics-Parsing 和 ABot-OCR 相比，它把主要工程重点放在中间布局序列和并行区域识别，而非只让整页模型自己学出结构。
