# In-Place Test-Time Training：把 MLP 投影变成快速可更新的上下文状态

来源：[arXiv v1](https://arxiv.org/html/2604.06169v1)，ICLR 2026。重点阅读 §2–§4、Appendix 8–9，尤其 §3.1–§3.4 和 §4.1。

## 问题：能否给现有 Transformer 加入 test-time learning，而不另造整套骨干？

常规注意力按需读取 KV cache，但上下文增长时，缓存和每 token 计算也持续增长。部分 TTT 架构把 hidden state 设计为学习器本身，通常需要模型从头为该层适配；In-Place TTT 则尝试让预训练 LLM 在原有 MLP 中复用一部分参数作为 fast weights。

## 机制：MLP down-projection 作为临时快速记忆

作者选择 MLP 的 down-projection 矩阵作为 fast weights。当前 chunk 的中间激活形成 key，后续预测目标形成 value；模型在 chunk 之间对 fast weights 做在线更新，再让更新后的映射影响后续 token。每个 chunk 产生 outer-product 写入并按因果顺序累积；与显式把全部文本保留在 KV cache 不同，它试图把历史压缩进固定大小的可学习状态。

论文的重要设计是将 fast-weight objective 对齐 next-token prediction，而不是仅重构当前 token。其理论分析使用重复 key-value token 的 induction-head 设置，说明下一 token 目标会提高相关 value 的 logit；这是受控结构中的分析，不表示任意自然文本都会被可靠压缩。[§3.2–§3.3](https://arxiv.org/html/2604.06169v1)

## Chunk 更新与因果边界

每个 chunk 先按当前状态生成，再进行 fast-weight 更新；因果 padding 使该 chunk 的写入不看未来 token。由于更新具有可结合结构，作者用 prefix scan 实现 context parallel，使多个 chunk 的部分计算并行，再按前序累积状态生成对应输出。[§3.4、Appendix 8](https://arxiv.org/html/2604.06169v1)

论文的预训练实验与“给既有 checkpoint 加适应”是两种设置。主要 drop-in 案例从预训练的 Qwen3-4B-Base 出发，以 continual training/适配在较长上下文任务中评测；从头训练对照则比较 TTT 结构的架构潜力。阅读时应分清模型本身是否为 TTT 机制训练、测试流中更新何处、以及一个文档结束是否 reset fast weights。[§4.1–§4.2、Appendix 9](https://arxiv.org/html/2604.06169v1)

## 取舍与边界

fast weights 用有限参数记住上下文，避免完整 attention cache 的增长，但这是**有损记忆**：容易保留的内容由训练目标、fast-weight容量和更新顺序共同决定，不能像 KV cache 那样回读任意原文细节。论文还要支付梯度/更新计算，不能等同于“免费增加上下文窗口”。作者的 benchmark 是语言建模和长上下文测试，不证明 fast weights 能跨用户持久记忆、不会遗忘或适合所有对话任务。

后续 [TTT-NTP v1，§3–§4.6](https://arxiv.org/html/2606.21803v1) 把写入值改成下一位置的 contextual hidden state；[Select-TTT v1，§4–§5.6](https://arxiv.org/html/2610.36794v1) 又按 query relevance 对 chunk 写入强度加权。两者说明“fast-weight TTT”内部仍有目标与写入选择的研究问题，而不是一种固定机制。
