# Test-Time Learning for Large Language Models：用无标签输入适应目标域

来源：[PMLR 267 正式论文页面](https://proceedings.mlr.press/v267/hu25z.html)，ICML 2025；arXiv:2505.20633v1。正文重点阅读 §3–§5，特别是 §4.1–§4.3 与 §5.4。arXiv HTML 是 supplementary，正文按 PMLR 论文 PDF 阅读。

## 问题：模型已能读取测试输入，但对新分布仍预测失准

TLM 研究目标域变化，例如专门领域术语或不同语言风格。与 TTT-NN 不同，它不依赖预训练语料或邻居索引，而希望只用部署时到来的无标签输入进行自监督更新。

## 方法：最小化输入 perplexity，并让高信息样本贡献更大

作者先提出一个工作假设：输入序列的预测困惑度和该输入下生成答案的困惑度存在相关性，因此可在没有答案标签时，通过降低输入的 next-token loss 来改善目标域表现。随后引入 perplexity-based sample weighting，突出高 perplexity 输入，并以 LoRA 限制可训练参数，尝试降低 full-parameter update 的成本和遗忘风险。[§3–§4.3](https://proceedings.mlr.press/v267/hu25z.html)

这是一个**测试样本流上的域适应**，不等于“模型从输入学到的事实必然正确”。关键推理链是：输入 loss 下降 → 表征与域更匹配 → 生成结果更好；第一步是优化目标，后两步需要独立任务评测支持。论文给出梯度关联分析、输入/输出 perplexity 的趋势和 AdaptEval 任务作证，但趋势相关不构成普遍因果保证。

## 更新状态与评测协议

算法初始化 LoRA 更新参数，按 batch 对测试输入计算选择分数与 loss，然后更新可训练部分。判断其是“每样本适应”还是“持续流适应”，必须看评测时 LoRA 是否跨样本保留、测试样本的顺序以及各子任务之间是否复位；这些决定了模型看到的是独立新请求还是同一个逐渐适应的目标域。

论文的 AdaptEval 覆盖领域知识、指令和推理等测试任务，作者报告 TLM 相较原始模型有提升。阅读这些结果应关注具体 backbone、任务拆分、更新预算和 baseline；不能把摘要的整体提升外推为所有无标签场景均改善。[§5、Appendix B–D](https://proceedings.mlr.press/v267/hu25z.html)

## 失效边界：自监督“信心”可能放大错方向

Perplexity 高可以代表目标域新颖，也可能代表噪声、拼写错误、异常值或模型本来不该吸收的内容。输入本身的分布拟合不是事实核验；测试流污染、错误文本和恶意提示若被用于更新，会把不可靠样本写入 LoRA。作者提出 LoRA 缓解遗忘，但这不等于保证不会发生跨请求串扰或目标域过拟合。

2026 年的 [FG-TTL (ICML 2026)，§3–§4](https://proceedings.mlr.press/v306/bian26b.html) 针对自回归生成的确认偏差风险，尝试根据后续 token 的 future gain 选择更新位置并做 risk-aware scaling。它仍属无标签流适应，但关注的是“模型自己生成的哪些 token 值得学”，可与 TLM 对输入样本的 perplexity 选择对照。

**带走的区别**：TLM 更新 LoRA 来拟合一个输入流的统计特征；它既不是普通提示上下文，也不是检索库，更不是利用 verifier 进行搜索。它的核心未决问题是自监督更新目标与下游真实正确性之间的距离。
